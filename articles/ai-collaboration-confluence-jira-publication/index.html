العودة إلى دورة التعاون بالذكاء الاصطناعي

يجمد المساهم PROP-042 قبل موافقة المالكين عليه. يحدّث مسؤول النشر المتطلبات في Confluence، ويدمج مشرف GitHub التنفيذ، وينشر فريق العمليات دليل التشغيل. ويسجل Jira كل خطوة. نفّذ ذلك بعد التحقق من الأذونات، لأن الأنظمة الثلاثة لا تشكل معاملة ذرية واحدة. يجعل سجل النشر التسليم غير المكتمل ظاهرًا.

النقاط الرئيسية #

  • تختلف النية المعتمدة عن السلوك الذي جرى تسليمه.
  • تربط مراجعات المقترح الثابتة المراجعة بإصدار محدد.
  • تكشف سجلات النشر الخطوات غير المكتملة.
  • تحمي القراءات الحديثة من تغير القواعد المصدرية.

قبل البدء #

المتطلبات السابقة: إعداد مكان العمل ، وصلاحية النشر، والمالكون، ومشرف المستودع. الوقت التقديري: ساعتان. الصعوبة: تنسيق متقدم.

الواجهة الأساسية: قراءة الصفحات في المتصفح، وصياغة اختيارية في دردشة معتمدة، ونشر ينفذه شخص. لا يفترض هذا المسار وجود اشتراك في موصل. راجع توفر المستأجر والنطاقات وطريقة تعامل المزوّد وربط الهويات قبل إضافة تكامل. لا تشارك أبدًا بيانات اعتماد مالك مع مساهم.

نتيجة القارئ: ستنهي العمل بمقترح ثابت، وسجل نشر لكل نظام، وأدلة إعادة القراءة، وقرار للتعافي من أول خطوة غير مكتملة. يثبت التمرين الإجراء والتعامل مع الأدلة، لا سلوك الاحتفاظ في الإنتاج.

تسجيل المصادر الحالية #

  1. اقرأ MAP-01، ثم افتح REQ-17 وRUN-04 باستخدام معرّفات الصفحات المرتبطة.
  2. افتح قائمة الصفحة وسجلها (Page History)، وسجل أرقام الإصدارات والحالة والصياغة والمالك والاستثناءات.
  3. اقرأ عنصر Jira وأرفق تصديرًا ثابتًا للمقترح أو commit من GitHub. لا يثبت المفتاح وحده أدلة المراجعة.
  4. اقرأ POL-01 المعتمدة وخط أساس الإعدادات المحمي.
  5. زوّد الدردشة بالمقتطفات الاصطناعية اللازمة فقط، وعلّمها بأنها لقطات، وأبقِ إجراءات الكتابة معطلة.
Task: PROP-042, propose only
Authority: Confluence REQ-17 for intent, GitHub for behavior
Read: mapped current pages, versions, scope, exceptions
Proposal: synthetic export retention from 7 to 30 days
Output: requirement wording, config diff, runbook, ledger
Evidence: source ID and captured revision for each factual claim
Unknowns: missing access and absent runtime observations
Stop: conflict, changed base, or denied access

تظل الحزم غير المتصلة مبنية على اللقطات. يعيد مسؤول النشر قراءة المصادر الحالية قبل الكتابة. يمنع رفض الوصول النشر. ولا يحل تصدير قديم محل التفويض الحالي.

تثبيت المقترح #

{
  "proposal_id": "PROP-042",
  "proposal_revision": 1,
  "requirement_base_version": 1,
  "runbook_base_version": 1,
  "policy_version": 1,
  "from_days": 7,
  "to_days": 30,
  "status": "awaiting-owner-review",
  "publication_order": ["requirement", "implementation", "runbook", "delivery"]
}

استبدل إصدارات الصفحات التوضيحية بالإصدارات التي التقطتها فعليًا. أرفق JSON الثابت والصياغة المقترحة في Jira. يسجل كل مالك دوره وقراره ومراجعة المقترح وإصدارات المصادر ووقت المراجعة. تعيد أي تعديلات جوهرية الحزمة إلى Review.

يراجع فريق المنتج النية والنطاق. ويراجع فريق العمليات التنظيف والتعافي. ويراجع المشرف فرق التغييرات. لا تمثل ردود الفعل على رسائل دردشة قابلة للتغيير موافقات مرتبطة بمراجعة محددة.

النشر وإعادة القراءة #

  1. انقل Jira إلى Publishing بعد أن يتحقق مسؤول النشر من مراجعتي المالكين وبقاء قواعد المصادر دون تغيير.
  2. انشر REQ-17 بمدة ثلاثين يومًا وحقل يدل على انتظار التسليم. سجل إصدار الصفحة الناتج والنطاق والاستثناءات.
  3. افتح طلب تنفيذ GitHub مشيرًا إلى إصدار الصفحة المعتمد. غيّر الإعداد إلى ثلاثين يومًا وأرفق لقطة متطلب غير مرجعية.
  4. ادمج بعد مراجعة المستودع وأعد قراءة main. سجل سلوك المستودع المثبت منفصلًا عن سلوك وقت التشغيل.
  5. انشر RUN-04 وأعد قراءته باستخدام معرّفه، وسجل إصداره الناتج. يحدّث مسؤول النشر مراجع التسليم في المتطلب.
  6. أكمل Jira فقط بعد تطابق كل السجلات وإرفاق دليل إعادة القراءة النهائية.

استخدم المدقق المحلي للتحقق من اتساق اللقطات فقط. انسخ متطلب Confluence السابق للتغيير إلى مخطط JSON الأساسي للمختبر، والتقطه، ثم عدّل النسخة المرشحة إلى ثلاثين يومًا. استخدم مراجعة لقطة محلية متزايدة، مع الاحتفاظ بإصدارات Confluence الفعلية منفصلة في Jira. لا يتحقق مسار GitHub بوصفه المصدر الجذري من Confluence المباشر. لا تعرض حالته الخضراء بوصفها تحققًا من مرجعية خارجية.

لا تُدخِل وظيفة حذف إلى بيئة التشغيل في هذا التمرين. تحتاج الخدمة الحقيقية إلى دليل نشر وبيانات اختبار مضبوطة وآلية تعليق واختبارات لحدود وقت التشغيل. يثبت الدمج حالة المستودع، لا سلوك الاحتفاظ في الإنتاج.

سجل كل نتيجة قبل محاولة الخطوة التالية. يربط PROP-042 أحداث كل نظام. لا يعني إكمال صف واحد اكتمال التغيير كله.

إخفاق توضيحي: ينشر Confluence مدة ثلاثين يومًا، لكن GitHub يرفض الدمج. أبقِ Jira في Blocked والمتطلب بحالة تسليم معلّق. يختار فريق المنتج إكمال التغيير أو استعادة السبعة أيام بعد مراجعة. لا تجعل نسخة README طارئة مرجعًا معتمدًا للمتطلب.

التعامل مع التعديلات المتزامنة #

أساس العمل عبر المتصفح: عيّن مسؤول نشر واحدًا خلال فترة التجربة. أعد فتح Page History مباشرة قبل التحرير وبعد النشر. إذا غيّر كاتب آخر المصدر، فتوقف وقارن وسوِّ الاختلافات وجدّد الموافقة. النشر المتسلسل إجراء عمل، وليس ضمانًا لمعاملة ذرية.

امتداد API: توثق Confluence v2 المسار GET /wiki/api/v2/pages/{id}?body-format=storage والمسار PUT /wiki/api/v2/pages/{id} مع كائن إصدار. يقارن تكامل النشر الخاضع للمراجعة الإصدار الحالي بالأساس المعتمد، ويرسل الإصدار التالي، ثم يعيد قراءته. لا تحدّث إصدارًا فاشلًا تلقائيًا ولا تعد محاولة إرسال محتوى قديم.

نجاح API وحده غير كافٍ. تحقق من المحتوى الناتج ومعرّف المصدر والنطاق والإصدار. لا تتضمن هذه الدورة عميل API قادرًا على الكتابة. النشر البشري عبر المتصفح هو الأساس القابل للتنفيذ لغير المبرمجين.

سجل النتائج الفعلية في البيئة التجريبية مع دور المنفذ والمراجعات قبل التغيير وبعده. لا تضع محتوى الصفحات المحمية في أدلة تظهر لمستخدم مرفوض. النتائج المتوقعة ليست نتائج مقاسة.

تجميع حزمة المراجعة #

ثبّت المحتوى، لا تسمية المقترح فقط. يظهر PROP-042 في كل نظام، لكن التسمية لا تحدد النص الذي راجعه المالك. أدرج صياغة المتطلب الدقيقة وفرق التنفيذ وصياغة دليل التشغيل وإصدارات المصادر وتسلسل النشر في حزمة ثابتة واحدة.

Package: PROP-042 revision 1, illustrative
Intent: synthetic export retention changes from 7 to 30 days
Exclusions: production data, backups, legal holds
Requirement amendment: fixed proposed REQ-17 wording
Implementation: fixed candidate diff and protected base reference
Runbook amendment: fixed RUN-04 wording and recovery limits
Review: product and operations decisions for this package
Delivery: requirement -> implementation -> runbook -> closure
Stop: changed source, missing review, denied write, failed read-back

اجعل الحزمة واضحة لكلا المالكين. يحتاج فريق المنتج إلى النية والاستثناءات. ويحتاج فريق العمليات إلى تغيير التشغيل وحدود التعافي. ويجب أن يفهم الاثنان فترة اختلاف النية المعتمدة عن الإعداد الذي جرى تسليمه. لا يكفي فرق شيفرة مجرد لمالك لا يعرف ملفات المستودع.

محتوى الحزمة المعبأة لهذا المثال الاصطناعي:

REQ-17 proposed v5: "Synthetic export files are retained for 30 days from creation. This pilot excludes production data, backups, and legal holds. Delivery remains pending until the GitHub configuration and RUN-04 read-backs match this approved wording."

GitHub config.json, proposed change against base-001:
-  "retention_days": 7
+  "retention_days": 30

RUN-04 proposed v3: "Retention days: 30. Synthetic exports only. No deletion job runs in this lab. If publication fails, keep delivery pending, read back each source, and obtain owner approval before restoring the seven-day configuration or completing the thirty-day publication."

هذه النصوص مقترحة كمثال وليست سجلات فعلية للمستأجر. أرفق commit الأساس الفعلي وإصدارات الصفحات قبل المراجعة. يجب أن تتضمن الحزمة الثابتة الأجسام المقترحة كاملة، لا ملخصًا يضطر المالك إلى استنتاج محتواها.

افصل اللقطة غير المتصلة عن النشر المباشر. قبل أول كتابة مباشرة، يعيد مسؤول النشر فحص الصفحات المرتبطة، ويعيد المشرف فحص الأساس المحمي. إذا تغير أي منهما، تتوقف الحزمة القديمة عند Review.

استعراض السجل #

تقدم توضيحي للحالة: يستخدم الجدول مراجعات تعليمية لا ملاحظات فعلية. املأ الإصدارات والـ commits الناتجة فعلًا بعد كل كتابة في البيئة التجريبية.

التسليم المعلّق حالة ذات معنى. فهو يمنع وصف التنفيذ القديم بأنه متوافق مع النية الجديدة بينما لا يزال النشر ناقصًا. يحتاج القراء إلى معرفة القيمتين خلال هذه الفترة، لا إلى ملخص واحد يزعم أن مدة الاحتفاظ أصبحت ثلاثين يومًا.

أضف المحاولات الفاشلة كأحداث منفصلة. إذا فشلت كتابة دليل التشغيل، فأبقِ نتائج نشر المتطلب والإعداد الناجحة. سجل الإجراء الذي جرت محاولته والفشل والإصدار الذي لم يتغير والدور المسند والخطوة التالية. لا تعد الصفوف المكتملة إلى Pending ولا تمحُ التسلسل المرصود.

مثال على رفض إصدار قديم: يقرأ مسؤول النشر REQ-17 v4، ثم ينشر محرر مخول آخر v5، وبعد ذلك يحاول مسؤول النشر تطبيق PROP-042 r1 على v4. تبلغ المنصة عن تعارض إصدار أو تكشف قراءة ما قبل الكتابة عن v5. سجل المنفذ publisher، والإصدار الأولي v4، والمحاولة PROP-042 r1، والتعارض المرصود أو تغير الإصدار الحالي، والإصدار النهائي v5 الذي لم تغيره هذه المحاولة، والمالك المعيّن product owner. أبقِ Jira في Review. أعد قراءة v5 وسوِّ الصياغة واطلب مراجعة حزمة ثابتة جديدة قبل كتابة أخرى. استخدم استجابة المنصة الفعلية وPage History في اختبار مباشر. هذا الصف مثال تعليمي.

التسميات أعلاه توضيحية وليست أدلة من المستأجر. يحتاج سجلك إلى روابط أصلية لإصدارات الصفحات ومعرّفات commits. قبل نقل Jira إلى Done، أرفق المقترح المجمد ومراجعتي الدورين وسجل قاعدة المصدر ونتيجة إعادة قراءة كل نشر ونتيجة الاختبار السلبي وحدود وقت التشغيل غير المحسومة. إذا غاب عنصر، فأبقِ التسليم مفتوحًا أو في Blocked.

بوابة الحزمة: علّم كل فحص من الفحوص الخمسة بحالة Supported أو Blocked: إصدارات المصادر حديثة، والمالكان وافقا على المراجعة الثابتة نفسها، وكل عمليات النشر المطلوبة تطابق إعادة القراءة، وحدود وقت التشغيل صريحة، وحالة التعافي مسوّاة. تتطلب Done خمسة فحوص Supported وعدم وجود كتابة غير مخولة.

التعامل مع كتابة غير مؤكدة #

يترك انتهاء المهلة النتيجة غير معروفة. لا يثبت النجاح ولا الفشل. في المسار الأساسي للمتصفح، أعد فتح المصدر المرتبط وافحص محتواه وسجله الحاليين قبل تقرير إعادة المحاولة.

  1. أوقف الخطوة التالية: أبقِ التسليم غير مكتمل.
  2. اقرأ الوجهة: قارن الصياغة الحالية والإصدار والنطاق بالحزمة الثابتة.
  3. سجل الملاحظة: مكتملة أو دون تغيير أو متعارضة أو يتعذر الوصول إليها.
  4. اختر الخطوة التالية: تابع من حالة إكمال تم التحقق منها، أو أعد محاولة خطوة مخولة لم تتغير، أو صعّد التعارض.
  5. احتفظ بحالة عدم اليقين: أبقِ المحاولة الفاشلة أو المجهولة بجانب إعادة القراءة اللاحقة.

لا تعِد تنفيذ التسلسل كاملًا بلا تحقق. فتكرار خطوة اكتملت يضيف إصدارات ويهدد باستبدال تعديلات لا تخصك. استأنف من حالة تم التحقق منها. إذا تعذر الوصول إلى المصدر، اختر Hold بدل التخمين اعتمادًا على السجل القديم.

فحص اكتمال النشر #

سلّم حزمة يستطيع مراجع مستقل تسويتها. يجب أن يجد المقترح الذي جرت مراجعته بنصه، وقواعد مصادره، ومراجعتي الدورين، ونتيجة كل كتابة، والقيم النهائية، وقيود وقت التشغيل المتبقية. اطلب منه تحديد أول خطوة ناقصة بعد انقطاع العمل.

الاستدلال المتوقع: تحدد المصادر الحديثة والسجل الخطوة التالية، لا ثقة المساعد السابق. انقل المراجع المرتبطة النهائية إلى اختبارات الاسترجاع، حيث يجب أن يحافظ الاكتشاف على التمييز نفسه بين مصادر الصلاحية.

استكشاف الأخطاء والتعافي #

تغير الإصدار: قارن السجل وجدّد المراجعة. تنجح مطابقة اللقطة لكن تختلف الويكي: اجلب مصادر Confluence الحالية مجددًا. جرى وضع Done مبكرًا: أعد فتح العنصر عبر الإجراء المسموح وسجل الخطوات الناقصة.

التعافي: استخدم مقارنة Page History واستعادة أو تعديلًا تعويضيًا راجعه مالك. سجل الإصدار الناتج بدل افتراض أن الاستعادة تعيد الترقيم. ارجع عن الإعداد عبر طلب سحب محمي إذا اختار المنتج التراجع. الملفات المحذوفة خارج ضمان التراجع.

التمرين والتقييم الذاتي #

أوقف العمل بعد نشر REQ-17 وأعطِ ناشرًا آخر الخريطة والسجل فقط.

الاستدلال المتوقع: يجلب الناشر المصادر الحالية، ويتأكد من الموافقة الثابتة، ويستأنف الخطوة المعلقة المخولة فقط. تعيد الأدلة الناقصة العمل إلى Review.
