実践AIワークフローコースに戻る

複数の会話で目的を共有する場合は、プロジェクトを作成します。安定した指示と承認済みの参照ファイルを1か所にまとめます。会話ごとに1つのタスクを扱います。このレッスンでは、個人データを使わずに練習できる架空の地域ワークショップを使います。

学習目標: 2つの管理された情報源を持つプロジェクトを作成し、新しいチャットで情報を検証します。

要点 #

  • プロジェクトの指示は、関連するチャットで再利用する動作を定めます。
  • プロジェクトの情報源には、アシスタントに参照させる資料を保存します。
  • 会話履歴は1回のやり取りを記録するもので、承認済みの情報源の代わりにはなりません。
  • 新しいチャットでのテストで、設定から十分なコンテキストが渡るか確認できます。

始める前に #

必要なもの: ChatGPTまたはClaudeのアカウントと レッスン1 のタスクパケット。35分ほど確保します。難易度は初級です。練習中は架空の名前、日付、場所だけを使います。

**コンピューターで小さなファイルを2つ作ります。**プレーンテキストエディターを開き、各ブロックを別々のファイルに貼り付け、指定された.md名で保存します。Markdownファイルはプレーンテキストです。workshop-brief.mdには対象者と文体を記します。approved-schedule.mdには架空の公式日程を記します。

workshop-brief.md、改訂1
対象者：入門ワークショップに登録した人。
文体：短い文で、親しみやすく事実に基づく調子。
料金、アクセシビリティ機能、駐車場の詳細を創作しない。

approved-schedule.md、改訂1
ソースマーカー：WS-2026-11-12-R1
イベント：デジタル安全入門
日付：2026-11-12
開始：7 p.m.
場所：Community Room A

ChatGPTを設定する #

  1. ChatGPTのサイドバーで**「Projects」を開き**、Workshop Practiceというプロジェクトを作成します。
  2. 2つのファイルをプロジェクトの情報源として追加します。
  3. プロジェクト設定を開き、以下の指示を追加します。
  4. 実際の資料を追加する前に、アカウントとワークスペースのメモリ設定と共有設定を確認します。
イベントの事実にはapproved-schedule.mdを使う。
対象者と文体にはworkshop-brief.mdを使う。
必要な事実がない場合は、情報源を尋ねるか不明と記す。
下書きだけを作成する。送信や公開はしない。
修正した下書きごとに、事実関係の変更点を列挙する。

**ChatGPTのプロジェクトは、関連するチャット、ファイル、指示をまとめます。**設定や利用できる機能は、プランとワークスペースによって異なります。作成時にプロジェクト専用メモリを選べる場合は、独立性を明確に検証するために選択します。標準メモリでは、アップロードしたファイル以外の情報をチャットが使うことがあります。下の固有のマーカーを使うと、メモリ由来の回答をファイルを読んだ証拠と誤認せずにテストできます。現在のメモリ設定は ChatGPT Projects公式ガイド で確認してください。

Claudeを設定する #

  1. Claudeで**「Projects」を開き**、同じ練習名のプロジェクトを作成します。
  2. 2つのファイルをプロジェクトの知識に追加します。
  3. 同じ5行をプロジェクト指示に設定します。
  4. プロジェクト内で新しいチャットを開始し、設定をテストします。

**この手順は従来のClaude Projectsを説明しています。**Anthropicは一部のClaude Code ProおよびMaxユーザーに別のProjectsベータを展開しています。ベータでは、1つのプロジェクトが並行するクラウドスレッドを持つ1つの会話に相当します。 Projectsとは を確認し、アカウントに表示される画面に従ってください。従来のプロジェクト指示はすべてのチャットに適用され、プロジェクトの知識は共有参照資料を提供します。アップロードしたファイルを管理対象の事実として使います。プロジェクトメモリの動作はアカウントや設定によって異なるため、別のチャットの情報を承認済み日程として扱わないでください。現在の操作方法は Claudeプロジェクト設定ガイド で確認します。

プロジェクトモード確認する共有資料新しいテスト
ChatGPTプロジェクトアップロードしたファイル、指示、選択したメモリモード新しいプロジェクトチャットが日程マーカーを示す
従来のClaudeプロジェクトチャット間で共有されるプロジェクト知識と指示新しいプロジェクトチャットが日程マーカーを示す
Claude Projectsベータプロジェクトとクラウドスレッド内の情報源とコンテキスト新しいプロジェクトスレッドが日程マーカーを示す

**プロジェクトはコンテキストをまとめますが、情報源を承認するものではありません。**マーカーで、指定したファイルがチャットに届いたか分かります。それでも日付、時刻、部屋をファイルと照合してください。

新しいチャットをテストする #

**新しいChatGPTプロジェクト会話か、従来のClaudeプロジェクトの新しいチャットを開きます。**Claude Projectsベータでは、プロジェクト内に新しいスレッドを作ります。短い告知文を依頼します。プロジェクトの情報源から必要な事実を取得できるよう、プロンプトに日程は含めません。

次回のワークショップについて、100語のメールの下書きを作成する。
日時と場所の情報源ファイル名と正確なソースマーカーを記す。
下書きの後に不足している事実を列挙する。
メッセージは送信しない。
結果意味次の対応
時刻、場所、マーカーが一致するこのチャットからファイルを参照できるファイルを見て自分でも事実を確認する
事実を作り出した指示または情報源の利用に失敗したその事実を削除し、依頼を具体化する
情報源が見つからない参照資料がチャットに届いていないプロジェクトへの追加とファイルのアップロードを確認する
古い版が出てくるプロジェクトに古い資料が残っている情報源を置き換えて再テストする

**1回の正しい回答だけで信頼性を判断しません。**標準のプロジェクトメモリは、アップロードしたファイルを読まずに見覚えのある時刻を出すことがあります。正確なWS-2026-11-12-R1マーカーを求め、次の食い違う草稿でテストを繰り返します。

承認済みのプロジェクト日程を使って、この文を修正する。
「デジタル安全入門の講座は6 p.m.にCommunity Room Aで始まります。」
事実の変更点、情報源ファイル、ソースマーカーを記す。メッセージは送信しない。

期待される回答: 行には午後7時と記され、approved-schedule.mdおよびマーカーWS-2026-11-12-R1が示されます。観察した失敗を記録します。テスト合格のために失敗を作り出す必要はありません。

テスト記録の例: 新しいチャット、最初のプロンプト、時刻は午後7時、場所はCommunity Room A、情報源はapproved-schedule.md、マーカーはWS-2026-11-12-R1、合格。食い違いのプロンプトでは午後6時を午後7時に修正、合格。これは記録例です。実際に観察した結果に置き換えてください。

プロジェクトを維持する #

**プロジェクト指示は短くします。**安定したルールを記載し、タスク固有の詳細は各プロンプトに入れます。古くなったファイルを置き換え、版を明記します。情報源の競合を防ぐため、無関係な作業は別のプロジェクトに分けます。

**プロジェクトを共有する前に、**ファイル、チャット、指示、アクセス一覧を確認します。プロジェクトは作業場所であり、承認システムではありません。「approved」という名前のファイルでも、重要な作業には実際の責任者と改訂記録が必要です。

練習して確認する #

成果物: 2つの合成情報源ファイル、5行の指示、短いテスト記録を含むプロジェクトです。観察した時刻、場所、情報源名、マーカー、作り出された事実を記録します。練習用プロジェクトが不要になったら削除します。

期待される考え方: 新しいチャットは安定した事実にプロジェクトの情報源を使い、プロンプトは直近の出力内容を指定します。回答をファイルと照合します。情報源がない、または誤った版が出た場合は、プロジェクト設定を見直します。

理解度を確認する #

  1. 質問: ChatGPTプロジェクトの新しいチャットは、どのメモリ設定でも情報の分離を保証しますか。回答: いいえ。プロジェクトのメモリモードを確認し、一意の情報源マーカーでテストします。

  2. 質問: プロジェクトが古い日程を繰り返したらどうしますか。回答: 添付された情報源とメモリの範囲を確認し、古い資料を置き換えます。

トラブルシューティング #

  • プロジェクト設定が見つからない: 利用中のプランとワークスペース設定をベンダーガイドで確認します。
  • 回答が食い違う: 重複または古い情報源ファイルを削除し、新しいチャットを始めます。
  • 意図しない共有: プロジェクトのメンバーを確認し、続ける前に機密情報源を取り除きます。
  • 文体のずれが続く: 指示を短くし、タスクプロンプトに短い例を1つ入れます。
