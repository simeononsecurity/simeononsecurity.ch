在两项 Ollama 模型测试中，H100 SXM 都是速度最快的显卡，但性价比并非最高。 RTX PRO 5000 和 RTX 6000 Ada 在速度与租用成本之间取得了更好的平衡。已完成的 Qwen3.8 27B 测试中，CMP 170HX 的每小时租金最低。

这些结果只测量一种模型、一层 Ollama 封装、默认量化方式和一种服务模式。请把它们作为此工作负载的硬件配置参考，而非普遍适用的 GPU 排名。

本文比较 Llama 3.1:8b（8.03B 参数的 Ollama Q4_K_M 构建）和 Qwen3.8:27b（约 27.3B 参数的 Ollama Q4_K_M 构建）。我们在 Vast.ai 租用的 GPU 实例上测试了两者，重点测量实际提示词长度下的解码吞吐量，最长达到模型支持的上下文范围。

简要结论 #

日常单人使用时，租用 RTX PRO 5000 或 RTX 6000 Ada。 短、中上下文测试中，RTX PRO 5000 的性价比最高。RTX 6000 Ada 租金较低，性能也明显领先 A100。若响应速度比每小时费用更重要，或工作负载包含长提示词，可租用 H100 SXM。

测试内容 #

基准测试使用 Ollama 和模型默认的 Q4_K_M 构建。 没有添加特殊量化、推测解码、自定义采样器或其他服务栈。目标是对 GPU 实例进行简单、可在本地复现的比较。

Vast.ai 将其服务描述为连接算力提供商和用户的 GPU 云市场。文档列出按需、预留、可中断和无服务器选项，并提供 GPU 型号、显存、价格和可用性筛选。下文的每小时租金来自本次基准测试选中的实例，并非 Vast.ai 的固定价格表。

测量指标是解码吞吐量，单位为每秒生成的令牌数。我们单独列出预填充吞吐量，因为它表示提示词处理速度，而非答案出现的速度。即使解码速度很高，处理长提示词仍可能需要较长时间。

每种上下文长度都进行两次有效测试，并记录解码结果的中位数。已完成的提示词级别依据实际 prompt_eval_count 值确定：

  • 约 16.4k 个提示词令牌
  • 约 32.8k 个提示词令牌
  • 约 65.5k 个提示词令牌
  • 约 131k 个提示词令牌

请求的 256k 令牌测试未能完成。40 GB A100 显卡和几款较小显卡仍在处理，或未能达到目标上下文长度。

基准测试的局限： 这些数字描述的是一种服务模式下的两种 Ollama Q4_K_M 工作负载。它们不能预测训练速度、多用户吞吐量、图像生成速度、vLLM 性能或其他模型的结果。

重新测试 Llama 3.1 8B #

Llama 3.1:8b 是这组 GPU 的实用基线模型。 Ollama 列出的下载量约为 1.2 亿，因此适合作为第二个热门基准模型。 Ollama 官方模型页面 列出 4.9 GB 的 Q4_K_M 构建、8.03B 参数和 128K 上下文窗口。

重新测试使用了针对该模型的基准测试程序，并依据 Ollama 的分词器校准提示词生成器。下列标签采用实际提示词令牌数，而非请求的上下文设置：

  • 32k 目标对应约 32,676 个实际提示词令牌
  • 64k 目标对应约 65,342 个实际提示词令牌
  • 128k 目标对应约 130,671 个实际提示词令牌

Llama 3.1 8B 的上下文上限为 128K，因此明确不支持 256k。测试程序增加了重试处理和状态行，所以超时会保留在表中，而不会被隐藏。

比较两种模型 #

在每张可比较的 GPU 上，较小的 Llama 模型都更快，但模型大小不等同于模型质量。 Llama 3.1 8B 是一种热门、低显存需求的基线。Qwen3.8 27B 需要更多显存，能力侧重也不同。应使用这些数字选择硬件，而不要据此断言某个模型总是更好。

用途更合适的基准参考原因

128K 上下文上限Llama 3.1:8b模型明确限制为 128K，因此 256k 不是有效目标

跨提供商基线Llama 3.1:8b模型流行且规模适中，更容易复现实验

此前对 Qwen 的重新测试也修正了支持的上下文级别下的实际提示词数量，约为 32,770、65,538 和 131,074 个令牌。比较 Qwen 测试时，应使用修正后的标签，而不是请求的 num_ctx 值。

租用、购买额度、订阅还是购买硬件？ #

合适的选择取决于使用率和控制要求。 GPU 租用是一项可变算力支出。API 额度是一项可变模型支出。聊天订阅是带使用限制的固定访问费用。自购硬件是资本开支，之后还要支付电费、散热、维护和折旧。

月预算与工作负载建议方式原因主要代价
低于 $10购买 API 额度或使用免费本地模型无需承担 GPU 闲置成本即可验证工作流程对模型托管和速率限制的控制较少
$10 至 $30偶尔使用时购买 API 额度，日常交互时购买聊天订阅订阅适合人工对话，额度适合脚本和可计量调用默认情况下，两者都不提供私有 27B 端点
$30 至 $100仅在活跃时段租用 RTX 6000 Ada 或 RTX PRO 5000可负担短期研究任务，同时避免持有硬件的额外开销仍需设置、存储、监控并及时关闭实例
$100 至 $250为计划任务租用高速显卡，或测试自有工作站方案月使用量持续增加时，开始显现利用率的作用租用可用性和小时价格会变化
$250 至 $600将一个月 RTX PRO 5000 的租金与新旧本地 GPU 比较这是频繁私有推理时的决策区间硬件增加电力、散热、支持和转售风险
高于 $600仅在利用率高时购买硬件，或为突发任务预留 H100 级租赁混合方案避免为了偶尔需求长期持有高端硬件资金会固定在单一配置上

这些区间是决策参考，不是服务商报价。测试租金展示了关键的盈亏平衡问题：H100 每小时 $2.693，连续运行 24 小时约 $64.63，连续 30 天约 $1,941.00，尚未计入存储及其他费用。RTX PRO 5000 每小时 $1.005，连续运行每天约 $24.12，30 天约 $723.60。仅在活跃时段租用 GPU 的总费用，与整月不间断运行不同。

何时 API 额度更合适 #

使用不规律、自动化重要且任务不要求特定本地模型时，API 额度更合适。 它们免去了 GPU 配置、模型下载、驱动问题和闲置时间。购买硬件前，也可以借此比较多个托管模型。

API 价格因模型和服务商而异。OpenRouter 模型目录便于比较上下文长度、服务商和令牌价格。把 API 账单与本测试比较前，请先查看服务商的实时计算器。本地 GPU 生成令牌时没有服务商按令牌收费，但实例等待时租用时间仍会继续。

何时订阅更合适 #

每天使用托管助手的人适合订阅。 例如，Claude 当前的个人计划分为 Free、Pro 和 Max，提供不同使用上限和功能。订阅并不等同于 API 访问。它通常提供完善的界面和捆绑工具，而 API 额度提供程序化控制。

如果工作主要是交互式写作、研究、编程或文件审查，可选订阅。如果脚本、应用或代理需要按用量计费的端点，可选 API 额度。

何时 Vast.ai 更合适 #

需要开放模型、私有运行时控制或短时高吞吐量时，Vast.ai 更合适。 选择 GPU，启动实例，运行 Ollama，测试模型，完成后关闭实例。这适合 Qwen3.8 27B、解除拒答限制的变体，以及无法装进消费级笔记本的其他模型文件。

代价是运维工作。你需要确认模型正在使用 GPU、留意显存、保护对外开放的服务、保存所需模型文件，并在运行后关闭实例。低小时租金无法抵消忘记关闭实例的费用。

何时购买 GPU 更合适 #

在使用率持续、模型需求稳定且需要本地控制时，购买硬件更合适。 自购可消除租赁可用性风险并提供持久环境，也能让你在不向托管服务商发送提示词的情况下处理私密数据。

购买价格只是总成本的一部分。还要计算主机系统、电源、存储、散热、电费、更换风险和配置时间。API 额度或订阅费用较低的时期，高端显卡也可能闲置。

NVIDIA 的 RTX 4090 参考规格列出 24 GB 显存、450 W 总图形功耗，以及建议至少 850 W 的系统电源。它可作为本地推理的参考，但其 24 GB 显存低于此处测试的 27B Q4_K_M 配置。请检查模型的实际显存占用，不要仅凭参数量假设显卡能运行模型。

解除拒答限制和无审查模型 #

解除拒答限制和无审查模型变体会改变购买决策。 它们通常因拒答较少或内置限制较少而受到关注。其代价包括安全行为较弱、来源不确定、提示词格式不一致、审查需求增加，以及潜在的许可或可接受使用限制。

对于此类模型，先租用再购买。按所列价格，租用 RTX PRO 5000 一天约 $24.12，尚未计入其他费用。这足以确认模型适配性、GPU 使用情况、回答质量和运维风险。

不要将无审查模型直接暴露在公共互联网中。 应在其前方设置身份验证、速率限制、日志控制和网络隔离。不要向未经审查的模型来源发送个人、机密或受监管的数据。

如果模型成为日常工具，请把每月租金与自有工作站的总成本比较。若只是偶尔使用，租用仍然更容易停止或更换。

基准测试注意事项 #

缺失的结果本身也是结果的一部分。 N/A 表示测试未产生有效测量，不代表该 GPU 的速度低到其他显卡分数所暗示的程度。

  • 第二个 H100 实例没有产生有效测试集，因为模型下载完成得太晚。
  • 2x RTX 5060 Ti 实例被排除，因为 Ollama 将模型加载到了 CPU，而非 GPU。
  • Qwen3.8 27B 的 256k 令牌提示词未完成。 最高有效级别约为 131k 个实际提示词令牌。Llama 3.1 8B 的上下文上限为 128K，因此 256k 不受支持。
  • 排名标签没有采用请求的 num_ctx。 最终表格使用实际 prompt_eval_count 值。
  • 每种上下文的两次有效测试取解码结果中位数。 这减少了一次慢速运行的影响，但无法替代更大的测试样本。
  • 服务封装刻意保持简单。 调优后的 vLLM 或 llama.cpp 部署会产生不同排名。

最终建议 #

先租用 RTX 6000 Ada 或 RTX PRO 5000。 如果能租到每小时 $0.813 的 RTX 6000 Ada，它是预算型选择。RTX PRO 5000 的速度更高，价格仍低于 H100。长提示词、严格的交互延迟要求，或时间比租金重要的短期基准测试，可使用 H100 SXM。对于 8B 模型，如果小时租金比峰值速度更重要，值得测试 CMP 170HX。

不要在一次成功测试后就购买 GPU。 先租用一个月并运行真实工作负载，记录活跃小时数、提示词长度、并发量和模型变化，再将租金总额与完整持有成本比较。只有工作足够频繁、能让显卡持续忙碌且足够稳定，值得放弃灵活性时，才购买硬件。

偶尔使用时，API 额度或聊天订阅更简单。私有本地推理、开放模型实验或解除拒答限制的模型测试，可用 Vast.ai 降低立即购买工作站的投入。用 Llama 3.1 8B 作为低显存基线；实际部署目标是较大模型时，再使用 Qwen3.8 27B。

后续步骤 #

用你自己的提示词长度和活跃小时估算重复比较。验证 GPU 使用情况，记录模型修订版和运行时版本，每次测试后关闭实例，并在购买硬件前把月租总额与完整持有成本比较。
