ATS Resume Improverとは #

ATS Resume Improver は、ブラウザーで動作するオープンソースの履歴書最適化ツールです。履歴書を求人票と照合し、あなたの経験と応募者追跡システム（ATS）の評価基準とのギャップを埋める支援をします。React 19、Vite、TypeScriptで構築され、すべての解析と採点処理がブラウザー内で完結します。バックエンドサーバーはありません。

ソースコードは** GitHub上のATS Resume Improverリポジトリ **にあります。ホスト版を使うか、Vercel/Netlify/Cloudflare/GitHub Pagesにワンクリックで自分の環境をデプロイするか、Dockerでローカル起動できます。

解決するプライバシーの問題 #

多くの履歴書最適化サービスは履歴書を自社サーバーにアップロードし、独自の採点処理を実行してデータを保持します。ATS Resume Improverは異なる方法を採用しています。

モードデバイスから送信されるデータ
AIキーなし何も送信されません。すべてローカルで、ブラウザー内で動作します。
OpenAI / Anthropic履歴書のテキストと求人票が、あなたのキーを使ってAIプロバイダーのAPIに直接送信されます。中継サーバーはありません。
Ollama（ローカル）何も送信されません。モデルは自分のコンピューターで動作します。

APIキーはメモリ内だけに保存され、タブを閉じると消去されます。分析、追跡、Cookieはありません。

主な機能 #

AIキーなしで使える機能 #

実用的な分析にAPIキーは不要です。キーなしのモードには次の機能があります。

  • 履歴書のアップロード: PDF、DOCX、TXT、Markdown
  • ATSテキスト抽出: 書式によって失われる情報も含め、ATSがファイルから読み取る内容を正確に表示
  • 履歴書タイプ判定: 7つのプロフィールから該当するものを自動判定し、セクションの順序を調整
  • セクション判定と書式の警告: 不足セクションやパーサーが扱いにくい形式を通知
  • **ATSスコア（0～100）**と5つの評価項目
  • キーワード不足分析: 求人票とのルールベースの文字列照合
  • 決定論的なATS最適化: ローカルでルールに基づき構成を調整
  • 変更前後の差分表示: 変更内容を正確に確認
  • PDF、DOCX、TXT、Markdownへのプロ品質の書き出し

AIで利用できる機能 #

OpenAI、Anthropic Claude、またはローカルのOllamaを接続すると、次の機能が追加されます。

  • 意味に基づくキーワード分析: 単なる文字列一致ではなく文脈を理解します。一致度（強い/中程度/部分的）、一致箇所（「スキルと3つの職務で検出」）、キーワードごとの重要度（重大/高/中/低）、2～3文のAI要約を表示します
  • AIによる履歴書の最適化: ATSのベストプラクティスに基づくプロンプトで全面的に書き直します
  • AIで強化した書き出し: ダウンロード前にAIがPDF/DOCXを整形します
  • カバーレターの作成: AIらしさをなくすための文章ルールを適用します（後述）
  • 面接質問の予測: 求人票に基づいて予測します
  • 給与レンジの推定

履歴書タイプの判定 #

アプリは履歴書を7つのプロフィールのいずれかに分類し、キャリア段階に応じた採用担当者やATSの期待に合わせてセクションの順序を調整します。

プロフィール対象セクションの優先順
🏢 経験豊富な専門職5年以上、直線的なキャリア経験 → スキル → 学歴
🌱 中堅2～5年経験 → スキル → 学歴
🎓 初級0～2年スキル → 学歴 → プロジェクト → 経験
🎒 学生 / 新卒在学中学歴 → プロジェクト → スキル → 経験
🔬 研究者 / 学術職博士号、論文あり学歴 → 研究 → 論文 → 経験
📜 資格重視学位より資格が重視される資格 → スキル → 経験 → 学歴
🔄 キャリアチェンジ空白期間や転向を検出要約 → 転用可能なスキル → 学歴 → 経験

この順序は画面だけでなく、最適化とPDF、DOCX、TXT、Markdownの書き出しにも一貫して適用されます。

AIによる意味ベースのキーワード分析 #

この機能が単純なキーワードカウンターとの違いです。AIプロバイダーを設定すると、キーワード不足の分析は文字列一致から意味的な推論に切り替わります。

評価項目AIなしAIあり
照合方法完全一致のみ文脈の意味を理解
一致度—強い / 中程度 / 部分的の評価
一致の文脈—「スキルと3つの職務で検出」
不足の重要度すべての不足を同等に扱う重大 / 高 / 中 / 低
提案一般的な助言キーワードごとの具体的な提案
カバー率 %文字列数ベース意味的な重み付け
要約—2～3文のAI要約

ルールベースのローカル分析はすぐに実行されます。AIの結果は確認中に非同期で追加されます。

カバーレターを自然な文章にする #

カバーレター生成機能は、AI生成文の典型的な特徴をなくすための文章スタイルガイドを適用します。 Sabrina Ramonovの文章を自然にするフレームワーク を参考に、生成するすべてのレターに次のルールを適用します。

  • emダッシュを使わない: 最も目立つAIの特徴を完全に取り除きます
  • 50以上の禁止語句: leverage, utilize, dive deep, delve, embark, game-changer, groundbreaking, cutting-edge, pivotal, tapestry, harness, moreover, in conclusion, it’s worth noting, ever-evolving, landscape, testament, not only…but also など
  • レター本文にMarkdownを使わない: 太字用のアスタリスク、ハッシュタグ、セミコロンは使いません
  • 原則として能動態: 動作主が本当に重要でない場合だけ受動態を使います
  • 短縮形を必須にする: “I’ve”, “I’m”, “it’s"を使い、“I have”, “I am”, “it is"は使いません
  • 文の長さに変化をつける: 短く力強い文と長めの文を組み合わせます
  • 中身のない導入を避ける: “It’s important to note that X"ではなく、単に"X"と書きます
  • 第1段落に求人票の具体的な情報を入れる: テンプレートでないことを示します

ルールにより自然な文章を書くようモデルに求めるため、人が書いたような結果になります。

実際の使い方 #

手順1: 履歴書をアップロード #

PDF、DOCX、TXT、Markdownファイルをアップロードします。**“What the ATS Sees”**タブで、パーサーが内容を正しく抽出したか確認してください。この画面でセクションが欠けたり崩れたりしていれば、採用担当者のATSでも同じ問題が起きます。

手順2: 求人票を貼り付け #

求人票全体をJob Descriptionパネルに貼り付けます。内容が充実しているほどキーワード分析の精度が上がるため、応募条件のセクションを削らないでください。

手順3: ATSスコアを確認 #

スコアパネルには0～100の総合スコアと5項目の内訳が表示されます。内訳を見ると改善点がわかります。書式の問題はある項目を下げ、キーワード不足は別の項目を下げ、職務経歴の説明が弱いとさらに別の項目が下がります。

手順4: キーワード不足を確認 #

Keyword Analysisでは、求人票のキーワードのうち履歴書にあるものと不足しているものを確認できます。AIを有効にすると、意味ベースの一致と重要度が表示されます。中核となる技術スキルの「重大」な不足は、一般的なソフトスキル用語の「低」な不足より優先して対応します。

手順5: 最適化 #

  • 決定論的モード: ルールに基づいて構成を調整します。安全で高速、API費用もかかりません。
  • AIモード: ATSのベストプラクティスを使ってLLMが全体を書き直します。

変更を適用する前に変更前後の差分を確認し、内容を把握してください。

手順6: 書き出し #

PDF、DOCX、TXT、Markdownで書き出せます。AIを有効にすると、プロらしい見栄えになるよう書き出しを整形します。PDFテンプレートは適切な書体と採用担当者に馴染みのあるレイアウトを使います。

履歴書のヒントとの連携 #

ツールには補足資料RESUME_TIPS.md（GitHubリポジトリにもあります）が含まれます。次の内容を解説します。

  • ATSが履歴書を実際にどう採点するか
  • 重要な書式ルールとパーサーを壊す形式
  • 効果的な要約、箇条書き、スキル欄の書き方
  • キーワードを詰め込まずに使う方法
  • カバーレターのトーンと構成
  • 送信前のチェックリスト

スコアの意味を理解するため、ツールを使う前に読んでください。

よくある質問 #

ツールは履歴書を保存しますか？ #

いいえ。アプリは完全にクライアント側で動作します。サーバーには何も保存されません。セッションデータはブラウザーのメモリにあり、タブを閉じると消去されます。

履歴書のスコアが低いです。心配すべきですか？ #

ATSスコアは合否判定ではなく、改善の目安です。スコアが60でもATSが不採用にするという意味ではありません。分析対象の求人票と履歴書の間に、測定可能なギャップがあることを示します。判定結果ではなく、編集の優先順位を決めるために使ってください。

複数の求人票に使えますか？ #

はい。いつでも新しい求人票を貼り付けられます。新しい求人票に対してキーワード分析と最適化が再実行されます。各分析は独立しています。

Ollama連携は本当にオフラインですか？ #

Ollamaが自分のコンピューター、またはローカルネットワーク内のコンピューターで動作していればオフラインです。アプリはHTTPでOllamaにテキストを送ります。外部サービスには送信しません。

履歴書タイプの判定精度はどの程度ですか？ #

判定器はルールベースのヒューリスティックを使い、記載された経験年数、学歴の指標、論文や研究のセクション、キャリアの空白を示す兆候を調べます。多くの履歴書では適切に動きますが、特殊な経歴では誤判定する場合があります。適用されたセクションの順序はいつでも変更できます。

結論 #

ATS Resume Improverは、データを第三者に預けずに本格的な履歴書分析を行うというニーズに応えます。キーなしモードでも、書式やキーワードの網羅性についてすぐに実用的なフィードバックが得られます。AIキーを追加すれば、意味的な推論、カバーレター作成、面接準備も使えます。分析1回あたり数セント、Ollamaなら完全無料です。

ホスト版は** ATS Resume Improverのライブ版 で利用できます。全ソースコードは GitHub上のATS Resume Improverリポジトリ **にあります。

自分の就職活動向けにセルフホストする場合も、特定の業界に合わせて採点の重みやプロンプトを変更する場合も、Dockerの設定と整理されたプロジェクト構成により、フォークして調整しやすくなっています。

履歴書最適化コース #

このツールの評価内容を段階的に実践するためのガイドが必要なら、関連コースを読んでください。

履歴書最適化コース: ATSを攻略して面接の機会を増やす — ATS採点、書式、箇条書き、キーワード、求人に合わせた調整、カバーレター、送信前チェックを扱う9つのモジュールです。各手順ですぐにフィードバックを得られるよう、コースとツールを併用してください。
