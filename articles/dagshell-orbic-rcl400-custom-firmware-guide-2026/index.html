DagShellとは #

概要 #

DagShellは、Orbic RCL400の標準ウェブインターフェースを包括的なセキュリティツールキットに置き換えるオープンソースファームウェアです。次の機能があります。

  • ASCIIアートとハッカー風デザインを備えたターミナル風インターフェース
  • 自己署名証明書を使うTLS 1.2+暗号化ウェブインターフェース
  • TTLマスキング、MACスプーフィング、DNSベースの広告ブロックなどのプライバシーツール
  • アクティブ接続、ルーティングテーブル、DNSクエリのネットワーク監視
  • IMSIキャッチャー検出、ポートスキャン、ARP探索向けのハッキングツール
  • Evil Twin AP、認証ポータル（キャプティブポータル）を使ったフィッシング、デオーセンティケーション攻撃などの攻撃機能
  • Wigle互換CSVエクスポートを使ったGPS追跡とウォードライビング
  • GPS、Bluetoothスキャン、Wi-Fi探索に使うRaspberry Piコンパニオン
  • ブラウザ内ファイルマネージャーによるファイルシステムアクセス
  • ATコマンドによるSMS機能
  • 永続化。DagShellは起動時に自動実行されます

技術仕様 #

プラットフォーム: Orbic RCL400モバイルホットスポット
アーキテクチャ: ARM Linux (カーネル3.18)
言語: C/C++ (静的ARMバイナリ)
暗号化: 自己署名証明書によるTLS 1.2+ (2階層PKI)
ウェブサーバー: 独自の組み込みHTTPSサーバー (ポート8443)
インターフェース: ブラウザベースのターミナルインターフェース
ライセンス: MIT (オープンソース)
GitHub: github.com/dagnazty/DagShell

ビジュアルデザイン #

DagShellはレトロなハッカー風デザインを採用しています。

  • 各ページにASCIIロゴを表示
  • 黒い背景に緑色の文字を使ったMatrix風の配色
  • 等幅フォント (Fira Code)
  • 走査線効果と光る文字
  • ターミナルを意識したレイアウト

機能の詳細 #

🏠 ダッシュボード #

システム概要:

  • 稼働時間表示。端末の起動後の経過時間
  • ATコマンドインターフェース。上級者向けのモデム直接制御
  • クイックステータス。IPアドレスと接続状態

ATコマンドでモデムを低レベルで制御できます。

ATコマンドの例：
AT+CSQ       - 信号品質
AT+COPS?     - 現在のネットワーク事業者
AT+CREG?     - ネットワーク登録状態
AT+CIMI      - IMSIを取得（加入者識別情報）
AT+CGSN      - IMEIを取得（端末識別子）

🌐 ネットワークツール #

現在のネットワーク情報:

  • IPアドレスとインターフェースの詳細
  • サブネットマスク、ゲートウェイ、ブロードキャストアドレス
  • ネットワーク統計 (送受信パケット数)

ルーティングテーブルビューアー:

  • すべてのネットワークルートを表示
  • デフォルトゲートウェイの情報
  • インターフェースの対応関係

アクティブ接続モニター:

  • すべてのTCP/UDP接続をリアルタイムで一覧表示
  • ローカルとリモートのIPアドレス
  • ポート番号と接続状態
  • 端末が通信している相手の監視に役立ちます

🔒 プライバシー保護機能 #

TTL補正 #

目的: ホットスポット通信を通信事業者の検出から隠します。

仕組み:

  • IPパケットのTime To Live (TTL)値を65に変更します
  • 事業者はTTLの減少でテザリングを検出します (電話は64、接続端末は63)
  • TTLを65に設定すると、すべての通信が端末内の通信に見えるようになります

用途: 事業者によるテザリング制限や速度制限の回避。

コマンド:

# TTL 修正を有効化
iptables -t mangle -A POSTROUTING -j TTL --ttl-set 65

# TTL 修正を無効化
iptables -t mangle -D POSTROUTING -j TTL --ttl-set 65

MACアドレススプーフィング #

目的: プライバシー保護のため端末のMACアドレスをランダム化します。

仕組み:

  • Wi-Fiインターフェース wlan0 のMACアドレスを変更
  • ランダムなMACアドレスを生成するか、任意の値を設定
  • セッション間で端末を追跡されにくくします

用途: 接続先ネットワークによるMACアドレス追跡の防止。

手順:

  1. インターフェースを停止
  2. 新しいMACアドレスを適用
  3. インターフェースを再度起動
  4. 接続を再確立

DNSベースの広告ブロック #

目的: DNSレベルで広告とトラッカーをブロックします。

仕組み:

  • ブロックリストで/etc/hostsファイルを変更
  • リスト内のドメインを127.0.0.1 (localhost) に解決
  • 接続中のすべての端末の広告をブロック

用途: 各端末を個別設定せず、ネットワーク全体で広告をブロックします。

ブロックリストの提供元: 一般的な広告・追跡ドメイン。リストはカスタマイズできます。

📱 SMS管理 #

SMSの送信:

  • モデムへのATコマンドでテキストメッセージを送信
  • リモート通知やテストに便利

メッセージの表示:

  • Orbic標準の受信トレイへのリンク
  • 受信したSMSを読む

使用するATコマンド:

AT+CMGS="PHONE_NUMBER"
ここにメッセージ本文^Z

🔧 ハッキングツール #

IMSIキャッチャー検出器 #

目的: 携帯電話基地局の情報を監視し、IMSIキャッチャー/Stingrayを示す異常を検出します。

仕組み:

  • モデムから基地局データを取得します:
    • Cell ID (基地局識別子)
    • LAC (位置エリアコード)
    • MCC/MNC (国・携帯通信網コード)
    • 信号強度 (RSSI)
    • ネットワーク世代 (2G/3G/4G)
  • 変化を記録し、疑わしい基地局切り替えを検出
  • 基準値を追跡し、地域内の通常の基地局を把握

検出の兆候:

  • 端末が静止しているのに基地局が突然切り替わる
  • 2Gへダウングレードする (IMSIキャッチャーは暗号化を無効にするため2Gを強制することがあります)
  • 未知のCell IDが現れる
  • 偽基地局からの弱い信号
  • 頻繁な再接続

RayHunterとの相乗効果: DagShellは基地局を監視し、RayHunterはより高度な解析で専用のIMSIキャッチャー検出を行います (後述のセクションを参照)。

ポートスキャナー #

目的: 対象IPアドレスの開放ポートをスキャンします。

仕組み:

  • TCP SYNスキャン。対象ポートへSYNパケットを送信
  • タイムアウト検出。ポートが開放、閉鎖、またはフィルター済みかを判定
  • 範囲指定。単一ポートまたはポート範囲をスキャン

用途:

  • ネットワーク偵察
  • IoT端末の検出
  • ローカルネットワークのセキュリティ監査
  • サービスの識別

コマンド:

# target のポート 1～1000 をスキャン
nc -zv -w 2 TARGET_IP 1-1000 2>&1

ファイアウォール管理 #

目的: iptablesでIPアドレスをブロックまたは解除します。

仕組み:

  • 指定したIPとの送受信パケットをDROPするiptablesルール
  • 保存すれば再起動後も有効な永続ルール
  • 許可リスト/ブロックリスト機能

用途:

  • 悪意あるIPのブロック
  • 不正アクセスの防止
  • トラフィック制御/フィルタリング
  • ペアレンタルコントロール

コマンド:

# IP をブロック
iptables -I INPUT -s IP_ADDRESS -j DROP
iptables -I OUTPUT -d IP_ADDRESS -j DROP

# IP のブロックを解除
iptables -D INPUT -s IP_ADDRESS -j DROP
iptables -D OUTPUT -d IP_ADDRESS -j DROP

⚔️ 攻撃ツール #

重要な法的免責事項: これらのツールは許可を得たセキュリティテストのみを目的としています。所有していないネットワークや、明示的な書面の許可を得ていないネットワークに対して使うことは、多くの法域で違法です (米国のComputer Fraud and Abuse Act、英国のComputer Misuse Actなど)。自分のネットワークまたは管理されたラボ環境でのみ使用してください。

DNSスニファー #

目的: 接続クライアントからのDNSクエリを記録します。

仕組み:

  • DNSポート53をiptablesでログ記録
  • プロミスキャスモードは不要
  • ホットスポットのクライアントからのDNS要求をすべて記録
  • クライアントがアクセスしているウェブサイトやサービスを把握

用途 (許可を得た場合):

  • ネットワークトラフィック分析
  • ペアレンタルモニタリング (自分の家族)
  • 自分の端末でのセキュリティ調査
  • マルウェアの挙動分析

接続クライアントが訪問したドメインなどのメタデータを取得します。所有または管理するネットワークでのみ使用してください。

ARPスキャナー #

目的: ローカルネットワーク上の端末を検出します。

仕組み:

  • サブネット内のすべてのIPにARP要求を送信
  • 端末は自身のMACアドレスを応答
  • OUI検索でメーカーを特定 (Apple、Samsungなど)
  • 稼働中の端末のネットワークマップを作成

用途:

  • ネットワーク資産の棚卸し
  • 未知の端末の検出
  • BYODネットワーク分析
  • IoT端末の検出

出力例:

IP: 192.168.1.50
MAC: A4:83:E7:XX:XX:XX
Vendor: Apple, Inc.

IP: 192.168.1.75
MAC: 2C:54:91:XX:XX:XX
Vendor: Samsung Electronics

Traceroute #

目的: 宛先までのネットワーク経路を可視化します。

仕組み:

  • TTLを段階的に増やしたパケットを送信
  • 各ホップでTTLが減少し、ICMP Time Exceededが返る
  • 宛先までのルーターと経路を表示
  • 各ホップの**往復時間 (RTT)**を計測

用途:

  • ネットワークのトラブルシューティング
  • 経路分析
  • 遅延の診断
  • ISPピアリングの調査

Evil Twin AP #

目的: 既存SSIDを複製した偽のWi-Fiアクセスポイントを作成します。

仕組み:

  • wlan1を使用 (Piコンパニオンで利用可能な場合は2つ目のWi-Fiインターフェース)
  • 対象ネットワークのSSIDと暗号化方式を複製
  • 接続しようとするクライアントを捕捉
  • 認証情報を取得するための認証ポータルを表示

攻撃シナリオ (ラボ環境):

  1. 正規のWi-Fiネットワークをスキャン
  2. 同じSSIDの偽APを作成
  3. デオーセンティケーション攻撃でクライアントを正規APから切断
  4. クライアントが偽APへ自動再接続
  5. 認証ポータルで認証情報を取得

検出方法: 両方のAPが同時に見える場合、クライアントに同じSSIDが重複して表示されます。

認証ポータル #

目的: 認証情報を取得するためのフィッシングページテンプレートです。

収録テンプレート:

  • ISPやホテル風の一般的なWi-Fiログインページ
  • Facebook、Twitter、Instagramに似せたソーシャルメディアログイン
  • 企業ログインポータル
  • 空港やコーヒーショップのWi-Fiゲート

仕組み:

  1. Evil Twin APがすべての通信をポータルへ転送
  2. クライアントにログインページを表示
  3. クライアントが認証情報を入力
  4. 認証情報をファイルに記録
  5. クライアントにインターネットを許可するか、エラーを表示

教育目的: ソーシャルエンジニアリングのリスクと、URL確認の重要性を示します。

📍 GPSトラッカーとウォードライビング #

GPS機能 #

GPSソース: Raspberry Piコンパニオンのみ

  • Orbic RCL400にはGPSが内蔵されていません。Piコンパニオンを使わない場合、位置情報は取得できません。
  • PiにUSB GPSドングル (U-Blox 7チップセット) を接続
  • 共有データファイルを介してPiからOrbicへ座標を送信
  • ECEFから緯度・経度への変換を自動処理

ダッシュボード表示:

  • 緯度/経度 (10進度)
  • 海抜高度
  • GPS測位状態 (精度)
  • 5秒ごとの自動更新
  • ブラウザの位置情報確認は表示されません (ブラウザAPIを使わないため)

共有GPS状態:

  • GPSデータはすべてのDagShellプロセスで利用可能
  • ウォードライビングはGPSを自動使用
  • 各機能は互いに競合しません

ウォードライビングモード #

目的: GPS座標付きでWi-Fiネットワークをスキャンし、マッピングします。

仕組み:

  1. 有効なGPS測位を待機 (0,0座標は記録しません)
  2. 連続ループで5秒ごとにWi-Fiネットワークをスキャン
  3. ネットワークデータを記録:
    • SSID (ネットワーク名)
    • BSSID (MACアドレス)
    • 暗号化方式 (WPA2、WPA3、Open)
    • 信号強度 (RSSI、dBm)
    • チャンネル番号
    • GPS座標 (緯度/経度)
    • タイムスタンプ
  4. Wigle互換CSV形式でエクスポート

Wigleとの連携:

  • WiGLE (wigle.net) は世界規模のWi-Fiマッピングプロジェクトです
  • DagShellのCSVはWiGLEへそのままアップロード可能です
  • 外部ツールなしで、Filesページからブラウザでアップロードできます
  • Wi-Fiの位置情報を含む公開データベースに情報を提供します

用途:

  • Wi-Fiカバレッジのマッピング
  • ISP向けのネットワーク調査
  • 信号強度分析
  • セキュリティ調査 (オープンネットワークや弱い暗号化)
  • 位置情報に基づく分析

CSV形式の例:

MAC,SSID,AuthMode,FirstSeen,Channel,RSSI,Latitude,Longitude,AltitudeMeters

🥧 Raspberry Piコンパニオン #

Raspberry Piコンパニオンは、外部ハードウェアを使ってDagShellの機能を拡張します。

ハードウェア要件 #

最低要件:

  • **Raspberry Pi 3B+**以降 (Pi Zeroは周辺機器へ十分なUSB電力を供給できません)
  • USB GPSドングル (U-Blox 7チップセットを推奨)
  • 電源 (Piには別電源が必要です。OrbicのUSBポートだけでは電力が不足します)

オプション:

  • Wi-Fiアダプター (接続を維持しながらスキャンするための2つ目のインターフェース)
  • Bluetoothドングル (Pi内蔵Bluetoothの性能が低い場合)

GPSモジュール (U-Blox 7) #

接続: USB GPSドングルをPiに接続
プロトコル: シリアル経由のNMEAセンテンス
変換: PiがECEFを緯度/経度へ自動変換
データ共有: Orbic上の共有ファイルにGPS座標を書き込み

センテンスの解析:

$GPGGA,123519,4807.038,N,01131.000,E,1,08,0.9,545.4,M,46.9,M,,*47
       |       |          |           |  |  |   |
       時刻  緯度  経度  測位状態  衛星数  高度

Bluetoothスキャン (BLE) #

目的: 近くのBluetooth端末を検出します。

仕組み:

  • BLEアドバタイズをスキャン
  • MACアドレスを取得
  • OUI検索でメーカーを特定
  • CSV形式で記録

リモート操作:

  • DagShellウェブUIからスキャンを開始/停止
  • PiへSSH接続する必要はありません
  • ステータスをリアルタイムで更新

用途:

  • 端末の追跡と台数計測
  • 通行量分析
  • Bluetooth端末の検出
  • IoTセキュリティ調査

CSV出力:

Timestamp,MAC,RSSI,Name,Manufacturer
2026-05-28 10:30:15,AA:BB:CC:DD:EE:FF,-65,Fitbit Charge,Fitbit Inc.

Wi-Fiスキャン #

目的: PiでWi-Fiネットワークをスキャンし、Orbicへデータを送信します。

利点: Orbicがホットスポットを維持しながら、専用インターフェースでスキャンできます。

仕組み:

  • Piで2つ目のWi-Fiアダプター、または接続に使っていない場合は内蔵Wi-Fiを使用
  • 全チャンネルをスキャン (2.4GHzは1～14、対応する場合は5GHzの36～165)
  • 共有ストレージ経由で結果をOrbicへ送信
  • DagShellがウォードライバーCSVへ記録

連携:

  • PiとOrbicがGPSタイムスタンプで同期
  • 重複記録を防止
  • 両方のスキャンデータを1つのログに統合

デオーセンティケーション攻撃 #

目的: (ラボでのテストとして) Wi-Fiネットワークからクライアントを切断します。

仕組み:

  • 802.11デオーセンティケーションフレームを送信
  • APのMACアドレスを偽装
  • クライアントはAPから「切断」の通知を受信
  • クライアントが接続を切り、再接続を試行

操作方法:

  • 単発のデオーセンティケーション: フレームを1回送信
  • 継続的なデオーセンティケーション: 再接続を妨害 (DoS)
  • リモート操作: DagShellのスキャンページから実行

用途 (許可を得た場合):

  • 自分のネットワークからの不正端末の除去
  • 許可を得たペネトレーションテスト
  • ラボでのEvil Twin攻撃 (クライアントを偽APへ誘導)

⚠️ 法的警告: 所有していないネットワークへのデオーセンティケーション攻撃は違法です。FCC規則違反やCFAA違反に問われる可能性があります。

セキュリティ証明書の警告 #

DagShellへアクセスすると、**「安全ではありません」または「信頼されていません」**という警告が表示されます。

デスクトップブラウザー:

  • **「詳細設定」**をクリック
  • **「192.168.1.1に進む (安全ではありません)」**をクリック

モバイルブラウザー:

  • **「詳細を表示」**をタップ
  • **「このウェブサイトにアクセス」**をタップ

警告が表示される理由:

  • 証明書は自己署名です (Let’s Encryptのような信頼されたCAが発行したものではありません)
  • 端末の信頼ストアにルート証明書がありません
  • カスタムファームウェアでは想定された動作であり、侵害を意味しません。

接続は本当に安全ですか?:

  • はい。接続はTLS 1.2+で暗号化されています
  • データを傍受できません
  • 証明書が公開CAの信頼チェーンにつながらないだけで、暗号化は有効です。

オプション: root.derを端末の信頼ストアにインストールすると警告が消えます。

トラブルシューティング #

インストール時の問題 #

問題: enable_shell.pyが接続に失敗する

解決方法:

  • OrbicのWi-Fiに接続していることを確認
  • IPアドレスが192.168.1.1 (既定値) であることを確認
  • 管理者パスワードを再入力 (大文字と小文字を区別)
  • ポート80にアクセスできるか確認: telnet 192.168.1.1 80

問題: ファームウェアのアップロードに失敗する

解決方法:

  • まずRoot Shellを有効化 (enable_shell.pyが成功していること)
  • ネットワークが安定していることを確認 (可能なら有線接続を使用)
  • deploy_base64.pyの代わりにdeploy_net.pyを試す
  • /dataパーティションの空き容量を確認: df -h /data

問題: 証明書の警告が消えない

解決方法:

  • 自己署名証明書では通常の動作です。接続は引き続き暗号化されています。
  • 毎回「詳細設定」->「続行」をクリック
  • オプション: root.derを端末の信頼ストアへインストール (上級者向け)

実行時の問題 #

問題: 起動時にDagShellが開始しない

解決方法:

  • 起動スクリプトを確認: ls -la /etc/rc.d/dagshell_boot.sh
  • 実行可能か確認: chmod +x /etc/rc.d/dagshell_boot.sh
  • ログを確認: logread | grep dagshell
  • 手動で起動: /data/orbic_app &

問題: GPSが動作しない

解決方法:

  • Piコンパニオンが動作しているか確認: systemctl status pi-companion
  • GPSが衛星を捕捉しているか確認: cgps -s (Pi上で実行)
  • GPSドングルが接続されているか確認: lsusb
  • コールドスタートではGPS測位まで5～10分待ちます。初回起動時は屋外でも時間がかかります。

問題: ウォードライビングの記録が行われない

解決方法:

  • 開始前にGPS測位を確認
  • /dataへの書き込み権限を確認
  • CSVファイルが作成されているか確認: ls -la /data/wardrive_log.csv
  • Wi-Fiインターフェースが起動しているか確認: ifconfig wlan0

問題: PiコンパニオンがOrbicと通信しない

解決方法:

  • ネットワーク接続を確認: ping 192.168.1.1
  • 設定ファイルのIPが正しいことを確認
  • ポート8443が開いているか確認: telnet 192.168.1.1 8443
  • Piコンパニオンのログを確認: journalctl -u pi-companion

パフォーマンスの問題 #

問題: ウェブインターフェースが遅い、または反応しない

解決方法:

  • ブラウザーのキャッシュを消去
  • ブラウザーの拡張機能を無効化 (広告ブロッカーが干渉する場合があります)
  • Wi-Fiではなく有線でOrbicに接続
  • DagShellを再起動: killall orbic_app && /data/orbic_app &

問題: ウォードライビングのスキャンに時間がかかる

解決方法:

  • 設定でスキャン間隔を長くする (頻度と性能を調整)
  • スキャンするチャンネル数を減らす
  • GPS測位が弱いとスキャンが遅くなります。有効な座標が得られるまで記録を待つためです。
