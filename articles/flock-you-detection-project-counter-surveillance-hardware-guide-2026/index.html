परिचय: ओपन सोर्स काउंटर-सर्विलांस #

Flock-You प्रोजेक्ट Flock Safety के ALPR सर्विलांस बुनियादी ढांचे का पता लगाने और मैपिंग के लिए एक ओपन-सोर्स, समुदाय-संचालित पहल है। GitHub पर colonelpanichacks/flock-you पर होस्ट किया गया, यह प्रोजेक्ट Flock कैमरों को उनके WiFi नेटवर्क सिग्नेचर के माध्यम से पहचानने के लिए किफायती ESP32-आधारित हार्डवेयर का उपयोग करता है।

यह व्यापक गाइड Flock डिटेक्शन के पीछे की तकनीकी पद्धति से लेकर तीन हार्डवेयर प्लेटफॉर्म के लिए चरण-दर-चरण सेटअप निर्देश, फर्मवेयर इंस्टॉलेशन, और अधिकृत विक्रेताओं से खरीद जानकारी तक सब कुछ कवर करती है। चाहे आप गोपनीयता समर्थक हों, सुरक्षा शोधकर्ता हों, या चिंतित नागरिक हों, यह गाइड आपको अपना स्वयं का डिटेक्शन डिवाइस बनाने या खरीदने में सक्षम बनाएगी।

इस तकनीक के महत्व और व्यापक सर्विलांस परिदृश्य के संदर्भ के लिए, हमारा साथी लेख पढ़ें: Flock Safety कैमरा सर्विलांस: प्रसार, गोपनीयता चिंताएं, और सुरक्षा रणनीतियां ।

क्या आप देखना चाहते हैं कि Flock कैमरों को पहले ही कहां मैप किया जा चुका है? Flock Finder एक ओपन-सोर्स उपकरण है जो WiGLE WiFi डेटा और OUI फिंगरप्रिंटिंग का उपयोग करके दुनिया भर में 40,000+ संदिग्ध Flock Safety कैमरों को प्लॉट करता है — प्रतिदिन अपडेट होता है। स्रोत GitHub पर।

Flock-You डिटेक्शन पद्धति को समझना #

तकनीकी आधार #

Flock Safety कैमरों में कनेक्टिविटी और रिमोट मैनेजमेंट के लिए एम्बेडेड WiFi मॉड्यूल होते हैं। ये मॉड्यूल पहचाने जाने योग्य नेटवर्क सिग्नेचर प्रसारित करते हैं जो प्रोमिस्क्यूअस WiFi मॉनिटरिंग मोड में काम करने वाले डिवाइसों द्वारा पता लगाए जा सकते हैं। Flock-You प्रोजेक्ट इस विशेषता का उपयोग इस प्रकार करता है:

1. WiFi OUI (संगठनात्मक अद्वितीय पहचानकर्ता) डिटेक्शन #

प्रत्येक नेटवर्क इंटरफ़ेस में एक MAC एड्रेस होता है जिसमें शामिल हैं:

  • पहले 3 बाइट (24 बिट): OUI, जो निर्माता की पहचान करता है

2. वाइल्डकार्ड प्रोब रिक्वेस्ट डिटेक्शन #

Flock कैमरे समय-समय पर उपलब्ध नेटवर्क खोजने के लिए वाइल्डकार्ड प्रोब रिक्वेस्ट भेजते हैं। इनकी विशिष्ट विशेषताएं हैं:

  • 802.11 मैनेजमेंट फ्रेम: Type=0, Subtype=4
  • SSID इनफॉर्मेशन एलिमेंट: Length=0 (खाली/वाइल्डकार्ड)
  • फ्रेम संरचना: प्रोब टाइमिंग में पूर्वानुमानित पैटर्न
  • वेंडर-स्पेसिफिक IEs: फ्रेम पेलोड में अतिरिक्त संकेतक

डिटेक्शन फर्मवेयर इन प्रोब रिक्वेस्ट पैटर्न का विश्लेषण करता है ताकि सरल OUI मिलान से परे Flock कैमरा पहचान में विश्वास बढ़ाया जा सके।

3. प्रोमिस्क्यूअस मोड WiFi मॉनिटरिंग #

मानक WiFi ऑपरेशन केवल आपके डिवाइस को संबोधित फ्रेम प्राप्त करता है। प्रोमिस्क्यूअस मोड रेंज के भीतर सभी WiFi फ्रेम कैप्चर करता है:

  • 802.11 फ्रेम संरचना: addr1, addr2, addr3 फ़ील्ड का विश्लेषण
  • मैनेजमेंट फ्रेम: प्रोब रिक्वेस्ट, बीकन फ्रेम, एसोसिएशन रिक्वेस्ट
  • डेटा फ्रेम: नेटवर्क व्यवहार पैटर्न प्रकट करते हैं
  • कंट्रोल फ्रेम: ACKs, RTSs, CTSs समय की जानकारी प्रदान करते हैं

ESP32 माइक्रोकंट्रोलर esp_wifi API के माध्यम से प्रोमिस्क्यूअस मोड का समर्थन करते हैं, जो कम लागत वाले डिटेक्शन हार्डवेयर को सक्षम बनाता है।

4. सिग्नल शक्ति विश्लेषण #

डिटेक्शन डिवाइस RSSI (रिसीव्ड सिग्नल स्ट्रेंथ इंडिकेटर) मापते हैं:

  • पता लगाए गए कैमरों की दूरी अनुमान
  • कई मापों के साथ स्थानों का त्रिकोणीकरण
  • अपेक्षित सिग्नल विशेषताओं के आधार पर झूठी सकारात्मकताओं को फ़िल्टर करना
  • कैमरा घनत्व के हीट मैप बनाना

डिटेक्शन सटीकता और झूठी सकारात्मकताएं #

Flock-You पद्धति उच्च सटीकता प्राप्त करती है:

  • सही सकारात्मक दर: रेंज में पुष्टि किए गए Flock कैमरों के लिए ~95%
  • झूठी सकारात्मक दर: पर्यावरण के आधार पर ~5-10%
  • डिटेक्शन रेंज: बाधाओं और एंटीना के आधार पर 50-300 फीट
  • कॉन्फिडेंस स्कोरिंग: बहु-कारक विश्लेषण झूठे अलार्म को कम करता है

सामान्य झूठी सकारात्मकता स्रोत:

  • ESP32 डेवलपमेंट बोर्ड जो अन्य IoT डिवाइसों में उपयोग किए जाते हैं
  • कमर्शियल ESP32-आधारित उत्पाद (स्मार्ट होम, सेंसर)
  • समान घटकों का उपयोग करने वाले अन्य सर्विलांस कैमरे
  • WiFi परीक्षण उपकरण जो तकनीशियनों द्वारा संचालित होते हैं

शमन रणनीतियां:

  • मल्टी-सिग्नेचर डिटेक्शन: OUI + प्रोब पैटर्न + भौतिक सत्यापन का संयोजन
  • स्थान सहसंबंध: ज्ञात कैमरा स्थानों के साथ क्रॉस-रेफरेंसिंग
  • दृश्य पुष्टि: इलेक्ट्रॉनिक डिटेक्शन के बाद भौतिक निरीक्षण
  • सामुदायिक डेटाबेस: डिटेक्शन का क्राउडसोर्स्ड सत्यापन

1. DIY ESP32 बिल्ड ($5-12) #

अवलोकन: ओपन-सोर्स फर्मवेयर के साथ मानक ESP32 डेवलपमेंट बोर्ड का उपयोग करके सबसे किफायती विकल्प।

हार्डवेयर विशेषताएं:

  • माइक्रोकंट्रोलर: ESP32-WROOM-32 या समान (ड्यूल-कोर, 240MHz)
  • WiFi: 802.11 b/g/n, प्रोमिस्क्यूअस मोड सक्षम
  • मेमोरी: 520KB SRAM, 4MB+ Flash
  • डिस्प्ले: वैकल्पिक (ऑनबोर्ड LED पर्याप्त)
  • पावर: USB-पावर्ड या बैटरी पैक
  • बज़र: वैकल्पिक पैसिव बज़र मॉड्यूल (KY-006)
  • इंडिकेटर: ऑनबोर्ड LED + वैकल्पिक बज़र
  • विस्तारणीयता: ब्रेडबोर्ड-फ्रेंडली, आसान संशोधन

फर्मवेयर: simeononsecurity/flock-you-esp32 पर ओपन-सोर्स फोर्क:

  • मानक ESP32 हार्डवेयर (GPIO 25, 2, 17) के लिए संशोधित
  • Super Mario Bros. स्टार्टअप धुन (बज़र काम करने की पुष्टि करती है)
  • नए डिटेक्शन पर दो तेज़ आरोही बीप
  • ट्रैकिंग सक्रिय होने पर 10-सेकंड हार्टबीट बीप
  • GPS वारड्राइविंग के लिए Flask डैशबोर्ड समर्थन
  • JSON, CSV, KML फॉर्मेट में एक्सपोर्ट

बिल्ड विकल्प:

मुख्य डिटेक्शन एल्गोरिदम (सरलीकृत) #

तकनीकी कार्यान्वयन में रुचि रखने वालों के लिए, यहां डिटेक्शन लॉजिक का एक सरलीकृत दृश्य है:

// Flock-You Detection Core (Conceptual - not full code)

// OUI Database (31 known Flock-associated OUIs)
const uint8_t FLOCK_OUI_LIST[][3] = {
    {0xD4, 0xAD, 0xFC}, // Espressif ESP32-S3
    {0xAC, 0x67, 0xB2}, // Espressif ESP32-WROOM
    {0x84, 0xF3, 0xEB}, // Espressif ESP32-S3 variant
    // ... 28 more OUIs ...
};

// Promiscuous mode callback
void wifi_sniffer_callback(void* buf, wifi_promiscuous_pkt_type_t type) {
    wifi_promiscuous_pkt_t *pkt = (wifi_promiscuous_pkt_t*)buf;
    
    // Extract MAC address from frame
    uint8_t *mac = pkt->payload + 10; // addr2 field position
    
    // Check against OUI database
    for (int i = 0; i < NUM_OUIS; i++) {
        if (memcmp(mac, FLOCK_OUI_LIST[i], 3) == 0) {
            // OUI match found
            int rssi = pkt->rx_ctrl.rssi;
            
            // Check signal strength threshold
            if (rssi > RSSI_THRESHOLD) {
                // Analyze frame for additional signatures
                if (is_wildcard_probe_request(pkt)) {
                    // High confidence detection
                    trigger_alert(mac, rssi, HIGH_CONFIDENCE);
                } else {
                    // OUI match only
                    trigger_alert(mac, rssi, MEDIUM_CONFIDENCE);
                }
            }
        }
    }
}

// Wildcard probe detection
bool is_wildcard_probe_request(wifi_promiscuous_pkt_t *pkt) {
    // Management frame, subtype probe request
    if ((pkt->payload[0] & 0x0F) != 0x04) return false;
    
    // Check for empty SSID IE (wildcard)
    // Position depends on frame structure
    uint8_t *ie = &pkt->payload[24]; // Start of IEs
    if (ie[0] == 0x00 && ie[1] == 0x00) {
        return true; // Wildcard probe
    }
    return false;
}

मुख्य तकनीकी अवधारणाएं समझाई गईं #

प्रोमिस्क्यूअस मोड: केवल आपके डिवाइस को संबोधित फ्रेम प्राप्त करने के बजाय, ESP32 रेंज में सभी WiFi फ्रेम कैप्चर करता है। यह आस-पास के उन डिवाइसों का पता लगाने के लिए आवश्यक है जो आपके डिटेक्टर के साथ संचार नहीं कर रहे।

MAC एड्रेस संरचना: प्रत्येक WiFi फ्रेम में कई MAC एड्रेस होते हैं:

  • addr1: रिसीवर एड्रेस
  • addr2: ट्रांसमीटर एड्रेस (OUI शामिल)
  • addr3: अंतिम गंतव्य/स्रोत का एड्रेस

RSSI (रिसीव्ड सिग्नल स्ट्रेंथ इंडिकेटर): dBm में सिग्नल शक्ति (1 मिलीवाट के सापेक्ष नकारात्मक डेसिबल)। सामान्य मान:

  • -30 dBm: अत्यधिक मज़बूत (बहुत पास)
  • -50 dBm: मज़बूत सिग्नल
  • -70 dBm: कमज़ोर लेकिन उपयोगी
  • -90 dBm: बहुत कमज़ोर (रेंज के किनारे पर)

प्रोब रिक्वेस्ट: WiFi डिवाइस उपलब्ध नेटवर्क खोजने के लिए प्रोब रिक्वेस्ट भेजते हैं। वाइल्डकार्ड प्रोब (खाली SSID) किसी भी नेटवर्क की खोज करते हैं, जो Flock कैमरों जैसे IoT डिवाइसों में सामान्य है, जिससे वे विश्वसनीय रूप से पहचाने जा सकते हैं।

  • लेटेस्ट Flock-You फर्मवेयर अपडेट करें
  • जांचें कि डिवाइस सक्रिय रूप से स्कैन कर रहा है (LED/डिस्प्ले गतिविधि सत्यापित करें)

समस्या: अत्यधिक झूठी सकारात्मकताएं #

संभावित कारण:

  1. ESP32 डिवाइसों का उच्च घनत्व: स्मार्ट होम, IoT डिवाइस सामान्य हैं
  2. संवेदनशीलता बहुत अधिक: दूर/अप्रासंगिक डिवाइसों का पता लगाना
  3. अन्य सर्विलांस कैमरे: कई ESP32 मॉड्यूल का उपयोग करते हैं

समाधान:

  • संवेदनशीलता सेटिंग कम करें
  • वाइल्डकार्ड प्रोब डिटेक्शन सक्षम करें (उच्च विश्वास)
  • लॉग करने से पहले डिटेक्शन की भौतिक रूप से सत्यापित करें
  • सिग्नल शक्ति का उपयोग करके फ़िल्टर करें (केवल मज़बूत सिग्नल पर अलर्ट)
  • पुष्टि किए गए Flock OUI पर ध्यान केंद्रित करने के लिए OUI डेटाबेस अपडेट करें

समस्या: बैटरी जल्दी खत्म हो जाती है #

संभावित कारण:

  1. निरंतर स्कैनिंग: कोई स्लीप/पावर मैनेजमेंट नहीं
  2. डिस्प्ले हमेशा चालू: स्क्रीन महत्वपूर्ण पावर की खपत करती है
  3. GPS सक्रिय: GPS मॉड्यूल पावर-भूखे होते हैं
  4. पुरानी बैटरी: Li-Po बैटरी समय के साथ खराब होती हैं

समाधान:

  • पैसिव स्कैन मोड सक्षम करें (निरंतर बनाम रुक-रुककर)
  • डिस्प्ले टाइमआउट सेट करें
  • मैपिंग की आवश्यकता न होने पर GPS अक्षम करें
  • बैटरी बदलें (OUI-SPY/mesh-detect v2 में बदलने योग्य बैटरी हैं)
  • विस्तारित सत्रों के लिए बाहरी बैटरी पैक का उपयोग करें

समस्या: GPS लॉक नहीं हो रहा #

संभावित कारण:

  1. इनडोर उपयोग: GPS के लिए आकाश दृश्यता आवश्यक है
  2. एंटीना कनेक्ट नहीं: mesh-detect v2 को बाहरी एंटीना कनेक्टेड चाहिए
  3. कोल्ड स्टार्ट: पहला GPS लॉक 5-15 मिनट लेता है
  4. हस्तक्षेप: पास के इलेक्ट्रॉनिक्स सिग्नल में हस्तक्षेप करते हैं

समाधान:

  • स्पष्ट आकाश दृश्य वाले स्थान पर जाएं
  • सुनिश्चित करें कि एंटीना ठीक से कनेक्ट है (SMA कनेक्टर)
  • प्रारंभिक लॉक के लिए प्रतीक्षा करें (बाद के लॉक तेज़ होते हैं)
  • RF हस्तक्षेप स्रोतों से दूर जाएं
  • जांचें कि GPS सेटिंग्स में सक्षम है

समस्या: SD कार्ड पर डेटा लॉग नहीं हो रहा #

संभावित कारण:

  1. SD कार्ड फॉर्मेट नहीं: FAT32 फॉर्मेट होना चाहिए
  2. SD कार्ड भरा हुआ: कोई स्थान नहीं बचा
  3. कार्ड नहीं पहचाना: पूरी तरह से डाला नहीं गया
  4. फाइल सिस्टम भ्रष्टाचार: कार्ड क्षतिग्रस्त

समाधान:

  • SD कार्ड को FAT32 फॉर्मेट करें (संगतता के लिए 32GB अधिकतम)
  • पुराने लॉग हटाएं या बड़ा कार्ड उपयोग करें
  • कार्ड पूरी तरह से दोबारा डालें (क्लिक की आवाज़ आनी चाहिए)
  • कार्ड को रिफॉर्मेट करें या क्षतिग्रस्त होने पर बदलें
  • जांचें कि डिवाइस कार्ड को पहचानता है (मेनू SD स्थिति दिखाएगा)

कानूनी और नैतिक विचार #

डिटेक्शन डिवाइसों की कानूनी स्थिति #

WiFi स्कैनिंग की वैधता:

  • ✅ अमेरिका में कानूनी: पैसिव WiFi मॉनिटरिंग (केवल प्राप्त करना) कानूनी है
  • ✅ कोई अवरोधन नहीं: डिवाइस केवल सार्वजनिक रूप से प्रसारित फ्रेम की निगरानी करते हैं
  • ✅ कोई डिक्रिप्शन नहीं: डेटा को डिक्रिप्ट करने या नेटवर्क से जुड़ने का प्रयास नहीं
  • ✅ रेडियो स्कैनर के समान: पुलिस स्कैनर के समान कानूनी स्थिति

महत्वपूर्ण अंतर:

  • ❌ अवैध: कैमरा संचालन में सक्रिय जैमिंग/हस्तक्षेप
  • ❌ अवैध: कैमरा सिस्टम को हैक करने या एक्सेस करने का प्रयास
  • ❌ अवैध: भौतिक कैमरों को नष्ट या छेड़छाड़ करना
  • ⚠️ ग्रे एरिया: कुछ न्यायक्षेत्रों में सख्त गोपनीयता कानून हैं। उपयोग से पहले स्थानीय नियम सत्यापित करें।

सिफारिश: डिटेक्शन डिवाइस केवल जागरूकता के लिए हैं। कैमरा संचालन में हस्तक्षेप न करें।

  • ✅ वकालत और नीति चर्चाओं के लिए दस्तावेज़ करें

  • ❌ सर्विलांस बुनियादी ढांचे के विरुद्ध आतंकी कार्रवाई

  • इस डेटा को सुरक्षित रूप से संग्रहीत करें
  • सबपोना जोखिम के बारे में जागरूक रहें यदि कानूनी कार्यवाही में शामिल हों
  • संवेदनशील लॉग फाइलों के लिए एन्क्रिप्शन पर विचार करें
  • क्लाउड-कनेक्टेड डिवाइसों के लिए विक्रेता गोपनीयता नीतियां समझें

  • डेटा साझाकरण के नैतिक प्रभावों पर विचार करें
