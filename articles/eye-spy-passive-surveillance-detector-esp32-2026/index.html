引言：看不见的监控环境 #

物理环境中安装的观察、录制和跟踪设备越来越多，包括路口的车牌读取器、执法人员佩戴的执法记录仪、出租房内的摄像头、藏在包或汽车里的商用AirTag类追踪器，以及商店入口处的监控摄像头。大多数设备通过Bluetooth LE或WiFi进行无线通信。其中许多通信会向周围开放广播，拥有合适接收器的人都能检测到。

Eye Spy 是一款利用这一特点的被动监控检测工具。它运行在M5Stack Atom Lite上。这是一块ESP32-PICO-D4开发板，大小约等于一颗方糖。Eye Spy持续监控BLE和WiFi频段，寻找录制设备、监控摄像头、ALPR（自动车牌识别）系统、无人机和个人追踪器的电子特征。发现信号时，它会改变RGB LED的颜色。

它不连接任何设备，也不发送数据。 它只监听、评分并亮灯提示。

LED指示灯：完整的用户界面 #

与 ESP32 WiFi Canary：2.4 GHz被动威胁检测器 类似，Eye Spy的全部输出来自一个连接到M5Stack Atom Lite GPIO 27的SK6812 RGB NeoPixel。LED始终显示四种威胁等级之一：

颜色含义分数范围
🔵 蓝色脉冲启动 / 首次扫描–
🟢 常亮绿色未发现设备0–2
🟡 常亮黄色注意：附近可能有录制设备3–5
🔴 红色闪烁警报：发现监控或追踪设备6+

一次高置信度检测（Axon执法记录仪、Flock Safety摄像头、匹配的ALPR OUI或AirTag）就足以在一个检测周期内将分数推至红色警报。 多次中等置信度检测会累积至黄色，也可能合并达到红色。

通用ESP32 DevKit #

第二个PlatformIO构建环境（esp32dev）适用于任何带有GPIO 2板载LED的标准ESP32 DevKit。所有检测逻辑都以相同方式运行。若不需要Atom Lite的小型外形，这个构建环境适合开发、测试检测逻辑或部署使用。

评分系统 #

Eye Spy采用置信度评分模型，将所有检测引擎的信号汇总为一个整数。分数决定LED状态（绿色、黄色或红色），并通过两种自动机制进行管理：

分数衰减 #

没有新检测时，分数会每60秒降低1分。离开检测到的设备后，无需用户操作，LED会在几分钟内恢复绿色。

再次计分的冷却时间 #

每种检测类型都有120秒冷却时间，同一来源在此期间无法再次加分。这可避免单个持续存在的设备无限累积分数。 仍在范围内的Flock Safety摄像头先加+5分，然后等待120秒才能再次贡献分数。

这两种机制结合起来意味着：

  • 短暂检测（例如一辆装有AirTag的汽车驶过）会自动消退。
  • 持续监控（例如固定部署的执法记录仪）会在你处于范围内时持续保持警报状态。
  • 单台设备反复出现不会导致分数失控增长。

检测引擎 #

Eye Spy持续轮换三个扫描阶段：

BLE被动扫描（9秒）→ WiFi扫描（约3秒）→ 混杂模式嗅探（5秒）→ 重复

为正确共享ESP32射频，Eye Spy会在任何WiFi操作前明确停止BLE，并在每个新周期开始时重新启动BLE。

引擎1：BLE被动扫描 #

BLE扫描使用NimBLE，且不会发送扫描请求。设备监听BLE广播数据包，不发送任何响应。因此，Eye Spy在电子层面不会被它要检测的设备发现，被动扫描器不会向目标暴露自身。

为减少密集环境中的误报，信号低于**−90 dBm**的设备会被忽略。

重要BLE检测详解 #

Axon执法记录仪（+5）：Axon（原TASER International）生产了美国执法部门广泛部署的执法记录仪系统。OUI 00:25:df注册给Axon，并用于其可穿戴设备。检测到一次即可达到警报阈值。

Ray-Ban Meta智能眼镜（+5）：Ray-Ban Meta合作产品包括能够录制视频和拍照的消费级智能眼镜。BLE服务UUID 0xFD5F是此类设备的特征广播。这是消费类产品，在人流密集的公共场所也可能出现。 无论佩戴者的意图如何，都应留意这一等级的检测。

撇取设备中的蓝牙模块（+5）：HC-03、HC-05和HC-06是廉价蓝牙串行模块，常见于支付终端覆盖装置和ATM撇取设备。检测逻辑会将设备名与这些模块已知的默认固件名称精确匹配。出现红色警报时，应立即检查附近的支付终端。

Apple AirTag（+4）：AirTag使用Apple专有的Nearby Interaction协议广播。检测逻辑会检查厂商专用数据头（0x004C = Apple）和AirTag专用子类型（标准广播为0x12，失物广播为0x1E）。原始负载模式提供了冗余检测方式。

OpenDroneID BLE（+4）：ASTM F3411 Remote ID标准也被美国FAA用于商业无人机，定义了无人机广播身份和位置的协议。Eye Spy查找GATT服务UUID 0xFFFA（指定的Remote ID服务），以及AD服务数据负载中的应用代码0x0D。附近符合标准的商用无人机将触发此检测。

未知的持续性设备（+2）：这是跟随检测引擎。它跟踪未被上述特定检测分类的所有BLE MAC。如果相同的未分类MAC在至少五分钟内出现三次或更多次，就会加分。持续性设备跟踪器最多同时监控50个未知MAC，设备离开30分钟后会删除记录。这样可以发现不符合已知服务UUID或厂商模式的定制或改装追踪器。

iBeacon（+2）：零售商、机场和体育场馆使用Apple iBeacon格式（0x4C 0x00 0x02 0x15）跟踪物理空间中的设备移动。无论UUID为何，只要出现标准广播格式就会触发检测。这针对的是部署类型，而非特定UUID。检测到iBeacon通常表示所在地点正在主动跟踪蓝牙设备是否出现。

引擎2：WiFi扫描，主动信道搜索 #

WiFi扫描引擎使用ESP32标准AP扫描接口枚举附近的接入点，并将其BSSID和SSID与已知监控设备特征进行比较。

Flock Safety OUI表 #

包含22个条目的FLOCK_OUIS表是项目中最详细的查找表，包含：

  • d4:bb:e6：IEEE注册的Flock Safety OUI。
  • 3c:61:05：IEEE注册的Flock Safety OUI。
  • 另外20个在现场Flock FS-Ext-Battery电池和Flock WiFi摄像头上观察到的MAC前缀。

这22个条目代表了已部署Flock Safety ALPR摄像头系统中观察到的硬件MAC地址范围。OUI检测独立于SSID：即使Flock摄像头使用不含关键词的SSID，只要BSSID OUI匹配，仍会加+5分。

Flock Safety和Vigilant Solutions的OUI位于不同表中，因此两类设备可以在同一扫描周期中分别计分。同时部署两家厂商设备的地点，一次WiFi扫描最多可能累计+10分。

监控摄像头厂商OUI表 #

31项监控摄像头表涵盖了可能出现在商店、商业场所和住宅中的主要IP摄像头厂商：

  • 企业和商业用途：Hikvision、Dahua、Axis、Vivotek、Hanwha（Samsung Techwin）、Mobotix和Genetec。
  • 消费级和小型办公室：Ring、Nest、Arlo、Wyze、Reolink、Blink、Lorex和Amcrest。
  • 基础设施：Ubiquiti UniFi（接入点和摄像头使用重叠的OUI范围）以及FLIR。

即使没有关键词确认，匹配也会增加+3分，进入注意等级。如果SSID关键词也匹配，同一摄像头网络会先因OUI增加+3分，再因SSID增加+2分，在一个扫描周期内达到警报等级。

引擎3：WiFi混杂模式，被动帧嗅探 #

混杂模式引擎将ESP32无线电切换到监视器模式并捕获原始802.11管理帧。这样可以检测不广播SSID的设备，尤其是通过WiFi邻近感知网络（NaN）使用Remote ID协议的无人机。

在混杂模式阶段，无线电每400 ms在{1, 6, 11, 3, 8, 13}之间切换信道，以扩大无人机NaN帧广播信道的覆盖范围。

混杂模式检测表 #

#目标检测方法分数
18无人机（OpenDroneID WiFi NaN）发送至51:6f:9a:01:00:00的802.11管理帧：ASTM F3411 Remote ID广播+4 🔴

OpenDroneID WiFi NaN（+4）：ASTM F3411标准为所有Remote ID WiFi NaN帧定义了组播目的地址51:6f:9a:01:00:00。通过WiFi广播位置和身份的受监管商用无人机会将帧发送到此地址。Eye Spy只需监听目的MAC为此组播地址的管理帧，检测方式被动且可靠。无人机操作员若想阻止检测，只能完全关闭Remote ID，而这本身会违反适用法规。

此检测补充BLE OpenDroneID引擎（检测#6）。根据硬件和配置，无人机可能通过BLE、WiFi或两者进行广播。 Eye Spy两种方式都能检测。

阶段计划与无线电管理 #

BLE被动扫描（9秒）→ WiFi扫描（约3秒）→ 混杂模式嗅探（5秒）→ 重复

ESP32-PICO-D4有一台共享的2.4 GHz无线电同时处理BLE和WiFi。Eye Spy按以下方式管理：

  1. BLE阶段（9秒）：NimBLE协议栈运行并进行被动扫描，不发送扫描请求。
  2. 停止BLE：使用WiFi前明确停止BLE协议栈。
  3. WiFi扫描（约3秒）：在所有信道主动扫描AP并匹配OUI与SSID。
  4. 混杂模式嗅探（5秒）：被动捕获802.11帧并切换信道。
  5. 停止WiFi：停止WiFi并重启BLE，进入下一轮循环。

这种明确的阶段管理可避免无线电冲突，并确保BLE和WiFi引擎在每个周期内有序访问无线电。

检测说明与实际限制 #

Eye Spy无法做到什么 #

5 GHz WiFi：ESP32是仅支持2.4 GHz的设备。仅在5 GHz频段运行的监控摄像头、ALPR系统或接入点不会被WiFi扫描或混杂模式引擎发现。许多现代IP摄像头虽然也支持5 GHz，但仍兼容2.4 GHz。只运行5 GHz的部署则无法检测。

加密BLE：一些高端监控产品会加密或混淆BLE广播。Eye Spy能检测以明文广播可识别特征（例如OUI、服务UUID、厂商数据）的设备。会轮换MAC地址的设备（这是消费级追踪器日益常见的隐私功能）能够避开基于MAC的检测。 如果其轮换间隔长于5分钟，持续性追踪器仍可能发现它们。

有线摄像头：通过以太网连接且未启用WiFi无线电的IP摄像头不会发出Eye Spy能够检测的无线信号。 不接入网络、仅在本地录像的隐藏摄像头同样不会产生RF特征。

范围限制：在室内，ESP32天线接收强信号的实际范围为20–40米，弱信号或受遮挡的信号更短。处于覆盖边缘或被显著RF屏蔽的设备可能得不到分数，或低于−90 dBm的RSSI过滤阈值。

可能出现的误报 #

邻居家中的消费级摄像头：Ring、Nest、Wyze、Arlo和Reolink摄像头在住宅区十分常见，其OUI已列入31项摄像头表。在住宅环境中，邻居的门铃摄像头可能带来一些黄色注意提示（+3）。 从技术角度看，这不算误报，因为设备确实检测到了摄像头，但需要结合环境判断。

零售场所部署的iBeacon：大型零售商几乎在每家门店都部署了iBeacon基础设施。前往购物中心或超市时，很可能触发iBeacon检测（+2）。 设备执行正常，因为零售追踪设施确实存在。

Ubiquiti UniFi基础设施：由于Ubiquiti生产网络设备和安全摄像头，且两者的OUI范围有重叠，UniFi接入点也会出现在监控摄像头OUI表中。使用UniFi网络设备的部署可能在WiFi扫描中因OUI匹配得到+3分。

Samsung SmartTag与消费设备：SmartTag UUID（0xFD5A）是Samsung注册的服务。Samsung SmartTag是有正当个人用途的消费级追踪器。 附近存在SmartTag时就会触发检测。

各分数等级在实际中的含义 #

6–10（🔴）高置信度的可信检测：约30米内的Axon摄像头、OUI匹配的Flock Safety摄像头、确认存在跟随模式的AirTag，或正在广播Remote ID的无人机

0–2（🟢）未发现重要监控特征；存在普通消费设备通信，但分数低于阈值

使用场景 #

了解周边监控情况 #

Eye Spy主要面向想了解周边监控基础设施的人。无论是在街区步行、驾车经过路口，还是参加公共活动，Eye Spy都能将复杂的RF分析转化为一个实时LED状态。

检测AirTag跟踪 #

利用AirTag跟踪他人是有记录的问题。Eye Spy的跟随设备检测引擎会查找在至少5分钟内出现至少3次的未知持续性BLE MAC，目标是发现不符合Apple已知广播格式的定制或改装追踪器。结合直接的AirTag检测，它提供了两条独立路径来发现跟随你的追踪器。

检查出租房或酒店客房 #

进入新的酒店房间或出租房并运行Eye Spy，可初步识别意料之外的BLE和WiFi设备。WiFi扫描若发现包含摄像头关键词的SSID或监控OUI，就会增加注意等级分数。这不能替代正规的RF扫描，但能为物理检查增加一层被动环境监测。

ALPR部署与隐私研究 #

记录监控基础设施的研究人员、在受监控环境中工作的记者，以及隐私倡导者，可以使用价格低廉、便于携带的Eye Spy进行现场检测。串口输出会记录每项检测及其RSSI，因此也适合简单的数据采集。

旅行安全 #

和WiFi Canary一样，Eye Spy采用便于旅行的外形。Atom Lite可放入口袋或挂在包上。在机场、火车站或监控密集的公共活动场所，它无需交互即可持续进行被动监测。

架构说明 #

被动BLE为何重要 #

选择不发送扫描请求包的BLE被动扫描方式具有重要安全意义。在标准BLE扫描中，扫描器会发送SCAN_REQ数据包，向每个广播设备请求额外广告数据。因此，BLE主动扫描对双方都可见，被扫描设备能从请求中看到扫描器的地址。

NimBLE被动模式只监听非定向广播包（ADV_IND、ADV_NONCONN_IND、ADV_SCAN_IND），从不发送SCAN_REQ。Eye Spy在扫描阶段不会通过BLE发射任何内容。 被检测到的Axon执法记录仪、Flock设备或AirTag无法观察扫描器，也无法对它的存在作出响应。

持续性追踪器设计 #

未知设备持续性追踪器最多保存50个BLE MAC地址及首次和末次检测时间。当同一个MAC在至少五分钟内出现三次或更多次时，就会触发检测。

50项上限和30分钟清除窗口是在检测灵敏度与ESP32 RAM限制之间进行平衡的工程选择。在公交、会议或商场等BLE设备密集环境中，表格可能很快被消费设备填满。 −90 dBm的RSSI阈值会过滤远处设备，使追踪器重点关注附近持续存在的信号源。

分数衰减与冷却时间的交互 #

120秒的重新计分冷却时间可防止始终处于范围内的设备在每个9秒BLE周期不断累积分数。若没有冷却时间，单个Flock摄像头会每15秒增加+5分，几分钟内就能达到数百分。

每60秒降低1分意味着设备离开范围且冷却时间结束后，只要未再次触发，分数就会下降。一次没有再次触发的+5分检测会在5分钟内降至零。 这样，在正常移动场景中，设备会自然恢复到无警报状态。

贡献与项目状态 #

Eye Spy以Apache-2.0许可证发布，地址为 github.com/simeononsecurity/eye-spy 。

可能的扩展方向包括：

  • 添加OUI条目：在现场记录到新的硬件MAC后，扩展Flock Safety和摄像头OUI表。
  • 添加BLE服务UUID：新款智能眼镜、摄像头或追踪器会带来新的UUID。
  • 调整持续性追踪器：50项上限、3次观测阈值和5分钟窗口都是可调整常量。
  • 记录串行数据：串口输出格式适合程序解析。外部记录器可汇总多台Eye Spy的检测事件。

固件位于src/目录下的单个main.cpp文件中，因此易于阅读、审查和修改。

结论 #

Eye Spy解决了一个范围有限但重要的问题：你周围的物理环境安装了越来越多的监控设备，其中大多数会广播可检测的RF特征。一台售价15美元、运行Eye Spy固件的M5Stack Atom Lite可以成为持续工作的环境扫描器，将复杂的BLE数据包分析和WiFi OUI查询转化为一个RGB LED信号。

置信度评分模型反映了实际威胁权重：执法活动附近的Axon执法记录仪加+5并立即点亮红灯；零售iBeacon加+2，有助于了解情况，但不会单独触发误报。分数衰减和再计分冷却机制可避免设备对短暂或低等级的持续信号反应过度。

无论是进行反监控、旅行安全、AirTag检测，还是单纯想了解附近是否有设备在观察你，Eye Spy都是一款实用、开源且被动运行的工具，值得安全从业者纳入装备。
