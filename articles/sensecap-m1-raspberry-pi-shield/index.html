SenseCAP M1 ਸ਼ੀਲਡ LoRaWAN ਗੇਟਵੇ ਹਾਰਡਵੇਅਰ ਵਜੋਂ ਲਾਭਦਾਇਕ ਹੈ, ਪਰ ਇਸ ਦੀ ਵਾਇਰਿੰਗ ਲਈ ਆਮ Raspberry Pi HAT ਟਿਊਟੋਰਿਅਲ ਨਾਲੋਂ ਵੱਧ ਜਾਂਚ ਚਾਹੀਦੀ ਹੈ। ਇਹ ਗਾਈਡ Clockwork Bird ਦੀ 2023 ਵਾਲੀ ਜਾਂਚ ਵਿੱਚ ਨਿਰਮਾਤਾ ਦੇ ਦਸਤਾਵੇਜ਼, upstream ਡਰਾਈਵਰ ਦੀ ਜਾਂਚ ਅਤੇ ਮੌਜੂਦਾ GPIO ਹਦਾਇਤਾਂ ਜੋੜਦੀ ਹੈ। ਤੁਸੀਂ ਹਾਰਡਵੇਅਰ ਦੀ ਪਛਾਣ ਕਰੋਗੇ, ਪੱਕੇ ਤੱਥਾਂ ਨੂੰ ਅਧੂਰੇ ਪਿਨਆਉਟ ਸਬੂਤ ਤੋਂ ਵੱਖ ਕਰੋਗੇ ਅਤੇ ਦੁਹਰਾਈ ਜਾ ਸਕਣ ਵਾਲਾ ਸ਼ੁਰੂਆਤੀ ਰਿਕਾਰਡ ਬਣਾਓਗੇ।

ਦਾਇਰਾ: ਇਹ ਦਸਤਾਵੇਜ਼ਾਂ ਉੱਤੇ ਆਧਾਰਿਤ ਹਾਰਡਵੇਅਰ ਗਾਈਡ ਹੈ। ਇਸ ਲੇਖ ਲਈ ਕਮਾਂਡਾਂ ਅਤੇ ਬੋਰਡ ਮੈਪ ਕਿਸੇ ਅਸਲ M1 ਉੱਤੇ ਨਹੀਂ ਪਰਖੇ ਗਏ।

ਮੁੱਖ ਗੱਲਾਂ #

  • ਦੋਵੇਂ ਬੋਰਡ ਪਛਾਣੋ: M1 ਕੈਰੀਅਰ ਅਤੇ ਹਟਾਇਆ ਜਾ ਸਕਣ ਵਾਲੇ concentrator ਦੇ ਮਾਡਲ ਅਤੇ ਰਿਵਿਜ਼ਨ ਵੱਖਰੇ ਹਨ।
  • ਰੀਸੈੱਟ ਸਕ੍ਰਿਪਟਾਂ ਦੀ ਜਾਂਚ ਕਰੋ: CoreCell ਦੇ ਡਿਫਾਲਟ ਮੁੱਲ ਪ੍ਰਕਾਸ਼ਿਤ M1 ਪਿਨਆਉਟ ਦੇ ਕੁਝ ਸਿਗਨਲਾਂ ਨਾਲ ਟਕਰਾਉਂਦੇ ਹਨ।
  • OS ਇੰਟਰਫੇਸ ਵੇਖੋ: SPI ਡਿਵਾਈਸ ਫਾਈਲਾਂ, GPIO ਨੰਬਰ ਅਤੇ GPIO ਟੂਲ ਦੇ ਵਰਜਨ ਵੱਖਰੇ ਸਵਾਲਾਂ ਦੇ ਜਵਾਬ ਦਿੰਦੇ ਹਨ।
  • ਸੁਰੱਖਿਅਤ ਤੱਤ ਦੀ provisioning ਬਚਾਓ: ਡਿਵਾਈਸ ਜਾਣਕਾਰੀ ਪੜ੍ਹਨਾ ਅਤੇ ਇਸਨੂੰ configure ਕਰਨਾ ਜਾਂ ਕੁੰਜੀਆਂ ਬਣਾਉਣਾ ਵੱਖਰੇ ਕੰਮ ਹਨ।
  • ਪੂਰਾ ਰਸਤਾ ਸਾਬਤ ਕਰੋ: concentrator ਮਿਲ ਜਾਣਾ ਸੈਂਸਰ ਡਾਟਾ ਪਹੁੰਚਣ ਦਾ ਸਬੂਤ ਨਹੀਂ।

ਸ਼ੁਰੂ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ #

ਮੁਸ਼ਕਲ: ਦਰਮਿਆਨੀ। ਸੂਚੀ ਬਣਾਉਣ, OS ਤਿਆਰ ਕਰਨ ਅਤੇ ਦਸਤਾਵੇਜ਼ ਜਾਂਚਣ ਲਈ ਲਗਭਗ ਇੱਕ ਤੋਂ ਦੋ ਘੰਟੇ ਰੱਖੋ। ਬਿਜਲੀ ਵਾਲੀ ਜਾਂਚ, ਡਰਾਈਵਰ ਬਦਲਾਅ ਅਤੇ ਨੈੱਟਵਰਕ ਸਰਵਰ ਲਗਾਉਣ ਲਈ ਵਾਧੂ ਕੰਮ ਚਾਹੀਦਾ ਹੈ, ਖਾਸ ਕਰਕੇ ਜੇ ਬੋਰਡ ਰਿਵਿਜ਼ਨ ਅਣਜਾਣ ਹੋਵੇ।

ਚੀਜ਼ਮਕਸਦ
M1 ਸ਼ੀਲਡ ਅਤੇ concentratorਕੈਰੀਅਰ ਰਿਵਿਜ਼ਨ ਅਤੇ ਮੋਡੀਊਲ ਦਾ ਪੂਰਾ ਲੇਬਲ ਪੜ੍ਹੋ
Raspberry Pi 4ਅਸਲ M1 ਡਿਜ਼ਾਈਨ ਵਿੱਚ ਵਰਤੇ ਹੋਸਟ ਨਾਲ ਸ਼ੁਰੂ ਕਰੋ
ਵਾਧੂ microSD ਕਾਰਡਪੁਰਾਣੀ ਇੰਸਟਾਲੇਸ਼ਨ ਬਚਾ ਕੇ ਵੱਖਰਾ OS ਤਿਆਰ ਕਰੋ
ਠੀਕ ਬਿਜਲੀ ਸਪਲਾਈ ਅਤੇ ਐਂਟੀਨਾਅਸੈਂਬਲੀ ਅਤੇ ਮੋਡੀਊਲ ਦੇ RF ਬੈਂਡ ਨਾਲ ਮੇਲ ਕਰੋ
SSH ਜਾਂ ਸਥਾਨਕ ਕਨਸੋਲਜਾਂਚਾਂ ਦਰਜ ਕਰੋ ਅਤੇ ਸੰਰਚਨਾ ਸੋਧੋ
LoRaWAN ਸੈਂਸਰ ਅਤੇ ਸਰਵਰਹਾਰਡਵੇਅਰ ਚਾਲੂ ਕਰਨ ਤੋਂ ਬਾਅਦ ਐਪ ਤੱਕ ਅਸਲ ਡਿਲਿਵਰੀ ਜਾਂਚੋ
ਮੀਟਰ ਅਤੇ ਹਾਰਡਵੇਅਰ ਤਜਰਬਾਅਣਦੱਸੇ ਕੁਨੈਕਸ਼ਨ ਚਲਾਉਣ ਤੋਂ ਪਹਿਲਾਂ ਹੱਲ ਕਰੋ

ਕੁਝ ਵੀ ਖੋਲ੍ਹਣ ਤੋਂ ਪਹਿਲਾਂ ਬਿਜਲੀ ਤੋਂ ਵੱਖਰੀ ਅਸੈਂਬਲੀ ਦੇ ਦੋਵੇਂ ਪਾਸਿਆਂ ਦੀਆਂ ਤਸਵੀਰਾਂ ਲਓ। ਕਨੈਕਟਰ ਦੀ ਦਿਸ਼ਾ, ਪੇਚ, ਸਪੇਸਰ ਅਤੇ ਐਂਟੀਨਾ ਦਾ ਰਸਤਾ ਲਿਖੋ। ਨਵੀਂ ਇੰਸਟਾਲੇਸ਼ਨ ਸਵੀਕ੍ਰਿਤੀ ਜਾਂਚਾਂ ਪਾਰ ਕਰਨ ਤੱਕ ਅਸਲ ਕਾਰਡ ਅਤੇ ਸੰਰਚਨਾ ਉਪਲਬਧ ਰੱਖੋ।

ਤਿੰਨ ਪਰਤਾਂ ਪਛਾਣੋ #

ਪੂਰਾ M1, ਕੈਰੀਅਰ ਸ਼ੀਲਡ ਅਤੇ concentrator ਵੱਖਰੇ ਹਿੱਸੇ ਹਨ। Seeed ਦੇ ਦਸਤਾਵੇਜ਼ਾਂ ਵਿੱਚ ਪੂਰੇ ਹੌਟਸਪੌਟ ਨੂੰ Raspberry Pi 4 ਅਤੇ WM1302/SX1302 ਜਾਂ WM1303/SX1303 concentrator ਵਜੋਂ ਦੱਸਿਆ ਗਿਆ ਹੈ। “SenseCAP M1 shield” ਵਾਲੀ ਸੂਚੀ ਇਹ ਨਹੀਂ ਦੱਸਦੀ ਕਿ ਕੈਰੀਅਰ ਨਾਲ ਕਿਹੜਾ ਹਿੱਸਾ ਮਿਲਦਾ ਹੈ। Seeed Studio ਦੀ M1 ਜਾਣਕਾਰੀ

ਕੈਰੀਅਰ Pi ਅਤੇ ਮੋਡੀਊਲ ਵਿਚਕਾਰ ਬਿਜਲੀ ਅਤੇ ਪੈਰੀਫਿਰਲ ਸਿਗਨਲ ਜੋੜਦਾ ਹੈ। Concentrator ਰੇਡੀਓ ਪ੍ਰਾਪਤੀ ਅਤੇ ਭੇਜਣ ਦਾ ਕੰਮ ਕਰਦਾ ਹੈ। ਹੋਸਟ ਉੱਤੇ ਚੱਲਦਾ ਪੈਕੇਟ ਫਾਰਵਰਡਰ ਪ੍ਰਾਪਤ ਰੇਡੀਓ ਪੈਕੇਟ ਅਤੇ ਤੈਅ ਡਾਊਨਲਿੰਕ ਸਰਵਰ ਨਾਲ ਲੈਣ-ਦੇਣ ਕਰਦਾ ਹੈ। Semtech ਦੀ SX1302 HAL ਜਾਣਕਾਰੀ

ਮਿਸਾਲ ਲਈ, ਸ਼ੈਲਫ਼ ਦਾ ਤਾਪਮਾਨ ਸੈਂਸਰ ਰੇਡੀਓ ਰਾਹੀਂ ਅੱਪਲਿੰਕ ਭੇਜਦਾ ਹੈ। Concentrator ਇਸਨੂੰ ਪ੍ਰਾਪਤ ਕਰਦਾ ਹੈ, ਹੋਸਟ ਅੱਗੇ ਭੇਜਦਾ ਹੈ ਅਤੇ ਨੈੱਟਵਰਕ ਤੇ ਐਪ ਸੇਵਾਵਾਂ ਇਸਨੂੰ ਸੰਭਾਲਦੀਆਂ ਹਨ। Linux ਦਾ ਚੱਲ ਪੈਣਾ ਇਸ ਲੜੀ ਦੇ ਸਿਰਫ਼ ਹੋਸਟ ਹਿੱਸੇ ਨੂੰ ਸਾਬਤ ਕਰਦਾ ਹੈ।

Clockwork Bird ਦੀ ਤਸਵੀਰ ਵਿੱਚ M1 v1.1 ਕੈਰੀਅਰ ਉੱਤੇ WM1302-SPI-EU868 ਲੇਬਲ ਵਾਲਾ ਮੋਡੀਊਲ ਹੈ। ਆਪਣੇ ਹਾਰਡਵੇਅਰ ਦੇ ਲੇਬਲ ਲੱਭਣ ਲਈ ਤਸਵੀਰ ਵਰਤੋ। ਸੀਰੀਅਲ ਨੰਬਰ ਤਸਵੀਰ ਵਾਲੇ ਸਾਮਾਨ ਦੀ ਪਛਾਣ ਕਰਦੇ ਹਨ, ਕਿਸੇ ਹੋਰ ਗੇਟਵੇ ਦੀ ਸੰਰਚਨਾ ਨਹੀਂ।

ਬਿਜਲੀ ਅਤੇ ਰੇਡੀਓ ਕੁਨੈਕਸ਼ਨ #

M1 ਦੇ USB-C ਕਨੈਕਟਰ ਨੂੰ ਬਿਜਲੀ ਦਾ ਇਨਪੁੱਟ ਸਮਝੋ। ਨਿਰਮਾਤਾ ਪੂਰੇ ਗੇਟਵੇ ਲਈ DC 5 V, 3 A ਦੱਸਦਾ ਹੈ ਅਤੇ USB-C ਨੂੰ ਬਿਜਲੀ ਸਪਲਾਈ ਇੰਟਰਫੇਸ ਕਹਿੰਦਾ ਹੈ। ਇਸਨੂੰ ਚਾਰਜਿੰਗ ਪੋਰਟ ਕਹਿਣ ਨਾਲ ਬੈਟਰੀ ਦਾ ਭਰਮ ਪੈਦਾ ਹੁੰਦਾ ਹੈ, ਜਿਸਦਾ ਇਨ੍ਹਾਂ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ ਵਿੱਚ ਜ਼ਿਕਰ ਨਹੀਂ। SenseCAP M1 ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ

ਨਿਰਮਾਤਾ ਦਾ ਬਲਾਕ ਡਾਇਗ੍ਰਾਮ 5 V ਸਪਲਾਈ ਅਤੇ ਮੋਡੀਊਲ ਦੀ ਨਿਯੰਤਰਿਤ 3.3 V ਰੇਲ ਵੱਖ ਦਿਖਾਉਂਦਾ ਹੈ। ਸਮੱਸਿਆ ਲੱਭਣ ਵੇਲੇ ਇਹ ਫਰਕ ਮਹੱਤਵ ਰੱਖਦਾ ਹੈ: Pi ਚੱਲ ਸਕਦਾ ਹੈ ਪਰ concentrator ਨੂੰ ਬਿਜਲੀ ਨਾ ਮਿਲੇ। ਸਿਗਨਲ ਪਿਨ ਵਿੱਚ 5 V ਨਾ ਦਿਓ ਅਤੇ ਦੋਵੇਂ ਪਾਵਰ ਇਨਪੁੱਟ ਇੱਕ-ਦੂਜੇ ਤੋਂ ਅਲੱਗ ਮੰਨ ਕੇ ਨਾ ਚਲੋ।

SPI ਅਤੇ USB ਮੋਡੀਊਲ ਰੂਪਾਂ ਲਈ ਹੋਸਟ ਕੁਨੈਕਸ਼ਨ ਵੱਖਰੇ ਹਨ। Seeed ਦੇ WM1302 ਦਸਤਾਵੇਜ਼ SPI ਮਾਡਲ ਲਈ ਸਿੱਧਾ SPI ਅਤੇ USB ਮਾਡਲ ਲਈ STM32L4 USB ਬ੍ਰਿਜ ਦੱਸਦੇ ਹਨ। mini-PCIe ਆਕਾਰ ਮੋਡੀਊਲ ਦੀ ਬਣਾਵਟ ਦੱਸਦਾ ਹੈ, ਜਦਕਿ ਦਰਜ ਬਿਜਲੀ ਇੰਟਰਫੇਸ SPI ਜਾਂ USB ਹਨ। ਲੈਪਟਾਪ ਸਾਕਟ ਵਿੱਚ ਆਕਾਰ ਫਿੱਟ ਹੋਣ ਨਾਲ ਅਨੁਕੂਲਤਾ ਸਾਬਤ ਨਹੀਂ ਹੁੰਦੀ। Seeed ਦੇ WM1302 ਦਸਤਾਵੇਜ਼

ਅਸੈਂਬਲੀ ਨੂੰ ਬਿਜਲੀ ਦੇਣ ਤੋਂ ਪਹਿਲਾਂ, ਬਿਜਲੀ ਬੰਦ ਰੱਖ ਕੇ ਮੋਡੀਊਲ ਲਗਾਓ ਅਤੇ ਢੁਕਵਾਂ ਐਂਟੀਨਾ ਜੋੜੋ। RF ਹਾਰਡਵੇਅਰ, ਐਂਟੀਨਾ ਅਤੇ ਖੇਤਰੀ ਯੋਜਨਾ ਮੇਲ ਕਰੋ। ਸੰਰਚਨਾ ਫਾਈਲ ਦਾ ਨਾਂ ਬਦਲਣ ਨਾਲ RF ਹਿੱਸੇ ਨਹੀਂ ਬਦਲਦੇ ਅਤੇ M1 ਪਾਵਰ ਸਾਕਟ USB concentrator ਰੂਪ ਦਾ ਸਮਰਥਨ ਸਾਬਤ ਨਹੀਂ ਕਰਦਾ।

ਪਿਨਆਉਟ ਧਿਆਨ ਨਾਲ ਪੜ੍ਹੋ #

BCM GPIO ਨੰਬਰ ਅਤੇ ਭੌਤਿਕ ਹੈਡਰ ਪਿਨ ਨੂੰ ਨੋਟ ਵਿੱਚ ਵੱਖਰੇ ਕਾਲਮਾਂ ਵਿੱਚ ਰੱਖੋ। ਮਿਸਾਲ ਲਈ, BCM GPIO17 Pi ਹੈਡਰ ਦੇ ਭੌਤਿਕ ਪਿਨ 11 ਉੱਤੇ ਹੈ। ਮੋਡੀਊਲ ਦਾ edge connector ਤੀਜੀ ਨੰਬਰ ਪ੍ਰਣਾਲੀ ਦਿੰਦਾ ਹੈ, ਇਸ ਲਈ ਉਸਦਾ reset pin ਨੰਬਰ Raspberry Pi GPIO ਨੰਬਰ ਨਹੀਂ।

Reset ਸਕ੍ਰਿਪਟਾਂ ਦੇ ਟਕਰਾਅ ਹੱਲ ਕਰੋ #

Reset ਸਕ੍ਰਿਪਟ ਬਿਜਲੀ ਵਾਲੇ ਆਉਟਪੁੱਟ ਚੁਣਦੀ ਹੈ, ਸਿਰਫ਼ ਸੌਫਟਵੇਅਰ ਪਸੰਦ ਨਹੀਂ। Semtech ਦੀ upstream reset_lgw.sh CoreCell ਰੈਫ਼ਰੈਂਸ ਡਿਜ਼ਾਈਨ ਲਈ ਹੈ। ਇਸਦੇ ਡਿਫਾਲਟ ਵਿੱਚ concentrator reset ਲਈ GPIO23, power enable ਲਈ GPIO18, ਵਾਧੂ reset ਲਈ GPIO22 ਅਤੇ AD5338R reset ਲਈ GPIO13 ਹਨ। Semtech reset ਸਕ੍ਰਿਪਟ ਸਰੋਤ

Seeed ਦੀਆਂ ਪੁਰਾਣੀਆਂ ਸੈਟਅੱਪ ਹਦਾਇਤਾਂ ਦੋ reset ਅਸਾਈਨਮੈਂਟ GPIO17 ਅਤੇ GPIO5 ਕਰਦੀਆਂ ਹਨ, ਪਰ ਰੈਫ਼ਰੈਂਸ ਡਿਜ਼ਾਈਨ ਦੀਆਂ ਹੋਰ ਐਂਟਰੀਆਂ ਰੱਖਦੀਆਂ ਹਨ। ਉਦਾਹਰਣ ਮੰਨਣ ਤੋਂ ਪਹਿਲਾਂ ਇਹ ਮੁੱਲ M1 ਦੇ ਚਿੰਨ੍ਹਿਤ ਚਿੱਤਰ ਨਾਲ ਮਿਲਾਓ। Seeed WM1302 ਸੈਟਅੱਪ ਹਦਾਇਤਾਂ

ਅਨੁਮਾਨ: ਜੇ ਚਿੱਤਰ ਵਾਂਗ GPIO18 ਵਾਧੂ ਰੇਡੀਓ ਆਉਟਪੁੱਟ ਨਾਲ ਜੁੜਦਾ ਹੈ, ਤਾਂ Pi ਵਾਲੇ ਸਿਰੇ ਨੂੰ ਆਉਟਪੁੱਟ ਬਣਾਉਣ ਨਾਲ ਬਿਜਲੀ ਟਕਰਾਅ ਦਾ ਜੋਖ਼ਮ ਹੈ। ਇਹ ਅੰਤਰ ਜਾਂਚ ਦੀ ਲੋੜ ਦੱਸਦਾ ਹੈ, ਨੁਕਸਾਨ ਜਾਂ ਸਾਰੇ M1 ਲਈ ਇੱਕੋ ਵਾਇਰਿੰਗ ਸਾਬਤ ਨਹੀਂ ਕਰਦਾ।

ਸਾਰੀ ਬਿਜਲੀ ਹਟਾ ਕੇ ਹੈਡਰ ਅਤੇ ਮੋਡੀਊਲ ਕਨੈਕਟਰ ਵਿਚਕਾਰ ਦਿਖਾਈ ਦੇਣ ਵਾਲੇ ਜੋੜ ਲੱਭੋ। ਬੋਰਡ ਰਿਵਿਜ਼ਨ ਅਤੇ ਦੋਵੇਂ ਸਿਰੇ ਲਿਖੋ। continuity ਨਤੀਜਾ ਜੋੜ ਸਾਬਤ ਕਰਦਾ ਹੈ; ਸਿਗਨਲ ਦੀ ਦਿਸ਼ਾ ਅਤੇ ਬਿਜਲੀ ਹੱਦ ਲਈ ਹਿੱਸੇ ਦੇ ਦਸਤਾਵੇਜ਼ ਵੇਖੋ।

ਮੋਡੀਊਲ ਦਾ ਹੇਠਾਂ ਦਿੱਤਾ ਡਾਇਗ੍ਰਾਮ ਵਰਤ ਕੇ edge connector ਪਿਨ ਅਤੇ Pi ਹੈਡਰ ਪਿਨ ਨਾ ਗਲਤ ਮਿਲਾਓ। ਵਾਧੂ ਰੇਡੀਓ ਲੇਬਲ ਪ੍ਰਕਾਸ਼ਿਤ ਮੋਡੀਊਲ ਰੈਫ਼ਰੈਂਸ ਦੱਸਦੇ ਹਨ, ਹਰ ਰਿਵਿਜ਼ਨ ਵਿੱਚ ਇਕੋ ਚਿਪ ਜਾਂ ਫੀਚਰ ਸਾਬਤ ਨਹੀਂ ਕਰਦੇ। Seeed WM1302 ਮੋਡੀਊਲ ਪਿਨਆਉਟ

Raspberry Pi OS ਤਿਆਰ ਕਰੋ #

ਵਾਧੂ ਇੰਸਟਾਲੇਸ਼ਨ ਉੱਤੇ ਹੋਸਟ ਵਾਤਾਵਰਣ ਦਰਜ ਕਰੋ:

cat /etc/os-release
uname -r
tr -d '\0' < /proc/device-tree/model

OS ਰਿਲੀਜ਼, kernel ਅਤੇ Pi ਮਾਡਲ ਦੁਹਰਾਈ ਜਾ ਸਕਣ ਵਾਲੀ ਸ਼ੁਰੂਆਤ ਬਣਾਉਂਦੇ ਹਨ। ਪੁਰਾਣੇ ਟਿਊਟੋਰਿਅਲ ਨਾਲ ਨਤੀਜੇ ਮਿਲਾਉਣ ਤੋਂ ਪਹਿਲਾਂ ਇਹ ਲਿਖੋ।

ਜਾਂਚ ਅਤੇ build ਟੂਲ ਲਗਾਓ:

sudo apt update
sudo apt install git build-essential i2c-tools gpiod
sudo raspi-config

Interface Options ਵਿੱਚ SPI ਅਤੇ I2C ਚਾਲੂ ਕਰਕੇ reboot ਕਰੋ। SPI concentrator ਰਸਤੇ ਲਈ ਹੈ, I2C ਅੱਗੇ ਦੱਸੇ ਪ੍ਰਬੰਧਕੀ ਡਿਵਾਈਸਾਂ ਲਈ। ਕਿਸੇ ਹੋਰ HAT ਟਿਊਟੋਰਿਅਲ ਤੋਂ ਬੇਲੋੜੇ GPS serial-port ਬਦਲਾਅ ਨਾ ਲਿਆਓ।

ਖੁੱਲ੍ਹੇ ਇੰਟਰਫੇਸ ਵੇਖੋ:

ls -l /dev/spidev* /dev/i2c-*
i2cdetect -l
gpiodetect
gpioinfo
gpioset --version

ਇਹ ਕਮਾਂਡਾਂ ਡਿਵਾਈਸ ਨੋਡ, ਐਡੈਪਟਰ, GPIO ਕੰਟਰੋਲਰ, ਲਾਈਨਾਂ ਅਤੇ ਲੱਗੇ GPIO ਟੂਲ ਦਾ ਵਰਜਨ ਦਿਖਾਉਂਦੀਆਂ ਹਨ। i2cdetect -l ਪਤੇ ਸਕੈਨ ਕੀਤੇ ਬਿਨਾਂ ਐਡੈਪਟਰ ਲਿਸਟ ਕਰਦਾ ਹੈ। /dev/spidev0.0 ਫਾਈਲ SPI ਇੰਟਰਫੇਸ ਖੁੱਲ੍ਹਾ ਹੋਣ ਦਾ ਸਬੂਤ ਹੈ, ਚੱਲਦੇ concentrator ਨਾਲ ਸੰਚਾਰ ਦਾ ਨਹੀਂ। i2c-tools ਮੈਨੂਅਲ , Raspberry Pi GPIO ਹਦਾਇਤਾਂ

GPIO ਵਰਜਨ ਧਿਆਨ ਵਿੱਚ ਰੱਖੋ #

ਹੋਰ ਮਸ਼ੀਨ ਦੇ global GPIO ਨੰਬਰ ਨਕਲ ਨਾ ਕਰੋ। ਪੁਰਾਣੀਆਂ ਸਕ੍ਰਿਪਟਾਂ /sys/class/gpio ਵਰਤਦੀਆਂ ਹਨ, ਜਿਸਨੂੰ kernel ਦਸਤਾਵੇਜ਼ ਪੁਰਾਣੀ ਇੰਟਰਫੇਸ ਕਹਿੰਦੇ ਹਨ। ਨਵੇਂ user-space ਇੰਟੀਗ੍ਰੇਸ਼ਨ ਸਹੀ ਕੰਟਰੋਲਰ ਅਤੇ line offset ਨਾਲ GPIO character-device ਇੰਟਰਫੇਸ ਵਰਤਣ। Linux GPIO ਦਸਤਾਵੇਜ਼

ਸਕ੍ਰਿਪਟ ਅਨੁਕੂਲ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ gpioset --help ਵੀ ਵੇਖੋ। ਵਰਜਨ 1 ਅਤੇ 2 ਵਿੱਚ syntax ਅਤੇ process ਦਾ ਵਿਹਾਰ ਵੱਖਰਾ ਹੈ। ਮੌਜੂਦਾ ਟੂਲ ਮੰਗੀਆਂ ਲਾਈਨਾਂ ਮੂਲ ਰੂਪ ਵਿੱਚ ਫੜੀ ਰੱਖਦਾ ਹੈ, ਪਰ portable ਸਮਝੌਤਾ process ਮੁੱਕਣ ਤੋਂ ਬਾਅਦ ਹਾਲਤ ਦੀ ਗਾਰੰਟੀ ਨਹੀਂ ਦਿੰਦਾ। libgpiod gpioset ਦਸਤਾਵੇਜ਼

Raspberry Pi kernel ਵਿੱਚ output ਕਾਇਮ ਰਹਿਣ ਦਾ ਵਿਹਾਰ ਅਤੇ ਇਸਨੂੰ ਬਦਲਣ ਦੇ ਵਿਕਲਪ ਦਰਜ ਕਰਦਾ ਹੈ। ਹਰ Linux ਇੱਕੋ ਵਰਤਾਅ ਕਰੇਗਾ ਇਹ ਮੰਨਣ ਦੀ ਥਾਂ ਅਸਲ kernel ਸੰਰਚਨਾ ਲਿਖੋ। ਨੰਬਰਿੰਗ ਜਾਂ ਟੂਲ ਅੱਪਡੇਟ ਕਰਨ ਨਾਲ ਗਲਤ ਬਿਜਲੀ ਮੈਪਿੰਗ ਠੀਕ ਨਹੀਂ ਹੁੰਦੀ। Raspberry Pi GPIO ਵਰਤੋਂ ਗਾਈਡ

ਯੂਜ਼ਰ LED ਜਾਂਚੋ #

GPIO22 LED ਨਾਲ ਜੁੜਿਆ ਹੈ ਅਤੇ ਟਕਰਾਉਂਦੇ GPIO ਵਰਤੋਂਕਾਰ ਹਟਾਏ ਹਨ, ਇਹ ਪੱਕਾ ਕਰਨ ਤੋਂ ਬਾਅਦ boot config ਸੋਧੋ:

sudoedit /boot/firmware/config.txt

ਨਵੇਂ Raspberry Pi OS ਵਿੱਚ boot config /boot/firmware/config.txt ਉੱਤੇ ਹੈ। ਪੁਰਾਣੀਆਂ ਇਮੇਜਾਂ /boot/config.txt ਵਰਤਦੀਆਂ ਹਨ, ਜੋ 2023 ਲੇਖ ਦਾ ਰਸਤਾ ਸੀ। ਸੋਧਣ ਤੋਂ ਪਹਿਲਾਂ ਸਰਗਰਮ ਫਾਈਲ ਦੀ ਨਕਲ ਰੱਖੋ। Raspberry Pi config.txt ਦਸਤਾਵੇਜ਼

ਆਪਣੇ Pi ਲਈ ਲਾਗੂ ਭਾਗ, ਜਿਵੇਂ [all], ਹੇਠ LED overlay ਜੋੜੋ:

dtoverlay=gpio-led,gpio=22,label=lorawan,trigger=heartbeat

gpio ਪੈਰਾਮੀਟਰ BCM ਨੰਬਰ ਵਰਤਦਾ ਹੈ। label Linux LED ਡਿਵਾਈਸ ਨੂੰ ਨਾਂ ਦਿੰਦਾ ਹੈ ਅਤੇ trigger=heartbeat kernel heartbeat trigger ਸੈੱਟ ਕਰਦਾ ਹੈ। Clockwork Bird M1 ਲਈ ਇਹ ਨਿਯੁਕਤੀ ਦੱਸਦਾ ਹੈ; Raspberry Pi overlay ਹਵਾਲਾ ਵੀ ਪੈਰਾਮੀਟਰ ਦਰਜ ਕਰਦਾ ਹੈ। ਮੂਲ LED ਨਿਰੀਖਣ , gpio-led overlay ਹਵਾਲਾ

Reboot ਤੋਂ ਬਾਅਦ ਦਰਜ LED ਵੇਖੋ:

ls -l /sys/class/leds/
cat /sys/class/leds/lorawan/trigger

ਉਮੀਦ ਦਾ ਨਤੀਜਾ lorawan LED ਐਂਟਰੀ ਹੈ, ਜਿਸ ਵਿੱਚ heartbeat ਚੌਰਸ ਬਰੈਕਟਾਂ ਵਿੱਚ ਚੁਣਿਆ ਹੈ। LED ਦਾ ਟਿਮਟਿਮਾਉਣਾ GPIO/ਡਰਾਈਵਰ ਰਸਤਾ ਦਿਖਾਉਂਦਾ ਹੈ। ਇਹ LoRaWAN ਰਜਿਸਟ੍ਰੇਸ਼ਨ, ਰੇਡੀਓ ਪ੍ਰਾਪਤੀ ਜਾਂ Helium ਹਾਲਤ ਨਹੀਂ ਦੱਸਦਾ।

ਪਿਛਲੇ ਭਾਗ ਦੀ ਐਡੈਪਟਰ ਸੂਚੀ ਤੋਂ ਸ਼ੁਰੂ ਕਰੋ। ਵਿਆਪਕ i2cdetect ਸਕੈਨ ਸਿਰਫ਼ ਸੁਣਦੇ ਨਹੀਂ, probe ਲੈਣ-ਦੇਣ ਭੇਜਦੇ ਹਨ; upstream ਮੈਨੂਅਲ ਰੁਕਾਵਟ ਦੀ ਚੇਤਾਵਨੀ ਦਿੰਦਾ ਹੈ। ਚੱਲਦੇ ਗੇਟਵੇ ਜਾਂ ਅਣਜਾਣ ਜੁੜੇ ਡਿਵਾਈਸ ਨੂੰ ਰੁਟੀਨ ਵਿੱਚ ਸਕੈਨ ਨਾ ਕਰੋ। i2c-tools probe ਵਿਹਾਰ

ਨਿਰੀਖਣਸਮਰਥਿਤ ਨਤੀਜਾਬਾਕੀ ਸਵਾਲ
