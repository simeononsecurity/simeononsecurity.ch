ਜਾਣ-ਪਛਾਣ: ਕੌਮੀ ਸੁਰੱਖਿਆ ਸੰਕਟ #

2024 ਦੇ ਅਖੀਰ ਵਿੱਚ ਅਤੇ ਪੂਰੇ 2025 ਦੌਰਾਨ ਸੁਤੰਤਰ ਸੁਰੱਖਿਆ ਖੋਜਕਾਰਾਂ ਨੇ ਅਮਰੀਕੀ ਕਾਨੂੰਨ ਲਾਗੂ ਕਰਨ ਵਾਲੀ ਨਿਗਰਾਨੀ ਤਕਨਾਲੋਜੀ ਦੇ ਇਤਿਹਾਸ ਦੀਆਂ ਸਭ ਤੋਂ ਵੱਡੀਆਂ ਸੁਰੱਖਿਆ ਨਾਕਾਮੀਆਂ ਵਿੱਚੋਂ ਇੱਕ ਲੱਭੀ। Flock Safety ਦੇ ਕੈਮਰਾ ਸਿਸਟਮਾਂ ਵਿੱਚ 50 ਤੋਂ ਵੱਧ ਗੰਭੀਰ ਕਮਜ਼ੋਰੀਆਂ ਮਿਲੀਆਂ। ਇਹ ਕੈਮਰੇ ਦੇਸ਼ ਭਰ ਵਿੱਚ 80,000 ਤੋਂ ਵੱਧ ਥਾਵਾਂ ਉੱਤੇ ਹਰ ਰੋਜ਼ 150 ਮਿਲੀਅਨ ਤੋਂ ਵੱਧ ਵਾਹਨਾਂ ਦੀਆਂ ਤਸਵੀਰਾਂ ਲੈਂਦੇ ਅਤੇ ਉਨ੍ਹਾਂ ਦਾ ਪਿੱਛਾ ਕਰਦੇ ਹਨ।

ਇਹ ਲੇਖ ਇਨ੍ਹਾਂ ਕਮਜ਼ੋਰੀਆਂ ਦਾ ਵਿਸਥਾਰਪੂਰਵਕ ਤਕਨੀਕੀ ਵਿਸ਼ਲੇਸ਼ਣ ਪੇਸ਼ ਕਰਦਾ ਹੈ। ਇਹ ਇਨ੍ਹਾਂ ਸਰੋਤਾਂ ਉੱਤੇ ਆਧਾਰਿਤ ਹੈ:

  • GainSec ਦਾ ਰਸਮੀ ਵ੍ਹਾਈਟਪੇਪਰ, “Examining the Security Posture of an Anti-Crime Ecosystem” (51 ਨਤੀਜੇ, 22 ਦਿੱਤੇ CVE, 8 ਲੰਬਿਤ)
  • Ben Jordan ਦੀ ਖੋਜੀ ਪੱਤਰਕਾਰੀ ਅਤੇ ਹੱਥੀਂ ਕੀਤੀ ਸੁਰੱਖਿਆ ਜਾਂਚ
  • ਜਨਤਕ ਤੌਰ ਉੱਤੇ ਖੁੱਲ੍ਹੀਆਂ ਕੈਮਰਾ ਫੀਡਾਂ ਬਾਰੇ 404 Media ਦੀ ਰਿਪੋਰਟਿੰਗ
  • Flock Safety ਅਤੇ ਅਮਰੀਕੀ ਸੈਨੇਟਰਾਂ ਦੇ ਰਸਮੀ ਜਵਾਬ
  • National Vulnerability Database (NVD) ਵਿੱਚ ਪ੍ਰਕਾਸ਼ਿਤ ਖੁਲਾਸੇ
  • Distributed Denial of Secrets ਵੱਲੋਂ ਜਾਰੀ ਕੀਤਾ ਸਤੰਬਰ 2026 ਦਾ ਫ਼ਾਈਲ-ਸਿਸਟਮ ਡੰਪ, ਜਿਸਦਾ ਲਾਈਨ-ਦਰ-ਲਾਈਨ ਤਕਨੀਕੀ ਵਿਸ਼ਲੇਸ਼ਣ Micah Lee ਨੇ ਕੀਤਾ ਅਤੇ WIRED ਤੇ 404 Media ਨੇ ਸਾਂਝੀ ਜਾਂਚ ਕੀਤੀ

ਇਹ ਕੈਮਰੇ ਕਿਉਂ ਹਨ ਅਤੇ ਪਰਦੇਦਾਰੀ ਉੱਤੇ ਅਸਰ ਬਾਰੇ ਸਾਡਾ ਲੇਖ ਪੜ੍ਹੋ: Flock Safety ਕੈਮਰਾ ਨਿਗਰਾਨੀ: ਫੈਲਾਅ, ਪਰਦੇਦਾਰੀ ਚਿੰਤਾਵਾਂ ਅਤੇ ਬਚਾਅ ਦੇ ਤਰੀਕੇ

ਇਨ੍ਹਾਂ ਕੈਮਰਿਆਂ ਨੂੰ ਲੱਭਣ ਦੇ ਤਰੀਕਿਆਂ ਲਈ ਪੜ੍ਹੋ: Flock-You ਪਛਾਣ ਪ੍ਰੋਜੈਕਟ: ਨਿਗਰਾਨੀ-ਵਿਰੋਧੀ ਹਾਰਡਵੇਅਰ ਗਾਈਡ

ਇਹ ਡੰਪ ਉਹ ਇਤਰਾਜ਼ ਦੂਰ ਕਰਦਾ ਹੈ। ਉਤਪਾਦਨ ਕੈਮਰੇ ਦੀ default ਹਾਲਤ ਵਿੱਚ, operator ਦੀ ਕਿਸੇ ਤਬਦੀਲੀ ਤੋਂ ਬਿਨਾਂ, ਬੁਨਿਆਦੀ ਢਾਂਚੇ ਦੇ ਪ੍ਰਮਾਣ ਸਾਫ਼-ਪਾਠ ਵਿੱਚ ਹਨ, ਸੁਰੱਖਿਅਤ ਕੀਤੇ ਜਾਣ ਵਾਲੇ ਡਾਟੇ ਕੋਲ ਕੁੰਜੀਆਂ ਹਨ ਅਤੇ operating system ਵਿੱਚ ਅੱਠ ਸਾਲਾਂ ਦੇ ਸੁਰੱਖਿਆ patch ਨਹੀਂ ਹਨ। ਕੋਈ ਐਕਸਪਲੋਇਟ ਨਹੀਂ ਚਾਹੀਦਾ ਸੀ। ਇੱਕ ਪਾਨਾ ਚਾਹੀਦਾ ਸੀ।

  • configuration ਫ਼ਾਈਲਾਂ ਵਿੱਚ MySQL/PostgreSQL ਪ੍ਰਮਾਣ
  • ਸਥਾਨਕ shell ਤੋਂ ਸਿੱਧੀ database ਪਹੁੰਚ

4. ਕ੍ਰਿਪਟੋਗ੍ਰਾਫ਼ਿਕ keystore #

  • CVE-2025-59407 ਨਾਲ ਪੁਸ਼ਟੀ: DetectionProcessing ਐਪ Java keystore ਦੇ ਨਾਲ ਹਾਰਡਕੋਡ ਪਾਸਵਰਡ ਰੱਖਦੀ ਹੈ ਅਤੇ keystore ਵਿੱਚ private key ਹੈ
  • ਗੰਭੀਰਤਾ: CRITICAL (CVSS 9.8), ਕਿਉਂਕਿ key material ਉਸੇ binary ਨਾਲ ਜਾਂਦਾ ਹੈ ਜਿਸਦਾ ਕੰਮ ਇਸਨੂੰ ਬਚਾਉਣਾ ਹੈ

5. Wi-Fi ਨੈੱਟਵਰਕ ਨਾਮ #

  • ਪਸੰਦੀਦਾ ਨੈੱਟਵਰਕਾਂ ਦੀ ਸੂਚੀ firmware ਵਿੱਚ ਹਾਰਡਕੋਡ ਹੈ
  • ਦੁਸ਼ਟ ਪਹੁੰਚ ਬਿੰਦੂ ਹਮਲੇ ਸੰਭਵ ਕਰਦੀ ਹੈ (ਕਮਜ਼ੋਰੀ #6 ਵੇਖੋ)

6. ਕਲਾਉਡ ਸੇਵਾ ਪ੍ਰਮਾਣ #

  • code ਵਿੱਚ AWS/Azure token
  • ਤੀਜੇ ਪੱਖ ਦੀਆਂ API key (ArcGIS, map ਸੇਵਾਵਾਂ)
  • ਕਦੇ ਨਾ ਬਦਲੇ OAuth token

ਹਮਲਾ ਦ੍ਰਿਸ਼: ਦੁਸ਼ਟ ਨੈੱਟਵਰਕ #

ਹਾਰਡਕੋਡ WiFi ਨਾਮਾਂ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਖੋਜਕਾਰਾਂ ਨੇ ਦਿਖਾਇਆ:

  1. ਹਮਲਾਵਰ ਹਾਰਡਕੋਡ SSID ਨਾਲ ਮਿਲਦਾ ਨਕਲੀ WiFi ਨੈੱਟਵਰਕ ਬਣਾਉਂਦਾ ਹੈ
  2. ਕੈਮਰਾ ਆਪਣੇ ਆਪ ਜੁੜਦਾ ਹੈ (ਹਾਰਡਕੋਡ ਨੈੱਟਵਰਕ ਨੂੰ ਤਰਜੀਹ ਦਿੰਦਾ ਹੈ)
  3. ਹਮਲਾਵਰ man-in-the-middle ਰਾਹੀਂ ਸਾਰਾ ਨੈੱਟਵਰਕ ਟ੍ਰੈਫਿਕ ਫੜਦਾ ਹੈ
  4. ਟ੍ਰੈਫਿਕ ਵਿੱਚੋਂ ਸਾਫ਼-ਪਾਠ ਪ੍ਰਮਾਣ ਕੱਢੇ ਜਾਂਦੇ ਹਨ
  5. ਹਮਲਾਵਰ ਨੂੰ backend ਸਿਸਟਮ ਪਹੁੰਚ ਮਿਲਦੀ ਹੈ

ਕੈਮਰੇ ਤੱਕ ਭੌਤਿਕ ਪਹੁੰਚ ਦੀ ਲੋੜ ਨਹੀਂ। WiFi range ਵਿੱਚ ਹੋਣਾ ਕਾਫ਼ੀ ਹੈ।

ਗੰਭੀਰ ਕਮਜ਼ੋਰੀ #5: ਬਹੁ-ਕਾਰਕ ਪ੍ਰਮਾਣੀਕਰਨ ਦੀ ਘਾਟ #

ਸੰਸਥਾਗਤ ਨੀਤੀ ਦੀ ਨਾਕਾਮੀ #

ਗੰਭੀਰਤਾ: HIGH (ਸੰਸਥਾਗਤ)

ਖੁਲਾਸਾ #

Flock Safety ਕੁਝ ਕਾਨੂੰਨ-ਲਾਗੂ ਏਜੰਸੀਆਂ ਲਈ 2FA/MFA ਲਾਜ਼ਮੀ ਨਹੀਂ ਕਰਦਾ, ਭਾਵੇਂ ਇਹੀ ਏਜੰਸੀਆਂ ਹਰ ਰੋਜ਼ 150 ਮਿਲੀਅਨ ਵਾਹਨਾਂ ਦੇ tracking ਡਾਟੇ ਤੱਕ ਪਹੁੰਚਦੀਆਂ ਹਨ।

ਸੁਰੱਖਿਆ ਖੋਜਕਾਰ ਦਾ ਹਵਾਲਾ:

“ਜਦੋਂ ਮੈਨੂੰ ਪਹਿਲੀ ਵਾਰ ਇਹ ਪਤਾ ਲੱਗਾ ਤਾਂ ਮੈਨੂੰ ਯਕੀਨ ਹੀ ਨਹੀਂ ਆਇਆ। Disney Plus ਵਿੱਚ login ਕਰਨ ਵੇਲੇ ਦੀ ਸੁਰੱਖਿਆ ਪ੍ਰਕਿਰਿਆ ਵੀ ਕੁਝ ਪੁਲਿਸ ਵਿਭਾਗਾਂ ਲਈ ਗੁਪਤ ਜਾਣਕਾਰੀ ਅਤੇ ਲਗਭਗ ਹਰੇਕ ਦੀ ਥਾਂ ਤੱਕ ਪਹੁੰਚਣ ਲਈ ਬਹੁਤ ਔਖੀ ਮੰਗ ਹੈ।”

ਇਹ ਕਿਉਂ ਅਹਿਮ ਹੈ #

MFA/2FA ਤੋਂ ਬਿਨਾਂ:

  • ਇੱਕ ਪਾਸਵਰਡ ਚੋਰੀ ਹੋਣ ਨਾਲ ਪੂਰੇ ਸਿਸਟਮ ਦੀ ਪਹੁੰਚ ਮਿਲਦੀ ਹੈ
  • phishing ਹਮਲੇ ਬਹੁਤ ਅਸਰਦਾਰ ਹੁੰਦੇ ਹਨ
  • ਹੋਰ ਉਲੰਘਣਾਂ ਦੇ ਪ੍ਰਮਾਣਾਂ ਨਾਲ credential stuffing ਕੰਮ ਕਰਦੀ ਹੈ
  • ਅੰਦਰੂਨੀ ਖਤਰੇ ਚਲਾਉਣੇ ਆਸਾਨ ਹੁੰਦੇ ਹਨ
  • ਚੋਰੀ ਹੋਏ ਯੰਤਰ ਤੁਰੰਤ ਪਹੁੰਚ ਦਿੰਦੇ ਹਨ

  • Gmail: ਨਵੇਂ ਖਾਤਿਆਂ ਲਈ 2FA default
  • ਬੈਂਕਿੰਗ: ਕਾਨੂੰਨ ਅਨੁਸਾਰ 2FA ਲੋੜੀਂਦਾ
  • ਸੋਸ਼ਲ ਮੀਡੀਆ: 2FA ਆਮ ਹੈ

ਹਰ ਰੋਜ਼ 150M ਤੋਂ ਵੱਧ ਵਾਹਨਾਂ ਨੂੰ track ਕਰਨ ਵਾਲੇ ਸਿਸਟਮ ਦੀ ਸੁਰੱਖਿਆ ਲੋੜ:

  • Flock Safety: 2FA ਚੋਣਵਾਂ (ਕੁਝ ਏਜੰਸੀਆਂ ਨਹੀਂ ਵਰਤਦੀਆਂ)

ਅਮਰੀਕੀ ਸੈਨੇਟਰ ਦਾ ਜਵਾਬ #

FTC ਜਾਂਚ ਦੀ ਮੰਗ ਵਾਲੇ ਸੈਨੇਟਰ Wyden ਦੇ ਪੱਤਰ ਵਿੱਚ ਇਸ ਖੋਜ ਨੂੰ ਖਾਸ ਤੌਰ ਉੱਤੇ ਦਰਸਾਇਆ ਗਿਆ। ਇਸਨੂੰ Flock Safety ਵੱਲੋਂ:

“ਅਮਰੀਕੀਆਂ ਦੇ ਸੰਵੇਦਨਸ਼ੀਲ ਨਿੱਜੀ ਡਾਟੇ ਨੂੰ ਹੈਕਰਾਂ ਅਤੇ ਵਿਦੇਸ਼ੀ ਜਾਸੂਸਾਂ ਵੱਲੋਂ ਚੋਰੀ ਦੇ ਜੋਖਮ ਵਿੱਚ ਬਿਨਾਂ ਲੋੜ ਪਾਇਆ”

ਜਾਣ ਦਾ ਸਬੂਤ ਕਿਹਾ ਗਿਆ।

ਸੌਖਾ ਹੱਲ #

USB/NFC ਸੁਰੱਖਿਆ key ਦੀ ਕੀਮਤ $10–25 ਹੈ ਅਤੇ ਇਹ ਦਿੰਦੀ ਹੈ:

  • phishing-ਰੋਧੀ ਪ੍ਰਮਾਣੀਕਰਨ
  • ਵਾਧੂ app ਜਾਂ code ਦੀ ਲੋੜ ਨਹੀਂ
  • FIDO2/WebAuthn ਮਿਆਰ ਨਾਲ ਮੇਲ
  • ਸੌਖੀ ਵਰਤੋਂ (ਲਗਾਓ ਜਾਂ ਯੰਤਰ ਨਾਲ ਛੁਹਾਓ)

ਜੇ ਕਾਨੂੰਨ-ਲਾਗੂ ਅਮਲੇ ਲਈ ਇਹ “ਬਹੁਤ ਝੰਝਟ” ਹੈ ਤਾਂ ਉਨ੍ਹਾਂ ਨੂੰ ਕੌਮੀ ਨਿਗਰਾਨੀ ਸਿਸਟਮਾਂ ਤੱਕ ਪਹੁੰਚ ਨਹੀਂ ਮਿਲਣੀ ਚਾਹੀਦੀ।

ਗੰਭੀਰ ਕਮਜ਼ੋਰੀ #6: ਨੈੱਟਵਰਕ ਟ੍ਰੈਫਿਕ ਸਾਫ਼-ਪਾਠ ਵਿੱਚ #

ਪਛਾਣ-ਨੰਬਰ ਮਿਲਣ ਦੀ ਉਡੀਕ #

ਗੰਭੀਰਤਾ: HIGH (ਖੋਜਕਾਰਾਂ ਦਾ ਅੰਦਾਜ਼ਾ CVSS 7.8)

ਇਸ ਸ਼੍ਰੇਣੀ ਲਈ ਕੋਈ CVE ਪਛਾਣ-ਨੰਬਰ ਨਹੀਂ ਦਿੱਤਾ ਗਿਆ। ਸਭ ਤੋਂ ਨੇੜਲਾ record CVE-2025-59406 ਹੈ, ਜਿਸ ਵਿੱਚ CWE-319 cleartext transmission ਵਰਗੀਕਰਨ ਹੈ। ਪਰ ਇਹ ਚੱਲਦੇ ਡਾਟੇ ਨੂੰ ਰੋਕਣ ਦੀ ਥਾਂ embedded Auth0 secret ਬਾਰੇ ਹੈ। ਇਸ ਹਿੱਸੇ ਦੇ ਨਤੀਜੇ ਉੱਪਰ ਦਿੱਤੀਆਂ ਖੋਜ ਰਿਪੋਰਟਾਂ ਉੱਤੇ ਟਿਕੇ ਹਨ।

ਕਮਜ਼ੋਰੀ #

ਜਦੋਂ ਕੈਮਰੇ LTE ਜਾਂ WiFi network ਨਾਲ ਜੁੜਦੇ ਹਨ, ਉਹ ਕਾਫ਼ੀ ਇਨਕ੍ਰਿਪਸ਼ਨ ਤੋਂ ਬਿਨਾਂ ਡਾਟਾ ਭੇਜਦੇ ਹਨ:

ਅਸਰ ਵਾਲਾ ਟ੍ਰੈਫਿਕ:

  • license plate ਦੀਆਂ ਤਸਵੀਰਾਂ ਅਤੇ ਲਿਖਤ
  • ਪਛਾਣ metadata
  • system log
  • configuration ਡਾਟਾ
  • ਕੁਝ ਮਾਮਲਿਆਂ ਵਿੱਚ ਪ੍ਰਮਾਣ

ਹਮਲੇ ਦਾ ਰਾਹ #1: ਦੁਸ਼ਟ WiFi ਨੈੱਟਵਰਕ #

ਖੋਜਕਾਰਾਂ ਨੇ ਦਿਖਾਇਆ:

  1. ਕੈਮਰੇ ਵਿੱਚੋਂ SIM card ਕੱਢੋ ਜਾਂ ਹਾਰਡਕੋਡ SSID ਵਾਲਾ ਨਕਲੀ network ਬਣਾਓ
  2. ਕੈਮਰਾ ਦੁਸ਼ਟ WiFi ਨਾਲ ਜੁੜਦਾ ਹੈ
  3. Wireshark ਜਾਂ ਹੋਰ packet analyzer ਨਾਲ ਟ੍ਰੈਫਿਕ ਫੜੋ
  4. NetworkMiner ਜਾਂ Unblo ਵਰਗੇ ਸੰਦ ਨਾਲ ਵਿਸ਼ਲੇਸ਼ਣ ਕਰੋ
  5. ਸਾਫ਼-ਪਾਠ ਪ੍ਰਮਾਣ ਅਤੇ ਸੰਵੇਦਨਸ਼ੀਲ ਡਾਟਾ ਕੱਢੋ

GainSec ਖੋਜ ਤੋਂ ਹਵਾਲਾ:

“ਮੈਂ ਇਨ੍ਹਾਂ ਕੈਮਰਿਆਂ ਵਿੱਚੋਂ ਇੱਕ ਵੱਲੋਂ ਭੇਜਿਆ pcap ਡਾਟਾ ਕੁਝ ਸਮੇਂ ਲਈ ਫੜਿਆ ਅਤੇ Wireshark ਤੇ Unblo ਨਾਲ ਵੇਖਿਆ…ਅਤੇ ਸੱਚਮੁੱਚ ਡਾਟੇ ਵਿੱਚ ਸਾਫ਼-ਪਾਠ ਪ੍ਰਮਾਣ ਸਨ।”

ਹਮਲੇ ਦਾ ਰਾਹ #2: IMSI catcher / Stingray #

ਹੋਰ ਜਟਿਲ ਹਮਲੇ ਲਈ ਭੌਤਿਕ ਨੇੜਤਾ ਵੀ ਨਹੀਂ ਚਾਹੀਦੀ:

  1. DIY Stingray ਯੰਤਰ ਵਜੋਂ IMSI catcher ਜਾਂ ਪੇਸ਼ੇਵਰ SDR ਵਰਤੋ
  2. cell tower ਬਣ ਕੇ LTE connection ਹਾਈਜੈਕ ਕਰੋ
  3. ਕੈਮਰਾ ਦੁਸ਼ਟ base station ਨਾਲ ਜੁੜਦਾ ਹੈ
  4. man-in-the-middle ਰਾਹੀਂ ਸਾਰਾ ਟ੍ਰੈਫਿਕ ਰੋਕੋ
  5. ਪ੍ਰਮਾਣ, ਤਸਵੀਰਾਂ ਅਤੇ metadata ਕੱਢੋ

ਭੌਤਿਕ ਪਹੁੰਚ ਦੀ ਲੋੜ ਨਹੀਂ। ਇਹ ਸੈਂਕੜੇ ਫੁੱਟ ਦੂਰ ਤੋਂ ਵੀ ਚੱਲਦਾ ਹੈ।

ਆਧੁਨਿਕ Tempest ਹਮਲੇ ਦੀ ਸੰਭਾਵਨਾ #

ਸਾਫ਼-ਪਾਠ ਸੰਚਾਰ Tempest-ਵਰਗੇ ਹਮਲੇ ਵੀ ਸੰਭਵ ਕਰਦਾ ਹੈ, ਜਿਵੇਂ:

  • ਵੀਡੀਓ stream ਨੂੰ ਦੂਰੋਂ ਮੁੜ ਬਣਾਇਆ ਜਾ ਸਕਦਾ ਹੈ

ਕਮਜ਼ੋਰੀਆਂ 11–51 #

GainSec ਦੇ white paper ਵਿੱਚ 41 ਹੋਰ ਖੋਜਾਂ ਦਰਜ ਹਨ, ਜਿਨ੍ਹਾਂ ਵਿੱਚ ਸ਼ਾਮਲ ਹਨ:

ਸਿਸਟਮ ਡਿਜ਼ਾਈਨ ਦੀਆਂ ਖਾਮੀਆਂ:

  • production firmware ਵਿੱਚ debug mode ਚਾਲੂ
  • ਅਸੁਰੱਖਿਅਤ boot process ਨਾਲ bootloader ਉੱਤੇ ਕਾਬੂ ਸੰਭਵ
  • keys ਸੰਭਾਲਣ ਲਈ secure element ਜਾਂ TPM ਨਹੀਂ
  • firmware update ਦਾ ਢੰਗ ਪਹਿਲਾਂ ਤੋਂ ਅਨੁਮਾਨਯੋਗ

ਪ੍ਰਮਾਣੀਕਰਨ ਦੀਆਂ ਸਮੱਸਿਆਵਾਂ:

  • session token ਕਦੇ ਮਿਆਦ ਪੂਰੀ ਨਹੀਂ ਕਰਦੇ
  • IP-ਅਧਾਰਿਤ ਪਹੁੰਚ ਪਾਬੰਦੀਆਂ ਨਹੀਂ
  • ਯੰਤਰਾਂ ਦੇ ਸਮੂਹਾਂ ਵਿੱਚ ਸਾਂਝੇ ਪ੍ਰਮਾਣ ਪੱਤਰ
  • certificate pinning ਨਹੀਂ

ਨੈੱਟਵਰਕ ਸੁਰੱਖਿਆ:

  • debug ਸੇਵਾਵਾਂ ਵਾਲੇ ਖੁੱਲ੍ਹੇ ਪੋਰਟ
  • ਕੁਝ ਯੰਤਰਾਂ ਉੱਤੇ Telnet ਚਾਲੂ
  • ਕਮਜ਼ੋਰ ਪ੍ਰਮਾਣ ਪੱਤਰਾਂ ਵਾਲੇ FTP server
  • DNS rebinding ਦੀਆਂ ਕਮਜ਼ੋਰੀਆਂ

ਪਰਦੇਦਾਰੀ / ਡਾਟਾ ਸੰਭਾਲ:

  • ਤਸਵੀਰਾਂ ਦੱਸੀ ਮਿਆਦ ਤੋਂ ਵੱਧ ਸਮੇਂ ਤੱਕ ਸੰਭਾਲੀਆਂ ਜਾਂਦੀਆਂ
  • metadata ਕਦੇ ਮਿਟਾਇਆ ਨਹੀਂ ਜਾਂਦਾ
  • ਚਿਹਰਾ ਪਛਾਣ ਡਾਟਾ ਇਕੱਠਾ ਕੀਤਾ ਜਾਂਦਾ ਹੈ
  • ਵਾਹਨਾਂ ਤੋਂ ਇਲਾਵਾ ਹੋਰਾਂ ਦੀ ਥਾਂ track ਕੀਤੀ ਜਾਂਦੀ ਹੈ

ਭੌਤਿਕ ਸੁਰੱਖਿਆ:

  • ਕੇਸ ਆਸਾਨੀ ਨਾਲ ਖੋਲ੍ਹੇ ਜਾ ਸਕਦੇ ਹਨ
  • serial interface ਬਾਹਰ ਹਨ
  • JTAG debugging ਪੋਰਟਾਂ ਤੱਕ ਪਹੁੰਚ ਸੰਭਵ ਹੈ
  • ਛੇੜਛਾੜ ਦਾ ਸਬੂਤ ਦੇਣ ਵਾਲੀਆਂ ਸੀਲਾਂ ਨਹੀਂ

ਕ੍ਰਿਪਟੋਗ੍ਰਾਫੀ ਦੀਆਂ ਨਾਕਾਮੀਆਂ:

  • ਕਮਜ਼ੋਰ random number generation
  • encryption keys ਕੋਡ ਵਿੱਚ ਪਹਿਲਾਂ ਤੋਂ ਲਿਖੀਆਂ
  • hash chain ਵਿੱਚ MD5 ਅਜੇ ਵੀ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ
  • certificate validation ਬੰਦ ਹੈ

ਜਾਣਕਾਰੀ ਸਾਹਮਣੇ ਆਉਣਾ:

  • ਵਿਸਥਾਰਪੂਰਵਕ error message ਅੰਦਰੂਨੀ ਜਾਣਕਾਰੀ ਦੱਸਦੇ ਹਨ
  • web server ਉੱਤੇ directory listing ਚਾਲੂ ਹੈ
  • source code ਦੀਆਂ ਟਿੱਪਣੀਆਂ ਵਿੱਚ ਪ੍ਰਮਾਣ ਪੱਤਰ ਹਨ
  • configuration backup ਹਰ ਕਿਸੇ ਵੱਲੋਂ ਪੜ੍ਹੇ ਜਾ ਸਕਦੇ ਹਨ

ਦ੍ਰਿਸ਼ 1: ਦੇਸ਼-ਪੱਧਰੀ ਜਾਸੂਸੀ #

ਖਤਰਾ ਪੈਦਾ ਕਰਨ ਵਾਲਾ: ਵਿਦੇਸ਼ੀ ਖੁਫੀਆ ਸੇਵਾ

ਤਰੀਕਾ:

  4. ਸਰਕਾਰੀ ਥਾਵਾਂ ਉੱਤੇ ਰਜਿਸਟਰ ਕੀਤੇ ਵਾਹਨਾਂ ਲਈ ਡਾਟਾਬੇਸ ਖੋਜੋ
  5. ਅਧਿਕਾਰੀਆਂ ਅਤੇ ਫ਼ੌਜੀ ਕਰਮਚਾਰੀਆਂ ਦੀ ਆਵਾਜਾਈ track ਕਰੋ

ਦ੍ਰਿਸ਼ 2: ਸੰਗਠਿਤ ਅਪਰਾਧ ਵੱਲੋਂ ਜਵਾਬੀ ਨਿਗਰਾਨੀ #

  5. ਹੋਰ ਤਰੀਕਾ: payload ਪੁਲਿਸ ਗੱਡੀਆਂ ਦੀ tracking ਦੂਰਲੇ server ਵੱਲ ਕੱਢਦਾ ਹੈ

  4. ਨੈੱਟਵਰਕ ਅਲੱਗ ਰੱਖੋ: ਕੈਮਰੇ ਸਮਰਪਿਤ VLAN ਉੱਤੇ ਰੱਖੋ
  5. ਭੌਤਿਕ ਸੁਰੱਖਿਆ: ਛੇੜਛਾੜ-ਸਪਸ਼ਟ ਸੀਲਾਂ, ਕੈਮਰਿਆਂ ਦੀ ਨਿਗਰਾਨੀ
  6. ਸਮਝੌਤਾ ਹੋਣ ਲਈ ਘਟਨਾ-ਜਵਾਬ ਯੋਜਨਾ ਬਣਾਓ

  1. ਸੁਤੰਤਰ ਕੰਪਨੀਆਂ ਵੱਲੋਂ ਨਿਯਮਤ ਸੁਰੱਖਿਆ ਜਾਂਚਾਂ

  5. ਸੁਰੱਖਿਆ ਭੰਗ ਲਈ SLA ਜੁਰਮਾਨੇ
  6. ਵਿਕਰੇਤਾ ਦੀਆਂ ਥਾਵਾਂ ਅਤੇ ਕੋਡ ਦੀ ਜਾਂਚ ਕਰਨ ਦਾ ਹੱਕ

  4. ਕੈਮਰਿਆਂ ਦੀਆਂ ਥਾਵਾਂ ਅਤੇ ਨੀਤੀਆਂ ਬਾਰੇ ਭਾਈਚਾਰੇ ਨਾਲ ਪਾਰਦਰਸ਼ਤਾ

  3. ਜਾਂਚ ਦੇ ਨਤੀਜਿਆਂ ਦਾ ਜਨਤਕ ਖੁਲਾਸਾ
  4. ਸੁਰੱਖਿਆ ਨਾਕਾਮੀਆਂ ਲਈ ਵਿਕਰੇਤਾ ਦੀ ਜਵਾਬਦੇਹੀ
  5. ਮਿਆਰਾਂ ਦੀ ਪਾਲਣਾ (NIST, ISO ਆਦਿ)

ਖਾਸ ਤੌਰ ਉੱਤੇ Flock Safety ਲਈ:

  1. ਗੰਭੀਰ ਕਮਜ਼ੋਰੀਆਂ ਲਈ ਤੁਰੰਤ ਐਮਰਜੈਂਸੀ patch
  2. ਸਮਰਥਿਤ platform ਵੱਲ OS ਤਬਦੀਲੀ
  3. ਸਮੱਸਿਆ ਦੇ ਪੈਮਾਨੇ ਦੀ ਜਨਤਕ ਸਵੀਕ੍ਰਿਤੀ
  4. ਪ੍ਰਭਾਵਿਤ ਖੋਜਕਾਰਾਂ ਲਈ ਮੁਆਵਜ਼ਾ
  5. ਸੁਰੱਖਿਆ ਸਥਿਤੀ ਬਾਰੇ ਪਾਰਦਰਸ਼ਤਾ ਰਿਪੋਰਟਾਂ

ਕਾਨੂੰਨ ਲਾਗੂ ਕਰਨ ਵਾਲੀਆਂ ਏਜੰਸੀਆਂ ਲਈ:

  1. ਖਰੀਦ ਇਕਰਾਰਨਾਮਿਆਂ ਵਿੱਚ ਸੁਰੱਖਿਆ ਲੋੜਾਂ
  2. ਲੱਗੇ ਸਿਸਟਮਾਂ ਦੀਆਂ ਨਿਯਮਤ ਜਾਂਚਾਂ
  3. ਸਾਰੇ ਵਰਤੋਂਕਾਰਾਂ ਲਈ MFA ਲਾਜ਼ਮੀ
  4. ਘਟਨਾ-ਜਵਾਬ ਯੋਜਨਾਵਾਂ
  5. ਨਿਗਰਾਨੀ ਪ੍ਰੋਗਰਾਮਾਂ ਬਾਰੇ ਭਾਈਚਾਰੇ ਨਾਲ ਪਾਰਦਰਸ਼ਤਾ

ਕਾਨੂੰਨਸਾਜ਼ਾਂ ਲਈ:

  1. ਨਿਗਰਾਨੀ ਤਕਨਾਲੋਜੀ ਲਈ ਸੰਘੀ ਮਿਆਰ
  2. ਪ੍ਰਭਾਵਿਤ ਧਿਰਾਂ ਨੂੰ ਕਮਜ਼ੋਰੀਆਂ ਬਾਰੇ ਲਾਜ਼ਮੀ ਸੂਚਨਾ
  3. ਸੁਰੱਖਿਆ ਖੋਜਕਾਰਾਂ ਲਈ whistleblower ਸੁਰੱਖਿਆ
  4. ਪਰਦੇਦਾਰੀ ਉਲੰਘਣਾਂ ਲਈ ਦੀਵਾਨੀ ਕਾਨੂੰਨੀ ਉਪਾਅ
  5. ਨਿਗਰਾਨੀ ਸਿਸਟਮਾਂ ਲਈ ਨਿਗਰਾਨੀ ਪ੍ਰਬੰਧ

ਵੱਡੀ ਤਸਵੀਰ #

ਇਹ ਮਾਮਲਾ ਸਿਰਫ਼ Flock Safety ਬਾਰੇ ਨਹੀਂ। ਇਹ ਦਰਸਾਉਂਦਾ ਹੈ:

  • ਨਿਗਰਾਨੀ ਉਦਯੋਗ ਸੁਰੱਖਿਆ ਤੋਂ ਪਹਿਲਾਂ ਵਾਧੇ ਨੂੰ ਤਰਜੀਹ ਦਿੰਦਾ ਹੈ
  • ਸਰਕਾਰੀ ਖਰੀਦ ਵਿੱਚ ਤਕਨੀਕੀ ਮਾਹਰਤਾ ਘੱਟ ਹੈ
  • ਵਿਕਰੇਤਾਵਾਂ ਦੇ ਦਾਅਵੇ ਬਿਨਾਂ ਜਾਂਚੇ ਤੇ ਤਸਦੀਕ ਕੀਤੇ ਰਹਿ ਜਾਂਦੇ ਹਨ
  • ਵਿੱਤੀ ਲਾਭ ਜਨਤਕ ਸੁਰੱਖਿਆ ਨਾਲ ਮੇਲ ਨਹੀਂ ਖਾਂਦੇ
  • ਨਵੀਂ ਤਕਨਾਲੋਜੀ ਲਈ ਨਿਯਮਕ ਖਾਲੀਆਂ ਥਾਵਾਂ ਹਨ

ਹਰ ਉਹ ਸ਼ਹਿਰ ਜੋ ਸੁਤੰਤਰ ਸੁਰੱਖਿਆ ਤਸਦੀਕ ਤੋਂ ਬਿਨਾਂ Flock ਇਕਰਾਰਨਾਮੇ ਉੱਤੇ ਦਸਤਖ਼ਤ ਕਰਦਾ ਹੈ, ਆਪਣੇ ਵਸਨੀਕਾਂ ਦੀ ਥਾਂ ਇਹ ਖਤਰੇ ਕਬੂਲ ਕਰਦਾ ਹੈ।

ਅਗਲਾ ਕਦਮ #

ਸੁਰੱਖਿਆ ਮਾਹਰਾਂ ਲਈ:

  • ਜ਼ਿੰਮੇਵਾਰ ਖੁਲਾਸੇ ਦੀਆਂ ਕੋਸ਼ਿਸ਼ਾਂ ਦਾ ਸਮਰਥਨ ਕਰੋ
  • ਮੁਕਤ-ਸਰੋਤ ਸੁਰੱਖਿਆ ਸਾਧਨਾਂ ਵਿੱਚ ਯੋਗਦਾਨ ਪਾਓ
  • ਖੋਜਕਾਰਾਂ ਦੀ ਸੁਰੱਖਿਆ ਲਈ ਵਕਾਲਤ ਕਰੋ

ਕਾਨੂੰਨ ਲਾਗੂ ਕਰਨ ਵਾਲਿਆਂ ਲਈ:

  • ਤਾਇਨਾਤੀ ਤੋਂ ਪਹਿਲਾਂ ਸੁਰੱਖਿਆ ਜਾਂਚ ਲਾਜ਼ਮੀ ਕਰੋ
  • ਤੁਰੰਤ MFA ਲਾਗੂ ਕਰੋ
  • ਸਲਾਹ ਲਈ ਸੁਰੱਖਿਆ ਭਾਈਚਾਰੇ ਨਾਲ ਜੁੜੋ

ਨੀਤੀ-ਨਿਰਧਾਰਕਾਂ ਲਈ:

  • ਸੁਰੱਖਿਆ ਮਿਆਰ ਲਾਜ਼ਮੀ ਕਰਨ ਵਾਲੇ ਕਾਨੂੰਨ ਪਾਸ ਕਰੋ
  • ਨਿਗਰਾਨੀ ਤਕਨਾਲੋਜੀ ਦੀਆਂ ਸੁਤੰਤਰ ਜਾਂਚਾਂ ਲਈ ਫੰਡ ਦਿਓ
  • whistleblower ਅਤੇ ਖੋਜਕਾਰਾਂ ਦੀ ਰੱਖਿਆ ਕਰੋ
  • ਤਕਨੀਕੀ ਮਾਹਰਤਾ ਵਾਲੇ ਨਿਗਰਾਨੀ ਸੰਗਠਨ ਬਣਾਓ

ਜਨਤਾ ਲਈ:

  • ਆਪਣੇ ਭਾਈਚਾਰੇ ਵਿੱਚ ਨਿਗਰਾਨੀ ਬਾਰੇ ਜਾਣਕਾਰੀ ਲਵੋ

  • ਪਾਰਦਰਸ਼ਤਾ ਲਈ ਕੰਮ ਕਰਦੀਆਂ ਸੰਸਥਾਵਾਂ ਦਾ ਸਮਰਥਨ ਕਰੋ
  • ਚਿੰਤਾਵਾਂ ਬਾਰੇ ਆਪਣੇ ਨੁਮਾਇੰਦਿਆਂ ਨਾਲ ਸੰਪਰਕ ਕਰੋ
  • ਨਿਗਰਾਨੀ ਨਕਸ਼ੇ ਬਣਾਉਣ ਲਈ ਪਛਾਣ ਸਾਧਨ ਵਰਤੋ (ਸਾਡੀ ਹਾਰਡਵੇਅਰ ਗਾਈਡ ਵੇਖੋ)
