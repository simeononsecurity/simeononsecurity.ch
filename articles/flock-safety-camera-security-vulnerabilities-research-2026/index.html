ভূমিকা: জাতীয় নিরাপত্তার সংকট #

২০২৪ সালের শেষদিকে এবং ২০২৫ সালজুড়ে স্বাধীন নিরাপত্তা গবেষকেরা যুক্তরাষ্ট্রের আইন প্রয়োগকারী সংস্থার নজরদারি প্রযুক্তির ইতিহাসে সবচেয়ে বড় নিরাপত্তা ব্যর্থতাগুলোর একটি উন্মোচন করেন। Flock Safety-এর ক্যামেরা ব্যবস্থায় ৫০টিরও বেশি গুরুতর দুর্বলতা পাওয়া গেছে। এই ক্যামেরাগুলো সারা দেশে ৮০,০০০-এর বেশি স্থাপনায় প্রতিদিন ১৫ কোটিরও বেশি গাড়ির ছবি তোলে এবং সেগুলোর চলাচল অনুসরণ করে।

এই নিবন্ধে দুর্বলতাগুলোর বিস্তারিত প্রযুক্তিগত বিশ্লেষণ দেওয়া হয়েছে। বিশ্লেষণটি নিচের উৎসের ওপর নির্ভর করে:

  • GainSec-এর আনুষ্ঠানিক শ্বেতপত্র, “Examining the Security Posture of an Anti-Crime Ecosystem” (৫১টি ফলাফল, ২২টি নির্ধারিত CVE, ৮টি অপেক্ষমাণ)
  • Ben Jordan-এর অনুসন্ধানী সাংবাদিকতা ও হাতে-কলমে নিরাপত্তা পরীক্ষা
  • জনসাধারণের জন্য উন্মুক্ত ক্যামেরা ফিড নিয়ে 404 Media-র প্রতিবেদন
  • Flock Safety এবং যুক্তরাষ্ট্রের সিনেটরদের আনুষ্ঠানিক প্রতিক্রিয়া
  • National Vulnerability Database (NVD)-এ প্রকাশিত তথ্য
  • Distributed Denial of Secrets প্রকাশিত ২০২৬ সালের সেপ্টেম্বরের ফাইলসিস্টেম ডাম্প, যার লাইন-অনুযায়ী প্রযুক্তিগত বিশ্লেষণ করেছেন Micah Lee এবং WIRED ও 404 Media যৌথভাবে তদন্ত করেছে

এই ক্যামেরাগুলো কেন আছে এবং গোপনীয়তার ওপর প্রভাব জানতে আমাদের নিবন্ধটি পড়ুন: Flock Safety ক্যামেরা নজরদারি: বিস্তার, গোপনীয়তার উদ্বেগ এবং সুরক্ষার কৌশল

এই ক্যামেরাগুলো শনাক্ত করার পদ্ধতি জানতে পড়ুন: Flock-You শনাক্তকরণ প্রকল্প: নজরদারি-বিরোধী হার্ডওয়্যার নির্দেশিকা

Flock-এর ব্যাকএন্ডে প্রবেশাধিকার দেওয়া একটি API কী অ্যাপ্লিকেশনের বাইনারিতে হার্ডকোড করা আছে। মানটি com.flocksafety.android.common.lib-এর CameraSettings নামের ক্লাসে আছে। Flock সাধারণ লাইব্রেরিটি ১৯টি অ্যাপেই যুক্ত করেছে। তাই প্রতিটি অ্যাপেই কীটি থাকে। flock-sambuca অ্যাপটি সেটআপের সময় কীটি ব্যবহার করে।

  3. ক্যামেরাটি ফেরত পাওয়া শংসাপত্র প্লেইনটেক্সটে সংরক্ষণ করে

এনক্রিপশন কীটি তালার সঙ্গেই পাঠানো হয়েছে #

Flock বলে তাদের ক্যামেরা ডিভাইসে এনক্রিপশন দিয়ে সুরক্ষিত। ডাম্পে বাস্তব প্রয়োগটি দেখা যায়।

১৮ GB-এর media পার্টিশনটি একটি এনক্রিপ্ট করা কনটেইনারের ভেতরে আছে। কিন্তু ডিক্রিপশন কী একই পার্টিশনে .key দিয়ে শেষ হওয়া নামের একটি ফাইলে আছে। stegan0gram দল কীটি পুনরুদ্ধার করে কনটেইনার খুলেছে এবং ভেতরের ডেটা পড়েছে। ঢাকনায় চাবি টেপ দিয়ে লাগানো তালাবদ্ধ বাক্স যতটা সুরক্ষিত, ছবিগুলোও ততটাই এনক্রিপ্ট করা।

পুনরুদ্ধার করা লগে ক্যামেরাটির অবস্থানও দেখা গেছে। লগে ১৫৫ বার GPS স্থানাঙ্ক আছে। সেগুলো প্রায় ১০০ মিটারের মধ্যে জমা হয়েছে, যা খুঁটিতে লাগানো রিসিভারের স্বাভাবিক বিচ্যুতি। স্থানাঙ্কগুলো Milwaukee-র উপশহর Wisconsin-এর Wauwatosa-য় যায়। সেখানে ক্যামেরাটি N Mayfair Road-এ বসানো ছিল। Micah Lee Google Street View-এর সঙ্গে লগ মিলিয়ে সিরিয়াল নম্বর ও MAC address দিয়ে নির্দিষ্ট ইউনিটটি শনাক্ত করেন।

Flock কী বলেছে #

Flock-এর প্রতিক্রিয়ায় আগের GainSec ফলাফল নিয়ে তাদের অবস্থানই পুনরাবৃত্তি হয়। একজন মুখপাত্র বলেন:

“Flock নিরাপত্তাকে গুরুত্ব দেয় এবং নিরাপত্তা গবেষকেরা সম্ভাব্য দুর্বলতা সরাসরি জানাতে পারেন, সে জন্য প্রকাশ্য Vulnerability Disclosure Policy বজায় রাখে। ওই প্রক্রিয়ায় আমরা কোনো প্রতিবেদন পাইনি। দেওয়া সীমিত তথ্যের ভিত্তিতে উত্থাপিত দাবিগুলো মূল্যায়নের মতো যথেষ্ট বিবরণ আমাদের কাছে নেই।”

এই বক্তব্যের সঙ্গে সময়রেখার মিল পাওয়া কঠিন। ক্যামেরার অপারেটিং সিস্টেমের দুর্বলতাগুলো ২০১৮ ও ২০২১ সালে প্রকাশ্যে প্যাচ করা হয়েছিল। শংসাপত্র সংরক্ষণ ও key management-এর মান ক্যামেরা পাঠানোর অনেক আগ থেকেই বদলায়নি। দশ বছরের প্রকাশ্য দুর্বলতার ইতিহাস পর্যালোচনায় বাইরের কোনো প্রতিবেদন লাগে না।

Flock ক্যামেরা খুলে বিশ্লেষণ করাকে বেআইনি বলেছে, যা বর্তমান আইনে সত্য। তবু যেভাবেই হার্ডওয়্যার পাওয়া হোক, নিরাপত্তা-সংক্রান্ত ফলাফলগুলো নিজস্ব ভিত্তিতে টিকে থাকে।

CVE-2025-47818, CVE-2025-47821, CVE-2025-47823, CVE-2025-59407 এবং CVE-2025-59409 #

তীব্রতা: সংকটজনক (সর্বোচ্চ পর্যায়ে CVSS 9.8)

হার্ডকোড করা গোপন তথ্যের বিভাগ #

নিরাপত্তা গবেষকেরা বিস্তৃত পরিসরে হার্ডকোড করা শংসাপত্র পেয়েছেন:

1. WiFi অ্যাক্সেস পয়েন্টের পাসওয়ার্ড #

  • সব Falcon/Sparrow ক্যামেরায় একই সার্বজনীন পাসওয়ার্ড
  • ব্যবহারকারী বা প্রশাসক পরিবর্তন করতে পারেন না
  • গবেষকদের জানা; শ্বেতপত্রের কিছু সম্পাদিত অংশে প্রকাশিত
  • CVE-2025-59409-এ নিশ্চিত: উৎপাদিত Falcon ও Sparrow firmware (build OPM1.171019.026)-এ উন্নয়ন WiFi credential প্লেইনটেক্সটে পাঠানো হয়

2. API key ও token #

  • firmware ও অ্যাপ্লিকেশন code-এ হার্ডকোড করা
  • বিভিন্ন পরিষেবার backend-এ প্রবেশাধিকার দেয়
  • Android APK reverse engineering করে পাওয়া গেছে
  • ২০২৬ সালের সেপ্টেম্বরের dump-এ নিশ্চিত: backend API key com.flocksafety.android.common.lib-এর CameraSettings-এ হার্ডকোড করা। একই shared library ডিভাইসের সব ১৯টি Flock app-এ যুক্ত
  • Auth0 client ID ও secret এনক্রিপ্ট না করা /persist partition-এ flock/auth0/auth0_cred-এ আছে। অবস্থানটি factory reset-এর পরেও টিকে থাকার জন্য তৈরি
  • ক্যামেরা নিজের MAC address দিয়ে Flock-এর Okta Auth0 পরিষেবায় প্রমাণীকরণের পর ফেরত পাওয়া credential প্লেইনটেক্সটে থাকে

3. Database credential #

  • পাসওয়ার্ড সুরক্ষা ছাড়া SQLite database
  • configuration file-এ MySQL/PostgreSQL credential
  • স্থানীয় shell থেকে সরাসরি database access

4. ক্রিপ্টোগ্রাফিক keystore #

  • CVE-2025-59407-এ নিশ্চিত: DetectionProcessing app-এ Java keystore-এর পাশে হার্ডকোড করা পাসওয়ার্ডও থাকে। keystore-এ একটি ব্যক্তিগত কী আছে
  • তীব্রতা: সংকটজনক (CVSS 9.8), কারণ যেই binary-র কাজ কী-সামগ্রী রক্ষা করা, তার সঙ্গেই কী-সামগ্রী পাঠানো হয়

5. Wi-Fi network name #

  • পছন্দের নেটওয়ার্কের তালিকা firmware-এ হার্ডকোড করা
  • দুর্বৃত্ত access point আক্রমণের সুযোগ দেয় (দুর্বলতা #6 দেখুন)

6. Cloud পরিষেবার credential #

  • code-এ AWS/Azure token যুক্ত
  • তৃতীয় পক্ষের API key (ArcGIS, mapping services)
  • কখনো পরিবর্তন না করা OAuth token

আক্রমণের দৃশ্য: দুর্বৃত্ত নেটওয়ার্ক #

হার্ডকোড করা WiFi network name ব্যবহার করে গবেষকেরা দেখিয়েছেন:

  1. আক্রমণকারী হার্ডকোড করা SSID-এর সঙ্গে মিলে যায় এমন ভুয়া WiFi network চালু করে
  2. ক্যামেরা স্বয়ংক্রিয়ভাবে সংযুক্ত হয় (হার্ডকোড করা network-কে অগ্রাধিকার দেয়)
  3. আক্রমণকারী man-in-the-middle পদ্ধতিতে সব network traffic ধরে
  4. ট্রাফিক থেকে প্লেইনটেক্সট credential বের করা হয়
  5. আক্রমণকারী backend system-এ প্রবেশাধিকার পায়

ক্যামেরার কাছে শারীরিকভাবে যাওয়ার দরকার নেই। WiFi range-এর মধ্যে থাকলেই চলে।

কেন এটি গুরুত্বপূর্ণ #

MFA/2FA না থাকলে:

  • একটি পাসওয়ার্ড চুরি হলেই পুরো সিস্টেমে প্রবেশ সম্ভব
  • ফিশিং আক্রমণ অত্যন্ত কার্যকর হয়
  • অন্য ডেটা ফাঁস থেকে পাওয়া credential stuffing কাজ করে
  • ভেতরের আক্রমণ চালানো সহজ হয়
  • চুরি হওয়া ডিভাইস সঙ্গে সঙ্গে প্রবেশাধিকার দেয়

  • Disney+: 2FA ব্যবহার করা যায়
  • Gmail: নতুন অ্যাকাউন্টে 2FA ডিফল্ট
  • ব্যাংকিং: আইন অনুযায়ী 2FA দরকার
  • সামাজিক যোগাযোগমাধ্যম: 2FA স্বাভাবিক ব্যবস্থা

Rubber Ducky / BadUSB আক্রমণ #

BadUSB device-এর দাম ৫–১৫ ডলার। এটি:

  • সিস্টেমের কাছে USB keyboard হিসেবে দেখা দেয়
  • আগে থেকে প্রোগ্রাম করা script বা payload চালায়
  • লাগালেই স্বয়ংক্রিয়ভাবে চলে
  • ব্যবহারকারীর কোনো পদক্ষেপ লাগে না

আক্রমণের দৃশ্য #

  1. স্থাপন করা Flock ডিভাইসের কাছে যান
  2. উন্মুক্ত port-এ BadUSB device লাগান
  3. ডিভাইসটি payload বা script চালায়
  4. payload স্থায়ী malware বসায়
  5. আক্রমণকারী সেখান থেকে চলে যায়
  6. malware LTE/WiFi দিয়ে আক্রমণকারীর সার্ভারে সংযোগ করে

দুর্বলতা ১১–৫১ #

GainSec-এর শ্বেতপত্রে আরও ৪১টি ফলাফল আছে, যার মধ্যে:

সিস্টেম নকশার ত্রুটি:

  • উৎপাদিত firmware-এ debug mode চালু
  • অনিরাপদ boot process-এ bootloader দখলের সুযোগ
  • key storage-এর জন্য secure element বা TPM নেই
  • অনুমান করা যায় এমন firmware update পদ্ধতি

প্রমাণীকরণের সমস্যা:

  • session token-এর মেয়াদ কখনো শেষ হয় না
  • IP-ভিত্তিক প্রবেশ সীমা নেই
  • ডিভাইসের বহরজুড়ে অভিন্ন credential
  • certificate pinning নেই

নেটওয়ার্ক নিরাপত্তা:

  • debug পরিষেবা থাকা উন্মুক্ত port
  • কিছু ইউনিটে Telnet চালু
  • দুর্বল credential-যুক্ত FTP server
  • DNS rebinding দুর্বলতা

গোপনীয়তা/ডেটা সংরক্ষণ:

  • ঘোষিত সময়ের পরেও ছবি সংরক্ষণ
  • metadata কখনো মুছে ফেলা হয় না
  • মুখ শনাক্তকরণের তথ্য সংগ্রহ
  • শুধু গাড়ি নয়, অন্যদের অবস্থান অনুসরণ

শারীরিক নিরাপত্তা:

  • enclosure সহজে খোলা যায়
  • serial interface উন্মুক্ত
  • JTAG debugging port-এ প্রবেশ সম্ভব
  • খোলা বা নাড়াচাড়া বোঝার seal নেই

ক্রিপ্টোগ্রাফির ব্যর্থতা:

  • দুর্বল random number generation
  • হার্ডকোড করা encryption key
  • hash chain-এ এখনও MD5 ব্যবহার
  • certificate validation বন্ধ

তথ্য প্রকাশ:

  • verbose error message-এ অভ্যন্তরীণ তথ্য দেখা যায়
  • web server-এ directory listing চালু
  • source code comment-এ credential আছে
  • configuration backup সবাই পড়তে পারে

ফেব্রুয়ারি ২০২৬: সিনেটর Ron Wyden (Oregon) ও Raja Krishnamoorthi (Illinois) FTC-কে তদন্তের অনুরোধ জানিয়ে আনুষ্ঠানিক চিঠি পাঠান।

চিঠির অংশ:

“Flock অপ্রয়োজনীয়ভাবে আমেরিকানদের সংবেদনশীল ব্যক্তিগত তথ্য হ্যাকার ও বিদেশি গুপ্তচরের চুরির ঝুঁকিতে রেখেছে।”

উল্লেখ করা কারণ:

  • জাতীয় নিরাপত্তার ঝুঁকি
  • গোপনীয়তা নিয়ে প্রতারণামূলক দাবি
  • অপর্যাপ্ত নিরাপত্তা চর্চা
  • MFA বাধ্যতামূলক নয়

Oakland, California:

  • স্বাধীন নিরাপত্তা নিরীক্ষা করা হয়
  • Flock-এর কার্যকারিতার দাবি বিভ্রান্তিকর বলে পাওয়া যায়

  • Flock-এর চুক্তি চেয়ে FOIA অনুরোধ
  • স্বাধীন নিরীক্ষার শর্ত
  • সম্প্রদায়ের পক্ষে প্রচারের চাপ

প্রযুক্তিগত বিশ্লেষণ: বাস্তব আক্রমণের দৃশ্য #

দৃশ্য ১: রাষ্ট্রীয় নজরদারি #

হুমকিদাতা: বিদেশি গোয়েন্দা সংস্থা

লক্ষ্য: সরকারি কর্মকর্তাদের অনুসরণ

পদ্ধতি:

  1. IMSI catcher দিয়ে ক্যামেরার LTE ট্রাফিক আটকানো
  2. stream থেকে প্লেইনটেক্সট credential বের করা
  3. আপসকৃত API key বা আগে উন্মুক্ত ArcGIS layer দিয়ে backend-এ প্রবেশ
  4. সরকারি স্থাপনায় নিবন্ধিত গাড়ির জন্য database খোঁজা
  5. কর্মকর্তা ও সামরিক সদস্যদের চলাচল অনুসরণ

সম্পন্নের সময়: কয়েক দিন (অবকাঠামো প্রস্তুত হওয়ার পর) শনাক্ত হওয়ার সম্ভাবনা: কম (এনক্রিপ্ট করা C2, স্বাভাবিক ট্রাফিকের মতো দেখায়)

দৃশ্য ২: সংঘবদ্ধ অপরাধের পাল্টা-নজরদারি #

হুমকিদাতা: মাদক পাচারকারী সংগঠন

লক্ষ্য: পুলিশের টহলের ধরন শনাক্ত করা

পদ্ধতি:

  1. ১৫ ডলারের BadUSB device কেনা
  2. কাজের এলাকার ক্যামেরায় যাওয়া
  3. উন্মুক্ত USB port-এ BadUSB লাগানো (৩০ সেকেন্ড)
  4. payload দিয়ে ক্যামেরা বন্ধ বা ফুটেজ বদলানো
  5. বিকল্পভাবে, payload পুলিশ গাড়ির tracking দূরের server-এ পাঠায়

সম্পন্নের সময়: প্রতি ক্যামেরায় ৩০ সেকেন্ড শনাক্ত হওয়ার সম্ভাবনা: কম (স্বাভাবিক ডিভাইসের কাজ বলে মনে হয়)

দৃশ্য ৩: অনুসরণকারী / পারিবারিক সহিংসতা #

হুমকিদাতা: নির্যাতনকারী সাবেক সঙ্গী

লক্ষ্য: ভুক্তভোগীর চলাচল অনুসরণ

পদ্ধতি:

  1. ভুক্তভোগীর লাইসেন্স প্লেট জানা (জনসাধারণের তথ্য)
  2. জানুয়ারি ২০২৬-এর দুর্বলতা কাজে লাগিয়ে Google-এ উন্মুক্ত Flock ক্যামেরা interface খোঁজা
  3. গাড়ির উপস্থিতির জন্য ৩০ দিনের ফুটেজ খোঁজা
  4. জনসাধারণের database-এর সঙ্গে মেলানো (কর্মস্থল, বাড়ি ইত্যাদি)
  5. দৈনন্দিন চলাচলের ধরন ও সময় বের করা

সম্পন্নের সময়: কয়েক মিনিট থেকে কয়েক ঘণ্টা শনাক্ত হওয়ার সম্ভাবনা: শূন্য (প্রমাণীকরণের log নেই)

দৃশ্য ৪: প্রমাণ নষ্ট করা #

হুমকিদাতা: ফৌজদারি মামলার আসামি

লক্ষ্য: বিচার শুরুর আগে প্রমাণ নষ্ট করা

পদ্ধতি:

  1. warrant-এর নথি থেকে ক্যামেরার অবস্থান জানা
  2. শারীরিকভাবে ক্যামেরায় যাওয়া (বোতাম চাপার ক্রম)
  3. root shell পাওয়া
  4. প্রমাণের folder-এ যাওয়া
  5. নির্দিষ্ট ছবি/ভিডিও মুছে ফেলা বা timestamp বদলানো

সম্পন্নের সময়: পাঁচ মিনিটেরও কম শনাক্ত হওয়ার সম্ভাবনা: কম (প্রতিরক্ষাপক্ষের প্রবেশের আগে ক্যামেরা forensic পরীক্ষা করা না হলে)

দৃশ্য ৫: গোপনীয়তার পক্ষে কর্মী / সাংবাদিক #

হুমকিদাতা: স্বচ্ছতার পক্ষে থাকা কর্মী

লক্ষ্য: নজরদারির অতিরিক্ত ব্যবহার নথিভুক্ত করা

পদ্ধতি:

  1. শনাক্তকরণ ডিভাইস ব্যবহার করুন (আমাদের Flock-You হার্ডওয়্যার নির্দেশিকা দেখুন)
  2. এলাকায় ক্যামেরার অবস্থান চিহ্নিত করুন
  3. ফুটেজ নীতিমালা চেয়ে FOIA অনুরোধ দিন
  4. নগর পরিষদের সামনে দুর্বলতা দেখান
  5. ক্যামেরা সরানো বা তদারকির পক্ষে কাজ করুন

সম্পন্নের সময়: চলমান শনাক্ত হওয়ার সম্ভাবনা: বেশি (কার্যক্রম জনসমক্ষে হয়)

এসব দুর্বলতার বিরুদ্ধে প্রতিরক্ষা #

আইন প্রয়োগকারী সংস্থার জন্য #

তাৎক্ষণিক পদক্ষেপ:

  1. সব ব্যবহারকারীর জন্য MFA/2FA বাধ্যতামূলক করুন (USB security key)
  2. অননুমোদিত query খুঁজতে মাসে একবার প্রবেশের log নিরীক্ষা করুন
  3. যতটুকু প্রয়োজন, ততটুকু অধিক্ষেত্রে তথ্য ভাগাভাগি সীমিত করুন
  4. নেটওয়ার্ক আলাদা রাখুন, ক্যামেরার জন্য আলাদা VLAN ব্যবহার করুন
  5. শারীরিক নিরাপত্তা দিন, tamper-evident seal লাগান ও ক্যামেরায় নজর রাখুন
  6. সিস্টেম দখল হলে কাজে লাগবে এমন ঘটনা মোকাবিলার পরিকল্পনা রাখুন

চুক্তির শর্ত:

  1. স্বাধীন প্রতিষ্ঠানের মাধ্যমে নিয়মিত নিরাপত্তা নিরীক্ষা
  2. প্যাচ প্রকাশের ৩০ দিনের মধ্যে firmware update বাধ্যতামূলক
  3. ২৪ ঘণ্টার মধ্যে CVE জানানোর নিয়ম
  4. গ্রাহক-নিয়ন্ত্রিত key-সহ এনক্রিপ্ট করা প্রমাণ সংরক্ষণ
  5. নিরাপত্তা ভাঙলে SLA অনুযায়ী জরিমানা
  6. বিক্রেতার স্থাপনা ও code নিরীক্ষার অধিকার

দীর্ঘমেয়াদি কৌশল:

  1. EOL অপারেটিং সিস্টেম থেকে সরে যাওয়ার পরিকল্পনা
  2. cloud নির্ভরতা কমাতে নিজস্ব অবকাঠামো
  3. মুক্ত উৎসের বিকল্প মূল্যায়ন
  4. ক্যামেরার অবস্থান ও নীতিমালা সম্পর্কে সম্প্রদায়ের জন্য স্বচ্ছতা

Flock Safety-এর জন্য (সুপারিশ) #

সর্বোচ্চ অগ্রাধিকার (এখনই):

  1. বোতাম চাপলে তারবিহীন access point তৈরি হয়, সেটি বন্ধ করুন
  2. কোনো ব্যতিক্রম ছাড়া সব ব্যবহারকারীর জন্য MFA বাধ্যতামূলক করুন
  3. পুরো সিস্টেমের সব হার্ডকোড করা credential বদলান
  4. উন্মুক্ত public interface-এর জন্য জরুরি patch দিন
  5. সঠিক key management-সহ সঞ্চিত ডেটা এনক্রিপ্ট করুন

উচ্চ অগ্রাধিকার (৩০ দিনের মধ্যে):

  1. সমর্থিত OS-এ স্থানান্তর করুন (Android 12+ বা Linux-ভিত্তিক)
  2. NDA ছাড়া bug bounty program চালু করুন
  3. তৃতীয় পক্ষের নিরাপত্তা নিরীক্ষা করে ফল প্রকাশ করুন
  4. শুরু থেকে শেষ পর্যন্ত network traffic এনক্রিপ্ট করুন
  5. শারীরিক নিরাপত্তা উন্নত করুন (উন্মুক্ত USB সরান, শক্ত enclosure ব্যবহার করুন)

মাঝারি অগ্রাধিকার (৯০ দিনের মধ্যে):

  1. প্রমাণীকরণ ব্যবস্থা সম্পূর্ণ নতুন করে নকশা করুন
  2. যাচাইকৃত firmware-সহ secure boot চালু করুন
  3. Hardware security module যুক্ত করুন
  4. FedRAMP, SOC 2, ISO 27001-এর মতো সনদ নিন
  5. নিরাপত্তা ভাঙলে সতর্ক করা গ্রাহক নিরাপত্তা dashboard চালু করুন

দীর্ঘমেয়াদি (১ বছরে):

  1. আস্থা বাড়াতে নিরাপত্তা উপাদান open source করুন
  2. red team দিয়ে প্রতিপক্ষের মতো পরীক্ষা চালান
  3. নিরাপত্তা প্রকৌশলীর পদ-যোগ্যতা নির্ধারণ করুন
  4. SDLC-তে নিরাপত্তা চর্চা যুক্ত করুন (DevSecOps)
  5. OWASP, CIS-এর মতো শিল্পমান তৈরিতে অংশ নিন

ব্যক্তির জন্য #

সুরক্ষার কৌশল:

  1. শনাক্তকরণ ডিভাইস ব্যবহার করুন (আমাদের হার্ডওয়্যার নির্দেশিকা দেখুন)
  2. নিজের এলাকায় ক্যামেরার অবস্থান মানচিত্রে দেখান
  3. পথ ও সময় বদলান যাতে চলাচলের ধরন বিশ্লেষণ কঠিন হয়
  4. নগর পরিষদে নজরদারির তদারকি ও স্বচ্ছতার দাবি তুলুন
  5. নিজের ডেটার জন্য FOIA অনুরোধ করুন (আইন অনুমতি দিলে)
  6. রাজ্য ও ফেডারেল পর্যায়ে গোপনীয়তা রক্ষার আইনের পক্ষে থাকুন

OpSec ব্যবস্থা:
