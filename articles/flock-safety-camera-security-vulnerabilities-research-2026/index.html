50 多项严重安全漏洞暴露了全国最大的私人监控网络

引言：国家安全危机 #

2024 年底和整个 2025 年期间，独立安全研究人员发现了可能是美国执法监控技术史上最严重的安全故障。Flock Safety 摄像头系统中已发现50 多项严重漏洞。这些摄像头每天拍摄并追踪超过 1.5 亿辆车，在全国部署超过 8 万台。

本文基于以下资料，对这些漏洞进行全面的技术分析：

  • GainSec 的正式白皮书《Examining the Security Posture of an Anti-Crime Ecosystem》（51 项发现、22 个已分配 CVE、8 个待分配）
  • Ben Jordan 的调查报道和实际安全测试
  • 404 Media 关于公开暴露摄像头视频流的报道
  • Flock Safety 和美国参议员的官方回应
  • 国家漏洞数据库（NVD）公布的漏洞披露
  • Distributed Denial of Secrets 于 2026 年 9 月发布的文件系统镜像，以及 Micah Lee 的逐行技术分析和 WIRED 与 404 Media 的联合调查

如需了解这些摄像头为何存在以及对隐私的影响，请参阅文章： Flock Safety 摄像头监控：普及情况、隐私问题与防护策略

如需了解如何发现这些摄像头，请参阅： Flock-You 检测项目：反监控硬件指南

问题范围 #

易受攻击基础设施的规模 #

截至 2026 年 5 月：

  • 美国部署了 8 万多台 Flock Safety 摄像头
  • 5,000 多个城市和城镇使用 Flock 服务
  • 3,500 多个执法机构可访问系统
  • 2.2 万多名执法人员访问数据库
  • 可搜索数据库中存储了数十亿个数据点

漏洞时间线 #

  • 2024 年底：安全研究人员 Jon “GainSec” Gaines 发现初始漏洞
  • 2025 年 2 月：开始向 Flock Safety 负责任地披露漏洞
  • 2025 年 4 月：公布首批 CVE 分配
  • 2025 年 11 月：正式白皮书发布，共列出 51 项发现
  • 2025 年 12 月：Ben Jordan 通过视频展示漏洞
  • 2026 年 1 月：404 Media 发现 60 多个可公开访问的摄像头视频流
  • 2026 年 2 月：美国参议员要求 FTC 展开调查
  • 2026 年 5 月：披露流程仍在继续

漏洞类别 #

50 多项漏洞涉及多个类别：

  1. 身份验证与授权（硬编码密码、缺少 MFA）
  2. 密码学与加密（静态和传输中的数据未加密）
  3. 网络安全（暴露的 Wi-Fi 接入点、明文凭据）
  4. 物理安全（按键利用、暴露的 USB 端口）
  5. 数据隐私（未经授权的数据收集、延长的数据保留）
  6. 系统设计（软件过时、访问控制不足）
  7. 信息泄露（暴露的 API 密钥、公开的摄像头视频流）

2026 年 9 月的文件系统转储 #

2026 年 9 月，透明度非营利组织 Distributed Denial of Secrets 发布了一台在役 Flock 摄像头的完整文件系统镜像。 一个自称 stegan0gram 的团体从杆柱上拧下硬件，复制内部存储，并发布了镜像。404 Media 和 WIRED 联合展开调查，安全研究人员 Micah Lee 发布了内容的技术分析。

本文之前的每项发现都来自研究人员的实验室设备或购买的设备。这个数据集来自一台正在市政服务中使用的摄像头，因此是迄今发布的最有力证据。

摄像头并非通过网络遭到入侵。它是被人从杆柱上物理拆下来的。

转储包含什么 #

发布内容包括三个分区镜像，每个分区都揭示了不同问题。

分区大小重要性
system1.5 GBAndroid 系统镜像，包含 19 个 Flock 开发的应用，包括 flock-sambuca、flock-collins 和 flock-phone-home
persist32 MB设备凭据位于 flock/auth0/auth0_cred，这是一个未加密分区，设计为恢复出厂设置后仍保留数据
media18 GB日志和图像位于一个容器中，而解密密钥存放在同一分区

凭据问题得到证实 #

这份转储确认了硬编码凭据并非理论问题，而是已在部署中使用。它们确实存在于部署设备上。

授予访问 Flock 后端权限的 API 密钥被硬编码在应用二进制文件中。 该值位于 com.flocksafety.android.common.lib 内名为 CameraSettings 的类中。Flock 将共享库打包进全部 19 个应用，因此每个应用都包含该密钥。flock-sambuca 应用在设备配置过程中使用它。

身份验证流程如下：

  1. 每台摄像头向 Flock 服务器请求凭据，并使用 MAC 地址标识自己
  2. Flock 的 Okta Auth0 登录服务返回一个短期 FlockAuth0Token
  3. 摄像头将返回的凭据以明文存储

Auth0 客户端 ID 和客户端密钥存放在未加密的 /persist 分区中，且所在文件设计为恢复出厂设置后仍然保留。攻击者首先提取 persist 分区，因为该分区没有受到保护。

严重漏洞 #4 介绍平台中更广泛的硬编码机密问题。

随锁附带的加密密钥 #

Flock 称其摄像头受到设备端加密保护。转储显示了这种实现的实际情况。

18 GB 的 media 分区确实位于加密容器中。解密密钥却放在同一分区中，文件名以 .key 结尾。stegan0gram 团体找回密钥、解锁容器并读取了内容。这种图像加密就像把钥匙用胶带贴在盒盖上，然后声称盒子上了锁。

恢复的日志还揭示了摄像头自身的位置。GPS 坐标在日志中出现 155 次，集中在约 100 米范围内，这对于固定在杆柱上的接收器而言属于正常漂移。坐标指向密尔沃基郊区威斯康星州沃瓦托萨市的 N Mayfair Road，摄像头就安装在那里。Micah Lee 将日志与 Google Street View 对照，并通过序列号和 MAC 地址识别出具体设备。

如果密钥和密文存放在一起，静态加密就毫无意义。

Flock 的回应 #

Flock 的回应重复了其对先前 GainSec 发现的立场。一位发言人表示：

“Flock 认真对待安全问题，并维护公开的漏洞披露政策，方便安全研究人员直接向我们报告潜在漏洞。我们没有通过该流程收到报告，而且根据所提供的有限信息，我们没有足够细节来评估相关说法。”

这番回应难以与时间线相符。摄像头操作系统中的漏洞早在 2018 年和 2021 年就已公开修复，而凭据存储和密钥管理标准在摄像头出货前很久就已存在。审查十年的公开漏洞历史并不需要外部报告。

Flock 还称拆除和分析摄像头的行为违法。根据现行法律，这一说法成立。但无论硬件如何取得，安全发现本身仍然成立。

为什么这比早期研究更重要 #

GainSec 白皮书记录了针对合法取得设备的 51 项发现。Flock 对严重程度提出异议，并声称访问需要靠近设备。

这次转储消除了这些保留条件。生产摄像头的默认状态未经操作人员修改，就包含明文基础设施凭据、与受保护数据存放在一起的密钥，以及缺少八年安全补丁的操作系统。这不需要任何漏洞利用，只需要一把扳手。

最明显的是不同世代之间的差距。计算盒运行 Android 13，而它服务的摄像头仍运行 2017 年发布的 Android 8.1。

Falcon 是最值得关注的设备。 它承担 ALPR 工作负载，仍在使用 Android 8.1，并将数据写入 32 GB 未加密 eMMC。stegan0gram 团体恢复的媒体文件和日志就存放在这块 eMMC 中。Sparrow 使用相同平台，但由有线供电。

Bravo 的情况相反。 这款现代计算盒运行 Android 13，并使用 AI 推理处理摄像头视频，表明公司愿意在选择这样做时提供当前的软件。

严重漏洞 #1：按键即可开启无线接入点 #

CVE-2025-59403 #

严重程度：严重（CVSS 9.8）

利用方式 #

发现的最令人担忧的漏洞允许任何获得 Flock Safety 摄像头物理访问权限的人在不到 60 秒内完全控制设备：

步骤 1：按下 Falcon/Sparrow 摄像头背面的按钮三次 步骤 2：设备创建开放 Wi-Fi 接入点 步骤 3：连接到 Wi-Fi 网络（硬编码密码已记载在 GainSec 白皮书中） 步骤 4：发送启用 ADB（Android Debug Bridge）的命令 步骤 5：通过 ADB 连接并取得 root shell

技术详情 #

设备:Flock Safety Falcon/Sparrow ALPR 摄像头
硬件:Android Things 8.0/8.1（2021 年停止支持）
攻击途径:按下实体按钮的一系列操作
身份验证:硬编码的 WiFi 密码（所有设备通用）
影响:设备被完全控制、数据外泄并安装恶意软件

这会导致什么 #

取得 shell 访问权限后，攻击者可以：

  • 提取所有已存储图像（包括人员，不只是车辆）
  • 修改或删除设备上存储的证据
  • 安装可持久运行的恶意软件（重启后仍然存在）
  • 克隆设备身份以进行欺骗
  • 拦截并修改视频流
  • 将设备用作僵尸网络客户端发动 DDoS 攻击
  • 捕获附近设备的 Wi-Fi 凭据（蜜罐攻击）
  • 禁用摄像头或造成拒绝服务

演示 #

安全研究人员 Ben Jordan 在 YouTube 上演示了此漏洞：

  • 不到 30 秒即可连接到 Wi-Fi 接入点
  • 不到 60 秒即可取得 root shell
  • 完全访问文件系统、已存储图像和系统内存
  • 能够安装任意 Android 应用

演示中的引述：

“这个接入点的密码是 [REDACTED]，全部使用小写字母。我们测试过的每台摄像头都有这个硬编码密码。接下来只要发送启用 ADB 的命令……大概不到 30 秒，你就能完全进入设备的 shell 并取得完整访问权限。”

供应商回应 #

Flock Safety 最初称此漏洞只影响未连接云端的设备，并将其比作“一台从卡车上偷走、尚未连接网络的 iPhone”。

这一说法后来被推翻。 研究人员在已连接云端的设备、多个存在相同漏洞的摄像头型号，以及从不同来源取得的设备上重现了漏洞。所有设备都有此缺陷。

严重漏洞 #2：Android 操作系统过时 #

严重漏洞 #3：运行时缺少加密 #

CVE-2025-47824 和 CVE-2025-59407 #

严重程度：高到严重（CVSS 2.0 至 9.8）

Flock Safety 的说法与现实 #

Flock Safety 网站声称：

“数据和视频在整个生命周期中均经过加密。”

独立研究人员的发现（GainSec 和 Ben Jordan）：

“在我们的所有研究中，我们没有解密或破解任何东西。所有数据在运行时都没有加密。”

营销说法与技术现实之间的差距是彻底的。

哪些数据未加密 #

研究人员检查设备时，发现以下内容未加密：

  1. 已存储的视频和图像
  2. 车牌数据和元数据
  3. Wi-Fi 凭据和 API 密钥
  4. 包含检测记录的数据库文件
  5. 网络流量（参见漏洞 #6）
  6. 包含敏感信息的系统日志

数据保留方面的矛盾 #

Flock Safety 声称：数据会在 7 天后自动删除。 研究发现：找到的图像可追溯到设备制造时（早了数月或数年）。

GainSec 白皮书摘录：

“我们找到了超过 7 天的图像。事实上，一些已存储图像是在摄像头在工厂制造时被触发所拍摄的。”

这意味着设备本身并未执行其公开的隐私政策。

隐私影响 #

这种加密缺陷意味着：

  • 设备被盗就会导致数据立即泄露
  • 网络拦截会暴露明文数据
  • 内部威胁很容易外传数据
  • 对未加密数据的保护可能不受搜查令保障
  • 违反 HIPAA、CCPA 等多项法规的合规要求

严重漏洞 #4：系统各处存在硬编码凭据 #

CVE-2025-47818、CVE-2025-47821、CVE-2025-47823、CVE-2025-59407 和 CVE-2025-59409 #

严重程度：严重（CVSS 9.8，处于最高等级）

硬编码机密的类别 #

安全研究人员发现了大量硬编码凭据：

1. Wi-Fi 接入点密码 #

  • 所有 Falcon/Sparrow 摄像头使用通用密码
  • 用户和管理员无法更改
  • 研究人员已知并在白皮书中发布（部分内容已删节）
  • CVE-2025-59409 已确认：生产版 Falcon 和 Sparrow 固件（构建版本 OPM1.171019.026）以明文附带开发用 Wi-Fi 凭据

2. API 密钥和令牌 #

  • 硬编码在固件和应用程序代码中
  • 授予对各类服务后端的访问权限
  • 通过对 Android APK 进行逆向工程发现
  • 2026 年 9 月转储证实：后端 API 密钥硬编码在 com.flocksafety.android.common.lib 内的 CameraSettings 中，这是设备上 19 个 Flock 应用共用的库
  • Auth0 客户端 ID 和密钥存储在未加密的 /persist 分区中，路径为 flock/auth0/auth0_cred，该位置设计为恢复出厂设置后仍保留
  • 摄像头使用自身 MAC 地址向 Flock 的 Okta Auth0 服务进行身份验证后，返回的凭据会以明文存储

3. 数据库凭据 #

  • SQLite 数据库没有密码保护
  • 配置文件中含 MySQL/PostgreSQL 凭据
  • 可从本地 shell 直接访问数据库

4. 加密密钥库 #

  • CVE-2025-59407 已确认：DetectionProcessing 应用将 Java 密钥库和硬编码密码一同打包，密钥库中有一把私钥
  • 严重程度：严重（CVSS 9.8），因为密钥材料与本应保护它的二进制文件一起发布

5. Wi-Fi 网络名称 #

  • 固件中硬编码了首选网络列表
  • 可用于发动恶意接入点攻击（参见漏洞 #6）

6. 云服务凭据 #

  • 代码中嵌入 AWS/Azure 令牌
  • 第三方 API 密钥（ArcGIS、地图服务）
  • 从不轮换的 OAuth 令牌

攻击场景：恶意网络 #

研究人员利用硬编码的 Wi-Fi 网络名称进行了演示：

  1. 攻击者设置一个与硬编码 SSID 相同的伪造 Wi-Fi 网络
  2. 摄像头自动连接（优先选择硬编码网络）
  3. 攻击者通过中间人攻击捕获所有网络流量
  4. 从流量中提取明文凭据
  5. 攻击者取得后端系统访问权限

无需物理接触摄像头。 只要进入 Wi-Fi 覆盖范围即可。

严重漏洞 #5：缺少多因素身份验证 #

组织政策失误 #

严重程度：高（组织层面）

这一发现 #

Flock Safety 并未对某些执法机构强制要求 2FA/MFA，而这些机构正是访问每天 1.5 亿辆车追踪数据的机构。

安全研究人员引述：

“我第一次发现这件事时，简直不敢相信。登录 Disney Plus 时要经过的安全流程，对某些警察部门来说却太麻烦，以至于他们不愿在访问机密信息以及几乎所有人的位置信息时使用。”

为什么重要 #

缺少 MFA/2FA 时：

  • 一个被盗密码就能获得完整系统访问权限
  • 网络钓鱼攻击非常有效
  • 其他泄露事件中的密码可用于凭据填充攻击
  • 内部威胁更容易实施
  • 被盗设备会立即授予访问权限

比较 #

安全敏感度较低的系统要求：

  • Disney+：提供 2FA
  • Gmail：新账户默认启用 2FA
  • 银行服务：法律要求 2FA
  • 社交媒体：2FA 已成为标准

每天追踪 1.5 亿多辆车的系统安全要求：

  • Flock Safety：2FA 为可选功能（部分机构未使用）

美国参议员的回应 #

这一发现被特别写入 Wyden 参议员要求 FTC 调查的信函，作为 Flock Safety：

“不必要地使美国人的敏感个人数据面临黑客和外国间谍窃取风险”

的证据。

简单的解决方案 #

USB/NFC 安全密钥售价 10 至 25 美元，并提供：

  • 抗网络钓鱼身份验证
  • 无需额外应用或验证码
  • 符合 FIDO2/WebAuthn 标准
  • 简单的用户体验（插入或轻触设备）

如果执法人员认为这“太麻烦”，他们就不应该访问国家监控系统。

严重漏洞 #6：网络流量以明文传输 #

等待分配标识符 #

严重程度：高（研究人员估计 CVSS 7.8）

此类别尚未分配 CVE 标识符。 最接近的已分配记录 CVE-2025-59406 带有 CWE-319 明文传输分类，但该记录涵盖的是嵌入式 Auth0 密钥，而不是传输中拦截。本节发现仍依据上文引用的研究报告。

漏洞 #

摄像头连接到网络（LTE 或 Wi-Fi）时，会在加密不足的情况下传输数据：

受影响的流量：

  • 车牌图像和文本
  • 检测元数据
  • 系统日志
  • 配置数据
  • 凭据（某些情况下）

攻击向量 #1：恶意 Wi-Fi 网络 #

研究人员展示了以下过程：

  1. 从摄像头中取出 SIM 卡，或者设置与硬编码 SSID 相同的伪造网络
  2. 摄像头连接到恶意 Wi-Fi
  3. 使用 Wireshark 或类似数据包分析器捕获流量
  4. 使用 NetworkMiner 或 Unblo 等工具分析
  5. 提取明文凭据和敏感数据

GainSec 研究引述：

“我捕获了一段时间这类摄像头发送的 pcap 数据，并用 Wireshark 和 Unblo 分析……果然，数据里存在明文凭据。”

攻击向量 #2：IMSI 捕获器 / Stingray #

更复杂的攻击无需物理接近摄像头：

  1. 使用 IMSI 捕获器（自制 Stingray 设备）或专业级 SDR
  2. 冒充基站以劫持 LTE 连接
  3. 摄像头连接到恶意基站
  4. 对所有流量实施中间人攻击
  5. 提取凭据、图像和元数据

无需物理访问。攻击者可在数百英尺外实施攻击。

现代 Tempest 攻击的可能性 #

明文传输也使 Tempest 式攻击成为可能：

  • 可捕获摄像头的射频辐射
  • 视频流可被远程重建
  • 类似于冷战时期 CIA 使用的技术
  • 现代 SDR 设备让这类攻击普通爱好者也能实施

严重漏洞 #7：摄像头视频流公开暴露 #

2026 年 1 月的发现 #

发现过程 #

2026 年 1 月，Ben Jordan 和 404 Media 发现，只需使用简单的 Google 搜索即可找到：

  • 完整的摄像头控制面板访问权限

可访问的内容 #

任何人都可通过这些暴露的界面：

  • 实时观看视频流
  • 查看 30 天的归档录像
  • 直接下载视频文件
  • 控制 Condor 设备上的 PTZ 摄像头（水平转动、垂直转动、变焦）

  • 修改摄像头设置

观察到的隐私侵犯 #

Ben Jordan 记录了自己看到的画面：

  • 一家人在 Lowe’s 停车场把婴儿放进汽车

  • 一名女子独自在佐治亚州的林间小路慢跑
  • 一对情侣在亚特兰大街市争吵（AI 自动放大并对准他们的脸）
  • 警员和救护车在爱荷华州协助处理心理健康危机

跟踪能力 #

暴露的 Condor PTZ 摄像头具有AI 跟踪功能：

  • 自动放大人物
  • 随着人物移动跟踪他们
  • 检测并对准智能手机（以读取屏幕）
  • 同时跟踪多个目标
  • 在无人监督的情况下持续录制

人肉搜索的可能性 #

严重漏洞 #8：未经授权的数据收集 #

与公开声明相矛盾 #

严重程度：高（隐私与法律影响）

Flock Safety 的说法 #

官方网站声明：

“Flock Safety 不会捕获或记录人员数据，只会记录车辆数据。”

独立研究发现 #

摄像头实际执行的操作：

  1. 运动检测会因任何运动触发摄像头，不只是车辆
  2. AI 会在图像中查找车牌
  3. 如果没有找到车牌，图像仍会保存，而非删除
  4. 一个单独文件夹保存没有车牌的图像
  5. 人员、行人和骑行者都会被拍摄并保留

“只拍摄车辆”的说法不实。任何走过摄像头前方的人都会被拍摄并保存图像。

已核实的观察 #

研究人员记录到摄像头拍摄了：

  • 走到摄像头前的人（图像被保存）
  • 对镜头挥手的人（图像被保存）
  • 在摄像头附近移动的桌子或物体（图像被保存）
  • 制造工厂的工人（图像保存了数月）

GainSec 引述：

“当我走到摄像头前方时，雷达模块触发摄像头模块给我拍照。然后，板载 AI 查找车牌，没有找到，但它仍将图像保存到了一个单独的文件夹。”

法律影响 #

这种未经授权的数据收集可能：

  • 违反公开的隐私政策（构成欺骗性做法）
  • 违反采购合同（如果城市规定“只记录车辆”）
  • 触发 GDPR/CCPA 违规（影响欧盟公民和加州居民）
  • 使同意协议失效
  • 因虚假广告使公司面临诉讼

监控范围扩大 #

Condor PTZ 摄像头（2025 至 2026 年部署）被明确设计用于跟踪人员：

  • AI 人员检测
  • 自动放大人脸
  • 随着人员移动进行跟踪
  • 没有退出机制
  • 经常部署在公园、步道和交通站点

监控范围从“车牌识别器”大幅扩大为对一般人群的监控，却没有政策变更、没有新合同，也没有公众通知。

严重漏洞 #9：暴露的 USB 端口可发动 Rubber Ducky 攻击 #

物理访问利用 #

严重程度：高（需要物理访问）

漏洞 #

Bravo 计算盒和部分摄像头型号具有：

  • 外壳上的暴露 USB-C 端口
  • 缺少物理安全防护（机壳密封）
  • 自动执行 USB 设备内容的功能
  • 无需身份验证

Rubber Ducky / BadUSB 攻击 #

BadUSB 设备售价约为 5 至 15 美元，它：

  • 在系统中显示为USB 键盘
  • 执行预先编写的脚本（载荷）
  • 插入后自动运行
  • 无需用户交互

攻击场景 #

GainSec 演示了以下过程：

  1. 接近已部署的 Flock 设备
  2. 将 BadUSB 设备插入暴露端口
  3. 设备执行载荷（脚本）
  4. 载荷安装持久恶意软件
  5. 攻击者转身离开
  6. 恶意软件通过 LTE/Wi-Fi 回连

总用时：不到 30 秒

载荷可以做什么 #

自动化脚本可以：

  • 启用无线接入点（绕过按键操作）
  • 安装后门以供远程访问
  • 将数据外传到远程服务器
  • 修改视频或证据
  • 禁用摄像头或造成 DoS
  • 加入僵尸网络发动 DDoS 攻击
  • 从其他系统捕获凭据

为什么重要 #

超过 8 万台摄像头通常位于半农村地区，且能见度有限：

  • 获取物理访问权限相对容易
  • 没有警卫或持续监控
  • 使用简单的喉箍固定
  • 通常安装在离地 7 英尺处（使用踏凳即可触及）

Ben Jordan 引述：

“这些摄像头并不是坚不可摧的小堡垒。它们是塑料 Android 摄像头和计算盒，用喉箍固定在离地 7 英尺的地方。”

严重漏洞 #10：API 密钥公开暴露 #

发现过程 #

2025 年，OSINT 研究人员 Joshua Michael 发现：

暴露的 ArcGIS API 密钥允许访问：

1. 注册数据

  • 客户姓名
  • 电子邮件地址
  • 每个地点的摄像头数量
  • 文件附件功能

2. 现场巡逻车辆位置（多个部门）

  • 实时 GPS 跟踪警车
  • 科罗拉多州奥罗拉部署情况
  • 卡罗尔顿警察局
  • 国家安全风险

3. 警员个人信息

  • 姓名和电话号码
  • 电子邮件地址
  • 预定巡逻区域
  • 所属辖区

4. 热名单警报数据库（德克萨斯州达拉斯）

  • 6,000 条被标记车辆记录
  • 车牌和标记原因
  • 检测位置和时间戳
  • 拍下车辆的摄像头 ID
  • 五个月的移动轨迹

Joshua Michael 引述：

“任何人都可以用 Google 找到这张地图，然后追踪这些人的移动模式长达五个月。我还要指出，原因类别里有人只被标记为‘嫌疑人’，其他很多记录根本没有原因，或者是空白。”

攻击面 #

暴露的 API 密钥可用于：

  • 跟踪特定车辆
  • 危及警员安全（家庭地址、巡逻模式）
  • 破坏行动安全（了解警察在哪里或不在哪里）
  • 恐吓证人（跟踪报案人员）
  • 为有组织犯罪收集犯罪情报

就在这一发现前几周，安全研究人员 Alexa Feminina 和 James Zhang 称，受中国国家支持的黑客组织 Flax Typhoon 入侵了 ArcGIS。

“据称，黑客以一个合法的公开 ArcGIS 应用为目标……该应用用于灾后恢复、应急管理和其他关键功能。”

这意味着敌对国家可能获得了以下信息：警车位置、警员身份、监控摄像头位置和应急响应模式。

  • 通过适当渠道倡导政策变革
  • 为告知公众承担个人风险

如果没有他们的工作：

  • 8 万多台易受攻击的摄像头会继续无人处理
  • 每天超过 1.5 亿次车辆扫描仍然缺乏保护
  • 数百万美国人会在不知情的情况下暴露隐私
  • 国家安全会遭到损害
  • 不会有任何立法行动展开

结论：前进之路 #

当前状况（2026 年 5 月） #

  • 已记录并部分披露 50 多项严重漏洞
  • 8 万多台摄像头仍在部署，缺陷尚未修复
  • 供应商没有进行全面补救
  • 监管行动有限（已请求 FTC 调查，但调查尚未启动）
  • 国家安全和个人隐私仍面临持续的利用风险

需要采取的措施 #

整个行业：

  1. 政府部署前进行强制安全审计
  2. 由合格的第三方开展独立测试
  3. 公开审计结果
  4. 供应商应对安全失误承担责任
  5. 遵守相关标准（NIST、ISO 等）

Flock Safety 应采取的措施：

  1. 立即为严重漏洞发布紧急补丁
  2. 将操作系统迁移到受支持的平台
  3. 公开承认问题范围
  4. 对受影响的研究人员进行补偿
  5. 发布关于安全态势的透明度报告

执法机构：

  1. 在采购合同中加入安全要求
  2. 对已部署的系统进行定期审计
  3. 对所有用户强制启用 MFA
  4. 制定事件响应计划
  5. 公开监控项目情况，保持社区透明度

立法部门：

  1. 为监控技术制定联邦标准
  2. 要求向受影响方披露漏洞
  3. 为安全研究人员提供举报人保护
  4. 为隐私侵犯提供民事救济途径
  5. 为监控系统建立监督机制

更广泛的背景 #

这个案例不仅关乎 Flock Safety，它还体现了：

  • 监控行业将增长置于安全之上
  • 政府采购缺乏技术专业知识
  • 供应商的说法未经质疑和验证
  • 财务激励与公共安全不一致
  • 新兴技术监管中的空白

任何城市在没有独立安全验证的情况下签署 Flock 合同，都是代表居民接受这些风险。
