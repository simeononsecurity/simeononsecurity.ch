個人セキュリティのガイドは、どれも同じものを提示します。優先順位のない、何百ものヒントを並べた長いリストです。 WebRTCの無効化、canvasフィンガープリントの偽装、user-agentの切り替えを、パスワードマネージャーや自動更新の設定と同列に勧めます。

これらの対策は同じ価値ではありません。同等に扱うと、多くの人が簡単な対策だけを行い、重要な対策を飛ばして、結局同じように危険な状態にとどまります。

この記事ではテーマを保ちながら、誤った同等扱いをやめます。必要な労力に対してどれだけリスクを減らせるかで助言を並べ、やめるべき習慣についても率直に説明します。

要点 #

質問短い回答
最も多くの攻撃を防ぐ対策は?パスワードマネージャー、フィッシング耐性のある追加要素、迅速な更新です。アカウント侵害の一般的な経路に対処しますが、あらゆる脅威を防ぐわけではありません。
今日できる最大の改善は?パスキーまたはハードウェアセキュリティキーです。 認証情報がデバイスから外に出ないため、どちらもサインイン時のフィッシングに強い対策です。復旧方法とデバイス自体も保護してください。
過大評価されている対策は?覚える複雑なパスワード、定期的なパスワード変更、ブラウザーフィンガープリントの調整の多くです。
過小評価されている対策は?バックアップ、アカウント復旧の設定、デバイスの物理的な保護です。
順番は重要?はい。網羅性よりも重要です。今日レベル1を実行する方が、300項目すべてをいつか実行するより効果的です。
レベル1にかかる時間は?一度だけ、約2時間です。

網羅性より順番が重要な理由 #

包括的なチェックリストには通常、数百の項目があり、必須、任意、高度などのラベルが付いています。ラベルは絞り込みに役立ちますが、項目ごとのリスク軽減量にかかわらず同じ分類になるため、優先順位の代わりにはなりません。

私の主張は、3段階でも細かさが足りないということです。「必須」という分類では、リスク軽減量が大きく異なる対策が一緒になります。同じ必須項目でも、次の2つを比べてください。

  • 2FAを有効にすると、アカウント乗っ取りの一種を丸ごと防げます。
  • WebRTCを無効にすると、少数の人に関係するローカルIPの漏えいを防げます。

どちらも完全なリストには必要です。最初の1時間に行うべきなのは一方だけです。

正しい優先順位の原則は比率です。 必要な労力に対して、各対策がどれだけリスクを減らすかを基準に並べ、上から実行します。順番は次のとおりです。

レベル目的労力防ぐもの
1. 攻撃を止める攻撃者が今使う経路を閉じる約2時間認証情報の窃取、フィッシング、マルウェア、デバイスの盗難
2. 被害を抑える問題が起きたときの影響を限定する約1時間単一障害点、アカウントロックアウト、なりすまし詐欺
3. 露出を減らすデジタル上の足跡を小さくする継続的プロファイリング、追跡、標的型ソーシャルエンジニアリング
4. 物理面と人間面ソフトウェアが届かない層を補う約30分デバイスの押収、肩越しの覗き見、音声フィッシング

下へ進めてください。面白そうだからといって、レベル1を飛ばしてレベル3から始めないでください。

レベル1: 攻撃を止める #

5つの項目で合計約2時間かかり、攻撃者が利用する経路に対処します。

1. すべてのアカウントに固有のパスワードを使う #

クレデンシャルスタッフィングは、アカウント乗っ取りで最も多い方法です。 パスワードを使い回す人がいるため成立します。あるサイトで情報が漏れると、攻撃者は同じ認証情報を自動で大量の他サイトに試します。

パスワードマネージャーは、誤った使い回しを不可能にし、根本原因を解決します。アカウントごとに高いエントロピーを持つ固有のパスワードを生成し、自動入力します。

多くの助言が省く重要な点があります。マネージャーのパスワードは、今や単一障害点です。 長くして、記憶してください。他の場所には保存しない唯一のパスワードです。ランダムな5、6語から成るパスフレーズは、短く複雑な文字列より強力で、はるかに覚えやすいものです。

有効な設計は2つあります。

方法強みトレードオフ
クラウド同期型 (Bitwardenなど)便利で、デバイス間で同期でき、復旧しやすいベンダーの暗号化と可用性を信頼する必要がある
オフラインのファイル型 (KeePassXCなど)完全に管理でき、ベンダーに依存しないバックアップと同期を自分で管理する

どちらかを選んでください。両者の差は、マネージャーを使うか使わないかの差よりはるかに小さいものです。

詳しい比較は 2026年版おすすめパスワードマネージャー: BitwardenとKeePassXC 、関連ガイドは 2026年に強力なパスワードを作る方法 をご覧ください。

2. フィッシング耐性のある追加要素 #

追加要素は互換ではありません。防げる攻撃が大きく異なります。

方法認証情報の詰め込み攻撃を阻止フィッシングを阻止セッショントークンの窃取を阻止
SMSコードはい一部、SIMスワップを通じていいえ
認証アプリのコードはい一部、リアルタイム中継を通じていいえ
プッシュ承認はい弱い、承認要求の大量送信を通じていいえ
パスキーまたはハードウェアキーはいはいはい

パスキーとFIDO2ハードウェアキーは、リストの中でフィッシングを防げる唯一の選択肢です。 少しずつ改善するというより、仕組みによる違いです。認証情報は接続先に結び付いているため、見た目が似たドメインには使える情報が渡りません。被害者が攻撃者に読み上げるコードもありません。

安全だと思われている対策を無効化する関連の脅威も挙げておきます。インフォスティーラーマルウェアはブラウザーのCookieを直接盗みます。 攻撃者はパスワードや2つ目の要素を使わず、認証済みセッションを再利用できます。だから最後の列が重要であり、レベル1の項目3は任意ではありません。

この項目内の優先順位: 提供されている場合はパスキー、メールと金融にはハードウェアキー、その他には認証アプリ、より良い選択肢がない場合のみSMSです。

時間ベースのコードは、 TOTPおよびHOTPジェネレーター でローカルに生成、検証できます。Base32シークレットまたは otpauth:// URIを読み取り、ブラウザー内だけで動作します。

3. すべてを自動更新する #

侵入成功の多くは、すでにパッチがある脆弱性を悪用します。 攻撃者は更新の遅れを狙います。

実用的な対策は、更新にもっと注意を払うことではありません。あらゆる層で自動更新を有効にし、判断そのものをなくします。

  • オペレーティングシステム: Windows Update、macOSのソフトウェアアップデート、Linuxのunattended-upgrades
  • ブラウザー: 自動更新を有効にしたままにし、求められたら再起動します。再起動待ちは、ブラウザーに未適用のパッチがあることを意味します。
  • スマートフォン: OSだけでなく、アプリの自動更新も有効にします。
  • ルーター: 外部から到達可能な層ですが、忘れられがちです。

再起動待ちのブラウザーは、脆弱なコードを実行しています。 この習慣だけで、レベル3の多くの項目を合わせた以上に露出を減らせます。

当サイトのカーネル脱出分析 コンテナーはもはやセキュリティ境界ではない は、権限昇格が関わる場合にパッチ適用までの時間がどれほど重要かを示しています。

4. デバイスを暗号化し、画面を確実にロックする #

ディスク全体の暗号化により、盗難デバイスはデータ侵害ではなくハードウェアの損失になります。 暗号化されていないと、デバイスを持つ人は誰でも、パスワードマネージャーの保管庫や有効なセッショントークンを含むすべてのデータを読めます。

一般的なプラットフォームはすべて暗号化を提供していますが、初期状態では有効でないものもあります。

プラットフォーム機能確認方法
WindowsBitLockerまたはDevice Encryption設定、プライバシーとセキュリティ、デバイスの暗号化
macOSFileVaultシステム設定、プライバシーとセキュリティ、FileVault
LinuxLUKSインストール時にrootとhomeのボリュームが暗号化されているか確認
iOSおよびAndroidパスコードを設定すると既定で有効パスコードを設定し、暗号化が有効か確認

暗号化に加えて、次の2点も守ってください。

  • 4桁コードではなく、パスフレーズか長いPINを使います。 メールと金融のアカウントには、最も強いスマートフォンのロックを使ってください。パスコードがデバイス上の他のすべてを保護するためです。
  • 法的な強制リスクがある場合は、生体認証よりPINを優先します。 生体認証は便利で忘れにくい一方、地域によっては強制された指紋や顔と、強制的に開示させられる知識への法的保護が異なります。

5. バックアップを一度はテストする #

ランサムウェアとハードウェア障害は同じ結果をもたらし、バックアップは両方に耐える唯一の対策です。 最もよく省略され、最も後悔される項目です。

標準は3-2-1です。2種類のメディアに3つのコピーを置き、そのうち1つを別の場所に保管します。個人の場合は次のようになります。

  • ローカルコピーを1つ、迅速な復旧用に保管
  • 暗号化した遠隔コピーを1つ、ランサムウェアや火災への対策として保管
  • オフラインまたは書き込み可能なコピーを1つ、ランサムウェアが同期ストレージに到達した場合に備えて保管

最後の点が最も重要ですが、実行されることは最も少ない項目です。同期ストレージはバックアップではありません。ランサムウェアや誤削除も同期されます。

少なくとも一度は復元をテストしてください。 一度も復元していないバックアップは仮説にすぎません。

レベル2: 被害を抑える #

レベル1は、何も失敗しない前提です。レベル2は、何かが失敗する前提で、影響を抑えます。

6. メールアドレスを使い回さない #

メールアドレスは、これまでに漏えいしたあらゆるデータベースをつなぐキーです。 どこでも同じアドレスを使うと、1つの侵害が他の侵害と結び付けられ、ソーシャルエンジニアリングに確認済みの出発点を与えます。

エイリアスを使うと両方の問題を解決できます。 サービスごとに固有のアドレスを作り、アドレス自体をラベルにします。

利点重要な理由
漏えい元を特定あるエイリアスにスパムが届けば、どのサービスがアドレスを漏らしたか、販売したかが分かります。
即時にブロック本当の受信箱に影響せず、エイリアスを1つ無効にできます。
相関を防止アドレスを分けると、複数のアカウントを1つのプロフィールに結び付けにくくなります。
フィッシングを検知使用していないエイリアス宛てのメールは、明らかに不正です。

サブアドレス (you+service@example.com) は弱い方法です。どのサービスがアドレスを漏らしたかは分かりますが、本当のアドレスも露出するため、相関を防げません。

独自ドメインがあれば、キャッチオールエイリアスを無料で利用できます。そうでなければ、専用のエイリアス事業者が同じ機能を提供します。

7. 本当の攻撃対象はアカウント復旧 #

攻撃者は正規の入口を避け、復旧手段を狙うようになっています。 デバイスをなくしても復旧でき、最も弱い経路にならないようにします。

次の設定を順番に行ってください。

  • バックアップコードをオフラインで保存します。 印刷するか、暗号化メディアに保存し、パスワードマネージャーとは別に保管します。一方が侵害されても、もう一方を渡さないためです。
  • セキュリティ質問より復旧キーを優先します。 母親の旧姓や最初の車についての答えは、公開記録で見つかることがよくあります。
  • サイトが質問を強制する場合は、事実と異なる答えを使います。 アカウントと一緒にマネージャーへ保存します。
  • サービスが許可する場合は、2台目のデバイスかキーを登録します。 1つの障害でロックアウトされるのを防ぎます。
  • 古い復旧連絡先と電話番号を削除します。 古い番号は、今では他人のものです。

警告: バックアップコードなしで2つ目の要素を失うと、アカウントを永久に失うことがよくあります。適切に保護されたアカウントへのアクセスをサポートチームが復元することはありません。 2つ目の要素を有効にするとき、同時に復旧手段を設定してください。

8. 漏えいを監視して早く知る #

漏えい通知の価値は、タイミングだけで決まります。 パスワードがどこかでまだ有効なうちに、漏えいを知りたいものです。

  • Have I Been Pwned は、メールアドレスが新しいデータセットに現れると通知します。ドメインを所有し、エイリアスを使っている場合は、ドメイン全体の通知も提供します。
  • パスワードマネージャーは、より良い手掛かりです。 通知対象のサービスに対応する保管庫内の項目を把握し、直接警告するためです。

有効な手順は簡単です。通知が届いたら、影響を受けたアカウントのパスワードを変更し、古いパスワードを使い回した場所でも変更します。これがレベル1の項目1の効果です。固有のパスワードなら、2つ目の手順は不要です。

9. 必要になる前に信用情報を凍結する #

信用情報の凍結は、新しい口座を作るなりすまし詐欺への最も強力な対策です。 無料で利用でき、金融機関があなたの信用情報を確認して本人名義の口座を作ることを防ぎます。

米国では、3つの大手信用情報機関のそれぞれで凍結できます。正当な申し込みのために、一時的かつ元に戻せる形で解除できます。手順は次のとおりです。

  1. 1社だけでなく、3社すべてで凍結します。 各社は別々の情報を保有します。
  2. 解除用PINをパスワードマネージャーに保存します。
  3. 信用を申し込むときだけ一時解除し、その後再び凍結します。

必要になる前に行ってください。詐欺対応と口座への異議申し立てをしながら手順を調べるのは、最悪のタイミングです。

レベル3: 露出を減らす #

レベル3ではデジタル上の足跡を小さくします。重要ですが、アカウント乗っ取りを防ぐ対策ではないため、上の項目より優先度は下がります。

10. 使用するブラウザーを強化する #

個人データの露出の大半はブラウザーで起きます。 多くの場合、2つの変更で対処できます。

  • コンテンツブロッカーを導入します。 広告やトラッカーは、ウェブ上の主要な収集手段です。ブロックすると追跡を止め、かなりの攻撃対象領域も減らせます。複数ではなく、信頼できるブロッカーを1つ選んでください。
  • 拡張機能を必要なものだけにします。 拡張機能はページの内容を読み取り、変更できます。 放置された拡張機能や悪意ある拡張機能が、セッションに直接アクセスする経路になる可能性があります。四半期ごとに一覧を見直してください。

ブラウザーフィンガープリントのランダム化は、理解する価値はありますが、優先する価値はほとんどありません。効果がゼロではなくても、項目1から5より効果は小さく、サイトを壊すことがあります。

詳しい解説は 2026年版プライバシーブラウザー: LibreWolf、Brave、Torの比較 をご覧ください。

11. DNSを暗号化する #

通常のDNSは暗号化されず、観察可能です。ネットワーク事業者や通信経路上の第三者は、解決するすべてのドメインを確認できます。 DNS-over-HTTPSまたはDNS-over-TLSで問い合わせを暗号化できます。

正直に伝えるべき注意点が2つあります。

  • DoHは信頼先を移すだけで、信頼そのものをなくしません。 ISPではなく、DNSリゾルバーが問い合わせを見ます。プライバシーポリシーを公開しているリゾルバーを選びましょう。プロトコルだけでは不十分です。
  • DoHはネットワークレベルのフィルタリングを迂回します。 多くの人が頼る保護者向けや企業向けの制御も対象です。

プライバシー以外の実質的なセキュリティ上の利点もあります。暗号化DNSは、敵対的なネットワークでDNS偽装を現実的な攻撃経路でなくします。

12. 共有前にメタデータを削除する #

写真に含まれるのはピクセルだけではありません。 多くのスマートフォンカメラは、GPS座標、タイムスタンプ、デバイス識別子などのEXIF情報を埋め込みます。

写真より文書の方が、これが重要になることがあります。 共有したPDFやOfficeファイルには、作成者名、編集履歴、社内ファイルパスが残ることがよくあります。社内文書から組織の詳細が漏れる原因になります。

EXIFビューアー は画像のメタデータをローカルで読み取ります。アップロードせずに写真から何が分かるか確認できます。 URLパーサー はリンクでも同じことを行い、チャットにURLを貼る前にトラッキングパラメーターとauthority内の認証情報を表示します。

レベル4: 物理面と人間面 #

このレベルは約30分かかり、ソフトウェア対策が届かない領域を補います。

13. デバイスを物理的に管理する #

  • すべての画面をロックし、短いタイムアウトを設定します。ロックされていないノートPCは、アカウントが完全に侵害された状態と同じです。
  • 車内にデバイスを見える状態で置かないでください。 盗難を防ぐ対策であり、盗難はデータ損失にもつながります。
  • 公共の場所ではプライバシースクリーンを使います。 肩越しの覗き見の大半を防げます。
  • 公共の充電場所は接続前に確認します。 不明なUSBポートより、充電専用ケーブルか自分の電源アダプターを優先してください。

14. メッセージではなく人を確認する #

音声や動画によるフィッシングは、聞き慣れた声が本人である証拠という前提を崩しています。 公開音声の数秒から声を複製することは珍しくなく、依頼にはたいてい緊急性と送金または認証情報の要求が含まれます。

別の経路で本人確認してください。

  1. 電話を切って、かけ直します。 発信者が伝えた番号ではなく、以前から知っている番号にかけてください。
  2. 緊急性は理由ではなく、警告サインと考えます。 すぐ行動するよう迫ることが攻撃の仕組みです。
  3. なりすまされる可能性のある家族と確認用の合言葉を決めます。
  4. 電話や音声メッセージだけを根拠に送金しないでください。

これはレベル4で最も効果が高い項目で、費用もかかりません。

15. 文書と廃棄 #

  • 口座番号、個人識別番号、医療情報を含む文書は裁断するか、黒塗りします。
  • 目的を限定して共有する文書には透かしを入れます。 受取人と日付を記載してください。費用はかからず、漏えい元の追跡に役立ちます。
  • 人名検索サイトから登録を解除します。 掲載が再開されるため、この手続きを繰り返すことを想定してください。
  • 公開記録を確認し、可能であれば削除を依頼します。

この層の詳細は 物理セキュリティチェックリスト をご覧ください。

多くの人が逆にしていること #

やめるべき8つの習慣と、続いている理由、代わりにすべきことをまとめます。

習慣続いている理由代わりにすること
短く複雑なパスワードを暗記する長年、複雑さのルールが推奨されていたマネージャーを使い、保管庫用には長いパスフレーズを設定する
予定に従ってパスワードを変更する古いコンプライアンス方針漏えい通知や侵害の疑いがあるときに変更し、カレンダーに従って変更しない
重要なアカウントにSMSを使う提供される既定の方法だからメール、金融、本人確認のアカウントをパスキーまたはハードウェアキーに移行する
パスワードと2FAコードを同じマネージャーに保存する便利だから2つを分け、一方の侵害で両方の要素が漏れないようにする
同期クラウドをバックアップとして扱うバックアップのように見えるオフラインまたは書き込み可能なコピーを追加する
完璧なブラウザーフィンガープリントを追求する測定できるため、行動しているように感じる先に項目1から5を実行する
セキュリティ質問に正直に答える必須に感じるマネージャーに保存した、事実と異なる答えを使う
HTTPSなら安全だと思い込む鍵マークが安心感を与えるドメインを確認する。フィッシングサイトの多くも有効な証明書を持つためです。

8つに共通するのは、目に見えて測定できるため注目を集める一方、より効果の高い対策より優先度が低いことです。 パスワードマネージャーを設定する前にフィンガープリントのエントロピーを最適化するのは、優先順位が逆です。

よくある誤り: 秘密を集約するため、パスワードマネージャーをリスクとみなすこと。 確かにリスクは集約されますが、代わりに数十のサイトでパスワードを使い回すことになります。自分で管理できる集約は、管理できない分散より安全です。

データを渡さずに保護する #

このテーマ全体を通して、実用上の問題があります。アカウントの保護に役立つツールが、守ろうとしている秘密そのものを求めることがあります。

パスワードをサーバーへ送信する強度チェッカーはリスクになります。ファイルをアップロードするハッシュ計算機は目的を損ないます。ホスト名を取得する証明書ツールは、運営するサイトを第三者に知らせます。

以下のツールはすべてブラウザー内で動作し、アップロードもアカウント登録も不要です。これはサイト上で明示している方針です。例外も隠さず記載しています。

境界を自分で確認してください。 ネットワークを切断してツールを開き、テスト値を処理するときにブラウザーのネットワークパネルを確認します。ローカル処理という説明は、想定される設計を示すものです。ブラウザーの拡張機能とツールのバージョンも確認してください。

作業ツール処理内容
強力なパスワードを作るパスワードジェネレーターcrypto.getRandomValues と棄却サンプリングで剰余バイアスを避け、選択した設定のエントロピーを利用
パスワードの強度を確認するパスワード強度チェッカーパターンや再利用の検出も含め、候補をローカルで評価
追加要素を設定するTOTPおよびHOTPジェネレーターBase32シークレットまたは otpauth:// URIを読み取り、時間枠内のコードを検証
サイトの証明書を確認するSSL証明書情報サブジェクト、有効期間、鍵の強度、SAN、弱いアルゴリズムの警告
証明書チェーンを確認するSSLチェーンテスターチェーンを並べ替えて各署名を検証し、中間証明書の不足を検出
ダウンロードやファイルを検証するハッシュ計算機MD5からSHA-512までを使い、公開されたダイジェストとの一致で完全性を確認
一意の識別子を生成するUUIDジェネレーター正しいバージョンとバリアントのビットを持つバージョン4識別子
疑わしいリンクを確認するURLパーサーパスをデコードし、パラメーターを一覧表示し、authority内の認証情報を検出
写真のメタデータを確認するEXIFビューアー写真のGPS、タイムスタンプ、デバイス情報を表示
エンコードや暗号化を測定するエントロピー分析ツールシャノンエントロピーで、反復データとエンコード済みまたは暗号化済みデータを区別
インジケーターを安全に無害化するIOCの無害化と復元URLやアドレスを共有時に無効化

脅威モデルについて考える #

適切なチェックリストは、誰から身を守るかによって変わります。 この問いを省くと、間違った対策に労力を費やします。

状況現実的な攻撃者注力すること
多くの個人日和見的な犯罪者、自動化された認証情報の詰め込み攻撃、無差別フィッシングレベル1と2、および持ち歩くデバイス
著名人や公的な役割標的型フィッシング、個人情報の暴露、アカウント乗っ取りの試みアカウントの分離とエイリアスを追加し、公開情報を監視する
ジャーナリスト、活動家、法的リスクがある人国家や資金力のある攻撃者、デバイスの押収Tor、専用デバイス、身元を分離するための運用規律を追加
小規模事業者ビジネスメールの侵害、請求書詐欺、支払いの転送すべての送金を別の経路で確認
技術職サプライチェーン、認証情報の窃取、依存関係を狙う攻撃ハードウェアキー、コード署名、仕事と個人の身元の分離を追加

表を率直に読むと。 多くの人にとって、現実的なリスクの大半はレベル1と2にあります。高度な対策は必要な人には非常に重要ですが、必要のない人にもよく使われています。

自分の評価を作る方法は 個人の脅威モデルを作成する方法 をご覧ください。

要点 #

  • 網羅性より順番が重要です。 レベル1の5項目は、300項目の包括的なリストを無作為に実行するより、多くの現実的なリスクを減らします。
  • パスキーとハードウェアキーは、フィッシングを防ぐ唯一の追加要素です。 認証情報が接続先に結び付いており、デバイスから外に出ないためです。
  • インフォスティーラーマルウェアはセッションCookieを直接盗みます。 そのため、弱い追加要素だけではセッショントークンの窃取を防げません。
  • 暗号化により、盗まれたデバイスはデータ侵害ではなくハードウェアの損失になります。 すべての環境で既定有効ではないので、確認してください。
  • 同期ストレージはバックアップではありません。 オフラインまたは書き込み可能なコピーを追加し、一度は復元をテストしてください。
  • アカウント復旧が新たな攻撃対象です。 バックアップコードをオフラインに、パスワードマネージャーとは別に保存します。
  • エイリアスは、アドレスを含む漏えいデータベース間の相関を防ぎます。
  • 注目されるセキュリティ対策の多くは効果が低いものです。 フィンガープリントやuser-agentの偽装より、パスワードマネージャーと自動更新の方がはるかに重要です。
  • 適切なチェックリストは攻撃者によって変わります。 高度な対策は必要な人には重要ですが、必要のない人にもよく使われます。

次のステップ #

  1. 今日、レベル1を実行します。 約2時間で、パスワードマネージャー、フィッシング耐性のある追加要素、自動更新、デバイスの暗号化、復元をテストしたバックアップを設定できます。
  2. 複数カテゴリの数百項目を含むコミュニティのチェックリスト で詳しく確認します: 個人セキュリティチェックリスト 。
  3. 対話型バージョンを使い、脅威モデルで絞り込んで進捗を記録します: デジタル防御 。
  4. この記事の仕事向けの対策には、サイトの組織向けチェックリストを使います。 パスワードセキュリティ 、 フィッシング対策の意識向上 、 データのバックアップと復旧 、 モバイルデバイスセキュリティ 、 ソーシャルメディアセキュリティ をご覧ください。
  5. 方式の比較を参考にパスワードマネージャーを選びます: BitwardenとKeePassXCの比較 。
  6. 弱いブラウザーを調整するのではなく、より安全なブラウザーを使います: LibreWolf、Brave、Torの比較 。
  7. 仮想カード番号で支払い情報を保護します: Privacy.comの仮想カード 。
  8. ツールはローカルで使用し、 パスワードジェネレーター と TOTPジェネレーター から始めます。
