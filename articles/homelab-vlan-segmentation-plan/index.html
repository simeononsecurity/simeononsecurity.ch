规划并测试 homelab 的 VLAN 分段

Homelab 常把笔记本电脑、服务器、摄像头和访客设备放在同一个网络中。VLAN 分段会将这些设备组放入不同网络。路由器、防火墙或三层交换机负责在网络之间路由流量。防火墙规则或交换机访问控制列表负责管理这些路由流量。本指南帮助你记录方案、每次只做一项更改，并验证结果。

要点 #

  • **按信任级别分组：**当管理设备、服务器、IoT 和访客有不同的访问需求时，将它们放在不同网络中。
  • **记录允许的路径：**对每个跨网络连接记录来源、目标、服务和原因。
  • **配置两个层面：**交换机和接入点的 VLAN 设置用于放置设备。防火墙规则或交换机访问控制列表用于控制路由流量。
  • **测试两种结果：**从每个相关网络分别检查一条允许连接和一条拒绝连接。

开始前 #

你需要配有 VLAN 接口的路由器或防火墙，或者支持 VLAN 路由和访问控制列表的三层交换机。网管型交换机可承载有线 VLAN。如果你要隔离无线客户端，还需要能将无线网络映射到 VLAN 的接入点。更改配置时，保留一个设备在当前管理网络中。先保存路由器、交换机和接入点的设置。以下步骤使用一个示例方案，请根据设备调整地址和端口。

VLAN 接口是网关与某个 VLAN 的连接。网关可以是路由器、防火墙或三层交换机。DHCP 地址池是 DHCP 服务为该网络中的设备提供的地址范围。DHCP 中继会将某个 VLAN 的地址请求转发给另一网络中的 DHCP 服务器。当网关不为该 VLAN 分配地址且 DHCP 服务器位于其他位置时，使用中继。 Juniper 的 DHCP 中继指南 介绍了此路径。无线 SSID 是客户端连接的网络名称。如果设备没有网管型交换机或支持 VLAN 的接入点，先使用设备自带的访客网络，并在购买或更换硬件前验证隔离效果。

如果需要先了解基本术语，请阅读 子网和 VLAN 。本站的 网络分段指南 介绍了更广泛的安全概念。CISA 在其 联邦移动办公安全指南 中介绍了为访客和物联网设备设置独立家庭网络的做法。

**警告：**如果管理连接经过的端口发生 VLAN 更改，你可能会失去访问权限。在所有网络通过测试前，请保留物理访问方式和已知的恢复路径。

移动网线前，导出每台设备的配置，并记录当前管理 IP、交换机端口、VLAN 设置和管理员登录信息。在原网络中保留一个可用的管理端口和笔记本电脑。如果更改导致连接中断，将笔记本电脑接回该端口，恢复已保存的设置或配置，并在重试前确认旧网关可以响应。如果交换机管理路径不可用，请使用其文档说明的控制台或本地恢复流程。确认重置会清除哪些内容前，不要重置设备。

盘点设备和流量 #

列出每台设备、当前地址、所有者和所需服务。记录设备访问其他网络的理由。例如，笔记本电脑可能需要管理服务器，而摄像头可能只需要访问录像机和 DNS 服务器。访客手机需要访问互联网，但不需要访问服务器。

设备组示例设备所需访问
管理管理员笔记本电脑、交换机和接入点管理接口路由器、交换机、接入点、服务器管理接口
服务器虚拟化主机、NAS、备份目标更新、DNS、获批的应用流量
IoT摄像头、智能插座、媒体设备DNS、时间服务、指定的控制器或录像机
访客访客的手机和笔记本电脑互联网、DNS，不得访问私有子网

添加规则前先记录例外情况。本地发现功能，例如投屏，经常依赖多播流量，而多播默认不会跨越路由边界。不要为解决一个发现问题而开放 VLAN 之间的所有流量。先确定协议，再添加设备支持的最小范围例外。

分配 VLAN 和地址 #

为每组设备分配一个 VLAN ID 和独立 IP 子网。此示例方案使用仅供文档使用的保留地址，并假设路由器提供 DHCP 和 DNS。检查地址冲突后再将表格用于实际网络。

网络VLAN ID子网示例网关
管理10192.0.2.0/27192.0.2.1
服务器20198.51.100.0/27198.51.100.1
IoT30203.0.113.0/27203.0.113.1
访客40192.0.2.32/27192.0.2.33

这些仅供文档使用的地址范围依据 RFC 5737 ，只用于说明布局。请在实验网络中使用 RFC 1918 定义的私有地址，并为每个 VLAN 分配互不重叠的子网。在方案中记录每个实际网关、DHCP 地址池、DNS 地址和设备保留地址。

接入端口承载单个设备的网络，不带 VLAN 标签。中继端口在路由器、交换机和接入点之间承载指定的带标签 VLAN。确保两端的 VLAN ID 以及 native 或无标签设置一致。 Netgate VLAN 交换机指南 说明了带标签的中继端口、无标签接入端口和端口 VLAN ID。如果硬件支持单独的管理 VLAN，避免使用默认 VLAN 1 进行管理，详见 Netgate VLAN 安全指南 。

中继链路上的 native 或无标签流量没有 VLAN 标签。两端必须将其映射到同一 VLAN，否则设备可能进入错误的网络。只允许链路所需的 VLAN。禁用未使用的交换机端口，或将其分配到受限网络。Netgate 还建议：当攻击者控制交换机端口时，不要把 VLAN 视为完整的安全边界。除了路由流量，也要保护物理端口和设备凭据。

创建流量矩阵 #

VLAN 本身只分隔广播域。路由器或三层交换机上的VLAN 间路由仍需要访问规则。确定由哪台设备在 VLAN 之间路由。如果三层交换机在本地路由，其 VLAN 之间的流量可能不会到达路由器防火墙。在交换机上应用等效访问控制列表，或让流量经过防火墙，然后在实际执行控制的位置进行测试。检查交换机 ACL 的方向以及是否跟踪连接状态。许多交换机 ACL 会分别匹配两个方向的数据包，因此允许某个连接可能还需要一条范围有限的返回流量规则。 Cisco ACL 指南 说明了接口方向和数据包匹配顺序。使用设备清单记录计划允许的连接。下面仅为示例，不是通用规则集。

来源目标服务决定
管理服务器管理界面TCP 443允许获批的管理设备访问
管理路由器、交换机和接入点的管理界面这些设备文档中列出的管理端口允许获批的管理设备访问
IoT摄像头录像机录像机文档中列出的端口仅在需要时允许
IoT获批的 DNS 和时间服务DNS 和 NTP仅允许访问选定服务
IoT管理子网任意拒绝
访客私有子网任意拒绝
访客DNS 和互联网DNS、Web 流量通过获批的解析器和网关允许

在方案中也要考虑路由器自身提供的服务。阻止 IoT 访问其他 VLAN 的规则仍可能让 IoT 设备访问路由器管理界面。将管理服务限制在管理网络中。先添加必要的允许规则，并默认拒绝其余路由流量。不要假设默认设置会拒绝流量，先检查现有的宽泛允许规则。 Netgate 防火墙最佳实践 指出，pfSense 默认 LAN 包含一条允许规则。如果使用 pfSense， 规则方法指南 说明接口规则会过滤进入该接口的流量，允许的连接会创建用于返回流量的状态。

示例表格涵盖 IPv4。如果网络使用 IPv6，为每个 VLAN 分配 IPv6 前缀和策略，检查路由器通告，并测试允许和拒绝的 IPv6 路径。阻止 IPv4 不能证明 IPv6 已隔离。如果不打算路由 IPv6，应检查路由器的 IPv6 设置和客户端地址，而不要假定 IPv6 不存在。Netgate 记录了 IPv6 防火墙行为 和 路由器通告 。

一次配置一个网络 #

  1. 选择 VLAN 的网关。如果由路由器或防火墙路由，在该设备上创建 VLAN 接口并分配网关地址。如果由三层交换机路由，则在交换机上创建 VLAN 接口。在网关上配置 DHCP 地址池，或设置 DHCP 中继指向现有 DHCP 服务器。确认获批的 DNS 解析器可访问。 Netgate VLAN 配置指南 列出了 pfSense 网关的接口和服务配置步骤。
  2. 如果路由器是 VLAN 网关，将该 VLAN 添加到路由器与交换机之间的中继链路。如果三层交换机是网关，让交换机持有该 VLAN 的网关地址，并通过独立传输网络或路由上行链路将流量路由到路由器或防火墙。在交换机上设置指向上游路由器的默认路由。在路由器上通过交换机为每个由交换机负责的 VLAN 配置返回路由。如果这些源子网需要访问互联网，检查路由器的防火墙策略和出站 NAT。不要在两台设备上配置相同的网关地址或 DHCP 地址池。 Cisco VLAN 间路由指南 展示了由交换机持有 VLAN 网关的方式。Netgate 说明了内部路由器后方网络所需的 返回路由 和 出站 NAT 。如果无线客户端需要此网络，请将 VLAN 添加到交换机与接入点之间对应的中继链路。
  3. 为 VLAN 分配一个测试接入端口或无线 SSID。将非关键测试设备连接到该端口或 SSID。
  4. 在负责路由 VLAN 的设备上添加计划的防火墙规则或交换机访问控制列表。确认其余路由流量被拒绝。如果交换机不跟踪状态，检查 ACL 方向和返回流量。测试对每个网关、管理界面、本地子网以及可用 IPv6 的访问。只允许流量矩阵中列出的路径。将管理访问限制在管理网络中。检查规则顺序，只有在测试管理路径正常后，才删除或收窄现有的宽泛允许规则。
  5. 确认测试设备从预定子网获得地址、网关和 DNS 服务器。再执行下面的连接检查，然后再迁移其他设备。

替代管理路径正常前，不要迁移最后一个管理设备。每个网络通过测试后保存可用配置。如果 DHCP、DNS 或管理访问失败，将测试设备接回原来的端口或 SSID，从已保存的配置恢复最近的交换机或路由器更改，并在继续前重新测试原网络。

测试隔离和访问 #

使用你能控制且确认在目标地址上监听的服务。在 Windows 测试设备上，将示例地址和端口替换为真实服务器，然后运行：

Test-NetConnection -ComputerName 198.51.100.10 -Port 443

TcpTestSucceeded 字段表示 TCP 连接是否成功建立。 Microsoft Test-NetConnection 参考文档 介绍了 -ComputerName 和 -Port 参数。连接失败本身不能证明防火墙规则生效。服务可能已停止，或者主机防火墙可能拒绝流量。得出结论前，检查目标服务和网络防火墙日志。

从实际连接到每个源 VLAN 的设备进行测试。每次测试前记录源地址、网关和 DNS 服务器。检查到预期服务的允许连接、到矩阵之外某个内部服务的拒绝连接、通过预期解析器进行的 DNS 查询，以及计划中的互联网访问。对于网关位于交换机上的 VLAN，如果允许连接失败，检查交换机默认路由、路由器返回路由和从目标返回的路径。IPv6 启用时，也使用 IPv6 地址重复允许和拒绝测试。在 pfSense 中，Status > System Logs > Firewall 显示记录的允许或阻止操作。 Netgate 防火墙日志指南 介绍了此视图。将日志中的来源、目标、端口和规则与测试结果比较。如果测试意外成功，检查宽泛的允许规则和现有状态条目。更改规则后发起新连接，因为已建立的连接可能依据现有状态继续工作。

在 Windows 上检查 DNS 时，运行 nslookup example.com，并将显示的服务器与计划使用的解析器比较。然后从 DNS 受限的访客或 IoT 客户端尝试查询。查询成功并不能单独证明客户端使用了所选解析器，所以还要检查显示的服务器以及防火墙或解析器日志。单独测试 IoT 或访客设备直接访问路由器管理地址的情况，并确认该访问被拒绝。

同一 VLAN 中的设备可能不经过路由器防火墙就能交换流量。如果接入点提供客户端隔离，请单独测试，并在服务器上使用主机防火墙。VLAN 间防火墙测试不能证明同一 VLAN 内的隔离效果。

**预期结果：**每台设备都从计划的子网获取地址。允许的服务正常运行。被拒绝的尝试对应防火墙阻止记录或有文档说明的等效控制。

故障排查 #

  • **没有获取地址：**检查接入端口或 SSID 的 VLAN、中继标签、DHCP 地址池和网关接口。
  • **地址正常，DNS 失败：**检查解析器地址、路由器服务绑定和 DNS 流量的防火墙规则。
  • **设备意外访问另一个 VLAN：**检查路由器规则、宽泛允许规则，以及两个设备是否仍共享同一无标签网络。
  • **路由流量没有防火墙日志：**检查三层交换机或其他网关是否在流量到达防火墙前完成了路由。
  • **网关位于交换机的 VLAN 可访问本地网络，但无法访问互联网：**检查交换机默认路由、路由器返回路由、防火墙策略以及该 VLAN 子网的出站 NAT。
  • **IPv4 被阻止，但连接仍然成功：**检查 IPv6 地址、路由器通告、IPv6 规则和现有状态条目。
  • **拒绝测试超时且没有防火墙日志：**确认目标服务正在监听，再检查路由和日志设置。 Netgate 防火墙故障排查指南 介绍了日志和状态检查。
  • **投屏或发现功能停止：**添加范围有限的例外前，先确定发现协议和控制器路径。

后续步骤 #

将设备清单和流量矩阵与网络图一起保存。添加服务器或 IoT 设备时重新检查规则。每次相关网络更改后，重复一次允许连接和一次拒绝连接测试。更广泛的设计原则见 网络分段 。
