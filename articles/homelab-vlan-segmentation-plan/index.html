ホームラボのVLANセグメント化を計画してテストする

ホームラボでは、ノートPC、サーバー、カメラ、ゲスト用デバイスを1つのネットワークにまとめることがあります。VLANセグメント化を使うと、これらのグループを別々のネットワークに配置できます。ルーター、ファイアウォール、またはレイヤー3スイッチがネットワーク間の通信をルーティングします。ファイアウォールルールやスイッチのアクセス制御リストが、ルーティングされた通信を制御します。このガイドでは、計画の記録、1回に1つの変更、結果のテストを進めます。

要点 #

  • 信頼度でグループ化する: 管理デバイス、サーバー、IoT、ゲストのアクセス要件が異なる場合は、別々のネットワークに配置します。
  • 許可する経路を記録する: ネットワーク間の各接続について、送信元、宛先、サービス、理由を記録します。
  • 両方の層を構成する: スイッチとアクセスポイントのVLAN設定でデバイスのネットワークを決めます。ファイアウォールルールやスイッチのアクセス制御リストでルーティング通信を制御します。
  • 許可と拒否を両方テストする: 関連する各ネットワークから、許可される接続と拒否される接続を確認します。

開始前の準備 #

VLANインターフェイスを備えたルーターまたはファイアウォールが必要です。あるいは、VLANルーティングとアクセス制御リストに対応したレイヤー3スイッチを使います。マネージドスイッチは有線VLANを運びます。無線クライアントを分ける場合は、VLANに対応した無線ネットワークを提供するアクセスポイントも必要です。設定変更中は、管理ネットワークに1台のデバイスを残します。最初にルーター、スイッチ、アクセスポイントの設定を保存します。以下は例示用の計画です。アドレスとポートは機器に合わせてください。

VLANインターフェイスはゲートウェイとVLANを接続します。ゲートウェイにはルーター、ファイアウォール、レイヤー3スイッチを使えます。DHCPスコープは、そのネットワークのDHCPサービスがデバイスに提供するアドレス範囲です。DHCPリレーは、VLANから別のネットワークにあるDHCPサーバーへアドレス要求を転送します。ゲートウェイがそのVLANのアドレスを配布せず、DHCPサーバーが別の場所にある場合にリレーを使います。 JuniperのDHCPリレーガイド でこの経路を確認できます。無線のSSIDは、クライアントが接続するネットワーク名です。マネージドスイッチやVLAN対応アクセスポイントがない場合は、内蔵のゲストネットワークから始め、機器の購入や変更前に分離状態を確認します。

基本用語を先に確認する場合は、 サブネットとVLAN を読んでください。サイトの ネットワークセグメンテーションガイド では、より広いセキュリティの考え方を扱います。CISAは 連邦政府のモバイルワークプレース向けセキュリティガイダンス で、ゲストとIoT機器用に家庭内ネットワークを分ける方法を説明しています。

警告: 管理接続が通るポートのVLANを変更すると、アクセスできなくなる場合があります。すべてのネットワークがテストに合格するまで、物理アクセスと既知の復旧手段を確保してください。

ケーブルを移動する前に、各機器の設定をエクスポートし、現在の管理IP、スイッチポート、VLAN設定、管理者ログインを記録します。元のネットワークには、動作する管理ポートとノートPCを1台残します。変更でアクセスが切れた場合は、そのポートにノートPCを戻し、保存した設定を復元してから、再試行前に旧ゲートウェイが応答することを確認します。スイッチの管理経路に到達できない場合は、文書化されたコンソールまたはローカル復旧手順を使います。リセットで何が消去されるかを確認する前に、機器を初期化しないでください。

デバイスと通信を棚卸しする #

各デバイス、現在のアドレス、所有者、必要なサービスを一覧にします。他のネットワークにアクセスする理由もデバイスごとに記録します。例えば、ノートPCはサーバーを管理し、カメラは録画装置とDNSサーバーだけに接続する場合があります。ゲストのスマートフォンにはインターネットが必要ですが、サーバーへのアクセスは不要です。

デバイスグループデバイスの例必要なアクセス
管理管理者用ノートPC、スイッチとアクセスポイントの管理機能ルーター、スイッチ、アクセスポイント、サーバー管理
サーバーハイパーバイザー、NAS、バックアップ先更新、DNS、承認済みアプリケーション通信
IoTカメラ、スマートプラグ、メディア機器DNS、時刻サービス、指定のコントローラーまたは録画装置
ゲスト訪問者のスマートフォンとノートPCインターネット、DNS、プライベートサブネットにはアクセス不可

ルール追加前に例外を記録します。画面へのキャストなどのローカル検出機能は、通常、ルーティング境界を越えないマルチキャスト通信に依存します。検出の問題を直すためにVLAN間の全通信を許可しないでください。プロトコルを特定し、機器が対応する最小範囲の例外を追加します。

VLANとアドレスを割り当てる #

各グループにVLAN IDと別々のIPサブネットを割り当てます。この例示用の計画は文書用に予約されたアドレスを使い、ルーターがDHCPとDNSを提供する前提です。アドレスの競合を確認せずに、表を稼働中のネットワークにコピーしないでください。

ネットワークVLAN IDサブネットゲートウェイ例
管理10192.0.2.0/27192.0.2.1
サーバー20198.51.100.0/27198.51.100.1
IoT30203.0.113.0/27203.0.113.1
ゲスト40192.0.2.32/27192.0.2.33

これらの文書用アドレス範囲は、 RFC 5737 に従ってレイアウトを示すためのものです。ラボでは RFC 1918 のプライベートアドレスを使用し、各VLANに重複しないサブネットを割り当てます。実際のゲートウェイ、DHCPプール、DNSアドレス、デバイス予約を計画に記録します。

アクセスポートはVLANタグなしで1台のデバイスのネットワークを運びます。トランクポートはタグ付きの選択したVLANをルーター、スイッチ、アクセスポイント間で運びます。両端でVLAN IDとnativeまたはタグなし設定を合わせます。 NetgateのVLANスイッチガイド では、タグ付きトランク、タグなしアクセスポート、ポートVLAN IDを説明しています。別のVLANを使える機器では、管理にデフォルトVLAN 1を使わないでください。 NetgateのVLANセキュリティガイダンス も参照してください。

トランク上のnativeまたはタグなし通信にはVLANタグがありません。両端で同じVLANに割り当てないと、デバイスが誤ったネットワークに入ることがあります。そのリンクに必要なVLANだけを許可します。未使用のスイッチポートは無効化するか、制限されたネットワークに割り当てます。攻撃者がスイッチポートを制御する場合、VLANだけで完全なセキュリティ境界を作れるわけではありません。ルーティング通信に加えて、物理ポートとデバイスの資格情報も保護します。

通信マトリックスを作る #

VLANだけで分離できるのはブロードキャストドメインです。ルーターまたはレイヤー3スイッチでのVLAN間ルーティングには、引き続きアクセスルールが必要です。VLAN間のルーティングを担当する機器を決めます。レイヤー3スイッチがローカルでルーティングする場合、そのVLAN間通信はルーターのファイアウォールを通らない可能性があります。スイッチに同等のアクセス制御リストを適用するか、ファイアウォール経由でルーティングし、実際の適用地点でテストします。スイッチACLの方向と、接続状態を追跡するかを確認します。多くのスイッチACLは各方向のパケットを別々に照合するため、許可した接続の戻り通信に狭い範囲のルールが必要な場合があります。 Cisco ACLガイド では、インターフェイスの方向と順序付きパケット照合を説明しています。デバイス一覧を使って許可する接続を記録します。以下は例であり、すべてに適用できるルールセットではありません。

送信元宛先サービス判定
管理サーバー管理インターフェイスTCP 443承認済み管理デバイスに許可
管理ルーター、スイッチ、アクセスポイントの管理インターフェイス各機器の文書に記載された管理ポート承認済み管理デバイスに許可
IoTカメラ録画装置録画装置の文書に記載されたポート必要な場合だけ許可
IoT承認済みDNSおよび時刻サービスDNS、NTP選択したサービスだけに許可
IoT管理サブネット任意拒否
ゲストプライベートサブネット任意拒否
ゲストDNSとインターネットDNS、Web通信承認済みリゾルバーとゲートウェイ経由で許可

ルーター自身のサービスも計画に含めます。IoTから他のVLANへのアクセスをブロックしても、ルーターの管理インターフェイスが到達可能な場合があります。管理サービスは管理ネットワークに限定します。必要な許可ルールだけを先に設定し、他のルーティング通信はデフォルトで拒否します。デフォルト設定で拒否されると思い込まず、既存の広範な許可ルールを確認します。 Netgateのファイアウォールのベストプラクティス によると、pfSenseの既定のLANには許可ルールがあります。pfSenseの ルール方法論 では、インターフェイスルールがそのインターフェイスに入る通信をフィルタリングし、許可された接続は戻り通信の状態を作成すると説明しています。

例の表はIPv4を対象としています。IPv6を使う場合は、各VLANにIPv6プレフィックスとポリシーを割り当て、ルーター広告を調べ、許可と拒否のIPv6経路もテストします。IPv4をブロックしても、IPv6が分離されたことにはなりません。IPv6をルーティングしない予定の場合も、存在しないと決めつけずにルーターのIPv6設定とクライアントアドレスを確認します。Netgateは IPv6ファイアウォールの動作 と ルーター広告 を説明しています。

1つずつネットワークを構成する #

  1. VLANのゲートウェイを選びます。ルーターまたはファイアウォールがルーティングする場合、その機器にVLANインターフェイスを作り、ゲートウェイアドレスを割り当てます。レイヤー3スイッチがルーティングする場合は、そのスイッチにVLANインターフェイスを作ります。ゲートウェイにDHCPスコープを設定するか、既存のDHCPサーバーを指すDHCPリレーを設定します。承認済みDNSリゾルバーへの到達を確認します。 NetgateのVLAN設定ガイド には、pfSenseゲートウェイのインターフェイスとサービスの手順があります。
  2. ルーターがVLANゲートウェイの場合、そのVLANをルーターとスイッチ間のトランクに追加します。レイヤー3スイッチがゲートウェイの場合、そのVLANのゲートウェイアドレスをスイッチに割り当て、別のトランジットネットワークまたはルーティングされたアップリンク経由でルーターやファイアウォールにルーティングします。スイッチには上流ルーターを指すデフォルトルートを設定します。ルーターには、スイッチがゲートウェイを持つ各VLANへの戻りルートをスイッチ経由で設定します。これらの送信元サブネットがインターネットを必要とする場合は、ルーターのファイアウォールポリシーと送信NATを確認します。同じゲートウェイアドレスやDHCPスコープを両方の機器に作らないでください。 CiscoのVLAN間ルーティングガイド では、スイッチが所有するVLANゲートウェイを説明しています。Netgateは、内部ルーターの背後にあるネットワークの 戻りルート と 送信NAT を説明しています。無線クライアントが必要とする場合は、該当するスイッチとアクセスポイント間のトランクにVLANを追加します。
  3. テスト用アクセスポートまたは無線SSIDをVLANに割り当てます。重要でないテストデバイスをそのポートまたはSSIDに接続します。
  4. VLANをルーティングする機器に、予定したファイアウォールルールまたはスイッチACLを追加します。他のルーティング通信が拒否されることを確認します。スイッチが状態を追跡しない場合は、ACLの方向と戻り通信も確認します。各ゲートウェイと管理インターフェイス、各ローカルサブネット、存在する場合はIPv6へのアクセスをテストします。通信マトリックスに記録した経路だけを許可します。管理アクセスを管理ネットワークに限定します。ルールの順序を確認し、既存の広範な許可ルールは、テスト用管理経路が動作した後に削除または範囲を狭めます。
  5. テストデバイスが予定したサブネットからアドレス、ゲートウェイ、DNSサーバーを取得したことを確認します。他のデバイスを移動する前に、以下の接続チェックを実行します。

代替経路が動作するまでは、最後の管理デバイスを移動しないでください。各ネットワークがテストに合格したら、正常な設定を保存します。DHCP、DNS、管理アクセスが失敗した場合は、テストデバイスを元のポートまたはSSIDに戻し、最後に行ったスイッチまたはルーターの変更を保存済み設定から復元してから、元のネットワークを再テストします。

分離とアクセスをテストする #

自分で管理し、宛先で待ち受けていると確認できるサービスを使います。Windowsテストデバイスでは、例のアドレスとポートを実際のサーバーに置き換えて、次を実行します。

Test-NetConnection -ComputerName 198.51.100.10 -Port 443

**TcpTestSucceeded**フィールドは、TCP接続が完了したかを示します。 MicrosoftのTest-NetConnectionリファレンス では、-ComputerNameと-Portパラメーターを説明しています。接続失敗だけでは、ファイアウォールルールが機能したとは言えません。サービスが停止しているか、ホストファイアウォールが通信を拒否している可能性があります。結論を出す前に、宛先サービスとネットワークファイアウォールのログを確認します。

送信元VLANごとに、実際にそのVLANに接続したデバイスからテストします。毎回、送信元アドレス、ゲートウェイ、DNSサーバーを記録します。予定したサービスへの許可接続、マトリックス外の内部サービスへの拒否接続、予定したリゾルバーを使ったDNS検索、計画したインターネットアクセスを確認します。スイッチがゲートウェイを持つVLANでは、許可接続が失敗した場合に、スイッチのデフォルトルート、ルーターの戻りルート、宛先からの戻り経路を調べます。IPv6が有効なら、許可と拒否のテストをIPv6アドレスでも繰り返します。pfSenseでは、Status > System Logs > Firewallに許可またはブロックされた操作が記録されます。 Netgateのファイアウォールログガイド で表示方法を確認できます。ログの送信元、宛先、ポート、ルールをテスト結果と比較します。予想外に成功する場合は、広範な許可ルールと既存の状態エントリを確認します。ルール変更後は新しい接続を開始してください。既存の接続は、既存の状態によって通信を続ける場合があります。

WindowsでDNSを確認するには、nslookup example.comを実行し、表示されたサーバーを予定したリゾルバーと比較します。次に、DNSを制限したゲストまたはIoTクライアントから問い合わせます。検索が成功しても、選択したリゾルバーを使った証拠にはなりません。表示されたサーバーとファイアウォールまたはリゾルバーのログも確認します。IoTまたはゲストデバイスからルーターの管理アドレスへの直接アクセスは、拒否するケースとして別にテストします。

同じVLANにあるデバイスは、ルーターのファイアウォールを通らずに通信する場合があります。アクセスポイントがクライアント分離機能を備えている場合は個別にテストし、サーバーではホストファイアウォールを使います。VLAN間のファイアウォールテストでは、同じVLAN内の分離を証明できません。

期待する結果: 各デバイスが予定したサブネットのアドレスを取得します。許可されたサービスは動作します。拒否された試行は、ファイアウォールのブロックまたは文書化された同等の制御に対応します。

トラブルシューティング #

  • アドレスがない: アクセスポートまたはSSIDのVLAN、トランクタグ、DHCPスコープ、ゲートウェイインターフェイスを確認します。
  • アドレスは取得できるがDNSが失敗する: リゾルバーアドレス、ルーターサービスのバインド、DNS通信のファイアウォールルールを確認します。
  • デバイスが予想外に別のVLANへ到達する: ルーターのルール、広範な許可ルール、両デバイスがまだ同じタグなしネットワークにいるかを確認します。
  • ルーティング通信のファイアウォールログがない: レイヤー3スイッチや別のゲートウェイがファイアウォールに届く前に通信をルーティングしていないか確認します。
  • スイッチがゲートウェイのVLANからローカルネットワークには届くがインターネットに出られない: スイッチのデフォルトルート、ルーターの戻りルート、ファイアウォールポリシー、VLANサブネットの送信NATを確認します。
  • IPv4はブロックされるが接続は成功する: IPv6アドレス、ルーター広告、IPv6ルール、既存の状態エントリを確認します。
  • 拒否テストがファイアウォールログなしでタイムアウトする: 宛先サービスが待ち受けていることを確認します。次にルーティングとログ設定を調べます。 Netgateのファイアウォールトラブルシューティングガイド でログと状態の確認方法を参照できます。
  • キャストや検出が停止する: 範囲を限定した例外を追加する前に、検出プロトコルとコントローラーへの経路を特定します。

次のステップ #

デバイス一覧と通信マトリックスをネットワーク図と一緒に保管します。サーバーやIoTデバイスを追加したらルールを見直します。関連するネットワーク変更の後は、許可接続と拒否接続を1回ずつ再テストします。より広い設計原則は ネットワークセグメンテーション を参照してください。
