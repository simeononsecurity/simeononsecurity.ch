ホームラボ向けUPSの容量選定と自動シャットダウンのテスト

UPS（無停電電源装置）があれば、停電時にホームラボの作業を保存し、システムを停止する時間を確保できます。ラベルだけではサーバーが何分動くか分かりません。機器の負荷、UPSのW数とVAの上限、その負荷での稼働時間の見積もり、そして検証済みの停止手順が必要です。

要点 #

  • 負荷を測定する： バッテリーで動かす各機器について、通常時と高負荷時のW数を記録します。
  • 両方の定格を確認する： UPSは接続機器のW数とVAの要件を満たす必要があります。
  • 稼働時間曲線を確認する： 稼働時間は負荷とバッテリーの状態で変わります。機種別の見積もりを使います。
  • 停止をテストする： UPSの信号が各ホストに届き、バッテリー切れ前にホストが停止することを確認します。

始める前に #

地域の電源に適合した電力計、機器と電源アダプターの一覧、候補となるUPSの仕様と稼働時間グラフが必要です。自動シャットダウンのテストには、対応するUSBまたはネットワーク管理接続と各ホスト用のソフトウェアも必要です。通常負荷の測定、高負荷時の観察、計画的な保守テストに時間を確保してください。完全な停止テストではサービスが中断するため、ホームラボ作業としては中級レベルです。

サイトの サージ保護タップのガイド では過電圧保護を扱います。 UPSモデルの比較記事 では製品を紹介します。このガイドでは、あなたの負荷に合わせた容量選定と検証を説明します。Eatonの UPS容量選定ガイド とSchneider Electricの UPS購入ガイド は、出力容量とバッテリー稼働時間を区別しています。

警告： UPSメーカーが認めた出力端子と負荷だけを使ってください。定格容量を超えない範囲でテストします。実際の停止テストでは接続したラボが停止します。

稼働を続ける機器を測る #

停止まで動かす必要がある機器を決めます。ホストがシャットダウン信号を受け取るためにネットワーク接続を必要とする場合は、ハイパーバイザー、ストレージ、ネットワークスイッチ、ルーターを含めます。計画上必要でなければ、モニター、プリンター、その他の任意機器はバッテリー出力に接続しません。

バッテリーで動かす予定の機器群をコンセントで測定します。通常時のW数と、ホストや仮想マシンの起動など代表的な作業で観測した最大W数を記録します。電源ユニットのラベルは定格容量を示すもので、システムの実測消費電力ではありません。それでも機器のラベルで入力や突入電流の上限を確認してください。測定条件を記録します。

機器通常時のW数観測した最大W数バッテリー出力に接続？
ルーターとスイッチ3035はい
NAS6090はい
小型サーバー90135はい
例示の合計1802603台

上の数値は例示であり、特定のラボの測定値ではありません。ディスク、GPU、電源設定、接続機器によって負荷は変わります。大きなハードウェア変更後は再測定してください。

W数とVAを比較する #

W数は機器が実際に使う有効電力を示します。ボルトアンペア（VA）は皮相電力を示します。両者の関係は力率で決まります。W数を力率で割るとVAになります。Eatonは 容量選定ガイド でこの計算を説明しています。1000 VAを1000 Wと同じだと考えないでください。UPSのW数の定格も確認します。

例示の最大負荷260 Wに25%の容量余裕を加えると325 Wです。Schneider Electricは負荷より 約20～25%高い出力W数 を推奨しています。計画したピーク負荷と余裕を上回る連続W定格のUPSを選びます。合計力率が分かる場合は、ピークW数を力率で割ってピークVAを見積もり、VAにも同じ余裕を加えます。不明な場合は適切な計測器またはメーカーの選定ツールでVA要件と余裕を確認します。測定していない力率を作り出さないでください。

容量の余裕は稼働時間を保証しません。W数の上限が高くてもバッテリーが小さいUPSでは、短時間しか給電できない場合があります。機種を決める前に出力端子、プラグ形状、入力電圧、通信インターフェース、バッテリー交換方法を確認します。

稼働時間の目標を決める #

ラボを安全に停止するのに必要な時間を記録します。停止通知がホストに届く時間、仮想マシンの停止、ストレージへの書き込み完了、UPS出力の停止を含めます。停止が遅れる場合やバッテリーが古い場合の余裕も加えます。短い停電中も稼働させたいラボと、正常に停止するだけのラボでは目標が異なります。

例として、テスト済みの停止に6分かかり、5分の余裕を確保するとします。予想負荷で必要な稼働時間は少なくとも11分です。これは計画例であり、普遍的な基準ではありません。実測した通常負荷と高負荷で候補機種の稼働時間グラフまたは選定ツールと比較し、バッテリーの経年劣化に応じて再確認します。Schneider Electricの UPS選定ツール は入力した負荷と機種仕様から稼働時間を見積もります。Eatonの デスクトップUPSガイド も機種別データを案内しています。

このワークシートをラボ用にコピーしてください。電力計の測定値を機器ごとの行に記入します。通常時と高負荷時のW数を合計し、高負荷の合計に選択した余裕を加え、実測または計算したピークVAにも同じ余裕を加えます。両方の結果を候補のUPSと比較します。メーカーの選定ツールを使う場合はVAの選定結果と余裕を記録します。稼働時間は機種の曲線から見積もります。テスト中に時間と復旧結果を記入します。

項目あなたの結果
機器とバッテリー出力機器名と割り当てた出力端子
機器別と合計の通常W数実測値と合計
機器別と合計の最大W数観測した最大値と合計
実測または仕様上の力率値と出典、または「不明」
実測または計算したピークVA分かる場合、ピークW数を合計力率で割った値
容量の余裕選んだ割合と、余裕を加えた後のW数およびVA
候補UPSの定格機種、出力W数とVA、出力端子の上限
目標と曲線の見積もり必要な分数と負荷に対する機種の見積もり
通知と停止の時刻バッテリー通知の時刻と最後のホストの停止時刻
復旧結果ホストの起動、ストレージ、アプリケーション、監視

力率が不明な場合はメーカーの選定ツールを使うか、適切な計測器で皮相電力を測ります。推測した力率に基づくVAを報告しないでください。UPSが両方の出力上限を満たし、見積もり稼働時間が停止目標を上回ったときにワークシートが完成します。

期待される結果： ワークシートには接続機器、実測負荷、UPSのW数とVAの上限、稼働時間の目標、機種別の見積もりが記載されています。

自動シャットダウンを計画する #

UPSは一時的に機器へ給電しますが、ホストにはシャットダウン信号が必要です。UPSにUSB、ネットワーク管理カード、その他の対応インターフェースがあるか確認します。停止が必要な各ホストに互換性のある監視経路があることを確認します。Eatonによると、多くの機種はUSBまたはネットワーク通信による NASやサーバーの正常なシャットダウン に対応しています。

Network UPS Tools（NUT）を使うLinuxラボでは、UPSドライバーが装置の状態を読み取り、upsdが状態を共有し、電源が危険な状態になるとupsmonがホストを停止します。USBまたはシリアルでUPSに直接接続されたホストは、通常、ドライバー、upsd、upsmonをPrimaryモードで実行します。他のホストはそのサーバーに対してupsmonをSecondaryモードで実行します。ネットワーク管理型UPSでは、対応ドライバーと機種固有のPrimary構成が必要です。 NUTのトポロジーガイド で役割を確認できます。バッテリー運転中も監視ホストが接続を保てるよう、ルーターとスイッチを構成します。シャットダウンコマンドと権限は管理者に限定します。

停止テストの前に、ドライバーが最新の状態を報告するか確認します。NUT構成内のUPS名でmyupsnameを置き換えます。

upsc myupsname@localhost ups.status

NUTの 構成ガイド では、通常の商用電源をOL、バッテリー運転をOBで示します。UPSを監視する各ホストから状態を確認し、リモートクライアントには正しいサーバー名を指定します。値が古い、または取得できない場合は、停止テストの前に信号経路を修復してください。

停止順序を記録します。たとえば、最初にアプリケーションVM、次にストレージクライアント、最後にハイパーバイザーとNASを停止します。電源復旧後に各サービスとファイルシステムが正常に戻るか確認します。ホストが停止してもアプリケーションが正常に復旧しなければ、テストは完了していません。

推測せずにテストする #

UPSドライバーを構成したホストでドライバーの試行から始めます。NUTはupsdrvctl -t shutdownをドライバー停止シーケンスのプレビューとして説明しています。このコマンドはドライバーを起動せず、電源も切りません。

upsdrvctl -t shutdown

このドライバーの試行では、停電通知が各ホストに届くことまでは確認できません。各監視サービスとログを確認します。メンテナンス時間には、NUTの シャットダウンテスト手順 を参照し、NUTのPrimaryホストでupsmon -c fsdによる強制停止テストを行います。このFSDテストは実際の停止シーケンスを開始します。FSDフラグはupsdを再起動するまで残ります。システム復旧後、upsdが再起動し、状態にFSDが表示されないことを確認してから監視に再び依存します。現在の upsmonマニュアル を読み、復旧方法を用意し、作業を保存してラボの利用者に知らせてからテストします。

制御されたバッテリーイベントテストでは、最初にUPSメーカーの手順に従い、重要でない負荷を使います。低負荷でのテストは信号の伝達を確認しますが、ラボの稼働時間を証明するものではありません。後日、メンテナンス時間に予定負荷を代表するバッテリー負荷でテストします。UPSを監視し、余裕が減った場合に商用電源を戻せる担当者を置きます。UPSに表示された負荷、バッテリー運転の通知時刻、各ホストの停止開始時刻、最後のホストが停止した時刻を記録します。ホスト停止前にバッテリーが尽きないことを確認します。電源復旧後は、ホスト起動、アプリケーションの状態、ストレージの整合性、監視状態を確認します。NUTが示す成功条件は、バッテリー切れ前にOSが停止し、電源復旧後に動作が戻ることです。

確認項目記録する内容
信号経路UPSイベントが各監視ホストに表示される
停止時間バッテリー切れ前に最後のホストが停止した
復旧ホスト、ストレージ、アプリケーションが正常に起動した
容量UPS負荷がW数とVAの上限内に収まる

トラブルシューティング #

  • UPS過負荷アラーム： 任意の負荷を取り外します。実測した高負荷をUPSの両方の定格と出力端子の上限に照らして確認します。
  • 稼働時間が予想より短い： 現在の負荷、バッテリーの使用年数、機種別の稼働時間データ、最近のバッテリーテストを確認します。VAだけから直線的に推定しないでください。
  • ホストが1台だけ動き続ける： 監視サービス、ネットワーク経路、停止権限、ログを確認します。
  • ホストは停止するが復帰しない： 電源復旧時のUPS出力動作、ホストのファームウェアの電源復旧設定、NUTの 電源切り替え競合に関する考慮事項 を確認します。
  • 試行は成功するが停電テストは失敗する： ドライバーのプレビューは限定された経路しか確認しません。イベント通知と実際の停止順序を調べます。

次の手順 #

ワークシートをホームラボの機器台帳と一緒に保管します。機器を追加したら負荷を再測定し、UPS、監視ソフトウェア、ホストの起動ポリシー、ストレージ構成を変更したら停止テストを繰り返します。バックアップと復元の計画は別に確認してください。バッテリーは停止に必要な時間を確保し、 テスト済みのホームラボバックアップ は他の障害からデータを守ります。
