返回实用 AI 工作流课程

当一个独立问题的工作量足以单独开启会话时，再进行委派。 工作代理在自己的上下文中检查来源、审查测试，或起草范围明确的改动。主代理检查并整合结果。本课比较文档，同时让主会话继续处理小型实验任务。

**学习目标：**你将分配一项独立审查工作，并验证工作代理提交的简短证据报告。

要点 #

  • **协调器：**负责协调任务和最终审查的主代理。
  • **工作代理：**负责一个边界明确结果的独立代理。
  • **独立工作：**其答案不依赖其他代理未完成结果的子任务。
  • **所有权：**分配给单个代理的指定文件或问题。
  • **整合：**主代理将工作代理的输出与当前来源进行比较。

开始之前 #

**前置要求：**你的 上下文交接 和 输出验证 记录。预留 40 分钟。难度为中级。连接式路线需要支持工作代理的产品。学习路线使用单独的聊天并手动整合。

本课从干净的起始副本开始。 将已编辑过滤器的差异和测试记录保存在实验之外。把原始 ZIP 解压到新的临时文件夹。运行起始命令和两个基线测试。重复课程设置课中的 Git 基线，并根据仓库上下文课重新创建简短的 AGENTS.md 和可选的 CLAUDE.md 指引。自行提交这些指引文件，然后确认 git status --short 输出为空。保留已编辑过滤器副本作为参考，但在干净起始副本上执行代理练习。

判断是否委派 #

小型顺序编辑使用一个代理。 委派需要准备、令牌和审查成本。当只读问题彼此独立，且答案原本会让主聊天装入许多文件或来源页面时，再使用工作代理。

实验任务是否委派原因
添加一个双值筛选器通常不需要一个小文件和有针对性的测试
在两个基线测试中找出遗漏案例通常不需要主会话读取一个短文件更快
比较三个产品的当前文档是，只读来源阅读留在工作代理上下文中
两次编辑同一个函数否并行编辑会产生冲突

**工作代理接收的上下文应少于协调器，**不要复制整个对话。提供目标、来源路径、任务边界和返回格式。在主会话中保留简短的证据报告。采取行动前自行检查引用的文件。

启动一个只读工作代理 #

主任务保持精简。 在主会话中读取本地 AGENTS.md，并记录测试命令所在文件。将下面独立的研究问题分配给一个工作代理。它不需要整个实验或之前的聊天。

**连接式路线：**在 Codex、Claude Code 或其他支持工作代理的客户端中将实验作为项目打开，并让主代理将下面的只读请求委派给一个工作代理。检查工具记录，确认真实工作代理已启动并返回报告。如果产品不显示工作代理，请使用单独会话并标记为独立工作会话。当前的 Codex 子代理指南 、 Claude Code 子代理指南 和 OpenCode 代理指南 介绍了相关控制。

**学习路线：**为同一请求打开新聊天。向它提供三个官方链接或来源摘录，并标记为模拟工作代理。第二个聊天属于独立上下文，但不能证明运行了原生子代理。

使用当前官方 Codex AGENTS.md、Claude Code memory 和 OpenCode rules 文档。
比较每个产品如何加载仓库指引文件。
不要编辑文件。
最多返回三行：产品、指引文件、来源 URL 和一种加载行为。
指出不确定之处。不要粘贴完整页面。

来源集： Codex 项目指引 、 Claude Code 记忆指南 和 OpenCode 规则 。预期报告会为 Codex 和 OpenCode 列出 AGENTS.md。当前 Claude Code 版本也会在没有 CLAUDE.md 或 CLAUDE.local.md 优先时直接加载 AGENTS.md。本实验使用带有 @AGENTS.md 导入的 CLAUDE.md，也支持旧版本或采用不同配置的会话。将此示例视作实际观察到的代理输出前，请先核对当前页面和生效版本。

整合发现 #

自行打开引用的来源页面。 如果工作代理声称 Claude Code 始终要求导入 CLAUDE.md，请检查其 memory 指南并更正报告。将报告与本地指引文件比较，写一段简短的整合说明：

采纳：Codex 和 OpenCode 使用 AGENTS.md 作为项目指引。
当前 Claude Code 可直接加载 AGENTS.md。本实验使用带有 @AGENTS.md 导入的
CLAUDE.md，以维护稳定的共享索引。
证据：记录三份当前官方页面的 URL 和审查日期。
决定：保留简短的共享索引和 Claude 导入。

**这段说明才是有用的工作代理成果。**协调器需要已验证的发现和来源路径，不需要完整研究记录。委派会增加总令牌消耗，因此只有当单独会话节省注意力时，才缩短主对话。

分配编辑所有权 #

**如果工作代理要编辑文件，**按文件分配所有权，或为重叠的仓库任务使用单独的工作树。工作树是同一 Git 仓库的另一份副本，拥有独立的工作文件。它能隔离并行编辑。主代理审查改动，通过明确的 merge、cherry-pick 或 patch 转移，然后在整合后的工作树中重新运行测试。

工作代理负责工作返回内容
实现task_report.py差异和测试命令
测试编写tests/test_task_report.py测试用例和实际结果
协调器要求和最终整合合并后的差异和验收条件

**小型实验不需要并行编辑。**此表展示大型任务的所有权划分方式。一个工作树中的测试不能验证仍隔离在另一个工作树中的实现。如果两个工作代理都需要同一个函数，请按顺序处理，或让其中一个只审查、不编辑。单独工作树可防止文件冲突，但不能解决相互矛盾的要求。

检查产品行为 #

子代理行为因宿主而异。 Codex、Claude Code 和 OpenCode 的上下文继承、工具权限和结果交付方式各不相同。针对已安装产品阅读 Codex 子代理指南 、 Claude Code 子代理指南 和 OpenCode 代理指南 。不要假定工作代理共享主会话的全部上下文，或在隔离工作树中运行。

练习与检查 #

**你的产出：**一份简短的文档工作代理报告和一份整合说明。在学习路线中，使用新聊天并将其标记为模拟工作代理。不要声称该路线运行了原生子代理。

**完成检查：**报告列出三个官方来源，围绕问题作答，并符合长度限制。整合说明核对来源并指出实验所用的指引文件。

检查理解情况 #

  1. **问题：**工作代理何时比单个代理更有帮助？**答案：**当它负责独立问题或产出，并提供有用的证据报告时。

  2. **问题：**两个工作代理改动了重叠文件后应做什么？**答案：**整合改动、检查合并后的差异，并重新运行检查。

故障排查 #

  • **工作代理返回冗长记录：**要求提供带文件引用的简短证据表。
  • **工作代理意见不一致：**选择答案前重新阅读权威文件。
  • **两个编辑发生重叠：**停止其中一个编辑，明确文件所有权或分开工作树。
  • **工作代理的工具权限不同：**检查其权限，不要假设与主代理设置相同。

后续步骤 #

**继续学习 有界目标循环 。**如需了解这个小实验之外的团队治理，请使用 AI 协作实施课程 。
