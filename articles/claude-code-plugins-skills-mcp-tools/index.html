Выбирайте расширение Claude Code для конкретного сбоя в рабочем процессе. Неясные требования требуют планировочной беседы. Пропущенные дефекты требуют проверки и тестов. Повторное исследование требует отслеживаемых источников. Установка новых инструментов помогает только при ясных обязанностях каждого инструмента.

Руководство сравнивает десять проектов для этих задач. В нём есть примеры настройки и полное упражнение по оценке. Анализ использует актуальную документацию проектов и предоставленное видео Chase AI. Рекомендации являются редакционными оценками, а не практическими измерениями производительности и не доказательством десятикратного роста продуктивности.

Главное #

  • Выбирайте по результату: проверенный план, карта кода и созданное изображение требуют разных инструментов.
  • Разделяйте уровни установки: инструкции, исполняемые программы, плагины и подключения к сервисам имеют разные зависимости.
  • Проверяйте названия: Graphify и grill-me-codex теперь имеют разные канонические адреса репозиториев.
  • Проверяйте больше, чем согласие: принятие плана двумя моделями не доказывает правильную реализацию.
  • Измеряйте принятую работу: учитывайте настройку, использование сервиса, неудачные попытки и исправления человека.

Перед началом #

Требования: рабочая установка Claude Code, отдельный проект или ветка для теста и разрешение использовать выбранные внешние сервисы. Примеры CLI предполагают терминал и названный менеджер пакетов. Облачным интеграциям нужны собственные учётные записи и аутентификация.

Расчётное время: 15 минут на чтение, затем 30–60 минут на одну ограниченную проверку. Сложность: средняя для настройки CLI и интеграции сервисов. Для чтения инструкционных навыков требуется меньше подготовки.

Документация проверена 10 октября 2026 года. Команды и правила доступа соответствуют указанным источникам. Проверьте установленную версию перед использованием старого руководства. Статья посвящена расширениям Claude Code и отмечает различия хоста там, где это важно.

После установки проверяйте слоями. Отдельно проверьте файлы, обнаружение хостом, исполняемые зависимости, учётные данные и одну представительную задачу. Успешный установщик не доказывает работу браузера, MCP-сервера, медиаинструмента или внешней учётной записи. Первый тест проводите на синтетических данных и запишите исходную ревизию.

Знайте тип расширения #

Тип Роль Пример
Файл инструкций Задаёт постоянные ожидания проекта CLAUDE.md
Skill Даёт процедуру для выбранной задачи grill-me
Плагин Объединяет зарегистрированные команды и интеграции плагин Codex
CLI Выполняет команды из терминала Graphify
MCP-сервер Открывает вызываемые инструменты клиенту агента интеграция экземпляра n8n

Model Context Protocol (MCP) соединяет приложение агента с инструментами и данными сервера. Интерфейс командной строки, или CLI, запускает исполняемые команды. Skill часто учит агента пользоваться одним из интерфейсов, но его наличие не доказывает рабочее соединение.

Начинайте с отсутствующей возможности. Если агент уже ищет по репозиторию, новая процедура поиска должна дать наблюдаемую пользу. Если у агента нет доступа к платформе автоматизации, текстовый файл инструкций не предоставит аутентифицированный доступ. Более широкий гид по среде выполнения агентов объясняет ПО вокруг вызовов моделей и выполнения инструментов.

Уточните работу #

grill-me и grill-with-docs #

Навыки Matt Pocock превращают недоопределённую идею в решения. Текущая точка входа grill-me вызывает общий skill grilling. grill-with-docs вызывает grilling и моделирование предметной области. Документация коллекции описывает общие термины и записи архитектурных решений.

Используйте вариант с документацией, когда деловые термины влияют на реализацию. Для учебного импортера CSV определите, означает ли существующий клиент тот же e-mail, тот же внешний идентификатор или оба значения. Запишите определение до реализации поиска дубликатов.

Сохраняйте пропорции интервью. Полезная сессия решает существенную неопределённость. Интервью не должно заставлять повторять ответы из репозитория. Завершите его планом, нерешёнными вопросами и наблюдаемыми проверками результата.

CLAUDE.md по мотивам Karpathy #

Рекомендации Multica переводят наблюдения Karpathy в четыре темы: явные предположения, простые решения, сфокусированные изменения и проверяемые цели. Репозиторий является общественной реализацией этих идей. Называть его лично поддерживаемым Karpathy плагином было бы неверно.

Встраивайте полезные советы в существующую политику проекта. Сохраняйте команды сборки, правила контента и ограничения развёртывания. Файл инструкций, удаляющий эти детали, создаёт новые ошибки.

Пример правила проекта: требуйте от изменения импортера сохранять обработку дубликатов и объяснять каждое намеренное изменение fixture-файлом. Инструкции задают ожидания. Тесты и средства контроля выполнения дают отдельные доказательства.

Артефакт планирования Назначение
Требование Называет видимый пользователю результат
Запись глоссария Придаёт одно значение перегруженному термину
Запись решения Сохраняет причину важного выбора
Проверка принятия Определяет оценку завершения

Проверяйте планы и код #

grill-me-codex, теперь Claudex Loop #

Claudex Loop является текущим продолжением проекта grill-me-codex. Документация описывает разведку репозитория, требования, проверку другим провайдером, реализацию и независимую инспекцию. Полный цикл требует оба CLI и Python 3.10 или новее.

Используйте Claudex Loop для важных планов с предположениями, которые стоит оспорить до реализации. Текущий процесс запускается из Claude Code или Codex. Он записывает замечания и решения и разделяет разрешение на проверку и разрешение на создание. Старое описание пяти раундов в видео не заменяет текущий бюджет раундов установленного процесса.

Просите доказательство для каждого возражения. Для импортера CSV проверка должна назвать конкретный случай дубликата или повторной отправки и ожидаемое поведение. Согласие моделей является результатом проверки, а не доказательством. Сохраняйте нерешённые замечания после исчерпания бюджета.

Плагин OpenAI Codex # 

/plugin marketplace add openai/codex-plugin-cc
/plugin install codex@openai-codex
/reload-plugins
/codex:setup

Плагин OpenAI Codex для Claude Code добавляет проверку кода и делегирование задач внутри Claude Code. Это команды Claude Code, а не команды оболочки. Официальный репозиторий описывает Node.js 18.18 или новее и аутентифицированный доступ к Codex через ChatGPT или ключ API OpenAI.

/codex:review --background
/codex:status
/codex:result

Используйте обычную проверку для текущих изменений или сравнения веток. Для целевой проверки используйте /codex:adversarial-review. Команды делегирования вроде /codex:rescue выполняют другую работу, поэтому укажите требуемые полномочия.

Отдельно планируйте использование Codex. Проект перечисляет ChatGPT Free среди поддерживаемых аккаунтов, но лимиты использования действуют. Установка плагина не создаёт неограниченный доступ.

Правило выбора: для существующего патча используйте ограниченную проверку плагином. Большой цикл нужен, когда требованиям и пересмотру плана требуется отдельный записанный процесс.

Сохраняйте полезный контекст #

Graphify # 

uv tool install graphifyy
graphify install --project
graphify extract . --code-only
graphify query "show the authentication flow"

Graphify превращает связи репозитория в доступный для запросов граф знаний. Его канонический репозиторий теперь находится в Graphify-Labs. Имя пакета graphifyy, с двумя конечными буквами y. Исполняемая команда остаётся graphify.

Извлечение только кода использует локальный разбор абстрактного синтаксического дерева. Документы и медиа обрабатываются отдельным путём на основе модели. Не переносите утверждения о приватности и стоимости режима code-only на все режимы.

Необязательные hook-и перестраивают граф после commit-ов и смены веток. После pull или merge документированный процесс требует graphify update .. Документам нужно отдельное обновление. Экспорт в Obsidian даёт другой вид графа.

Используйте Graphify для вопросов о связях, затем проверяйте исходный файл. Граф помогает выбрать файлы. Его структура не доказывает поведение во время выполнения и не заменяет тесты. Измеряйте экономию токенов на собственных вопросах, включая построение и обслуживание графа.

claude-obsidian #

claude-obsidian организует источники в связанные страницы Obsidian с цитатами. Его репозиторий описывает загрузку, поиск, обслуживание знаний, сохранение источников и записи подтверждений или противоречий. Vault остаётся обычным набором локальных файлов.

Используйте claude-obsidian для долговременных знаний проекта: решений дизайна, исходных документов и исследовательских заметок. Полезный результат является поддерживаемой записью с происхождением, то есть отслеживаемым источником каждого важного утверждения.

Проверяйте vault после загрузки. Выберите несколько утверждений и пройдите по их цитатам до источника. Сохраняйте конфликтующие доказательства вместо уверенного объединения разногласий. Локальное хранение не доказывает локальный вывод. Проверьте хост и конфигурацию модели перед передачей чувствительных документов.

Система контекста Лучший первый вопрос
Graphify Какие исходные компоненты связаны?
claude-obsidian Какое сохранённое доказательство поддерживает решение?
notebooklm-py Что говорят выбранные источники исследования?

notebooklm-py # 

uv tool install "notebooklm-py[browser]"
notebooklm login
notebooklm auth check --test --json
notebooklm skill install

notebooklm-py предоставляет библиотеку Python, CLI и skill агента для исследовательского сервиса Google Notebook. Проект описывает импорт источников, вопросы с опорой на источники, создание артефактов и пакетные загрузки. Дополнение browser поддерживает интерактивный вход.

Это неофициальная интеграция. Библиотека использует недокументированные интерфейсы Google и подвержена поломкам и ограничениям. Не называйте её публичным API, поддерживаемым Google.

Используйте notebooklm-py для ограниченного корпуса, например заметок о выпуске и руководств миграции одной зависимости. Проверяйте цитаты по исходному тексту до включения выводов в план. Защищайте сохранённое состояние аутентификации как материал доступа к аккаунту.

Передача исследования меняет место выполнения работы. Она не устраняет токены оркестрации, квоты сервисов, работу по проверке и обязанности по обработке данных. Экономию токенов нужно измерять, а не считать свойством установки.

Проектируйте и создавайте ресурсы #

Impeccable # 

/impeccable critique settings
/impeccable audit settings
/impeccable polish settings

Impeccable даёт словарь дизайна для целевой работы над интерфейсом. Документация охватывает критику, компоновку, типографику, доступность, движение и визуальную итерацию в браузере. Примеры предполагают установленный skill и проект с экраном настроек.

Начинайте с проблемы взаимодействия. Для импортера выясните, почему пользователи пропускают ошибки проверки или неправильно понимают обработку дубликатов. Просмотрите предложения до визуальной полировки. Хорошие отступы не исправляют неясное действие.

Итерация в браузере помогает сравнить варианты. Проверьте клавиатурную навигацию, мобильный вид, сообщения об ошибках и контраст. Число команд меняется между версиями, поэтому используйте список установленной версии.

Higgsfield #

MCP-интеграция Higgsfield соединяет агентов с сервисом генерации изображений и видео. Официальная страница перечисляет варианты подключения Claude Code и CLI. Используйте текущий процесс для своего аккаунта и интерфейса.

Выбирайте Higgsfield, когда не хватает медиафайла. Для иллюстративной страницы продукта заранее задайте пропорции, композицию, ограничения бренда и место размещения. Отделяйте визуальный бриф от реализации страницы.

Сначала проверьте доступ и расход. Список интеграций не доказывает доступ к каждой модели, неограниченную генерацию или конкретные коммерческие права. Проверьте условия аккаунта и выбранную модель.

Проверьте итоговый файл в целевом размере. Проверьте текст, лишние символы, кадрирование и соответствие продукту. Сгенерированные экраны терминала и диаграммы не являются доказательством успешного теста.

Результат дизайна Доказательство завершения
Изменение интерфейса Нужные действия работают в целевых представлениях
Изображение Размеры, кадрирование и содержание соответствуют брифу
Видео Время, движение и финальный экспорт соответствуют брифу

Подключайте повторяемые процессы #

n8n MCP #

Встроенный MCP-сервер n8n открывает операции рабочих процессов подключённым клиентам. Документация подключения охватывает Cloud и самостоятельный хостинг. Создание и редактирование рабочих процессов описано начиная с n8n 2.13.0. Здесь рассматривается собственный сервер n8n, а не сторонний пакет с похожим названием.

Для этой интеграции используйте доступ уровня экземпляра. Узел MCP Server Trigger имеет другой охват и открывает инструменты одного процесса. Сверьте справочник инструментов с развёрнутой версией.

Включайте доступ осознанно. Существующим процессам нужна экспозиция MCP для полного доступа. Предпросмотры поиска имеют более широкую видимость в рамках прав пользователя. Экспозиция процесса не является отдельным списком клиентов, хотя права клиента управляют операциями.

Проверьте режим выполнения. Документированное значение execute_workflow по умолчанию запускает опубликованную продуктивную версию. Ручной режим запускает текущую неопубликованную версию. Проверьте входы и последующие действия.

Полезный первый тест: классифицируйте синтетические запросы поддержки и запишите результаты в тестовое место. Проверьте пропущенные поля и повторы. Самостоятельный хостинг всё равно требует вычислительных ресурсов, обслуживания и платных последующих сервисов.

Проведите контролируемый тест #

Иллюстративное упражнение: добавьте импортер CSV в небольшое приложение. Он показывает строки, сообщает о неверных e-mail и предотвращает создание дубликатов. Данные клиентов и рабочие внешние места не нужны.

# Evaluation worksheet, not a tool configuration file
task: "add CSV import preview"
inputs:
  - "valid rows"
  - "invalid email field"
  - "repeated customer identifier"
  - "same import submitted twice"
acceptance:
  - "preview creates no records"
  - "invalid rows receive useful messages"
  - "duplicate policy matches the written requirement"
  - "repeat submission creates no extra records"
record:
  - "source revision and selected skill version"
  - "model and service configuration"
  - "elapsed time and billed usage"
  - "failed checks and human corrections"

Сначала установите базовый результат. Сохраните исходную ревизию и попросите агента выполнить задачу с текущим процессом. Проведите независимые проверки принятия и сохраните результат. Повторите с той же ревизии, одним расширением и теми же требованиями.

Свяжите эксперимент с предполагаемой проблемой. Для неправильного понимания дубликатов проверьте skill требований. Для пропущенного валидатора проверьте карту репозитория. Для незаметных ошибок проверьте интерфейс. Загрузка всех десяти инструментов мешает определить источник улучшения.

Ожидаемое рассуждение: успешная вторая попытка является полезным доказательством, но один запуск не устанавливает общий множитель продуктивности. Повторные запуски отделяют ценность инструмента от изменчивости модели. Сравнивайте принятые результаты, включая проверку и неудачные попытки.

Наблюдение Интерпретация
Быстрый ответ, неудачные тесты Меньше времени без завершения задачи
Долгий запуск, меньше исправлений Возможная выгода в общей работе по доставке
Два проверяющих согласны Согласие требует независимой проверки
Меньше расход агента, новые расходы сервиса Стоимость перенесена между поставщиками

Создайте сохранённую запись решения. Назовите проблему, инструмент, наблюдаемую пользу, нерешённый вопрос и условия следующего теста. Оставляйте инструмент, если его вклад проходит эту проверку. Большой набор установленных инструментов не требует большого активного процесса.

Устранение проблем #

Симптом Что проверить
Skill есть, команда завершается ошибкой Установку программы, PATH и вспомогательные файлы
В старом руководстве нет команд Установленную версию и канонические инструкции
Граф пропускает свежие изменения Свежесть графа и отдельное обновление документов
Проверяющий повторяет решённые возражения Ревизию плана, доказательства и бюджет проверки
Аутентификация Notebook не работает Диагностику, сессию и проблемы источника
В n8n нет ожидаемых операций Версию, настройки экспозиции и права
Дизайн лучше, но работает хуже Исходные критерии и проверки взаимодействия

Проверяйте уровни по порядку: файлы, обнаружение хостом, готовые зависимости, рабочая аутентификация и подтверждённая представительная задача. Установщик подтверждает только часть цепочки.

Перед добавлением копии проверьте пересекающиеся skill-и. Интервью требований, планировщики, дизайн-инструменты и пакеты проверки иногда задают разные значения по умолчанию. Выберите одну основную процедуру, затем добавляйте инструменты с названным вкладом. Сохраняйте политику репозитория и запрошенный охват.

Видеообзор #

Видео Chase AI представляет десять обсуждаемых проектов. Посмотрите оригинальное видео для демонстраций. Актуальную установку и поведение проверяйте в документации проектов. Заголовок видео является рекламным утверждением, а не измеренным результатом этого руководства.

Следующие шаги #

Выберите один повторяющийся сбой и одну проверку принятия. Испытайте расширение на отдельном проекте, затем оставьте минимальный набор, улучшающий результат. Добавляйте управление знаниями, генерацию медиа или автоматизацию только при необходимости.

Связанное руководство: прочитайте сравнение CLI-агентов для кода при выборе агента. Используйте курс сотрудничества с ИИ для практики требований, доказательств и ответственности за проверку.
