16GB 显卡上的本地 AI 编程：Strata、OpenCode 与 Qwen3.8

在 16GB 显卡上运行本地编程助手，适合处理范围明确的开发任务。 Strata 和 OpenCode 将本地推理与文件编辑、Shell 命令及测试执行结合起来。一次已公开的 Qwen3.8-Flash-Next 测试在 RTX 4060 Ti 上完成了应用开发、后续修改和赛车游戏原型，过程中没有产生付费推理调用。

要判断它能否取代订阅服务，还需要更广泛的测试。 已发布的结果证明这套配置在一台机器上能够运行，但不能证明它在各种语言、代码库或复杂调试任务上都能达到付费编程服务的水平。该系统还配备了 64GB 内存，模型有相当一部分依赖系统内存。

核心要点 #

  • 16GB 指的是显存，不是这套测试配置所需的总内存。
  • 提示词复用很重要，因为编程助手会反复提交重叠的对话历史。
  • 推理需要预算上限，这样规划阶段才会给代码和工具调用留出空间。
  • 生成的测试通过只算部分证据，Docker 和游戏运行情况还需分别检查。
  • API 费用为零不代表没有成本，电费、设备折旧和维护时间都要考虑。

准备条件： 一台兼容的电脑、所选模型所需的可用存储空间、Git、带有 npm 的 Node.js，以及终端工具使用经验。要复现报告中的 IQ3_S 配置，请准备 64GB 内存。其他配置请使用当前版 Strata 安装程序确认。

时间和难度： 中级。下载大型模型和完成安装需要时间，之后再评估任务完成速度。报告中的任务耗时不包含安装时间。

NetworkCoder 发布的配置与结果提供了这些数据。 测试代码库 报告称，46.84GiB 专家权重在 28 秒内加载，4,431 个专家占用 8.45GiB 显存。这些数据只描述该次测试，不能保证在其他引擎版本上得到相同分配结果。

当前兼容范围比这次测试更广。 根据 2026 年 10 月 6 日查阅的资料， Strata 项目 列出了部分至少配有 12GB 显存的 NVIDIA 和 AMD 显卡，也为 32GB 内存系统提供了较小的模型选项。这些选项并不等同于 16GB 显卡、64GB 内存和 IQ3_S 的实验。购买硬件前，请确认具体显卡、模型变体和运行环境都受支持。

模型如何分布在各处 #

混合专家（MoE）模型会为每个 token 激活一部分专家网络。与每一步都使用全部参数相比，这能减少活跃计算量。其余权重仍需要存储，并传送到计算位置。

Strata 的混合执行方式会把常用专家保留在 GPU 附近，同时把整组专家放在系统内存中。CPU 会在原位置计算未缓存的专家，GPU 则处理已缓存的专家。存储设备还用于保存模型文件和查找数据。该系统并没有把整个 125B 模型塞进 16GB 显存。

GPU 显存要由多个用途共享。 运行时分配、注意力状态和专家缓存都要占用有限的显存。给上下文留出更多空间，就会减少专家缓存可用的容量。当前版 Strata 也支持 KV 缓存流式传输，因此具体数据放置方式会与旧配置不同。请查阅对应引擎版本的 技术文档 。

提示词复用如何影响速度 #

**编程助手会不断循环：**读取任务、请求工具执行操作、接收结果，再决定下一步。文件内容、错误信息和测试输出会逐渐累积在对话中。助手也会压缩或筛选上下文，因此不会永远在每轮都重新提交一份完全相同的完整历史记录。

预填充会在生成前处理输入 token。解码则生成回复。如果系统解码很快，但每次工具调用前都要重复缓慢的预填充，你仍然需要等待。

报告中的 44K token 计时使用了前缀复用。 Strata 复用了先前处理过的对话内容，扩展后的提示词大约在一到三秒内准备就绪。这说明持续进行的助手会话能从中受益，但不能证明系统能在一秒内从头处理 44,000 个全新 token。

测量项目记录内容
冷提示词没有可复用前缀状态时处理新内容所需的时间
热续接向现有上下文追加工具结果后的处理时间
生成速度回复生成期间每秒输出的 token 数
任务耗时规划、生成、工具调用、测试和重试的总时间

两类缓存用途不同。 专家缓存会把常用权重放在靠近 GPU 计算的位置。前缀复用则避免重新处理先前输入。专家缓存命中率高，并不能证明提示词缓存也命中。

测试任务展示了什么 #

任务报告耗时报告结果

修复编辑功能并添加日期4 分 58 秒修改完成，6/6 项测试通过
添加导入导出和打包3 分 48 秒7/7 项测试通过，Docker 构建未验证
赛车游戏，首次尝试6 分 35 秒推理阶段耗尽输出额度，未生成代码

** 已发布的结果文件 **记录了前三项任务的输出速度：第一项为每秒 48–52 个 token，第二项为 40–43 个，第三项为 37–44 个。“最高 52”指这些观测中的峰值，不代表每项任务都能持续达到该速度。

前三项任务是在同一个应用上逐步扩展的。 5/5、6/6 和 7/7 表示依次扩展的测试套件，并不能证明有 18 项彼此独立的能力。由同一个助手编写的测试也需要检查覆盖范围和断言是否有效。

过程中也包含了环境故障恢复。 助手从一条不合适的 Shell 命令中恢复，并在测试期间发现一个已过期的应用服务器。这些表现有参考价值，但在共享开发环境中，结束现有进程前应先谨慎确认权限。

Docker 仍未验证。 助手编写了 Dockerfile，但由于没有可运行的 Docker 引擎，无法完成构建。在容器外通过应用测试，不能证明镜像可以正常工作。游戏重试也只检查了语法并打开浏览器，助手没有直接确认游戏是否正常运行。

为输出预留空间 #

{
  "reasoning_budget_tokens": 8000
}

**将此设置合并到现有的 strata-iq3_s.json 配置中，**保留其他字段，然后重启所选的 Strata 模型。这是 Strata 的设置，不能用来替换 OpenCode 配置文件。请从启动输出确认生效的预算。

Strata 支持硬性推理预算上限，达到上限后会结束思考阶段并转向生成回答。请求级的值会覆盖已配置的默认值。它与 low 或 high 这样的通用推理强度指令不同。

赛车游戏的首次尝试在规划阶段耗尽了 16,384 个 token 的额度。 重试时将思考预算设为 8,000 个 token，最终生成了代码。这支持在此类工作负载中使用有上限的推理阶段，但不能证明 8,000 是所有任务的最佳设置。

剩余输出额度只是上限，不保证都会用于输出。 如果 8,000 个 token 的推理上限全部用完，在总上限为 16,384 时，扣除其他开销前大约还剩 8,384 个 token。结果日志显示重试时写出了 11,054 个 token，但没有完整拆分推理和代码所占数量。不能据此理解为在同一个上限下先用了 8,000 个推理 token，又额外用了 11,054 个代码 token。

**范围较小的修改可先使用更小的预算，**再为需要更多分析的任务测试较大的预算。检查完整文件输出、任务结束状态和测试结果。只有当更多规划改善最终交付时，它才有价值。

连接 Strata 和 OpenCode #

git clone https://github.com/Niko1221/Strata.git
cd Strata
./setup.sh

这是 Linux 安装入口。 请查看当前安装说明。Windows 的文档路径使用 START-HERE.bat。选择原版 Qwen3.8-Flash-Next IQ3_S，并设置 65,536-token 上下文，以接近报告中的配置。请在基准测试记录中保存引擎版本和所选模型文件。

npm install -g opencode-ai

按照 OpenCode 官方说明 安装 OpenCode。 在另一个终端中，将 STRATA_BASE_URL 设为 Strata 输出的本地 API 基础地址，并保留末尾的 /v1。在这套配置中，让推理服务只绑定本机。

{
  "provider": {
    "strata": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Strata local",
      "options": {
        "baseURL": "{env:STRATA_BASE_URL}",
        "apiKey": "local"
      },
      "models": {
        "qwen3.8-flash-next-iq3_s": {
          "name": "Qwen3.8-Flash-Next IQ3_S",
          "limit": { "context": 65536, "output": 16384 }
        }
      }
    }
  },
  "model": "strata/qwen3.8-flash-next-iq3_s"
}

**将 provider 配置块合并到 ~/.config/opencode/opencode.json 中，**保留已有设置。此配置改编自 已发布的示例配置 ，使用环境变量加载本地端点。OpenCode 提供 自定义 provider 文档 和 环境变量替换文档 。

**local 是占位凭据，**与示例中的未认证本地配置一致。它不能保护服务器。如果 Strata 实例启用了身份验证，请通过合适的本地机密管理方式提供已配置的凭据。

**请在项目的临时副本中启动 opencode，**然后选择已配置的模型。发送代码前，请确认选中的 provider。客户端声明的上下文长度不会增加服务器配置的上下文长度。如果输出也需要空间，65,536-token 窗口就不能全部用于输入。

本地推理与权限 #

{
  "permission": {
    "edit": "ask",
    "bash": "ask"
  }
}

评估助手时，请将这些初始权限合并到 OpenCode 配置中。 权限文档 介绍了可用控制。无论推理在哪里运行，文件修改和 Shell 执行都会影响你的机器。

本地推理不代表每种工具都在本地运行。 软件包下载、网页工具、外部集成和可选分享仍会涉及网络服务。处理私有代码库前，请检查已启用的工具。“模型在本地运行”比“任何数据都不会离开电脑”范围更窄。

首次运行故障排查 #

现象优先检查
服务提供方不可用Strata 是否正在运行，以及环境变量是否传递到 OpenCode 进程
选择列表中找不到模型Provider ID 和 model ID 是否与保存的配置一致
上下文长度错误提示词长度与请求的输出是否都能放进服务器当前窗口
只规划而没有代码推理预算、总输出上限和任务结束状态
续接较慢前缀复用、内存压力、专家缓存行为和竞争进程
Docker 命令失败是否有可用的 Docker 引擎，而不只是命令行客户端

**每次只改一个设置，**并从保存的起始状态重复同一任务。这样能把配置改进与不同提示词或更简单的测试区分开。

它能取代订阅服务吗？ #

值得测试的本地配置仍应保留其他方案的情况
已经拥有兼容硬件仅为未经测试的工作负载购买硬件
范围明确的应用修改大型陌生代码库和复杂迁移
可重复的验收测试没有可靠方式检查正确性的任务
有时间维护运行环境需要尽量减少安装和支持开销的工作

**API 费用为零很有意义，**尤其是硬件已经到手的情况下。但这不包括电费、硬件折旧、存储和环境维护时间。界面显示的零成本字段也不会统计这些支出。

要比较订阅服务，必须使用匹配的任务。 在两套系统中使用相同的起始代码库、指令和验收检查。除耗时外，还要记录重试次数和人工修正。评估完整工作流时，也应计入赛车游戏首次失败的尝试，而不能只报告成功的重试。

本地助手不必在所有方面都胜出。 如果它能可靠完成日常修改，并把少数困难任务留给其他工具，它就已经改变了你对付费服务的需求。请根据自己项目中被接受的工作结果来决定。

演示与后续步骤 #

延伸观看： 125B 本地编程助手演示 。以上报告数据来自已发布的测试，并非本文独立执行的基准测试。

  1. **用固定验收标准复现一个小任务，**并保存起始版本。
  2. **分别测量冷启动和热续接，**不要把前缀复用误认为冷预填充速度。
  3. **单独验证打包过程，**成功构建镜像、启动容器并完成容器内检查。
  4. **检查生成的测试，**再添加实现过程中未覆盖的测试用例。
  5. **比较完成的工作，**再决定是否更换当前编程工具。

**规划硬件时，**请阅读 本地 AI 模型与 GPU 上下文指南 。了解托管模型的行为，请参阅 OpenRouter 服务提供方路由和成本 。
