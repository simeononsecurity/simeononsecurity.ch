ਕਮਾਂਡ-ਲਾਈਨ ਏਜੰਟ ਨੂੰ ਉਪਯੋਗੀ ਪਹੁੰਚ ਦੀ ਲੋੜ ਹੈ, ਹਰੇਕ ਕ੍ਰੈਡੈਂਸ਼ੀਅਲ ਦੀ ਨਕਲ ਦੀ ਨਹੀਂ। ਇਹ ਗਾਈਡ 1Password CLI, 1Password SSH ਏਜੰਟ, Bitbucket Git ਪਹੁੰਚ, ਅਤੇ Model Context Protocol (MCP) ਲਈ ਇੱਕ ਸੀਮਤ ਡਿਜ਼ਾਈਨ ਪੇਸ਼ ਕਰਦੀ ਹੈ। ਪਹਿਲਾ ਵਰਕਫਲੋ ਸੰਸਲੇਸ਼ਿਤ ਨਾਵਾਂ, ਪੜ੍ਹਨ-ਹੀ-ਮਾਤਰ ਕਾਰਵਾਈਆਂ, ਅਤੇ SSH ਸੀਮਾ ‘ਤੇ ਮਨੁੱਖੀ ਮਨਜ਼ੂਰੀ ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ।

ਮੁੱਖ ਅੰਤਰ ਸਧਾਰਨ ਹੈ। ਇੰਟਰਐਕਟਿਵ SSH 1Password SSH ਏਜੰਟ ਰਾਹੀਂ ਸਹਿਮਤੀ ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ। ਅਣ-ਨਿਗਰਾਨੀ ਆਟੋਮੇਸ਼ਨ ਨੂੰ ਇੱਕ ਵੱਖਰੀ ਪਛਾਣ, ਸੰਕੁੱਪਤ ਪਹੁੰਚ, ਅਤੇ ਇੱਕ ਵੱਖਰੀ ਕੀ ਲਾਈਫਸਾਈਕਲ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ। MCP ਕਨੈਕਸ਼ਨ ਨੂੰ ਕਿਸੇ ਵੀ ਵਰਕਫਲੋ ਚਲਾਉਣ ਦੀ ਇਜਾਜ਼ਤ ਵਜੋਂ ਨਾ ਮੰਨੋ।

ਮੁੱਖ ਨੁਕਤੇ #

  • ਪ੍ਰਾਈਵੇਟ-ਕੀ ਸੁਰੱਖਿਆ: 1Password SSH ਏਜੰਟ SSH ਪ੍ਰਮਾਣੀਕਰਨ ਕਰਦਾ ਹੈ ਜਦੋਂ ਕਿ ਪ੍ਰਾਈਵੇਟ ਕੀਆਂ ਨੂੰ 1Password ਐਪ ਦੇ ਅੰਦਰ ਰੱਖਦਾ ਹੈ।
  • ਪਬਲਿਕ-ਕੀ ਸੰਭਾਲ: ਸਿਰਫ਼ ਇੱਕ ਪਬਲਿਕ ਕੀ ਨੂੰ Bitbucket ਜਾਂ ਕਿਸੇ ਦੂਰੀ ਵਾਲੇ ਖਾਤੇ ਵਿੱਚ ਪ੍ਰਕਾਸ਼ਿਤ ਕਰੋ। ਪ੍ਰਾਈਵੇਟ ਅੱਧਾ ਹਿੱਸਾ ਇੱਕ SSH Key ਆਈਟਮ ਵਿੱਚ ਰੱਖੋ।
  • ਇੰਟਰਐਕਟਿਵ ਸਹਿਮਤੀ: SSH ਏਜੰਟ ਕੀ ਦੀ ਵਰਤੋਂ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ, ਇੱਕ ਵਿਅਕਤੀ ਕਲਾਈਂਟ ਜਾਂ ਟਰਮੀਨਲ ਸੈਸ਼ਨ ਦੀ ਮਨਜ਼ੂਰੀ ਦਿੰਦਾ ਹੈ।
  • ਅਣ-ਨਿਗਰਾਨੀ ਵੱਖਰਾਪਨ: ਇੱਕ ਸਕੇਜੂਲਡ ਜੌਬ ਨੂੰ ਇੱਕ ਵਿਸ਼ੇਸ਼ ਸਰਵਿਸ ਖਾਤੇ ਅਤੇ ਇੱਕ ਸੰਕੁੱਪਤ ਵਾਲਟ ਸਕੋਪ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ। ਇੰਟਰਐਕਟਿਵ SSH ਏਜੰਟ ਮਨਜ਼ੂਰੀ ਇਸ ਲੋੜ ਨੂੰ ਪੂਰਾ ਨਹੀਂ ਕਰਦੀ।
  • MCP ਸੀਮਾਵਾਂ: MCP ਏਜੰਟ ਨੂੰ ਟੂਲਾਂ ਅਤੇ ਸਰੋਤਾਂ ਨਾਲ ਜੋੜਦਾ ਹੈ। ਕਲਾਈਂਟ, ਸਰਵਰ, ਓਪਰੇਟਿੰਗ ਸਿਸਟਮ, ਅਤੇ 1Password ਨੀਤੀ ਅਜੇ ਵੀ ਪਹੁੰਚ ਨੂੰ ਨਿਯੰਤਰਿਤ ਕਰਦੀਆਂ ਹਨ।

ਸ਼ੁਰੂ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ #

ਪੂਰਵ-ਸ਼ਰਤਾਂ: 1Password 8 ਅਤੇ 1Password CLI 2.20.0 ਜਾਂ ਬਾਅਦ ਵਰਜਨ ਇੰਸਟਾਲ ਕਰੋ। ਇੱਕ ਸਮਰਥਿਤ 1Password ਖਾਤੇ ਰਾਹੀਂ ਸਾਈਨ ਇਨ ਕਰੋ। ਇੱਕ OpenSSH ਕਲਾਈਂਟ ਦੀ ਵਰਤੋਂ ਕਰੋ। ਇੱਕ ਟੈਸਟ Bitbucket ਰਿਪੋਜ਼ਿਟਰੀ ਜਾਂ ਕਿਸੇ ਹੋਰ ਗੈਰ-ਉਤਪਾਦਨ ਟਾਰਗੇਟ ਬਣਾਓ। ਰੋਲਬੈਕ ਲਈ ਇੱਕ ਦੂਜਾ ਪ੍ਰਸ਼ਾਸਨਿਕ ਪਾਥ ਉਪਲਬਧ ਰੱਖੋ।

ਸਮਾਂ: ਡਿਜ਼ਾਈਨ ਸਮੀਖਿਆ ਅਤੇ ਸੰਸਲੇਸ਼ਿਤ ਵਾਕਥਰੂ ਲਈ 30 ਤੋਂ 45 ਮਿੰਟ।

ਮੁਸ਼ਕਲ ਦਰਜਾ: ਵਿਚਕਾਰਲਾ। ਤੁਹਾਨੂੰ ਬੁਨਿਆਦੀ Git, SSH, ਸ਼ੈਲ, ਅਤੇ ਐਕਸੈਸ-ਕੰਟਰੋਲ ਗਿਆਨ ਦੀ ਲੋੜ ਹੈ।

ਇਹ ਗਾਈਡ ਡਿਜ਼ਾਈਨ ਅਤੇ ਯੋਜਨਾਬੰਦੀ ਨੂੰ ਕਵਰ ਕਰਦੀ ਹੈ। ਲਿੰਕ ਕੀਤੀ Bitbucket ਲੇਖ Bitbucket-ਵਿਸ਼ੇਸ਼ ਪਹੁੰਚ ਸੀਮਾਵਾਂ ਨੂੰ ਕਵਰ ਕਰਦਾ ਹੈ। ਇਹ ਗਾਈਡ ਕਿਸੇ ਲਾਈਵ ਖਾਤੇ ਦੀ ਜਾਂਚ ਨਹੀਂ ਕਰਦੀ, ਕੋਈ ਅਸਲ ਕੀ ਨਹੀਂ ਬਣਾਉਂਦੀ, ਕਿਸੇ ਅਸਲ ਹੋਸਟ ਨਾਲ ਜੋੜ ਨਹੀਂਦੀ, ਜਾਂ ਕਿਸੇ ਅਸਲ MCP ਸਰਵਰ ਦਾ ਰਜਿਸਟਰ ਨਹੀਂ ਕਰਦੀ। ਹੇਠਾਂ ਦਿੱਤੇ ਸਾਰੇ ਪਛਾਣਕਾਰੀ ਸੰਸਲੇਸ਼ਿਤ ਹਨ। ਪਲੇਸਹੋਲਡਰਾਂ ਨੂੰ ਸਿਰਫ਼ ਤੁਹਾਡੇ ਆਪਣੇ ਨਿਯੰਤ੍ਰਿਤ ਵਾਤਾਵਰਣ ਦੇ ਅੰਦਰ ਹੀ ਬਦਲੋ।

ਵਰਜਨ ਸਥਿਤੀ: ਇਸ ਵਰਕਫਲੋ ਲਈ 1Password 8 ਅਤੇ 1Password CLI 2.20.0 ਜਾਂ ਬਾਅਦ ਦੀ ਵਰਤੋਂ ਕਰੋ। 1Password CLI 1 ਨੂੰ ਅਸਮਰਥਿਤ ਕਰ ਦਿੱਤਾ ਗਿਆ ਹੈ । 1Password 7 ਦਾ 2027 ਦੇ ਸ਼ੁਰੂ ਵਿੱਚ ਰਿਟਾਇਰਮੈਂਟ ਹੋਵੇਗਾ । SSH-ਕੀ ਜਨਰੇਸ਼ਨ, ਇੰਪੋਰਟ, ਅਤੇ ਸਾਂਝਾ ਕਰਨ ਲਈ 1Password 8 ਦੀ ਲੋੜ ਹੈ। ਟੈਸਟਿੰਗ ਤੋਂ ਪਹਿਲਾਂ ਇੰਸਟਾਲ ਕੀਤੇ Git, OpenSSH, MCP ਹੋਸਟ, ਅਤੇ MCP ਸਰਵਰ ਵਰਜਨਾਂ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ। ਹੇਠਾਂ ਦਿੱਤੇ ਉਦਾਹਰਣਾਂ ਅਜੇ ਵੀ ਅਜ਼ਮਾਈ ਗਈਆਂ ਨਹੀਂ ਹਨ।

vault ਇੱਕ ਸੁਰੱਖਿਅਤ 1Password ਆਈਟਮਾਂ ਦਾ ਸੰਗ੍ਰਹਿ ਹੈ। OpenSSH ਉਹ SSH ਕਲਾਇੰਟ ਅਤੇ ਸਰਵਰ ਸਾਫਟਵੇਅਰ ਹੈ ਜਿਸਦਾ ਬਹੁਤ ਸਾਰੇ ਓਪਰੇਟਿੰਗ ਸਿਸਟਮਾਂ ਦੁਆਰਾ ਉਪਭੋਗ ਕੀਤਾ ਜਾਂਦਾ ਹੈ। MCP, ਜਾਂ ਮਾਡਲ ਕੰਟੈਕਸਟ ਪ੍ਰੋਟੋਕੋਲ, ਇੱਕ ਏਜੰਟ ਨੂੰ ਮਨਜ਼ੂਰ ਕੀਤੇ ਗਏ ਟੂਲਾਂ ਜਾਂ ਸਰੋਤਾਂ ਨਾਲ ਜੋੜਦਾ ਹੈ।

ਨਿੱਜੀ ਕੁੰਜੀਆਂ ਨੂੰ ਅਪੜ੍ਹੇ ਰੱਖਣ ਦਾ ਕਾਰਨ #

ਇੱਕ SSH ਕੁੰਜੀ ਜੋੜੇ ਵਿੱਚ ਇੱਕ ਪਬਲਿਕ ਕੁੰਜੀ ਅਤੇ ਇੱਕ ਨਿੱਜੀ ਕੁੰਜੀ ਹੁੰਦੀ ਹੈ। ਇੱਕ ਰਿਮੋਟ Git ਸੇਵਾ ਜਾਂ ਸਰਵਰ ਪਬਲਿਕ ਕੁੰਜੀ ਨੂੰ ਸਟੋਰ ਕਰਦਾ ਹੈ। ਕਲਾਇੰਟ ਪ੍ਰਮਾਣੀਕਰਨ ਦੌਰਾਨ ਨਿੱਜੀ ਕੁੰਜੀ ਦੇ ਮਾਲਕੀ ਦੀ ਪੁਸ਼ਟੀ ਕਰਦਾ ਹੈ। ਨਿੱਜੀ ਕੁੰਜੀ ਨੂੰ ਰਿਮੋਟ ਸੇਵਾ ਤੱਕ ਜਾਣ ਦੀ ਲੋੜ ਨਹੀਂ ਹੁੰਦੀ।

1Password SSH Agent ਇਸ ਮਾਡਲ ਨੂੰ ਵਧਾਉਂਦਾ ਹੈ। ਇਸਦੀ ਦਸਤਾਵੇਜ਼ੀਕਰਨ ਕਹਿੰਦਾ ਹੈ ਕਿ SSH ਅਤੇ Git ਕਲਾਇੰਟ ਏਜੰਟ ਰਾਹੀਂ ਪ੍ਰਮਾਣੀਕਰਨ ਕਰਦੇ ਹਨ, ਜਦੋਂ ਕਿ ਨਿੱਜੀ ਕੁੰਜੀ 1Password ਐਪ ਵਿੱਚ ਰਹਿੰਦੀ ਹੈ। ਕਲਾਇੰਟ ਨੂੰ ਇੱਕ ਸਾਈਨਿੰਗ ਨਤੀਜਾ ਮਿਲਦਾ ਹੈ, ਨਿੱਜੀ-ਕੁੰਜੀ ਫਾਈਲ ਨਹੀਂ।

ਇਹ ਸੀਮਾ ਕਈ ਖਤਰਿਆਂ ਦੇ ਰਾਹਾਂ ਨੂੰ ਘਟਾਉਂਦੀ ਹੈ:

  • ਸੋਰਸ ਕੰਟਰੋਲ: ਨਿੱਜੀ ਕੁੰਜੀ ਕਿਸੇ ਰਿਪੋਜ਼ਿਟਰੀ ਜਾਂ ਪੁੱਲ ਰਿਕਵੈਸਟ ਵਿੱਚ ਨਹੀਂ ਆਉਂਦੀ।
  • ਸ਼ੈਲ ਇਤਿਹਾਸ: ਨਿੱਜੀ-ਕੁੰਜੀ ਦਾ ਮੁੱਲ ਕਿਸੇ ਕਮਾਂਡ ਆਰਗੂਮੈਂਟ ਵਿੱਚ ਨਹੀਂ ਦਿਖਾਈ ਦਿੰਦਾ।
  • ਅਸਥਾਈ ਫਾਈਲਾਂ: ਇੱਕ ਸਕ੍ਰਿਪਟ ਨੂੰ ਨਿੱਜੀ ਕੁੰਜੀ ਨੂੰ ~/.ssh/ ਵਿੱਚ ਲਿਖਣ ਦੀ ਲੋੜ ਨਹੀਂ ਹੁੰਦੀ।
  • ਏਜੰਟ ਕੰਟੈਕਸਟ: ਇੱਕ ਵੱਡੀ ਭਾਸ਼ਾ ਮਾਡਲ (LLM) ਨੂੰ SSH ਓਪਰੇਸ਼ਨ ਦੀ ਮੰਗ ਕਰਨ ਲਈ ਨਿੱਜੀ-ਕੁੰਜੀ ਦੇ ਟੈਕਸਟ ਦੀ ਲੋੜ ਨਹੀਂ ਹੁੰਦੀ।
  • ਗਲਤੀ ਨਾਲ ਦੁਬਾਰਾ ਵਰਤੋਂ: ਇੱਕ ਕਾਪੀ ਕੀਤੀ ਗਈ ਕੁੰਜੀ ਟਾਸਕ ਖਤਮ ਹੋਣ ਤੋਂ ਬਾਅਦ ਪੁਰਾਣੇ ਵਰਕਸਪੇਸ ਵਿੱਚ ਨਹੀਂ ਰਹਿੰਦੀ।

ਇਹ ਸੀਮਾ SSH ਨੂੰ ਨੁਕਸਾਨਹੀਂ ਨਹੀਂ ਬਣਾਉਂਦੀ। ਕਿਸੇ ਪ੍ਰੋਸੈਸ ਨੂੰ ਏਜੰਟ ਸਾਕੇਟ ਦੀ ਵਰਤੋਂ ਕਰਨ ਦੀ ਇਜਾਜ਼ਤ ਹੋਣ ‘ਤੇ, ਉਹ ਮਨਜ਼ੂਰ ਕੀਤੀ ਗਈ ਕੁੰਜੀ ਵਜੋਂ ਕਾਰਵਾਈਆਂ ਕਰ ਸਕਦਾ ਹੈ। ਹੋਸਟ-ਕੁੰਜੀ ਪ੍ਰਮਾਣੀਕਰਨ, ਰਿਮੋਟ ਖਾਤਾ ਸੀਮਾਵਾਂ, ਰਿਪੋਜ਼ਿਟਰੀ ਇਜਾਜ਼ਤਾਂ, ਕਮਾਂਡ ਨੀਤੀ, ਅਤੇ ਪ੍ਰੋਸੈਸ ਵੱਖਰਾਪਣ ਅਜੇ ਵੀ ਮਹੱਤਵਪੂਰਨ ਹਨ।

ਨਿੱਜੀ-ਕੁੰਜੀ ਸੀਮਾ ਕੁੰਜੀ ਸਮੱਗਰੀ ਦੀ ਰੱਖਿਆ ਕਰਦੀ ਹੈ। ਸੀਮਾ ਕਿਸੇ ਰਿਮੋਟ ਕਮਾਂਡ ਨੂੰ ਮਨਜ਼ੂਰ ਨਹੀਂ ਕਰਦੀ ਜਾਂ ਸਾਬਤ ਨਹੀਂ ਕਰਦੀ ਕਿ ਟਾਰਗੇਟ ਹੋਸਟ ਭਰੋਸੇਯੋਗ ਹੈ।

ਇੰਟਰਐਕਟਿਵ SSH ਸਹਿਮਤੀ #

ਏਜੰਟ ਕੁੰਜੀਆਂ ਲਈ ਇੱਕ ਵਿਸ਼ੇਸ਼ vault ਸੈੱਟ ਕਰੋ। SSH ਏਜੰਟ ਸੰਰਚਨਾ ਫਾਈਲ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਸਭ ਤੋਂ ਛੋਟੀ ਕੁੰਜੀ ਸੈੱਟ ਅਤੇ ਹੋਸਟ-ਵਿਸ਼ੇਸ਼ ਕੁੰਜੀ ਦੀ ਚੋਣ ਕਰੋ। ਓਟੋਮੇਸ਼ਨ ਪ੍ਰੋਸੈਸ ਨੂੰ ਹਰ ਬਿਲਟ-ਇਨ vault ਤੋਂ ਹਰ ਮਨਜ਼ੂਰ ਕੁੰਜੀ ਨੂੰ ਖੁੱਲ੍ਹਾ ਨਾ ਕਰੋ।

1Password SSH Agent ਸੁਰੱਖਿਆ ਮਾਡਲ ਸਹਿਮਤੀ ਨੂੰ ਇੱਕ ਕੁੰਜੀ ਅਤੇ ਮੰਗ ਕਰਨ ਵਾਲੇ ਪ੍ਰੋਸੈਸ ਨਾਲ ਜੋੜਦਾ ਹੈ। ਪ੍ਰਮਪਟ ਪ੍ਰੋਸੈਸ ਅਤੇ ਕੁੰਜੀ ਦੀ ਪਛਾਣ ਕਰਦਾ ਹੈ। ਫਿਰ ਵਿਅਕਤੀ ਸੰਰਚਿਤ ਪ੍ਰਮਾਣੀਕਰਨ ਵਿਧੀ ਰਾਹੀਂ ਮੰਗ ਨੂੰ ਮਨਜ਼ੂਰ ਕਰਦਾ ਹੈ।

1Password ਕਈ ਸਹਿਮਤੀ ਸਕੋਪ ਦਸਤਾਵੇਜ਼ੀਕਰਨ ਕਰਦਾ ਹੈ। ਪ੍ਰਤੀ-ਕੁੰਜੀ ਅਤੇ ਪ੍ਰਤੀ-ਐਪਲੀਕੇਸ਼ਨ ਸਹਿਮਤੀ ਡਿਫੌਲਟ ਹੈ। ਟਰਮੀਨਲ-ਸੈਸ਼ਨ ਸਕੋਪ ਸਹਿਮਤੀ ਨੂੰ ਇੱਕ ਟੈਬ ਜਾਂ ਸੈਸ਼ਨ ਤੱਕ ਸੀਮਿਤ ਕਰਦਾ ਹੈ। ਪ੍ਰਤੀ-ਮੰਗ ਸਹਿਮਤੀ ਹਰ ਮੰਗ ਲਈ ਦੁਬਾਰਾ ਪੁੱਛਦੀ ਹੈ। ਇੱਕ ਸਾਰੇ-ਪ੍ਰੋਸੈਸ ਸਹਿਮਤੀ ਵਿਕਲਪ ਮੌਜੂਦ ਹੈ, ਪਰ ਇਹ ਵਿਕਲਪ ਮੌਜੂਦਾ ਓਪਰੇਟਿੰਗ-ਸਿਸਟਮ ਯੂਜ਼ਰ ਹੇਠਾਂ ਹਰ ਪ੍ਰੋਸੈਸ ਨੂੰ ਸੈਸ਼ਨ ਲਈ ਐਕਸੈਸ ਦਿੰਦਾ ਹੈ।

ਕਾਰਜ ਲਈ ਢੁਕਵੀਂ ਸਭ ਤੋਂ ਤੰਗ ਮਨਜ਼ੂਰੀ ਸੀਮਾ ਦੀ ਵਰਤੋਂ ਕਰੋ। ਸਿਸਟਮ-ਪ੍ਰਬੰਧਨ ਏਜੰਟ ਨੂੰ ਇੱਕ ਵਿਸ਼ੇਸ਼ ਟਰਮੀਨਲ ਜਾਂ ਸੈਂਡਬੌਕਸ ਵਿੱਚ ਚਲਾਇਆ ਜਾਣਾ ਚਾਹੀਦਾ ਹੈ। ਜਦੋਂ ਇੱਕ ਟਰਮੀਨਲ ਸੈਸ਼ਨ ਕਾਫ਼ੀ ਹੋਵੇ, ਤਾਂ ਹਰ ਪ੍ਰਕਿਰਿਆ ਨੂੰ ਮਨਜ਼ੂਰ ਨਾ ਕਰੋ।

ਮਨਜ਼ੂਰੀ ਸੈਸ਼ਨ ਇੱਕ ਸਥਾਈ ਅਧਿਕਾਰ ਨਹੀਂ ਹੈ। 1Password ਨਿਰਧਾਰਿਤ ਅਵਧੀ ਲਈ ਜਾਂ ਐਪ ਲਾਕ ਜਾਂ ਬੰਦ ਹੋਣ ਤੱਕ ਅਧਿਕਾਰਤਾ ਦਾ ਰਿਕਾਰਡ ਰੱਖਦਾ ਹੈ। ਜਦੋਂ ਐਪ ਲਾਕ ਹੁੰਦੀ ਹੈ, ਏਜੰਟ ਬਾਅਦ ਵਿੱਚ ਵਰਤੋਂ ਲਈ ਪ੍ਰਾਈਵੇਟ ਕੀ ਨਹੀਂ ਰੱਖਦਾ। ਜਦੋਂ 1Password ਬੰਦ ਹੁੰਦਾ ਹੈ, ਤਾਂ ਸਹਿਯੋਗੀ ਸੈਟਿੰਗ ਸਰਗਰਮ ਹੋਣ ‘ਤੇ SSH ਏਜੰਟ ਪ੍ਰਕਿਰਿਆ ਪਿਛੋਕੜ ਵਿੱਚ ਜਾਰੀ ਰਹਿੰਦੀ ਹੈ, ਪਰ ਇੱਕ ਨਵਾਂ ਸਾਈਨਿੰਗ ਬੇਨਤੀ ਲਈ 1Password ਨੂੰ ਅਨਲਾਕ ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ।

1Password SSH ਸੈਟਅੱਪ ਗਾਈਡ ਆਮ ਪ੍ਰਵਾਹ ਦਿਖਾਉਂਦੀ ਹੈ: ਇੱਕ ਕੀ ਬਣਾਓ ਜਾਂ ਆਏਕਿਤ ਕਰੋ, ਪਬਲਿਕ ਕੀ ਪ੍ਰਕਾਸ਼ਿਤ ਕਰੋ, SSH ਏਜੰਟ ਸਰਗਰਮ ਕਰੋ, SSH ਕਲਾਇੰਟ ਸੰਰਚਿਤ ਕਰੋ, ਇੱਕ SSH ਜਾਂ Git ਕਮਾਂਡ ਚਲਾਓ, ਅਤੇ ਬੇਨਤੀ ਨੂੰ ਮਨਜ਼ੂਰ ਕਰੋ। ਸਹੀ ਸਾਕੇਟ ਪਾਥ ਓਪਰੇਟਿੰਗ ਸਿਸਟਮ ਅਨੁਸਾਰ ਵੱਖਰਾ ਹੁੰਦਾ ਹੈ। ਕਿਸੇ ਹੋਰ ਮਸ਼ੀਨ ਤੋਂ ਪਾਥ ਕਾਪੀ ਕਰਨ ਦੀ ਬਜਾਏ, ਮੌਜੂਦਾ ਪਲੇਟਫਾਰਮ ਨਿਰਦੇਸ਼ਾਂ ਦੀ ਵਰਤੋਂ ਕਰੋ।

ਨਵਾਂ ਸਾਈਨਿੰਗ ਬੇਨਤੀ ਸਫਲ ਹੋਣ ਤੋਂ ਪਹਿਲਾਂ 1Password ਐਪ ਨੂੰ ਅਨਲਾਕ ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ। ਏਜੰਟ ਪ੍ਰਕਿਰਿਆ ਐਪ ਬੰਦ ਹੋਣ ਦੇ ਦੌਰਾਨ ਪਿਛੋਕੜ ਵਿੱਚ ਜਾਰੀ ਰਹਿ ਸਕਦੀ ਹੈ। ਇੱਕ ਲਾਕ ਕੀਤੀ ਐਪ ਸਾਈਨਿੰਗ ਲਈ ਪ੍ਰਾਈਵੇਟ-ਕੀ ਸਮੱਗਰੀ ਨਹੀਂ ਜਾਰੀ ਕਰਦੀ।

ਪਬਲਿਕ ਕੀ ਅਤੇ Bitbucket #

1Password ਕੀ-ਮੈਨੇਜਮੈਂਟ ਗਾਈਡ SSH ਕੀ ਆਈਟਮਾਂ, ਕੀ ਜਨਰੇਸ਼ਨ, ਕੀ ਆਏਕਿਤੀ, ਪਬਲਿਕ ਕੀ, ਫਿੰਗਰਪ੍ਰਿੰਟ, ਅਤੇ ਪ੍ਰਾਈਵੇਟ ਕੀ ਦਾ ਦਸਤਾਵੇਜ਼ੀਕਰਨ ਕਰਦੀ ਹੈ। CLI ਉਦਾਹਰਨ op item create --category ssh ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਇੱਕ SSH ਕੀ ਆਈਟਮ ਬਣਾਉਂਦੀ ਹੈ। 1Password CLI ਇਸ ਉਦਾਹਰਨ ਲਈ ਡਿਫਾਲਟ ਵਜੋਂ Ed25519 ਕੀ ਬਣਾਉਂਦਾ ਹੈ ਅਤੇ ਆਪਣੇ ਆਉਟਪੁੱਟ ਵਿੱਚ ਪ੍ਰਾਈਵੇਟ ਕੀ ਨੂੰ ਲੁਕਾਉਂਦਾ ਹੈ।

Bitbucket Cloud ਨਿਯਮਤ Git ਅਤੇ OpenSSH ਕਮਾਂਡ-ਲਾਈਨ ਵਰਕਫਲੋ ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ। ਇਸਦੀ ਕਮਾਂਡ-ਲਾਈਨ ਗਾਈਡ ਸਥਾਨਕ ਰਿਪੋਜ਼ਿਟਰੀ ਤੋਂ Git ਓਪਰੇਸ਼ਨਾਂ ਦਾ ਵਰਣਨ ਕਰਦੀ ਹੈ। ਇਸਦੀ SSH ਸੰਰਚਨਾ ਗਾਈਡ SSH ਰਿਮੋਟ ਫਾਰਮਾਂ ਅਤੇ ਸਹਿਯੋਗੀ ਪਬਲਿਕ-ਕੀ ਫਾਰਮੈਟਾਂ ਦੀ ਸੂਚੀ ਪੇਸ਼ ਕਰਦੀ ਹੈ।

Bitbucket ਨੂੰ ਪਬਲਿਕ-ਕੀ ਖਪਤਕਾਰ ਵਜੋਂ ਮੰਨੋ। ਮਨਜ਼ੂਰ Bitbucket ਖਾਤਾ ਜਾਂ ਰਿਪੋਜ਼ਿਟਰੀ ਸੈਟਿੰਗ ਰਾਹੀਂ ਪਬਲਿਕ ਕੀ ਜਾਂ ਫਿੰਗਰਪ੍ਰਿੰਟ ਨੂੰ ਰਜਿਸਟਰ ਕਰੋ। ਪ੍ਰਾਈਵੇਟ ਕੀ ਨੂੰ 1Password ਵਿੱਚ ਰੱਖੋ। Git ਕਲਾਇੰਟ SSH ਏਜੰਟ ਨੂੰ ਸਾਈਨ ਕਰਨ ਲਈ ਬੇਨਤੀ ਕਰਦਾ ਹੈ। ਕਲਾਇੰਟ ਕੋਈ ਪ੍ਰਾਈਵੇਟ-ਕੀ ਫਾਈਲ ਨਹੀਂ ਪੜ੍ਹਦਾ।

Bitbucket ਐਕਸੈਸ-ਕੀ ਸੀਮਾ, ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਪਾਥ, ਅਤੇ ਰੀਡ-ਓਨਲੀ Git ਟੈਸਟ ਲਈ, Bitbucket Cloud SSH Keys and Git CLI: Read-Only Access for AI Agents ਵੇਖੋ।

Bitbucket ਦਸਤਾਵੇਜ਼ਾਂ ਇਸਨੂੰ Git CLI ਵਰਕਫਲੋ ਕਹਿੰਦੀਆਂ ਹਨ। ਇਹ ਲੇਖ ਕਿਸੇ ਵੱਖਰੇ Bitbucket MCP ਸਰਵਰ ਜਾਂ Bitbucket CLI ਨਾਮੀ ਉਤਪਾਦ ਦੀ ਧਾਰਨਾ ਨਹੀਂ ਕਰਦਾ। Bitbucket-ਵਿਸ਼ੇਸ਼ CLI ਨੂੰ ਆਪਣੀ ਮੌਜੂਦਾ ਦਸਤਾਵੇਜ਼ਾਂ ਅਤੇ ਆਪਣੀ ਆਪਣੀ ਅਧਿਕਾਰ ਸਮੀਖਿਆ ਦੀ ਲੋੜ ਹੁੰਦੀ ਹੈ।

ਏਜੰਟ ਅਤੇ MCP ਸੀਮਾ #

ਨਵੇਂ ਸਰਵਰ ਦੀ ਸਮੀਖਿਆ ਕਰਦੇ ਸਮੇਂ ਵਰਤਮਾਨ MCP ਨਿਰਦੇਸ਼ ਦੀ ਵਰਤੋਂ ਕਰੋ।

MCP ਇੱਕ LLM ਐਪਲੀਕੇਸ਼ਨ, ਇੱਕ ਕਲਾਇੰਟ ਕਨੈਕਟਰ, ਅਤੇ ਇੱਕ ਸਰਵਰ ਦੇ ਵਿਚਕਾਰ ਸੰਪਰਕਾਂ ਨੂੰ ਮਿਆਰੀ ਬਣਾਉਂਦਾ ਹੈ। ਇੱਕ ਸਰਵਰ ਟੂਲ, ਸਰੋਤ, ਜਾਂ ਪ੍ਰਮਪਟ ਪੇਸ਼ ਕਰਦਾ ਹੈ। ਨਿਰਦੇਸ਼ ਵਿੱਚ ਇਹ ਵੀ ਕਿਹਾ ਗਿਆ ਹੈ ਕਿ ਹੋਸਟਾਂ ਨੂੰ ਡਾਟਾ ਪ੍ਰਗਟ ਕਰਨ ਜਾਂ ਟੂਲਾਂ ਨੂੰ ਸਰਗਰਮ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਯੂਜ਼ਰ ਦੀ ਸਹਿਮਤੀ ਲੈਣੀ ਚਾਹੀਦੀ ਹੈ।

MCP ਖੁਦ ਕੋਈ ਅਧਿਕਾਰ ਨਹੀਂ ਦਿੰਦਾ। ਇੱਕ MCP ਟੂਲ ਅਜੇ ਵੀ ਆਪਣੇ ਸਰਵਰ ਪ੍ਰੋਸੈਸ, ਓਪਰੇਟਿੰਗ-ਸਿਸਟਮ ਯੂਜ਼ਰ, ਨੈੱਟਵਰਕ ਪਾਥ, ਕਲਾਉਡ ਖਾਤੇ, ਅਤੇ ਸੰਰਚਿਤ ਕ੍ਰੈਡੈਂਸ਼ਲ ਦੇ ਅਧਿਕਾਰਾਂ ਦੇ ਅੰਦਰ ਚਲਦਾ ਹੈ। ਇੱਕ ਟੂਲ ਵਰਣਨ ਇੱਕ ਅਧਿਕਾਰੀਤਾ ਨੀਤੀ ਨਹੀਂ ਹੈ।

  • ਯੋਜਨਾ ਟੂਲ: ਕਮਾਂਡ ਨੂੰ ਚਲਾਉਣ ਤੋਂ ਪਹਿਲਾਂ ਇੱਕ ਕਮਾਂਡ ਜਾਂ ਬਦਲਾਅ ਰਿਕਾਰਡ ਤਿਆਰ ਕਰੋ।
  • ਮਨਜ਼ੂਰੀ ਟੂਲ: ਦੂਰ-ਸਥਿਤ ਲਿਖਾਈ ਤੋਂ ਪਹਿਲਾਂ ਇੱਕ ਮਨੁੱਖੀ ਫੈਸਲੇ ਦੀ ਮੰਗ ਕਰੋ।
  • ਲਿਖਣ ਦੇ ਟੂਲ: ਜਦੋਂ ਤੱਕ ਟਾਰਗੇਟ, ਕਮਾਂਡ, ਸਕੋਪ, ਅਤੇ ਰੋਲਬੈਕ ਯੋਜਨਾ ਸਪਸ਼ਟ ਨਹੀਂ ਹੁੰਦੀ, ਤਦ ਤੱਕ ਇਨ੍ਹਾਂ ਨੂੰ ਅਸਮਰੱਥ ਰੱਖੋ।

ਏਜੰਟ ਨੂੰ ਹਵਾਲੇ, ਮੈਟਾਡਾਟਾ, ਅਤੇ ਓਪਰੇਸ਼ਨ ਨਤੀਜੇ ਮਿਲਣੇ ਚਾਹੀਦੇ ਹਨ। ਏਜੰਟ ਨੂੰ ਪ੍ਰਾਈਵੇਟ-ਕੀ ਟੈਕਸਟ, ਵਾਲਟ-ਵਾਈਡ ਆਈਟਮ ਡੰਪ, ਜਾਂ ਅਸੀਮਿਤ ਸ਼ੈੱਲ ਨਹੀਂ ਮਿਲਣਾ ਚਾਹੀਦਾ।

ਇੱਕ ਸੁਰੱਖਿਅਤ ਪਹਿਲੀ ਨੀਤੀ #

ਇੱਕ ਏਜੰਟ ਨੂੰ ਸਰਗਰਮ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਇੱਕ ਲਿਖਤੀ ਨੀਤੀ ਨਾਲ ਸ਼ੁਰੂਆਤ ਕਰੋ। ਨੀਤੀ ਨੂੰ MCP ਸੰਰਚਨਾ ਦੇ ਨੇੜੇ ਰੱਖੋ, ਪਰ ਫਾਈਲ ਵਿੱਚ ਕ੍ਰੈਡੈਂਸ਼ਲ ਨਾ ਰੱਖੋ।

agent_policy:
  purpose: "Read-only repository and system inspection"
  identities:
    interactive_ssh: "1Password SSH Agent with per-terminal consent"
    unattended_jobs: "Dedicated service account with one narrow vault"
  allowed:
    - "Read repository metadata through Git"
    - "Read approved service status and logs"
    - "Run one synthetic SSH connectivity check"
  approval_required:
    - "Any remote write"
    - "Any package, firewall, clock, or service change"
    - "Any new host-key acceptance"
    - "Any private-key export"
  denied:
    - "Read or print private-key fields"
    - "List every vault or every item"
    - "Write tokens or secrets to shell profiles"
    - "Run arbitrary commands from tool output"
  rollback:
    - "Revoke the service account"
    - "Remove the public key from the target"
    - "Disable the MCP server entry"
    - "Lock 1Password and end the agent session"

ਇਹ ਨੀਤੀ ਇੱਕ ਉਦਾਹਰਣ ਹੈ, 1Password ਸੰਰਚਨਾ ਫਾਰਮੈਟ ਨਹੀਂ। ਅਸਲ ਨੀਤੀ ਨੂੰ ਉਸ ਕੰਟਰੋਲ ਪਲੇਨ ਵਿੱਚ ਸੰਭਾਲੋ ਜਿਸ ਦੀ ਵਰਤੋਂ ਤੁਹਾਡੇ ਏਜੰਟ ਕਲਾਇੰਟ ਦੁਆਰਾ ਕੀਤੀ ਜਾਂਦੀ ਹੈ। ਹਰ ਟੂਲ ਨੂੰ ਸਰਗਰਮ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਨੀਤੀ ਦੇ ਵਿਰੁੱਧ ਹਰ ਟੂਲ ਦੀ ਸਮੀਖਿਆ ਕਰੋ।

ਸਰਵਿਸ ਖਾਤੇ ਅਤੇ ਸੀਕ੍ਰੇਟ ਹਵਾਲੇ #

ਇੱਕ ਸਰਵਿਸ ਖਾਤਾ ਇੱਕ ਆਟੋਮੇਟਿਡ ਪ੍ਰੋਸੈਸ ਨੂੰ ਉਸਦੀ ਆਪਣੀ ਪਛਾਣ ਦਿੰਦਾ ਹੈ। 1Password CLI ਸਕ੍ਰਿਪਟ ਗਾਈਡ ਚੁਣੇ ਹੋਏ ਵਾਲਟਾਂ ਲਈ ਘੱਟ-ਅਧਿਕਾਰ ਪਹੁੰਚ ਲਈ ਸਰਵਿਸ ਖਾਤਿਆਂ ਦੀ ਸਿਫਾਰਸ਼ ਕਰਦੀ ਹੈ। ਇਹ ਇੱਕ ਅਗਾਜ਼ ਜੌਬ ਨੂੰ ਇੱਕ ਵਿਅਕਤੀ ਦੇ SSO, MFA, ਵਾਲਟ ਇੰਵੈਂਟਰੀ, ਅਤੇ ਰੋਜ਼ਾਨਾ ਖਾਤੇ ਤੋਂ ਵੱਖ ਕਰਦਾ ਹੈ।

A secret reference (ਗੁਪਤ ਹਵਾਲਾ) ਕਿਸੇ ਮੁੱਲ ਦਾ ਨਾਮ ਦਿੰਦਾ ਹੈ, ਬਿਨਾਂ ਕਿਸੇ ਸਰੋਤ ਵਿੱਚ ਮੁੱਲ ਨੂੰ ਰੱਖੇ। 1Password CLI reference op://vault/item/field ਰੂਪ ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ। ਹਵਾਲਾ ਸਿਰਫ਼ ਉਦੋਂ ਸੁਰੱਖਿਅਤ ਹੈ ਜਦੋਂ ਘੇਰੇ ਵਾਲਾ ਪ੍ਰਕਿਰਿਆ (process) ਅਜੇ ਵੀ ਸੰਕੁਚਤ ਪਹੁੰਚ ਰੱਖਦਾ ਹੈ। ਇੱਕ ਹਵਾਲਾ ਨੀਤੀ ਨੂੰ ਚੁਰਾ ਨਹੀਂ ਸਕਦਾ।

ਜਦੋਂ ਇੱਕ ਕਮਾਂਡ ਨੂੰ ਇੱਕ ਮੁੱਲ ਦੀ ਲੋੜ ਹੋਵੇ, ਤਾਂ op read ਦੀ ਵਰਤੋਂ ਕਰੋ। ਜਦੋਂ ਇੱਕ ਬੱਚੇ ਪ੍ਰਕਿਰਿਆ (child process) ਨੂੰ ਕੰਟਰੋਲ ਕੀਤੇ ਗਏ ਰਨਟਾਈਮ ਮੁੱਲਾਂ ਦੇ ਸੈੱਟ ਦੀ ਲੋੜ ਹੋਵੇ, ਤਾਂ op run ਦੀ ਵਰਤੋਂ ਕਰੋ। ਜਦੋਂ ਇੱਕ ਨਵਾਂ SSH Key ਆਈਟਮ ਨੂੰ ਮਨਜ਼ੂਰ ਕੀਤੇ ਗਏ ਵਾਲਟ ਵਿੱਚ ਮੌਜੂਦ ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ, ਤਾਂ op item create ਦੀ ਵਰਤੋਂ ਕਰੋ।

ਰਨਟਾਈਮ ਇੰਜੈਕਸ਼ਨ ਨੂੰ ਪ੍ਰਾਈਵੇਟ-ਕੀ ਸੁਰੱਖਿਆ ਨਾਲ ਗੜਬੜ ਨਾ ਕਰੋ। ਇੱਕ API ਟੋਕਨ ਜੋ ਇੱਕ ਐਨਵਾਇਰਨਮੈਂਟ ਵੇਰੀਏਬਲ ਵਜੋਂ ਪਾਸ ਕੀਤਾ ਜਾਂਦਾ ਹੈ, ਉਹ ਅਜੇ ਵੀ ਬੱਚੇ ਪ੍ਰਕਿਰਿਆ ਲਈ ਦਿਖਾਈ ਦਿੰਦਾ ਹੈ। ਇੱਕ ਪ੍ਰਾਈਵੇਟ ਕੀ ਨੂੰ ਇੱਕ ਐਨਵਾਇਰਨਮੈਂਟ ਵੇਰੀਏਬਲ ਰਾਹੀਂ ਪਾਸ ਕਰਨਾ ਹੋਰ ਖ਼ਤਰਨਾਕ ਹੈ ਕਿਉਂਕਿ ਮੁੱਲ ਪ੍ਰਕਿਰਿਆ ਜਾਂਚ, ਕਰੈਸ਼ ਰਿਪੋਰਟਾਂ, ਡਿਬੱਗ ਆਉਟਪੁੱਟ, ਸ਼ੈੱਲ ਟਰੇਸਿੰਗ, ਅਤੇ ਗ਼ਲਤੀ ਨਾਲ ਲੌਗਿੰਗ ਵਿੱਚ ਖੁੱਲ੍ਹਣ ਨੂੰ ਵਧਾਉਂਦਾ ਹੈ।

ਸਰੋਤ ਵਿੱਚ ਇੱਕ ਹਵਾਲੇ ਅਤੇ ਸੰਭਵ ਤੌਰ ‘ਤੇ ਸਭ ਤੋਂ ਛੋਟੀ ਪ੍ਰਕਿਰਿਆ ਵਿੱਚ ਇੱਕ ਰਨਟਾਈਮ ਮੁੱਲ ਨੂੰ ਤਰਜੀਹ ਦਿਓ। ਪ੍ਰਕਿਰਿਆ ਨੂੰ ਛੋਟੀ-ਮੁੱਟ ਰੱਖੋ। ਸ਼ੈੱਲ ਟਰੇਸਿੰਗ ਨੂੰ ਅਸਮਰਥ ਬਣਾਓ। ਐਨਵਾਇਰਨਮੈਂਟ ਨੂੰ ਪ੍ਰਿੰਟ ਨਾ ਕਰੋ। ਇੱਕ ਅਸਫਲ ਚਾਲ ਤੋਂ ਬਾਅਦ ਅਸਥਾਈ ਫਾਈਲਾਂ ਨੂੰ ਹਟਾਓ।

ਸੁਰੱਖਿਅਤ ਪਹਿਲਾ ਵਰਕਫਲੋ #

ਹੇਠਾਂ ਦਿੱਤੀ ਕ੍ਰਮਵਾਰਤਾ ਪਬਲਿਕ-ਕੀ ਰਜਿਸਟ੍ਰੇਸ਼ਨ, ਇੰਟਰਐਕਟਿਵ SSH, MCP ਖੋਜ, ਅਤੇ ਅਣਗੌਹਤ ਡਿਜ਼ਾਈਨ ਨੂੰ ਵੱਖ ਕਰਦੀ ਹੈ।

1. ਟਾਰਗੇਟ ਨੂੰ ਪਰਿਭਾਸ਼ਿਤ ਕਰੋ #

ਟਾਰਗੇਟ ਕਲਾਸ, ਰਿਮੋਟ ਖਾਤਾ, ਨਿਰਧਾਰਤ ਰਿਪੋਜ਼ਿਟਰੀ ਜਾਂ ਕਮਾਂਡ, ਹੋਸਟ-ਕੀ ਸਰੋਤ, ਮਨਜ਼ੂਰੀ ਮਾਲਕ, ਅਤੇ ਰੋਲਬੈਕ ਕਾਰਵਾਈ ਲਿਖੋ। ਪਹਿਲੀ ਅਭਿਆਸ ਦੌਰਾਨ ਇੱਕ ਸਿੰਥੈਟਿਕ ਰਿਕਾਰਡ ਦੀ ਵਰਤੋਂ ਕਰੋ।

target_class: test-repository
remote_account: git
operation: read-only connectivity check
host_key_source: approved administrator record
approval_owner: named operator
rollback: remove public key and revoke test identity

ਅਨੁਮਾਨਿਤ ਨਤੀਜਾ, ਅਜ਼ਮਾਇਸ਼-ਹੀਣ: ਰਿਕਾਰਡ ਇੱਕ ਟਾਰਗੇਟ ਅਤੇ ਇੱਕ ਕਾਰਵਾਈ ਦੀ ਪਛਾਣ ਕਰਦਾ ਹੈ। ਰਿਕਾਰਡ ਵਿੱਚ ਕੋਈ ਹੋਸਟਨੇਮ, IP ਪਤਾ, ਟੋਕਨ, ਪ੍ਰਾਈਵੇਟ ਕੀ, ਜਾਂ ਨਿੱਜੀ ਡਾਟਾ ਨਹੀਂ ਹੁੰਦਾ।

2. SSH Key ਆਈਟਮ ਬਣਾਓ ਜਾਂ ਚੁਣੋ #

ਆਧਿਕਾਰਿਕ 1Password SSH key guide CLI ਸਿਰਜਣਾ ਪੈਟਰਨ ਦਾ ਦਸਤਾਵੇਜ਼ੀਕਰਨ ਕਰਦਾ ਹੈ। ਹੇਠਾਂ ਦਿੱਤੀ ਕਮਾਂਡ ਇੱਕ ਸਿੰਥੈਟਿਕ ਸਿਰਲੇਖ ਅਤੇ ਨਾਮ-ਸੰਕੇਤਿਤ ਟੈਸਟ ਵਾਲਟ ਦੀ ਵਰਤੋਂ ਕਰਦੀ ਹੈ।

op item create --category ssh --ssh-generate-key=ed25519 --vault "synthetic-test-vault" --title "synthetic-agent-admin-key"

ਅਨੁਮਾਨਿਤ ਆਉਟਪੁੱਟ, ਅਜ਼ਮਾਇਸ਼-ਹੀਣ: 1Password ਨਾਮ-ਸੰਕੇਤਿਤ ਟੈਸਟ ਵਾਲਟ ਵਿੱਚ ਇੱਕ SSH Key ਆਈਟਮ ਬਣਾਉਂਦਾ ਹੈ ਅਤੇ ਟਰਮੀਨਲ ਆਉਟਪੁੱਟ ਵਿੱਚ ਪ੍ਰਾਈਵੇਟ ਕੀ ਨੂੰ ਲੁਕਾਉਂਦਾ ਹੈ। ਕਮਾਂਡ 1Password ਸਥਿਤੀ ਨੂੰ ਬਦਲਦੀ ਹੈ। ਸਹੀ ਮਨੁੱਖੀ-ਪੜ੍ਹਨਯੋਗ ਆਉਟਪੁੱਟ CLI ਵਰਜਨ ਅਤੇ ਸਾਈਨ-ਇਨ ਸਥਿਤੀ ‘ਤੇ ਨਿਰਭਰ ਕਰਦਾ ਹੈ।

ਪ੍ਰਾਈਵੇਟ-ਕੀ ਫੀਲਡ ਨੂੰ ਕਾਪੀ ਕਰਨ ਤੋਂ ਬਿਨਾਂ ਵਾਪਸ ਕੀਤੇ ਗਏ ਆਈਟਮ ਪਛਾਣਕਰਤਾ ਨੂੰ ਟੈਸਟ ਰਿਕਾਰਡ ਵਿੱਚ ਰੱਖੋ। ਆਈਟਮ ਸਕੀਮਾ ਦੀ ਪੁਸ਼ਟੀ ਹੋਣ ਤੋਂ ਬਾਅਦ ਹੀ ਬਾਅਦ ਵਿੱਚ ਫੀਲਡ-ਵਿਸ਼ੇਸ਼ ਪੜ੍ਹਾਈਆਂ ਲਈ ਪਛਾਣਕਰਤਾ ਜਾਂ ਸਹੀ ਆਈਟਮ ਸਿਰਲੇਖ ਦੀ ਵਰਤੋਂ ਕਰੋ।

ਇਸ ਆਉਟਪੁੱਟ ਨੂੰ ਕਿਸੇ ਸਾਂਝੇ ਲੌਗ ਵਿੱਚ ਰੀਡਾਇਰੈਕਟ ਨਾ ਕਰੋ। ਸਿਰਫ਼ ਆਈਟਮ ਪਛਾਣਕਰਤਾ, ਪਬਲਿਕ-ਕੀ ਫਿੰਗਰਪ੍ਰਿੰਟ, ਅਤੇ ਮਨਜ਼ੂਰੀ ਰਿਕਾਰਡ ਨੂੰ ਰੱਖੋ ਜਦੋਂ ਸਥਾਨਕ ਪ੍ਰਕਿਰਿਆ ਸੁਰੱਖਿਅਤ ਢਾਂਚਾਗਤ ਆਉਟਪੁੱਟ ਦਾ ਸਮਰਥਨ ਕਰਦੀ ਹੈ।

3. ਪਬਲਿਕ ਕੀ ਨੂੰ ਸੰਭਾਲੋ #

1Password ਵਿੱਚ SSH Key ਆਈਟਮ ਖੋਲ੍ਹੋ ਅਤੇ ਇਸਦੇ Copy Public Key ਕਾਰਜ ਦੀ ਵਰਤੋਂ ਕਰੋ। ਸਿਰਫ਼ ਤਾਂ ਹੀ ਫੀਲਡ-ਵਿਸ਼ੇਸ਼ ਰੈਫਰੈਂਸ ਦੀ ਵਰਤੋਂ ਕਰੋ ਜਦੋਂ ਤੁਸੀਂ ਆਪਣੇ ਖਾਤੇ ਵਿੱਚ ਪਬਲਿਕ-ਕੀ ਫੀਲਡ ਲੇਬਲ ਦੀ ਪੁਸ਼ਟੀ ਕਰ ਲੈਂਦੇ ਹੋ। ਪੂਰੀ ਆਈਟਮ ਨੂੰ ਡੰਪ ਨਾ ਕਰੋ।

PUBLIC_KEY_REF="op://synthetic-test-vault/synthetic-agent-admin-key/synthetic-public-key-field"
op read "$PUBLIC_KEY_REF"

ਅਨੁਮਾਨਿਤ ਆਉਟਪੁੱਟ, ਅਜ਼ਮਾਇਸ਼ ਨਹੀਂ ਕੀਤਾ ਗਿਆ: ਇੱਕ ਸਿੰਥੈਟਿਕ OpenSSH ਪਬਲਿਕ-ਕੀ ਲਾਈਨ ਜਾਂ ਪੁਸ਼ਟੀ ਕੀਤੇ ਫੀਲਡ ਤੋਂ ਪਬਲਿਕ-ਕੀ ਮੁੱਲ। ਉੱਪਰ ਦਿੱਤਾ ਗਿਆ ਪਲੇਸਹੋਲਡਰ ਫੀਲਡ ਨਾਮ ਤੁਹਾਡੀ ਆਈਟਮ ਦੇ ਫੀਲਡ ਲੇਬਲ ਬਾਰੇ ਕੋਈ ਵਾਅਦਾ ਨਹੀਂ ਹੈ।

ਪਬਲਿਕ ਕੀ ਨੂੰ ਮਨਜ਼ੂਰ Bitbucket ਖਾਤੇ, Bitbucket ਰਿਪੋਜ਼ਿਟਰੀ, ਜਾਂ ਰਿਮੋਟ ਖਾਤੇ ਵਿੱਚ ਰਜਿਸਟਰ ਕਰੋ। ਕਦੇ ਵੀ ਮੇਲਦਾ ਮਿਲਦਾ ਪ੍ਰਾਈਵੇਟ ਕੀ Bitbucket ਵਿੱਚ ਪੇਸਟ ਨਾ ਕਰੋ। Bitbucket SSH ਗਾਈਡ ਵੀ ਪਹਿਲੀ ਕਨੈਕਸ਼ਨ ਤੋਂ ਪਹਿਲਾਂ Bitbucket ਹੋਸਟ ਕੀ ਦਰਜ ਕਰਨ ਦੀ ਸਿਫ਼ਾਰਸ਼ ਕਰਦਾ ਹੈ।

Bitbucket ਲਈ, ਪ੍ਰਕਾਸ਼ਿਤ ਹੋਸਟ-ਕੀ ਰਿਕਾਰਡ ਪ੍ਰਾਪਤ ਕਰੋ ਅਤੇ ਕਿਸੇ ਸੁਰੱਖਿਅਤ ਸੁਰੱਖਿਅਤ ਕਾਪੀ ਨਾਲ ਰਿਕਾਰਡ ਦੀ ਤੁਲਨਾ ਕਰੋ, ਫਿਰ ~/.ssh/known_hosts ਵਿੱਚ ਇੱਕ ਲਾਈਨ ਸ਼ਾਮਲ ਕਰੋ। ਤੁਲਨਾ ਪਾਸ ਹੋਣ ਤੋਂ ਬਾਅਦ ਸਖ਼ਤ ਹੋਸਟ ਚੈਕਿੰਗ ਦੀ ਵਰਤੋਂ ਕਰੋ। ਏਜੰਟ ਚਾਲੂ ਹੋਣ ਦੌਰਾਨ ਬਦਲੇ ਹੋਏ ਹੋਸਟ ਕੀ ਨੂੰ ਸਵੀਕਾਰ ਨਾ ਕਰੋ।

4. ਇੰਟਰਐਕਟਿਵ SSH ਸਰਗਰਮ ਕਰੋ #

ਡੈਸਕਟਾਪ ਐਪ ਵਿੱਚ 1Password SSH Agent ਨੂੰ ਚਾਲੂ ਕਰੋ। ਪਲੇਟਫਾਰਮ-ਵਿਸ਼ੇਸ਼ IdentityAgent ਜਾਂ SSH_AUTH_SOCK ਮੁੱਲ ਨਾਲ OpenSSH ਦੀ ਸੰਰਚਨਾ ਕਰੋ, ਜਿਵੇਂ ਕਿ ਅਧਿਕਾਰਤ ਸੈਟਅਪ ਗਾਈਡ ਵਿੱਚ ਦਰਸਾਇਆ ਗਿਆ ਹੈ। ਪਹਿਲੀ ਜਾਂਚ ਨੂੰ ਇੱਕ ਰਿਪੋਜ਼ਿਟਰੀ ਜਾਂ ਇੱਕ ਗੈਰ-ਉਤਪਾਦਨ ਖਾਤੇ ਤੱਕ ਸੀਮਿਤ ਰੱਖੋ।

macOS ਜਾਂ Linux ‘ਤੇ, ਪਲੇਟਫਾਰਮ ਸੈਟਅਪ ਗਾਈਡ ਤੋਂ ਸਾਕੇਟ ਸੈੱਟ ਕਰੋ ਅਤੇ ssh-add -l ਚਲਾਓ। Windows ‘ਤੇ, ਸਮਰਥਿਤ ਨਾਮ-ਪਾਈਪ ਸੰਰਚਨਾ ਦੀ ਵਰਤੋਂ ਕਰੋ ਅਤੇ 1Password SSH Agent ਇੰਟਰਫੇਸ ਜਾਂ ਦਸਤਾਵੇਜ਼ਬੰਦ Windows SSH ਟੈਸਟ ਰਾਹੀਂ ਉਪਲਬਧ ਕੀਆਂ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ। ssh-add -l ਨੂੰ ਕ੍ਰਾਸ-ਪਲੇਟਫਾਰਮ ਪੁਸ਼ਟੀ ਕਮਾਂਡ ਵਜੋਂ ਪੇਸ਼ ਨਾ ਕਰੋ।

ਸਿਰਫ਼ macOS ਜਾਂ Linux ‘ਤੇ:

ssh-add -l
git ls-remote "<repository-ssh-url>" HEAD

ਅਨੁਮਾਨਿਤ ਆਉਟਪੁੱਟ, ਅਜ਼ਮਾਇਸ਼ ਨਹੀਂ ਕੀਤਾ ਗਿਆ: macOS ਜਾਂ Linux ‘ਤੇ, ssh-add -l ਸਰਗਰਮ ਏਜੰਟ ਤੋਂ ਫਿੰਗਰਪ੍ਰਿੰਟਸ ਦੀ ਸੂਚੀ ਦਿੰਦਾ ਹੈ। Windows ‘ਤੇ, ਦਸਤਾਵੇਜ਼ਬੰਦ ਨਾਮ-ਪਾਈਪ ਟੈਸਟ ਜਾਂ 1Password SSH Agent ਇੰਟਰਫੇਸ ਦੀ ਵਰਤੋਂ ਕਰੋ। ਸਫਲ Git ਪੜ੍ਹਾਈ ਇੱਕ ਕਮਿਟ ਰੈਫਰੈਂਸ ਵਾਪਸ ਕਰਦੀ ਹੈ। ਉੱਪਰ ਦਿੱਤਾ ਗਿਆ ਰਿਪੋਜ਼ਿਟਰੀ ਪਲੇਸਹੋਲਡਰ ਨੂੰ ਇੱਕ ਨਿਯੰਤ੍ਰਿਤ ਟੈਸਟ ਵਿੱਚ ਬਦਲਣ ਦੀ ਲੋੜ ਹੈ।

ਕਮਾਂਡ ਇੱਕ ਰਿਪੋਜ਼ਿਟਰੀ ਪਲੇਸਹੋਲਡਰ ਦੀ ਵਰਤੋਂ ਕਰਦੀ ਹੈ। ਪਲੇਸਹੋਲਡਰ ਨੂੰ ਸਿਰਫ਼ ਇੱਕ ਨਿਯੰਤ੍ਰਿਤ ਟੈਸਟ ਵਿੱਚ ਬਦਲੋ। ਜਿਸ ਟਾਰਗੇਟ ਜਾਂ ਪ੍ਰੋਸੈਸ ਲਈ ਤੁਸੀਂ ਉਮੀਦ ਨਹੀਂ ਕਰਦੇ, ਉਸਦੇ ਪ੍ਰੋਂਪਟ ਨੂੰ ਮਨਜ਼ੂਰ ਨਾ ਕਰੋ।

5. SSH ਪਾਥ ਕੰਮ ਕਰਨ ਤੋਂ ਬਾਅਦ MCP ਸ਼ਾਮਲ ਕਰੋ #

ਸਭ ਤੋਂ ਪਹਿਲਾਂ MCP ਤੋਂ ਬਿਨਾਂ SSH ਕਲਾਇੰਟ ਅਤੇ ਟਾਰਗੇਟ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ। ਫਿਰ ਇੱਕ ਰੀਡ-ਓਨਲੀ MCP ਸਰਵਰ ਜਾਂ ਲੋਕਲ ਕਨੈਕਟਰ ਸ਼ਾਮਲ ਕਰੋ। ਏਜੰਟ ਨੂੰ read_status ਜਾਂ prepare_command ਵਰਗਾ ਟੂਲ ਦਿਓ। ਇੱਕ ਆਮ ਸ਼ੈਲ ਟੂਲ ਨਾਲ ਸ਼ੁਰੂਆਤ ਨਾ ਕਰੋ।

MCP ਸੰਰਚਨਾ ਨੂੰ ਕਲਾਇੰਟ ਦੁਆਰਾ ਸਮਰਥਿਤ ਵਾਤਾਵਰਣ ਮਕੈਨਿਜ਼ਮ ਰਾਹੀਂ ਰਨਟਾਈਮ ਮੁੱਲਾਂ ਦਾ ਹਵਾਲਾ ਦੇਣਾ ਚਾਹੀਦਾ ਹੈ। 1Password AI ਸੁਰੱਖਿਆ ਗਾਈਡ ਵਿੱਚ 1Password ਤੋਂ ਲੋਡ ਕੀਤੇ ਗਏ ਵਾਤਾਵਰਣ ਚਲਾਨਾਂ (environment variables) ਨਾਲ ਪਲੇਨਟੈਕਸਟ MCP ਸੰਰਚਨਾ ਟੋਕਨਾਂ ਨੂੰ ਬਦਲਣ ਦਾ ਵਰਣਨ ਕੀਤਾ ਗਿਆ ਹੈ। ਸੰਰਚਨਾ ਵਿੱਚ ਹਵਾਲਾ ਜਾਂ ਚਲਾਨ ਨਾਮ ਨੂੰ ਬਰਕਰਾਰ ਰੱਖੋ। ਐਜੰਟ ਟ੍ਰਾਂਸਕ੍ਰਿਪਟ ਵਿੱਚ ਹੱਲ ਕੀਤਾ ਗਿਆ ਮੁੱਲ ਨੂੰ ਬਾਹਰ ਰੱਖੋ।

ਇਹ ਖੰਡ ਇੱਕ ਡਿਜ਼ਾਈਨ ਦਾ ਵਰਣਨ ਕਰਦਾ ਹੈ, ਨਾ ਕਿ ਕਿਸੇ ਪਰੀਖਿਤ MCP ਸੰਰਚਨਾ ਦਾ। ਇੱਥੇ ਕੋਈ ਕਲਾਇੰਟ, ਸਰਵਰ, ਟ੍ਰਾਂਸਪੋਰਟ, ਵਰਜਨ, ਜਾਂ ਫਿਕਸਚਰ ਨਿਰਧਾਰਤ (pinned) ਨਹੀਂ ਹੈ। ਕਿਸੇ ਏਜੰਟ ਨੂੰ ਪ੍ਰੋਡਕਸ਼ਨ ਸਿਸਟਮ ਨਾਲ ਜੋੜਨ ਤੋਂ ਪਹਿਲਾਂ, ਇੱਕ ਵੱਖਰੇ ਟੈਸਟ ਪ੍ਰੋਫਾਈਲ ਵਿੱਚ ਇੱਕ ਰੀਡ-ਓਨਲੀ ਸਰਵਰ ਦੀ ਪ੍ਰਮਾਣਿਕਤਾ ਪ੍ਰਾਪਤ ਕਰੋ।

6. ਨਤੀਜਾ ਰਿਕਾਰਡ ਕਰੋ #

ਟਾਰਗੇਟ ਕਲਾਸ, ਟੂਲ ਦਾ ਨਾਮ, ਮਨਜ਼ੂਰੀ ਫੈਸਲਾ, ਪਬਲਿਕ-ਕੀ ਫਿੰਗਰਪ੍ਰਿੰਟ, ਕਮਾਂਡ ਨਤੀਜਾ, ਅਤੇ ਸਫ਼ਾਈ ਨਤੀਜਾ ਰਿਕਾਰਡ ਕਰੋ। ਗੁਪਤ ਮੁੱਲਾਂ ਨੂੰ ਛੱਡੋ। ਹਰ ਆਉਟਪੁੱਟ ਨੂੰ ਦੇਖਿਆ ਗਿਆ ਜਾਂ ਅਨੁਮਾਨਿਤ ਵਜੋਂ ਨਿਸ਼ਾਨਤ ਕਰੋ।

ਅਨੁਮਾਨਿਤ ਨਤੀਜਾ, ਅਜ਼ਮਾਇਆ ਨਹੀਂ: ਏਜੰਟ ਸਟੇਟਸ ਪੜ੍ਹਦਾ ਹੈ, ਇੱਕ ਸੀਮਿਤ ਕਮਾਂਡ ਦਾ ਪ੍ਰਸਤਾਵ ਪੇਸ਼ ਕਰਦਾ ਹੈ, SSH ਬੇਨਤੀ ਲਈ ਸਪਸ਼ਟ ਮਨਜ਼ੂਰੀ ਪ੍ਰਾਪਤ ਕਰਦਾ ਹੈ, ਰੀਡ-ਓਨਲੀ ਕਾਰਵਾਈ ਨੂੰ ਪੂਰਾ ਕਰਦਾ ਹੈ, ਅਤੇ ਪ੍ਰਾਈਵੇਟ-ਕੀ ਟੈਕਸਟ ਤੋਂ ਬਿਨਾਂ ਇੱਕ ਰਿਕਾਰਡ ਪੈਦਾ ਕਰਦਾ ਹੈ।

ਸਿੰਥੈਟਿਕ ਕਮਾਂਡ ਕ੍ਰਮ #

ਹੇਠਾਂ ਦਿੱਤਾ ਗਿਆ ਕ੍ਰਮ ਅਸਲ ਇਨਫਰਾਸਟ੍ਰਕਚਰ ਦੀ ਵਰਤੋਂ ਕੀਤੇ ਬਿਨਾਂ ਕ੍ਰਮ ਦਾ ਪ੍ਰਦਰਸ਼ਨ ਕਰਦਾ ਹੈ। ਇਹ ਕਮਾਂਡ ਸਿਰਫ਼ ਉਦਾਹਰਨਾਂ ਹਨ। ਇਹਨਾਂ ਨੂੰ ਲੇਖ ਦੀ ਤਿਆਰੀ ਦੌਰਾਨ ਚਲਾਇਆ ਨਹੀਂ ਗਿਆ ਸੀ।

op --version
op item create --category ssh --ssh-generate-key=ed25519 --vault "synthetic-test-vault" --title "synthetic-agent-admin-key"
op read "op://synthetic-test-vault/synthetic-agent-admin-key/synthetic-public-key-field"
# macOS or Linux only
ssh-add -l
git ls-remote "<repository-ssh-url>" HEAD

ਅਨੁਮਾਨਿਤ ਆਉਟਪੁੱਟ, ਅਜ਼ਮਾਇਆ ਨਹੀਂ:

2.x.y
SSH Key item created. Private key: redacted
ssh-ed25519 AAAA<synthetic-public-key> synthetic-key-label
256 SHA256:<synthetic-fingerprint> synthetic-agent-admin-key (ED25519)
<synthetic-commit-id>        HEAD

ਆਉਟਪੁੱਟ ਬਲਾਕ ਵਿਆਖਿਆਤਮਕ ਹੈ। ਇਹ ਬਲਾਕ 1Password ਖਾਤੇ, Bitbucket, Git ਪ੍ਰੋਵਾਈਡਰ, ਜਾਂ ਰਿਮੋਟ ਹੋਸਟ ਦੇ ਵਿਰੁੱਧ ਕਿਸੇ ਚਾਲੂ ਕਰਨ ਦਾ ਪ੍ਰਤੀਨਿਧਤਾ ਨਹੀਂ ਕਰਦਾ। ਪ੍ਰੋਡਕਸ਼ਨ ਰਿਕਾਰਡ ਨੂੰ ਸਿਰਫ਼ ਮਨਜ਼ੂਰ ਡਾਟਾ ਅਤੇ ਸਫਲਤਾ ਜਾਂ ਅਸਫਲਤਾ ਦੀ ਅਵਸਥਾ ਸੰਭਾਲਣੀ ਚਾਹੀਦੀ ਹੈ।

ਇੰਟਰਐਕਟਿਵ ਬਨਾਮ ਅਨਅਟੈਂਡਿਡ ਐਕਸੈਸ #

ਐਕਸੈਸ ਮੋਡਪਛਾਣਪ੍ਰਾਈਵੇਟ-ਕੀ ਪਾਥਮਨਜ਼ੂਰੀ ਮਾਡਲ
ਇੰਟਰਐਕਟਿਵ SSH1Password SSH ਏਜੰਟ ਰਾਹੀਂ ਮਨੁੱਖੀ ਖਾਤਾਪ੍ਰਾਈਵੇਟ ਕੀ 1Password ਐਪ ਵਿੱਚ ਬਰਕਰਾਰ ਰਹਿੰਦਾ ਹੈਮਨੁੱਖੀ ਇੱਕ ਪ੍ਰਕਿਰਿਆ, ਟਰਮੀਨਲ ਸੈਸ਼ਨ, ਜਾਂ ਬੇਨਤੀ ਦੀ ਮਨਜ਼ੂਰੀ ਦਿੰਦਾ ਹੈ
ਸਕੈਜੁਲਡ ਰੀਡਵਿਸ਼ੇਸ਼ ਸਰਵਿਸ ਖਾਤਾop run ਸੰਕੁਚਿਤ ਰਨਟਾਈਮ ਮੁੱਲ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈਜੌਬ ਪਾਲਿਸੀ ਅਤੇ ਸਰਵਿਸ-ਖਾਤਾ ਸਕੋਪ
ਸਕੈਜੁਲਡ SSHਵਿਸ਼ੇਸ਼ ਆਟੋਮੇਸ਼ਨ ਪਛਾਣਕੀ ਐਕਸਪੋਰਟ ਅੰਤਿਮ ਉਪਾਯ ਵਜੋਂ ਡਿਜ਼ਾਈਨ ਬਣਿਆ ਰਹਿੰਦਾ ਹੈਜੌਬ ਵੱਖਰਾਪਨ, ਛੋਟੀ ਉਮਰ, ਹੋਸਟ ਸੀਮਾ, ਅਤੇ ਰੋਟੇਸ਼ਨ
ਏਜੰਟ ਲਿਖਤਮਨੁੱਖੀ ਜਾਂ ਟਾਸਕ-ਵਿਸ਼ੇਸ਼ ਪਛਾਣਮਨਜ਼ੂਰ ਇੰਟੀਗ੍ਰੇਸ਼ਨ ‘ਤੇ ਨਿਰਭਰ ਕਰਦਾ ਹੈਹਰ ਪਰਿਭਾਸ਼ਿਤ ਬਦਲਾਅ ਤੋਂ ਪਹਿਲਾਂ ਮਨੁੱਖੀ ਮਨਜ਼ੂਰੀ

ਇੰਟਰਐਕਟਿਵ SSH ਏਜੰਟ ਪ੍ਰਮਪਟ ਦੇ ਆਲੇ-ਦੁਆਲੇ ਕਿਸੇ ਵਰਕਫਲੋ ਨੂੰ ਸਕੈਜੁਲ ਨਾ ਕਰੋ। ਇੱਕ ਵੱਖਰਾ ਆਟੋਮੇਸ਼ਨ ਡਿਜ਼ਾਈਨ ਵਰਤੋ ਜਾਂ ਉਸ ਕਦਮ ਨੂੰ ਮਨੁੱਖੀ-ਚਾਲੂ ਰੱਖੋ।

ਬਿਨਾਂ ਨਿਗਰਾਨੀ ਵਾਲੇ ਜੌਬਾਂ ਲਈ, ਇੱਕ ਸਰਵਿਸ ਖਾਤਾ ਬਣਾਓ ਜਿਸਦਾ ਇੱਕ ਵਾਲਟ ਜਾਂ ਛੋਟੀਆਂ ਆਈਟਮਾਂ ਦੇ ਸੈੱਟ ਤੱਕ ਪਹੁੰਚ ਹੋਵੇ। ਜੌਬ ਨੂੰ ਇੱਕ ਉਦੇਸ਼ ਦਿਓ। ਇੱਕ ਵਿਸ਼ੇਸ਼ ਰਿਪੋਜ਼ਿਟੋਰੀ ਜਾਂ ਸਰਵਰ ਖਾਤਾ ਵਰਤੋਂ ਕਰੋ। ਹੋਸਟ-ਕੀ ਸत्यापਨ (host-key verification) ਸ਼ਾਮਲ ਕਰੋ। ਇੱਕ ਚਲਾਈ ਸਮਾਂ-ਸੀਮਾ (execution timeout) ਸੈੱਟ ਕਰੋ। ਸਿੱਕਟਾਂ (secrets) ਤੋਂ ਬਿਨਾਂ ਕਾਰਵਾਈ ਮੈਟਾਡੇਟਾ ਦਾ ਲੌਗ ਰੱਖੋ। ਟੈਸਟ ਤੋਂ ਬਾਅਦ ਪਛਾਣ (identity) ਨੂੰ ਘੁੰਮਾਓ ਜਾਂ ਰੱਦ ਕਰੋ।

ਜੇਕਰ ਕੋਈ ਬਿਨਾਂ ਨਿਗਰਾਨੀ ਵਾਲਾ ਜੌਬ ਅਸਲ ਵਿੱਚ SSH ਪ੍ਰਾਈਵੇਟ ਕੀ ਦੀ ਲੋੜ ਰੱਖਦਾ ਹੈ, ਤਾਂ ਇੱਕ ਵਿਸ਼ੇਸ਼ ਆਟੋਮੇਸ਼ਨ ਕੀ, ਇੱਕ ਸੰਕੁੱਚ ਰਿਮੋਟ ਖਾਤੇ ਅਤੇ ਇੱਕ ਦਸਤਾਵੇਜ਼ਾਂ ਵਾਲੇ ਅੰਤਿਮ ਤਾਰੀਖ਼ ਨਾਲ ਵਰਤੋਂ ਕਰੋ। op read ਨਾਲ ਪ੍ਰਾਈਵੇਟ ਕੀ ਨੂੰ ਲਿਆਉਣਾ ਅਜੇ ਵੀ ਪ੍ਰੋਸੈਸ ਸੀਮਾ ਦੇ ਪਾਰ ਕੀ ਮੈਟੀਰੀਅਲ ਨੂੰ ਐਕਸਪੋਰਟ ਕਰਦਾ ਹੈ। ਇਸ ਡਿਜ਼ਾਈਨ ਦਾ ਬਲੈਸਟ ਰੇਡੀਅਸ 1Password SSH ਏਜੰਟ ਤੋਂ ਵੱਡਾ ਹੈ। ਜਦੋਂ ਟਾਰਗੇਟ ਇਸਨੂੰ ਸਮਰਥਨ ਕਰਦਾ ਹੈ, ਤਾਂ ਪਲੇਟਫਾਰਮ ਪਛਾਣ, ਡਿਪਲੋਇ ਸਰਵਿਸ ਜਾਂ ਹੋਰ ਵਰਕਲੋਡ ਪਛਾਣ ਨੂੰ ਤਰਜੀਹ ਦਿਓ।

ਸਾਫ਼ਟੇਕਸਟ ਏਨਵਾਇਰਨਮੈਂਟ ਚਲਾਵਾਂ ਖਤਰੇ ਨੂੰ ਕਿਉਂ ਵਧਾਉਂਦੀਆਂ ਹਨ #

ਏਨਵਾਇਰਨਮੈਂਟ ਚਲਾਵਾਂ ਸਿੱਕਟਾਂ ਨੂੰ ਸਰੋਤ ਫਾਈਲਾਂ ਤੋਂ ਬਾਹਰ ਰੱਖਦੀਆਂ ਹਨ, ਪਰ ਉਹ ਸਿੱਕਟਾਂ ਨੂੰ ਅਦਿਸ਼ ਨਹੀਂ ਬਣਾਉਂਦੀਆਂ। ਇੱਕ ਬੱਚਾ ਪ੍ਰੋਸੈਸ (child process) ਆਪਣਾ ਏਨਵਾਇਰਨਮੈਂਟ ਪੜ੍ਹਦਾ ਹੈ। ਪ੍ਰੋਸੈਸ ਜਾਂਚ, ਕਰੈਸ਼ ਹੈਂਡਲਰ, ਡਿਬੱਗ ਆਉਟਪੁੱਟ, ਸ਼ੈੱਲ ਟਰੇਸਿੰਗ, ਅਤੇ ਕਾਪੀ ਕੀਤੇ ਕਮਾਂਡ ਰਿਕਾਰਡ ਮੁੱਲਾਂ ਨੂੰ ਖੁੱਲ੍ਹ ਸਕਦੇ ਹਨ।

1Password op run ਨੂੰ ਇੱਕ ਰਨਟਾਈਮ ਤਰੀਕੇ ਵਜੋਂ ਦਸਤਾਵੇਜ਼ਾਂ ਕਰਦਾ ਹੈ ਜੋ ਸਬਪ੍ਰੋਸੈਸ ਵਿੱਚ ਰੈਫਰੈਂਸ ਲੋਡ ਕਰਦਾ ਹੈ। op run ਨੂੰ ਉਹਨਾਂ ਮੁੱਲਾਂ ਲਈ ਵਰਤੋਂ ਕਰੋ ਜਿਨ੍ਹਾਂ ਦੀ ਪ੍ਰੋਸੈਸ ਨੂੰ ਅਸਲ ਵਿੱਚ ਲੋੜ ਹੁੰਦੀ ਹੈ। ਬੱਚਾ ਪ੍ਰੋਸੈਸ ਨੂੰ ਛੋਟੀ-ਮੁੱਟੀ ਰੱਖੋ ਅਤੇ ਇਸਦੀ ਕਮਾਂਡ ਨੂੰ ਸੀਮਤ ਕਰੋ। ਜਦੋਂ SSH ਏਜੰਟ ਐਕਸਪੋਰਟ ਦੀ ਲੋੜ ਨੂੰ ਹਟਾ ਦਿੰਦਾ ਹੈ, ਤਾਂ ਪ੍ਰਾਈਵੇਟ ਕੀ ਨੂੰ SSH_PRIVATE_KEY, KEY, ਜਾਂ ਕਿਸੇ ਸਮਾਨ ਚਲਾਵਾਂ ਰਾਹੀਂ ਨਾ ਲਾਵੋ।

ਸੁਰੱਖਿਅਤ ਕ੍ਰਮ ਇਹ ਹੈ:

  1. ਇੰਟਰਐਕਟਿਵ SSH ਲਈ SSH ਏਜੰਟ ਵਰਤੋਂ ਕਰੋ।
  2. Bitbucket ਜਾਂ ਰਿਮੋਟ ਖਾਤੇ ਲਈ ਪਬਲਿਕ-ਕੀ ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਵਰਤੋਂ ਕਰੋ।
  3. ਇੱਕ ਸੰਕੁੱਚ ਬਿਨਾਂ ਨਿਗਰਾਨੀ ਵਾਲੇ ਬੱਚਾ ਪ੍ਰੋਸੈਸ ਲਈ op run ਵਰਤੋਂ ਕਰੋ।
  4. ਜਦੋਂ ਬੱਚਾ ਪ੍ਰੋਸੈਸ ਨੂੰ ਪੂਰਾ ਏਨਵਾਇਰਨਮੈਂਟ ਨਹੀਂ ਚਾਹੀਦਾ, ਤਾਂ ਇੱਕ ਮੁੱਲ ਲਈ op read ਵਰਤੋਂ ਕਰੋ।
  5. ਲਿਖਤੀ ਅਪਵਾਦ, ਸੰਕੁੱਚ ਸਕੋਪ, ਸਾਫ਼-ਸੁਥਰਾ ਯੋਜਨਾ, ਅਤੇ ਰੋਟੇਸ਼ਨ ਯੋਜਨਾ ਤੋਂ ਬਾਅਦ ਹੀ ਪ੍ਰਾਈਵੇਟ ਕੀ ਨੂੰ ਐਕਸਪੋਰਟ ਕਰੋ।

ਫੈਸਲਾ ਟੇਬਲ #

ਲੋੜਤਰਜ਼ੀਹਤ ਰਾਹਰੁਕਣ ਜਾਂ ਮੁੜ-ਡਿਜ਼ਾਈਨ ਕਰਨ ਦਾ ਕਾਰਨ
ਮਨੁੱਖ SSH ਰਾਹੀਂ Git ਚਲਾਉਂਦਾ ਹੈ1Password SSH Agentਜੇਕਰ ਪ੍ਰਮਪਟ (prompt) ਅਚਾਨਕ ਕੋਈ ਪ੍ਰਕਿਰਿਆ ਜਾਂ ਕੀ ਨਾਮ ਲੈਂਦਾ ਹੈ ਤਾਂ ਰੁਕੋ
ਇੱਕ ਰਿਪੋਜ਼ਟਰੀ ਕੀ ਦਾ ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਕਰੋਪਬਲਿਕ ਕੀ ਪੜ੍ਹੋ ਜਾਂ ਆਟੋਫਿਲ ਕਰੋਕਦੇ ਵੀ ਪ੍ਰਾਈਵੇਟ ਕੀ ਨੂੰ ਰਿਪੋਜ਼ਟਰੀ ਸੇਵਾ ਵਿੱਚ ਕਾਪੀ ਨਾ ਕਰੋ
ਏਜੰਟ ਸੇਵਾ ਸਥਿਤੀ ਪੜ੍ਹਦਾ ਹੈOS-ਸਤਹੀ ਸਕੋਪ ਵਾਲਾ Read-only MCP ਟੂਲਜੇਕਰ ਟੂਲ ਇੱਕ ਅਸੀਮਿਤ ਸ਼ੈਲ (shell) ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ ਤਾਂ ਰੁਕੋ
ਏਜੰਟ ਇੱਕ ਰਿਮੋਟ ਬਦਲਾਅ ਦੀ ਸੁਝਾਅ ਦਿੰਦਾ ਹੈਯੋਜਨਾ ਟੂਲ ਤੋਂ ਬਾਅਦ ਮਨੁੱਖੀ ਮਨਜ਼ੂਰੀਜੇਕਰ ਟਾਰਗੇਟ, ਕਮਾਂਡ, ਜਾਂ ਰੋਲਬੈਕ ਅਸਪਸ਼ਟ ਹੈ ਤਾਂ ਰੁਕੋ
ਜੌਬ ਇੱਕ API ਟੋਕਨ ਪੜ੍ਹਦੀ ਹੈਸਰਵਿਸ ਖਾਤਾ ਅਤੇ op read ਜਾਂ op runਜੇਕਰ ਟੋਕਨ ਸੋਰਸ, ਲੌਗਾਂ, ਜਾਂ ਗਲੋਬਲ ਪ੍ਰੋਫਾਈਲ ਵਿੱਚ ਆਉਂਦਾ ਹੈ ਤਾਂ ਰੁਕੋ
ਜੌਬ ਨੂੰ SSH ਐਕਸੈਸ ਦੀ ਲੋੜ ਹੈਵਰਕਲੋਡ ਪਛਾਣ ਜਾਂ ਵਿਸ਼ੇਸ਼ ਆਟੋਮੇਸ਼ਨ ਕੀਜੇਕਰ ਜੌਬ ਨੂੰ ਨਿੱਜੀ ਕੀ ਜਾਂ ਵਿਆਪਕ ਖਾਤਾ ਲੋੜੀਂਦਾ ਹੈ ਤਾਂ ਰੁਕੋ
MCP ਕਨਫਿਗ ਨੂੰ ਟੋਕਨ ਦੀ ਲੋੜ ਹੈਸਮਰਥਿਤ ਕਲਾਇੰਟ ਦੁਆਰਾ ਲੋਡ ਕੀਤਾ ਗਿਆ ਰਨਟਾਈਮ ਰੈਫਰੈਂਸਜੇਕਰ ਪਲੇਨਟੈਕਸਟ ਟੋਕਨ ਕਨਫਿਗ ਵਿੱਚ ਕਮਿਟ ਕੀਤਾ ਜਾਂਦਾ ਹੈ ਤਾਂ ਰੁਕੋ

ਫੇਲ੍ਹਰ ਹੈਂਡਲਿੰਗ #

ਅਚਾਨਕ SSH ਸਹਿਮਤੀ ਪ੍ਰਮਪਟ: ਪ੍ਰਮਪਟ ਨੂੰ ਨਕਾਰੋ। ਪ੍ਰਕਿਰਿਆ ਦਾ ਨਾਮ, ਟਰਮੀਨਲ ਸੈਸ਼ਨ, ਕੀ ਫਿੰਗਰਪ੍ਰਿੰਟ, ਰਿਪੋਜ਼ਟਰੀ ਟਾਰਗੇਟ, ਅਤੇ ਹੋਸਟ ਕੀ ਦੀ ਜਾਂਚ ਕਰੋ। ਦੁਬਾਰਾ ਕੋਸ਼ਿਸ਼ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ SSH ਕਲਾਇੰਟ ਸੰਰਚਨਾ ਦੀ ਸਮੀਖਿਆ ਕਰੋ।

SSH ਏਜੰਟ ਸਾਕੇਟ ਦੀ ਘਾਟ: ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ 1Password ਡੈਸਕਟਾਪ ਐਪ ਨੂੰ ਸਮਰਥਿਤ ਤਰੀਕੇ ਰਾਹੀਂ ਇੰਸਟਾਲ ਕੀਤਾ ਗਿਆ ਹੈ, SSH ਏਜੰਟ ਸਰਗਰਮ ਹੈ, ਅਤੇ ਕਲਾਇੰਟ ਪਲੇਟਫਾਰਮ-ਵਿਸ਼ੇਸ਼ ਸਾਕੇਟ ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ। ਅਧਿਕਾਰਤ SSH ਏਜੰਟ ਪੇਜ ਓਪਰੇਟਿੰਗ ਸਿਸਟਮ ਦੀਆਂ ਲੋੜਾਂ ਅਤੇ ਸਾਕੇਟ ਸੈਟਅਪ ਲਿੰਕਾਂ ਦੀ ਸੂਚੀ ਦਿੰਦਾ ਹੈ।

ਪਬਲਿਕ-ਕੀ ਪ੍ਰਮਾਣੀਕਰਨ ਅਸਫਲ ਹੁੰਦਾ ਹੈ: ਚੁਣੀ ਗਈ ਪਬਲਿਕ ਕੀ, ਰਿਮੋਟ ਖਾਤਾ, ਰਿਪੋਜ਼ਟਰੀ ਇਜਾਜ਼ਤ, ਹੋਸਟ ਕੀ, ਅਤੇ SSH ਸੰਰਚਨਾ ਦੀ ਜਾਂਚ ਕਰੋ। ਇੱਕ ਪਬਲਿਕ ਫਿੰਗਰਪ੍ਰਿੰਟ ਤੁਲਨਾ ਦੀ ਵਰਤੋਂ ਕਰੋ। ਗਲਤੀ ਨੂੰ ਹੱਲ ਕਰਨ ਲਈ ਕਿਸੇ ਅਸੰਬੰਧਿਤ ਪ੍ਰਾਈਵੇਟ ਕੀ ਨੂੰ ਐਕਸਪੋਰਟ ਨਾ ਕਰੋ।

op read ਐਕਸੈਸ ਨਕਾਰਦਾ ਹੈ: ਸਰਵਿਸ-ਖਾਤਾ ਵਾਲਟ ਸਕੋਪ, ਆਈਟਮ ਪਛਾਣ, ਫੀਲਡ ਰੈਫਰੈਂਸ, ਸਾਈਨ-ਇਨ ਅਵਸਥਾ, ਅਤੇ ਆਈਟਮ ਸਥਿਤੀ ਦੀ ਜਾਂਚ ਕਰੋ। ਰੈਫਰੈਂਸ ਨੂੰ ਇੱਕ ਮਨਜ਼ੂਰ ਆਈਟਮ ਤੱਕ ਘਟਾਓ। ਪਹਿਲੀ ਪ੍ਰਤੀਕਿਰਿਆ ਵਜੋਂ ਵਾਲਟ ਗ੍ਰਾਂਟ ਨੂੰ ਵਿਸ਼ਾਲ ਨਾ ਕਰੋ।

op run ਮੁੱਲ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ: ਜੌਬ ਨੂੰ ਰੋਕੋ। ਸਿਰਫ਼ ਘੱਟੋ-ਘੱਟ ਇੰਸੀਡੈਂਟ ਰਿਕਾਰਡ ਨੂੰ ਸੰਭਾਲੋ। ਤੁਹਾਡੇ ਰਿਟੈਨਸ਼ਨ ਪ੍ਰਕਿਰਿਆ ਅਨੁਸਾਰ ਕਾਪੀ ਕੀਤੇ ਗਏ ਲੌਗ ਅਤੇ ਅਸਥਾਈ ਫਾਈਲਾਂ ਨੂੰ ਹਟਾਓ। ਪ੍ਰਭਾਵਿਤ ਸੀਕ੍ਰੇਟ ਜਾਂ ਕੀ ਨੂੰ ਰੋਟੇਟ ਕਰੋ। ਸ਼ੈਲ ਟ੍ਰੇਸਿੰਗ, ਪ੍ਰਕਿਰਿਆ ਜਾਂਚ, ਕ੍ਰੈਸ਼ ਰਿਪੋਰਟਾਂ, ਅਤੇ MCP ਟ੍ਰਾਂਸਕ੍ਰਿਪਟ ਰਿਟੈਨਸ਼ਨ ਦੀ ਸਮੀਖਿਆ ਕਰੋ।

MCP ਟੂਲ ਅਨੁਮਾਨਿਤ ਤਰੀਕੇ ਨਾਲ ਵਿਵਹਾਰ ਨਹੀਂ ਕਰਦਾ: ਟੂਲ ਆਉਟਪੁੱਟ ਨੂੰ ਅਭਰਸ਼ਟ ਡਾਟਾ ਵਜੋਂ ਮੰਨੋ। ਆਉਟਪੁੱਟ ਦੁਆਰਾ ਸੁਝਾਏ ਗਏ ਕਮਾਂਡਾਂ ਨੂੰ ਚਲਾਉਣ ਤੋਂ ਪਹਿਲਾਂ ਰੁਕੋ। ਸਰਵਰ ਸੋਰਸ, ਕਨਫਿਗਰੇਸ਼ਨ, ਪਰਮਿਸ਼ਨਾਂ ਅਤੇ ਟ੍ਰਾਂਸਪੋਰਟ ਦੀ ਜਾਂਚ ਕਰੋ। MCP ਹੋਸਟ ਨੂੰ ਯੂਜ਼ਰ ਸਹਿਮਤੀ ਪ੍ਰਾਪਤ ਕਰਨੀ ਚਾਹੀਦੀ ਹੈ। ਸਪੈਸੀਫਿਕੇਸ਼ਨ ਸਹਿਮਤੀ ਅਤੇ ਐਕਸੈਸ ਕੰਟਰੋਲਾਂ ਲਈ ਇੰਪਲੀਮੈਂਟਰ ਗਾਈਡੈਂਸ ਵੀ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ, ਪਰ ਪ੍ਰੋਟੋਕੋਲ ਤੁਹਾਡੀ ਸਮੀਖਿਆ ਨੂੰ ਬਦਲ ਨਹੀਂ ਸਕਦਾ।

ਰੋਲਬੈਕ ਅਤੇ ਹਟਾਉਣਾ #

ਰੋਲਬੈਕ ਫਾਈਲ ਹਟਾਉਣ ਨਾਲ ਨਹੀਂ, ਸਗੋਂ ਐਕਸੈਸ ਹਟਾਉਣ ਨਾਲ ਸ਼ੁਰੂ ਹੁੰਦਾ ਹੈ।

  1. ਏਜੰਟ ਜਾਂ ਸਕੈਡਿਊਲਡ ਜੌਬ ਨੂੰ ਰੋਕੋ। MCP ਸਰਵਰ ਐਂਟਰੀ ਨੂੰ ਅਸਮਰਥ (disable) ਕਰੋ ਜਾਂ ਕਲਾਇੰਟ ਨੂੰ ਡਿਸਕਨੈਕਟ ਕਰੋ।
  2. 1Password ਨੂੰ ਲਾਕ ਕਰੋ। ਇੰਟਰਐਕਟਿਵ SSH ਔਥਰਾਈਜ਼ੇਸ਼ਨ ਸੈਸ਼ਨ ਨੂੰ ਖਤਮ ਕਰੋ।
  3. ਪਬਲਿਕ ਕੀ ਨੂੰ ਹਟਾਓ। Bitbucket, ਰਿਪੋਜ਼ਿਟਰੀ ਜਾਂ ਰਿਮੋਟ ਖਾਤੇ ਤੋਂ ਟੈਸਟ ਕੀ ਨੂੰ ਮਿਟਾਓ।
  4. ਸਰਵਿਸ ਐਕਾਊਂਟ ਨੂੰ ਰਿਵੋਕ ਕਰੋ। ਇਸਦੀ ਵਾਲਟ ਐਕਸੈਸ ਨੂੰ ਹਟਾਓ ਅਤੇ ਇਸਦੇ ਟੋਕਨ ਨੂੰ ਅਸਮਰਥ (invalidate) ਕਰੋ।
  5. ਟੈਸਟ SSH Key ਆਈਟਮ ਨੂੰ ਮਿਟਾਓ ਜਦੋਂ ਤੱਕ ਤੁਸੀਂ ਪੁਸ਼ਟੀ ਨਹੀਂ ਕਰਦੇ ਕਿ ਕੋਈ ਮਨਜ਼ੂਰ ਕੀਤਾ ਵਰਕਫਲੋ ਇਸ ਆਈਟਮ ਦੀ ਵਰਤੋਂ ਨਹੀਂ ਕਰਦਾ।
  6. ਅਸਥਾਈ ਕਨਫਿਗਰੇਸ਼ਨ ਨੂੰ ਹਟਾਓ। ਟੈਸਟ ਰੈਫਰੈਂਸ, ਲੋਕਲ ਸਾਕੇਟ ਓਵਰਰਾਈਡ ਅਤੇ ਜਨਰੇਟ ਕੀਤੇ ਗਏ ਲੌਗ ਨੂੰ ਮਿਟਾਓ।
  7. ਸਬੂਤਾਂ ਦੀ ਸਮੀਖਿਆ ਕਰੋ। ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਰੋਲਬੈਕ ਰਿਕਾਰਡ ਵਿੱਚ ਕੋਈ ਪ੍ਰਾਈਵੇਟ ਕੀ, ਟੋਕਨ ਜਾਂ ਐਨਵਾਇਰਨਮੈਂਟ ਡੰਪ ਨਹੀਂ ਹੈ।

ਇੱਕ ਮਿਟਾਈ ਗਈ ਲੋਕਲ ਫਾਈਲ ਪਬਲਿਕ ਕੀ, ਸਰਵਿਸ ਐਕਾਊਂਟ, ਕੈਸ਼ ਕੀਤੇ ਟੋਕਨ ਜਾਂ ਰਿਮੋਟ ਔਥਰਾਈਜ਼ੇਸ਼ਨ ਨੂੰ ਰਿਵੋਕ ਨਹੀਂ ਕਰਦੀ। ਹਰ ਇੱਕ ਗ੍ਰਾਂਟ ਨੂੰ ਇਸਦੇ ਸੋਰਸ ਤੋਂ ਹਟਾਓ।

ਟਰਬਲਸ਼ੂਟਿੰਗ #

ਏਜੰਟ ਹਰ ਕਮਾਂਡ ਲਈ ਕੀ ਦੀ ਮੰਗ ਕਰਦਾ ਹੈ #

ਚੁਣੀ ਗਈ ਔਥਰਾਈਜ਼ੇਸ਼ਨ ਸਕੋਪ ਦੀ ਜਾਂਚ ਕਰੋ। ਪ੍ਰਤੀ-ਰਿਕੁਐਸਟ ਮਨਜ਼ੂਰੀ ਵੱਧ ਸੀਮਤ ਹੈ। ਟਰਮੀਨਲ ਜਾਂ ਐਪਲੀਕੇਸ਼ਨ ਸੈਸ਼ਨ ਖਤਮ ਹੋ ਸਕਦਾ ਹੈ। 1Password ਵੀ ਲਾਕ ਜਾਂ ਕੁਇਟ ਈਵੰਟ ਤੋਂ ਬਾਅਦ ਦੁਬਾਰਾ ਪੁੱਛਦਾ ਹੈ।

ਏਜੰਟ ਨੂੰ ਆਪਣੇ ਟ੍ਰਾਂਸਕ੍ਰਿਪਟ ਵਿੱਚ ਪ੍ਰਾਈਵੇਟ ਕੀ ਦਿਖਦਾ ਹੈ #

ਵਰਕਫਲੋ ਨੂੰ ਰੋਕੋ ਅਤੇ ਕੀ ਨੂੰ ਰੋਟੇਟ ਕਰੋ। MCP ਸਰਵਰ ਰਿਸਪਾਂਸ, ਸ਼ੈਲ ਕਮਾਂਡ, ਡਿਬਗ ਲੌਗ ਅਤੇ ਟੂਲ ਵ੍ਰੈਪਰ ਦੀ ਜਾਂਚ ਕਰੋ। ਇੰਟਰਐਕਟਿਵ ਕੰਮਾਂ ਲਈ ਪ੍ਰਾਈਵੇਟ-ਕੀ ਪੜ੍ਹਨ ਦੀ ਥਾਂ SSH Agent ਦੀ ਵਰਤੋਂ ਕਰੋ। ਜੌਬਾਂ ਲਈ, ਨਿੱਜੀ ਕੀ ਦੀ ਥਾਂ ਇੱਕ ਵਿਸ਼ੇਸ਼ ਪਛਾਣ ਅਤੇ ਦਸਤਾਵੇਜ਼ਾਂ ਵਾਲੇ ਐਕਸੈਪਸ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰੋ।

ਕੀ ਦੀ ਸੂਚੀ ਵਿੱਚ ਬਹੁਤ ਸਾਰੀਆਂ ਪਛਾਣਾਂ ਹਨ #

1Password SSH Agent ਆਪਣੇ ਕਨਫਿਗਰ ਕੀਤੇ ਗਏ ਵਾਲਟਾਂ ਤੋਂ ਯੋਗ ਕੀ ਨੂੰ ਪ੍ਰਦਰਸ਼ਿਤ ਕਰਦਾ ਹੈ। ਸਕੋਪ ਕੀਤੇ ਗਏ ਏਜੰਟ ਕਨਫਿਗਰੇਸ਼ਨ ਜਾਂ ਹੋਸਟ-ਵਿਸ਼ੇਸ਼ SSH ਕਨਫਿਗਰੇਸ਼ਨ ਦੀ ਵਰਤੋਂ ਕਰੋ। ਏਜੰਟ ਦਸਤਾਵੇਜ਼ਾਂ ] ਵਿੱਚ ਵੀ OpenSSH ਸਰਵਰ ਦੀ ਛੇ-ਕੀ ਸੀਮਾ ਦਾ ਜ਼ਿਕਰ ਹੈ।

ਇੱਕ ਕਮਾਂਡ ਹੱਥ ਨਾਲ ਕੰਮ ਕਰਦਾ ਹੈ ਪਰ ਜੌਬ ਵਿੱਚ ਫੇਲ੍ਹ ਹੁੰਦਾ ਹੈ #

ਪਛਾਣ, ਵਾਲਟ ਸਕੋਪ, ਐਨਵਾਇਰਨਮੈਂਟ, ਹੋਸਟ-ਕੀ ਡਾਟਾ, ਵਰਕਿੰਗ ਡਾਇਰੈਕਟਰੀ ਅਤੇ ਮਨਜ਼ੂਰੀ ਮੰਨਣ ਦੀਆਂ ਤੁਲਨਾ ਕਰੋ। ਇੰਟਰਐਕਟਿਵ 1Password ਸੈਸ਼ਨ ਵਿੱਚ ਮਨੁੱਖੀ ਸਹਿਮਤੀ ਸ਼ਾਮਲ ਹੁੰਦੀ ਹੈ। ਇੱਕ ਸਕੈਡਿਊਲਡ ਜੌਬ ਵਿੱਚ ਨਹੀਂ। ਜੌਬ ਨੂੰ ਇੱਕ ਵੱਖਰੇ ਐਕਸੈਸ ਮੋਡ ਵਜੋਂ ਡਿਜ਼ਾਈਨ ਕਰੋ।

MCP ਸਰਵਰ ਕਨੈਕਟ ਹੈ ਪਰ ਟਾਸਕ ਫੇਲ੍ਹ ਹੁੰਦਾ ਹੈ #

ਕਨੈਕਸ਼ਨ ਦੀ ਪੁਸ਼ਟੀ ਅਧਿਕਾਰਿਤਾ ਨਹੀਂ ਦਰਸਾਉਂਦੀ। ਟੂਲ ਖੋਜ, ਸਰਵਰ ਕ੍ਰੈਡੈਂਸ਼ਲ, ਕਲਾਇੰਟ ਸਹਿਮਤੀ, ਓਪਰੇਟਿੰਗ-ਸਿਸਟਮ ਅਧਿਕਾਰ, ਨੈੱਟਵਰਕ ਐਕਸੈਸ, ਅਤੇ ਟਾਰਗੇਟ-ਸਾਈਡ ਅਧਿਕਾਰਾਂ ਦੀ ਜਾਂਚ ਵੱਖਰੇ ਕਦਮਾਂ ਵਿੱਚ ਕਰੋ। ਪਹਿਲਾ ਟੈਸਟ ਰੀਡ-ਓਨਲੀ ਰੱਖੋ।

ਅਗਲੇ ਕਦਮ #

ਨਵੇਂ ਮਨਜ਼ੂਰੀਆਂ ਲਈ ਮੌਜੂਦਾ 2026-07-28 MCP ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ ਦੀ ਵਰਤੋਂ ਕਰੋ। ਇਸ ਲੇਖ ਵਿੱਚ 2025-06-18 ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ ਦਾ ਕੋਈ ਲਿੰਕ ਇਤਿਹਾਸਕ ਪਿਛੋਕੜ ਹੈ।

ਇੱਕ ਸੰਸਲੇਸ਼ਿਤ ਰਿਪੋਜ਼ਟਰੀ ਅਤੇ ਇੱਕ ਰੀਡ-ਓਨਲੀ MCP ਟੂਲ ਨਾਲ ਸ਼ੁਰੂ ਕਰੋ। ਹਰ ਉਮੀਦ ਕੀਤੇ ਨਤੀਜੇ ਨੂੰ ਅਜ਼ਮਾਇਆ ਨਹੀਂ ਮੰਨੋ ਜਦੋਂ ਤੱਕ ਕਿ ਕੰਟਰੋਲਡ ਵਾਤਾਵਰਣ ਪ੍ਰਮਾਣ ਪੈਦਾ ਨਹੀਂ ਕਰਦਾ। ਫਿਰ, ਗੈਰ-ਪ੍ਰੋਡਕਸ਼ਨ ਟਾਰਗੇਟ, ਨਾਮ-ਸੂਚਿਤ ਓਪਰੇਟਰ, ਪ੍ਰਮਾਣਿਤ ਹੋਸਟ ਕੀ, ਅਤੇ ਲਿਖਤੀ ਰੋਲਬੈਕ ਰਿਕਾਰਡ ਨਾਲ ਵਰਕਫਲੋ ਦੁਹਰਾਓ।
