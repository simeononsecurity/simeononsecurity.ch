Tailoring means making the evidence for a particular role easy to find. A useful edit might reorder truthful bullets, clarify a relevant skill, or select a project. It does not require a new identity, invented experience, or a target similarity percentage.

## Start with the Employer's Requirements

Save the posting privately with its URL and date. Separate required qualifications, preferred qualifications, duties, and location or work-authorization conditions. A posting may contain broad or copied language. Ask whether each item is relevant to the actual work and whether you have evidence for it.

| Posting item | Your evidence | Resume location | Decision |
|---|---|---|---|
| Fictional role: explain outages to users | Two redacted support reports you wrote | Support role, first bullet | Move the truthful bullet higher |
| Fictional role: configure Kubernetes | Only read an introduction | None | Do not claim configuration skill |
| Fictional role: document changes | Approved class change record | Projects section | Name it as a class project |

The table is a decision record. A missing required qualification does not become true because a synonym appears in your resume.

## Edit from a Master Copy

Keep a private master resume with accurate dates, titles, and full evidence. Make a copy for the role. Preserve the employer's official title for your prior jobs. If an internal title needs explanation, add a clearly labeled description rather than rewriting the title in a way that conflicts with an employment check.

1. Choose two or three posting duties you can support.
2. Move the strongest relevant bullet or project near the top of its section.
3. Use the posting's terminology only where it describes work you performed. For example, name Docker only if you used Docker, not because you used another container tool.
4. Remove detail that distracts from the role, while keeping dates and facts consistent.
5. Compare the tailored copy with the master, line by line. Explain each change in a short private note.
6. Export the requested format and check extracted text, links, and visual reading order.

A summary is optional. If you include one, it should state relevant evidence, not repeat the job title without support.

## Treat Tool Scores as Diagnostics

Employer applicant systems differ. [Indeed's employer ATS overview](https://www.indeed.com/hire/c/info/what-is-ats) describes collection, screening questions, filtering, and recruiter review, which vary by setup. A local resume tool's similarity score is not an employer's decision threshold. Use it to spot a missing truthful term or a parsing problem, then inspect the actual text. Do not stuff words or delay a suitable application to reach an arbitrary score.

If you use the [ATS Resume Improver](https://atsresumeimprover.netlify.app/), check its current privacy and model settings before entering personal data. A local text check and a cloud AI request have different data paths. Use synthetic or redacted content when you have not approved a provider for your own resume. The course hub describes the tool's data-flow limits.

## Stop When the Change Stops Helping

Submit after the role evidence is visible, every claim remains defensible, employer instructions are met, and the file is readable. More keyword changes can reduce clarity or inflate a claim. Record unresolved gaps instead of hiding them. The posting and version note let you explain your choices later.

## Practice and Pass Check

Use one sanitized resume and two fictional postings: a support role prioritizing customer explanation and a junior developer role prioritizing tested code. Make two tailored copies from the same master. For each, submit the requirement-to-evidence table, a diff or change note, the exported file's extracted text, and a claim check. Ask a reader to identify the target role and locate the evidence for two duties. Fail the exercise if either copy gains a skill, title, or result absent from the master evidence.
