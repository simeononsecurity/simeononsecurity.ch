**Software development includes many roles, markets, work settings, and entry routes.** Demand, pay, remote eligibility, hiring filters, and advancement differ by occupation, geography, employer, level, and date. This playbook teaches you to test a route with current evidence and produce work a reviewer can inspect.

Choose the route which matches your starting experience, target role, access needs, budget, and available time. Keep the evidence record separate from passwords, private data, employer code, and confidential interview material.

---

## Prerequisites and Practice Environment

- A supported computer with a text editor, terminal or accessible equivalent, Git, and a current language runtime
- A local folder or private repository for exercises, with no credentials, personal data, employer code, or unlicensed material
- A weekly practice window you can sustain, plus a budget ceiling of zero unless a later decision record approves spending
- Permission before publishing team, school, volunteer, client, or employer work
- One reviewer, mentor, peer, instructor, or repeatable automated check for feedback

Run a setup check before the first lesson. Create a repository, add a small program and one test, run the test, make a commit, clone into a temporary folder, repeat the test, then delete the temporary copy. Save the commands and result without account names or local paths.

## What Is a Software Development Career?

**Software development** is the practice of designing, writing, testing, and maintaining software systems. The discipline spans everything from frontend web interfaces and mobile apps to backend APIs, database systems, distributed infrastructure, embedded firmware, machine learning pipelines, and the tools developers use to build other software.

Credential requirements vary by employer and role. Current postings might accept degrees, community college, apprenticeships, bootcamps, self-study, internal transfers, domain experience, or reviewed work. Record each actual requirement rather than assuming one universal route.

### Why Software Development Is a Strong Career Choice

| Factor | Detail |
|---|---|
| **Demand** | Measure the target occupation, geography, level, and date through official data and current postings |
| **Compensation** | Compare base pay, total compensation, hours, on-call, benefits, location, and uncertainty |
| **Remote work** | Verify hiring geography, employment status, tax, schedule, security, monitoring, and accommodations |
| **Advancement** | Use the employer framework, feedback, available scope, support, and documented evidence |
| **Entry filters** | Degree, experience, license, clearance, language, and work-authorization rules differ by role |
| **Variety** | Dozens of specializations and stacks mean you can pivot without leaving development |

## Software Development Specializations

Software development is not one job. Different roles require different skills, tools, and mindsets. Understanding the landscape helps you build a focused learning plan.

| Specialization | What You Build | Key Technologies |
|---|---|---|
| **Frontend Developer** | User interfaces, visual experiences, browser behavior | HTML, CSS, JavaScript, React, Vue, TypeScript |
| **Backend Developer** | APIs, databases, business logic, server-side systems | Python, Java, Go, Node.js, PostgreSQL, Redis |
| **Full Stack Developer** | Both frontend and backend systems | Any combination of the above |
| **Mobile Developer** | iOS and Android applications | Swift, Kotlin, React Native, Flutter |
| **DevOps / Platform Engineer** | CI/CD pipelines, infrastructure, reliability tooling | Docker, Kubernetes, Terraform, GitHub Actions |
| **Data Engineer** | Data pipelines, warehouses, transformation systems | Python, Spark, dbt, Airflow, Snowflake |
| **Machine Learning Engineer** | ML models, training pipelines, inference systems | Python, PyTorch, TensorFlow, MLflow |
| **Embedded / Systems Developer** | Firmware, operating systems, low-level software | C, C++, Rust, assembly |
| **Security Engineer** | Secure code, vulnerability testing, AppSec tooling | Python, Rust, SAST/DAST tools |

Use target postings and a small work trial to compare specialties. Add testing, QA automation, developer experience, desktop, game, scientific, enterprise, product, support, and technical-writing routes when they match your market.

## Getting Started: Your First 90 Days

If you are starting from zero, a focused 90-day plan:

1. **Pick one language**, Python or JavaScript. Do not switch mid-stream.
2. **Choose one current structured resource** after checking cost, access, feedback, privacy, and cancellation.
3. **Build one small project** with a README, tests, license decision, secret check, and local demo.
4. **Use version control** once the basic tool setup works, then practice clone and recovery.
5. **Request one review** through a safe community, class, colleague, or mentor route.
6. **Revise from evidence** and start matched applications while the next project remains in progress.

*The goal of the first 90 days is momentum, not mastery. Ship something. Fix it. Ship again.*

## Getting a Job in Software Development

### Resume and Portfolio Strategy

Portfolio relevance depends on the role and hiring process. A work sample supports claims when you own the work, have permission to share it, and explain the design, tests, trade-offs, and feedback.

- **Work sample**: choose a public, private, school, or supervised route. Include a clear README and permission to share.
- **Resume format**: follow target-employer instructions and verify plain-text extraction, links, metadata, and accessibility.
- **Quantify when possible**: "reduced API latency by 40%" beats "improved performance."
- **Truthful evidence**: list your specific contribution, team credit, verified results, and relevant education or projects.

See the [Resume Optimization Course](/resume-optimization-course-start/) for a full guide to building an ATS-optimized developer resume.

### Interview Format

Software interview formats vary. Research the target employer before preparing for any of these possible stages:

1. **Recruiter screen**: background, role interest, eligibility, and logistics.
2. **Technical screen**: possible code reading, debugging, coding, testing, or domain questions.
3. **Take-home assignment**: verify scope, time, compensation, IP, privacy, and permitted tools before accepting.
4. **Interview loop**: possible behavioral, work-sample, coding, or system-design stages with an accommodations route.
5. **Offer**: compare written base, bonus, equity, benefits, conditions, location, and dates before responding.

## Final Capstone

1. Produce a target-role decision from at least ten dated postings.
2. Submit one work sample with setup steps, tests, accessibility check, license decision, secret scan, privacy review, cost boundary, and reviewer feedback.
3. Add one debugging record showing a reproduced failure, evidence, fix, and regression test.
4. Add a delivery record showing automated checks, a disposable stage, deliberate failure, rollback, and teardown.
5. Add a truthful application packet and a scored mock interview.
6. Add an education and growth plan with total cost, weekly capacity, support, and review date.

```text
REDACTED CAPSTONE EXAMPLE
Target role sample:     10 backend postings, checked 2026-10-10
Work sample:            local API, 14 tests passed, README review completed
Debugging evidence:     null-input failure reproduced and regression test added
Delivery evidence:      failed test blocked stage, prior version restored, resources removed
Application packet:     links checked, claims verified, mock score 16/20
Next checkpoint:        2026-11-10
```

**Pass gate**

- [ ] The project runs from documented steps on a clean environment
- [ ] Tests cover a normal path, boundary, and handled failure
- [ ] No secret, private data, confidential work, or unsupported claim appears
- [ ] Accessibility, security, license, dependency, and cost checks have evidence
- [ ] A reviewer comment led to a documented revision
- [ ] Delivery failure and rollback were rehearsed in a disposable environment
- [ ] The career plan uses dated role, education, and compensation sources
