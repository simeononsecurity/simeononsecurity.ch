## ভূমিকা: হ্যাকারদের হটস্পট

**DagShell** হলো **Orbic RCL400 মোবাইল হটস্পটের** জন্য ওপেন সোর্স কাস্টম ফার্মওয়্যার। এটি সাধারণ সেলুলার ডিভাইসকে **বহনযোগ্য নিরাপত্তা গবেষণা ও গোপনীয়তার টুলকিটে** রূপান্তর করে। নিরাপত্তা গবেষক “dag” তৈরি করেছেন এই টার্মিনাল-ধাঁচের ফার্মওয়্যার। এতে রয়েছে **হ্যাকিং টুল, গোপনীয়তা বৈশিষ্ট্য ও নেটওয়ার্ক পর্যবেক্ষণ**, সবুজ-কালো হ্যাকার-ধাঁচের ইন্টারফেসে।

## DagShell কী?

### সারসংক্ষেপ

**DagShell** হলো ওপেন সোর্স কাস্টম ফার্মওয়্যার, যা Orbic RCL400-এর মূল ওয়েব ইন্টারফেস বদলে **সম্পূর্ণ নিরাপত্তা টুলকিট** দেয়। এতে রয়েছে:

- ASCII আর্ট ও হ্যাকার নকশাসহ **টার্মিনাল-ধাঁচের ইন্টারফেস**
- **TLS 1.2 বা নতুন সংস্করণে এনক্রিপ্ট করা** ওয়েব ইন্টারফেস (স্ব-স্বাক্ষরিত সার্টিফিকেট)
- **গোপনীয়তা সুরক্ষা টুল** (TTL আড়াল, MAC স্পুফিং, DNS-ভিত্তিক বিজ্ঞাপন ব্লক)
- **নেটওয়ার্ক পর্যবেক্ষণ** (সক্রিয় সংযোগ, রাউটিং টেবিল, DNS কোয়েরি)
- **হ্যাকিং টুল** (IMSI ক্যাচার শনাক্তকরণ, পোর্ট স্ক্যান, ARP আবিষ্কার)
- **আক্রমণ সক্ষমতা** (Evil Twin AP, ক্যাপটিভ পোর্টাল ফিশিং, ডিঅথ আক্রমণ)
- Wigle-সামঞ্জস্যপূর্ণ CSV রপ্তানিসহ **GPS ট্র্যাকিং ও ওয়ারড্রাইভিং**
- GPS, Bluetooth স্ক্যান ও WiFi রিকনেসান্সের জন্য **Raspberry Pi সহায়ক**
- ব্রাউজার-ভিত্তিক ফাইল ব্যবস্থাপকের মাধ্যমে **ফাইল সিস্টেমে প্রবেশ**
- AT কমান্ডে **SMS সুবিধা**
- **স্থায়িত্ব**: বুটের সময় স্বয়ংক্রিয়ভাবে চালু হয়

- **দ্রুত অবস্থা**: IP ঠিকানা ও সংযোগের অবস্থা

**AT কমান্ড** মডেমকে নিম্ন স্তরে নিয়ন্ত্রণ করে:
```
Example AT Commands:
AT+CSQ       - Signal quality
AT+COPS?     - Current network operator  
AT+CREG?     - Network registration status
AT+CIMI      - Get IMSI (subscriber identity)
AT+CGSN      - Get IMEI (device identifier)
```

### 🔒 গোপনীয়তা সুরক্ষা ব্যবস্থা

#### TTL সংশোধন

**উদ্দেশ্য**: অপারেটরের শনাক্তকরণ থেকে হটস্পট ট্র্যাফিক আড়াল করা

**যেভাবে কাজ করে**:
- IP প্যাকেটের **Time To Live (TTL)** মান **65** করে
- অপারেটর TTL কমে যাওয়া দেখে টেথারিং শনাক্ত করে (ফোন=64, সংযুক্ত ডিভাইস=63)
- TTL 65 করলে **সব ট্র্যাফিক স্থানীয় বলে মনে হয়**

**ব্যবহার**: অপারেটরের টেথারিং সীমাবদ্ধতা বা গতি কমানো এড়ানো

**কমান্ড**:
```bash
# TTL সংশোধন সক্রিয় করুন
iptables -t mangle -A POSTROUTING -j TTL --ttl-set 65

# TTL সংশোধন বন্ধ করুন
iptables -t mangle -D POSTROUTING -j TTL --ttl-set 65
```

#### MAC ঠিকানা স্পুফিং

**উদ্দেশ্য**: গোপনীয়তার জন্য ডিভাইসের MAC ঠিকানা এলোমেলো করা

**যেভাবে কাজ করে**:
- **wlan0** (WiFi ইন্টারফেস)-এর MAC ঠিকানা বদলায়
- **এলোমেলো MAC ঠিকানা** তৈরি করে বা নিজস্ব ঠিকানা দেওয়ার সুযোগ দেয়
- একাধিক সেশনে ডিভাইস **ট্র্যাক করা কঠিন** করে

**ব্যবহার**: সংযুক্ত নেটওয়ার্কে MAC-ভিত্তিক ট্র্যাকিং ঠেকানো

**ধাপ**:
1. ইন্টারফেস বন্ধ হয়
2. নতুন MAC ঠিকানা প্রয়োগ হয়
3. ইন্টারফেস আবার চালু হয়
4. সংযোগ পুনরায় স্থাপিত হয়

#### DNS-ভিত্তিক AdBlock

**উদ্দেশ্য**: DNS স্তরে বিজ্ঞাপন ও ট্র্যাকার ব্লক করা

**যেভাবে কাজ করে**:
- **ব্লকলিস্ট** দিয়ে `/etc/hosts` ফাইল বদলায়
- তালিকার ডোমেইনগুলো **127.0.0.1** (localhost) ঠিকানায় মেলে
- **সংযুক্ত সব ডিভাইসে** বিজ্ঞাপন ব্লক করে

**ব্যবহার**: প্রতিটি ডিভাইসে আলাদা সেটআপ ছাড়াই পুরো নেটওয়ার্কে বিজ্ঞাপন ব্লক করা

**ব্লকলিস্টের উৎস**: সাধারণ বিজ্ঞাপন ও ট্র্যাকিং ডোমেইন (পরিবর্তনযোগ্য)

### 🔧 হ্যাকিং টুল

#### IMSI ক্যাচার শনাক্তকারী

**উদ্দেশ্য**: IMSI ক্যাচার বা **Stingray** ডিভাইসের ইঙ্গিত দেয় এমন অস্বাভাবিকতার জন্য সেল টাওয়ারের তথ্য পর্যবেক্ষণ

**যেভাবে কাজ করে**:
- মডেম থেকে **সেল টাওয়ারের তথ্য** নেয়:
  - **Cell ID** (টাওয়ারের শনাক্তকারী)
  - **LAC** (লোকেশন এরিয়া কোড)
  - **MCC/MNC** (মোবাইল কান্ট্রি ও নেটওয়ার্ক কোড)
  - **সিগন্যাল শক্তি** (RSSI)
  - **নেটওয়ার্কের প্রজন্ম** (2G/3G/4G)
- সন্দেহজনক টাওয়ার পরিবর্তন ধরতে **পরিবর্তন লগ করে**
- **স্বাভাবিক অবস্থা নির্ধারণ** করে এলাকার পরিচিত টাওয়ার চিহ্নিত করে

**শনাক্তকরণের লক্ষণ**:
- স্থির অবস্থায় **হঠাৎ সেল টাওয়ার বদলে যাওয়া**
- **2G-তে নেমে যাওয়া** *(এনক্রিপশন সরাতে IMSI ক্যাচার প্রায়ই 2G বাধ্যতামূলক করে)*
- **অজানা Cell ID** দেখা
- নকল টাওয়ার থেকে **দুর্বল সিগন্যাল**
- **বারবার পুনঃসংযোগ**

**RayHunter-এর সঙ্গে সমন্বয়**: DagShell **সেল টাওয়ার পর্যবেক্ষণ** করে। RayHunter আরও উন্নত বিশ্লেষণ দিয়ে **বিশেষায়িত IMSI ক্যাচার শনাক্তকরণ** দেয় (পরের অংশ দেখুন)।

#### পোর্ট স্ক্যানার

**উদ্দেশ্য**: লক্ষ্য IP ঠিকানায় খোলা পোর্ট খোঁজা

**যেভাবে কাজ করে**:
- **TCP SYN স্ক্যান**: লক্ষ্য পোর্টে SYN প্যাকেট পাঠায়
- **টাইমআউট শনাক্তকরণ**: পোর্ট খোলা, বন্ধ নাকি ফিল্টার করা তা নির্ধারণ করে
- **রেঞ্জ সমর্থন**: একক পোর্ট বা পোর্টের পরিসর স্ক্যান করে

**ব্যবহার**:
- **নেটওয়ার্ক রিকনেসান্স**
- **IoT ডিভাইস খোঁজা**
- স্থানীয় নেটওয়ার্কের **নিরাপত্তা নিরীক্ষা**
- **সেবা শনাক্তকরণ**

**কমান্ড**:
```bash
# target-এর 1–1000 পোর্ট স্ক্যান করুন
nc -zv -w 2 TARGET_IP 1-1000 2>&1
```

#### ফায়ারওয়াল ব্যবস্থাপক

**উদ্দেশ্য**: iptables দিয়ে IP ঠিকানা ব্লক বা আনব্লক করা

**যেভাবে কাজ করে**:
- নির্দিষ্ট IP থেকে বা সেই IP-তে যাওয়া প্যাকেট DROP করতে **iptables নিয়ম** ব্যবহার করে
- সংরক্ষণ করলে **স্থায়ী নিয়ম** রিবুটের পরও থাকে
- **অনুমোদিত তালিকা ও ব্লকলিস্ট** সুবিধা

**ব্যবহার**:
- **ক্ষতিকর IP ব্লক করা**
- **অননুমোদিত প্রবেশ ঠেকানো**
- **ট্র্যাফিক নিয়ন্ত্রণ বা ফিল্টার করা**
- **অভিভাবকীয় নিয়ন্ত্রণ**

**কমান্ড**:
```bash
# IP ব্লক করুন
iptables -I INPUT -s IP_ADDRESS -j DROP
iptables -I OUTPUT -d IP_ADDRESS -j DROP

# IP ব্লক তুলে দিন
iptables -D INPUT -s IP_ADDRESS -j DROP
iptables -D OUTPUT -d IP_ADDRESS -j DROP
```

### ⚔️ আক্রমণের টুল

**গুরুত্বপূর্ণ আইনি সতর্কতা**: এই টুলগুলো **শুধু অনুমোদিত নিরাপত্তা পরীক্ষার জন্য**। নিজের নয় বা স্পষ্ট লিখিত অনুমতি নেই এমন নেটওয়ার্কে ব্যবহার করা অনেক অঞ্চলে **অবৈধ** (যুক্তরাষ্ট্রের Computer Fraud and Abuse Act, যুক্তরাজ্যের Computer Misuse Act ইত্যাদি)। শুধু **নিজের নেটওয়ার্কে** বা **নিয়ন্ত্রিত ল্যাব পরিবেশে** ব্যবহার করুন।

#### DNS স্নিফার

**উদ্দেশ্য**: সংযুক্ত ক্লায়েন্টদের DNS কোয়েরি লগ করা

**যেভাবে কাজ করে**:
- DNS-এর port 53-এ **iptables লগিং**
- **প্রমিসকুয়াস মোড লাগে না**
- হটস্পট ক্লায়েন্টদের সব DNS অনুরোধ লগ করে
- ক্লায়েন্ট **কোন ওয়েবসাইট ও সেবা** ব্যবহার করছে তা প্রকাশ করে

**অনুমোদিত ব্যবহার**:
- **নেটওয়ার্ক ট্র্যাফিক বিশ্লেষণ**
- **নিজের পরিবারের অভিভাবকীয় পর্যবেক্ষণ**
- নিজের ডিভাইসে **নিরাপত্তা গবেষণা**
- **ম্যালওয়্যারের আচরণ বিশ্লেষণ**

*এটি সংযুক্ত ক্লায়েন্টদের ভিজিট করা ডোমেইনের মতো মেটাডেটা সংগ্রহ করে। শুধু নিজের বা পরিচালিত নেটওয়ার্কে ব্যবহার করুন।*

#### ARP স্ক্যানার

**উদ্দেশ্য**: স্থানীয় নেটওয়ার্কে ডিভাইস খোঁজা

**যেভাবে কাজ করে**:
- সাবনেটের সব IP-তে **ARP অনুরোধ** পাঠায়
- ডিভাইসগুলো তাদের **MAC ঠিকানা** দিয়ে জবাব দেয়
- **OUI অনুসন্ধান** প্রস্তুতকারক শনাক্ত করে (Apple, Samsung ইত্যাদি)
- সক্রিয় ডিভাইসের **নেটওয়ার্ক মানচিত্র** তৈরি করে

**ব্যবহার**:
- **নেটওয়ার্ক তালিকা তৈরি**
- **অজানা ডিভাইস শনাক্তকরণ**
- **BYOD নেটওয়ার্ক বিশ্লেষণ**
- **IoT ডিভাইস খোঁজা**

**নমুনা ফলাফল**:
```
IP: 192.168.1.50
MAC: A4:83:E7:XX:XX:XX
Vendor: Apple, Inc.

IP: 192.168.1.75
MAC: 2C:54:91:XX:XX:XX
Vendor: Samsung Electronics
```

#### Traceroute

**উদ্দেশ্য**: গন্তব্য পর্যন্ত নেটওয়ার্ক পথ দেখানো

**যেভাবে কাজ করে**:
- **ক্রমবর্ধমান TTL**-সহ প্যাকেট পাঠায়
- প্রতিটি hop TTL কমায় এবং **ICMP Time Exceeded** ফেরত দেয়
- গন্তব্যের **রাউটার ও পথ** প্রকাশ করে
- প্রতিটি hop-এর **Round-Trip Time (RTT)** মাপে

**ব্যবহার**:
- **নেটওয়ার্ক সমস্যা নির্ণয়**
- **রুট বিশ্লেষণ**
- **লেটেন্সি নির্ণয়**
- **ISP peering তদন্ত**

#### Evil Twin AP

**উদ্দেশ্য**: বিদ্যমান SSID নকল করে নকল WiFi অ্যাক্সেস পয়েন্ট তৈরি

**যেভাবে কাজ করে**:
- **wlan1** ব্যবহার করে (Pi সহায়ক থাকলে দ্বিতীয় WiFi ইন্টারফেস)
- লক্ষ্য নেটওয়ার্কের **SSID ও এনক্রিপশন ধরন** নকল করে
- সংযোগের চেষ্টা করা **ক্লায়েন্টদের ধরে**
- পরিচয়পত্র সংগ্রহে **ক্যাপটিভ পোর্টাল** দেখায়

**আক্রমণের ধাপ** (ল্যাব পরিবেশ):
1. বৈধ WiFi নেটওয়ার্ক স্ক্যান করুন
2. একই SSID-সহ **নকল AP** তৈরি করুন
3. প্রকৃত AP থেকে ক্লায়েন্টদের বিচ্ছিন্ন করতে **ডিঅথ আক্রমণ** চালান
4. ক্লায়েন্টরা স্বয়ংক্রিয়ভাবে **নকল AP-তে** আবার যুক্ত হয়
5. ক্যাপটিভ পোর্টাল পরিচয়পত্র সংগ্রহ করে

*শনাক্তকরণ: দুটি AP একই সময়ে দেখা গেলে ক্লায়েন্টরা **একই SSID-এর একাধিক কপি** দেখতে পায়।*

#### ক্যাপটিভ পোর্টাল

**উদ্দেশ্য**: পরিচয়পত্র সংগ্রহের ফিশিং পৃষ্ঠার টেমপ্লেট

**যে টেমপ্লেটগুলো আছে**:
- **WiFi লগইন পৃষ্ঠা** (সাধারণ ISP বা হোটেলের ধাঁচে)
- **সামাজিক মাধ্যমের লগইন** (Facebook, Twitter, Instagram-এর নকল)
- **করপোরেট লগইন** পোর্টাল
- **বিমানবন্দর ও কফিশপের** WiFi গেট

**যেভাবে কাজ করে**:
1. Evil Twin AP **সব ট্র্যাফিক** পোর্টালে পাঠায়
2. ক্লায়েন্ট **লগইন পৃষ্ঠা** দেখে
3. ক্লায়েন্ট পরিচয়পত্র লেখে
4. পরিচয়পত্র **ফাইলে লগ হয়**
5. ক্লায়েন্ট ইন্টারনেট পায় বা ত্রুটি বার্তা দেখে

**শিক্ষামূলক উদ্দেশ্য**: **সোশ্যাল ইঞ্জিনিয়ারিংয়ের ঝুঁকি** এবং URL যাচাইয়ের গুরুত্ব দেখানো

### 📍 GPS ট্র্যাকার ও ওয়ারড্রাইভিং

#### GPS সুবিধা

**GPS উৎস**: শুধু **Raspberry Pi সহায়ক**
- *Orbic RCL400-এ **GPS বিল্ট-ইন নেই**। Pi সহায়ক না থাকলে অবস্থানের তথ্যও থাকবে না।*
- Pi-তে **USB GPS ডঙ্গল** যুক্ত হয় (U-Blox 7 চিপসেট সুপারিশ করা হয়)
- **শেয়ার করা ডেটা ফাইল** দিয়ে Pi Orbic-এ স্থানাঙ্ক পাঠায়
- **ECEF থেকে অক্ষাংশ/দ্রাঘিমাংশ** রূপান্তর স্বয়ংক্রিয়ভাবে হয়

**ড্যাশবোর্ডে প্রদর্শন**:
- দশমিক ডিগ্রিতে **অক্ষাংশ/দ্রাঘিমাংশ**
- সমুদ্রপৃষ্ঠ থেকে **উচ্চতা**
- **GPS ফিক্সের অবস্থা** (নির্ভুলতা)
- প্রতি ৫ সেকেন্ডে **স্বয়ংক্রিয় রিফ্রেশ**
- **ব্রাউজারের অবস্থান অনুমতি চায় না** (ব্রাউজার API ব্যবহার করে না)

**শেয়ার করা GPS অবস্থা**:
- GPS ডেটা **DagShell-এর সব প্রক্রিয়ায়** পাওয়া যায়
- ওয়ারড্রাইভিং স্বয়ংক্রিয়ভাবে GPS ব্যবহার করে
- ফিচারগুলোর মধ্যে সংঘাত হয় না

#### ওয়ারড্রাইভিং মোড

**উদ্দেশ্য**: মানচিত্র তৈরির জন্য GPS স্থানাঙ্কসহ WiFi নেটওয়ার্ক স্ক্যান করা

**যেভাবে কাজ করে**:
1. **বৈধ GPS ফিক্সের** জন্য অপেক্ষা করে (0,0 স্থানাঙ্ক লগ হয় না)
2. একটানা প্রতি **৫ সেকেন্ডে** WiFi নেটওয়ার্ক স্ক্যান করে
3. নেটওয়ার্কের তথ্য লগ করে:
   - **SSID** (নেটওয়ার্কের নাম)
   - **BSSID** (MAC ঠিকানা)
   - **এনক্রিপশন ধরন** (WPA2, WPA3, খোলা)
   - **সিগন্যালের শক্তি** (dBm-এ RSSI)
   - **চ্যানেল নম্বর**
   - **GPS স্থানাঙ্ক** (অক্ষাংশ/দ্রাঘিমাংশ)
   - **সময়চিহ্ন**
4. **Wigle-সামঞ্জস্যপূর্ণ CSV** ফরম্যাটে রপ্তানি করে

**Wigle সংযোগ**:
- **WiGLE** (wigle.net) বিশ্বব্যাপী WiFi মানচিত্র প্রকল্প
- DagShell CSV সরাসরি **WiGLE-এ আপলোড করা যায়**
- Files পৃষ্ঠা থেকে **ব্রাউজারে আপলোড** (বাইরের টুল লাগে না)
- WiFi অবস্থানের **সর্বজনীন ডেটাবেসে** অবদান রাখে

**ব্যবহার**:
- **WiFi কভারেজ ম্যাপিং**

### 🥧 Raspberry Pi সহায়ক

**Raspberry Pi সহায়ক** বাইরের **হার্ডওয়্যার** দিয়ে DagShell-এর সুবিধা বাড়ায়।

**ন্যূনতম**:

- **পাওয়ার সাপ্লাই** *(Pi-র আলাদা বিদ্যুৎ দরকার, Orbic-এর USB পোর্টে যথেষ্ট শক্তি নেই)*

#### WiFi স্ক্যানিং

**উদ্দেশ্য**: Pi WiFi নেটওয়ার্ক স্ক্যান করে এবং Orbic-এ ডেটা পাঠায়

**সুবিধা**: আলাদা ইন্টারফেসে স্ক্যান হয়, আর **Orbic হটস্পট চালু রাখে**

**যেভাবে কাজ করে**:
- সংযোগের জন্য প্রয়োজন না হলে Pi **দ্বিতীয় WiFi অ্যাডাপ্টার** বা বিল্ট-ইন WiFi ব্যবহার করে
- সমর্থিত হলে **সব চ্যানেল** স্ক্যান করে (2.4GHz-এ 1-14, 5GHz-এ 36-165)
- শেয়ার করা স্টোরেজে ফলাফল Orbic-এ পাঠায়
- DagShell **ওয়ারড্রাইভ CSV-তে** লগ করে

**সমন্বয়**:
- Pi ও Orbic GPS সময়ের সঙ্গে **সমন্বিত হয়**
- একই এন্ট্রি বারবার তৈরি হওয়া ঠেকায়
- **দুই স্ক্যানের উৎস** এক লগে মেশায়

#### ডিঅথ আক্রমণ

**উদ্দেশ্য**: WiFi নেটওয়ার্ক থেকে ক্লায়েন্ট বিচ্ছিন্ন করা (ল্যাবে পরীক্ষার জন্য)

**যেভাবে কাজ করে**:
- **802.11 ডিঅথেনটিকেশন ফ্রেম** পাঠায়
- **AP-র MAC ঠিকানা** নকল করে
- ক্লায়েন্ট AP থেকে সংযোগ বিচ্ছিন্ন হওয়ার বার্তা পায়
- ক্লায়েন্ট **সংযোগ হারিয়ে** আবার যুক্ত হওয়ার চেষ্টা করে

**নিয়ন্ত্রণের পদ্ধতি**:
- **একবারের ডিঅথ**: এক দফা ফ্রেম পাঠায়
- **অবিরাম ডিঅথ**: পুনঃসংযোগ আটকে দেয় (DoS)
- **দূরবর্তী নিয়ন্ত্রণ**: DagShell স্ক্যান পৃষ্ঠা থেকে চালু হয়

**অনুমোদিত ব্যবহার**:
- নিজের নেটওয়ার্ক থেকে **অননুমোদিত ডিভাইস সরানো**
- অনুমতি নিয়ে **পেনেট্রেশন টেস্টিং**
- ল্যাবে **Evil Twin আক্রমণ** (ক্লায়েন্টকে নকল AP-তে পাঠানো)

**⚠️ আইনি সতর্কতা**: নিজের নয় এমন নেটওয়ার্কে ডিঅথ আক্রমণ **অবৈধ**। FCC লঙ্ঘন ও CFAA-র অধীনে অভিযোগ হতে পারে।

#### স্বয়ংক্রিয়-চালু সেবা

**systemd সেবা**: Pi সহায়ক বুটের সময় স্বয়ংক্রিয়ভাবে চলে

**সেবা ফাইল** (`/etc/systemd/system/pi-companion.service`):
```ini
[Unit]
Description=DagShell Pi Companion
After=network.target

[Service]
ExecStart=/usr/bin/python3 /opt/dagshell/pi_companion.py
Restart=always
User=root

[Install]
WantedBy=multi-user.target
```

**কমান্ড**:
```bash
# স্বয়ংক্রিয় চালু সক্রিয় করুন
sudo systemctl enable pi-companion

# সার্ভিস চালু করুন
sudo systemctl start pi-companion

# অবস্থা দেখুন
sudo systemctl status pi-companion
```


**আউটপুট**: `orbic_app` (স্থির ARM বাইনারি) ও DER সার্টিফিকেট ফাইল

**⚠️ macOS-এর নোট**: `gcc_mac/` ফোল্ডারে **crosstool-ng** দিয়ে তৈরি কাস্টম ARM টুলচেইন আছে। এটি Orbic-এর kernel 3.18-এর সঙ্গে সামঞ্জস্যের জন্য **Linux kernel 3.2** হেডার লক্ষ্য করে। *Homebrew-এর সাধারণ ARM কম্পাইলার নতুন kernel লক্ষ্য করে এবং **কাজ করবে না**।*

#### ধাপ ৪: Orbic-এ Root Shell চালু করুন

```bash
# Orbic WiFi-তে সংযোগ করুন
# YOUR_ADMIN_PASSWORD-এর বদলে আসল পাসওয়ার্ড দিন

python enable_shell.py YOUR_ADMIN_PASSWORD
```

এই কমান্ড Orbic ওয়েব API কাজে লাগিয়ে **port 24-এ root shell** খোলে।

#### ধাপ ৫: ফার্মওয়্যার স্থাপন করুন

```bash
python deploy_base64.py
```

এটি আপলোড ও ইনস্টল করে:
- `orbic_app`-কে `/data/orbic_app`-এ
- সার্টিফিকেটগুলোকে `/data/root.der` ও `/data/server.der`-এ
- বুট স্ক্রিপ্টকে `/etc/rc.d/dagshell_boot.sh`-এ

**চালু থাকার ব্যবস্থা**: init স্ক্রিপ্টের মাধ্যমে রিবুটের পর ফার্মওয়্যার স্বয়ংক্রিয়ভাবে চলে।

#### ধাপ ৬: রিবুট করে প্রবেশ করুন

```bash
# Orbic রিবুট করুন (পাওয়ার সাইকেল বা SSH দিয়ে)
reboot

# রিবুটের পরে DagShell খুলুন
# ব্রাউজার: https://192.168.1.1:8443/
```

### নিরাপত্তা সার্টিফিকেটের সতর্কতা

DagShell খুললে **"Not Secure"** বা **"Not Trusted"** সতর্কতা দেখা যাবে:

**ডেস্কটপ ব্রাউজার**:
- **"Advanced"**-এ ক্লিক করুন
- **"Proceed to 192.168.1.1 (unsafe)"**-এ ক্লিক করুন

**মোবাইল ব্রাউজার**:
- **"Show Details"** চাপুন
- **"visit this website"** চাপুন

**এটি কেন হয়**:
- সার্টিফিকেটটি **স্ব-স্বাক্ষরিত** (Let's Encrypt-এর মতো বিশ্বস্ত CA থেকে নয়)
- ডিভাইসের trust store-এ root সার্টিফিকেট নেই
- *কাস্টম ফার্মওয়্যারে এটি **প্রত্যাশিত আচরণ**, অনুপ্রবেশের লক্ষণ নয়।*

**সংযোগ কি আসলেই নিরাপদ?**:
- **হ্যাঁ**। সংযোগটি **TLS 1.2 বা নতুন সংস্করণে** এনক্রিপ্ট করা
- ডেটা আটকানো যায় না
- *সার্টিফিকেটটি কোনো সর্বজনীন CA-র সঙ্গে বিশ্বাসের শৃঙ্খলে নেই, তবে এনক্রিপশন বাস্তব।*

**ঐচ্ছিক**: সতর্কতা সরাতে ডিভাইসের trust store-এ `root.der` ইনস্টল করুন।

## Raspberry Pi সহায়ক সেটআপ

সব সুবিধা পেতে এটি **ঐচ্ছিক কিন্তু জোরালোভাবে সুপারিশ করা হয়**।

### হার্ডওয়্যার সেটআপ

**ধাপ ১**: যন্ত্রাংশ সংগ্রহ করুন
- **Raspberry Pi 3B+** বা নতুন সংস্করণ ($35-55)
- U-Blox 7 চিপসেটসহ **USB GPS ডঙ্গল** ($15-30)
- Pi OS-এর জন্য **16GB বা বড় MicroSD কার্ড** ($10)
- Pi-র জন্য **পাওয়ার সাপ্লাই** ($10)

**ধাপ ২**: Raspberry Pi OS ইনস্টল করুন
```bash
# Raspberry Pi Imager ডাউনলোড করুন
# https://www.raspberrypi.org/software/

# SD কার্ডে Raspberry Pi OS Lite ফ্ল্যাশ করুন
# Pi চালু করে সেটআপ শেষ করুন
```

**ধাপ ৩**: GPS ডঙ্গল সংযোগ করুন
- Pi-তে USB GPS লাগান
- শনাক্তকরণ দেখুন: `lsusb` (GPS ডিভাইস দেখা উচিত)
- সিরিয়াল পোর্ট যাচাই করুন: `ls /dev/ttyUSB*` অথবা `ls /dev/ttyACM*`

### সফটওয়্যার ইনস্টলেশন

**ধাপ ১**: Pi-তে DagShell রিপোজিটরি ক্লোন করুন

```bash
git clone https://github.com/dagnazty/DagShell.git
cd DagShell/pi_companion
```

**ধাপ ২**: নির্ভরতা ইনস্টল করুন

```bash
# প্যাকেজ তালিকা আপডেট করুন
sudo apt-get update

# প্রয়োজনীয় প্যাকেজ ইনস্টল করুন
sudo apt-get install python3-serial python3-requests gpsd gpsd-clients

# Python মডিউল ইনস্টল করুন
pip3 install pyserial gps3 bluetooth pybluez
```

**ধাপ ৩**: GPS ডেমন কনফিগার করুন

```bash
# gpsd কনফিগ সম্পাদনা করুন
sudo nano /etc/default/gpsd

# DEVICES লাইনে আপনার GPS সিরিয়াল পোর্ট দিন
DEVICES="/dev/ttyUSB0"  # প্রয়োজনমতো বদলান

# gpsd পুনরায় চালু করুন
sudo systemctl restart gpsd

# GPS পরীক্ষা করুন
cgps -s  # প্রায় 30 সেকেন্ড পরে স্যাটেলাইট ডেটা দেখা উচিত
```

**ধাপ ৪**: Pi সহায়ক কনফিগার করুন

```bash
# কনফিগারেশন ফাইল সম্পাদনা করুন
nano pi_companion/config.py

# Orbic IP ঠিকানা সেট করুন
ORBIC_IP = "192.168.1.1"
ORBIC_PORT = "8443"

# GPS সিরিয়াল পোর্ট সেট করুন
GPS_DEVICE = "/dev/ttyUSB0"

# সংরক্ষণ করে বেরিয়ে যান
```

**ধাপ ৫**: systemd সেবা ইনস্টল করুন

```bash
# সার্ভিস ফাইল কপি করুন
sudo cp pi_companion.service /etc/systemd/system/

# systemd পুনরায় লোড করুন
sudo systemctl daemon-reload

# স্বয়ংক্রিয় চালু সক্রিয় করুন
sudo systemctl enable pi-companion

# সার্ভিস চালু করুন
sudo systemctl start pi-companion

# অবস্থা দেখুন
sudo systemctl status pi-companion
```

**ধাপ ৬**: যোগাযোগ যাচাই করুন

```bash
# লগ দেখুন
journalctl -u pi-companion -f

# Orbic-এ GPS স্থানাঙ্ক পাঠানো হচ্ছে দেখা উচিত
```

### নেটওয়ার্ক সেটআপ

**বিকল্প A**: WiFi সংযোগ

```bash
# Pi Orbic হটস্পটে সংযুক্ত হয়
# wpa_supplicant কনফিগ সম্পাদনা করুন
sudo nano /etc/wpa_supplicant/wpa_supplicant.conf

# নেটওয়ার্ক যোগ করুন
network={
    ssid="Orbic_SSID"
    psk="PASSWORD"
}

# WiFi পুনরায় চালু করুন
sudo systemctl restart networking
```

**বিকল্প B**: USB Ethernet (সুপারিশকৃত)

- **USB কেবল** দিয়ে Pi-কে Orbic-এ যুক্ত করুন (Pi-র USB পোর্ট থেকে Orbic-এর USB পোর্ট)
- Pi-তে **USB gadget mode** চালু করুন
- Pi **USB Ethernet ডিভাইস** হিসেবে কাজ করে
- *একটানা ডেটা স্থানান্তরে WiFi-এর চেয়ে এটি বেশি নির্ভরযোগ্য।*
- Pi Orbic-এর মাধ্যমে ইন্টারনেটে যায়

**USB Gadget কনফিগারেশন**:
```bash
# config.txt সম্পাদনা করুন
sudo nano /boot/config.txt

# শেষে যোগ করুন
dtoverlay=dwc2

# cmdline.txt সম্পাদনা করুন
sudo nano /boot/cmdline.txt

# rootwait-এর পরে যোগ করুন
modules-load=dwc2,g_ether

# রিবুট করুন
sudo reboot
```

### সমন্বিত ব্যবহার

#### ১. **IMSI ক্যাচারের বিরুদ্ধে পূর্ণ প্রতিরক্ষা**

**পরিস্থিতি**: উচ্চ নজরদারির এলাকায় ভ্রমণ

**DagShell-এর ভূমিকা**:
- **সেল টাওয়ার পরিবর্তন তাৎক্ষণিক পর্যবেক্ষণ**
- সন্দেহজনক পরিবর্তনের সময় **GPS অবস্থান ট্র্যাক**
- পরে বিশ্লেষণের জন্য **টাওয়ারের সব তথ্য লগ**

**RayHunter-এর ভূমিকা**:
- সেলুলার প্রোটোকলে **মেশিন লার্নিং-ভিত্তিক অস্বাভাবিকতা শনাক্তকরণ**
- জটিল আক্রমণ খুঁজতে **SS7/Diameter প্যাকেট পরিদর্শন**
- তুলনার জন্য পরিচিত নির্ভরযোগ্য টাওয়ারের **ডেটাবেস**

**সমন্বিত ফল**: DagShell দেয় **অবিরাম পর্যবেক্ষণ**, RayHunter দেয় **গভীর বিশ্লেষণ**।

#### ২. **নিরাপত্তাসহ ওয়ারড্রাইভিং**

**পরিস্থিতি**: শহুরে এলাকায় WiFi নেটওয়ার্কের মানচিত্র তৈরি

**DagShell-এর ভূমিকা**:
- GPS স্থানাঙ্কসহ **WiFi স্ক্যান**
- **নেটওয়ার্ক বিশ্লেষণ** (সিগন্যাল শক্তি, এনক্রিপশন)
- মানচিত্রের জন্য **Wigle CSV রপ্তানি**

**RayHunter-এর ভূমিকা**:
- ওয়ারড্রাইভিংয়ের সময় **সেল টাওয়ার ট্র্যাকিং**
- WiFi স্ক্যানের সময় **IMSI ক্যাচার শনাক্ত**
- সেলুলার নিরাপত্তা ঝুঁকিতে থাকলে **সতর্কতা**

**সমন্বিত ফল**: **সেলুলার নিরাপত্তা সম্পর্কে সচেতন** থেকে ওয়ারড্রাইভিং।

#### ৩. **নিরাপত্তা গবেষণাগার**

**পরিস্থিতি**: রেড টিম বা পেনেট্রেশন টেস্টিং

**DagShell-এর ভূমিকা**:
- WiFi পরীক্ষায় **Evil Twin AP**
- সোশ্যাল ইঞ্জিনিয়ারিং প্রদর্শনে **ক্যাপটিভ পোর্টাল**
- স্থিতিস্থাপকতা যাচাইয়ে **ডিঅথ আক্রমণ**
- **নেটওয়ার্ক রিকনেসান্স** টুল

**RayHunter-এর ভূমিকা**:
- পরীক্ষা চলাকালে **আপনাকে নজরদারি করা হচ্ছে কি না শনাক্ত**
- **সেল টাওয়ারের নিরাপত্তা** সম্পর্কে সচেতনতা
- পরীক্ষার সময় **পাল্টা নজরদারি** ঠেকাতে সহায়তা

**সমন্বিত ফল**: আক্রমণাত্মক টুলের সঙ্গে **প্রতিরক্ষামূলক সচেতনতা**।

#### ৪. **গোপনীয়তাকে অগ্রাধিকার দিয়ে ভ্রমণ**

**পরিস্থিতি**: সংবেদনশীল পরিবেশে সাংবাদিক বা কর্মী

**DagShell-এর ভূমিকা**:
- টেথারিং আড়াল করতে **TTL লুকানো**
- পরিচয় গোপন রাখতে **MAC স্পুফিং**
- ট্র্যাকিং ঠেকাতে **AdBlock**
- **IMSI ক্যাচার পর্যবেক্ষণ**

**RayHunter-এর ভূমিকা**:
- **উন্নত IMSI ক্যাচার শনাক্তকরণ**

- অ্যাডমিন পাসওয়ার্ড আবার দিন (বড়-ছোট অক্ষর আলাদা)
- port 80 খোলা কি না যাচাই করুন: `telnet 192.168.1.1 80`

**সমস্যা**: ফার্মওয়্যার আপলোড ব্যর্থ হয়

**সমাধান**:
- আগে root shell চালু হয়েছে নিশ্চিত করুন (`enable_shell.py` সফল হতে হবে)
- নেটওয়ার্কের স্থায়িত্ব দেখুন (সম্ভব হলে তারযুক্ত সংযোগ ব্যবহার করুন)
- `deploy_base64.py`-এর বদলে `deploy_net.py` চেষ্টা করুন
- `/data` পার্টিশনে জায়গা দেখুন: `df -h /data`

**সমস্যা**: সার্টিফিকেট সতর্কতা দূর হয় না

**সমাধান**:
- *স্ব-স্বাক্ষরিত সার্টিফিকেটে এটি **স্বাভাবিক**, সংযোগ এখনও এনক্রিপ্ট করা থাকে।*
- প্রতিবার "Advanced" > "Proceed anyway" নির্বাচন করুন
- **ঐচ্ছিক**: ডিভাইসের trust store-এ `root.der` ইনস্টল করুন (উন্নত পদক্ষেপ)

### চালানোর সমস্যা

**সমস্যা**: বুটের সময় DagShell শুরু হয় না

**সমাধান**:
- বুট স্ক্রিপ্ট দেখুন: `ls -la /etc/rc.d/dagshell_boot.sh`
- চালানোর অনুমতি যাচাই করুন: `chmod +x /etc/rc.d/dagshell_boot.sh`
- লগ দেখুন: `logread | grep dagshell`
- হাতে চালু করুন: `/data/orbic_app &`

**সমস্যা**: GPS কাজ করে না

**সমাধান**:
- **Pi সহায়ক** চলছে কি না দেখুন: `systemctl status pi-companion`
- GPS স্যাটেলাইট লক পেয়েছে কি না দেখুন: `cgps -s` (Pi-তে)
- GPS ডঙ্গল সংযুক্ত কি না দেখুন: `lsusb`
- *প্রথম চালুতে GPS-এর প্রাথমিক ফিক্স পেতে ৫-১০ মিনিট অপেক্ষা করুন। প্রথমবার বাইরে থাকলেও সময় বেশি লাগতে পারে।*

**সমস্যা**: ওয়ারড্রাইভিং লগ তৈরি করে না

**সমাধান**:
- শুরু করার আগে GPS ফিক্স হয়েছে নিশ্চিত করুন
- `/data`-তে লেখার অনুমতি আছে কি না দেখুন
- CSV তৈরি হচ্ছে কি না যাচাই করুন: `ls -la /data/wardrive_log.csv`
- WiFi ইন্টারফেস চালু আছে কি না দেখুন: `ifconfig wlan0`

**সমস্যা**: Pi সহায়ক Orbic-এর সঙ্গে যোগাযোগ করে না

**সমাধান**:
- নেটওয়ার্ক সংযোগ যাচাই করুন: `ping 192.168.1.1`
- কনফিগারেশন ফাইলে সঠিক IP আছে কি না দেখুন
- port 8443 খোলা কি না নিশ্চিত করুন: `telnet 192.168.1.1 8443`
- Pi সহায়কের লগ দেখুন: `journalctl -u pi-companion`

### কর্মক্ষমতার সমস্যা

**সমস্যা**: ওয়েব ইন্টারফেস ধীর বা আটকে যায়

**সমাধান**:
- ব্রাউজারের ক্যাশে পরিষ্কার করুন
- ব্রাউজার এক্সটেনশন বন্ধ করুন (বিজ্ঞাপন ব্লকারে সমস্যা হতে পারে)
- WiFi-এর বদলে Orbic-এ **তারযুক্ত** সংযোগ ব্যবহার করুন
- DagShell রিস্টার্ট করুন: `killall orbic_app && /data/orbic_app &`

**সমস্যা**: ওয়ারড্রাইভিং স্ক্যান বেশি সময় নেয়

- *দুর্বল GPS ফিক্সে স্ক্যান ধীর হয়, কারণ বৈধ স্থানাঙ্ক লগ না করা পর্যন্ত সিস্টেম অপেক্ষা করে।*
