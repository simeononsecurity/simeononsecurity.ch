**虚拟卡的核心功能是：它改变商户接收到的信息，而非银行所知的信息。** 这就是整个机制，理解它能解释你获得的保护以及未获得的保护。

大多数报道将虚拟卡视为通用隐私工具，忽略技术细节。本文涵盖卡上存储的内容、为何磁条是薄弱环节，以及 Privacy.com 卡类型的实际表现。

*实际收益具体且真实：被盗号码对窃贼毫无用处，因为它仅在发卡商户处有效。*

## 简短回答

| 问题 | 简短回答 |
|---|---|
| **虚拟卡改变了什么？** | 商户存储的号码。您的真实卡信息不会传给他们 |
| **交易是私密的吗？** | 不是。您的银行、网络和发卡机构仍然能看到交易 |
| **什么防止泄露伤害您？** | 商户锁定或一次性使用号码，其他地方无法使用 |
| **实体卡最薄弱的部分是什么？** | 磁条，存储完整轨道数据且未加密 |
| **虚拟卡能建立信用吗？** | 不能。这些不是信用账户，也不会进行信用查询 |
| **谁有资格使用 Privacy.com？** | 美国公民或合法居民，18岁以上，拥有美国银行或信用合作社的支票账户 |

## 支付卡上有什么

**无卡交易授权依赖三项内容：主账号、有效期和验证值。**

| 元素 | 长度 | 来源 |
|---|---|---|
| **主账号（PAN）** | 最多19位数字 | 由发卡机构提供，前导数字标识卡组织和银行 |
| **有效期** | 四位数字，格式为 MM/YY | 由发卡机构提供 |
| **CVV 或 CVC** | 三或四位数字 | 由 PAN、有效期和仅发卡机构持有的密钥生成 |
| **持卡人姓名** | 最多26个字符 | 仅出现在磁条轨道1上 |

**主账号不是随机字符串。** 首位数字标识卡组织，接下来的几位标识发卡银行，剩余部分标识账户。结构使得卡号可在无需联系任何方的情况下进行合理性校验，Luhn 校验位能捕捉单个数字错位。

**CVV 证明持卡人在发卡时实际持有该卡。** 它不存储在磁条上，这正是盗刷器复制磁条时无法获得 CVV 的原因。

*您可以使用 **[磁条解码器和编码器](/magnetic-stripe-decoder/)** 自行检查所有这些内容，它能解析轨道1和轨道2，解码服务代码数字，并重新编码结果。该工具完全在浏览器中运行，这很重要，因为它展示了支付卡的完整内容。*

## 为什么磁条是薄弱环节

**磁条以明文存储账户数据，任何兼容读卡器都能读取。**

磁条最多包含三条轨道。轨道1携带主账号、持卡人姓名、有效期和三位服务代码，是唯一包含字母文本的轨道。轨道2以更密集的数字编码携带主账号、有效期和服务代码，**几乎所有销售点终端读取的都是轨道2。**轨道3实际上未被主要网络使用，且通常卡上根本没有轨道3。

服务代码值得了解，因为它描述了卡的允许用途。第一位数字涵盖交换规则，第二位涵盖授权处理，第三位涵盖服务范围。编码为 `201` 的卡允许国际交换，无需特殊授权路径，且无服务限制。

历史解释了磁条为何存在如此之久。1969年，IBM 工程师 Forrest Parry 试图将磁带粘贴到塑料卡上，但无法粘牢且不损坏磁带。他妻子建议用熨斗加热，热量使磁带粘合到卡上。这一临时方案成为了半个多世纪的标准。

两项发展正在终结它：

| 里程碑 | 状态 |
|---|---|
| **万事达宣布移除磁条** | 到2033年，所有万事达信用卡和借记卡将不再带磁条 |
| **欧洲** | 2024年起，万事达卡开始逐步取消磁条 |
| **美国** | 银行将从2027年起停止发放带磁条的卡 |

*磁条被芯片和非接触支付取代，因为复制磁条不需要除拥有读卡器外的任何技能。我们的 **[磁条工具](/magnetic-stripe-decoder/)** 展示了重建有效轨道所需的数据之少。*

## 如何读取轨道数据

**磁条字符串是一系列字段，而非第二个卡号。** 读卡器找到起始符，分隔字段，读取有效期和服务代码，然后检查结束符和纵向冗余校验（LRC）。

| 轨道 | 开始 | 主要字段 | 结束 | 字符集 |
|---|---|---|---|---|
| **轨道 1** | `%` | 格式代码，主账号，姓名，有效期，服务代码，自定义数据 | `?` 加上 LRC | 六位 ALPHA，因此包含字母 |
| **轨道 2** | `;` | 主账号，有效期，服务代码，自定义数据 | `?` 加上 LRC | 四位 BCD，因此包含数字和少量标点符号 |

可选的哨兵标识物理记录边界。解码器通常在显示字段时省略它们，但物理编码器需要读卡器期望的完整记录格式。

### 轨道 1 示例

这是一个合成示例。它使用工具中的标准测试主账号和虚假姓名、有效期、服务代码及自定义数据。它不是 Privacy.com 卡，也不是有效的支付数据。

```text
%B4111111111111111^TEST/USER^2912501000000000?
```

从左到右读取：

| 段 | 值 | 含义 |
|---|---|---|
| **开始哨兵** | `%` | 轨道 1 记录开始 |
| **格式代码** | `B` | 金融卡格式 B |
| **主账号** | `4111111111111111` | 合成主账号 |
| **字段分隔符** | `^` | 主账号结束，姓名开始 |
| **姓名** | `TEST/USER` | 姓氏，分隔符，名字 |
| **字段分隔符** | `^` | 姓名结束，交易字段开始 |
| **有效期** | `2912` | 2029年12月，格式为 YYMM |
| **服务代码** | `501` | 国家交换，正常处理，无限制 |
| **自定义数据** | `0000000` | 本例中发行者定义的填充数据 |
| **结束哨兵** | `?` | 轨道 1 数据在 LRC 之前结束 |

真实编码记录在结束哨兵后还带有一个 LRC 字符，当读卡器需要时。可见文本形式有助于研究结构。位级表示还包含每个字符的奇校验位。

### 轨道 2 示例

轨道 2 去掉了姓名和格式代码。相同的合成值变为：

```text
;4111111111111111=291250100000000?
```

| 段 | 值 | 含义 |
|---|---|---|
| **开始哨兵** | `;` | 轨道 2 记录开始 |
| **主账号** | `4111111111111111` | 合成主账号 |
| **分隔符** | `=` | 主账号结束，交易字段开始 |
| **有效期** | `2912` | 2029年12月，格式为 YYMM |
| **服务代码** | `501` | 与轨道 1 相同的合成服务代码 |
| **自定义数据** | `0000000` | 本例中发行者定义的填充数据 |
| **结束哨兵** | `?` | 轨道 2 数据在 LRC 之前结束 |

**轨道 2 较短，因为它没有持卡人姓名。** 许多终端在普通刷卡交易中读取轨道 2，而轨道 1 在读卡器请求时提供姓名字段。

### 服务代码数字

**三个服务代码数字描述终端和授权行为。** 它们不包含 CVV，未经发行者授权更改真实卡上的这些数字会导致支付凭证格式错误或误导。

| 数字 | 值 | 描述内容 |
|---|---|---|
| **第一位** | `0`, `1`, `2`, `5`, `6`, `7`, `9` | 交换规则和芯片偏好 |
| **第二位** | `0`, `1`, `2`, `4` | 授权路径 |
| **第三位** | `0` 到 `7` | PIN、现金、商品与服务限制 |

**第一位数字** 涵盖交换和芯片偏好：

| 值 | 含义 |
|---|---|
| `0` | 国家使用 |
| `1` | 允许国际交换 |
| `2` | 国际交换，尽可能使用 IC（芯片） |
| `5` | 仅限国家交换，除非有双边协议 |
| `6` | 仅限国家交换，除非有双边协议，尽可能使用 IC |
| `7` | 除非有双边协议，否则不交换（闭环） |
| `9` | 测试 |

**第二位数字** 涵盖授权处理：

| 值 | 含义 |
|---|---|
| `0` | 正常授权 |
| `1` | 正常授权 |
| `2` | 通过在线方式联系发行者 |
| `4` | 除非有双边协议，否则通过在线方式联系发行者 |

**第三位数字** 涵盖服务限制：

| 值 | 含义 |
|---|---|
| `0` | 无限制，需 PIN |
| `1` | 无限制 |
| `2` | 仅商品和服务（无现金） |
| `3` | 仅 ATM，需 PIN |
| `4` | 仅现金 |
| `5` | 仅商品和服务（无现金），需 PIN |
| `6` | 无限制，尽可能使用 PIN |
| `7` | 仅商品和服务（无现金），尽可能使用 PIN |

例如，`201` 表示国际交换，尽可能使用芯片，正常授权处理，无服务限制。解码器分别显示每位数字，无需记忆表格。

### LRC 和奇偶校验

**LRC 是校验字符，不是另一个需要发明的字段。** 编码器对从开始哨兵到结束哨兵的每个字符的数据值进行异或运算。然后将结果转换回轨道的可打印字符范围，并单独报告编码的奇校验位。

轨道 1 使用六位 ALPHA 字符集。其数据值是 ASCII 码减去 `0x20`。轨道 2 使用四位 BCD 字符集。其数据值是 ASCII 码的低半字节。将轨道 1 映射应用于轨道 2 会产生错误的 LRC。

解码器的 **包含计算的 LRC** 选项会将可打印的 LRC 字符添加到输出。其分解还显示带奇校验的 LRC 位模式。使用此功能学习读卡器如何校验记录，而非绕过发行者控制。

## 编写合成卡用于测试

**使用解码器编写测试字符串，不要用于真实支付卡。** 该工具接受字段，重建轨道 1 和轨道 2，添加可选哨兵，并计算 LRC。它在浏览器本地运行。

1. 打开 **[磁条解码器和编码器](/magnetic-stripe-decoder/)**。
2. 选择 **加载测试卡**。这会填充工具中的合成主账号（PAN）`4111111111111111`、姓名`TEST/USER`、有效期`2912`、服务代码`201`和测试专用数据。
3. 启用 **包含起始和结束哨兵** 以显示物理记录边界。
4. 启用 **包含计算的LRC** 以附加计算出的校验字符。
5. 仅启用 **将专用数据拆分为PVKI、PVV和CVV**，以查看九位数字合成字段的显示方式。这些标签是发行方的惯例，不是通用的轨道1或轨道2布局。
6. 更改姓名、有效期、服务代码或合成专用数据。输出会随着输入实时更新。
7. 比较解码字段与生成的字符串。完成后清除字段。

对于合成轨道1练习，请使用：

```text
PAN: 4111111111111111
Surname: TEST
First name: USER
Expiry: 12/29
Service code: 201
Discretionary data: 000000000
```

对于合成轨道2练习，使用相同的主账号、有效期、服务代码和数字专用字段。生成的轨道2字符串省略了姓名，因为轨道2没有姓名字段。

**请勿将真实的Privacy.com主账号、有效期、CVV或专用值复制到可写卡中。** Privacy.com将其产品描述为通过其网站或应用创建的虚拟卡号。其官方页面未将该服务描述为磁条写入系统，而虚拟卡号并非发行方授权的物理磁条记录的证明。包含真实凭证的可写测试卡会创建重复的支付工具，违反发行方条款或支付规则。

安全边界很简单：使用工具内置的合成样本，使用带有虚拟值的实验室卡，以及在需要现场支付时使用发行方批准的实体卡。不要试图将Privacy.com虚拟卡变成实体刷卡卡。

## 虚拟卡改变了什么

**虚拟卡是一个替代真实卡号的第二个号码。**

使用虚拟卡支付时，商户收到的是属于虚拟卡的号码、有效期和CVV。您的真实主账号不会传递给他们。实际上，这种变化在数据泄露后体现得尤为明显：

| 场景 | 使用您的真实卡 | 使用商户锁定的虚拟卡 |
|---|---|---|
| **商户数据库泄露** | 该号码在所有接受的地方有效 | 该号码在其他商户处均无效 |
| **您取消的订阅** | 继续收费直到您提出异议 | 您关闭卡后收费失败 |
| **试用期静默转换** | 账单上出现不想要的收费 | 限额或关闭阻止收费 |
| **卡信息在论坛出售** | 可用于无卡支付欺诈 | 仅限一个商户使用（如果能用） |

**它未改变的部分同样重要。** 您的银行仍然能看到交易。卡网络仍然处理交易。发行方仍然掌握您的身份信息，因为反洗钱法规要求验证。**虚拟卡减少的是商户端的风险暴露。它不是匿名消费的方式。**

*这个区别经常让人混淆。如果您的威胁模型包括发行方或网络，虚拟卡对此没有任何改变。*

## 三种卡片形态

术语使用不统一，选择交给商户的卡片类型时差异很重要。

| 类型 | 卡号 | 实体版本 | 典型用途 |
|---|---|---|---|
| **数字卡** | 与您的实体卡相同 | 有 | 将现有卡添加到移动钱包 |
| **虚拟卡** | 与任何实体卡不同 | 无 | 在线购物、订阅、一次性商户 |
| **数字优先卡** | 不同，带可选关联实体卡 | 可选 | 金融科技账户，实体卡无印刷信息 |

**移动钱包使用的是完全不同的第四种机制。** 当您将卡添加到钱包时，钱包存储的是设备专用令牌而非主账号，商户收到的是该令牌。这称为令牌化，这也是为什么即使没有虚拟卡，用手机支付比直接交出塑料卡更安全的原因。

*网络令牌化和虚拟卡解决了同一问题的不同部分。令牌化保护传输和存储中的号码。虚拟卡保护您免受商户后续保留信息的风险。*

## Privacy.com卡类型

**Privacy.com提供四种卡行为，它们不可互换。**

| 卡类型 | 行为 | 最适合 |
|---|---|---|
| **一次性使用** | 一次交易后自动关闭 | 一次性购买和不熟悉的商户 |
| **商户锁定** | 锁定首次使用的商户，其他商户失败 | 日常在线购物 |
| **类别锁定** | 限制在特定消费类别 | 控制某一类消费 |
| **通用卡** | 具有相同保护模型的实体卡 | 现场购物 |

**商户锁定是最有价值的机制。** 锁定卡在首次使用的商户之外均无法使用，这意味着商户泄露后该号码在其他地方无效。

**一次性使用是更强的选项。** 一次收费后关闭的卡无法被重放，也免去了后续关闭的麻烦。

两个值得了解的操作细节：

- **共享卡锁定在首次使用的商户**，因此与家人或员工共享时仍受商户限制。
- **卡是暂停而非关闭。** 暂停是可逆的，适合暂时停止订阅而不丢失卡信息。

## 支出限额和控制

**每张卡都有支出限额，这是与商户锁定不同的控制措施。**

| 控制 | 防止的情况 |
|---|---|
| **单笔交易限额** | 超出授权的单笔收费 |
| **月度限额** | 计费周期内累计收费 |
| **暂停** | 任何收费，且可逆 |
| **关闭** | 任何未来收费，永久 |

**对任何绑定订阅的卡设置单笔和月度限额。** 商户悄悄涨价时触及限额而非余额，您会通过失败的收费而非缺失账单行察觉。

*我们的**[个人理财安全](/personal-security-course/personal-finance/)**模块将此与信用冻结和卡令牌化并列，作为限制单一受损商户风险的三大控制措施。*

| **Premium** | $25/月 | 包含 Pro 的所有功能，且每月卡片创建上限提升至 60 张 |

**免费套餐涵盖核心安全优势。** 商户锁定、一次性卡和消费限额是减少风险的机制，且无需付费即可使用。付费套餐增加的是组织和便利性，而非额外保护。

**外币交易手续费因套餐而异。** 免费套餐对外币交易收取 3% 费用，最低 $0.50，付费套餐则无此费用。

## Privacy.com 不提供的功能

**明确限制比列出功能更有用。**

| 限制 | 详情 |
|---|---|
| **不提供匿名** | 注册时需验证身份，发行方持有身份信息 |
| **不隐藏交易信息给银行** | 银行看到资金转账，网络看到消费记录 |
| **不建立信用记录** | 不是信用账户，无信用查询 |
| **仅限美国用户** | 需美国公民或合法居民身份及美国银行或信用合作社账户 |
| **需身份验证** | 反洗钱法规要求必须进行客户身份识别（KYC） |
| **不支持所有商户** | 部分商户会屏蔽预付卡和虚拟卡号段 |

**商户屏蔽问题在实际中很重要。** 一些订阅服务和航空公司会拒绝他们认为是虚拟卡或预付卡的卡号段，且无法通过配置解决。请保留一张实体卡作为备用。

*诚实总结：虚拟卡是控制商户端风险的手段，不是匿名工具。如果需要匿名，这是不同的问题，需要不同的工具。*

## 谁发行卡片及其重要性

**虚拟卡仍然是真实卡，由真实银行发行，持有真实的卡组织许可。**

| 详情 | 内容 |
|---|---|
| **发行银行** | Patriot Bank, N.A., FDIC 成员 |
| **卡组织许可** | Mastercard 和 Visa |
| **接受范围** | Mastercard 和 Visa 接受的任何地方 |
| **资金来源** | 从您关联的美国支票账户转账 |

**这就是保护真实有效的原因。** 该卡享有与任何 Mastercard 或 Visa 产品相同的卡组织保护，包括拒付权利和欺诈争议流程。它不是礼品卡或封闭循环的商店信用卡。

值得提及的两个认证，因为它们是独立可验证的，而非营销声明：

- **PCI-DSS 合规性**，支付卡行业处理持卡人数据的标准
- **SOC 2 类型 II**，涵盖一段时间内安全控制的审计报告，而非单点时间声明

**关于商业模式：** 公司声明其收入来自商户的交换费，不向广告商或第三方出售客户数据。这与其他卡发行商的收入模式相同，值得理解，而非视为异常。

*实际检查发行银行的原因是验证。任何人都可以声称运营卡计划，卡上的发行银行名称是您与文件中银行名称核对的依据。*

使用 **[磁条解码器](/magnetic-stripe-decoder/)** 检查卡号前缀，报告主要卡组织范围并验证 Luhn 校验位。

## 如何有效使用虚拟卡

**控制措施只有配置后才有效。** 六个习惯带来大部分好处。

1. **除非有特殊原因，否则锁定每张卡到指定商户。** 锁定使泄露的卡号无用。
2. **对不熟悉的商户使用一次性卡，** 包括试用和小型网站的一次性购买。
3. **为订阅卡设置双重消费限额，** 这样价格上涨时交易会失败而非扣款。
4. **以商户名称命名每张卡，** 使交易列表清晰，异常消费易于发现。
5. **计划恢复服务时暂停卡片，** 不再使用时关闭卡片。
6. **为拒绝虚拟卡号段的商户保留一张实体卡，** 避免结账被阻成为紧急情况。

> **常见错误：将虚拟卡当作监控账单的替代。** 商户锁定防止一种风险，但无法检测银行账户被攻破、未经授权的转账或实体卡上的欺诈消费。

## 关键要点

- **虚拟卡改变了商户存储的卡号。** 您的真实卡号不会传给商户，这是核心机制。
- **它不使交易私密。** 您的银行、网络和发行方仍然能看到交易，且必须进行身份验证。
- **商户锁定是最有价值的功能，** 泄露的卡号在其他地方无效。
- **免费套餐包含安全控制。** 付费套餐增加的是组织和便利性，而非保护。
- **磁条以明文存储卡数据，** 预计到 2033 年淘汰，美国银行将于 2027 年停止发行带磁条的卡。
- **CVV 不在磁条上，** 这就是为什么复制磁条的刷卡器仍缺少许多在线商户要求的信息。
- **部分商户拒绝虚拟卡号段。** 请保留实体卡作为备用。
- **验证发行银行，** 不要盲目信任卡计划声明，自己检查卡号前缀。
