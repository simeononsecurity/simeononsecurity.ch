**監視カメラの地図に146,526個の地点を載せました。そのうち少なくとも50,278件はBarco ClickShareプレゼンテーションシステムでした。会議室の機器が、見出しで「マッピング済みカメラ」とした数の3分の1以上を占めていました。**

これは私たちのプロジェクトであり、データパイプラインであり、私たちの誤りでした。Flock FinderはFlock Safetyカメラで観測されたMACアドレスプレフィックスを毎日WiGLEに照会し、完全な座標精度で結果を公開し、すべてを同じピンで表示していました。メタデータには`suspected`と記載され、ドキュメントにも誤検出への言及がありました。それでも、地図と見出しは確実な事実のように伝えていました。

**読者が得ること：**監査を再現し、観測と帰属を分け、ピンと見出しの両方に確信度を表示します。プレフィックスの一致は調査の手掛かりであり、カメラの証明ではありません。

SSID列の頻度ヒストグラムをようやく作成すると、数分でデータセットが問題を示しました。ClickShareは最大のカテゴリにすぎません。さらに6,099件の名前は`SMARTGATE_*`、3,801件は汎用WiFi Directプレフィックス`DIRECT-`で始まり、314件は正確に`AndroidAP`、138件は`Audi HUD`、133件は`MAX-PRINTER`でした。30件には別の検出器の判定文字列が含まれていました。合計すると、**60,793行、つまり41.5%が、元の監査で判明した他機器の命名ルールに一致しました。**

現在のFlock Finderは各記録に証拠クラスを付け、既知の他機器を既定の地図と見出しから除外し、フィルターを公開し、主要市場外の記録に印を付け、高確信度プレフィックスと受託製造業者のプレフィックスを分けています。この記事では、誤り、根拠、残る限界を記録します。

## コミュニティによるALPR検出の仕組み

コミュニティ製のFlock検出器は、通常3種類の無線証拠を組み合わせます。

1. **WiFi MAC/OUIプレフィックス。**グローバル管理MACアドレスの先頭バイトから、アドレスブロックの割当先を識別できる場合があります。
2. **WiFiの挙動。**SSID、ワイルドカードのプローブ要求、受信先アドレス、チャネルパターン、802.11情報要素の並びから、機器クラスを絞り込めます。
3. **Bluetoothの証拠。**メーカーIDやサービスUUIDから、製品やファームウェア世代が公開する無線機能を識別できます。

OUI照合が広まったのは、低コストで受動的だからです。安価なESP32はネットワークに接続せず、近くの802.11フレームを調べられます。[WiGLE](https://wigle.net/)のような履歴データベースを使えば、自前のスキャナーを設置せずに過去の観測を検索できます。

この手法はコミュニティの流れをたどっています。[DeFlock](https://deflock.org/)のマッピングと地域活動、[colonelpanichacks/flock-you](https://github.com/colonelpanichacks/flock-you)、フォークや関連プロジェクトである私たちの[flock-you-esp32](https://github.com/simeononsecurity/flock-you-esp32)、そしてプレフィックス一覧を世界規模のWiGLEデータに適用した[Flock Finder](https://github.com/simeononsecurity/flock-finder)です。

元の現場調査には明確な謝意を示すべきです。[@NitekryDPaul](https://github.com/NitekryDPaul)はプロミスキャスモードの調査で、実際のFlock機器上で30個のプレフィックスを観測しました。[DeFlockJoplin](https://github.com/DeflockJoplin/flock-you)は現場テストで1つを追加しました。これらの観測は正当なものでした。私たちの後続の誤りは、**「Flockカメラ上で観測された」を「Flockカメラだけに存在する」と扱ったことです。**

## 構造上の欠陥：OUIが示すのはサプライチェーン

IEEEはOUIを、ベンダー、メーカー、その他の組織に割り当てる24ビット識別子と定義しています。割当先が選ぶ別の24ビットと組み合わせてMACアドレスになります。[IEEE Registration Authority](https://standards.ieee.org/products-programs/regauth/)が登録情報を公開しています。

OUIが示すのはアドレスブロックの割当先です。完成品に印刷されたブランドとは限りません。受託製造業者は多くの顧客向けに無線モジュールを作ります。そのため、同じチップベンダーがカメラ、プロジェクター、プリンター、車両、ホビー用基板に使われることがあります。

一覧の登録情報にもリスクは表れていました。

| 登録者 | 監査対象の一覧にあるプレフィックス |
|---|---|
| Liteon Technology | `74:4C:A1`、`F4:6A:DD`、`9C:2F:9D`、`C0:35:32`、`E4:AA:EA`、`14:5A:FC`など |
| Universal Global Scientific Industrial (USI) | `E0:4F:43`、`08:3A:88` |
| Espressif | `A4:CF:12`、`3C:71:BF` |
| Silicon Laboratories | `58:8E:81`、`90:35:EA`、`EC:1B:BD` |
| Flock Safety | `B4:1E:52` |

Espressifの項目は警告になるべきでした。カメラ一覧とされた中の2つのプレフィックスは、世界で最も普及した組み込みWiFiプラットフォームの一つのメーカーに割り当てられていました。多くのコミュニティ検出器で使うチップも含まれます。

`B4:1E:52`はFlock Safetyに直接登録されている点で異なります。監査対象のコミットでは38プレフィックスの一覧に追加されていましたが、**まだ照会されていませんでした**。`scan_stats.json`によれば照会済みは31個でした。新たに追加されたバッテリーパック用の6プレフィックスも同様です。このスナップショットはFlock独自プレフィックスの頻度を示しません。「未照会」を「結果ゼロ」に置き換えません。

現在のリポジトリには、検出器ファームウェアとの整合のため`E0:0A:F6`を追加し、39個のプレフィックスがあります。保存されたスキャン概要は引き続き31個のデータだけを報告しています。そのため、新しい項目は完全な再計算待ちであり、結果ゼロが証明されたものではありません。

## データセットが自らを監査した

以下の過去の監査値はすべて、Flock Finderコミット[`5551829`](https://github.com/simeononsecurity/flock-finder/tree/5551829)の`data/flock_cameras.csv`から、Python標準ライブラリの`csv`と`collections.Counter`を使って再生成しました。新たな走行テストは不要でした。名前、地理、プレフィックス構成がすでに見出しと矛盾していました。修正後の実装に関する数値は、現行リポジトリに残る`scan_stats.json`の概要に基づきます。

### 地理は初期の警告だった

146,526行のうち、75,818件は米国内、70,674件は米国外、34件は国の値がありませんでした。ドイツが13,491件で最多、次いでカナダ6,251件、フランス5,839件、英国4,836件、オランダ4,636件、スイス4,515件でした。

{{< figure src="flock-finder-us-non-us-split.webp" alt="米国内75,818件、米国外70,674件、国の値なし34件を示す積み上げ棒グラフ" caption="34行の国がnullのため、国別ヒストグラムの合計は146,492件です。" >}}

地理はスクリーニングの手掛かりであり、証明ではありません。Flockはネットワークを「全国規模」と説明し、[米国49州](https://www.flocksafety.com/flock-ecosystem)の顧客を接続していると述べています。国際展開で市場境界が変わることもあります。そのため市場外の行は削除したり、すべて誤りと断定したりせず、確認用に印を付けます。

慎重な結論で十分です。記録のほぼ半数がプロジェクトの主要市場である米国外でした。追加の信号なしに、世界規模のOUIヒットを同じ確からしさで扱うことはできません。

Barcoのサポート文書によると、ClickShareベースユニットの既定ネットワーク名は[`ClickShare-<serial base number>`](https://www.barco.com/en/support/knowledge-base/2675-how-to-connect-to-your-clickshare-base-unit-wifi)です。これは製品ファミリーの一次資料による確認であり、地域やベンダー登録からの推測ではありません。

本番分類器は、完全一致による名前判定を大文字小文字を区別しない正規表現に置き換えました。ClickShare、SmartGate、WiFi Direct、AndroidAP、Audi HUD、MAX-PRINTER、検出器出力ラベルが対象です。同じ146,526行でAndroidAPの変種629件、Audi HUD139件、MAX-PRINTER134件を検出します。したがって、現在のリポジトリは**`identified_other`を61,110件**と報告しており、元の監査の60,793件を少し上回ります。

### 確認信号はわずか2.4%

本物のFlock型SSIDを持つ行は**3,502件**だけでした。さらに24,964件にはSSIDがありません。残りは他の機器を示すか、分類されていない名前とOUIの組み合わせでした。

確認された3,502行には、本物のSSIDの変種が161種類ありました。単純な`Flock`が3,342件、一度だけ確認された`Flock-XXXXXX`または`FLOCK-XXXXXX`の初期設定名が157件、さらに`flock`を含む名前が3件です。READMEの以前の166種類という数には、検出器の注釈文字列`Flock ALPR [...]`が5種類含まれていました。この5つは検出器の証拠であり、カメラの証拠ではありません。

## 30行に隠れていたフィードバックループ

テキサス州の30件は、別の検出器の出力と明らかに分かるSSIDを持っていました。

| SSIDとして保存された検出器ラベル | ツールが付けた確信度 | 記録数 |
|---|---:|---:|
| `Flock ALPR [wifi_receiver_oui;low]` | 低 | 20 |
| `Flock ALPR [wifi_oui_wildcard_probe;medium]` | 中 | 4 |
| `Flock ALPR [wifi_bssid_oui;low]` | 低 | 3 |
| `Flock ALPR [flock_receiver_oui;low]` | 低 | 2 |
| `Flock ALPR [wifi_hidden_ssid_oui;low]` | 低 | 1 |

30件中26件は、作成したツール自身が低確信度と判定していました。その後のWiGLEへの投稿で、その判定がSSID欄に保存されました。私たちのパイプラインは`Flock`を見つけ、そのラベルを独立した確認として扱う可能性がありました。

統計上、30行は小さな数です。しかし仕組みには重要性があります。クラウドソースのデータベースを共有するツールは互いの出力を取り込み、低確信度の推測を独立した裏付けのように見せることがあります。修正では、確認用の部分文字列`flock`を調べる前に`Flock ALPR [`全体のパターンを除外します。

## どこで誤ったか

READMEの見出しは**「マッピング済みカメラ | 146,526」**でした。地図は座標を最大精度で公開し、すべての結果を同じ種類のピンで描いていました。GitHub Actionsのスケジュールで更新していたため、弱いヒューリスティックが保守された台帳のように見えました。

但し書きはありました。各項目に`match_confidence: "suspected"`がありました。READMEはClickShareが近くに共存する可能性に触れ、プロジェクトはSSIDから見つけた候補を別に管理していました。しかし、実際に読者が見た数字、ピン、既定表示には但し書きが反映されませんでした。

文章では慎重さを示し、見出しでは数字を断定しました。地図が主張を作りました。

最も防げたはずの点は、私たちの[flock-you-esp32](https://github.com/simeononsecurity/flock-you-esp32)ファームウェアが、すでに高確信度の識別子と受託製造業者の識別子を分け、弱い証拠を警告しきい値より低く評価していたことです。同じ組織に考え方があったのに、マッピングパイプラインは取り入れませんでした。

自分たちのSSID列でヒストグラムを実行し、誤りの規模が分かりました。数分で済みました。私たちは毎日、表示の誤りを示す証拠を146,526行もコミットしていました。

## 変更した点

修正をFlock Finderのデータモデルとインターフェースに実装しました。

- **レコード別の証拠：**`ssid_confirmed`、`oui_high`、`oui_mfr`、`identified_other`。
- **OUIの段階分け：**現場観測で高確信度のものと、複数製品で共有する受託製造業者のものを分離。
- **既知の他機器を除外：**ClickShare、SmartGate、WiFi Direct、Androidホットスポット、Audi HUD、MAX-PRINTER、検出器出力のSSIDを既定の地図と見出しから除外。
- **不確実性を表示：**ピンの色、ポップアップ、件数、フィルターに証拠クラスを表示。
- **市場外の印：**米国の主要市場外の記録に`out_of_market: true`を付け、確認用として保持。
- **内訳付きの見出し：**SSID確認3,502件、高位OUIの疑い73,691件、受託製造業者OUIの疑い8,223件、他機器と識別61,110件。

修正後の実用的な数は**85,416件**です。その中にも未確認のOUI一致が81,914件あります。これは現行ルールを通過した件数を説明するもので、検証済みのカメラ台帳ではありません。

`identified_other`も運用上の分類器であり、万能な判定ではありません。ClickShareの既定SSIDには強い一次資料があります。一方、`DIRECT-`のような広いパターンは、多くの製品カテゴリーが使うWiFi Directの命名規則です。一致ルールと`blocked_reason`フィールドを公開すれば、研究者は除外内容を監査し、証拠が増えたときに見直せます。

### 長期的な答えはファームウェアの指紋

OUIの段階分けは被害を抑えますが、共有メーカーのプレフィックスを製品固有にはできません。より強い方法は802.11プローブ要求の情報要素が並ぶ順序構造です。上流の作業では次のTLV署名が記録されています。

```text
2,12,127,221:506f9a16030103,45,191,221:0050f208000000
```

この並びが示すのは特定ファームウェアスタックの挙動であり、MACブロックの所有者ではありません。プローブ要求の指紋は確立された機器識別手法です。[802.11 MAC層の指紋に関する公開研究](https://doi.org/10.1155/2017/6235484)は、MACアドレスが変わってもプローブ要求の情報要素が識別に使える場合を示しています。[flock-you issue #43](https://github.com/colonelpanichacks/flock-you/issues/43)で報告された具体的な問題にも対応します。`Flock Camera net.`が2.4GHzと5GHzで連続したローカル管理MACアドレスに現れます。

この署名には、機器とファームウェア版をまたぐ独立した現場検証が必要です。壊れたキャプチャには防御的な解析も必要です。それでも正しい方向です。MACランダム化によって、OUIだけの照合は時間の問題で行き詰まります。

## 1つのリポジトリを超えて重要な理由

人々は監視地図を使って、運転、駐車、通報、調査、組織活動の場所を決めます。誤ったピンは注意をそらします。何万もの誤ったピンは、近くにある正確な観測まで信用されなくします。

信頼性には非対称性もあります。ベンダーや批判者は、ClickShareの誤ったピンを1つ証明するだけでデータセット全体に異議を唱えられます。私たちは50,278件を提供していました。報道機関や擁護団体は、後の訂正が追いつくより早く簡潔な見出しを繰り返せます。

オープンソースの透明性は、検証可能な方法と目に見える不確実性によって信頼を得ます。生データの公開が誤りの発見に役立ちました。しかし、生データへアクセスできることは、結論を誇張する画面の言い訳にはなりません。読者が主張に出会う場所、つまりフィールド、フィルター、ピン、凡例、見出しに修正を置く必要があります。

### すべてのFlock・ALPRマップへのお願い

他のFlockやALPRのマッピングプロジェクトもデータセットを監査してください。これは手法を比べるための招待であり、すべての地図が私たちの誤りを引き継いだという主張ではありません。

[WiGLE](https://www.wigle.net/stats/)は、私たちの知る限り、公開アクセスでき世界中を検索できる最大規模のWiFi観測データセットです。その範囲の広さがFlock Finderの魅力でした。API一つで、現場調査した署名一覧を世界地図にできました。同時に、誤りを測れる規模にしました。グローバルデータベースは、検索の目的となった製品だけでなく、無線部品の供給元とアドレス空間を共有するすべての無関係な製品も返します。

他の地図は異なる証拠を使います。写真やボランティアの現場観察に基づくものもあれば、OpenStreetMapの監視タグ、公的記録、ベンダーの開示、別のコミュニティプロジェクトのデータを取り込むものもあります。それらの合計は私たちのWiGLE結果と直接比較できず、SSID確認率2.4%を現場確認済みデータへ適用すべきではありません。共通の危険は、あるプロジェクトの分類が別のプロジェクトの元データに流れ込み、独立した裏付けに見えることです。

公開地図は、次の短い監査質問に答えられる必要があります。

1. **1つのピンは何を意味しますか。**撮影した機器、公的記録、OUI一致、利用者の報告、他地図からのインポートのどれですか。
2. **製品の直接証拠がある記録はいくつですか。**カメラの総数1つだけでなく、証拠クラス別の件数を公開してください。
3. **どの情報源が独立していますか。**同じ観測を複数の確認として数えないよう、インポートの来歴を追跡してください。
4. **分類に反する情報は何ですか。**SSID、ベンダー、国、投稿者ラベルなどカテゴリ項目の頻度表を作成してください。
5. **不確実性や異議をどう表示しますか。**確信度と修正状況をピン、フィルター、エクスポート、見出しに示してください。
6. **他の研究者が件数を再現できますか。**クエリ、ソーススナップショット、分類ルール、日付を公開してください。

この監査でFlockの問題が小さくなるわけではありません。ALPRカメラ網は移動を記録し、管轄を越えた検索を支援し、収集に同意していない人にも影響を与えます。正確な件数は、その批判を退けにくくします。監視システムに異議を唱えるなら、地図は観測、推論、確認を区別する必要があります。

私たちは十分な情報がある中で誤りました。プレフィックスは正当な現場調査に由来し、パイプラインは再現可能で、但し書きも実在しました。それでも推論は証拠を超えていました。善意や良い入力があっても、システムが大規模に出す結果を検証する責務はなくなりません。

## 監査を再現する

コミット`5551829`をチェックアウトし、リポジトリのルートで以下を実行します。Python標準ライブラリだけを使い、合計、地理、一般的なSSID、指定した機器名ファミリーを表示します。

```bash
git clone https://github.com/simeononsecurity/flock-finder.git
cd flock-finder
git checkout 5551829

python3 - <<'PY'
import csv
from collections import Counter

with open("data/flock_cameras.csv", newline="", encoding="utf-8") as f:
    rows = list(csv.DictReader(f))

ssids = Counter((row["ssid"] or "").strip() for row in rows)
countries = Counter((row["country"] or "").strip() for row in rows)

families = {
    "clickshare": lambda s: "clickshare" in s.lower(),
    "smartgate": lambda s: s.lower().startswith("smartgate_"),
    "direct": lambda s: s.lower().startswith("direct-"),
    "androidap": lambda s: s.lower().startswith("androidap"),
    "detector_output": lambda s: s.lower().startswith("flock alpr ["),
}

print("行", len(rows))
print("米国", countries["US"])
print("米国外", sum(countries.values()) - countries["US"] - countries[""])
print("国情報なし", countries[""])
print("上位の SSID", ssids.most_common(20))
for name, matches in families.items():
    print(name, sum(matches(ssid) for ssid in ssids.elements()))
PY
```

当時と同じ入力を使うには、現在生成されているデータではなく、そのコミットのCSVを使います。監査後、巨大なCSV、GeoJSON、OUI別ファイルのGit登録をやめました。スキャンのたびに数百メガバイトを書き換え、リポジトリが大きくなっていたためです。現在の生成データは継続リリース[`data-latest`](https://github.com/simeononsecurity/flock-finder/releases/tag/data-latest)から復元して公開しています。小さな`scan_stats.json`概要はGitに残しています。現行ブランチに生成ファイルがないことは、過去の証拠が削除されたことや件数がゼロになったことを意味しません。
