**Claude Code CLI と Desktop** には、Anthropic のコーディングエージェントを操作する二つの方法があります。CLI はシェルのワークフローとプログラムからの呼び出しに向きます。Desktop は会話の横でファイル変更とレビューを確認できる、見えるプロジェクトワークスペースに向きます。

**この比較の対象はデスクトップのコーディングワークスペースです。** Anthropic の [デスクトップクイックスタート](https://code.claude.com/docs/en/desktop-quickstart)では Code タブとして説明されています。一般的なチャットとほかのデスクトップワークフローは対象外です。リポジトリへのアクセスと設定を確認するとき、この区別が重要です。

## 主なポイント

- **スクリプト、パイプ入力、ターミナル中心の作業には CLI を使います。**
- **グラフィカルな監視、添付ファイル、diff の確認には Desktop を使います。**
- **共有設定は重複を減らします。** ただし、セッションの動作と利用できる操作は異なります。
- **会話の移動には対応した引き継ぎが必要です。** 新しいチャットへ prompt をコピーする方法ではありません。

**対象と日付:** 2026 年 10 月 10 日に公式ドキュメントを確認しました。これは機能とワークフローの比較であり、コーディングベンチマークではありません。テスト可能なリポジトリと承認済みのアカウント経路が必要です。小さな試行には 45〜60 分を確保します。

## 同じエンジン、異なる操作

**Anthropic は Desktop を、同じ基盤エンジンに GUI を加えたものとして説明しています。** [デスクトップリファレンス](https://code.claude.com/docs/en/desktop)には共有設定とプロジェクトメモリが記載され、クライアント固有の機能も区別されています。基盤が共通でも、すべての CLI オプションに Desktop のボタンがあるとは限りません。

| 作業 | CLI | Desktop Code ワークスペース |
|---|---|---|
| **対話的な作業** | ターミナルの会話 | プロジェクトペイン付きのグラフィカルな会話 |
| **スクリプト呼び出し** | Print モードとパイプ入力 | このワークフローには CLI を使います |
| **変更の確認** | ターミナルまたはエディターのワークフロー | 統合された視覚的 diff |
| **タスク整理** | ターミナルセッションと CLI 操作 | セッションサイドバーとワークスペースレイアウト |
| **定期作業** | 外部スケジューラーまたは CI | Desktop のスケジュールタスク |
| **プロジェクト規則** | リポジトリとユーザーの設定 | 画面ごとに異なる動作を持つ共有設定 |

**監視に必要な作業量で選びます。** シェル中心のバグ調査と、視覚的なアプリケーション変更では、インターフェースへの要求が異なります。どちらも、より強いモデルである証拠にはなりません。

## ターミナル作業とスクリプト

```bash
claude -p "Explain the failing test and propose a fix. Do not edit files."
```

**Print モードは通常の対話会話なしで動きます。** Anthropic の [CLI リファレンス](https://code.claude.com/docs/en/cli-reference)には、このコマンド群、パイプ入力、再開オプションが記載されています。調査に合わせてツール権限を設定します。上の prompt は読み取り専用ポリシーの代わりになりません。

**入出力の契約が安定している場合にスクリプトを使います。** 例として、定期レポート、範囲を限定したリポジトリ検査、レビュー資料を作る CI 手順があります。失敗の定義を決め、証拠を保存します。エージェントの最後のメッセージが完全に見えるという理由だけでパッチを承認しません。

**判断が残っている作業は対話的に続けます。** API 設計の選択や矛盾する要件の解決が必要なら、明確なチェックポイントを持つターミナルセッションの方が、ヘッドレスラッパーより少ない自動化コードで済む場合があります。

## Desktop のレビューとスケジュール

**Desktop は CLI を別にインストールせずにコーディングワークスペースを提供します。** クイックスタートには、プロジェクトの選択、モデルの選択、変更のグラフィカルな受け入れが説明されています。ソースファイル、テスト、設定ファイルにまたがるパッチで評価し、複数のペインを使うレビューにします。

**スケジュール作業は Desktop の別機能です。** Anthropic の [スケジュールタスクのドキュメント](https://code.claude.com/docs/en/desktop-scheduled-tasks)には、定期タスクと動作要件が説明されています。毎日のワークフローで使う前に、タスクの実行場所と、利用可能な状態を保つ必要があるものを確認します。

**集約されたパッチを確認します。** 個別の編集承認だけでは、変更ファイル間の相互作用をすべて確認できません。実行後に最終 diff を調べ、受け入れチェックを別に実行します。

## 設定と権限

**設定には範囲と優先順位があります。** Anthropic の [設定リファレンス](https://code.claude.com/docs/en/settings)は、管理、ユーザー、プロジェクト、ローカルの設定を区別しています。クライアントの違いを調べる前に、有効な設定を確認します。プロジェクト規則が組織ポリシーを必ず上書きするとは限りません。

**権限モードは操作を変えます。** 一致するポリシーで両方のクライアントを比較し、その後で希望するポリシーを別にテストします。承認要求が少ないことを無条件の利点として扱いません。許可された操作がタスクと環境に合うかが重要です。

| 設定の確認 | 理由 |
|---|---|
| **プロジェクトフォルダー** | 意図したコードとプロジェクト規則を読み込む |
| **アカウント経路** | アクセスと課金のコンテキストを決める |
| **選択したモデル** | インターフェース変更とモデル変更の混同を避ける |
| **権限ポリシー** | どの操作を進めるか制御する |
| **実行環境** | 利用できるコマンドとテストを決める |

**正規のプロジェクト指示はリポジトリに置きます。** ビルドコマンド、除外ファイル、受け入れ基準を記録します。編集前にエージェントへ制約を特定させます。不一致があれば、動作を比較する前に設定問題を解決します。

## セッションを移動する

```text
/desktop
```

**文書化された CLI から Desktop への引き継ぎは、セッションを保存して CLI を終了します。** デスクトップリファレンスでは、このコマンドを対応する macOS と x64 Windows のサブスクリプションセッションに限定しています。API キーやサードパーティプロバイダーのセッションでは同じ経路を使えません。依存する前に、インストール済みのバージョンとアカウントを確認します。

**引き継ぎを制御された移行として扱います。** 実行中の操作を完了または停止し、現在のブランチを確認して保留中の変更を調べます。移行先の画面を開いた後、リポジトリを確認して次の手順を尋ねます。最初の実装が動いている間に、同じファイルへ二つ目の実装を開始しません。

**ファイルの共有と会話の共有は異なります。** 同じ checkout を開く二つのクライアントはファイルシステムの変更を見ますが、新しい会話には元のセッションの理由と制約がありません。持ち運べる引き継ぎが必要なら、リポジトリに短いタスク記録を保存します。

## 小さな試行で選ぶ

**目に見える症状のあるバグを使います。** 再現手順、期待する動作、エージェントが保持すべきファイルを示します。同じベースリビジョンから、モデルと権限設定をそろえて別々に試します。

| 試行段階 | 観察すること |
|---|---|
| **コンテキスト** | ログ、ファイル、スクリーンショットを添付する手間 |
| **実装** | 中断と確認が必要になる場面 |
| **レビュー** | 変更ファイルをすべて調べやすいか |
| **修正** | 却下した方法への反応 |
| **完了** | 独立したテスト結果とクリーンな diff |

**スクリプトとターミナルのコンテキストが中心なら CLI を選びます。** **見えるプロジェクト状態とグラフィカルなレビューが負担を減らすなら Desktop を選びます。** 両方の需要を切り替える場合は、両方を意図的に使います。

## トラブルシューティングと次の手順

**Desktop に CLI のコマンドがない場合は、** インストール失敗と決めつけず、機能比較を確認します。ターミナルでのみコマンドが動く場合は、実行環境と runtime の検出を比較します。引き継ぎが使えない場合は、プラットフォームと認証資格を確認します。

より広い候補は [CLI 比較](/articles/cli-coding-agents-comparison/)または [GUI 比較](/articles/gui-coding-agents-comparison/)で確認できます。ベンダーをまたぐエージェント比較は [OpenCode と Claude Code](/articles/opencode-vs-claude-code/)を参照してください。
