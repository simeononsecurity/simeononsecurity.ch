**Claude Code CLI और Desktop** Anthropic के कोडिंग एजेंट को निर्देश देने के दो तरीके देते हैं। CLI शेल वर्कफ़्लो और प्रोग्रामेटिक कॉल के लिए है। Desktop बातचीत के साथ फ़ाइल बदलाव और समीक्षा दिखाने वाले प्रोजेक्ट वर्कस्पेस के लिए है।

**यह तुलना डेस्कटॉप कोडिंग वर्कस्पेस पर है।** Anthropic के [डेस्कटॉप क्विक स्टार्ट](https://code.claude.com/docs/en/desktop-quickstart) में इसे Code टैब कहा गया है। सामान्य चैट और दूसरे डेस्कटॉप वर्कफ़्लो इसमें शामिल नहीं हैं। रिपॉज़िटरी एक्सेस और कॉन्फ़िगरेशन जाँचते समय यह अंतर महत्वपूर्ण है।

## मुख्य बातें

- **स्क्रिप्ट, पाइप इनपुट और टर्मिनल-केंद्रित काम के लिए CLI इस्तेमाल करें।**
- **ग्राफ़िकल निगरानी, अटैचमेंट और diff समीक्षा के लिए Desktop इस्तेमाल करें।**
- **साझा कॉन्फ़िगरेशन दोहराव घटाता है**, पर सेशन व्यवहार और उपलब्ध नियंत्रण अलग हैं।
- **बातचीत स्थानांतरित करने के लिए समर्थित हैंडऑफ चाहिए**, नए चैट में prompt कॉपी करना पर्याप्त नहीं है।

**दायरा और तारीख:** आधिकारिक दस्तावेज़ 10 अक्टूबर 2026 को जाँचे गए। यह फीचर और वर्कफ़्लो तुलना है, कोडिंग बेंचमार्क नहीं। एक टेस्ट योग्य रिपॉज़िटरी और स्वीकृत अकाउंट मार्ग चाहिए। छोटे परीक्षण के लिए 45–60 मिनट रखें।

## एक इंजन, अलग नियंत्रण

**Anthropic Desktop को GUI वाला वही आधार इंजन बताता है।** [डेस्कटॉप रेफ़रेंस](https://code.claude.com/docs/en/desktop) साझा कॉन्फ़िगरेशन और प्रोजेक्ट मेमोरी बताता है और क्लाइंट फीचर अलग करता है। साझा आधार का अर्थ हर CLI विकल्प के लिए Desktop बटन नहीं है।

| गतिविधि | CLI | Desktop Code वर्कस्पेस |
|---|---|---|
| **इंटरैक्टिव काम** | टर्मिनल बातचीत | प्रोजेक्ट पैनल वाली ग्राफ़िकल बातचीत |
| **स्क्रिप्ट कॉल** | Print मोड और पाइप इनपुट | इस काम के लिए CLI इस्तेमाल करें |
| **बदलाव समीक्षा** | टर्मिनल या एडिटर वर्कफ़्लो | एकीकृत दृश्य diff |
| **टास्क संगठन** | टर्मिनल सेशन और CLI नियंत्रण | सेशन साइडबार और वर्कस्पेस लेआउट |
| **दोहराया काम** | बाहरी शेड्यूलर या CI | Desktop शेड्यूल्ड टास्क |
| **प्रोजेक्ट नियम** | रिपॉज़िटरी और यूज़र कॉन्फ़िगरेशन | सतह-विशिष्ट व्यवहार वाली साझा सेटिंग |

**निगरानी के प्रयास के आधार पर चुनें।** शेल-केंद्रित बग जाँच और दृश्य ऐप बदलाव इंटरफ़ेस से अलग माँग करते हैं। कोई विकल्प बेहतर मॉडल का प्रमाण नहीं है।

## टर्मिनल काम और स्क्रिप्ट

```bash
claude -p "Explain the failing test and propose a fix. Do not edit files."
```

**Print मोड सामान्य इंटरैक्टिव बातचीत के बिना चलता है।** Anthropic का [CLI रेफ़रेंस](https://code.claude.com/docs/en/cli-reference) इस कमांड परिवार, पाइप इनपुट और रिज़्यूम विकल्पों को दर्ज करता है। टूल अनुमतियों को जाँच के अनुसार रखें। ऊपर का prompt केवल-पठन नीति का विकल्प नहीं है।

**इनपुट और आउटपुट अनुबंध स्थिर हो तो स्क्रिप्ट इस्तेमाल करें।** उदाहरणों में शेड्यूल्ड रिपोर्ट, सीमित रिपॉज़िटरी जाँच और समीक्षा सामग्री बनाने वाला CI चरण आते हैं। विफलता की परिभाषा तय करें और प्रमाण बचाएँ। एजेंट का अंतिम संदेश पूरा दिखे, इस कारण अकेले patch स्वीकार न करें।

**निर्णय खुले हों तो काम इंटरैक्टिव रखें।** API डिज़ाइन चुनने या विरोधी आवश्यकताओं को सुलझाने वाली टास्क में स्पष्ट चेकपॉइंट वाली टर्मिनल सेशन अक्सर हेडलेस रैपर से कम ऑटोमेशन कोड माँगती है।

## Desktop समीक्षा और शेड्यूलिंग

**Desktop अलग CLI इंस्टॉलेशन के बिना कोडिंग वर्कस्पेस देता है।** क्विक स्टार्ट प्रोजेक्ट, मॉडल और बदलाव स्वीकार करने की ग्राफ़िकल प्रक्रिया बताता है। स्रोत फ़ाइल, टेस्ट और कॉन्फ़िगरेशन फ़ाइल वाले patch से जाँच करें।

**शेड्यूल्ड काम Desktop का अलग फीचर है।** [शेड्यूल्ड टास्क दस्तावेज़](https://code.claude.com/docs/en/desktop-scheduled-tasks) दोहराए जाने वाले काम और संचालन आवश्यकताएँ बताता है। दैनिक वर्कफ़्लो में भरोसा करने से पहले रन स्थान और उपलब्ध रहनी वाली चीज़ें जाँचें।

**पूरे patch की समीक्षा करें।** अलग-अलग बदलावों की स्वीकृति बदली हुई फ़ाइलों की सभी अंतःक्रियाएँ नहीं दिखाती। रन के बाद अंतिम diff जाँचें और स्वीकृति परीक्षण अलग से चलाएँ।

## सेटिंग और अनुमतियाँ

**सेटिंग का दायरा और प्राथमिकता होती है।** Anthropic का [सेटिंग रेफ़रेंस](https://code.claude.com/docs/en/settings) मैनेज्ड, यूज़र, प्रोजेक्ट और स्थानीय कॉन्फ़िगरेशन अलग करता है। क्लाइंट अंतर की जाँच से पहले प्रभावी सेटअप जाँचें। प्रोजेक्ट नियम संगठन नीति को हमेशा ओवरराइड नहीं करता।

**अनुमति मोड इंटरैक्शन बदलता है।** दोनों क्लाइंट को समान नीतियों के साथ तुलना करें और पसंदीदा नीति को अलग से जाँचें। कम स्वीकृति संकेत अपने आप लाभ नहीं हैं। अनुमति प्राप्त कार्य टास्क और वातावरण से मेल खाने चाहिए।

| कॉन्फ़िगरेशन जाँच | कारण |
|---|---|
| **प्रोजेक्ट फ़ोल्डर** | सही कोड और प्रोजेक्ट नियम लोड करता है |
| **अकाउंट मार्ग** | एक्सेस और बिलिंग संदर्भ तय करता है |
| **चयनित मॉडल** | इंटरफ़ेस और मॉडल बदलावों को मिलाने से बचाता है |
| **अनुमति नीति** | चलने वाली प्रक्रियाएँ नियंत्रित करती है |
| **रनटाइम वातावरण** | उपलब्ध कमांड और टेस्ट तय करता है |

**मुख्य प्रोजेक्ट निर्देश रिपॉज़िटरी में रखें।** बिल्ड कमांड, बाहर रखी फ़ाइलें और स्वीकृति मानदंड लिखें। एडिट से पहले एजेंट से प्रतिबंध पहचानने को कहें। अंतर मिले तो पहले कॉन्फ़िगरेशन समस्या हल करें।

## सेशन स्थानांतरित करना

```text
/desktop
```

**दस्तावेज़ित CLI-to-Desktop हैंडऑफ सेशन बचाकर CLI बंद करता है।** Desktop रेफ़रेंस इसे समर्थित macOS और x64 Windows सब्सक्रिप्शन सेशन तक सीमित करता है। API key और थर्ड-पार्टी प्रोवाइडर सेशन को यही मार्ग नहीं मिलता। निर्भर करने से पहले संस्करण और अकाउंट जाँचें।

**हैंडऑफ को नियंत्रित बदलाव मानें।** सक्रिय काम पूरा या रोकें, वर्तमान branch पहचानें और लंबित बदलाव देखें। लक्ष्य इंटरफ़ेस खोलने के बाद रिपॉज़िटरी जाँचें और अगला कदम पूछें। पहला काम चलते समय उन्हीं फ़ाइलों पर दूसरा काम शुरू न करें।

**फ़ाइल साझा करना बातचीत साझा करने से अलग है।** एक ही checkout देखने वाले दो क्लाइंट फ़ाइल बदलाव देखते हैं, पर नए सेशन में पुराने सेशन का तर्क और प्रतिबंध नहीं होते। पोर्टेबल हैंडऑफ के लिए रिपॉज़िटरी में छोटा टास्क रिकॉर्ड रखें।

## छोटे परीक्षण से चुनें

**दिखने वाले लक्षण वाली बग लें।** रीप्रोडक्शन, अपेक्षित व्यवहार और बचाई जाने वाली फ़ाइलें दें। उसी बेस रिविज़न, मॉडल और अनुमति सेटिंग से अलग प्रयास चलाएँ।

| परीक्षण चरण | देखें |
|---|---|
| **संदर्भ** | लॉग, फ़ाइल और स्क्रीनशॉट जोड़ने का प्रयास |
| **इम्प्लीमेंटेशन** | रुकावट और स्पष्टीकरण की ज़रूरत |
| **समीक्षा** | हर बदली फ़ाइल देखना कितना आसान है |
| **सुधार** | अस्वीकार किए तरीके पर प्रतिक्रिया |
| **पूर्णता** | स्वतंत्र टेस्ट परिणाम और साफ़ diff |

**स्क्रिप्ट और टर्मिनल संदर्भ प्रमुख हों तो CLI चुनें।** **दृश्य प्रोजेक्ट स्थिति और ग्राफ़िकल समीक्षा घर्षण घटाए तो Desktop चुनें।** जरूरत बदलने पर दोनों का सोचकर उपयोग करें।

## समस्या समाधान और अगले चरण

**Desktop में CLI का कमांड न हो तो** फीचर तुलना देखें, इंस्टॉलेशन विफलता न मानें। कमांड केवल टर्मिनल में चले तो रनटाइम वातावरण और runtime खोज की तुलना करें। हैंडऑफ उपलब्ध न हो तो प्लेटफ़ॉर्म और प्रमाणीकरण पात्रता जाँचें।
