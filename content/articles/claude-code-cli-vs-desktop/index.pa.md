**Claude Code CLI ਅਤੇ Desktop** Anthropic ਦੇ ਕੋਡਿੰਗ ਏਜੰਟ ਨੂੰ ਚਲਾਉਣ ਦੇ ਦੋ ਤਰੀਕੇ ਦਿੰਦੇ ਹਨ। CLI shell ਵਰਕਫਲੋ ਅਤੇ ਪ੍ਰੋਗਰਾਮੇਟਿਕ ਕਾਲ ਲਈ ਹੈ। Desktop ਗੱਲਬਾਤ ਦੇ ਨਾਲ ਫਾਈਲ ਬਦਲਾਅ ਅਤੇ ਸਮੀਖਿਆ ਵਾਲਾ ਦਿਸਣਯੋਗ ਪ੍ਰੋਜੈਕਟ ਵਰਕਸਪੇਸ ਦਿੰਦਾ ਹੈ।

**ਇਹ ਤੁਲਨਾ ਡੈਸਕਟਾਪ ਕੋਡਿੰਗ ਵਰਕਸਪੇਸ ਬਾਰੇ ਹੈ।** Anthropic ਦੇ [ਡੈਸਕਟਾਪ ਕਵਿਕ ਸਟਾਰਟ](https://code.claude.com/docs/en/desktop-quickstart) ਵਿੱਚ ਇਸ ਨੂੰ Code ਟੈਬ ਕਿਹਾ ਗਿਆ ਹੈ। ਆਮ ਚੈਟ ਅਤੇ ਹੋਰ ਡੈਸਕਟਾਪ ਵਰਕਫਲੋ ਇਸ ਵਿੱਚ ਨਹੀਂ ਹਨ। ਰਿਪੋਜ਼ਟਰੀ ਪਹੁੰਚ ਅਤੇ ਸੰਰਚਨਾ ਜਾਂਚਦਿਆਂ ਇਹ ਫਰਕ ਮਹੱਤਵਪੂਰਨ ਹੈ।

## ਮੁੱਖ ਗੱਲਾਂ

- **ਸਕ੍ਰਿਪਟਾਂ, ਪਾਈਪ ਕੀਤੇ ਇਨਪੁਟ ਅਤੇ ਟਰਮੀਨਲ-ਕੇਂਦਰਿਤ ਕੰਮ ਲਈ CLI ਵਰਤੋ।**
- **ਗ੍ਰਾਫਿਕਲ ਨਿਗਰਾਨੀ, ਅਟੈਚਮੈਂਟ ਅਤੇ diff ਸਮੀਖਿਆ ਲਈ Desktop ਵਰਤੋ।**
- **ਸਾਂਝੀ ਸੰਰਚਨਾ ਦੁਹਰਾਵਾਂ ਘਟਾਉਂਦੀ ਹੈ**, ਪਰ ਸੈਸ਼ਨ ਵਿਹਾਰ ਅਤੇ ਉਪਲਬਧ ਕੰਟਰੋਲ ਵੱਖਰੇ ਹਨ।
- **ਗੱਲਬਾਤ ਹਿਲਾਉਣ ਲਈ ਸਮਰਥਿਤ ਹੈਂਡਆਫ ਚਾਹੀਦਾ ਹੈ**, ਨਵੀਂ ਚੈਟ ਵਿੱਚ prompt ਕਾਪੀ ਕਰਨਾ ਕਾਫ਼ੀ ਨਹੀਂ।

**ਦਾਇਰਾ ਅਤੇ ਮਿਤੀ:** ਅਧਿਕਾਰਤ ਦਸਤਾਵੇਜ਼ 10 ਅਕਤੂਬਰ 2026 ਨੂੰ ਜਾਂਚੇ ਗਏ। ਇਹ ਫੀਚਰ ਅਤੇ ਵਰਕਫਲੋ ਤੁਲਨਾ ਹੈ, ਕੋਡਿੰਗ ਬੈਂਚਮਾਰਕ ਨਹੀਂ। ਤੁਹਾਨੂੰ ਟੈਸਟਯੋਗ ਰਿਪੋਜ਼ਟਰੀ ਅਤੇ ਮਨਜ਼ੂਰਸ਼ੁਦਾ ਅਕਾਊਂਟ ਰੂਟ ਚਾਹੀਦਾ ਹੈ। ਛੋਟੀ ਅਜ਼ਮਾਇਸ਼ ਲਈ 45–60 ਮਿੰਟ ਰੱਖੋ।

## ਇੱਕੋ ਇੰਜਣ, ਵੱਖਰੇ ਕੰਟਰੋਲ

**Anthropic Desktop ਨੂੰ GUI ਵਾਲਾ ਉਹੀ ਮੂਲ ਇੰਜਣ ਦੱਸਦਾ ਹੈ।** [ਡੈਸਕਟਾਪ ਰੈਫਰੈਂਸ](https://code.claude.com/docs/en/desktop) ਸਾਂਝੀ ਸੰਰਚਨਾ ਅਤੇ ਪ੍ਰੋਜੈਕਟ ਮੈਮੋਰੀ ਦੱਸਦਾ ਹੈ ਅਤੇ ਕਲਾਇੰਟ ਫੀਚਰ ਵੱਖ ਕਰਦਾ ਹੈ। ਸਾਂਝਾ ਆਧਾਰ ਹਰ CLI ਵਿਕਲਪ ਲਈ Desktop ਬਟਨ ਨਹੀਂ ਦਿੰਦਾ।

| ਗਤੀਵਿਧੀ | CLI | Desktop Code ਵਰਕਸਪੇਸ |
|---|---|---|
| **ਇੰਟਰਐਕਟਿਵ ਕੰਮ** | ਟਰਮੀਨਲ ਗੱਲਬਾਤ | ਪ੍ਰੋਜੈਕਟ ਪੈਨਲਾਂ ਵਾਲੀ ਗ੍ਰਾਫਿਕਲ ਗੱਲਬਾਤ |
| **ਸਕ੍ਰਿਪਟ ਕਾਲ** | Print ਮੋਡ ਅਤੇ ਪਾਈਪ ਇਨਪੁਟ | ਇਸ ਵਰਕਫਲੋ ਲਈ CLI ਵਰਤੋ |
| **ਬਦਲਾਅ ਸਮੀਖਿਆ** | ਟਰਮੀਨਲ ਜਾਂ ਐਡੀਟਰ ਵਰਕਫਲੋ | ਇਕੱਠਾ ਦ੍ਰਿਸ਼ਮਾਨ diff |
| **ਟਾਸਕ ਸੰਗਠਨ** | ਟਰਮੀਨਲ ਸੈਸ਼ਨ ਅਤੇ CLI ਕੰਟਰੋਲ | ਸੈਸ਼ਨ ਸਾਈਡਬਾਰ ਅਤੇ ਵਰਕਸਪੇਸ ਲੇਆਉਟ |
| **ਦੁਹਰਾਇਆ ਕੰਮ** | ਬਾਹਰੀ ਸ਼ਡਿਊਲਰ ਜਾਂ CI | Desktop ਸ਼ਡਿਊਲਡ ਟਾਸਕ |
| **ਪ੍ਰੋਜੈਕਟ ਨਿਯਮ** | ਰਿਪੋਜ਼ਟਰੀ ਅਤੇ ਯੂਜ਼ਰ ਸੰਰਚਨਾ | ਸਤਹ-ਵਿਸ਼ੇਸ਼ ਵਿਹਾਰ ਵਾਲੀਆਂ ਸਾਂਝੀਆਂ ਸੈਟਿੰਗਾਂ |

**ਨਿਗਰਾਨੀ ਦੀ ਮਿਹਨਤ ਅਨੁਸਾਰ ਚੁਣੋ।** Shell-ਕੇਂਦਰਿਤ ਬੱਗ ਜਾਂਚ ਅਤੇ ਦ੍ਰਿਸ਼ਮਾਨ ਐਪਲੀਕੇਸ਼ਨ ਬਦਲਾਅ ਇੰਟਰਫੇਸ ਤੋਂ ਵੱਖਰੀਆਂ ਮੰਗਾਂ ਰੱਖਦੇ ਹਨ। ਕੋਈ ਵੀ ਵਧੀਆ ਮਾਡਲ ਦਾ ਸਬੂਤ ਨਹੀਂ।

## ਟਰਮੀਨਲ ਕੰਮ ਅਤੇ ਸਕ੍ਰਿਪਟ

```bash
claude -p "Explain the failing test and propose a fix. Do not edit files."
```

**Print ਮੋਡ ਆਮ ਇੰਟਰਐਕਟਿਵ ਗੱਲਬਾਤ ਤੋਂ ਬਿਨਾਂ ਚੱਲਦਾ ਹੈ।** Anthropic ਦੀ [CLI ਰੈਫਰੈਂਸ](https://code.claude.com/docs/en/cli-reference) ਕਮਾਂਡ ਪਰਿਵਾਰ, ਪਾਈਪ ਇਨਪੁਟ ਅਤੇ ਰਿਜ਼ਿਊਮ ਵਿਕਲਪ ਦੱਸਦੀ ਹੈ। ਟੂਲ ਇਜਾਜ਼ਤਾਂ ਨੂੰ ਜਾਂਚ ਨਾਲ ਮਿਲਾਓ। ਉੱਪਰਲਾ prompt ਸਿਰਫ਼ ਪੜ੍ਹਨ ਵਾਲੀ ਨੀਤੀ ਦਾ ਬਦਲ ਨਹੀਂ।

**ਜਦੋਂ ਇਨਪੁਟ ਅਤੇ ਆਉਟਪੁਟ ਦਾ ਕਰਾਰ ਸਥਿਰ ਹੋਵੇ ਤਾਂ ਸਕ੍ਰਿਪਟ ਵਰਤੋ।** ਉਦਾਹਰਨਾਂ ਵਿੱਚ ਸ਼ਡਿਊਲਡ ਰਿਪੋਰਟ, ਸੀਮਤ ਰਿਪੋਜ਼ਟਰੀ ਜਾਂਚ ਅਤੇ ਸਮੀਖਿਆ ਸਮੱਗਰੀ ਬਣਾਉਣ ਵਾਲਾ CI ਕਦਮ ਹਨ। ਅਸਫਲਤਾ ਦੀ ਪਰਿਭਾਸ਼ਾ ਦਿਓ ਅਤੇ ਸਬੂਤ ਸੰਭਾਲੋ। ਏਜੰਟ ਦਾ ਅੰਤਿਮ ਸੁਨੇਹਾ ਪੂਰਾ ਲੱਗਣ ਕਰਕੇ ਹੀ patch ਮਨਜ਼ੂਰ ਨਾ ਕਰੋ।

**ਫੈਸਲੇ ਖੁੱਲ੍ਹੇ ਹੋਣ ਤਾਂ ਕੰਮ ਇੰਟਰਐਕਟਿਵ ਰੱਖੋ।** API ਡਿਜ਼ਾਈਨ ਚੁਣਨ ਜਾਂ ਵਿਰੋਧੀ ਲੋੜਾਂ ਹੱਲ ਕਰਨ ਲਈ ਸਪਸ਼ਟ ਚੈਕਪੋਇੰਟ ਵਾਲਾ ਟਰਮੀਨਲ ਸੈਸ਼ਨ ਅਕਸਰ ਹੈੱਡਲੈੱਸ ਰੈਪਰ ਨਾਲੋਂ ਘੱਟ ਆਟੋਮੇਸ਼ਨ ਕੋਡ ਮੰਗਦਾ ਹੈ।

## Desktop ਸਮੀਖਿਆ ਅਤੇ ਸ਼ਡਿਊਲਿੰਗ

**Desktop ਵੱਖਰੀ CLI ਇੰਸਟਾਲੇਸ਼ਨ ਤੋਂ ਬਿਨਾਂ ਕੋਡਿੰਗ ਵਰਕਸਪੇਸ ਦਿੰਦਾ ਹੈ।** ਕਵਿਕ ਸਟਾਰਟ ਪ੍ਰੋਜੈਕਟ ਅਤੇ ਮਾਡਲ ਚੋਣ ਅਤੇ ਬਦਲਾਅ ਸਵੀਕਾਰ ਕਰਨ ਦੀ ਗ੍ਰਾਫਿਕਲ ਪ੍ਰਕਿਰਿਆ ਦੱਸਦਾ ਹੈ। ਸਰੋਤ ਫਾਈਲ, ਟੈਸਟ ਅਤੇ ਸੰਰਚਨਾ ਫਾਈਲ ਵਾਲੇ patch ਨਾਲ ਜਾਂਚੋ।

**ਸ਼ਡਿਊਲਡ ਕੰਮ Desktop ਦਾ ਵੱਖਰਾ ਫੀਚਰ ਹੈ।** [ਸ਼ਡਿਊਲਡ ਟਾਸਕ ਡੌਕੂਮੈਂਟੇਸ਼ਨ](https://code.claude.com/docs/en/desktop-scheduled-tasks) ਦੁਹਰਾਏ ਕੰਮ ਅਤੇ ਚਲਾਉਣ ਦੀਆਂ ਲੋੜਾਂ ਦੱਸਦੀ ਹੈ। ਰੋਜ਼ਾਨਾ ਕੰਮ ਲਈ ਭਰੋਸਾ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਚਲਾਉਣ ਦੀ ਥਾਂ ਅਤੇ ਉਪਲਬਧ ਰਹਿਣ ਵਾਲੀਆਂ ਚੀਜ਼ਾਂ ਜਾਂਚੋ।

**ਸਮੁੱਚੇ patch ਦੀ ਸਮੀਖਿਆ ਕਰੋ।** ਇਕੱਲੇ ਐਡਿਟ ਦੀ ਮਨਜ਼ੂਰੀ ਬਦਲੀਆਂ ਫਾਈਲਾਂ ਵਿਚਕਾਰ ਸਾਰੀਆਂ ਕੜੀਆਂ ਨਹੀਂ ਦਿਖਾਉਂਦੀ। ਚਲਾਉਣ ਤੋਂ ਬਾਅਦ ਅੰਤਿਮ diff ਵੇਖੋ ਅਤੇ ਸਵੀਕ੍ਰਿਤੀ ਜਾਂਚ ਵੱਖਰੇ ਤੌਰ ਤੇ ਚਲਾਓ।

## ਸੈਟਿੰਗਾਂ ਅਤੇ ਇਜਾਜ਼ਤਾਂ

**ਸੈਟਿੰਗਾਂ ਦਾ ਦਾਇਰਾ ਅਤੇ ਤਰਜੀਹ ਹੁੰਦੀ ਹੈ।** Anthropic ਦੀ [ਸੈਟਿੰਗ ਰੈਫਰੈਂਸ](https://code.claude.com/docs/en/settings) ਪ੍ਰਬੰਧਿਤ, ਯੂਜ਼ਰ, ਪ੍ਰੋਜੈਕਟ ਅਤੇ ਸਥਾਨਕ ਸੰਰਚਨਾ ਵੱਖ ਕਰਦੀ ਹੈ। ਕਲਾਇੰਟ ਫਰਕ ਦੀ ਜਾਂਚ ਤੋਂ ਪਹਿਲਾਂ ਪ੍ਰਭਾਵੀ ਸੰਰਚਨਾ ਵੇਖੋ। ਪ੍ਰੋਜੈਕਟ ਨਿਯਮ ਸੰਸਥਾ ਨੀਤੀ ਨੂੰ ਲਾਜ਼ਮੀ ਤੌਰ ਤੇ ਨਹੀਂ ਬਦਲਦਾ।

**ਇਜਾਜ਼ਤ ਮੋਡ ਇੰਟਰਐਕਸ਼ਨ ਬਦਲਦਾ ਹੈ।** ਦੋਵੇਂ ਕਲਾਇੰਟ ਇੱਕੋ ਨੀਤੀਆਂ ਨਾਲ ਤੁਲਨਾ ਕਰੋ ਅਤੇ ਆਪਣੀ ਪਸੰਦੀਦਾ ਨੀਤੀ ਵੱਖਰੇ ਤੌਰ ਤੇ ਜਾਂਚੋ। ਘੱਟ ਮਨਜ਼ੂਰੀ ਸਵਾਲ ਆਪਣੇ ਆਪ ਲਾਭ ਨਹੀਂ। ਇਜਾਜ਼ਤ ਵਾਲੇ ਕੰਮ ਟਾਸਕ ਅਤੇ ਵਾਤਾਵਰਣ ਨਾਲ ਮਿਲਣੇ ਚਾਹੀਦੇ ਹਨ।

|---|---|
| **ਪ੍ਰੋਜੈਕਟ ਫੋਲਡਰ** | ਇੱਛਿਤ ਕੋਡ ਅਤੇ ਪ੍ਰੋਜੈਕਟ ਨਿਯਮ ਲੋਡ ਕਰਦਾ ਹੈ |
| **ਅਕਾਊਂਟ ਰੂਟ** | ਪਹੁੰਚ ਅਤੇ ਬਿਲਿੰਗ ਸੰਦਰਭ ਤੈਅ ਕਰਦਾ ਹੈ |
| **ਚੁਣਿਆ ਮਾਡਲ** | ਇੰਟਰਫੇਸ ਅਤੇ ਮਾਡਲ ਬਦਲਾਅ ਮਿਲਣ ਤੋਂ ਰੋਕਦਾ ਹੈ |
| **ਇਜਾਜ਼ਤ ਨੀਤੀ** | ਚੱਲਣ ਵਾਲੀਆਂ ਕਾਰਵਾਈਆਂ ਕੰਟਰੋਲ ਕਰਦੀ ਹੈ |
| **ਰਨਟਾਈਮ ਵਾਤਾਵਰਣ** | ਕਮਾਂਡ ਅਤੇ ਟੈਸਟ ਉਪਲਬਧਤਾ ਤੈਅ ਕਰਦਾ ਹੈ |

**ਮੁੱਖ ਪ੍ਰੋਜੈਕਟ ਹਦਾਇਤਾਂ ਰਿਪੋਜ਼ਟਰੀ ਵਿੱਚ ਰੱਖੋ।** ਬਿਲਡ ਕਮਾਂਡ, ਬਾਹਰ ਰੱਖੀਆਂ ਫਾਈਲਾਂ ਅਤੇ ਸਵੀਕ੍ਰਿਤੀ ਮਾਪਦੰਡ ਲਿਖੋ। ਐਡਿਟ ਤੋਂ ਪਹਿਲਾਂ ਏਜੰਟ ਤੋਂ ਸੀਮਾਵਾਂ ਪਛਾਣਨ ਲਈ ਕਹੋ। ਫਰਕ ਮਿਲੇ ਤਾਂ ਪਹਿਲਾਂ ਸੰਰਚਨਾ ਸਮੱਸਿਆ ਹੱਲ ਕਰੋ।

## ਸੈਸ਼ਨ ਹਿਲਾਉਣਾ

```text
/desktop
```

**ਦਸਤਾਵੇਜ਼ੀ CLI-to-Desktop ਹੈਂਡਆਫ ਸੈਸ਼ਨ ਬਚਾ ਕੇ CLI ਬੰਦ ਕਰਦਾ ਹੈ।** Desktop ਰੈਫਰੈਂਸ ਇਸ ਕਮਾਂਡ ਨੂੰ ਸਮਰਥਿਤ macOS ਅਤੇ x64 Windows ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਸੈਸ਼ਨਾਂ ਤੱਕ ਰੱਖਦਾ ਹੈ। API key ਅਤੇ ਤੀਜੇ ਪੱਖ ਦੇ ਪ੍ਰੋਵਾਈਡਰ ਸੈਸ਼ਨਾਂ ਨੂੰ ਇਹ ਰਸਤਾ ਨਹੀਂ ਮਿਲਦਾ। ਨਿਰਭਰ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਵਰਜਨ ਅਤੇ ਅਕਾਊਂਟ ਵੇਖੋ।

**ਹੈਂਡਆਫ ਨੂੰ ਨਿਯੰਤਰਿਤ ਤਬਦੀਲੀ ਸਮਝੋ।** ਸਰਗਰਮ ਕੰਮ ਪੂਰਾ ਜਾਂ ਰੋਕੋ, ਮੌਜੂਦਾ branch ਪਛਾਣੋ ਅਤੇ ਲੰਬਿਤ ਬਦਲਾਅ ਵੇਖੋ। ਮੰਜ਼ਿਲ ਇੰਟਰਫੇਸ ਖੋਲ੍ਹਣ ਤੋਂ ਬਾਅਦ ਰਿਪੋਜ਼ਟਰੀ ਜਾਂਚੋ ਅਤੇ ਅਗਲਾ ਕਦਮ ਪੁੱਛੋ। ਪਹਿਲਾ ਕੰਮ ਚੱਲਦੇ ਸਮੇਂ ਉਹਨਾਂ ਫਾਈਲਾਂ ਤੇ ਦੂਜਾ ਕੰਮ ਸ਼ੁਰੂ ਨਾ ਕਰੋ।

**ਫਾਈਲਾਂ ਸਾਂਝੀਆਂ ਕਰਨਾ ਗੱਲਬਾਤ ਸਾਂਝੀ ਕਰਨ ਤੋਂ ਵੱਖਰਾ ਹੈ।** ਇੱਕੋ checkout ਖੋਲ੍ਹਣ ਵਾਲੇ ਦੋ ਕਲਾਇੰਟ ਫਾਈਲ ਸਿਸਟਮ ਬਦਲਾਅ ਵੇਖਦੇ ਹਨ, ਪਰ ਨਵੀਂ ਗੱਲਬਾਤ ਵਿੱਚ ਪਹਿਲੇ ਸੈਸ਼ਨ ਦੀ ਸੋਚ ਅਤੇ ਸੀਮਾਵਾਂ ਨਹੀਂ ਹੁੰਦੀਆਂ। ਪੋਰਟੇਬਲ ਹੈਂਡਆਫ ਲਈ ਰਿਪੋਜ਼ਟਰੀ ਵਿੱਚ ਛੋਟਾ ਟਾਸਕ ਰਿਕਾਰਡ ਰੱਖੋ।

## ਛੋਟੀ ਅਜ਼ਮਾਇਸ਼ ਨਾਲ ਚੁਣੋ

**ਦਿਖਣਯੋਗ ਲੱਛਣ ਵਾਲਾ ਬੱਗ ਵਰਤੋ।** ਰੀਪ੍ਰੋਡਕਸ਼ਨ, ਉਮੀਦ ਕੀਤਾ ਵਿਹਾਰ ਅਤੇ ਬਚਾਉਣ ਵਾਲੀਆਂ ਫਾਈਲਾਂ ਦਿਓ। ਇੱਕੋ ਬੇਸ ਰਿਵਿਜ਼ਨ, ਮਾਡਲ ਅਤੇ ਇਜਾਜ਼ਤ ਸੈਟਿੰਗਾਂ ਤੋਂ ਵੱਖਰੇ ਯਤਨ ਕਰੋ।

| ਅਜ਼ਮਾਇਸ਼ ਪੜਾਅ | ਵੇਖੋ |
|---|---|
| **ਸੰਦਰਭ** | ਲੌਗ, ਫਾਈਲਾਂ ਅਤੇ ਸਕ੍ਰੀਨਸ਼ਾਟ ਜੋੜਨ ਦੀ ਮਿਹਨਤ |
| **ਲਾਗੂ ਕਰਨਾ** | ਰੁਕਾਵਟਾਂ ਅਤੇ ਸਪਸ਼ਟੀਕਰਨ ਦੀ ਲੋੜ |
| **ਸਮੀਖਿਆ** | ਹਰ ਬਦਲੀ ਫਾਈਲ ਦੀ ਜਾਂਚ ਕਿੰਨੀ ਸੌਖੀ ਹੈ |
| **ਸੁਧਾਰ** | ਰੱਦ ਕੀਤੇ ਤਰੀਕੇ ਲਈ ਪ੍ਰਤੀਕਿਰਿਆ |
| **ਮੁਕੰਮਲਤਾ** | ਸੁਤੰਤਰ ਟੈਸਟ ਨਤੀਜਾ ਅਤੇ ਸਾਫ਼ diff |

**ਸਕ੍ਰਿਪਟ ਅਤੇ ਟਰਮੀਨਲ ਸੰਦਰਭ ਮੁੱਖ ਹੋਣ ਤਾਂ CLI ਪਸੰਦ ਕਰੋ।** **ਦਿਸਣਯੋਗ ਪ੍ਰੋਜੈਕਟ ਸਥਿਤੀ ਅਤੇ ਗ੍ਰਾਫਿਕਲ ਸਮੀਖਿਆ ਰੁਕਾਵਟ ਘਟਾਏ ਤਾਂ Desktop ਪਸੰਦ ਕਰੋ।** ਲੋੜ ਬਦਲਣ ਤੇ ਦੋਵੇਂ ਸੋਚ ਸਮਝ ਕੇ ਵਰਤੋ।

## ਸਮੱਸਿਆ ਹੱਲ ਅਤੇ ਅਗਲੇ ਕਦਮ

**ਜੇ Desktop ਵਿੱਚ CLI ਵਾਲੀ ਕਮਾਂਡ ਨਾ ਹੋਵੇ**, ਫੀਚਰ ਤੁਲਨਾ ਵੇਖੋ, ਇੰਸਟਾਲੇਸ਼ਨ ਅਸਫਲ ਨਾ ਮੰਨੋ। ਜੇ ਕਮਾਂਡ ਸਿਰਫ਼ ਟਰਮੀਨਲ ਵਿੱਚ ਚੱਲੇ, ਰਨ ਵਾਤਾਵਰਣ ਅਤੇ runtime ਖੋਜ ਦੀ ਤੁਲਨਾ ਕਰੋ। ਹੈਂਡਆਫ ਨਾ ਮਿਲੇ ਤਾਂ ਪਲੇਟਫਾਰਮ ਅਤੇ ਪ੍ਰਮਾਣੀਕਰਨ ਯੋਗਤਾ ਜਾਂਚੋ।
