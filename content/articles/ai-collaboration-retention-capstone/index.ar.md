[العودة إلى دورة التعاون بالذكاء الاصطناعي](/ai-collaboration-course-start/)

**سلّم PROP-042 مرتين**، مرة عبر GitHub أولاً ومرة عبر GitHub مع Confluence وJira. ساهم في العمل، ودع مالكين منفصلين يراجعانه، ثم يطبّق الناشرون المصرّح لهم التغيير. استخدم صناديق رمل اصطناعية معزولة بعد الدروس السابقة. يختبر المشروع الختامي الإجراء الكامل، بما في ذلك الرفض والاسترداد والتسليم المستقل، وليس جودة نص المساعد فقط.

## أهم النتائج

- **تغيير مشترك واحد** يقارن نموذجي الصلاحية.
- **الاختبارات السلبية** مهمة بقدر التسليم الناجح.
- **حزم الأدلة** تدعم المراجعة المستقلة.
- **إكمال المختبر** لا يصرّح بالنشر في الإنتاج.

## قبل البدء

**المتطلبات السابقة:** [وحدات الدورة السابقة](/ai-collaboration-course-start/)، وصول معتمد إلى صندوق الرمل، ومراجعون منفصلون. **الوقت المخطط:** من ثماني إلى اثنتي عشرة ساعة عبر جلسات متعددة، إضافة إلى المراجعة المستقلة. يعتمد الوقت الفعلي على إعداد الحساب وإصلاح العمل. **الصعوبة:** متقدمة.

**المصنوعات المطلوبة:** الميثاق، والخريطة، والسياسة، والمحوّلات، وخط الأساس، والبيان، والاقتراح المثبّت، ومراجعات المالكين، والسجل، وسجل الاسترداد، والتسليم. تمنع الصلاحيات المعتمدة على الخطة والتي لم تُمنح الإكمال، ولا تتحول إلى نجاح مفترض.

**حضّر دليلاً واحداً لكل مسار قبل الاختبار.** يجب أن يحدد المراجع الفاعل، ومراجعات المصدر، والإجراء المجرّب، والنتيجة المرصودة، والحالة النهائية من دون الاعتماد على ملخص محادثة.

## إنشاء خطي أساس

1. **أنشئ تشغيلات معزولة** باسم GitHub-first وMixed. أبقِ المراجعات والإصدارات منفصلة.
2. **استعد خط أساس الأيام السبعة** عبر إجراء كل مسار المعتمد، وسجّل المراجعات الناتجة.
3. **تحقق من ضوابط الرفض** باستخدام حسابات المساهم والمستخدم المستبعد.
4. **التقط السياق الحالي** وتحقق من اتفاق المحوّل والسياسة.
5. **حدّد النطاق:** الاحتفاظ بتصدير اصطناعي لمدة ثلاثين يوماً، مع استبعاد البيانات الحقيقية والنسخ الاحتياطية والحجوزات القانونية.

**PROP-042 تسمية ارتباط وليست موافقة قابلة لإعادة الاستخدام.** يحتاج كل تشغيل إلى مراجعة مجمّدة وأدلة مصدر خاصة به. أدرج معرّفات التشغيل في التقارير.

## تسليم GitHub أولاً

**افتح Issue وPR مرشحاً** باستخدام دروس GitHub. غيّر المتطلب والإعداد والاقتراح ودليل التشغيل معاً. التقط الأساس المحمي، وشغّل الفحوص الموثوقة، واحصل على مراجعة المنتج والعمليات عند الالتزام النهائي.

```text
Run: GitHub-first
Change: synthetic retention 7 -> 30 days
Requirement: REQ-17 revision 2
Configuration: retention_days 30
Runbook: Retention days: 30
Proposal: base revision 1, from 7, to 30
Manifest: protected pre-change source hashes
Review: product and operations at final proposal revision
Publication: merged commit and read-back
Limit: no running deletion service exercised
```

**املأ المراجع الفعلية من صندوق الرمل.** المخطط هو خريطة متوقعة وليس دليلاً مكتملاً. لا يدمج المشرف إلا بعد المراجعة، ثم يقرأ **`main`** بشكل مستقل. أغلق Issue بعد ربط السجلات النهائية.

## تسليم المسار المختلط

**اقرأ إصدارات Confluence وثبّت اقتراح Jira.** احصل على مراجعة المالكين. انشر المتطلب مع حالة التسليم المعلّق، وادمج الإعداد، وانشر دليل التشغيل، ثم اقرأ كل الأنظمة مرة أخرى قبل Done.

**سجّل كل نشر** مع دليل إصدار الصفحة أو الالتزام أو الانتقال. تبقى نسخ متطلبات المستودع لقطات. لا يثبت الفاحص المحلي صلاحية Confluence الحالية.

| المقارنة | GitHub أولاً | مكان عمل مختلط |
|---|---|---|
| **المتطلب** | مراجعة مستودع محمي | نشر راجعه مالك Confluence |
| **التنسيق** | Issue/PR | اقتراح Jira مثبت |
| **وحدة النشر** | دمج المستودع | كتابات صفحات منفصلة ودمج |
| **الحداثة** | التزام محمي | إصدارات الصفحات مع الالتزام |
| **الاسترداد** | تراجع أو تعويض راجع | تعويض موجّه بالسجل |

**اختر سير العمل حسب احتياجات الملكية.** يقلل GitHub أولاً التنسيق بين الأنظمة. يحافظ المسار المختلط على مواقع العمل ويضيف فحوص النشر والوصول.

## تشغيل مصفوفة الفشل

| الحالة | الحقن | الدليل المرصود المطلوب |
|---|---|---|
| **تغيير معتمد** | أرسل اقتراحاً راجعاً لمدة ثلاثين يوماً | قراءة متسقة ومراجعة |
| **سياق قديم** | غيّر المصدر بعد الالتقاط | رفض ومصالحة وإعادة موافقة |
| **كتابة غير مصرّح بها** | ينشر المساهم | رفض وعدم تغيير المراجعة |
| **تعارض** | يقول Jira ستيناً وConfluence سبعة | حظر ومصالحة المالك |
| **نشر جزئي** | قاطع بعد كتابة واحدة | سجل معلّق واسترداد |
| **رفض الوصول** | أزل وصول قراءة المهمة | لا نص محمي ولا نشر |
| **استرداد** | إكمال أو رجوع معتمد | مراجعات جديدة راجعها المالك |
| **تسليم** | تحصل جلسة جديدة على الخريطة والسجل فقط | قراءة جديدة وإجراء تالٍ صحيح |

**ينتمي تعارض الأنظمة إلى Mixed.** في GitHub أولاً، اختبر تعارض وصف Issue مع الملف المعتمد. شغّل الحالات الأخرى المنطبقة في كلا المسارين. لا يستبدل فشل الفاحص المحلي دليل الصلاحيات الحية.

| الحالة وملف الدليل | تشغيل GitHub أولاً | التشغيل المختلط |
|---|---|---|
| **تغيير معتمد** `01-approved-change.md` | PR مراجع وقراءة لاحقة | صفحات مراجعة ودمج وسجل |
| **سياق قديم** `02-stale-context.md` | تغيير الأساس المحمي بعد الالتقاط | تغيير صفحة صلاحية بعد الالتقاط |
| **كتابة غير مصرّح بها** `03-unauthorized-write.md` | رفض الدفع المباشر للمساهم | رفض تعديل الصفحة والانتقال |
| **تعارض** `04-conflict.md` | Issue يخالف الملف المعتمد | نص Jira يخالف Confluence |
| **نشر جزئي** `05-partial-publication.md` | توقف قبل الدمج أو القراءة | توقف بعد كتابة صفحة واحدة |
| **رفض الوصول** `06-access-denial.md` | حجب مصدر مستودع محمي | استبعاد مستخدم من صفحة مقيدة |
| **استرداد** `07-recovery.md` | رجوع أو إكمال مراجع | تعويض موجّه بالسجل |
| **تسليم** `08-handoff.md` | جلسة جديدة تقرأ الملفات المحمية | جلسة جديدة تقرأ الصفحات والسجل المعيّنين |

**أنشئ كل ملف قبل اختباره.** سجّل النتيجة المتوقعة والمرصودة، ودور الفاعل، والمراجعات الأولية والنهائية، ومرجع الدليل الأصلي، وقرار المراجع. أبقِ دليلي المسارين منفصلين.

**افصل النتائج المتوقعة عن المرصودة.** لكل حالة، سجّل معرّف التشغيل، ودور الفاعل، والمراجعات الأولية، والإجراء المجرّب، والتوقع، والملاحظة، والمراجعات الناتجة، وقرار المراجع. احذف بيانات الاعتماد ومعرّفات الحساب من التقارير المشتركة.

## تقييم الإكمال

**يتطلب النجاح دليلاً مرصوداً لكل صف منطبق** وقبولاً مستقلاً. يراجع المراجعون الصلاحيات وحداثة المصدر ومراجعة الدور والنشر الجزئي وإعادة بناء التسليم، إضافة إلى سجلات الاتساق.

**يفشل الاختبار فوراً** عند النشر غير المصرّح به، أو وصول نص مرفوض إلى النموذج، أو الكتابة الصامتة فوق أساس تغيّر. أبقِ العمل محظوراً حتى تمر الضوابط المصححة بإعادة اختبار. لا تحسب هذه الإخفاقات ضمن نتيجة إيجابية.

**قِس الحالات المكتملة والمحظورة، والاقتراحات القديمة المرفوضة، والكتابات المرفوضة، والاستردادات، ووقت المراجع.** تبقى النتائج المقترحة متوقعة حتى تُرصد.

## تخطيط التشغيلين

**لا تعِد استخدام الموافقة بين المسارين.** القيمة المطلوبة واحدة، لكن مواضع المصادر والمراجعات الملتقطة والصلاحيات وتسلسل النشر مختلفة. أعطِ كل تشغيل دليله الخاص وحزمة مراجعته.

```text
capstone-evidence/
  github-first/
    charter-and-map
    captured-sources
    fixed-proposal
    role-reviews
    consistency-results
    permission-results
    publication-readback
    recovery-and-handoff
  mixed/
    same evidence categories, independently captured
```

**هذه الأسماء مثال تنظيمي** وليست ملفات أرشيف مقدمة. خزّن الأدلة الفعلية بشكل خاص في صندوق الرمل المعتمد. استخدم أدواراً ومراجع منقحة في التسليمات المشتركة، بينما يحتفظ المراجعون بالوصول إلى السجلات الأصلية.

**عيّن مراقب اختبار قبل تشغيل الإخفاقات.** ينفّذ المساهم الإجراء المجرّب. يسجل المراقب الحالة الأولية والنتيجة والحالة الناتجة. يقرر مراجع لاحقاً إن كان الدليل يدعم الادعاء. اذكر تداخل الأدوار بدلاً من الإيحاء بقبول مستقل.

## تشغيل الإخفاقات بعزل

**أعد الضبط إلى حالة مراجعَة موثوقة بين الحالات.** يؤدي حقن انجراف المصدر وسحب الوصول وعدم تطابق دليل التشغيل معاً إلى إخفاء الضابط الذي رفض الاقتراح. يمنح فشل واحد في كل تشغيل المراجع سبباً قابلاً للتتبع.

1. **التقط الحالة الأولية:** مراجعات المصدر، والإعداد، وحالة التسليم، ودور الفاعل.
2. **طبّق حقناً اصطناعياً واحداً:** غيّر شرطاً واحداً ذا صلة عبر مسار اختبار معتمد.
3. **جرّب الإجراء المحدود:** تحقق أو قراءة أو نشر أو تسليم.
4. **سجّل الملاحظة:** المخرج الفعلي وحالة المصدر الناتجة.
5. **أصلح عبر المراجعة:** احفظ دليل الفشل قبل استعادة الضوابط.
6. **كرر الحالة الإيجابية:** تحقق من أن سير العمل المصحح ما زال يسلّم العمل المسموح.

**الفشل المخطط ما زال ملاحظة فشل.** لا تعِد تسمية النشر غير المصرّح به اختباراً ناجحاً لمجرد أنك قصدت فحصه. نجح الاختبار في كشف عيب، لكن حد النشر فشل ويحتاج إلى إصلاح.

## تفسير نتيجة مختلطة

**حزمة أدلة توضيحية:** ينجح الاتساق المحلي، ويراجع المنتج والعمليات الحزمة المثبتة، وينجح نشر المتطلب، ويُرفض تعديل دليل التشغيل. لم يندمج الإعداد بعد. تبقى حالة Jira محظورة.

| الادعاء | الحكم | السبب |
|---|---|---|
| **السجلات المرشحة متفقة** | مدعوم بفحص محلي | اجتازت السجلات المقدمة المقارنات |
| **قبل المالكون النية والعمليات** | يحتاج إلى مراجعات أصلية مثبتة | تسميات الأدوار وحدها غير كافية |
| **اكتمل التسليم لمدة ثلاثين يوماً** | غير مدعوم | خطوات النشر المطلوبة ما زالت معلقة |
| **يعمل حد الصلاحيات لكل دور** | غير مدعوم | الفعل المرفوض محدود النطاق |
| **ينبغي لمالك الاسترداد التصرف** | مدعوم كخطوة تالية | التسليم الجزئي يحتاج قراراً مراجعاً |

**الاستدلال المتوقع:** أبقِ التشغيل غير مكتمل، وتحقق من المصادر الحالية، واطلب قرار المالك المناسب. لا تُنهِ العمل بإضعاف الصلاحيات أو بوصف فحص اللقطة دليلاً على النشر الحي.

## مراجعة مع قارئ مستقل

**اطلب من المراجع إعادة بناء الأحداث**، لا قراءة استنتاجك فقط. يجب أن يحدد خط الأساس المعتمد، والاقتراح المثبت، وقرارات المالكين، والمراجعات الناتجة، والمحاولات الفاشلة، والإصلاح، والفجوات المتبقية من دون سردك.

```text
Reviewer questions:
Which source governs retention intent in this track?
Which exact package did each owner review?
Did any source change after review?
What was published, and what remains pending?
Which denied action was observed under which role?
Did protected text reach an excluded user's context?
Which repair was reviewed and read back?
Does the fresh handoff reconstruct current state independently?
```

**قيّم كل متطلب منفرداً.** استخدم Supported أو Failed أو Blocked أو Not run مع مرجع دليل. الاتساق والموافقة والصلاحيات والاسترداد والتسليم متطلبات منفصلة. لا يعوض جمع اختبارات محلية ناجحة حد نشر حي فاشل.

```text
Run ID and track:
Reviewer role and review date:
Case 01 approved change: status ___ evidence ___ gap ___
Case 02 stale context: status ___ evidence ___ gap ___
Case 03 unauthorized write: status ___ evidence ___ gap ___
Case 04 conflict: status ___ evidence ___ gap ___
Case 05 partial publication: status ___ evidence ___ gap ___
Case 06 access denial: status ___ evidence ___ gap ___
Case 07 recovery: status ___ evidence ___ gap ___
Case 08 handoff: status ___ evidence ___ gap ___
Overall decision: Supported / Failed / Blocked / Not run
Next accountable role and action:
```

**يعني Supported أن المراجع وجد دليلاً مرصوداً لكل حالة منطبقة.** سجّل Failed عند فشل ضابط مرصود، وBlocked عند غياب الوصول أو الضابط، وNot run للحالة غير المجربة. أبقِ المرجع الأصلي لكل حالة في ملف دليلها.

**بوابة نجاح الدورة:** أكمل مساري GitHub-first وMixed. يحتاج كل مسار إلى Supported لكل الحالات الثماني المنطبقة. يحظر حد فاشل أو قراءة أصلية مفقودة المسار. ينتج عن المسار المكتمل نتيجة جزئية موثقة، لا إكمال الدورة.

**حزمة نموذج منقحة، توضيحية فقط:**

```text
Track: github-first | Run: G-01 | Reviewer: separate pilot role
Base: protected commit base-001 | Fixed proposal: PROP-042 r1
Approvals: product review ref P-01, operations review ref O-01
Consistency: local check pass, saved output ref C-01
Permission: contributor direct push denied, native event ref D-01
Publication: merged commit merge-002, fresh clone confirms thirty
Exception: backups and legal holds remain excluded
Recovery: interruption case R-01 read back and resolved through review
Handoff: second reader found current base, exception, and next action
Runtime limit: no production deletion or deployment claim
Decision: Supported for synthetic GitHub-first track only
```

استبدل كل مرجع توضيحي بأثر مرصود من صندوق الرمل. كرر الحزمة كاملة للمسار المختلط مع إصدارات مصادره ومراجعاته. يجب أن يرفض المراجع موافقة GitHub المنسوخة في الحزمة المختلطة.

## كتابة قرار محدود

**يحدد القرار الختامي المفيد المشروع التجريبي التالي**، لا نشرًا غير مقيد. اختر مثلاً إعداد تصدير اصطناعي آخر مع الأدوار نفسها ومسار البحث المباشر، مع إبقاء البيانات الحقيقية والنشر الآلي خارج النطاق.

| عنصر القرار | التفاصيل المطلوبة |
|---|---|
| **النطاق** | تغيير تالٍ واحد واستبعادات واضحة |
| **الدليل** | الحالات المدعومة والإخفاقات غير المحلولة |
| **الضوابط** | المتطلبات المفروضة من المنصة والإجرائية كل على حدة |
| **المالكون** | الدور المسؤول عن كل فجوة متبقية |
| **فجوة التشغيل** | سلوك الحذف أو النشر غير المختبر |
| **شروط التوقف** | وصول مفقود أو صلاحية متغيرة أو نشر غير مصرّح به |

**فحص الإكمال:** تصمد حزمتا التشغيل أمام إعادة بناء مستقلة، وتحمل حالات الفشل المنطبقة أدلة مرصودة، وتبقى الضوابط غير المحلولة ظاهرة. إذا اكتمل مسار GitHub فقط، فأبلغ عن إكمال جزئي للدورة ولا تفترض أن المسار المختلط سيتصرف بالطريقة نفسها.

## استكشاف الأخطاء والرجوع

**دليل المسار السعيد فقط:** أعد اختبارات الرفض والانقطاع. **تداخل الأدوار:** أفصح عنه وأعد الاختبار بمستخدمين منفصلين. **ضوابط خطة مفقودة:** توقف واحصل على صندوق رمل معتمد.

**الرجوع:** استعد خط الأساس عبر PRs مراجعة وتعديلات Confluence، وألغِ التكاملات المؤقتة، وأرشف أدلة Jira، ونفذ تنظيفاً اصطناعياً معتمداً من المالك بعد الاحتفاظ بالأدلة. احفظ تاريخ الاسترداد.

## إنشاء قرار النشر

```text
Decision: another synthetic pilot, blocked, or rejected
Evidence: both run packages and failure matrix
Unenforced requirements: procedural controls listed explicitly
Provider review: input scope and retention handling
Owner coverage: product, operations, policy, repository, delivery
Production gaps: runtime tests, secrets, deployment, access review
Next action: one bounded follow-up with accountable role
Review date: assigned by pilot owners
```

**الاستدلال المتوقع:** يدعم النجاح الاصطناعي مشروعاً تجريبياً محدوداً آخر. يحتاج الإنتاج إلى موافقة منفصلة للبيانات الحقيقية والنشر ومعالجة المزوّد وسلوك التشغيل. لا يساوي جواب مساعد ناجح تصريحاً بالنشر.
