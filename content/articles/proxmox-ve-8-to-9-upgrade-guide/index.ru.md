**Proxmox VE 9.0 выпущена на базе Debian 13 Trixie с ядром 6.14, QEMU 10, LXC 6 и ZFS 2.3.** В руководстве описаны ручной путь обновления на месте и автоматизированный скрипт Bash, который определяет конфигурацию и обрабатывает изменения репозиториев, известные проблемы и предварительные проверки.

## Новое в Proxmox VE 9

Proxmox VE 9, выпущенная в августе 2025 года, представляет собой обновление основной версии. Ключевые изменения:

| Компонент | PVE 8 | PVE 9.0 |
|-----------|--------|--------|
| **Базовая Debian** | Bookworm (12) | Trixie (13) |
| **Ядро по умолчанию** | 6.8 | 6.14 |
| **QEMU** | 9.x | 10.x |
| **LXC** | 5.x | 6.x |
| **ZFS** | 2.2 | 2.3 |
| **Ceph** | Quincy / Reef / Squid | Squid (19.2) |
| **cgroup** | cgroupv2 (v1 еще возможна) | Только cgroupv2 |

[Proxmox VE, версия 9.2](https://forum.proxmox.com/threads/proxmox-virtual-environment-9-2-available.183742/) по умолчанию поставляется с ядром 7.0, QEMU 11, LXC 7 и ZFS 2.4. В Proxmox VE 9.2 по умолчанию используется Ceph Tentacle, но Squid остается доступной. Переход на Squid перед обновлением кластера Ceph на VE 8 является отдельным предварительным условием.

**К основным новым функциям PVE 9.0 и более поздних выпусков относятся:**
- Снимки виртуальных машин на толстом LVM с помощью цепочек томов (технологическая предварительная версия → производственная эксплуатация в 9.1)
- Правила аффинности высокой доступности вместо групп HA
- SDN Fabrics для сетей Ceph с полной связностью OpenFabric и OSPF
- Новый мобильный веб-интерфейс (Rust/Yew)
- Расширение устройств ZFS RAIDZ без простоя
- Динамическая балансировка нагрузки с Cluster Resource Scheduler (PVE 9.2)
- WireGuard и BGP как протоколы сетевой фабрики SDN (PVE 9.2)
- Теперь `/tmp` монтируется как `tmpfs` (изменение Debian Trixie, файлы периодически удаляются)

## Перед началом: предварительные условия

**Перед изменением репозиториев необходимо выполнить все эти требования.** Полный список проверок приведен в [официальной вики обновления, раздел «Предварительные условия»](https://pve.proxmox.com/wiki/Upgrade_from_8_to_9#Prerequisites).

### 1. Требуется Proxmox VE 8.4 или новее

```bash
pveversion
```

В выводе должна быть версия `pve-manager/8.4.x` или новее. Если версия ниже:

```bash
apt update && apt dist-upgrade
```

### 2. Ceph должен работать на Squid (19.x), только для гиперконвергентной конфигурации

```bash
ceph --version
```

В выводе должна быть версия 19.x (Squid). Если у вас Reef (18.x) или Quincy (17.x), сначала обновите Ceph. Переходите между версиями поочередно:

- Quincy (17) → Reef (18) → Squid (19)

*Не начинайте обновление PVE 9, пока все узлы Ceph не перейдут на Squid.*

### 3. Proxmox Backup Server установлен на том же узле

Если PBS 3.4 и PVE 8.4 работают на одном узле, следуйте [инструкциям по совместной установке](https://pbs.proxmox.com/wiki/Upgrade_from_3_to_4#Installed_alongside_Proxmox_VE) и выполните оба обновления в одной операции APT. Убедитесь, что резервные копии можно восстановить, и запустите `pve8to9 --full` и `pbs3to4 --full` до изменения репозиториев. Устраните найденные проблемы до продолжения.

### 4. Требования к доступу

- **Рекомендуется**: доступ к консоли через IPMI, iKVM или физическую клавиатуру. Сеанс SSH прервется при перезапуске служб.
- **SSH**: используйте `tmux` или `screen`, чтобы обновление продолжилось при потере соединения:
  ```bash
  tmux new -s upgrade
  ```

### 5. Место на диске

```bash
df -h /
```

Нужно не менее **5 ГБ свободного места**, лучше 10 ГБ или больше.

### 6. Проверенные резервные копии

До продолжения скопируйте все ВМ и контейнеры на внешнее хранилище. Проверьте восстановление. Проверенная резервная копия обязательна.

## Несовместимые изменения, о которых важно знать

Прочитайте этот раздел до обновления. Некоторые изменения требуют действий до или после обновления.

### cgroup V1 больше не поддерживается

PVE 9 совсем не поддерживает устаревшую среду cgroupv1. Если вы включали ее ранее:

```bash
grep -E 'cgroup_no_v1|systemd.unified_cgroup_hierarchy=0' /proc/cmdline
```

Если команда что-то выводит, удалите параметр ядра из `/etc/default/grub` и выполните `update-grub` до обновления.

**Влияние на контейнеры**: контейнеры с systemd 230 или более ранней версией (CentOS 7, Ubuntu 16.04) не запустятся в PVE 9. До перехода на PVE 9 перенесите такие нагрузки. Поддержка Proxmox VE 8.4 поставщиком завершилась в августе 2026 года.

### Группы HA устарели

Вместо групп HA используются правила HA. Они автоматически переносятся после перехода всех узлов кластера на PVE 9. Ручные действия не требуются, но проверьте результат после обновления последнего узла.

### Привилегия VM.Monitor удалена

Обновите пользовательские роли, в которых указана `VM.Monitor`. Для базового доступа к монитору KVM используйте `Sys.Audit`. Скрипт `pve8to9` находит затронутые роли.

### Новая привилегия: VM.Replicate

Теперь для создания и изменения заданий репликации хранилища нужна привилегия `VM.Replicate` на `/vms/<vmid>`. При необходимости измените пользовательские роли.

### Для привилегированных контейнеров LXC требуется Sys.Modify

Для создания новых привилегированных контейнеров теперь требуется `Sys.Modify`. Для восстановления существующего привилегированного контейнера на месте эта привилегия не нужна.

### systemd-sysctl больше не читает /etc/sysctl.conf

После обновления пользовательские настройки в `/etc/sysctl.conf` будут молча игнорироваться. До перезапуска перенесите их в `/etc/sysctl.d/<NN>-name.conf`.

```bash
# Проверьте содержимое sysctl.conf
grep -v '^\s*#\|^\s*$' /etc/sysctl.conf
```

### /tmp теперь является tmpfs

Debian Trixie монтирует `/tmp` как tmpfs объемом до 50% оперативной памяти. Во время работы системы файлы периодически удаляются. Если вы используете `/tmp` для больших временных файлов, перенесите эту работу в `/var/tmp` или на отдельную точку монтирования.

### Совместимость Veeam с резервным копированием и восстановлением {#veeam-backup-broken-for-qemu-machine-version--100}

До обновления проверьте сборки [Veeam Backup & Replication и модуля Proxmox](https://helpcenter.veeam.com/docs/vbr/userguide/pve_system_requirements.html). В текущих требованиях указана поддержка Proxmox VE с версии 8.2 до 9.2 на узлах x86-64, установленных с официального ISO Proxmox. Для старых сборок Veeam действуют собственные диапазоны поддержки.

Текущие [ограничения Veeam](https://helpcenter.veeam.com/docs/vbr/userguide/pve_limitations.html) допускают резервное копирование ВМ с хранилища на базе LVM, если включены Snapshots as Volume Chains (SAVC). Это не означает, что SAVC поддерживается для файлов рабочих узлов Veeam или как место назначения Instant Recovery. Отдельная проблема восстановления, описанная в [KB4773](https://www.veeam.com/kb4773), затрагивает типы машин QEMU до версии 10 с дисками QCOW2, восстановленными в хранилище SAVC на PVE 9. Используйте назначение без SAVC либо восстановите диск в RAW, как указано в документации. Это обходные решения для восстановления, а не причина закреплять тип машины для всего парка. Прежде чем полагаться на обновление, проверьте резервное копирование и восстановление на планируемом хранилище.

### Имена сетевых интерфейсов могут измениться

Ядро 6.14 распознает больше функций сетевых карт, чем 6.8. Некоторые сетевые карты получают дополнительные суффиксы в именах. Перед обновлением инструмент `pve-network-interface-pinning` может закрепить за всеми интерфейсами стабильные имена `nicX`:

```bash
pve-network-interface-pinning --help
```

## Вариант A: ручное обновление на месте

Выполните официальные шаги из [руководства по обновлению Proxmox VE](https://pve.proxmox.com/wiki/Upgrade_from_8_to_9).

### Шаг 1: запустите проверку pve8to9

```bash
pve8to9 --full
```

До продолжения устраните все пункты `FAIL`. После каждого исправления запускайте проверку повторно.

### Шаг 2: перенесите работающие ВМ, если узел состоит в кластере

```bash
qm migrate <vmid> <target-node>
pct migrate <ctid> <target-node>
```

### Шаг 3: полностью обновите PVE 8

```bash
apt update && apt dist-upgrade
pveversion   # должна показывать версию 8.4.1 или новее
```

### Шаг 4: обновите базовые репозитории Debian

```bash
sed -i 's/bookworm/trixie/g' /etc/apt/sources.list
sed -i 's/bookworm/trixie/g' /etc/apt/sources.list.d/pve-enterprise.list
```

Закомментируйте или удалите все оставшиеся строки репозиториев для Bookworm.

### Шаг 5: добавьте репозиторий пакетов PVE 9

**Enterprise, требуется подписка:**

```bash
cat > /etc/apt/sources.list.d/pve-enterprise.sources << EOF
Types: deb
URIs: https://enterprise.proxmox.com/debian/pve
Suites: trixie
Components: pve-enterprise
Signed-By: /usr/share/keyrings/proxmox-archive-keyring.gpg
EOF
```

**Без подписки:**

```bash
cat > /etc/apt/sources.list.d/proxmox.sources << EOF
Types: deb
URIs: http://download.proxmox.com/debian/pve
Suites: trixie
Components: pve-no-subscription
Signed-By: /usr/share/keyrings/proxmox-archive-keyring.gpg
EOF
```

Проверьте с помощью `apt update && apt policy`, что новый репозиторий отображается без ошибок. Затем удалите старый файл `.list` или закомментируйте его.

### Шаг 6: обновите репозиторий Ceph, только для гиперконвергентной конфигурации

```bash
cat > /etc/apt/sources.list.d/ceph.sources << EOF
Types: deb
URIs: https://enterprise.proxmox.com/debian/ceph-squid
Suites: trixie
Components: enterprise
Signed-By: /usr/share/keyrings/proxmox-archive-keyring.gpg
EOF
```

В конфигурации без подписки используйте `http://download.proxmox.com/debian/ceph-squid` с `pve-no-subscription`.

### Шаг 7: обновите индекс пакетов

```bash
apt update
```

Убедитесь, что ошибок нет.

### Шаг 8: выполните dist-upgrade

```bash
apt dist-upgrade
```

Операция занимает от 5 до более чем 60 минут в зависимости от скорости хранилища. Во время обновления:

- **`/etc/issue`**: оставьте текущую версию (безопасный выбор)
- **`/etc/lvm/lvm.conf`**: установите версию сопровождающего пакета (рекомендуется)
- **`/etc/ssh/sshd_config`**: установите версию сопровождающего пакета, если файл не настраивали
- **`/etc/default/grub`**: оставьте текущую версию, если изменяли файл
- **`/etc/chrony/chrony.conf`**: установите версию сопровождающего пакета, если файл не изменяли

### Шаг 9: перезагрузите систему

```bash
reboot
```

Перезагрузка нужна, даже если ядро 6.14 было установлено в PVE 8 как дополнительный вариант. Ядро пересобирается с инструментарием PVE 9.

### Шаг 10: действия после обновления

```bash
# Очистите кеш браузера: Ctrl+Shift+R (или ⌘+Alt+R в macOS)
# Проверьте все узлы кластера:
pvesh get /nodes

# В кластерах группы HA автоматически переходят на правила HA после обновления всех узлов до PVE 9
journalctl -eu pve-ha-crm  # проверьте наличие ошибок
```

## Вариант B: автоматизированный скрипт (pve8to9-upgrade.sh)

Ручной процесс включает множество условных шагов, которые зависят от конфигурации. Скрипт `pve8to9-upgrade.sh` автоматизирует их все.

**Источник скрипта:** [репозиторий Gist со скриптом](https://gist.github.com/simeononsecurity/ba3831f487c4e960f9e218c7da5c4b8d)

### Что делает скрипт

Скрипт автоматически выполняет полное обновление, включая:

| Проверка | Действие |
|-----------|--------|
| Репозитории Enterprise или без подписки | Использует тип репозитория, который **включен сейчас**, и не включает Enterprise на узлах без подписки |
| Версия Ceph | Останавливает процесс для Quincy или Reef и показывает пошаговую инструкцию обновления Ceph |
| Тип репозитория Ceph | Создает новый `ceph.sources` в соответствии с используемым типом репозитория |
| Драйвер NVIDIA vGPU | Останавливает процесс, если версия ниже 570 (минимум GRID 18.3) |
| Проброс GPU NVIDIA | Показывает предупреждение и создает напоминание о тестировании после обновления |
| Репозитории CUDA | Заменяет `debian12` на `debian13` в URI |
| Метапакет systemd-boot | Удаляет его (это исправляет ошибку Debian #1110177, из-за которой прекращается dist-upgrade) |
| Пользовательские настройки sysctl.conf | Переносит их в `/etc/sysctl.d/99-pve8to9-migrated.conf` |
| Блокировка FRR после старта | Исправляет `/etc/network/interfaces` до перезагрузки |
| `systemd-journald-audit.socket` | Отключает его, чтобы во время обновления не было избытка журналов |
| Проблема GRUB с UEFI и LVM | Устанавливает `grub-efi-amd64` и записывает памятку по восстановлению в `/root/` |
| Сторонние репозитории `bookworm` | Комментирует их и оставляет напоминание об обновлении |
| Конфликт `linux-image-amd64` | Удаляет пакет, если он установлен |
| Автоматическая активация LVM | Запускает скрипт миграции до и после обновления |
| Proxmox Backup Server (сервер резервного копирования Proxmox) | Проверяет `pbs3to4 --full` и обновляет репозитории PBS для Trixie |
| Корневая файловая система ZFS | Обнаруживает и подтверждает конфигурацию; дополнительных действий не нужно |

Все изменения записываются в `/var/log/pve8to9-upgrade-<timestamp>.log`. Резервные копии репозиториев APT сохраняются в `/root/pve8to9-apt-backups/`. Файлы не копируются с расширением `.bak` в `/etc/apt/sources.list.d/`, иначе Web UI покажет ошибку «invalid extension» (недопустимое расширение).

### Установка и использование

```bash
# Скачайте скрипт
curl -fsSL https://gist.githubusercontent.com/simeononsecurity/ba3831f487c4e960f9e218c7da5c4b8d/raw/pve8to9-upgrade.sh \
  -o pve8to9-upgrade.sh

# Сделайте файл исполняемым
chmod +x pve8to9-upgrade.sh

# Проверьте скрипт до запуска (всегда читайте скрипты перед запуском от root)
less pve8to9-upgrade.sh
```

**Режимы запуска:**

```bash
# Полный интерактивный режим (рекомендуется)
./pve8to9-upgrade.sh

# Автоматически подтвердить все безопасные исправления без разрушительных последствий
./pve8to9-upgrade.sh --yes

# Пробный запуск: показать все изменения без их применения
./pve8to9-upgrade.sh --dry-run

# Пропустить предварительную проверку pve8to9 --full (не рекомендуется)
./pve8to9-upgrade.sh --skip-preflight
```

*При подключении по SSH запускайте скрипт в `tmux` или `screen`.*

### Пример вывода скрипта

Перед тем как предложить продолжить, скрипт показывает сводку обнаруженной конфигурации:

### Блокирующие проверки безопасности скрипта

Скрипт **откажется продолжать**, если истинно любое из этих условий:

- cgroup V1 явно включена в командной строке ядра
- Ceph все еще работает на Quincy (17.x) или Reef (18.x), скрипт покажет команды обновления Ceph
- Драйвер NVIDIA vGPU ниже версии 570 (GRID 18.3)
- Версия PVE ниже 8.4

Для каждой блокирующей проблемы скрипт выводит точные команды для ее решения. После этого проверку нужно запустить снова.

## Известные проблемы обновления

### GRUB не загружается с LVM в режиме UEFI

**Затрагивает** системы с root на LVM, загрузкой в режиме UEFI и обновлением с PVE 7.x.

```bash
# Исправление (запустите в работающей системе после обновления):
[ -d /sys/firmware/efi ] && apt install grub-efi-amd64
```

Скрипт `pve8to9-upgrade.sh` обнаруживает сочетание UEFI и LVM и автоматически устанавливает этот пакет. Он также создает памятку по восстановлению `/root/GRUB-RECOVERY-CHEATSHEET.txt`.

**Если узел уже завис** на `grub rescue>` или сообщении "disk 'lvmid/...' not found" (диск не найден):

1. Загрузите ISO PVE → Advanced → **Rescue Boot**
2. Или выполните действия из [раздела восстановления GRUB для LVM](https://pve.proxmox.com/wiki/Recover_From_Grub_Failure#Recovering_from_grub_.22disk_not_found.22_error_when_booting_from_LVM) в официальной вики

### Метапакет systemd-boot прерывает dist-upgrade

Метапакет `systemd-boot` автоматически устанавливался в системах PVE 8.1–8.4, развернутых с помощью ISO. В Trixie он содержит обработчики, срабатывающие при обновлении других пакетов. Они могут прервать `dist-upgrade`, если ESP не смонтирован (ошибка Debian #1110177).

```bash
# Удалите его до dist-upgrade:
apt remove systemd-boot
# НЕ удаляйте systemd-boot-efi или systemd-boot-tools, они должны остаться
```

Скрипт `pve8to9-upgrade.sh` автоматически обрабатывает эту ситуацию и подробно объясняет причину.

### Passthrough PCI иногда не работает с ядром 6.14

Некоторые пользователи сообщают, что ВМ с passthrough PCI не запускаются на ядре 6.14. Если это происходит:

```bash
# Временно закрепите предыдущее ядро:
proxmox-boot-tool kernel pin 6.8.12-4-pve
```

### Конфигурации Ceph full mesh зависают при перезагрузке

Если `/etc/network/interfaces` содержит:

```
post-up /usr/bin/systemctl restart frr.service
```

Замените строку на:

```
post-up /usr/bin/systemctl is-active --quiet frr.service && /usr/bin/systemctl restart frr.service || true
```

Сделайте это **до перезагрузки**. Скрипт автоматически обнаруживает и исправляет этот вариант.

### Тонкий пул LVM требует восстановления

После обновления в некоторых системах появляется сообщение:

```
Check of pool pve/data failed (status:64). Manual repair required!
```

Исправление:

```bash
lvconvert --repair pve/data
```

### Минимальная версия драйвера NVIDIA vGPU

До обновления нужна как минимум версия **драйвера 570.158.02** (GRID 18.3). Старые драйверы несовместимы с ядром 6.x.

```bash
nvidia-smi --query-gpu=driver_version --format=csv,noheader
```

## Порядок обновления кластера

Обновляйте узлы по одному. Перед переходом к следующему узлу убедитесь, что текущий работает исправно.

```bash
# Проверьте состояние кластера до обновления каждого узла:
pvecm status
ceph -s   # если развернут Ceph
```

**Правила миграции при частичном обновлении:**

- ВМ/CT с PVE 8 на PVE 9: всегда работает
- ВМ/CT с PVE 9 на PVE 8: обычно не поддерживается

После перехода всех узлов на PVE 9 группы HA автоматически переходят на правила аффинности HA. Проверьте наличие ошибок:

```bash
journalctl -eu pve-ha-crm
```

## Устранение неполадок

### Обновление зависло или появляется сообщение об удалении proxmox-ve

Если отображается:

```
W: (pve-apt-hook) You are attempting to remove the meta-package 'proxmox-ve'!
```

Один или несколько пакетов не обновляются, потому что настроен репозиторий Bookworm. Найдите оставшиеся записи Bookworm:

```bash
grep -r 'bookworm' /etc/apt/sources.list /etc/apt/sources.list.d/
```

Закомментируйте их, затем выполните:

```bash
apt update && apt dist-upgrade
```

Если процесс завершился частично:

```bash
apt -f install
```

### Система не загружается после обновления ZFS

Если корневая файловая система использует ZFS и загрузка выполняется через устаревший BIOS, см. руководство [ZFS: переход с Legacy-Boot на Proxmox Boot Tool](https://pve.proxmox.com/wiki/ZFS:_Switch_Legacy-Boot_to_Proxmox_Boot_Tool). В системах с ZFS загрузкой должен управлять `proxmox-boot-tool`, а не непосредственно GRUB, чтобы пережить обновления функций ZFS.

## Контрольный список после обновления

После перезагрузки каждого узла:

- [ ] Очистите кеш браузера (`Ctrl+Shift+R` / `⌘+Alt+R`)
- [ ] `pveversion` показывает 9.x
- [ ] `uname -r` показывает 6.14.x или новее
- [ ] Все ВМ и CT запускаются корректно
- [ ] Состояние Ceph: `ceph -s` показывает HEALTH_OK
- [ ] Если UEFI и LVM: убедитесь, что дата изменения `grubx64.efi` недавняя
- [ ] Если используется passthrough NVIDIA: проверьте непроизводственную ВМ
- [ ] Обновите сторонние репозитории, закомментированные во время обновления
- [ ] Перенесите пользовательские настройки `/etc/sysctl.conf` в `/etc/sysctl.d/`

## Проверка после обновления

После обновления проверьте конфигурацию репозиториев, кворум кластера, состояние хранилища, запуск гостевых систем, резервные копии, правила брандмауэра и административный доступ. Прежде чем объявить обновление завершенным, изучите системные журналы. Если кластер поддерживает такую возможность, проверьте восстановление одной гостевой системы на отдельном узле.

Для команд, зависящих от версии, используйте актуальное [руководство администратора Proxmox VE](https://pve.proxmox.com/pve-docs/) и [примечания к выпускам](https://pve.proxmox.com/wiki/Roadmap). Не переносите команду из старой версии, не проверив целевую версию и состояние резервных копий.
