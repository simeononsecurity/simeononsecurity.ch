[Вернуться к практическому курсу по рабочим процессам с ИИ](/effective-ai-course-start/)

**Хороший запрос описывает работу и способ оценки результата.** Дополнительные слова не восполняют отсутствующие границы задачи. В этом уроке расплывчатый запрос преобразуется в пакет задач для практической работы курса.

**Цель обучения:** вы составите ограниченный пакет задачи с источником, областью файлов, проверками и условием остановки.

## Главное

- **Результат** называет нужный артефакт или поведение.
- **Область работ** называет разрешенные файлы и исключенные действия.
- **Источник** указывает утвержденное требование.
- **Критерии приемки** делают успех наблюдаемым.
- **Условия остановки** предотвращают догадки и неразрешенную дальнейшую работу.

## Перед началом

**Предварительные условия:** распакованная лабораторная работа, ее файл `docs/requirements.md` и [урок о контексте репозитория](/articles/effective-ai-agents-md-context/). Выделите 30 минут. Уровень сложности начальный. Упражнение завершается письменным пакетом. Код пока менять не требуется.

## Сравните два запроса

**Расплывчатый запрос:** «Улучши скрипт задач». Агент может переписать вывод, добавить зависимости, изменить примерные данные или пропустить тесты. В запросе ни один из этих вариантов не определен.

**Ограниченный запрос:** «Добавь необязательный фильтр состояния в `task_report.py` согласно редакции 1 файла `docs/requirements.md`. Сохрани вывод по умолчанию. Добавь тесты. Не меняй примерные данные. Остановись до коммита». Агент по-прежнему выбирает детали реализации, но задача определяет критерии успеха.

| Часть пакета | Пример лабораторной работы | Проверка |
|---|---|---|
| **Результат** | Добавить `--status` в отчет | Работают оба допустимых значения |
| **Источник** | `docs/requirements.md`, редакция 1 | Код соответствует утвержденным значениям |
| **Область работ** | Только программа и тесты | В diff нет других файлов |
| **Ограничения** | Сохранить вывод по умолчанию и примерные данные | Базовый вывод остается `Total tasks: 4` |
| **Доказательство** | Команда тестирования и ручные запуски | Вывод совпадает с ожидаемыми количествами |
| **Остановка** | Не выполнять commit или push | История Git и удаленный репозиторий не меняются |

## Используйте шаблон повторно

**Скопируйте этот шаблон** для небольшой задачи по программированию или исследованию. Удалите не относящиеся к делу поля вместо того, чтобы заполнять их расплывчатым текстом.

```text
Outcome:
Authoritative source and revision:
Relevant files or records:
Allowed changes:
Excluded changes and actions:
Examples of desired behavior:
Completion checks:
Stop or ask when:
Report back with:
```

**Для лабораторной работы** заполненный пакет выглядит так:

```text
Outcome: Add an optional --status filter to task_report.py.
Source: docs/requirements.md, revision 1.
Relevant files: task_report.py, tasks.json, tests/.
Allowed changes: task_report.py and focused tests.
Excluded: tasks.json, new dependencies, commits, pushes.
Examples: no filter prints Total tasks: 4. Open and done each print 2.
Checks: run unit tests and four manual commands: no filter, open, done, and invalid.
The invalid value must exit nonzero with a clear error.
Stop or ask: source conflict, missing file, unrelated failing baseline.
Report: changed files, commands, observed outputs, unresolved issues.
```

**В Windows** используйте `py -3` в командах пакета, если в вашей среде применяется средство запуска Python.

**Пакет не предписывает каждую строку кода.** Агент выбирает небольшую реализацию, а результат остается проверяемым.

## Добавляйте примеры аккуратно

**Точный пример устраняет неоднозначность.** Примеры `open` и `done` задают вывод для предоставленного файла с четырьмя задачами. Они не устанавливают общее правило для всех файлов. Для другого файла количество зависит от его записей.

**Разделяйте ожидаемое и наблюдаемое.** До запуска программы `Total tasks: 2` является ожидаемым результатом для каждого состояния. После запуска вывод терминала становится наблюдением. Если значения различаются, проверьте данные и реализацию, прежде чем заявлять об успехе.

## Установите условие остановки

**Предположим, файл требований отсутствует.** В пакете он указан как утвержденный источник. Остановитесь и запросите требование, вместо того чтобы выводить допустимые значения из старого чата или примерной задачи.

**Предположим, базовые тесты не проходят до изменений.** Зафиксируйте сбой и спросите, нужно ли сначала исправить исходное состояние. Поздний успешный запуск не покажет, был ли причиной фильтр или исходное состояние.

**Предположим, агент хочет создать commit.** Пакет исключает коммиты. Попросите остановиться после diff и тестов. Вы решите, соответствует ли последующий commit процессу проекта.

## Проверьте пакет

**Начислите один балл за каждый ответ:** результат конкретен? Назван управляющий источник? Область файлов ясна? Указаны как минимум две наблюдаемые проверки? Есть условие остановки? Если баллов меньше пяти, пересмотрите пакет до передачи задачи.

**Ваш результат:** сохраните итоговый пакет задач и однострочное пояснение одного условия остановки. Передайте его агенту-программисту в следующем практическом уроке или вручную укажите ожидаемые результаты на учебном маршруте.

## Проверьте понимание

1. **Вопрос:** что делает пакет задач проверяемым? **Ответ:** Источник, разрешенные файлы, наблюдаемые проверки и условие остановки.
2. **Вопрос:** что агенту делать, если в источнике не хватает нужной детали? **Ответ:** Остановиться и сообщить о пропущенной детали, а не придумывать ее.

## Устранение проблем

- **Агент меняет слишком много:** укажите в пакете файлы и исключенные действия.
- **Агент задает много вопросов:** предоставьте отсутствующий источник или конкретный пример.
- **Агент слишком рано заявляет об успехе:** запросите фактический вывод команд и проверьте файлы.
- **Пакет становится слишком длинным:** замените скопированный текст источника путем и редакцией.
