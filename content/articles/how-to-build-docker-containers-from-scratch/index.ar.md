**كيفية إنشاء حاويات Docker**

Docker أداة قوية لإنشاء تطبيقات قابلة للنقل ويسهل نشرها. في هذا الدليل، سنتناول الخطوات الأساسية لإنشاء حاويات Docker وبنائها. وسنستعرض أيضًا أفضل الممارسات والنصائح لضمان كفاءة حاويات Docker وأمانها وسهولة استخدامها.

## فهم Docker

قبل أن نبدأ في بناء حاويات Docker، من المهم فهم ماهية Docker وكيفية عملها.

Docker أداة تتيح لك تجميع تطبيق واعتمادياته في حاوية يمكن تشغيلها على أي نظام. تكون الحاوية معزولة عن النظام المضيف، وتتضمن كل ما يلزم لتشغيل التطبيق، بما في ذلك الشيفرة وبيئة التشغيل وأدوات النظام والمكتبات والإعدادات.

الحاويات خفيفة الوزن وسهلة النشر، لذلك تُعد خيارًا شائعًا لبناء التطبيقات ونشرها. باستخدام Docker، يمكنك إنشاء الحاويات وإدارتها وتشغيلها عبر واجهة سطر أوامر بسيطة.

## بناء صورة Docker

لبناء حاوية Docker، تحتاج أولًا إلى إنشاء صورة Docker. صورة Docker لقطة لحاوية تتضمن جميع الملفات والمكتبات والاعتماديات اللازمة لتشغيل التطبيق.

فيما يلي الخطوات الأساسية لإنشاء صورة Docker:

1. **إنشاء Dockerfile**
2. **بناء الصورة**
3. **تشغيل الحاوية**

### الخطوة 1: إنشاء Dockerfile

الخطوة الأولى لبناء صورة Docker هي إنشاء Dockerfile. وهو ملف نصي يحتوي على التعليمات اللازمة لبناء الصورة. إليك مثالًا على Dockerfile بسيط:

```bash
FROM ubuntu:latest
RUN apt-get update && apt-get install -y nginx
COPY index.html /var/www/html/
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

لنشرح هذا Dockerfile:

- يحدد `FROM ubuntu:latest` الصورة الأساسية المستخدمة للحاوية. في هذا المثال، نستخدم أحدث إصدار من Ubuntu.
- يحدّث `RUN apt-get update && apt-get install -y nginx` قائمة الحزم ويثبّت خادم الويب nginx.
- ينسخ `COPY index.html /var/www/html/` ملف index.html إلى جذر الويب في الحاوية.
- يتيح `EXPOSE 80` المنفذ 80 للنظام المضيف.
- يبدأ `CMD ["nginx", "-g", "daemon off;"]` خادم nginx ويشغّله في المقدمة.

### الخطوة 2: بناء الصورة

بعد إنشاء Dockerfile، يمكنك بناء الصورة باستخدام الأمر `docker build`. إليك مثالًا:

```bash
docker run -d -p 80:80 my-nginx-image
```

لنشرح هذا الأمر:

- يخبر `docker run` Docker بتشغيل حاوية.
- يشغّل `-d` الحاوية في وضع التشغيل المنفصل، أي إنها تعمل في الخلفية.
- يربط `-p 80:80` المنفذ 80 على النظام المضيف بالمنفذ 80 داخل الحاوية.
- يحدد `my-nginx-image` اسم صورة Docker المراد استخدامها للحاوية.

## أفضل الممارسات

بعد أن تعرفت على كيفية بناء حاويات Docker، لنستعرض بعض أفضل الممارسات لضمان كفاءتها وأمانها وسهولة استخدامها.

### استخدم صورًا أساسية صغيرة

للحفاظ على صغر حجم حاويات Docker وسرعة نشرها، يُفضّل استخدام صور أساسية صغيرة لا تتضمن سوى الاعتماديات التي يحتاج إليها تطبيقك. فبدلًا من استخدام نظام تشغيل كامل مثل Ubuntu أو CentOS، يمكنك استخدام صورة أصغر مثل Alpine Linux أو BusyBox.

### قلّل عدد الطبقات

ينشئ كل سطر في Dockerfile طبقة جديدة في صورة Docker، وتزيد كل طبقة حجم الصورة. للحفاظ على أصغر حجم ممكن لصور Docker، حاول تقليل عدد الطبقات. ومن طرق ذلك جمع الأوامر المتشابهة في سطر واحد داخل Dockerfile. فبدلًا من استخدام أمري `RUN` منفصلين لتحديث قائمة الحزم وتثبيت حزمة، يمكنك استخدام أمر `RUN` واحد لتنفيذ الأمرين معًا.

مثال:
```dockerfile
RUN apt update
RUN apt install apache -y
```
مقابل
```dockerfile
RUN apt update && apt install apache -y
```

### استخدم متغيرات البيئة

يسهّل استخدام متغيرات البيئة في Dockerfile بدلًا من تثبيت القيم فيه تخصيص الحاوية وقت التشغيل، كما يحافظ على قابلية نقل Dockerfile. مثلًا، يمكنك استخدام متغيرات البيئة لتحديد المنفذ الذي يعمل عليه التطبيق أو مسار ملف الإعدادات.

مثال:
```bash
docker run -e PORT=3000 my-app
```
```Dockerfile
FROM node:14

# تعيين دليل العمل
WORKDIR /app

# نسخ package.json وyarn.lock إلى الحاوية
COPY package.json yarn.lock ./

# تثبيت الاعتماديات
RUN yarn install --frozen-lockfile

# نسخ شيفرة التطبيق إلى الحاوية
COPY . .

# إتاحة منفذ التطبيق
EXPOSE $PORT

# بدء التطبيق
CMD ["yarn", "start"]
```


### استخدم تركيب وحدات التخزين

تتيح عمليات تركيب وحدات التخزين مشاركة البيانات بين النظام المضيف وحاوية Docker. وهذا يسهّل إدارة البيانات ويقلّل حجم حاوية Docker. مثلًا، يمكنك تركيب وحدة تخزين لمشاركة ملف قاعدة بيانات بين النظام المضيف والحاوية.

مثال:
```bash
docker run -v /home/user/app/data:/app/data my-app
```

```Dockerfile
FROM node:14

# تعيين دليل العمل
WORKDIR /app

# نسخ ملفي package.json وyarn.lock إلى الحاوية
COPY package.json yarn.lock ./

# تثبيت الاعتماديات
RUN yarn install --frozen-lockfile

# نسخ بقية شيفرة التطبيق إلى الحاوية
COPY . .

# إتاحة منفذ التطبيق
EXPOSE 3000

# بدء التطبيق
CMD ["yarn", "start"]

# تركيب وحدة تخزين لبيانات التطبيق
VOLUME ["/app/data"]
```

### تجنب التشغيل كمستخدم جذر

قد يشكّل تشغيل حاوية Docker كمستخدم جذر خطرًا أمنيًا. بدلًا من ذلك، أنشئ مستخدمًا جديدًا في Dockerfile وشغّل الحاوية بهذا المستخدم. مثلًا، يمكنك استخدام تعليمة `USER` في Dockerfile لإنشاء مستخدم جديد ثم التبديل إليه عند تشغيل الحاوية.

مثال:
```Dockerfile
FROM node:14

# إنشاء مستخدم جديد لتشغيل الحاوية
RUN useradd --user-group --create-home --shell /bin/false app

# تغيير دليل العمل إلى الدليل الرئيسي لمستخدم التطبيق
WORKDIR /home/app

# تثبيت الاعتماديات بصلاحيات مستخدم التطبيق
COPY package.json yarn.lock ./
RUN chown -R app:app /home/app
USER app
RUN yarn install --frozen-lockfile --production

# نسخ شيفرة التطبيق بصلاحيات مستخدم التطبيق
COPY --chown=app:app . .

# إتاحة المنفذ
EXPOSE 3000

# بدء التطبيق بصلاحيات مستخدم التطبيق
CMD ["yarn", "start"]
```

### أبقِ الصور محدثة

لضمان أمان حاويات Docker وخلوّها من الثغرات، من المهم إبقاء صور Docker محدثة. ويعني ذلك تحديث الصورة الأساسية والاعتماديات التي يستخدمها التطبيق بانتظام. مثلًا، يمكنك استخدام أمري `apt-get update` و`apt-get upgrade` في Dockerfile لإبقاء الحاوية محدثة بأحدث تصحيحات الأمان وإصلاحات الأخطاء.

مثال:
```Dockerfile
FROM ubuntu:latest

# تحديث قائمة الحزم وتثبيت تحديثات الأمان
RUN apt-get update && apt-get upgrade -y && apt-get clean

# تثبيت خادم الويب nginx
RUN apt-get install -y nginx

# نسخ شيفرة التطبيق إلى الحاوية
COPY . /var/www/html/

# إتاحة المنفذ 80 للنظام المضيف
EXPOSE 80

# بدء خادم nginx
CMD ["nginx", "-g", "daemon off;"]

```
## مواصلة التعلّم
### وثائق Docker
[Docker](https://www.docker.com/) منصة مفتوحة المصدر لبناء التطبيقات وشحنها وتشغيلها داخل الحاويات. يقدم موقع وثائق Docker معلومات تفصيلية عن تثبيت Docker وإعداده واستخدامه لمجموعة متنوعة من أنظمة التشغيل وحالات الاستخدام. ويتضمن الموقع أيضًا معلومات عن واجهات Docker البرمجية وأوامر Docker CLI ونصائح استكشاف الأخطاء وإصلاحها.

فيما يلي بعض الأقسام المفيدة في وثائق Docker:

- [البدء باستخدام Docker](https://docs.docker.com/get-started/)
- [مرجع Docker CLI](https://docs.docker.com/engine/reference/commandline/cli/)
- [مرجع Docker API](https://docs.docker.com/engine/api/v1.41/)
- [مرجع Docker Compose](https://docs.docker.com/compose/compose-file/)
- [مرجع Dockerfile](https://docs.docker.com/engine/reference/builder/)

تُعد وثائق Docker موردًا مهمًا لتعلّم استخدام Docker واستكشاف أي مشكلات قد تواجهك وإصلاحها.

### Docker Hub

[Docker Hub](https://hub.docker.com/) مستودع سحابي يتيح لك تخزين صور Docker ومشاركتها وإدارتها. يتضمن Docker Hub مستودعات عامة وخاصة، بالإضافة إلى عمليات بناء وسير عمل آلية. يمكنك استخدام Docker Hub لتخزين صور Docker الخاصة بك، وكذلك للعثور على صور جاهزة لتطبيقات وأدوات برمجية شائعة.

تشمل بعض ميزات Docker Hub المفيدة ما يلي:

- [البحث عن صور Docker](https://hub.docker.com/search?type=image)
- [تخزين الصور وإدارتها في المستودعات](https://hub.docker.com/repositories)
- [أتمتة عمليات البناء والاختبار باستخدام إجراءات Docker Hub](https://docs.docker.com/docker-hub/builds/)

Docker Hub أداة أساسية للعمل مع Docker، ويمكنها توفير كثير من الوقت والجهد عند إدارة الصور ومشاركتها.

## الخلاصة

Docker أداة قوية تساعد على جعل التطبيقات أكثر قابلية للنقل وكفاءة وسهولة في النشر. باتباع أفضل الممارسات والنصائح هذه، يمكنك إنشاء حاويات Docker آمنة وسهلة الاستخدام وسريعة النشر. سواء كنت تبني تطبيقًا جديدًا أو تنقل تطبيقًا قائمًا إلى Docker، ستساعدك هذه الخطوات على البدء في إنشاء حاويات Docker.
