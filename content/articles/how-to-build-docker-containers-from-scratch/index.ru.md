**Как создавать контейнеры Docker**

Docker — мощный инструмент для создания переносимых приложений, которые легко развертывать. В этом руководстве рассмотрены основные этапы создания и сборки контейнеров Docker. Также мы разберем рекомендации и советы, которые помогут сделать контейнеры эффективными, безопасными и удобными в использовании.

## Что такое Docker

Прежде чем создавать контейнеры Docker, важно понять, что такое Docker и как он работает.

Docker позволяет упаковать приложение и его зависимости в контейнер, который можно запускать в любой системе. Контейнер изолирован от хост-системы и содержит все необходимое для работы приложения: код, среду выполнения, системные инструменты, библиотеки и настройки.

Контейнеры легковесны и просты в развертывании, поэтому они популярны для создания и развертывания приложений. С помощью Docker вы можете создавать, управлять и запускать контейнеры через простой интерфейс командной строки.

## Сборка образа Docker

Чтобы создать контейнер Docker, сначала нужно создать образ Docker. Образ Docker — это снимок контейнера со всеми файлами, библиотеками и зависимостями, необходимыми для запуска приложения.

Основные этапы создания образа Docker:

1. **Создать Dockerfile**
2. **Собрать образ**
3. **Запустить контейнер**

### Шаг 1: Создайте Dockerfile

Первый шаг при создании образа Docker — подготовить Dockerfile. Это текстовый файл с инструкциями для сборки образа. Вот простой пример Dockerfile:

```bash
FROM ubuntu:latest
RUN apt-get update && apt-get install -y nginx
COPY index.html /var/www/html/
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

Разберем этот Dockerfile:

- `FROM ubuntu:latest` указывает базовый образ для контейнера. В этом примере используется последняя версия Ubuntu.
- `RUN apt-get update && apt-get install -y nginx` обновляет список пакетов и устанавливает веб-сервер nginx.
- `COPY index.html /var/www/html/` копирует файл index.html в корневой каталог веб-сайта в контейнере.
- `EXPOSE 80` открывает порт 80 для хост-системы.
- `CMD ["nginx", "-g", "daemon off;"]` запускает сервер nginx на переднем плане.

### Шаг 2: Соберите образ

После создания Dockerfile можно собрать образ командой `docker build`. Например:

```bash
docker run -d -p 80:80 my-nginx-image
```

Разберем эту команду:

- `docker run` указывает Docker запустить контейнер.
- `-d` запускает контейнер в отсоединенном режиме, то есть в фоновом режиме.
- `-p 80:80` связывает порт 80 хост-системы с портом 80 в контейнере.
- `my-nginx-image` задает имя образа Docker, используемого для контейнера.

## Рекомендации

Теперь вы знаете, как собирать контейнеры Docker. Рассмотрим рекомендации, которые помогут сделать их эффективными, безопасными и удобными в использовании.

### Используйте небольшие базовые образы

Чтобы контейнеры Docker занимали меньше места и быстрее развертывались, используйте небольшие базовые образы, содержащие только необходимые приложению зависимости. Например, вместо полноценной операционной системы, такой как Ubuntu или CentOS, подойдет более легкий образ Alpine Linux или BusyBox.

### Сокращайте количество слоев

Каждая строка Dockerfile создает новый слой в образе Docker, и каждый слой увеличивает его размер. Чтобы образы Docker оставались как можно меньше, старайтесь сокращать число слоев. Один из способов — объединять похожие команды в одну строку Dockerfile. Например, вместо двух отдельных команд `RUN` для обновления списка пакетов и установки пакета используйте одну команду `RUN`, которая выполнит оба действия.

Пример:
```dockerfile
RUN apt update
RUN apt install apache -y
```
вместо
```dockerfile
RUN apt update && apt install apache -y
```

### Используйте переменные среды

Переменные среды в Dockerfile вместо жестко заданных значений упрощают настройку контейнера во время выполнения и делают Dockerfile переносимым. Например, переменные среды можно использовать, чтобы указать порт приложения или расположение файла конфигурации.

Пример:
```bash
docker run -e PORT=3000 my-app
```
```Dockerfile
FROM node:14

# Задайте рабочий каталог
WORKDIR /app

# Скопируйте package.json и yarn.lock в контейнер
COPY package.json yarn.lock ./

# Установите зависимости
RUN yarn install --frozen-lockfile

# Скопируйте код приложения в контейнер
COPY . .

# Откройте порт приложения
EXPOSE $PORT

# Запустите приложение
CMD ["yarn", "start"]
```


### Используйте монтирование томов

Монтирование томов позволяет обмениваться данными между хост-системой и контейнером Docker. Это упрощает управление данными и уменьшает размер контейнера Docker. Например, том можно смонтировать для обмена файлом базы данных между хост-системой и контейнером.

Пример:
```bash
docker run -v /home/user/app/data:/app/data my-app
```

```Dockerfile
FROM node:14

# Задайте рабочий каталог
WORKDIR /app

# Скопируйте файлы package.json и yarn.lock в контейнер
COPY package.json yarn.lock ./

# Установите зависимости
RUN yarn install --frozen-lockfile

# Скопируйте остальной код приложения в контейнер
COPY . .

# Откройте порт приложения
EXPOSE 3000

# Запустите приложение
CMD ["yarn", "start"]

# Смонтируйте том для данных приложения
VOLUME ["/app/data"]
```

### Не запускайте контейнер от root

Запуск контейнера Docker от имени пользователя root может создать угрозу безопасности. Вместо этого создайте нового пользователя в Dockerfile и запускайте контейнер от его имени. Например, с помощью инструкции `USER` в Dockerfile можно создать пользователя, а затем переключиться на него при запуске контейнера.

Пример:
```Dockerfile
FROM node:14

# Создайте пользователя для запуска контейнера
RUN useradd --user-group --create-home --shell /bin/false app

# Измените рабочий каталог на домашний каталог пользователя app
WORKDIR /home/app

# Установите зависимости от имени пользователя app
COPY package.json yarn.lock ./
RUN chown -R app:app /home/app
USER app
RUN yarn install --frozen-lockfile --production

# Скопируйте код приложения от имени пользователя app
COPY --chown=app:app . .

# Откройте порт
EXPOSE 3000

# Запустите приложение от имени пользователя app
CMD ["yarn", "start"]
```

### Поддерживайте образы в актуальном состоянии

Чтобы контейнеры Docker были безопасными и не содержали уязвимостей, важно поддерживать образы Docker в актуальном состоянии. Для этого регулярно обновляйте базовый образ и зависимости приложения. Например, команды `apt-get update` и `apt-get upgrade` в Dockerfile помогут установить в контейнер последние исправления уязвимостей и ошибок.

Пример:
```Dockerfile
FROM ubuntu:latest

# Обновите список пакетов и установите обновления безопасности
RUN apt-get update && apt-get upgrade -y && apt-get clean

# Установите веб-сервер nginx
RUN apt-get install -y nginx

# Скопируйте код приложения в контейнер
COPY . /var/www/html/

# Откройте порт 80 для хост-системы
EXPOSE 80

# Запустите сервер nginx
CMD ["nginx", "-g", "daemon off;"]

```

### Docker Hub

[Docker Hub](https://hub.docker.com/) — облачный репозиторий для хранения, публикации и управления образами Docker. В Docker Hub есть публичные и частные репозитории, а также автоматические сборки и рабочие процессы. Там можно хранить собственные образы Docker и находить готовые образы популярных программ и инструментов.

Полезные возможности Docker Hub:

- [Поиск образов Docker](https://hub.docker.com/search?type=image)
- [Хранение и управление образами в репозиториях](https://hub.docker.com/repositories)
- [Автоматизация сборок и тестирования с помощью рабочих процессов Docker Hub](https://docs.docker.com/docker-hub/builds/)

Docker Hub — важный инструмент для работы с Docker. Он экономит время и усилия при управлении образами и обмене ими.
