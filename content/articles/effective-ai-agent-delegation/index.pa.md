[ਵਿਹਾਰਕ AI ਵਰਕਫਲੋ ਕੋਰਸ ਵੱਲ ਵਾਪਸ ਜਾਓ](/effective-ai-course-start/)

**ਜਦੋਂ ਕਿਸੇ ਸੁਤੰਤਰ ਸਵਾਲ ਲਈ ਵੱਖਰੇ ਸੈਸ਼ਨ ਜਿਤਨਾ ਕੰਮ ਹੋਵੇ, ਤਦ ਕੰਮ ਸੌਂਪੋ।** ਕਰਮਚਾਰੀ ਏਜੰਟ ਆਪਣੇ ਸੰਦਰਭ ਵਿੱਚ ਸਰੋਤ ਜਾਂਚਦਾ, ਟੈਸਟ ਸਮੀਖਿਆ ਕਰਦਾ ਜਾਂ ਸੀਮਤ ਤਬਦੀਲੀ ਦਾ ਖਾਕਾ ਬਣਾਉਂਦਾ ਹੈ। ਮੁੱਖ ਏਜੰਟ ਨਤੀਜਾ ਜਾਂਚ ਕੇ ਜੋੜਦਾ ਹੈ। ਇਹ ਪਾਠ ਦਸਤਾਵੇਜ਼ਾਂ ਦੀ ਤੁਲਨਾ ਕਰਦਾ ਹੈ, ਜਦਕਿ ਤੁਹਾਡਾ ਮੁੱਖ ਸੈਸ਼ਨ ਛੋਟਾ ਲੈਬ ਕੰਮ ਕਰਦਾ ਰਹਿੰਦਾ ਹੈ।

**ਸਿੱਖਣ ਦਾ ਨਤੀਜਾ:** ਤੁਸੀਂ ਇੱਕ ਕਰਮਚਾਰੀ ਨੂੰ ਸੁਤੰਤਰ ਸਮੀਖਿਆ ਦਿਓਗੇ ਅਤੇ ਉਸਦੀ ਛੋਟੀ ਸਬੂਤ ਰਿਪੋਰਟ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋਗੇ।

## ਮੁੱਖ ਗੱਲਾਂ

- **ਸੰਯੋਜਕ:** ਮੁੱਖ ਏਜੰਟ ਜੋ ਕੰਮ ਅਤੇ ਅੰਤਿਮ ਸਮੀਖਿਆ ਦਾ ਤਾਲਮੇਲ ਕਰਦਾ ਹੈ।
- **ਕਰਮਚਾਰੀ:** ਵੱਖਰਾ ਏਜੰਟ ਜਿਸ ਨੂੰ ਇੱਕ ਸੀਮਤ ਨਤੀਜਾ ਦਿੱਤਾ ਗਿਆ ਹੈ।
- **ਸੁਤੰਤਰ ਕੰਮ:** ਅਜਿਹਾ ਉਪਕੰਮ ਜਿਸਦਾ ਜਵਾਬ ਦੂਜੇ ਕਰਮਚਾਰੀ ਦੇ ਅਧੂਰੇ ਨਤੀਜੇ ਉੱਤੇ ਨਿਰਭਰ ਨਹੀਂ।
- **ਮਾਲਕੀ:** ਨਿਰਧਾਰਤ ਫਾਈਲ ਜਾਂ ਸਵਾਲ ਜੋ ਇੱਕ ਕਰਮਚਾਰੀ ਨੂੰ ਦਿੱਤਾ ਗਿਆ ਹੈ।
- **ਇਕੱਠਾ ਕਰਨਾ:** ਮੁੱਖ ਏਜੰਟ ਵੱਲੋਂ ਕਰਮਚਾਰੀ ਦੇ ਨਤੀਜੇ ਦੀ ਮੌਜੂਦਾ ਸਰੋਤਾਂ ਨਾਲ ਤੁਲਨਾ।

## ਸ਼ੁਰੂ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ

**ਪੂਰਵ-ਸ਼ਰਤਾਂ:** ਤੁਹਾਡੇ [ਸੰਦਰਭ ਹਵਾਲਗੀ](/articles/effective-ai-context-window-management/) ਅਤੇ [ਆਉਟਪੁੱਟ ਤਸਦੀਕ](/articles/effective-ai-output-verification/) ਰਿਕਾਰਡ। 40 ਮਿੰਟ ਰੱਖੋ। ਮੁਸ਼ਕਲ ਦਰਮਿਆਨੀ ਹੈ। ਜੁੜਿਆ ਰਸਤਾ ਕਰਮਚਾਰੀ-ਸਹਾਇਤਾ ਵਾਲੇ ਉਤਪਾਦ ਲਈ ਹੈ। ਅਧਿਐਨ ਰਸਤਾ ਵੱਖਰੀ ਚੈਟ ਅਤੇ ਹੱਥੀਂ ਜੋੜਨ ਦੀ ਵਰਤੋਂ ਕਰਦਾ ਹੈ।

**ਇਸ ਪਾਠ ਲਈ ਸਾਫ਼ ਸ਼ੁਰੂਆਤੀ ਕਾਪੀ ਲਵੋ।** ਸੋਧੇ ਫਿਲਟਰ ਦਾ diff ਅਤੇ ਟੈਸਟ ਰਿਕਾਰਡ ਲੈਬ ਤੋਂ ਬਾਹਰ ਸੰਭਾਲੋ। ਅਸਲ ZIP ਨੂੰ ਨਵੇਂ ਅਸਥਾਈ ਫੋਲਡਰ ਵਿੱਚ ਖੋਲ੍ਹੋ। ਸ਼ੁਰੂਆਤੀ ਕਮਾਂਡ ਅਤੇ ਉਸਦੇ ਦੋ ਮੂਲ ਟੈਸਟ ਚਲਾਓ। ਕੋਰਸ-ਸੈਟਅੱਪ ਪਾਠ ਦੀ Git ਬੇਸਲਾਈਨ ਦੁਹਰਾਓ ਅਤੇ ਰਿਪੋਜ਼ਟਰੀ-ਸੰਦਰਭ ਪਾਠ ਤੋਂ ਛੋਟੀਆਂ `AGENTS.md` ਅਤੇ ਵਿਕਲਪੀ `CLAUDE.md` ਹਦਾਇਤਾਂ ਮੁੜ ਬਣਾਓ। ਉਹ ਹਦਾਇਤ ਫਾਈਲਾਂ ਆਪ commit ਕਰੋ, ਫਿਰ ਵੇਖੋ ਕਿ `git status --short` ਸਾਫ਼ ਹੈ। ਸੋਧੀ ਫਿਲਟਰ ਕਾਪੀ ਹਵਾਲੇ ਲਈ ਰੱਖੋ, ਪਰ ਕਰਮਚਾਰੀ ਅਭਿਆਸ ਸਾਫ਼ ਸ਼ੁਰੂਆਤੀ ਕਾਪੀ ਉੱਤੇ ਕਰੋ।

## ਫੈਸਲਾ ਕਰੋ ਕਿ ਕੰਮ ਸੌਂਪਣਾ ਹੈ ਜਾਂ ਨਹੀਂ

**ਛੋਟੇ ਲੜੀਵਾਰ ਸੋਧ ਲਈ ਇੱਕ ਏਜੰਟ ਵਰਤੋ।** ਕੰਮ ਸੌਂਪਣ ਦੀ ਸੈਟਅੱਪ, ਟੋਕਨ ਅਤੇ ਸਮੀਖਿਆ ਲਾਗਤ ਹੁੰਦੀ ਹੈ। ਜਦੋਂ ਪੜ੍ਹਨ-ਮਾਤਰ ਸਵਾਲ ਸੁਤੰਤਰ ਹੋਵੇ ਅਤੇ ਜਵਾਬ ਲਈ ਨਹੀਂ ਤਾਂ ਮੁੱਖ ਚੈਟ ਵਿੱਚ ਕਈ ਫਾਈਲਾਂ ਜਾਂ ਸਰੋਤ ਪੰਨੇ ਆਉਣ, ਤਦ ਕਰਮਚਾਰੀ ਵਰਤੋ।

| ਲੈਬ ਕੰਮ | ਸੌਂਪਣਾ? | ਕਾਰਨ |
|---|---|---|
| **ਦੋ ਮੁੱਲਾਂ ਵਾਲਾ ਫਿਲਟਰ ਜੋੜਨਾ** | ਆਮ ਤੌਰ ਤੇ ਨਹੀਂ | ਇੱਕ ਛੋਟੀ ਫਾਈਲ ਅਤੇ ਕੇਂਦਰਿਤ ਟੈਸਟ |
| **ਦੋ ਮੂਲ ਟੈਸਟਾਂ ਵਿੱਚ ਛੁੱਟੇ ਕੇਸ ਲੱਭਣਾ** | ਆਮ ਤੌਰ ਤੇ ਨਹੀਂ | ਮੁੱਖ ਸੈਸ਼ਨ ਇੱਕ ਛੋਟੀ ਫਾਈਲ ਜ਼ਿਆਦਾ ਤੇਜ਼ੀ ਨਾਲ ਪੜ੍ਹ ਸਕਦਾ ਹੈ |
| **ਤਿੰਨ ਮੌਜੂਦਾ ਉਤਪਾਦ ਦਸਤਾਵੇਜ਼ਾਂ ਦੀ ਤੁਲਨਾ** | ਹਾਂ, ਪੜ੍ਹਨ-ਮਾਤਰ | ਸਰੋਤ ਪੜ੍ਹਨਾ ਕਰਮਚਾਰੀ ਦੇ ਸੰਦਰਭ ਵਿੱਚ ਰਹਿੰਦਾ ਹੈ |
| **ਉਹੀ ਫੰਕਸ਼ਨ ਦੋ ਵਾਰ ਸੋਧਣਾ** | ਨਹੀਂ | ਇਕੱਠੀਆਂ ਸੋਧਾਂ ਟਕਰਾਅ ਪੈਦਾ ਕਰਦੀਆਂ ਹਨ |

**ਕਰਮਚਾਰੀ ਨੂੰ ਸੰਯੋਜਕ ਨਾਲੋਂ ਘੱਟ ਸੰਦਰਭ ਦਿਓ,** ਪੂਰੀ ਗੱਲਬਾਤ ਦੀ ਨਕਲ ਨਹੀਂ। ਉਸਨੂੰ ਟੀਚਾ, ਸਰੋਤ ਪਾਥ, ਕੰਮ ਦੀ ਹੱਦ ਅਤੇ ਜਵਾਬ ਦਾ ਰੂਪ ਦਿਓ। ਮੁੱਖ ਸੈਸ਼ਨ ਵਿੱਚ ਛੋਟੀ ਸਬੂਤ ਰਿਪੋਰਟ ਰੱਖੋ। ਕਾਰਵਾਈ ਤੋਂ ਪਹਿਲਾਂ ਹਵਾਲਾ ਦਿੱਤੀਆਂ ਫਾਈਲਾਂ ਆਪ ਵੇਖੋ।

## ਇੱਕ ਪੜ੍ਹਨ-ਮਾਤਰ ਕਰਮਚਾਰੀ ਚਲਾਓ

**ਮੁੱਖ ਕੰਮ ਛੋਟਾ ਰੱਖੋ।** ਮੁੱਖ ਸੈਸ਼ਨ ਵਿੱਚ ਸਥਾਨਕ `AGENTS.md` ਪੜ੍ਹੋ ਅਤੇ ਲਿਖੋ ਕਿ ਟੈਸਟ ਕਮਾਂਡ ਕਿਸ ਫਾਈਲ ਵਿੱਚ ਹੈ। ਹੇਠਾਂ ਦਿੱਤਾ ਵੱਖਰਾ ਖੋਜ ਸਵਾਲ ਇੱਕ ਕਰਮਚਾਰੀ ਨੂੰ ਦਿਓ। ਉਸਨੂੰ ਪੂਰੀ ਲੈਬ ਜਾਂ ਪਿਛਲੀ ਚੈਟ ਦੀ ਲੋੜ ਨਹੀਂ।

**ਜੁੜਿਆ ਰਸਤਾ:** Codex, Claude Code ਜਾਂ ਕਰਮਚਾਰੀ-ਸਹਾਇਤਾ ਵਾਲੇ ਹੋਰ ਕਲਾਇੰਟ ਵਿੱਚ ਲੈਬ ਨੂੰ ਪ੍ਰੋਜੈਕਟ ਵਜੋਂ ਖੋਲ੍ਹੋ ਅਤੇ ਮੁੱਖ ਏਜੰਟ ਨੂੰ ਹੇਠਲੀ ਪੜ੍ਹਨ-ਮਾਤਰ ਬੇਨਤੀ ਇੱਕ ਕਰਮਚਾਰੀ ਨੂੰ ਦੇਣ ਲਈ ਕਹੋ। ਟੂਲ ਟ੍ਰਾਂਸਕ੍ਰਿਪਟ ਵਿੱਚ ਅਸਲ ਕਰਮਚਾਰੀ ਦੀ ਸ਼ੁਰੂਆਤ ਅਤੇ ਵਾਪਸ ਆਈ ਰਿਪੋਰਟ ਦੀ ਜਾਂਚ ਕਰੋ। ਜੇ ਉਤਪਾਦ ਕਰਮਚਾਰੀ ਨਹੀਂ ਦਿਖਾਉਂਦਾ, ਵੱਖਰਾ ਸੈਸ਼ਨ ਵਰਤੋ ਅਤੇ ਉਸਨੂੰ ਵੱਖਰਾ ਕਰਮਚਾਰੀ ਸੈਸ਼ਨ ਕਹੋ। [Codex ਸਬਏਜੰਟ ਗਾਈਡ](https://learn.chatgpt.com/docs/agent-configuration/subagents), [Claude Code ਸਬਏਜੰਟ ਗਾਈਡ](https://code.claude.com/docs/en/sub-agents), ਅਤੇ [OpenCode ਏਜੰਟ ਗਾਈਡ](https://opencode.ai/docs/agents/) ਮੌਜੂਦਾ ਨਿਯੰਤਰਣ ਦੱਸਦੀਆਂ ਹਨ।

**ਅਧਿਐਨ ਰਸਤਾ:** ਉਸੇ ਬੇਨਤੀ ਲਈ ਨਵੀਂ ਚੈਟ ਖੋਲ੍ਹੋ। ਤਿੰਨ ਅਧਿਕਾਰਤ ਲਿੰਕ ਜਾਂ ਸਰੋਤ ਅੰਸ਼ ਦਿਓ। ਇਸਨੂੰ ਨਕਲੀ ਕਰਮਚਾਰੀ ਕਹੋ। ਦੂਜੀ ਚੈਟ ਵੱਖਰਾ ਸੰਦਰਭ ਹੈ, ਅਸਲ ਸਬਏਜੰਟ ਚੱਲਣ ਦਾ ਸਬੂਤ ਨਹੀਂ।

```text
ਮੌਜੂਦਾ ਅਧਿਕਾਰਤ Codex AGENTS.md, Claude Code memory ਅਤੇ OpenCode rules ਦਸਤਾਵੇਜ਼ ਵਰਤੋ।
ਤੁਲਨਾ ਕਰੋ ਕਿ ਹਰ ਉਤਪਾਦ ਰਿਪੋਜ਼ਟਰੀ ਹਦਾਇਤ ਫਾਈਲਾਂ ਕਿਵੇਂ ਲੋਡ ਕਰਦਾ ਹੈ।
ਫਾਈਲਾਂ ਨਾ ਸੋਧੋ।
ਵੱਧ ਤੋਂ ਵੱਧ ਤਿੰਨ ਕਤਾਰਾਂ ਦਿਓ: ਉਤਪਾਦ, ਹਦਾਇਤ ਫਾਈਲ, ਸਰੋਤ URL ਅਤੇ ਲੋਡ ਕਰਨ ਦਾ ਇੱਕ ਤਰੀਕਾ।
ਅਣਿਸ਼ਚਿਤਤਾ ਦੱਸੋ। ਪੂਰੇ ਪੰਨੇ ਨਾ ਪੇਸਟ ਕਰੋ।
```

**ਸਰੋਤ ਸਮੂਹ:** [Codex ਪ੍ਰੋਜੈਕਟ ਹਦਾਇਤਾਂ](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [Claude Code ਦੀ ਮੈਮੋਰੀ ਗਾਈਡ](https://code.claude.com/docs/en/memory), ਅਤੇ [OpenCode ਦੇ ਨਿਯਮ](https://opencode.ai/docs/rules/)। ਉਮੀਦ ਕੀਤੀ ਰਿਪੋਰਟ Codex ਅਤੇ OpenCode ਲਈ `AGENTS.md` ਦੱਸਦੀ ਹੈ। ਮੌਜੂਦਾ Claude Code ਰੀਲੀਜ਼ ਵੀ `AGENTS.md` ਸਿੱਧਾ ਲੋਡ ਕਰਦੀਆਂ ਹਨ ਜੇ `CLAUDE.md` ਜਾਂ `CLAUDE.local.md` ਨੂੰ ਪਹਿਲ ਨਾ ਮਿਲੇ। ਇਹ ਲੈਬ `@AGENTS.md` ਆਯਾਤ ਵਾਲੀ `CLAUDE.md` ਫਾਈਲ ਵਰਤਦੀ ਹੈ, ਜੋ ਪੁਰਾਣੇ ਜਾਂ ਵੱਖਰੀ ਤਰ੍ਹਾਂ ਸੰਰਚਿਤ ਸੈਸ਼ਨਾਂ ਲਈ ਵੀ ਢੁੱਕਵੀਂ ਹੈ। ਇਸ ਉਦਾਹਰਨ ਨੂੰ ਦੇਖੇ ਗਏ ਕਰਮਚਾਰੀ ਨਤੀਜੇ ਵਜੋਂ ਮੰਨਣ ਤੋਂ ਪਹਿਲਾਂ ਮੌਜੂਦਾ ਪੰਨੇ ਅਤੇ ਸਰਗਰਮ ਰੀਲੀਜ਼ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ।

## ਨਤੀਜੇ ਇਕੱਠੇ ਕਰੋ

**ਹਵਾਲਾ ਦਿੱਤੇ ਸਰੋਤ ਪੰਨੇ ਆਪ ਖੋਲ੍ਹੋ।** ਜੇ ਕਰਮਚਾਰੀ ਕਹੇ ਕਿ Claude Code ਲਈ ਹਮੇਸ਼ਾ `CLAUDE.md` ਆਯਾਤ ਚਾਹੀਦਾ ਹੈ, ਤਾਂ ਉਸਦੀ memory guide ਵੇਖੋ ਅਤੇ ਰਿਪੋਰਟ ਠੀਕ ਕਰੋ। ਸਥਾਨਕ ਹਦਾਇਤ ਫਾਈਲਾਂ ਨਾਲ ਤੁਲਨਾ ਕਰੋ। ਛੋਟਾ ਇਕੱਠਾ ਕਰਨ ਵਾਲਾ ਨੋਟ ਲਿਖੋ:

```text
ਮਨਜ਼ੂਰ: Codex ਅਤੇ OpenCode ਪ੍ਰੋਜੈਕਟ ਹਦਾਇਤਾਂ ਲਈ AGENTS.md ਵਰਤਦੇ ਹਨ।
ਮੌਜੂਦਾ Claude Code ਸਿੱਧਾ AGENTS.md ਲੋਡ ਕਰ ਸਕਦਾ ਹੈ। ਇਹ ਲੈਬ ਸਥਿਰ ਸਾਂਝੇ ਨਕਸ਼ੇ ਲਈ
@AGENTS.md ਆਯਾਤ ਨਾਲ CLAUDE.md ਵਰਤਦੀ ਹੈ।
ਸਬੂਤ: ਤਿੰਨ ਮੌਜੂਦਾ ਅਧਿਕਾਰਤ ਪੰਨਿਆਂ ਦੇ URL ਅਤੇ ਸਮੀਖਿਆ ਤਾਰੀਖ ਲਿਖੋ।
ਫੈਸਲਾ: ਇੱਕ ਛੋਟਾ ਸਾਂਝਾ ਨਕਸ਼ਾ ਅਤੇ Claude ਆਯਾਤ ਰੱਖੋ।
```

**ਇਹ ਨੋਟ ਹੀ ਲਾਭਦਾਇਕ ਕਰਮਚਾਰੀ ਨਤੀਜਾ ਹੈ।** ਸੰਯੋਜਕ ਨੂੰ ਜਾਂਚੇ ਨਤੀਜੇ ਅਤੇ ਸਰੋਤ ਪਾਥ ਚਾਹੀਦੇ ਹਨ, ਖੋਜ ਟ੍ਰਾਂਸਕ੍ਰਿਪਟ ਨਹੀਂ। ਕੰਮ ਸੌਂਪਣ ਵਿੱਚ ਕੁੱਲ ਟੋਕਨ ਵੱਧ ਲੱਗਦੇ ਹਨ, ਇਸ ਲਈ ਮੁੱਖ ਗੱਲਬਾਤ ਛੋਟੀ ਤਦ ਹੀ ਰੱਖੋ ਜਦੋਂ ਵੱਖਰਾ ਸੈਸ਼ਨ ਧਿਆਨ ਬਚਾਉਂਦਾ ਹੋਵੇ।

## ਸੋਧਾਂ ਦੀ ਮਾਲਕੀ ਦਿਓ

**ਜੇ ਕਰਮਚਾਰੀ ਫਾਈਲਾਂ ਸੋਧਣ,** ਤਾਂ ਫਾਈਲ ਅਨੁਸਾਰ ਮਾਲਕੀ ਵੰਡੋ ਜਾਂ ਆਪਸ ਵਿੱਚ ਮਿਲਦੇ ਰਿਪੋਜ਼ਟਰੀ ਕੰਮ ਲਈ ਵੱਖਰੀਆਂ ਵਰਕਟ੍ਰੀ ਵਰਤੋ। ਵਰਕਟ੍ਰੀ ਉਸੇ Git ਰਿਪੋਜ਼ਟਰੀ ਦੀ ਦੂਜੀ ਨਕਲ ਹੁੰਦੀ ਹੈ, ਜਿਸ ਦੀਆਂ ਕੰਮ ਵਾਲੀਆਂ ਫਾਈਲਾਂ ਵੱਖਰੀਆਂ ਹੁੰਦੀਆਂ ਹਨ। ਇਸ ਨਾਲ ਇਕੱਠੀਆਂ ਸੋਧਾਂ ਅਲੱਗ ਰਹਿੰਦੀਆਂ ਹਨ। ਮੁੱਖ ਏਜੰਟ ਤਬਦੀਲੀਆਂ ਦੀ ਸਮੀਖਿਆ ਕਰਦਾ ਅਤੇ ਸਪਸ਼ਟ merge, cherry-pick ਜਾਂ patch ਨਾਲ ਲਿਆਉਂਦਾ ਹੈ, ਫਿਰ ਇਕੱਠੇ ਹੋਏ tree ਵਿੱਚ ਟੈਸਟ ਮੁੜ ਚਲਾਉਂਦਾ ਹੈ।

| ਕਰਮਚਾਰੀ | ਸੌਂਪਿਆ ਕੰਮ | ਵਾਪਸ ਦਿਓ |
|---|---|---|
| **ਕਾਰਜਾਨਵਿਅਨ** | `task_report.py` | diff ਅਤੇ ਟੈਸਟ ਕਮਾਂਡ |
| **ਟੈਸਟ ਲੇਖਕ** | `tests/test_task_report.py` | ਟੈਸਟ ਕੇਸ ਅਤੇ ਦੇਖਿਆ ਨਤੀਜਾ |
| **ਸੰਯੋਜਕ** | ਲੋੜਾਂ ਅਤੇ ਅੰਤਿਮ ਇਕੱਠ | ਸੰਯੁਕਤ diff ਅਤੇ ਮਨਜ਼ੂਰੀ ਮਾਪਦੰਡ |

**ਛੋਟੀ ਲੈਬ ਨੂੰ ਸਮਾਂਤਰ ਸੋਧਾਂ ਦੀ ਲੋੜ ਨਹੀਂ।** ਇਹ ਟੇਬਲ ਵੱਡੇ ਕੰਮ ਲਈ ਮਾਲਕੀ ਵੰਡਣ ਦਾ ਢੰਗ ਦਿਖਾਉਂਦੀ ਹੈ। ਇੱਕ ਵਰਕਟ੍ਰੀ ਦੇ ਟੈਸਟ ਦੂਜੀ ਵਿੱਚ ਅਲੱਗ ਪਈ ਕਾਰਜਾਨਵਿਅਨ ਨੂੰ ਜਾਂਚਦੇ ਨਹੀਂ। ਜੇ ਦੋ ਕਰਮਚਾਰੀਆਂ ਨੂੰ ਇੱਕੋ ਫੰਕਸ਼ਨ ਚਾਹੀਦਾ ਹੋਵੇ ਤਾਂ ਵਾਰੀ ਵਾਰੀ ਕੰਮ ਕਰੋ ਜਾਂ ਇੱਕ ਨੂੰ ਬਿਨਾਂ ਸੋਧ ਸਮੀਖਿਆ ਕਰਨ ਦਿਓ। ਵੱਖਰੀਆਂ ਵਰਕਟ੍ਰੀ ਫਾਈਲ ਟਕਰਾਅ ਰੋਕਦੀਆਂ ਹਨ, ਵਿਰੋਧੀ ਲੋੜਾਂ ਹੱਲ ਨਹੀਂ ਕਰਦੀਆਂ।

## ਉਤਪਾਦ ਦਾ ਵਿਹਾਰ ਜਾਂਚੋ

**ਸਬਏਜੰਟ ਹੋਸਟ ਅਨੁਸਾਰ ਵੱਖਰੇ ਹੁੰਦੇ ਹਨ।** Codex, Claude Code ਅਤੇ OpenCode ਵਿੱਚ ਸੰਦਰਭ ਵਿਰਾਸਤ, ਟੂਲ ਅਧਿਕਾਰ ਅਤੇ ਨਤੀਜਾ ਵਾਪਸੀ ਦੇ ਤਰੀਕੇ ਵੱਖਰੇ ਹਨ। ਸਥਾਪਤ ਉਤਪਾਦ ਲਈ [Codex ਸਬਏਜੰਟ ਗਾਈਡ](https://learn.chatgpt.com/docs/agent-configuration/subagents), [Claude Code ਸਬਏਜੰਟ ਗਾਈਡ](https://code.claude.com/docs/en/sub-agents), ਅਤੇ [OpenCode ਏਜੰਟ ਗਾਈਡ](https://opencode.ai/docs/agents/) ਪੜ੍ਹੋ। ਇਹ ਨਾ ਮੰਨੋ ਕਿ ਕਰਮਚਾਰੀ ਮੁੱਖ ਗੱਲਬਾਤ ਦਾ ਪੂਰਾ ਸੰਦਰਭ ਸਾਂਝਾ ਕਰਦਾ ਜਾਂ ਵੱਖਰੀ ਵਰਕਟ੍ਰੀ ਵਿੱਚ ਚੱਲਦਾ ਹੈ।

## ਅਭਿਆਸ ਅਤੇ ਜਾਂਚ

**ਤੁਹਾਡਾ ਨਤੀਜਾ:** ਇੱਕ ਛੋਟੀ ਦਸਤਾਵੇਜ਼ੀ ਕਰਮਚਾਰੀ ਰਿਪੋਰਟ ਅਤੇ ਇੱਕ ਇਕੱਠ ਨੋਟ। ਅਧਿਐਨ ਰਸਤੇ ਵਿੱਚ ਨਵੀਂ ਚੈਟ ਵਰਤੋ ਅਤੇ ਇਸਨੂੰ ਨਕਲੀ ਕਰਮਚਾਰੀ ਕਹੋ। ਇਸ ਰਸਤੇ ਉੱਤੇ ਅਸਲ ਸਬਏਜੰਟ ਚੱਲਣ ਦਾ ਦਾਅਵਾ ਨਾ ਕਰੋ।

**ਪੂਰਾ ਹੋਣ ਦੀ ਜਾਂਚ:** ਰਿਪੋਰਟ ਤਿੰਨ ਅਧਿਕਾਰਤ ਸਰੋਤ ਦੱਸਦੀ, ਸਵਾਲ ਦੀ ਹੱਦ ਵਿੱਚ ਰਹਿੰਦੀ ਅਤੇ ਨਿਰਧਾਰਤ ਲੰਬਾਈ ਮੰਨਦੀ ਹੈ। ਇਕੱਠ ਨੋਟ ਸਰੋਤ ਜਾਂਚਦਾ ਅਤੇ ਲੈਬ ਦੀਆਂ ਹਦਾਇਤ ਫਾਈਲਾਂ ਦੱਸਦਾ ਹੈ।

## ਆਪਣੀ ਸਮਝ ਜਾਂਚੋ

1. **ਸਵਾਲ:** ਇੱਕ ਏਜੰਟ ਨਾਲੋਂ ਕਰਮਚਾਰੀ ਕਦੋਂ ਵੱਧ ਮਦਦ ਕਰਦਾ ਹੈ? **ਜਵਾਬ:** ਜਦੋਂ ਉਹ ਸੁਤੰਤਰ ਸਵਾਲ ਜਾਂ ਨਤੀਜੇ ਦੀ ਮਾਲਕੀ ਲੈਂਦਾ ਅਤੇ ਲਾਭਦਾਇਕ ਸਬੂਤ ਰਿਪੋਰਟ ਦਿੰਦਾ ਹੈ।

2. **ਸਵਾਲ:** ਦੋ ਕਰਮਚਾਰੀ ਮਿਲਦੀਆਂ ਫਾਈਲਾਂ ਸੋਧਣ ਤੋਂ ਬਾਅਦ ਕੀ ਕਰਨਾ ਚਾਹੀਦਾ ਹੈ? **ਜਵਾਬ:** ਤਬਦੀਲੀਆਂ ਜੋੜੋ, ਇਕੱਠਾ diff ਵੇਖੋ ਅਤੇ ਜਾਂਚਾਂ ਮੁੜ ਚਲਾਓ।

## ਸਮੱਸਿਆ-ਹੱਲ

- **ਕਰਮਚਾਰੀ ਲੰਮਾ ਟ੍ਰਾਂਸਕ੍ਰਿਪਟ ਦੇਵੇ:** ਫਾਈਲ ਹਵਾਲਿਆਂ ਵਾਲੀ ਛੋਟੀ ਸਬੂਤ ਟੇਬਲ ਮੰਗੋ।
- **ਕਰਮਚਾਰੀ ਅਸਹਿਮਤ ਹੋਣ:** ਜਵਾਬ ਚੁਣਨ ਤੋਂ ਪਹਿਲਾਂ ਅਧਿਕਾਰਤ ਫਾਈਲ ਮੁੜ ਪੜ੍ਹੋ।
- **ਦੋ ਸੋਧਾਂ ਟਕਰਾਉਣ:** ਇੱਕ ਰੋਕੋ ਅਤੇ ਫਾਈਲ ਮਾਲਕੀ ਤੈਅ ਕਰੋ ਜਾਂ ਵਰਕਟ੍ਰੀ ਵੱਖਰੀਆਂ ਕਰੋ।
- **ਕਰਮਚਾਰੀ ਦੀ ਟੂਲ ਪਹੁੰਚ ਵੱਖਰੀ ਹੋਵੇ:** ਮੁੱਖ ਏਜੰਟ ਵਰਗੀ ਮੰਨਣ ਦੀ ਥਾਂ ਉਸਦੀ ਇਜਾਜ਼ਤ ਜਾਂਚੋ।
