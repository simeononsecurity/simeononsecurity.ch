تضع **وكلاء البرمجة الرسومية** محادثات المهام بجانب الملفات والفروقات والتشخيصات ومعاينات التطبيقات. يقارن هذا الدليل بين Cursor، وخط منتجات Windsurf/Cascade، وإضافة Cline في VS Code، وGitHub Copilot في VS Code، وإضافة Continue للـ IDE. يظهر Roo Code كخيار ترحيل قديم لأن وثائقه تعلن الآن عن إيقافه.

**اختر مساحة العمل قبل النموذج.** يغيّر المحرر المستقل بيئة التطوير لديك. تضيف الإضافة وكيلاً إلى محرر موجود. قيّم التصحيح الناتج والجهد المطلوب لفحصه.

## أهم النقاط

- **Cursor وخط منتجات Windsurf** ينتميان إلى مجموعة المحررات الكاملة.
- **Cline وCopilot وContinue** تقدم سير عمل للوكلاء داخل محرر موجود.
- **يحتاج Roo Code إلى تخطيط للترحيل**، وليس إلى معاملة كعملية نشر جديدة عادية.
- **تحتاج التغييرات المرئية إلى اختبارات** ومراجعة للتبعيات وقرار قبول واضح.

**النطاق والتاريخ:** فُحصت الوثائق الرسمية في 6 أكتوبر 2026. هذه مقارنة لسير العمل، وليست معياراً للسرعة أو جودة البرمجة. تغطي [مقارنة CLI](/articles/cli-coding-agents-comparison/) المنتجات الطرفية في مقال منفصل.

**المتطلبات السابقة:** مشروع موجود، واختبارات تعمل، وإذن لتثبيت المحرر أو الإضافة المختارة. الصعوبة من المبتدئ إلى المتوسط. خصص بعد الظهر لتجربتين للمنتجات.

## الأسماء والحالة الحالية

**تعيد وثائق Cascade في Windsurf التوجيه إلى Devin Desktop.** تضع [مرجعية Cascade الحالية](https://docs.devin.ai/desktop/cascade/cascade) Cascade داخل Devin Desktop بجانب وكيل محلي آخر. يستخدم هذا المقال “Windsurf/Cascade” لربط الاسم المألوف بالوثائق الحالية. افحص المنتج المثبت والوكيل المختار قبل إعادة تنفيذ درس قديم.

**تعلن وثائق Roo Code عن إيقاف الإضافة في 2026-05-15.** توجه [إشعارات الوثائق الرسمية](https://roocodeinc.github.io/Roo-Code/) القراء إلى البدائل. لا تثبت التعليمات القديمة أو الكود الموجود استمرار الصيانة. استبعد Roo من أي طرح جديد، إلا إذا قيّمت بشكل منفصل نسخة متفرعة وصيانتها وإصداراتها ودعمها.

| واجهة المنتج | الفئة | الدور في القائمة المختصرة |
|---|---|---|
| **محرر Cursor** | محرر رسومي كامل | وكيل متكامل وسير عمل للمراجعة |
| **Windsurf/Cascade** | سلالة محررات رسومية كاملة | سير عمل Cascade الحالي في Devin Desktop |
| **Cline في VS Code** | إضافة محرر | اختيار المزوّد والمهام المعتمدة على الأدوات |
| **Copilot في VS Code** | تكامل محرر | اقتراحات ومحادثة وعمل الوكيل |
| **إضافة Continue** | إضافة محرر | نماذج وأنماط مهام قابلة للضبط |
| **Roo Code** | إضافة قديمة | مرجع للترحيل، وليس توصية نشطة |

## المحررات الكاملة

يجمع **Cursor Agent** التعليمات والأدوات والنموذج المختار. توثق [نظرة الوكيل](https://cursor.com/docs/agent/overview) تغييرات الملفات وتنفيذ الطرفية والتفاعل مع المتصفح ونقاط التحقق. تنفصل نقاط التحقق عن Git، لذلك استخدمها لاستعادة الجلسة مع إبقاء الالتزامات سجل المراجعة الدائم.

يوفر **Cascade** وضعي الكود والمحادثة، وسياقاً واعياً بالمحرر، واستخدام الأدوات، ونقاط التحقق. تصف الوثائق الحالية الإدراج التلقائي للنص المحدد من المحرر أو الطرفية. أثناء التقييم، سجل السياق الذي قدمته والوكيل النشط. يغيّر تبديل المحرر المحيط أو الوكيل المحلي المقارنة.

**تحتاج تجربة المحرر الكامل إلى فحوص ترحيل.** افتح مساحة العمل الحالية وتحقق من دعم اللغة والتنسيق وتصحيح الأخطاء واختصارات المفاتيح والإضافات قبل قياس ناتج الوكيل. لا يعوض توفير الوكيل للوقت في التصحيحات عن مصحح أخطاء معطل في سير عملك اليومي.

| اختبار المحرر | الأدلة التي تجمعها |
|---|---|
| **بدء المشروع** | استمرار مهام البناء والتشغيل الحالية |
| **أدوات اللغة** | تطابق التشخيص والتنقل مع خط الأساس |
| **تعديلات الوكيل** | ظهور التغييرات في فرق قابل للمراجعة |
| **الاستعادة** | حفاظ التراجع على العمل اليدوي غير المرتبط |
| **فحوص التطبيق** | توافق الاختبارات والسلوك التفاعلي |

## الإضافات داخل محررك

تقرأ **إضافة Cline في VS Code** الملفات وتكتبها، وتنّفذ الأوامر، وتستخدم الأدوات من المحرر. تصف [النظرة العامة](https://docs.cline.bot/cline-overview) طرقاً متعددة للوصول إلى النماذج، ومنها بيانات اعتماد المزوّد وبيئات التشغيل المحلية. تقيم هذه المقارنة الإضافة، مع أن Cline يشحن أيضاً واجهات أخرى.

يتضمن **GitHub Copilot في VS Code** اقتراحات ومحادثة وتغييرات وكيلية. تفصل [نظرة IDE](https://docs.github.com/en/copilot/concepts/copilot-surfaces/copilot-in-ides) هذه التجارب. قيّم المساعدة داخل السطر منفصلة عن المهام المفوضة، لأن قبول إكمال ومراجعة تغيير متعدد الملفات يتطلبان قرارين مختلفين.

تفصل **إضافة Continue** بين أوضاع Chat وPlan وAgent. تشرح [بداية Agent السريعة](https://docs.continue.dev/ide-extensions/agent/quick-start) التخطيط للقراءة فقط والتنفيذ المفعّل بالأدوات. وتحدد دعم النموذج أو المزوّد للأدوات كمتطلب سابق. لا يكفي اتصال النموذج لإثبات إعداد وكيل يعمل.

تقلل **الإضافات عمل ترحيل المحرر**، لكن الإعداد يظل مهماً. افحص الاختصارات المتعارضة وسلوك خادم اللغة وموافقات الأدوات والمزوّد المختار. عطّل إضافات الوكلاء المنافسة أثناء التجربة الأولى كي تعرف أي تكامل أنتج كل نتيجة.

## المراجعة والتحكم

**تعرض واجهة GUI المفيدة أساس القرار.** ابحث عن الملفات المتغيرة ومخرجات الأوامر والإجراءات المعلقة وطريقة واضحة لإعادة توجيه العمل. توفر لوحة محادثة مصقولة وحدها أدلة قليلة عما حدث لمستودعك.

**افصل الموافقة عن القبول النهائي.** يسمح الأمر للوكيل بتنفيذ العمل. يعني قبول التصحيح النهائي أنك راجعت النطاق والسلوك. ينتج تسلسل العمليات الموافق عليها فردياً فرقاً موحداً يحتاج إلى مراجعة.

| سؤال المراجعة | ما الذي تفحصه |
|---|---|
| **ما الذي تغير؟** | الفرق الكامل، بما فيه الإعدادات وملفات القفل |
| **لماذا تغير؟** | الصلة بين المتطلب وكل تعديل |
| **ما الذي شُغّل؟** | الأوامر وحالة الخروج والمخرجات المفيدة |
| **ما الذي فشل؟** | الأخطاء غير المحلولة والطرق المتروكة |
| **ما الذي يمكن استعادته؟** | سلوك نقطة التحقق وخط أساس Git |

**استخدم تعديلاً غير ملتزم به موجوداً كاختبار للاستعادة** في نسخة مؤقتة من المشروع. دع الوكيل ينفذ تغييراً منفصلاً، ثم تراجع عن عمله. تحقق من بقاء تعديلك الأصلي. يختبر هذا فشلاً يومياً في سير العمل دون تعريض نسخة العمل النشطة للخطر.

## النماذج والخصوصية والفوترة

**لا تحدد نافذة المحرر وجهة الاستدلال.** سجل النموذج المختار وحساب المزوّد وسلوك فهرسة المستودع واتصالات الأدوات وبيئة التنفيذ. الإضافة المحلية والنموذج المحلي خاصيتان منفصلتان.

**اربط الأسعار بمسار الوصول.** تختلف حصص الاشتراك واستخدام الخدمة المستضافة وفوترة API للمزوّد. افحص شروط المنتج الحالية ولوحة حسابك بدلاً من مقارنة سعر شراء الإضافة بحصة استدلال منتج آخر.

**يضيف طرح الفريق طبقة قرار أخرى.** تحقق من النماذج المعتمدة وسياسة التثبيت والتحديث ومعالجة بيانات الاعتماد واستثناءات المستودع وملكية الدعم. وثق الإعدادات التي يتحكم فيها المستخدمون وما يفرضه المسؤولون. لا تفترض انتقال خيارات السياسة من منتج إلى إضافة أخرى.

## قائمة مختصرة عملية

| وضع البداية | المقارنة الأولى |
|---|---|
| **مستعد لتغيير المحررات** | Cursor ومساحة Windsurf/Cascade الحالية |
| **الإبقاء على VS Code والوصول إلى Copilot** | وضع Copilot Agent وCline |
| **اختيار المزوّدين بنفسك** | Cline وContinue |
| **الترحيل من Roo Code** | Cline وخيار آخر تتم صيانته حالياً |
| **كتابة الكود يدوياً غالباً** | المساعدة داخل السطر أولاً، ثم المهام المفوضة |

**نفذ تمريناً خاصاً بالمحرر.** اختر دالة فاشلة، واطلب تشخيصاً، ووافق على إصلاح محدود، وافحص الفرق، وشغّل اختبارات مستقلة. ثم نفذ تصحيحاً يدوياً مع بقاء المحادثة مفتوحة. لاحظ هل يحافظ دور الوكيل التالي عليه.

**قيّم التفاعل كله.** سجل صحة المهمة والسياق الذي قدمته يدوياً ومقاطعات الموافقة وجهد المراجعة وسلوك الاستعادة. لا تحول الصقل المرئي أو عدد الأزرار المتاحة إلى درجة لجودة البرمجة.

## استكشاف الأخطاء والخطوات التالية

**غالباً يحتاج وضع الوكيل المعطل إلى فحص الإعداد.** أكد دعم أدوات النموذج وثقة مساحة العمل وسياسة المؤسسة وتوافق الإضافة قبل تغيير النماذج عشوائياً. إذا اختلفت تشخيصات المحرر واختبارات سطر الأوامر، افحص اختيار المفسر ومتغيرات البيئة.

**اختر إعداد محرر واحداً لأسبوع** بعد التجربة الأولى واحتفظ بسجل صغير للتغييرات المقبولة والإصلاحات. استخدم [Copilot CLI مقابل VS Code](/articles/github-copilot-cli-vs-vscode/) لسير عمل GitHub بين الواجهات، أو قارن [Codex](/articles/codex-cli-vs-desktop/) و[Claude Code](/articles/claude-code-cli-vs-desktop/) و[OpenCode](/articles/opencode-cli-vs-desktop/) داخل عائلات منتجاتها.
