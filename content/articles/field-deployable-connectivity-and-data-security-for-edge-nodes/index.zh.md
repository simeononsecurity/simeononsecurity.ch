**现场部署节点是一台无人持续看管、并连接到你无法控制的网络的计算机。** 与放在上锁数据中心里的服务器相比，这会改变安全工作的优先级。*假设物理站点和上行链路都不可信，并据此设计防护。*

这是关于紧凑型快速部署服务器和网络硬件的**四篇系列文章中的第三篇**。[第一篇](/articles/field-deployable-edge-compute-hardware-and-enclosure-selection/)介绍机箱和计算能力，[第二篇](/articles/field-deployable-power-and-environmental-resilience/)介绍供电和环境适应能力。本文讲解如何让节点联网并保护其中的数据。[第四篇](/articles/field-it-tidbits-beyond-the-mini-datacenter/)汇总容易忽略的小细节。

## 选择上行链路

合适的上行链路取决于现场已有的基础设施，而不是理想条件下哪种方式速度最快。

| 上行链路 | 适用场景 | 取舍 |
|---|---|---|
| **蜂窝调制解调器/路由器** | 有任何蜂窝覆盖且需要快速部署的站点 | 覆盖范围和速度因地点和运营商而异 |
| **卫星互联网（Starlink 等）** | 能清楚看到天空且没有蜂窝覆盖的站点 | 需要无遮挡的天空视野，功耗高于蜂窝连接 |
| **LoRa mesh 无线电（Meshtastic/MeshCore）** | 完全没有互联网路径时传输低带宽遥测或消息 | 不适用于大量数据。带宽以每秒字节而不是兆比特计 |
| **点对点无线桥接** | 将现场连接到附近已有互联网的地点 | 需要视距，并需要一对匹配的无线设备 |

*任务完全不能接受停机时，至少准备两种上行链路。* 以蜂窝为主、卫星或 mesh 为备用，能够避免仅使用蜂窝设计中的单点故障。

如需详细比较作为低带宽备用链路或带外管理通道的 LoRa mesh 方案，请参阅我们的 [MeshCore 与 Meshtastic 对比指南](/articles/meshcore-vs-meshtastic-comparison-guide/)。

## 通过隧道连接回可信网络

**切勿将现场节点的管理界面直接暴露在它所使用的上行网络上。** 上行网络可能是酒店 Wi-Fi、共享蜂窝 APN，或不熟悉的卫星服务商网络，这些都不可信。

- **先建立从现场节点到受控家庭网络或云主机的 VPN 隧道，再进行其他部署操作。** 基于 WireGuard 的方案在受限链路上的额外开销较低。
- **即使隧道已建立，也要将现场视为不可信环境。** 零信任模型要求每项服务进行身份验证，并验证每个连接。如果隧道端点遭到入侵，这种方式仍能提供保护。
- **将防火墙设备放在所有设备前面，包括上行调制解调器。** 这样现场流量到达节点上运行的服务之前，必须先经过策略边界。

*隧道不是可有可无的便利功能。它决定了你是在安全管理现场节点，还是把管理端口暴露给附近任意网络。*

## 每条管理路径都启用 MFA

**VPN 隧道为你提供通往节点的可信路径，但它无法阻止他人通过同一路径使用被盗密码。** 现场部署中的每次管理登录都需要第二个身份验证因素，不留例外。

- **在 VPN 集中器、防火墙管理面板和所有远程管理工具上要求 MFA**，而不只是要求团队共用的账户启用 MFA。
- **使用硬件安全密钥或身份验证器应用，而不是 SMS。** SMS 验证码容易受到 SIM 卡交换攻击。现场使用蜂窝上行时，这项风险更加实际。
- **规划在没有蜂窝信号时使用 MFA。** 基于时间的一次性密码（TOTP）应用可以离线工作，SMS 验证码则不行。当节点上行链路也是团队唯一的连接方式时，这一点尤其重要。

我们的[多因素身份验证因素指南](/articles/what-are-the-diferent-kinds-of-factors-in-mfa/)更详细地介绍了各类因素。离线可用的身份验证方式对现场部署尤其重要。

## 分段隔离现场网络

**机箱内部使用单一平面网络时，一台遭入侵的设备就能看到其他所有设备。** 大多数紧凑型管理交换机都支持 VLAN。现场设备也应像固定网络一样使用 VLAN。

- **将交换机、接入点和防火墙的管理接口放在独立 VLAN 中。** 只能通过专用管理设备或 VPN 隧道访问，不能从通用网络访问。
- **将不可信或访客流量与部署所用的计算和存储设备分开**，尤其是在外部人员接入同一物理网络的站点。
- **将摄像头、传感器和环境监测器等 IoT 设备放入无法直接访问存储或管理接口的 VLAN。** 这些设备往往是现场套件中最薄弱的一环。

*平面网络让仓促设置变得方便，却会给部署的其余部分带来风险。* 设置时多花十分钟配置 VLAN，在第一台不可信设备接入机箱时就能体现价值。基础概念请参阅 [Networking Basics 的子网和 VLAN 指南](/articles/networking-basics-what-are-subnets-and-vlans/)。

## 为断连节点集中记录日志

**日志如果只保存在丢失、被扣押或被擦除的设备上，事后就无法提供帮助。** 现场节点需要一套即使节点本身发生故障也能保留记录的日志方案。

- **只要网络可用，就通过 VPN 隧道持续将日志转发到中央日志服务器。** 这样调查事件时就不必只依赖本地磁盘上残留的数据。
- **上行链路中断时，将日志缓存在本地的 store-and-forward 队列中。** 隧道重新连接后自动发送队列中的记录。
- **本地保留足够长时间的日志，以覆盖预计最长的网络中断。** 没有本地缓冲区的队列会丢失离线期间生成的日志。

*节点十天中有九天联网，也仍然需要为第十天制定方案。* store-and-forward 日志机制可避免事件记录在那一天出现盲区。

## 使用 ECC 内存维护现场数据完整性

**振动、高温和陌生电源中的电噪声都会增加内存位翻转的可能性。** 位翻转可能在没有任何错误提示的情况下破坏数据。

- **ECC（错误纠正码）RAM 能自动检测并纠正单个位的内存错误。** 这类瞬时故障在现场环境中比在温控服务器机房更常见，ECC 正好能处理它们。
- **服务器级瘦客户端和小型系统往往支持 ECC 内存，即使产品面向桌面市场销售。** 不要以为 ECC 只用于服务器，应该查阅主板规格。
- **将 ECC 内存与本节中的加密和完整性措施结合使用。** 加密可以防止攻击者读取数据，却无法修复硬件位翻转导致的静默数据损坏。

我们的 [ECC 内存与数据损坏详解](/articles/the-role-of-ecc-memory-in-mitigating-data-corruption/)更深入地介绍了纠错机制。核心观点是：*现场部署正是 ECC 内存要保护的环境。*

## 加密静态数据

现场机箱就是一个箱子，而箱子可能丢失、被盗或被扣押。**机箱中每块驱动器都应启用全盘加密，这是基线要求，不是高级选项。**

- **为构建中的每个存储设备启用全盘加密**，包括用于备份或固件镜像的 USB 驱动器。
- **将解密密钥或口令保存在机箱之外。** 把密钥放在加密驱动器旁边没有保护作用。
- **对最敏感的部署，使用硬件安全模块或带锁 USB 密钥。** 让解密材料保存在与设备分离的实体物品上。

*静态加密假设机箱最终会落入不该接触它的人手中。应为这种情况做好准备，而不是寄希望于它永远不会发生。*

## 检测篡改并应对失窃

上锁的机箱能拖慢顺手行窃的人，却挡不住有意为之的窃贼。因此要提前制定应对未经授权人员打开机箱的方案。

- **防拆封条或贴纸**可以显示上次检查后、下次访问前机箱是否被打开。
- **通过用于管理的同一 VPN 隧道触发远程擦除或锁定**，可在数据被提取前禁用受侵节点。
- **地理围栏或最后已知位置日志**可以在设备联网时报告其位置，帮助找回设备，并确认丢失的机箱是否离开了预定区域。
- **机箱上的物理锁只能起到威慑作用，不是安全控制措施。** 预算时应考虑有决心的攻击者会破坏锁具。

*应假设机箱在使用期间最终会遭到篡改、丢失或被盗，并据此设计响应方案。只覆盖理想情况的方案并不完整。*

## 保护部署地点的 OPSEC

当部署地点本身敏感时，保护节点只完成了一半工作。**硬件会泄露软件不会泄露的线索：天线位置、RF 辐射，以及附近人员能看到的实体外观。**

- **需要隐蔽时，尽量缩小可见范围和 RF 特征。** 外接天线会让观察者注意到部署设备。
- **如果同一团队反复在相似站点部署，应改变部署模式。** 可预测的设置流程本身就是信息。
- **出发前向全体成员说明哪些关于地点、用途和日程的信息可以讨论，哪些不能讨论。** 不要等到有人说漏嘴之后才提醒。

*本系列的硬件和网络章节假设任务已经具备稳妥的 OPSEC。* 硬件纪律无法弥补不谨慎的谈话。

## 连接与安全检查清单

- [ ] 对任何关键任务，至少准备两条独立的上行链路
- [ ] 暴露管理界面前，先建立通往可信网络的 VPN 隧道
- [ ] 每次管理登录都要求 MFA，并提供可离线使用的方式
- [ ] 管理、通用和 IoT 设备分别置于不同 VLAN
- [ ] 日志转发到中央服务器，并使用本地 store-and-forward 缓冲应对中断
- [ ] 机箱内的每个存储设备都启用全盘加密
- [ ] 解密密钥或口令与机箱分开放置
- [ ] 安装防拆封条，并在每次访问时检查
- [ ] 在首次正式部署前测试远程擦除或锁定能力
