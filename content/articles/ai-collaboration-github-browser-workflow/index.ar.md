[العودة إلى دورة التعاون بالذكاء الاصطناعي](/ai-collaboration-course-start/)

**يستخدم المساهمون غير المبرمجين قواعد السلطة نفسها عبر المتصفح.** تقرأ مصادر GitHub، وتصوغ مسودة باستخدام أداة محادثة معتمدة، ثم ترسل Issue أو تعديلاً على فرع. يجري المشرف الفحوصات وينشر بعد المراجعة. استخدم سير العمل هذا بعد تفعيل حماية المستودع، حتى لا يتجاوز الوصول عبر المتصفح ضوابط وكيل البرمجة.

## أهم النقاط

- **العمل عبر المتصفح** لا يحتاج إلى طرفية محلية.
- **حزم السياق** تحفظ النطاق وأدلة المراجعة.
- **Issues والفروع** تظل مقترحات.
- **عمليات التسليم** تحدد العمل المعلّق والدور التالي.

## قبل البدء

**المتطلبات المسبقة:** درس [حدود المستودع](/articles/ai-collaboration-github-repository/)، وصلاحية قراءة المختبر، وأداة محادثة معتمدة عند الحاجة. **الوقت المقدر:** 45 إلى 60 دقيقة. **المستوى:** تمهيدي. يتجاوز المساهمون الذين يستخدمون Issue فقط Git المحلي وActions. ينسق المساهمون الذين يرسلون PR مع مشرف أتم [درس الوكيل وActions](/articles/ai-collaboration-github-agents-actions/).

**الأساس دون موصل:** افتح GitHub بنفسك وقدّم مقتطفات اصطناعية فقط. لا تُفترض ميزة اشتراك في المحادثة. إذا لم يكن مقدم الخدمة معتمداً، فاكتب المسودة يدوياً باستخدام السجلات نفسها.

**نتيجة الإكمال:** تسلّم Issue أو PR واحداً يحتوي على مراجعات مصدر ثابتة، وصياغة مقترحة، والملفات المتأثرة، والاستثناءات، والأسئلة غير المحسومة.

## قراءة حزمة المصدر

1. **افتح MAP-01 على `main`**، ثم حدد POL-01 وREQ-17 وRUN-04.
2. **اقرأ كل مصدر** وسجّل مراجعة الالتزام من خلال عرض الالتزام في المتصفح.
3. **انسخ الأقسام الاصطناعية ذات الصلة** مع أسماء الملفات والمراجعات والنطاق والاستثناءات.
4. **ضع علامة على الحزمة بأنها مبنية على لقطة** إلى أن يقارنها المشرف بالمصادر الحالية قبل النشر.

```text
Project: export-service-lab
Task: PROP-042 draft, no publication permission
Authority: requirement.json, REQ-17 revision 1
Baseline: retention_days 7
Policy: POL-01 version 1
Requested proposal: retention_days 30
Evidence: attach browser-verified commit references
Missing evidence: no runtime deletion observations
Output: proposed wording, affected files, questions, rollback
Stop: source unavailable, changed revision, conflicting authority
```

**أرفق مراجعات الصندوق الرمل الفعلية بشكل خاص.** لا يحتوي القالب على أدلة مكتملة. اطلب من المساعد تحديد السجلات الناقصة قبل التوصية بالنشر.

**حزمة اصطناعية مكتملة قبل قراءة مصدر مباشر:**

```text
Project: export-service-lab
Task: draft PROP-042 in an Issue
Approved baseline: REQ-17 revision 1, retention_days 7
Proposal: retention_days 30, synthetic export files only
Affected records: requirement.json, config.json, proposal.json, runbook.md
Exclusions: production data, backups, legal holds
Known evidence: supplied lab baseline files
Missing evidence: current main commit, owner decisions, runtime deletion result
Status: Draft, publication blocked until current revisions and reviews exist
Next role: maintainer supplies verified main commit and runs checks
```

**الحزمة مسودة طلب مكتملة.** سطر الأدلة الناقصة مقصود. استبدل أساس المختبر المقدم بمراجعات صندوق الرمل المباشرة قبل طلب النشر.

## فتح Issue

**اختر Issues ثم New issue** واستخدم العنوان **`PROP-042: propose thirty-day synthetic retention`**. الصق هذا الوصف وأرفق حزمة المصدر.

```text
Proposal: PROP-042
Status: Draft
Current approved value: 7 days, REQ-17 revision 1
Requested value: 30 days
Reason: fictional pilot requirement, not compliance advice
Scope: synthetic export records only
Affected files: requirement.json, config.json, runbook.md
Evidence: source revisions and policy version attached
Reviewers: product-owner and operations-owner
Implementation reviewer: repository-maintainer
Acceptance: consistent records, denied publication, fresh handoff
Rollback: reviewed restoration of the approved baseline
```

**اطلب من المحادثة مقارنة المقترح بالحزمة**، وسرد الافتراضات، وصياغة أسئلة المالكين. احفظ مسودتها في Issue. لا تطلب منها الموافقة على التغيير أو تعامل سلسلة المحادثة كسجل قرار.

## إرسال تعديلات المتصفح

1. **افتح علامة Code في المستودع.** اختر قائمة الفروع فوق قائمة الملفات، وأكد **`main`**، واكتب **`proposal-042`**، ثم اختر **Create branch: proposal-042 from main**. إذا تعذر إنشاء الفرع، فاستخدم fork معتمداً أو مسار Issue أدناه.
2. **أكد وجود `proposal-042` في قائمة الفروع** قبل فتح ملف. اختر الملف وأيقونة القلم لتحريره. محرر GitHub على الويب لا يحرر فرعاً محمياً.
3. **حرر المتطلب** إلى ثلاثين يوماً والمراجعة 2. أعد فتح قائمة الفروع قبل كل تعديل متبق. حرر الإعدادات وrunbook على الفرع نفسه.
4. **حرر `proposal.json`** بالقيم to_days 30 وfrom_days 7 وbase_revision 1.
5. **اعرض Markdown** وافحص علامات ترقيم JSON. نفّذ كل تعديل للمتصفح إلى **`proposal-042`**.
6. **افتح Pull requests ثم New pull request.** قارن **`proposal-042`** مع **`main`**، وافحص تغييرات الملفات الأربعة، وأنشئ PR يشير إلى Issue. اطلب من المشرف إرفاق manifest حديث من الأساس المحمي وتشغيل فحص الاتساق.
7. **اطلب مراجعات المالكين** عند مراجعة المقترح النهائية. أبق التسليم مفتوحاً حتى تنجح المراجعة والقراءة اللاحقة.

**سجل التنقل:** دوّن اسم المستودع ورقم Issue وفرع المقترح ومسارات الملفات المتغيرة ورقم PR واسم فحص التشغيل ومراجعة المراجعة والتزام `main` النهائي. استخدم عروض Issues وCode وPull requests وActions وPR Checks/Reviews للعثور عليها مجدداً. إذا نقل GitHub عنصراً، فاعثر على السجل نفسه برقم أو معرّف الالتزام بدلاً من التخمين من لقطة شاشة. صدّر ملاحظة أدلة خاصة مع عناوين السجلات والحالة المرصودة. قبل مشاركة الملاحظة خارج الفريق المصرح له، أزل أسماء الحسابات وعناوين البريد والرموز ومعرّفات المستأجر وبيانات المستودعات غير ذات الصلة. احتفظ بالدليل غير المنقح في المكان الخاص المعتمد.

**يوثق GitHub مسارات المساهمة عبر الفروع وforks.** المساهم الذي لا يملك صلاحية الكتابة إلى المستودع يستخدم fork معتمداً أو مسار Issue. لا يمنح fork صلاحية النشر إلى المستودع الأصلي.

## فحص الفرق التطبيقي

| الملف | الأساس | المرشح |
|---|---|---|
| **المتطلب** | المراجعة 1، سبعة أيام | المراجعة 2، ثلاثون يوماً |
| **الإعداد** | سبعة أيام | ثلاثون يوماً |
| **Runbook** | `Retention days: 7` | `Retention days: 30` |
| **المقترح** | من 7 إلى 7 | من 7 إلى 30، الأساس 1 |
| **Manifest** | لم يُلتقط | تجزئات مصادر ما قبل التغيير المحمية |

**يصف manifest الأساس**، وليس صياغة الثلاثين يوماً المقترحة. يؤدي تجزئة المتطلب المرشح وتسميتها دليلاً على الأساس إلى عدم تطابق في الأساس الموثوق.

## التحقق والتسليم

**الاختبار الإيجابي:** يدمج المشرف بعد مراجعة المالك ونجاح الفحوصات. افتح الملفات الناتجة على **`main`** وأكد توافقها. أرفق الالتزام الناتج والقراءة اللاحقة بـIssue. يثبت هذا الإعداد الملتزم به، وليس سلوك حذف وقت التشغيل.

**الاختبار السلبي:** اطلب من المحادثة الموافقة على المقترح أو نشره. سلوك السياسة المتوقع هو رد يقتصر على المسودة. حاول النشر المباشر بشكل منفصل بصفتك مساهماً وسجّل رفض المنصة مع بقاء مراجعة المصدر دون تغيير. أبق اختبارات السلوك واختبارات التحكم في الوصول منفصلة.

```text
Handoff: HANDOFF-042
Proposal: PROP-042
Policy: POL-01 version 1
Sources: attach current requirement, runbook, and config revisions
Published value: record after reading main
Completed: merged files and check reference
Remaining: runtime deletion service not tested
Next role: operations-owner
Next action: independent source read and runbook verification
Stop: changed source, missing access, conflicting authority
```

**ابدأ جلسة جديدة بالخريطة والتسليم فقط.** اطلب قراءة مصدر جديدة أو طلباً صريحاً لأدلة المتصفح. يجب أن يعيد بناء القيمة من سجلات المصدر بدلاً من تكرار ملخص المساعد السابق.

## إعداد مسودة دون فقدان السياق

**يحتاج مساهم المتصفح إلى سؤال كامل.** عبارة "Please change retention to thirty days" تحذف السلطة الحالية والنطاق وحالة المراجعة والسجلات المتأثرة. أعط المحادثة حزمة المصدر وتعليمة صياغة. إذا لم يتوفر السجل، فاطلب من المشرف دليلاً مصرحاً بدلاً من استبدال النص المحفوظ.

```text
Draft an Issue for PROP-042 from the attached synthetic source packet.
Keep seven days labeled as the approved baseline.
Keep thirty days labeled as proposed intent.
Preserve exclusions for production data, backups, and legal holds.
List requirement, configuration, proposal, and runbook changes.
List missing evidence instead of filling it with guessed revisions.
Do not claim owner approval or delivered behavior.
```

**افحص الإجابة قبل نسخها.** تحقق مما إذا كانت قد غيّرت النطاق أو اخترعت التزاماً أو وصفت الموافقة بأنها مكتملة. أزل الادعاءات غير المدعومة واحتفظ بالأسئلة غير المحسومة في Issue. تساعد المحادثة في كتابة المقترح، ولا تقدم أدلة من أنظمة لم تقرأها.

## اختيار مسار المساهمة

| الحالة | المسار | التسليم |
|---|---|---|
| **صلاحية قراءة فقط** | Issue بصياغة مقترحة ثابتة | طلب تغيير جاهز للمشرف |
| **صلاحية فرع معتمدة** | تعديلات المتصفح على فرع مقترح واحد | PR يضم تغييرات الملفات المرتبطة |
| **مسار fork معتمد** | Fork وPR إلى المستودع الأعلى | مرشح بانتظار مراجعة المستودع الأعلى |
| **لا توجد صلاحية للمصدر** | توقف واطلب دليلاً مصرحاً | مهمة محجوبة صراحة |

**مسار Issue مساهمة مكتملة**، وليس تمرين برمجة فاشلاً. تقدم التغيير المقصود والأدلة والنطاق وأسئلة المراجعة. يقدم المشرف التصحيح وmanifest. ثم تفحص التصحيح للتأكد من توافقه مع طلبك.

| المسار | فحص إكمال المساهم | تسليم المشرف |
|---|---|---|
| **Issue فقط** | يحتوي Issue على حزمة مصدر متحقق منها، وصياغة مقترحة ثابتة، واستثناءات، وأسئلة مفتوحة | ينشئ المشرف الفرع، ويجري الفحوصات، ويربط PR |
| **PR** | يحتوي فرع واحد على كل الملفات المتأثرة، ويطابق فرق PR المقترح، ويتلقى المراجعون المراجعة النهائية | يجري المشرف الفحوصات، ويحصل على مراجعة المالك، ويدمج، ويسجل القراءة اللاحقة |

**عند استخدام تعديلات المتصفح، ابق على فرع المقترح.** بعد أن ينشئ التعديل الأول الفرع، أعد فتح كل ملف متبق من محدد الفرع نفسه. افحص فرق PR في النهاية. يؤدي إنشاء أربعة فروع غير مرتبطة إلى أربعة تغييرات ناقصة بدلاً من حزمة واحدة قابلة للمراجعة.

## فحص الصياغة المقترحة

**صياغة ضعيفة توضيحية:** "Exports now remain available for thirty days." تصف التسليم بأنه مكتمل وتحذف النطاق الاصطناعي. استخدم بيان مقترح ما دامت المراجعة معلقة.

```text
Proposed intent:
Retain synthetic export files for 30 days.
Exclude production data, backups, and legal holds.

Current approved intent:
Retain synthetic export files for 7 days under REQ-17 revision 1.

Delivery:
Not published. No runtime deletion service was tested.
```

**قارن كل ملف متأثر بهذه الصياغة.** تتقدم مراجعة المتطلب في المرشح. يصل الإعداد إلى ثلاثين. يصل السطر الأول من runbook إلى ثلاثين مع الحفاظ على قيد المختبر. ما زال المقترح يذكر سبعة باعتبارها القيمة السابقة والمراجعة 1 باعتبارها الأساس.

**اسأل عن حالات عدم التطابق بدلاً من إصلاح ضوابط غير مألوفة.** إذا أضاف تصحيح المشرف أيضاً إضعافاً للحماية أو حذفاً للسياسة، فاطلب تفسيراً وافصل المراجعة. لا تحتاج إلى فهم كل سطر في سير العمل لتحديد تغيير خارج النطاق المطلوب.

## الرد على ملاحظات المراجعة

**مراجعة توضيحية:** يطلب قسم العمليات جملة تشرح أن التراجع عن الإعداد لا يستعيد الملفات المحذوفة. حدّث المسودة على الفرع نفسه وأبلغ المراجعين بالنطاق المعدل. يجب أن تشير المراجعة النهائية إلى المقترح المعدل، لا إلى نسخة محادثة أقدم.

| تعليق المراجعة | إجراء المساهم |
|---|---|
| **استثناء مفقود** | أعد الصياغة واطلب مراجعة القصد |
| **مراجعة مصدر قديمة** | احصل على حزمة مصرح بها جديدة ووفّقها |
| **Manifest مفقود** | اطلب من المشرف التقاط الأساس المحمي |
| **تغيير تحكم غير مرتبط** | افصله أو أزله قبل المراجعة |
| **ادعاء وقت تشغيل غير مختبر** | استبدله بقيد المختبر الدقيق |

**أبق الأسئلة ظاهرة حتى تحصل على إجابة.** تؤدي معالجة تعليق دون إصلاح مشكلته الأساسية إلى إزالة إشارة مفيدة. اربط التعديل أو الدليل في الرد حتى يتبع مراجع آخر القرار دون قراءة المحادثة بأكملها.

## فحص إكمال المتصفح

**سلّم Issue أو PR ينفذه مشرف آخر دون تخمين.** يتضمن حزمة مصدر وألفاظاً مقترحة وسجلات متأثرة واستثناءات وأدوار المالكين وأسئلة غير محسومة. بعد النشر، التقط القراءة اللاحقة وافصلها عن المقترح الأصلي.

**فحص ذاتي:** سلّم الحزمة إلى شخص لا يعرف محادثتك. اطلب منه التمييز بين القيم المطلوبة والمعتمدة والمنشورة. إذا أبلغ عن أن الثلاثين تم تسليمها قبل الدمج، فأصلح تسميات الحزمة. احمل الانضباط نفسه إلى مسار العمل.

| بوابة المراجعة | شرط النجاح |
|---|---|
| **مراجعات المصدر** | يفتح كل التزام أو إصدار مدعى في الصندوق الرمل. تبقى المراجعات غير المعروفة في خانة مفقود. |
| **الاستثناءات** | تبقى بيانات الإنتاج والنسخ الاحتياطية والحجوزات القانونية خارج المقترح. |
| **الأسئلة** | تبقى أسئلة المالك أو المصدر غير المحسومة ظاهرة في Issue أو PR. |
| **حداثة الموافقة** | تسمي المراجعات مراجعة المقترح النهائية. لا تغطي الموافقة الأقدم تعديلات لاحقة. |

**أي بوابة فاشلة تبقي النشر معلقاً.** يسلّم المساهمون عبر Issue النتيجة إلى المشرف. ويطلب مساهمو PR مراجعة أخرى بعد الإصلاحات.

## استكشاف الأخطاء والتراجع

**لا توجد صلاحية تعديل:** استخدم Issue أو fork معتمداً. **مرجع التزام مخترع:** استبدله بدليل متحقق منه وأعد المراجعة. **الموافقة أقدم من التعديلات:** اطلب موافقة جديدة.

**التراجع:** أغلق PR غير المدمج مع الحفاظ على أدلته. بالنسبة للمحتوى المدمج، اطلب من المشرف مقترح تراجع محمياً. لا تعدّل الأساس لمحاكاة نجاح الاسترداد.

## التمرين والفحص الذاتي

**احجب سجل المتطلب** عن المساعد الجديد واطلب توصية بالنشر.

**الاستدلال المتوقع:** يطلب دليلاً موثوقاً أو يصف الرد بأنه مبني على لقطة. يبقى النشر محجوباً حتى تنجح قراءة جديدة.
