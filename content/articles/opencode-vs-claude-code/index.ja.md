**OpenCode** は、モデルプロバイダー、エージェント設定、ローカル推論を管理したい開発者に向いています。**Claude Code** は、Anthropic の統合コーディングワークフロー、Claude のサブスクリプション、文書化された組織向け制御を求める開発者に向いています。どちらも実際のリポジトリで動作します。役に立つ結果は、ツール実行、プロジェクト指示、検証に左右されます。

**エージェントとモデルは別の選択です。** ホストされた Claude モデルを使う Claude Code から、小さなローカルモデルを使う OpenCode に切り替えると、複数の変数が同時に変わります。結果の差だけでは、どちらのエージェントアプリケーションが優れているかは判断できません。

## 要点

- **プロバイダーの柔軟性には OpenCode を選びます。** オープンソースのカスタマイズと、ホスト型またはローカルモデルでの試行にも向いています。
- **Claude 中心のワークフローには Claude Code を選びます。** サブスクリプションや組織がすでに対応している場合に適しています。
- **ローカル実行には注意が必要です。** ターミナルアプリケーションでも、設定した推論サービスへプロンプトを送信します。
- **完了した作業を比較します。** トークン速度だけでなく、レビュー時間と失敗した試行も含めます。

**範囲と日付:** この比較は、2026年10月6日時点の公式ドキュメントと料金を確認しています。選択の助言であり、実機パフォーマンスベンチマークではありません。

**前提:** Git リポジトリ、動作するビルドとテストコマンド、使用するモデルへのアクセスが必要です。インストール後の初回比較には60から90分を見込みます。難易度は中級です。

## 機能比較

| 分野 | OpenCode | Claude Code |
|---|---|---|
| **エージェントライセンス** | MIT オープンソース | 独自の利用条件 |
| **主なモデル方式** | 設定可能なプロバイダーとモデル | Claude のファーストパーティーワークフロー |
| **インターフェース** | ターミナル、デスクトップ、IDE 拡張 | ターミナル、デスクトップ、エディター統合 |
| **計画** | 組み込みの Plan エージェント | Plan 権限モード |
| **カスタマイズ** | エージェントのプロンプト、モデル、ツール、権限 | プロジェクト指示と権限ポリシー |
| **推論の課金** | 選択したプロバイダーまたは任意の OpenCode サービス | サブスクリプションまたは設定した API プロバイダー |
| **ローカルモデルの経路** | 対応するローカル推論プロバイダー | Ollama の文書化された統合 |

**ライセンスとモデルアクセスは別です。** [OpenCode の MIT ライセンス](https://github.com/anomalyco/opencode/blob/dev/LICENSE) はエージェントソフトウェアを対象にします。ホストされたモデルを無料にはしません。Claude Code の公開リポジトリには、オープンソースライセンスではなく [Anthropic のライセンス条件](https://github.com/anthropics/claude-code/blob/main/LICENSE.md) が適用されます。

**インターフェースは試用する価値があります。** [OpenCode の紹介](https://opencode.ai/docs/) と [Claude Code の概要](https://code.claude.com/docs/en/overview) は複数の作業方法を説明しています。どちらもターミナルチャットだけに限定されません。普段の環境で、編集、割り込み、最終 diff の表示方法を比較してください。

## モデルとローカル推論

**OpenCode はプロバイダー設定とエージェントインターフェースを分離します。** [プロバイダードキュメント](https://opencode.ai/docs/providers/) では、複数のホスト型サービスとカスタム互換エンドポイントを扱います。日々のコーディングインターフェースを変えずにモデルを変更したい場合に役立ちます。互換性は、エンドポイントがモデルのツール呼び出しとリクエスト形式をサポートするかにも左右されます。

**Claude Code には公式のデプロイ経路が複数あります。** Anthropic は [サードパーティーデプロイガイド](https://code.claude.com/docs/en/third-party-integrations) で Claude サブスクリプション、API、クラウドプラットフォーム統合を説明しています。認証、課金、インフラの要件を扱います。任意のゲートウェイの背後にあるすべてのモデルが、対応済みの Claude デプロイと同等になるわけではありません。

```bash
ollama launch claude
```

**Ollama はこの Claude Code 統合を [セットアップガイド](https://docs.ollama.com/integrations/claude-code) で説明しています。** ローカルで提供するモデルが推論を行い、Claude Code がエージェントインターフェースを提供します。この方法で Claude の独自モデル重みをローカル実行するわけではありません。Ollama にはクラウドモデルもあります。ローカル構成と説明する前に、モデルと送信先を確認してください。

**体験を決める層は3つあります。** エージェントはツールの使い方を決め、モデルは推論とツール要求を生成し、推論サービスは提供動作を決めます。統合が対応していれば、ローカルサービスとホスト型サービスはどちらのインターフェースの背後にも配置できます。下の図は、機能対応が同一だと示さずに各層を分けています。

## 料金と実行コスト

**ソフトウェア料金は項目の一つにすぎません。** OpenCode のクライアントは無料で使えます。従量制の推論料金はプロバイダーによって変わります。任意の [Zen サービス](https://opencode.ai/docs/zen/) は、厳選したモデルをトークン単価で提供します。[Go プラン](https://opencode.ai/docs/go/) には、定められた利用上限を持つ別の課金経路があります。

| 経路 | 表示価格 | 確認する点 |
|---|---|---|
| **OpenCode クライアント** | ソフトウェアサブスクリプション不要 | 推論料金は別 |
| **OpenCode Go** | 月10ドル | 含まれるモデルと利用上限 |
| **OpenCode Go Plus** | 月40ドル | 高い利用枠と適用される上限 |
| **Claude Pro** | 月20ドル、月払い | Claude Code の利用を含む |
| **Claude Max** | 月100ドルから | 選択した利用枠と上限 |
| **API ベースのエージェント** | プロバイダーのトークン料金 | 入力、出力、キャッシュ、再試行 |
| **ローカル推論** | ハードウェアと運用コスト | メモリ、電力、保守 |

**価格は日付付きのスナップショットです。** 同等の計算資源を示すものではありません。[Claude の料金ページ](https://claude.com/pricing) は Pro と Max のアクセスを示します。利用上限と税は別です。OpenCode Go と Claude のサブスクリプションは、異なるモデルと利用枠を対象にします。月額が安いだけでは、あなたの負荷に対して安い経路とは判断できません。

**サブスクリプションアクセスと API 課金は別です。** [Claude Code のコストドキュメント](https://code.claude.com/docs/en/costs) は利用状況と API コストを説明します。長いセッションの前に、現在の認証経路を確認してください。既存の個人向けサブスクリプションが支払うと考えず、プロバイダー API キーを別の課金判断として扱います。

**受け入れた変更ごとのコストを測ります。** 失敗した試行、追加プロンプト、テスト、レビュー時間を含めます。移行を何度も壊す安価なモデルは、正しいパッチを出す高価なモデルより開発者の時間を消費する場合があります。これは評価基準であり、製品の実測ランキングではありません。

## 計画と権限

**OpenCode の組み込みエージェントは計画と実装を分けます。** [エージェントドキュメント](https://opencode.ai/docs/agents/) は Plan と Build、および設定可能な専門エージェントを説明しています。エージェントごとのモデルとツール設定により、探索と実装で別モデルを使う実験ができます。結果を比較するときは選択を記録してください。

```json
{
  "permission": {
    "edit": "ask",
    "bash": "ask"
  }
}
```

**OpenCode では、編集とシェルコマンドの承認を求めるためにこの断片を `opencode.json` に統合します。** [権限リファレンス](https://opencode.ai/docs/permissions/) は allow、ask、deny の動作を定義します。特に組織固有の設定があるリポジトリでは、追加前に既存ルールを確認してください。

```json
{
  "permissions": {
    "defaultMode": "plan"
  }
}
```

**Claude Code では、Plan モードで開始するためにこの断片を `.claude/settings.json` に統合します。** [権限ドキュメント](https://code.claude.com/docs/en/permissions) は、計画、編集の承認、自動権限判断などを区別しています。実装の準備ができたら、意図を持ってモードを変更します。

**例の目的は異なります。** OpenCode の断片は2種類のツールについて承認を求めます。Claude Code の断片は計画ワークフローを開始します。どちらも OS のサンドボックスや完全なネットワークポリシーを定義しません。機密作業を任せる前に、安全な操作で権限の挙動を試してください。

## リポジトリのルールを共有する

```markdown
# AGENTS.md

Use the repository's documented build and test commands.
Preserve unrelated changes.
Explain failures before changing dependencies.
Review the final diff before committing.
```

**共有指示は比較時のノイズを減らします。** ビルドコマンド、アーキテクチャ制約、受け入れ基準を一つの正規ファイルに置きます。[OpenCode のルールドキュメント](https://opencode.ai/docs/rules/) は `AGENTS.md` と `CLAUDE.md` へのフォールバックを説明しています。すべての指示ファイルが自動的に結合されると考えないでください。

```markdown
@AGENTS.md
```

**必要ならこの import を `CLAUDE.md` に置きます。** [Claude Code のメモリドキュメント](https://code.claude.com/docs/en/memory) は、設定と指示ファイルの優先順位に従い、バージョン2.1.277以降で `AGENTS.md` を直接サポートすると説明しています。プロジェクトまたは祖先の `CLAUDE.md` は既定の選択を変えます。明示的な import は、`CLAUDE.md` がある場合や直接読み込みが使えない場合に共有ルールを支えます。

**新しいセッションで読み込まれた指示を確認します。** 編集前に各エージェントへ、リポジトリのビルドコマンドと変更制限を答えさせます。誤答はセットアップの問題を示します。モデル品質の証拠として失敗を扱う前に、問題を直してください。

## プライバシーとチーム適合性

**ローカルインターフェースはローカル推論を示しません。** ソースコード、プロンプト、ツール出力、セッションデータを受け取るサービスを整理します。ローカルモデルは遠隔推論への依存を減らしますが、接続ツール、ウェブリクエスト、プラグイン、共有機能も確認が必要です。

**OpenCode はソースコードを確認してカスタマイズできます。** 同時に、選んだプロバイダーと設定の評価責任は利用者にあります。Claude Code の文書化された管理権限ポリシーとクラウドデプロイ経路は、アクセスを標準化するチーム向けの別の選択肢です。ソフトウェアライセンスだけで組織のデータポリシーは決まりません。

| チーム要件 | 評価する質問 |
|---|---|
| **モデル選択** | どの承認済みプロバイダーとモデルを動かす必要があるか |
| **データ処理** | プロンプト、ログ、ツール出力はどこへ行くか |
| **アクセス制御** | 誰がポリシーを決め、誰が変更できるか |
| **運用** | ローカルランタイムとカスタム統合を誰が保守するか |
| **レビュー** | 依存関係、パッチ、デプロイを誰が承認するか |

## 公平な試行を行う

**同じリポジトリリビジョンから開始します。** 別々の使い捨てブランチまたは worktree を使います。同じ指示、受け入れテスト、時間制限、承認ポリシーを使います。モデルや提供設定が異なる場合は、その差を記録し、エージェントだけの比較結果とは呼びません。

**独立した検査を持つタスクを使います。** 既知の再現手順があるバグ、事前に書いた受け入れ基準を持つ小さな機能、既存テストで保護されたリファクタリングを選びます。各エージェントには相手のパッチを見せずに作業させます。終了後に両方の diff をレビューします。

| 指標 | 各試行で記録する内容 |
|---|---|
| **正確性** | 既存テストと独立した受け入れ検査 |
| **時間** | 開始からレビュー済みで使えるパッチまで |
| **介入** | 説明要求と手動修正 |
| **変更範囲** | 無関係な編集と依存関係の変更 |
| **コスト** | 課金された利用量またはローカル資源コスト |
| **復旧** | 失敗したテストや拒否されたコマンドへの対応 |

**選ぶ前に試行を繰り返します。** 一つの成功タスクは広い優位性の証拠として弱いものです。生成テストもレビューが必要です。エージェントが実装とテストで同じ誤った前提を繰り返す場合があるためです。失敗した試行も記録に残します。

**速度と完了を分けます。** 高速なトークン生成は、テスト実行、繰り返しの推論、人間のレビューを測りません。ローカル構成では、初回プロンプト処理とキャッシュされた継続を分けて記録します。ウォームセッションの高速な継続は、コールドスタート性能を示しません。

## トラブルシューティング

| 症状 | 次の確認 |
|---|---|
| **予想外の請求** | 有効なアカウント、API 認証情報、プロバイダー経路 |
| **プロジェクトルールが無視される** | ファイルの優先順位、作業ディレクトリ、読み込まれた指示 |
| **ツール呼び出しが壊れる** | モデル能力と提供 API の互換性 |
| **承認要求が多すぎる** | 既知のコマンドに対する狭い権限ルール |
| **ローカルセッションが遅い** | メモリ圧迫、コンテキスト長、推論設定 |
| **テストは通るが動作が誤る** | 独立した再現と受け入れ基準 |

## どちらを選ぶか

**OpenCode から始めます。** プロバイダーの切り替えやエージェントソースの確認がワークフローの中心なら適しています。モデル選択、提供互換性、推論コストについて、自分で決める項目が増えます。

**Claude Code から始めます。** Anthropic の統合体験が優先で、適切な Claude アクセスをすでに持っている場合に適しています。チーム要件に対して、インターフェース、権限、組織向けデプロイオプションを評価してください。

**決定を変更できる状態に保ちます。** プロジェクトルールと受け入れテストをリポジトリに置きます。エージェントに関係なく diff を確認します。自分のタスクで繰り返した結果を基に選び、モデル、負荷、課金方法が変わったら再評価します。
