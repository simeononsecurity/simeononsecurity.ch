**OpenCode** এমন ডেভেলপারদের জন্য উপযোগী, যারা মডেল প্রদানকারী, এজেন্ট কনফিগারেশন এবং স্থানীয় ইনফারেন্স নিয়ন্ত্রণ করতে চান। **Claude Code** এমন ডেভেলপারদের জন্য উপযোগী, যারা Anthropic-এর সমন্বিত কোডিং ওয়ার্কফ্লো, Claude সাবস্ক্রিপশন অ্যাক্সেস এবং নথিভুক্ত সাংগঠনিক নিয়ন্ত্রণ চান। দুটিই বাস্তব রিপোজিটরির ভিতরে কাজ করে। উপযোগী ফলাফল টুল চালানো, প্রকল্পের নির্দেশনা এবং যাচাইয়ের উপর নির্ভর করে।

**এজেন্ট ও মডেল আলাদা সিদ্ধান্ত।** হোস্টেড Claude মডেলসহ Claude Code থেকে ছোট স্থানীয় মডেলসহ OpenCode-এ বদলালে একসঙ্গে কয়েকটি ভেরিয়েবল বদলে যায়। ফলাফলের পার্থক্য কোন এজেন্ট অ্যাপ্লিকেশন ভালো, তা প্রমাণ করে না।

## মূল বিষয়

- **প্রদানকারী নমনীয়তার জন্য OpenCode বেছে নিন**, ওপেন-সোর্স কাস্টমাইজেশন এবং হোস্টেড বা স্থানীয় মডেল নিয়ে পরীক্ষার জন্য।
- **Claude-কেন্দ্রিক ওয়ার্কফ্লোর জন্য Claude Code বেছে নিন**, বিশেষ করে আপনার সাবস্ক্রিপশন বা প্রতিষ্ঠান এটি সমর্থন করলে।
- **স্থানীয় চালনার ক্ষেত্রে স্পষ্টতা দরকার।** টার্মিনাল অ্যাপ্লিকেশন এখনও তার কনফিগার করা ইনফারেন্স সার্ভিসে প্রম্পট পাঠায়।
- **সম্পন্ন কাজ তুলনা করুন**, রিভিউ সময় এবং ব্যর্থ প্রচেষ্টাসহ, শুধু টোকেনের গতি নয়।

**পরিধি ও তারিখ:** এই তুলনায় 6 অক্টোবর 2026-এর অফিসিয়াল নথি ও মূল্য পরীক্ষা করা হয়েছে। এটি নির্বাচন-সংক্রান্ত পরামর্শ দেয়, হাতে করা পারফরম্যান্স বেঞ্চমার্ক নয়।

**পূর্বশর্ত:** একটি Git রিপোজিটরি, কার্যকর বিল্ড ও টেস্ট কমান্ড এবং আপনার নির্ধারিত মডেলে অ্যাক্সেস। ইনস্টলেশনের পর প্রাথমিক তুলনার জন্য 60 থেকে 90 মিনিট রাখুন। কঠিনতার স্তর মধ্যম।

## ফিচার তুলনা

| ক্ষেত্র | OpenCode | Claude Code |
|---|---|---|
| **এজেন্ট লাইসেন্স** | MIT ওপেন সোর্স | মালিকানাধীন শর্ত |
| **প্রধান মডেল পদ্ধতি** | কনফিগারযোগ্য প্রদানকারী ও মডেল | প্রথম পক্ষের Claude ওয়ার্কফ্লো |
| **ইন্টারফেস** | টার্মিনাল, ডেস্কটপ, IDE এক্সটেনশন | টার্মিনাল, ডেস্কটপ, এডিটর ইন্টিগ্রেশন |
| **পরিকল্পনা** | বিল্ট-ইন Plan এজেন্ট | Plan পারমিশন মোড |
| **কাস্টমাইজেশন** | এজেন্ট প্রম্পট, মডেল, টুল, অনুমতি | প্রকল্পের নির্দেশনা ও অনুমতি নীতি |
| **ইনফারেন্স বিলিং** | নির্বাচিত প্রদানকারী বা ঐচ্ছিক OpenCode সার্ভিস | সাবস্ক্রিপশন বা কনফিগার করা API প্রদানকারী |
| **স্থানীয় মডেলের পথ** | সামঞ্জস্যপূর্ণ স্থানীয় ইনফারেন্স প্রদানকারী | Ollama-নথিভুক্ত ইন্টিগ্রেশন |

**লাইসেন্স ও মডেল অ্যাক্সেস আলাদা।** OpenCode-এর [MIT লাইসেন্স](https://github.com/anomalyco/opencode/blob/dev/LICENSE) তার এজেন্ট সফটওয়্যারকে কভার করে। এটি হোস্টেড মডেলকে বিনামূল্যে করে না। Claude Code-এর পাবলিক রিপোজিটরিতে ওপেন-সোর্স লাইসেন্সের বদলে [Anthropic-এর লাইসেন্স শর্ত](https://github.com/anthropics/claude-code/blob/main/LICENSE.md) আছে।

**ইন্টারফেস পরীক্ষা করে দেখা দরকার।** [OpenCode পরিচিতি](https://opencode.ai/docs/) এবং [Claude Code ওভারভিউ](https://code.claude.com/docs/en/overview) বিভিন্ন কাজের পদ্ধতি বর্ণনা করে। কোনো পণ্যই শুধু টার্মিনাল চ্যাটে সীমাবদ্ধ নয়। আপনার স্বাভাবিক পরিবেশে প্রতিটি ইন্টারফেস সম্পাদনা, বিরতি এবং চূড়ান্ত diff কীভাবে দেখায়, তা তুলনা করুন।

## মডেল ও স্থানীয় ইনফারেন্স

**OpenCode প্রদানকারীর কনফিগারেশনকে এজেন্ট ইন্টারফেস থেকে আলাদা রাখে।** এর [প্রদানকারী নথি](https://opencode.ai/docs/providers/) একাধিক হোস্টেড সার্ভিস ও কাস্টম সামঞ্জস্যপূর্ণ এন্ডপয়েন্ট কভার করে। দৈনিক কোডিং ইন্টারফেস না বদলে মডেল পাল্টাতে চাইলে এটি উপকারী। এন্ডপয়েন্টটি মডেলের টুল কল ও অনুরোধের ফরম্যাট সমর্থন করলেই সামঞ্জস্য থাকবে।

**Claude Code-এর একাধিক অফিসিয়াল ডিপ্লয়মেন্ট পথ আছে।** Anthropic তার [তৃতীয় পক্ষের ডিপ্লয়মেন্ট গাইডে](https://code.claude.com/docs/en/third-party-integrations) Claude সাবস্ক্রিপশন, API এবং ক্লাউড প্ল্যাটফর্ম ইন্টিগ্রেশন নথিভুক্ত করেছে। এসব পথে প্রমাণীকরণ, বিলিং ও অবকাঠামোর প্রয়োজনীয়তা থাকে। ইচ্ছেমতো কোনো গেটওয়ের পেছনের প্রতিটি মডেলকে সমর্থিত Claude ডিপ্লয়মেন্ট বানায় না।

```bash
ollama launch claude
```

**Ollama এই Claude Code ইন্টিগ্রেশন নথিভুক্ত করেছে** তার [সেটআপ গাইডে](https://docs.ollama.com/integrations/claude-code)। স্থানীয়ভাবে পরিবেশিত সামঞ্জস্যপূর্ণ মডেল ইনফারেন্স দেয়, আর Claude Code এজেন্ট ইন্টারফেস দেয়। এতে Claude-এর মালিকানাধীন মডেল ওজন স্থানীয়ভাবে চলে না। Ollama ক্লাউড মডেলও দেয়। সেটআপটিকে স্থানীয় বলার আগে নির্বাচিত মডেল ও গন্তব্য পরীক্ষা করুন।

**তিনটি স্তর অভিজ্ঞতা নির্ধারণ করে:** এজেন্ট ঠিক করে কীভাবে টুল ব্যবহার হবে, মডেল যুক্তি ও টুল অনুরোধ তৈরি করে, আর ইনফারেন্স সার্ভিস পরিবেশন আচরণ নির্ধারণ করে। ইন্টিগ্রেশন সমর্থন করলে স্থানীয় ও হোস্টেড সার্ভিস উভয় ইন্টারফেসের পেছনে কাজ করে। নিচের চিত্রটি একই ফিচার সমর্থনের দাবি না করে স্তরগুলো আলাদা করে।

## মূল্য ও চলতি খরচ

**সফটওয়্যারের মূল্য মোট খরচের একটি অংশ।** OpenCode ক্লায়েন্ট বিনামূল্যে ব্যবহার করা যায়, আর পেইড ইনফারেন্স আপনার প্রদানকারীর উপর নির্ভর করে। ঐচ্ছিক [Zen সার্ভিস](https://opencode.ai/docs/zen/) টোকেন মূল্যে বাছাই করা মডেল অ্যাক্সেস দেয়। [Go প্ল্যান](https://opencode.ai/docs/go/) নির্দিষ্ট ব্যবহারসীমাসহ আরেকটি বিলিং পথ দেয়।

| পথ | তালিকাভুক্ত মূল্য | যা পরীক্ষা করবেন |
|---|---|---|
| **OpenCode ক্লায়েন্ট** | সফটওয়্যার সাবস্ক্রিপশন লাগে না | আলাদা ইনফারেন্স চার্জ |
| **OpenCode Go** | $10/মাস | অন্তর্ভুক্ত মডেল ও ব্যবহারের সীমা |
| **OpenCode Go Plus** | $40/মাস | বেশি বরাদ্দ ও প্রযোজ্য সীমা |
| **Claude Pro** | $20/মাস, মাসিক বিলিং | অন্তর্ভুক্ত Claude Code ব্যবহার |
| **Claude Max** | $100/মাস থেকে | নির্বাচিত ব্যবহার স্তর ও সীমা |
| **API-নির্ভর এজেন্ট** | প্রদানকারীর টোকেন রেট | ইনপুট, আউটপুট, ক্যাশিং, পুনঃচেষ্টা |
| **স্থানীয় ইনফারেন্স** | হার্ডওয়্যার ও পরিচালনা খরচ | মেমরি, বিদ্যুৎ, রক্ষণাবেক্ষণ |

**মূল্য একটি তারিখ-নির্দিষ্ট স্ন্যাপশট**, সমমানের কম্পিউট বরাদ্দ নয়। [Claude-এর মূল্য পৃষ্ঠা](https://claude.com/pricing) Pro ও Max অ্যাক্সেস দেখায়। ব্যবহারসীমা ও কর আলাদা। OpenCode Go এবং Claude সাবস্ক্রিপশন আলাদা মডেল নির্বাচন ও বরাদ্দ কভার করে। কম মাসিক মূল্য একাই আপনার কাজের জন্য সস্তা পথ চিহ্নিত করে না।

**সাবস্ক্রিপশন অ্যাক্সেস ও API বিলিং আলাদা।** [Claude Code-এর খরচের নথি](https://code.claude.com/docs/en/costs) ব্যবহার ট্র্যাকিং ও API খরচ ব্যাখ্যা করে। দীর্ঘ সেশনের আগে সক্রিয় প্রমাণীকরণ পথ পরীক্ষা করুন। প্রদানকারীর API কীকে আলাদা বিলিং সিদ্ধান্ত হিসেবে দেখুন। বিদ্যমান ভোক্তা সাবস্ক্রিপশন এর খরচ দিচ্ছে ধরে নেবেন না।

**প্রতি গৃহীত পরিবর্তনের খরচ মাপুন।** ব্যর্থ প্রচেষ্টা, অতিরিক্ত প্রম্পট, টেস্ট ও রিভিউ সময় ধরুন। বারবার মাইগ্রেশন নষ্ট করা সস্তা মডেল অনেক সময় সঠিক প্যাচ তৈরি করা দামি মডেলের চেয়ে বেশি ডেভেলপার সময় নেয়। এটি মূল্যায়নের মানদণ্ড, এই পণ্যগুলোর মাপা র‍্যাঙ্কিং নয়।

## পরিকল্পনা ও অনুমতি

**OpenCode-এর বিল্ট-ইন এজেন্ট পরিকল্পনা ও বাস্তবায়ন আলাদা করে।** এর [এজেন্ট নথি](https://opencode.ai/docs/agents/) Plan ও Build এবং কনফিগারযোগ্য বিশেষায়িত এজেন্ট বর্ণনা করে। প্রতি-এজেন্ট মডেল ও টুল সেটিং অনুসন্ধান ও বাস্তবায়নে ভিন্ন মডেল পরীক্ষা করতে সাহায্য করে। তুলনার সময় এসব সিদ্ধান্ত লিখে রাখুন।

```json
{
  "permission": {
    "edit": "ask",
    "bash": "ask"
  }
}
```

**সম্পাদনা ও শেল কমান্ডের অনুমোদন চাইলে এই অংশ `opencode.json`-এ মেশান।** [অনুমতি রেফারেন্স](https://opencode.ai/docs/permissions/) allow, ask ও deny আচরণ সংজ্ঞায়িত করে। যোগ করার আগে বর্তমান নিয়ম পরীক্ষা করুন, বিশেষ করে সাংগঠনিক কনফিগারেশন থাকা রিপোজিটরিতে।

```json
{
  "permissions": {
    "defaultMode": "plan"
  }
}
```

**Claude Code-এর জন্য Plan মোডে শুরু করতে এই অংশ `.claude/settings.json`-এ মেশান।** এর [অনুমতি নথি](https://code.claude.com/docs/en/permissions) পরিকল্পনা, সম্পাদনা গ্রহণ, স্বয়ংক্রিয় অনুমতি সিদ্ধান্ত এবং অন্যান্য মোড আলাদা করে। বাস্তবায়নের আগে ইচ্ছাকৃতভাবে মোড বদলান।

**এই উদাহরণগুলোর উদ্দেশ্য আলাদা।** OpenCode অংশটি দুটি টুল শ্রেণির জন্য অনুমোদন চায়। Claude Code অংশটি পরিকল্পনার ওয়ার্কফ্লো শুরু করে। কোনো অংশই অপারেটিং সিস্টেম স্যান্ডবক্স বা সম্পূর্ণ নেটওয়ার্ক নীতি তৈরি করে না। সংবেদনশীল কাজ দেওয়ার আগে নিরীহ কাজ দিয়ে অনুমতি পরীক্ষা করুন।

## রিপোজিটরির নিয়ম ভাগ করুন

```markdown
# AGENTS.md

Use the repository's documented build and test commands.
Preserve unrelated changes.
Explain failures before changing dependencies.
Review the final diff before committing.
```

**ভাগ করা নির্দেশনা তুলনার শব্দ কমায়।** বিল্ড কমান্ড, আর্কিটেকচার সীমা ও গ্রহণযোগ্যতার মানদণ্ড একটি মূল ফাইলে রাখুন। [OpenCode-এর নিয়মের নথি](https://opencode.ai/docs/rules/) `AGENTS.md` এবং `CLAUDE.md` বিকল্প বর্ণনা করে। প্রতিটি নির্দেশনা ফাইল স্বয়ংক্রিয়ভাবে একত্রিত হয় ধরে নেবেন না।

```markdown
@AGENTS.md
```

**প্রয়োজনে এই ইমপোর্ট `CLAUDE.md`-এ রাখুন।** [Claude Code-এর মেমরি নথি](https://code.claude.com/docs/en/memory) এখন 2.1.277 সংস্করণ থেকে সরাসরি `AGENTS.md` সমর্থন বর্ণনা করে, যা সেটিংস ও নির্দেশনা ফাইলের অগ্রাধিকারের উপর নির্ভরশীল। প্রকল্প বা ঊর্ধ্বতন ডিরেক্টরির `CLAUDE.md` ডিফল্ট নির্বাচন বদলায়। সরাসরি লোডিং না থাকলে বা `CLAUDE.md` উপস্থিত থাকলে স্পষ্ট ইমপোর্ট ভাগ করা নিয়ম সমর্থন করে।

**নতুন সেশনে লোড হওয়া নির্দেশনা যাচাই করুন।** সম্পাদনার আগে প্রতিটি এজেন্টকে রিপোজিটরির বিল্ড কমান্ড ও পরিবর্তনের সীমা বলতে বলুন। ভুল উত্তর সেটআপ সমস্যার সংকেত। ব্যর্থ কাজকে মডেলের মানের প্রমাণ ধরার আগে এটি ঠিক করুন।

## গোপনীয়তা ও দলের উপযোগিতা

**স্থানীয় ইন্টারফেস স্থানীয় ইনফারেন্স প্রমাণ করে না।** সোর্স কোড, প্রম্পট, টুল আউটপুট ও সেশন ডেটা গ্রহণ করা সার্ভিসগুলো তালিকাভুক্ত করুন। স্থানীয় মডেল দূরবর্তী ইনফারেন্সের উপর নির্ভরতা কমায়। সংযুক্ত টুল, ওয়েব অনুরোধ, প্লাগইন ও শেয়ারিং ফিচারের আলাদা পর্যালোচনা দরকার।

**OpenCode-এর সোর্স পাওয়া গেলে পরীক্ষা ও কাস্টমাইজেশন সহজ হয়।** আপনার নির্বাচিত প্রদানকারী ও কনফিগারেশন মূল্যায়নের দায়িত্বও আপনার। Claude Code-এর নথিভুক্ত পরিচালিত অনুমতি নীতি ও ক্লাউড ডিপ্লয়মেন্ট পথ অ্যাক্সেস মানসম্মত করা দলের বিকল্প। কোনো সফটওয়্যার লাইসেন্স একাই প্রতিষ্ঠানের ডেটা নীতি নির্ধারণ করে না।

| দলের প্রয়োজন | মূল্যায়নের প্রশ্ন |
|---|---|
| **মডেল নির্বাচন** | কোন অনুমোদিত প্রদানকারী ও মডেল কাজ করতে হবে? |
| **ডেটা ব্যবস্থাপনা** | প্রম্পট, লগ ও টুল আউটপুট কোথায় যায়? |
| **অ্যাক্সেস নিয়ন্ত্রণ** | কে নীতি নির্ধারণ করে এবং কে বদলাতে পারে? |
| **অপারেশন** | স্থানীয় রানটাইম ও কাস্টম ইন্টিগ্রেশন কে রক্ষণাবেক্ষণ করে? |
| **রিভিউ** | ডিপেন্ডেন্সি, প্যাচ ও ডিপ্লয়মেন্ট কে অনুমোদন করে? |

## ন্যায্য পরীক্ষা চালান

**একই রিপোজিটরি রিভিশন থেকে শুরু করুন** আলাদা ফেলে দেওয়া যায় এমন ব্রাঞ্চ বা ওয়ার্কট্রিতে। একই নির্দেশনা, গ্রহণযোগ্যতা টেস্ট, সময়সীমা ও অনুমোদন নীতি ব্যবহার করুন। মডেল বা সার্ভিং সেটিং আলাদা হলে পার্থক্য লিখুন, ফলাফলকে বিচ্ছিন্ন এজেন্ট তুলনা বলবেন না।

**স্বাধীন যাচাইসহ কাজ ব্যবহার করুন।** পরিচিত পুনরুৎপাদনসহ একটি বাগ, আগে লেখা গ্রহণযোগ্যতা মানদণ্ডসহ একটি ছোট ফিচার এবং বিদ্যমান টেস্টে সুরক্ষিত একটি রিফ্যাক্টর বাছুন। এক এজেন্টকে অন্যের প্যাচ না দেখে কাজ করতে দিন। কাজ শেষে দুইটি diff রিভিউ করুন।

| মাপ | প্রতিটি প্রচেষ্টায় যা লিখবেন |
|---|---|
| **সঠিকতা** | বিদ্যমান টেস্ট ও স্বাধীন গ্রহণযোগ্যতা পরীক্ষা |
| **সময়** | শুরু থেকে রিভিউ করা ব্যবহারযোগ্য প্যাচ পর্যন্ত |
| **হস্তক্ষেপ** | ব্যাখ্যা ও ম্যানুয়াল মেরামত |
| **পরিবর্তনের পরিধি** | সম্পর্কহীন পরিবর্তন ও ডিপেন্ডেন্সি পরিবর্তন |
| **খরচ** | বিল করা ব্যবহার বা স্থানীয় সম্পদের খরচ |
| **পুনরুদ্ধার** | ব্যর্থ টেস্ট ও প্রত্যাখ্যাত কমান্ডে প্রতিক্রিয়া |

**বেছে নেওয়ার আগে পরীক্ষা পুনরাবৃত্তি করুন।** একটি সফল কাজ সাধারণ শ্রেষ্ঠত্বের দুর্বল প্রমাণ। তৈরি করা টেস্টেরও রিভিউ দরকার, কারণ এজেন্ট কখনও বাস্তবায়ন ও টেস্টে একই ভুল ধারণা পুনরাবৃত্তি করে। ব্যর্থ প্রচেষ্টার রেকর্ড রাখুন।

**গতি ও সম্পন্ন হওয়া আলাদা করুন।** দ্রুত টোকেন তৈরি টেস্ট চালানো, পুনরায় যুক্তি করা বা মানুষের রিভিউ মাপে না। স্থানীয় কনফিগারেশনে প্রাথমিক প্রম্পট প্রক্রিয়াকরণ ও ক্যাশ করা ধারাবাহিকতা আলাদা করুন। উষ্ণ সেশনে দ্রুত ধারাবাহিকতা ঠান্ডা শুরুর কর্মক্ষমতা প্রমাণ করে না।

## কোনটি বেছে নেবেন?

**OpenCode দিয়ে শুরু করুন** যদি প্রদানকারী বদলানো বা এজেন্টের সোর্স দেখা আপনার ওয়ার্কফ্লোর কেন্দ্রে থাকে। মডেল নির্বাচন, সার্ভিং সামঞ্জস্য ও ইনফারেন্স খরচ নিয়ে আপনাকে বেশি সিদ্ধান্ত নিতে হবে।

**Claude Code দিয়ে শুরু করুন** যদি Anthropic-এর সমন্বিত অভিজ্ঞতা আপনার অগ্রাধিকার হয় এবং আপনার উপযুক্ত Claude অ্যাক্সেস থাকে। আপনার দলের প্রয়োজনের সঙ্গে ইন্টারফেস, অনুমতি ও সাংগঠনিক ডিপ্লয়মেন্ট বিকল্প তুলনা করুন।

**সিদ্ধান্তটি ফেরানো যায় এমন রাখুন।** প্রকল্পের নিয়ম ও গ্রহণযোগ্যতা টেস্ট রিপোজিটরিতে রাখুন। এজেন্ট যাই হোক, diff রিভিউ করুন। নিজের কাজের পুনরাবৃত্ত ফল দেখে বাছুন, তারপর মডেল, কাজের চাপ বা বিলিং ব্যবস্থা বদলালে সিদ্ধান্ত পুনর্বিবেচনা করুন।
