**OpenCode** ਉਹਨਾਂ ਡਿਵੈਲਪਰਾਂ ਲਈ ਢੁੱਕਵਾਂ ਹੈ ਜੋ ਮਾਡਲ ਪ੍ਰੋਵਾਈਡਰਾਂ, ਏਜੰਟ ਕੌਂਫ਼ਿਗਰੇਸ਼ਨ ਅਤੇ ਲੋਕਲ ਇਨਫ਼ਰੈਂਸ ਉੱਤੇ ਕਾਬੂ ਚਾਹੁੰਦੇ ਹਨ। **Claude Code** ਉਹਨਾਂ ਡਿਵੈਲਪਰਾਂ ਲਈ ਢੁੱਕਵਾਂ ਹੈ ਜੋ Anthropic ਦਾ ਇਕੱਠਾ ਕੋਡਿੰਗ ਵਰਕਫ਼ਲੋ, ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਰਾਹੀਂ Claude ਦੀ ਪਹੁੰਚ ਅਤੇ ਦਰਜ ਕੀਤੇ ਸੰਗਠਨਾਤਮਕ ਕੰਟਰੋਲ ਚਾਹੁੰਦੇ ਹਨ। ਦੋਵੇਂ ਅਸਲੀ ਰਿਪੋਜ਼ਟਰੀਆਂ ਵਿੱਚ ਕੰਮ ਕਰਦੇ ਹਨ। ਲਾਭਦਾਇਕ ਨਤੀਜੇ ਟੂਲ ਚਲਾਉਣ, ਪ੍ਰੋਜੈਕਟ ਹਦਾਇਤਾਂ ਅਤੇ ਵੈਰੀਫ਼ਿਕੇਸ਼ਨ ਉੱਤੇ ਨਿਰਭਰ ਕਰਦੇ ਹਨ।

**ਏਜੰਟ ਅਤੇ ਮਾਡਲ ਵੱਖਰੀਆਂ ਚੋਣਾਂ ਹਨ।** ਹੋਸਟ ਕੀਤੇ Claude ਮਾਡਲ ਵਾਲੇ Claude Code ਤੋਂ ਛੋਟੇ ਲੋਕਲ ਮਾਡਲ ਵਾਲੇ OpenCode ਵੱਲ ਜਾਣ ਨਾਲ ਕਈ ਵੇਰੀਏਬਲ ਇਕੱਠੇ ਬਦਲਦੇ ਹਨ। ਨਤੀਜਿਆਂ ਦਾ ਫ਼ਰਕ ਇਹ ਸਾਬਤ ਨਹੀਂ ਕਰਦਾ ਕਿ ਕਿਹੜੀ ਏਜੰਟ ਐਪਲੀਕੇਸ਼ਨ ਬਿਹਤਰ ਹੈ।

## ਮੁੱਖ ਨੁਕਤੇ

- **ਪ੍ਰੋਵਾਈਡਰ ਲਚਕਤਾ ਲਈ OpenCode ਚੁਣੋ**, ਓਪਨ-ਸੋਰਸ ਕਸਟਮਾਈਜ਼ੇਸ਼ਨ ਅਤੇ ਹੋਸਟ ਕੀਤੇ ਜਾਂ ਲੋਕਲ ਮਾਡਲਾਂ ਨਾਲ ਪ੍ਰਯੋਗ ਲਈ।
- **Claude-ਕੇਂਦਰਿਤ ਵਰਕਫ਼ਲੋ ਲਈ Claude Code ਚੁਣੋ**, ਖ਼ਾਸ ਕਰਕੇ ਜਦੋਂ ਤੁਹਾਡੀ ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਜਾਂ ਸੰਸਥਾ ਪਹਿਲਾਂ ਹੀ ਇਸਨੂੰ ਸਹਿਯੋਗ ਦਿੰਦੀ ਹੋਵੇ।
- **ਲੋਕਲ ਐਗਜ਼ਿਕਿਊਸ਼ਨ ਨੂੰ ਸਪਸ਼ਟ ਕਰਨਾ ਲੋੜੀਂਦਾ ਹੈ।** ਟਰਮੀਨਲ ਐਪਲੀਕੇਸ਼ਨ ਹਾਲੇ ਵੀ ਪ੍ਰੌਂਪਟ ਕੌਂਫ਼ਿਗਰ ਕੀਤੀ ਇਨਫ਼ਰੈਂਸ ਸਰਵਿਸ ਨੂੰ ਭੇਜਦੀ ਹੈ।
- **ਮੁਕੰਮਲ ਕੰਮ ਦੀ ਤੁਲਨਾ ਕਰੋ**, ਜਿਸ ਵਿੱਚ ਸਮੀਖਿਆ ਸਮਾਂ ਅਤੇ ਅਸਫ਼ਲ ਕੋਸ਼ਿਸ਼ਾਂ ਸ਼ਾਮਲ ਹੋਣ, ਸਿਰਫ਼ ਟੋਕਨ ਗਤੀ ਨਹੀਂ।

**ਦਾਇਰਾ ਅਤੇ ਤਾਰੀਖ:** ਇਹ ਤੁਲਨਾ 6 ਅਕਤੂਬਰ 2026 ਦੀ ਅਧਿਕਾਰਤ ਡੌਕੂਮੈਂਟੇਸ਼ਨ ਅਤੇ ਕੀਮਤਾਂ ਦੀ ਜਾਂਚ ਕਰਦੀ ਹੈ। ਇਹ ਚੋਣ ਲਈ ਸਲਾਹ ਦਿੰਦੀ ਹੈ, ਹੱਥੋਂ ਕੀਤੇ ਪਰਫ਼ਾਰਮੈਂਸ ਬੈਂਚਮਾਰਕ ਨਹੀਂ।

**ਲੋੜਾਂ:** Git ਰਿਪੋਜ਼ਟਰੀ, ਚੱਲਣ ਵਾਲੇ ਬਿਲਡ ਅਤੇ ਟੈਸਟ ਕਮਾਂਡ, ਅਤੇ ਤੁਹਾਡੇ ਚੁਣੇ ਮਾਡਲ ਦੀ ਪਹੁੰਚ। ਇੰਸਟਾਲੇਸ਼ਨ ਤੋਂ ਬਾਅਦ ਪਹਿਲੀ ਤੁਲਨਾ ਲਈ 60–90 ਮਿੰਟ ਰੱਖੋ। ਮੁਸ਼ਕਲ ਪੱਧਰ ਦਰਮਿਆਨਾ ਹੈ।

**ਲਾਇਸੈਂਸ ਅਤੇ ਮਾਡਲ ਪਹੁੰਚ ਵੱਖਰੀਆਂ ਗੱਲਾਂ ਹਨ।** [OpenCode ਦਾ MIT ਲਾਇਸੈਂਸ](https://github.com/anomalyco/opencode/blob/dev/LICENSE) ਇਸਦੇ ਏਜੰਟ ਸੌਫ਼ਟਵੇਅਰ ਨੂੰ ਕਵਰ ਕਰਦਾ ਹੈ। ਇਹ ਹੋਸਟ ਕੀਤੇ ਮਾਡਲ ਨੂੰ ਮੁਫ਼ਤ ਨਹੀਂ ਬਣਾਉਂਦਾ। Claude Code ਦੀ ਜਨਤਕ ਰਿਪੋਜ਼ਟਰੀ ਵਿੱਚ [Anthropic ਦੀਆਂ ਲਾਇਸੈਂਸ ਸ਼ਰਤਾਂ](https://github.com/anthropics/claude-code/blob/main/LICENSE.md) ਹਨ, ਓਪਨ-ਸੋਰਸ ਲਾਇਸੈਂਸ ਨਹੀਂ।

**ਇੰਟਰਫ਼ੇਸ ਦੀ ਪਸੰਦ ਨੂੰ ਅਜ਼ਮਾਉਣਾ ਚਾਹੀਦਾ ਹੈ।** [OpenCode ਜਾਣ-ਪਛਾਣ](https://opencode.ai/docs/) ਅਤੇ [Claude Code ਝਲਕ](https://code.claude.com/docs/en/overview) ਕੰਮ ਕਰਨ ਦੇ ਕਈ ਤਰੀਕੇ ਦੱਸਦੇ ਹਨ। ਕੋਈ ਵੀ ਉਤਪਾਦ ਸਿਰਫ਼ ਟਰਮੀਨਲ ਚੈਟ ਤੱਕ ਸੀਮਿਤ ਨਹੀਂ। ਆਪਣੇ ਆਮ ਵਾਤਾਵਰਣ ਵਿੱਚ ਵੇਖੋ ਕਿ ਹਰ ਇੰਟਰਫ਼ੇਸ ਐਡਿਟ, ਰੁਕਾਵਟਾਂ ਅਤੇ ਅੰਤਿਮ diff ਕਿਵੇਂ ਦਿਖਾਉਂਦਾ ਹੈ।

## ਮਾਡਲ ਅਤੇ ਲੋਕਲ ਇਨਫ਼ਰੈਂਸ

**OpenCode ਪ੍ਰੋਵਾਈਡਰ ਕੌਂਫ਼ਿਗਰੇਸ਼ਨ ਨੂੰ ਏਜੰਟ ਇੰਟਰਫ਼ੇਸ ਤੋਂ ਵੱਖ ਕਰਦਾ ਹੈ।** ਇਸਦੀ [ਪ੍ਰੋਵਾਈਡਰ ਡੌਕੂਮੈਂਟੇਸ਼ਨ](https://opencode.ai/docs/providers/) ਕਈ ਹੋਸਟ ਕੀਤੀਆਂ ਸਰਵਿਸਾਂ ਅਤੇ ਕਸਟਮ ਅਨੁਕੂਲ endpoint ਨੂੰ ਕਵਰ ਕਰਦੀ ਹੈ। ਇਹ ਉਦੋਂ ਲਾਭਦਾਇਕ ਹੈ ਜਦੋਂ ਤੁਸੀਂ ਰੋਜ਼ਾਨਾ ਕੋਡਿੰਗ ਇੰਟਰਫ਼ੇਸ ਬਦਲੇ ਬਿਨਾਂ ਮਾਡਲ ਬਦਲਣਾ ਚਾਹੁੰਦੇ ਹੋ। ਅਨੁਕੂਲਤਾ endpoint ਵੱਲੋਂ ਮਾਡਲ ਦੇ ਟੂਲ ਕਾਲ ਅਤੇ ਰਿਕਵੈਸਟ ਫ਼ਾਰਮੈਟ ਦੀ ਸਹਾਇਤਾ ਉੱਤੇ ਨਿਰਭਰ ਕਰਦੀ ਹੈ।

**Claude Code ਕੋਲ ਕਈ ਅਧਿਕਾਰਤ ਡਿਪਲੌਇਮੈਂਟ ਰਸਤੇ ਹਨ।** Anthropic ਆਪਣੀਆਂ ਸਬਸਕ੍ਰਿਪਸ਼ਨਾਂ, API ਅਤੇ ਕਲਾਊਡ ਪਲੇਟਫ਼ਾਰਮ ਇੰਟੀਗ੍ਰੇਸ਼ਨ ਨੂੰ [ਥਰਡ-ਪਾਰਟੀ ਡਿਪਲੌਇਮੈਂਟ ਗਾਈਡ](https://code.claude.com/docs/en/third-party-integrations) ਵਿੱਚ ਦਰਜ ਕਰਦਾ ਹੈ। ਇਹ ਰਸਤੇ ਪ੍ਰਮਾਣਿਕਤਾ, ਬਿਲਿੰਗ ਅਤੇ ਇਨਫ਼ਰਾਸਟਰੱਕਚਰ ਲੋੜਾਂ ਨੂੰ ਸੰਭਾਲਦੇ ਹਨ। ਇਹ ਕਿਸੇ ਵੀ ਮਨਮਾਨੇ gateway ਪਿੱਛੇ ਮਾਡਲ ਨੂੰ ਸਹਿਯੋਗੀ Claude ਡਿਪਲੌਇਮੈਂਟ ਦੇ ਬਰਾਬਰ ਨਹੀਂ ਬਣਾਉਂਦੇ।

```bash
ollama launch claude
```

**Ollama ਇਸ Claude Code ਇੰਟੀਗ੍ਰੇਸ਼ਨ ਨੂੰ** ਆਪਣੇ [ਸੈਟਅਪ ਗਾਈਡ](https://docs.ollama.com/integrations/claude-code) ਵਿੱਚ ਦਰਜ ਕਰਦਾ ਹੈ। ਲੋਕਲ ਤੌਰ ਉੱਤੇ ਸਰਵ ਕੀਤਾ ਅਨੁਕੂਲ ਮਾਡਲ ਇਨਫ਼ਰੈਂਸ ਦਿੰਦਾ ਹੈ ਅਤੇ Claude Code ਏਜੰਟ ਇੰਟਰਫ਼ੇਸ ਦਿੰਦਾ ਹੈ। ਇਹ Claude ਦੇ ਮਲਕੀਅਤੀ ਮਾਡਲ ਵਜ਼ਨਾਂ ਨੂੰ ਲੋਕਲ ਨਹੀਂ ਚਲਾਉਂਦਾ। Ollama ਕਲਾਊਡ ਮਾਡਲ ਵੀ ਦਿੰਦਾ ਹੈ। ਸੈਟਅਪ ਨੂੰ ਲੋਕਲ ਕਹਿਣ ਤੋਂ ਪਹਿਲਾਂ ਚੁਣਿਆ ਮਾਡਲ ਅਤੇ ਮੰਜ਼ਿਲ ਜਾਂਚੋ।

**ਅਨੁਭਵ ਤਿੰਨ ਪਰਤਾਂ ਤੈਅ ਕਰਦੀਆਂ ਹਨ:** ਏਜੰਟ ਟੂਲ ਵਰਤਣ ਦਾ ਤਰੀਕਾ ਚੁਣਦਾ ਹੈ, ਮਾਡਲ ਤਰਕ ਅਤੇ ਟੂਲ ਰਿਕਵੈਸਟ ਬਣਾਉਂਦਾ ਹੈ, ਅਤੇ ਇਨਫ਼ਰੈਂਸ ਸਰਵਿਸ ਸਰਵਿੰਗ ਵਿਹਾਰ ਤੈਅ ਕਰਦੀ ਹੈ। ਜਦੋਂ ਇੰਟੀਗ੍ਰੇਸ਼ਨ ਸਹਾਇਤਾ ਕਰਦੀ ਹੋਵੇ ਤਾਂ ਲੋਕਲ ਅਤੇ ਹੋਸਟ ਕੀਤੀਆਂ ਸਰਵਿਸਾਂ ਦੋਵੇਂ ਇੰਟਰਫ਼ੇਸਾਂ ਦੇ ਪਿੱਛੇ ਕੰਮ ਕਰਦੀਆਂ ਹਨ। ਚਿੱਤਰ ਇਨ੍ਹਾਂ ਪਰਤਾਂ ਨੂੰ ਵੱਖ ਕਰਦਾ ਹੈ ਅਤੇ ਫ਼ੀਚਰ ਸਹਾਇਤਾ ਇਕੋ ਜਿਹੀ ਹੋਣ ਦਾ ਦਾਅਵਾ ਨਹੀਂ ਕਰਦਾ।

## ਕੀਮਤ ਅਤੇ ਚਲਾਉਣ ਦੇ ਖ਼ਰਚੇ

**ਕੀਮਤਾਂ ਇੱਕ ਤਾਰੀਖ ਦੀ ਤਸਵੀਰ ਹਨ**, ਬਰਾਬਰ ਕੰਪਿਊਟ ਵੰਡ ਨਹੀਂ। [Claude ਕੀਮਤ ਪੰਨਾ](https://claude.com/pricing) Pro ਅਤੇ Max ਪਹੁੰਚ ਦਿਖਾਉਂਦਾ ਹੈ, ਜਦਕਿ ਵਰਤੋਂ ਸੀਮਾਵਾਂ ਅਤੇ ਟੈਕਸ ਵੱਖ ਹਨ। OpenCode Go ਅਤੇ Claude ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਵੱਖਰੇ ਮਾਡਲ ਅਤੇ ਹੱਦਾਂ ਕਵਰ ਕਰਦੇ ਹਨ। ਘੱਟ ਮਹੀਨਾਵਾਰ ਕੀਮਤ ਇਕੱਲੀ ਤੁਹਾਡੇ ਵਰਕਲੋਡ ਲਈ ਸਸਤਾ ਰਸਤਾ ਨਹੀਂ ਦੱਸਦੀ।

**ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਪਹੁੰਚ ਅਤੇ API ਬਿਲਿੰਗ ਵੱਖ ਹਨ।** [Claude Code ਖ਼ਰਚਾ ਡੌਕੂਮੈਂਟੇਸ਼ਨ](https://code.claude.com/docs/en/costs) ਵਰਤੋਂ ਟ੍ਰੈਕਿੰਗ ਅਤੇ API ਖ਼ਰਚੇ ਸਮਝਾਉਂਦੀ ਹੈ। ਲੰਮੀ ਸੈਸ਼ਨ ਤੋਂ ਪਹਿਲਾਂ ਸਰਗਰਮ ਪ੍ਰਮਾਣਿਕਤਾ ਰਸਤਾ ਜਾਂਚੋ। ਪ੍ਰੋਵਾਈਡਰ API ਕੁੰਜੀ ਨੂੰ ਵੱਖਰਾ ਬਿਲਿੰਗ ਫ਼ੈਸਲਾ ਸਮਝੋ। ਇਹ ਨਾ ਮੰਨੋ ਕਿ ਮੌਜੂਦਾ ਖਪਤਕਾਰ ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਇਸਦਾ ਭੁਗਤਾਨ ਕਰਦੀ ਹੈ।

## ਪਲਾਨਿੰਗ ਅਤੇ ਇਜਾਜ਼ਤਾਂ

**OpenCode ਦੇ ਬਿਲਟ-ਇਨ ਏਜੰਟ ਪਲਾਨਿੰਗ ਨੂੰ ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ ਤੋਂ ਵੱਖ ਕਰਦੇ ਹਨ।** ਇਸਦੀ [ਏਜੰਟ ਡੌਕੂਮੈਂਟੇਸ਼ਨ](https://opencode.ai/docs/agents/) Plan ਅਤੇ Build ਅਤੇ ਕੌਂਫ਼ਿਗਰ ਕੀਤੇ ਜਾ ਸਕਣ ਵਾਲੇ ਵਿਸ਼ੇਸ਼ ਏਜੰਟ ਦੱਸਦੀ ਹੈ। ਹਰ ਏਜੰਟ ਲਈ ਮਾਡਲ ਅਤੇ ਟੂਲ ਸੈਟਿੰਗਾਂ ਖੋਜ ਅਤੇ ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ ਲਈ ਵੱਖਰੇ ਮਾਡਲ ਵਰਤਣ ਵਰਗੇ ਪ੍ਰਯੋਗ ਸਹਾਇਕ ਹਨ। ਨਤੀਜੇ ਤੁਲਨਾ ਕਰਦੇ ਸਮੇਂ ਇਹ ਚੋਣਾਂ ਲਿਖੋ।

```json
{
  "permission": {
    "edit": "ask",
    "bash": "ask"
  }
}
```

**OpenCode ਲਈ ਇਹ ਭਾਗ `opencode.json` ਵਿੱਚ ਮਿਲਾਓ**, ਜੇ ਤੁਸੀਂ ਐਡਿਟ ਅਤੇ ਸ਼ੈਲ ਕਮਾਂਡਾਂ ਲਈ ਮਨਜ਼ੂਰੀ ਮੰਗਣਾ ਚਾਹੁੰਦੇ ਹੋ। [ਇਜਾਜ਼ਤ ਰੈਫ਼ਰੈਂਸ](https://opencode.ai/docs/permissions/) allow, ask ਅਤੇ deny ਵਿਹਾਰ ਦੱਸਦੀ ਹੈ। ਭਾਗ ਜੋੜਨ ਤੋਂ ਪਹਿਲਾਂ ਮੌਜੂਦਾ ਨਿਯਮ ਜਾਂਚੋ, ਖ਼ਾਸ ਕਰਕੇ ਸੰਗਠਨਾਤਮਕ ਕੌਂਫ਼ਿਗਰੇਸ਼ਨ ਵਾਲੀ ਰਿਪੋਜ਼ਟਰੀ ਵਿੱਚ।

```json
{
  "permissions": {
    "defaultMode": "plan"
  }
}
```

**Claude Code ਲਈ ਇਹ ਭਾਗ `.claude/settings.json` ਵਿੱਚ ਮਿਲਾਓ**, ਤਾਂ ਜੋ ਸ਼ੁਰੂਆਤ Plan ਮੋਡ ਵਿੱਚ ਹੋਵੇ। ਇਸਦੀ [ਇਜਾਜ਼ਤ ਡੌਕੂਮੈਂਟੇਸ਼ਨ](https://code.claude.com/docs/en/permissions) ਪਲਾਨਿੰਗ, ਐਡਿਟ ਸਵੀਕਾਰਨਾ, ਆਟੋਮੈਟਿਕ ਇਜਾਜ਼ਤ ਫ਼ੈਸਲੇ ਅਤੇ ਹੋਰ ਮੋਡ ਵੱਖ ਕਰਦੀ ਹੈ। ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ ਲਈ ਤਿਆਰ ਹੋਣ ਉੱਤੇ ਮੋਡ ਸੋਚ ਸਮਝ ਕੇ ਬਦਲੋ।

**ਇਨ੍ਹਾਂ ਉਦਾਹਰਣਾਂ ਦੇ ਮਕਸਦ ਵੱਖਰੇ ਹਨ।** OpenCode ਭਾਗ ਦੋ ਟੂਲ ਸ਼੍ਰੇਣੀਆਂ ਲਈ ਮਨਜ਼ੂਰੀ ਮੰਗਦਾ ਹੈ। Claude Code ਭਾਗ ਪਲਾਨਿੰਗ ਵਰਕਫ਼ਲੋ ਸ਼ੁਰੂ ਕਰਦਾ ਹੈ। ਕੋਈ ਵੀ ਭਾਗ ਓਪਰੇਟਿੰਗ ਸਿਸਟਮ ਸੈਂਡਬਾਕਸ ਜਾਂ ਪੂਰੀ ਨੈੱਟਵਰਕ ਨੀਤੀ ਨਹੀਂ ਬਣਾਉਂਦਾ। ਸੰਵੇਦਨਸ਼ੀਲ ਕੰਮ ਦੇਣ ਤੋਂ ਪਹਿਲਾਂ ਸੁਰੱਖਿਅਤ ਕਾਰਵਾਈਆਂ ਨਾਲ ਇਜਾਜ਼ਤ ਵਿਹਾਰ ਜਾਂਚੋ।

## ਆਪਣੀ ਰਿਪੋਜ਼ਟਰੀ ਦੇ ਨਿਯਮ ਸਾਂਝੇ ਕਰੋ

```markdown
# AGENTS.md

Use the repository's documented build and test commands.
Preserve unrelated changes.
Explain failures before changing dependencies.
Review the final diff before committing.
```

**ਸਾਂਝੀਆਂ ਹਦਾਇਤਾਂ ਤੁਲਨਾ ਦਾ ਸ਼ੋਰ ਘਟਾਉਂਦੀਆਂ ਹਨ।** ਬਿਲਡ ਕਮਾਂਡ, ਆਰਕੀਟੈਕਚਰ ਸੀਮਾਵਾਂ ਅਤੇ ਸਵੀਕ੍ਰਿਤੀ ਮਾਪਦੰਡ ਇੱਕ ਕੈਨੋਨੀਕਲ ਫ਼ਾਈਲ ਵਿੱਚ ਰੱਖੋ। OpenCode ਦੀ [ਨਿਯਮ ਡੌਕੂਮੈਂਟੇਸ਼ਨ](https://opencode.ai/docs/rules/) `AGENTS.md` ਅਤੇ `CLAUDE.md` fallback ਦੱਸਦੀ ਹੈ। ਇਹ ਨਾ ਮੰਨੋ ਕਿ ਹਰ ਹਦਾਇਤ ਫ਼ਾਈਲ ਆਪਣੇ ਆਪ ਜੋੜੀ ਜਾਂਦੀ ਹੈ।

```markdown
@AGENTS.md
```

**ਲੋੜ ਪੈਣ ਉੱਤੇ ਇਹ ਇੰਪੋਰਟ `CLAUDE.md` ਵਿੱਚ ਰੱਖੋ।** Claude Code ਦੀ [ਮੈਮੋਰੀ ਡੌਕੂਮੈਂਟੇਸ਼ਨ](https://code.claude.com/docs/en/memory) ਵਰਜਨ 2.1.277 ਤੋਂ `AGENTS.md` ਦੀ ਸਿੱਧੀ ਸਹਾਇਤਾ ਦੱਸਦੀ ਹੈ। ਇਹ ਸੈਟਿੰਗਾਂ ਅਤੇ ਹਦਾਇਤ ਫ਼ਾਈਲਾਂ ਦੀ ਤਰਜੀਹ ਉੱਤੇ ਨਿਰਭਰ ਹੈ। ਪ੍ਰੋਜੈਕਟ ਜਾਂ ਮਾਪੇ ਦੀ `CLAUDE.md` ਡਿਫ਼ਾਲਟ ਚੋਣ ਬਦਲਦੀ ਹੈ। ਸਪਸ਼ਟ ਇੰਪੋਰਟ ਸਾਂਝੇ ਨਿਯਮ ਚਲਾਉਂਦਾ ਹੈ ਜਦੋਂ `CLAUDE.md` ਮੌਜੂਦ ਹੋਵੇ ਜਾਂ ਸਿੱਧੀ ਲੋਡਿੰਗ ਉਪਲਬਧ ਨਾ ਹੋਵੇ।

**ਨਵੀਂ ਸੈਸ਼ਨ ਵਿੱਚ ਲੋਡ ਕੀਤੀਆਂ ਹਦਾਇਤਾਂ ਦੀ ਜਾਂਚ ਕਰੋ।** ਐਡਿਟ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਹਰ ਏਜੰਟ ਨੂੰ ਰਿਪੋਜ਼ਟਰੀ ਦੀ ਬਿਲਡ ਕਮਾਂਡ ਅਤੇ ਬਦਲਾਅ ਸੀਮਾਵਾਂ ਦੱਸਣ ਲਈ ਕਹੋ। ਗਲਤ ਜਵਾਬ ਸੈਟਅਪ ਸਮੱਸਿਆ ਦਿਖਾਉਂਦਾ ਹੈ। ਅਸਫ਼ਲ ਕੰਮ ਨੂੰ ਮਾਡਲ ਗੁਣਵੱਤਾ ਦਾ ਸਬੂਤ ਮੰਨਣ ਤੋਂ ਪਹਿਲਾਂ ਸਮੱਸਿਆ ਠੀਕ ਕਰੋ।

## ਨਿਰਪੱਖ ਟ੍ਰਾਇਲ ਚਲਾਓ

**ਇੱਕੋ ਰਿਪੋਜ਼ਟਰੀ ਰਿਵਿਜ਼ਨ ਤੋਂ ਸ਼ੁਰੂ ਕਰੋ** ਅਤੇ ਵੱਖਰੀਆਂ ਅਸਥਾਈ ਬ੍ਰਾਂਚਾਂ ਜਾਂ worktree ਵਰਤੋ। ਇੱਕੋ ਹਦਾਇਤਾਂ, ਸਵੀਕ੍ਰਿਤੀ ਟੈਸਟ, ਸਮਾਂ ਸੀਮਾ ਅਤੇ ਮਨਜ਼ੂਰੀ ਨੀਤੀ ਵਰਤੋ। ਜੇ ਮਾਡਲ ਜਾਂ ਸਰਵਿੰਗ ਸੈਟਿੰਗਾਂ ਵੱਖਰੀਆਂ ਹੋਣ ਤਾਂ ਫ਼ਰਕ ਦਰਜ ਕਰੋ, ਨਤੀਜੇ ਨੂੰ ਇਕੱਲੀ ਏਜੰਟ ਤੁਲਨਾ ਨਾ ਕਹੋ।

**ਸੁਤੰਤਰ ਜਾਂਚਾਂ ਵਾਲੇ ਕੰਮ ਵਰਤੋ।** ਜਾਣੀ ਹੋਈ ਰੀਪ੍ਰੋਡਕਸ਼ਨ ਵਾਲਾ ਬੱਗ, ਪਹਿਲਾਂ ਲਿਖੇ ਸਵੀਕ੍ਰਿਤੀ ਮਾਪਦੰਡਾਂ ਵਾਲਾ ਛੋਟਾ ਫ਼ੀਚਰ ਅਤੇ ਮੌਜੂਦਾ ਟੈਸਟਾਂ ਨਾਲ ਸੁਰੱਖਿਅਤ ਰੀਫ਼ੈਕਟਰ ਚੁਣੋ। ਹਰ ਏਜੰਟ ਨੂੰ ਦੂਜੇ ਦਾ ਪੈਚ ਵੇਖਣ ਤੋਂ ਬਿਨਾਂ ਕੰਮ ਕਰਨ ਦਿਓ। ਕੰਮ ਮੁਕਣ ਤੋਂ ਬਾਅਦ ਦੋਵੇਂ diff ਦੀ ਸਮੀਖਿਆ ਕਰੋ।

| ਮਾਪ | ਹਰ ਕੋਸ਼ਿਸ਼ ਲਈ ਦਰਜ ਕਰੋ |
|---|---|
| **ਸਹੀਪਣ** | ਮੌਜੂਦਾ ਟੈਸਟ ਅਤੇ ਸੁਤੰਤਰ ਸਵੀਕ੍ਰਿਤੀ ਜਾਂਚਾਂ |
| **ਸਮਾਂ** | ਸ਼ੁਰੂਆਤ ਤੋਂ ਸਮੀਖਿਆ ਕੀਤੇ ਵਰਤਣਯੋਗ ਪੈਚ ਤੱਕ |
| **ਦਖ਼ਲ** | ਸਪਸ਼ਟੀਕਰਨ ਅਤੇ ਹੱਥੋਂ ਕੀਤੀਆਂ ਮੁਰੰਮਤਾਂ |
| **ਬਦਲਾਅ ਦਾ ਦਾਇਰਾ** | ਗੈਰ-ਸੰਬੰਧਿਤ ਐਡਿਟ ਅਤੇ ਡਿਪੈਂਡੈਂਸੀ ਬਦਲਾਅ |
| **ਲਾਗਤ** | ਬਿਲ ਕੀਤਾ ਵਰਤੋਂ ਖ਼ਰਚ ਜਾਂ ਲੋਕਲ ਸਰੋਤ ਲਾਗਤ |
| **ਰਿਕਵਰੀ** | ਅਸਫ਼ਲ ਟੈਸਟ ਅਤੇ ਰੱਦ ਕਮਾਂਡਾਂ ਉੱਤੇ ਪ੍ਰਤੀਕਿਰਿਆ |

**ਚੋਣ ਤੋਂ ਪਹਿਲਾਂ ਟ੍ਰਾਇਲ ਦੁਹਰਾਓ।** ਇੱਕ ਸਫ਼ਲ ਕੰਮ ਵਿਆਪਕ ਬਿਹਤਰੀ ਦਾ ਕਮਜ਼ੋਰ ਸਬੂਤ ਹੈ। ਬਣਾਏ ਗਏ ਟੈਸਟਾਂ ਦੀ ਵੀ ਸਮੀਖਿਆ ਕਰੋ, ਕਿਉਂਕਿ ਏਜੰਟ ਕਈ ਵਾਰ ਇੰਪਲੀਮੈਂਟੇਸ਼ਨ ਅਤੇ ਟੈਸਟਾਂ ਵਿੱਚ ਇੱਕੋ ਗਲਤ ਧਾਰਨਾ ਦੁਹਰਾਉਂਦਾ ਹੈ। ਅਸਫ਼ਲ ਕੋਸ਼ਿਸ਼ਾਂ ਦਾ ਰਿਕਾਰਡ ਰੱਖੋ।

**ਗਤੀ ਅਤੇ ਮੁਕੰਮਲਤਾ ਨੂੰ ਵੱਖ ਰੱਖੋ।** ਤੇਜ਼ ਟੋਕਨ ਉਤਪਾਦਨ ਟੈਸਟ ਚਲਾਉਣ, ਮੁੜ ਤਰਕ ਕਰਨ ਜਾਂ ਮਨੁੱਖੀ ਸਮੀਖਿਆ ਨੂੰ ਨਹੀਂ ਮਾਪਦਾ। ਲੋਕਲ ਕੌਂਫ਼ਿਗਰੇਸ਼ਨ ਲਈ ਸ਼ੁਰੂਆਤੀ ਪ੍ਰੌਂਪਟ ਪ੍ਰੋਸੈਸਿੰਗ ਨੂੰ ਕੈਸ਼ ਕੀਤੀ continuation ਤੋਂ ਵੱਖ ਕਰੋ। ਗਰਮ ਸੈਸ਼ਨ ਵਿੱਚ ਤੇਜ਼ continuation cold-start ਪਰਫ਼ਾਰਮੈਂਸ ਸਾਬਤ ਨਹੀਂ ਕਰਦੀ।

## ਤੁਹਾਨੂੰ ਕਿਹੜਾ ਚੁਣਨਾ ਚਾਹੀਦਾ ਹੈ?

**OpenCode ਤੋਂ ਸ਼ੁਰੂ ਕਰੋ** ਜੇ ਪ੍ਰੋਵਾਈਡਰ ਬਦਲਣਾ ਜਾਂ ਏਜੰਟ ਦਾ ਸਰੋਤ ਦੇਖਣਾ ਤੁਹਾਡੇ ਵਰਕਫ਼ਲੋ ਦਾ ਕੇਂਦਰ ਹੈ। ਮਾਡਲ ਚੋਣ, ਸਰਵਿੰਗ ਅਨੁਕੂਲਤਾ ਅਤੇ ਇਨਫ਼ਰੈਂਸ ਖ਼ਰਚਿਆਂ ਬਾਰੇ ਹੋਰ ਫ਼ੈਸਲੇ ਤੁਹਾਨੂੰ ਸੰਭਾਲਣੇ ਪੈਣਗੇ।

**Claude Code ਤੋਂ ਸ਼ੁਰੂ ਕਰੋ** ਜੇ ਤੁਹਾਡੀ ਤਰਜੀਹ Anthropic ਦਾ ਇਕੱਠਾ ਅਨੁਭਵ ਹੈ ਅਤੇ ਤੁਹਾਡੇ ਕੋਲ ਢੁੱਕਵੀਂ Claude ਪਹੁੰਚ ਹੈ। ਇਸਦੇ ਇੰਟਰਫ਼ੇਸ, ਇਜਾਜ਼ਤਾਂ ਅਤੇ ਸੰਗਠਨਾਤਮਕ ਡਿਪਲੌਇਮੈਂਟ ਵਿਕਲਪਾਂ ਨੂੰ ਟੀਮ ਦੀਆਂ ਲੋੜਾਂ ਨਾਲ ਮਿਲਾਓ।

**ਫ਼ੈਸਲਾ ਵਾਪਸ ਬਦਲਣਯੋਗ ਰੱਖੋ।** ਪ੍ਰੋਜੈਕਟ ਨਿਯਮ ਅਤੇ ਸਵੀਕ੍ਰਿਤੀ ਟੈਸਟ ਰਿਪੋਜ਼ਟਰੀ ਵਿੱਚ ਰੱਖੋ। ਏਜੰਟ ਕੋਈ ਵੀ ਹੋਵੇ, diff ਦੀ ਸਮੀਖਿਆ ਕਰੋ। ਆਪਣੇ ਕੰਮਾਂ ਦੇ ਦੁਹਰਾਏ ਨਤੀਜਿਆਂ ਨਾਲ ਚੋਣ ਕਰੋ। ਮਾਡਲ, ਵਰਕਲੋਡ ਜਾਂ ਬਿਲਿੰਗ ਬਦਲਣ ਉੱਤੇ ਫ਼ੈਸਲੇ ਦੀ ਮੁੜ ਜਾਂਚ ਕਰੋ।

**ਅਗਲੇ ਕਦਮ:** [ਲੋਕਲ OpenCode ਅਤੇ Strata ਗਾਈਡ](/articles/strata-opencode-local-coding-agent-16gb/) ਇੱਕ ਰਿਪੋਰਟ ਕੀਤੇ ਖਪਤਕਾਰ GPU ਸੈਟਅਪ ਦੀ ਜਾਂਚ ਕਰਦੀ ਹੈ। [OpenRouter ਪ੍ਰੋਵਾਈਡਰ ਤੁਲਨਾ](/articles/openrouter-provider-routing-quality-cost/) ਦੱਸਦੀ ਹੈ ਕਿ ਸਰਵਿੰਗ endpoint ਕਾਂਟੈਕਸਟ, ਪੈਰਾਮੀਟਰ ਅਤੇ ਲਾਗਤ ਨੂੰ ਕਿਉਂ ਪ੍ਰਭਾਵਿਤ ਕਰਦੇ ਹਨ, ਭਾਵੇਂ ਮਾਡਲ ਦਾ ਨਾਮ ਉਹੀ ਰਹੇ।
