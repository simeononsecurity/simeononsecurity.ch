**只有在核查了适合该任务的证据后，才接受 AI 结果。** 润色完善的说明、已配置的工具和绿色测试提示回答的是不同问题。本课将为工作坊实验创建一份统一的审查记录。

**学习目标：**你将为来源、文件范围、测试、隐私和用量制作验收记录。

## 重点

- **来源核查：**将事实声明与当前权威记录进行比较。
- **范围核查：**检查哪些文件或系统发生了更改。
- **行为核查：**运行测试和相关的手动案例。
- **隐私核查：**检查工具或供应商收到了哪些材料。
- **用量核查：**记录令牌、工具调用以及用于计算成本的费率。

## 开始之前

**准备条件：**课程实验、`docs/requirements.md`、本地 Git 快照，以及 [MCP 课程](/articles/effective-ai-mcp-server-setup/)或其浏览器替代方案。预留 40 分钟。难度为中级。使用你在第一个编码代理任务中编辑过的实验副本。如果跳过了编辑，请重新解压一份，并将功能检查标记为尚未实现。未修改的基线仍能通过原有的两项测试。

## 核查事实声明

**声明：**“获准的状态值为 `open` 和 `pending`。”打开第 1 版 `docs/requirements.md`。文件规定的是 `open` 和 `done`。该声明不成立。自信的语气不会改变需求。

**对于产品声明，**请使用最新的官方文档，并记录页面标题和审查日期。菜单、套餐、命令或上下文限制方面的信息，比一般工作流原则更容易过时。[Codex 文档](https://learn.chatgpt.com/docs/codex/cli)、[Claude Code 文档](https://code.claude.com/docs/en/overview)和 [OpenCode 文档](https://opencode.ai/docs/)介绍了各自当前的界面。

| 声明 | 来源 | 决定 |
|---|---|---|
| **`open` 和 `pending`** | 实验要求，第 1 版 | 拒绝，将 `pending` 替换为 `done` |
| **无筛选计数为 4** | 基线程序和四条 JSON 记录 | 运行程序进行核查 |
| **发生过 MCP 读取** | 会话工具记录 | 仅当记录中显示工具调用时接受 |

## 检查更改

**对于编码任务，**使用 Git 列出已更改文件并查看实际差异。新建的未跟踪文件会出现在状态中，但不会出现在普通差异里，因此两者都要检查。

```bash
git status --short
git diff -- task_report.py tests
```

**预期范围：**筛选任务完成后，只有 `task_report.py` 和针对性测试发生变化。对 `tasks.json`、`docs/requirements.md` 或隐藏配置文件的更改需要说明并单独审查。如果你没有执行编辑，则不应有任何更改。

## 测试行为

**在解压后的实验目录中运行相同的基线和功能检查。**代理的完成报告应列出这些检查观察到的结果。

```bash
python3 -m unittest discover -s tests -v
python3 task_report.py tasks.json
python3 task_report.py tasks.json --status open
python3 task_report.py tasks.json --status done
python3 task_report.py tasks.json --status invalid
```

**在编辑后的副本中，**测试应覆盖新案例，计数结果为 4、2、2，输入无效值时应清楚报错并返回非零退出码。在新解压的起始副本中，只有两项基线测试通过，总数为 4。单独记录这一初始状态。

**功能测试失败时要诊断原因。**如果 `open` 输出 4，请检查筛选参数是否传入计数函数，以及程序是否比较任务的 `status` 字段。不要仅因代理声称实现完成，就把失败的测试说成通过。

## 检查隐私和访问

**记录代理收到的文件。**实验使用合成数据，不含机密。真实项目可能包含凭据、客户记录或私人文档。分享输出前，检查提示词、日志、屏幕截图和差异，确认其中没有这类信息。

**本地测试只能证明本地行为。**它无法证明云账户权限、MCP 服务器范围或已部署服务的行为。在相关环境中测试每一道边界。

## 记录用量和成本

**令牌用于衡量模型输入和输出的数量。**不同产品的仪表板有所差异，因此使用供应商显示的用量数据。必要时单独记录工具调用以及图像或托管环境费用。计算真实账单前，先核对当前费率。

**打开执行任务的账户用量页面。**记录显示的输入和输出令牌数、模型、计费周期，以及任何缓存输入类别。对于 ChatGPT 或 Claude 订阅，用量上限或额度不等于某项任务的 API 费用。通过 API 或供应商运行 OpenCode 时，查看该供应商的用量或账单以及当前费率。如果产品不显示每项任务的令牌数，请写“不可用”，不要根据对话长度推算费用。

**示例计算，不代表供应商价格：**每百万输入令牌 1 美元时，30,000 个输入令牌费用为 0.03 美元。每百万输出令牌 5 美元时，5,000 个输出令牌费用为 0.025 美元。本例的模型费用合计为 0.055 美元，尚未计入工具或托管费用。

```text
输入成本 = 输入令牌 / 1,000,000 × 输入费率
输出成本 = 输出令牌 / 1,000,000 × 输出费率
总计 = 输入成本 + 输出成本 + 单独的工具费用
```

**工作者任务也会消耗令牌。**委派会将详细输出移出主对话，但不会让工作变成免费。比较成本与独立核查带来的价值。

**分开记录不同费用类别。**缓存输入、新输入、输出、工具调用和托管执行可能采用不同费率。本例只使用新输入和输出费率，不涉及订阅账单或工具费用。

## 保留验收记录

| 字段 | 编辑后的填写示例 |
|---|---|
| **来源** | 已阅读第 1 版 `docs/requirements.md` |
| **已更改文件** | `git status --short` 中的 `task_report.py` 和 `tests/test_task_report.py` |
| **测试** | 基线测试和新增筛选测试通过，记录观察到的计数 |
| **手动输出** | 观察到 `Total tasks: 4`、`2` 和 `2`，无效值被拒绝 |
| **功能状态** | 已实现 `--status open` 和 `--status done` |
| **隐私** | 仅含合成文件 |
| **用量** | 如果可用，记录供应商显示的数据 |
| **决定** | 只有来源、差异、测试和隐私检查全部通过后才接受 |

**你的交付物：**复制这份记录，并在自己运行后填写。只有在亲眼看到输出后，才将“观察到”替换为具体结果。所有必要检查通过时选择“接受”，修复范围明确时选择“修改”，来源、范围或访问权限不明确时选择“停止”。

## 检查理解情况

1. **问题：**起始基线通过能证明所需功能已经存在吗？**答案：**不能。编辑后要测试新的验收行为。

2. **问题：**验收记录应包括什么？**答案：**来源证据、已更改文件、行为检查、访问范围和观察到的用量。

## 故障排除

- **声明没有来源：**标记为未验证，并查找权威记录。
- **测试通过但输出不同：**增加一个手动案例并检查数据。
- **缺少用量数据：**记录“不可用”，不要估算实际费用。
- **差异中含私人数据：**停止分享输出，并从练习记录中删除这些数据。
