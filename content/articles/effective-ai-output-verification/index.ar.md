**لا تقبل نتيجة الذكاء الاصطناعي إلا بعد فحص الأدلة المناسبة للمهمة.** يجيب الشرح المصقول والأداة المهيأة وشريط الاختبارات الأخضر عن أسئلة مختلفة. ينشئ هذا الدرس سجل مراجعة واحدًا لمختبر الورشة.

**هدف التعلّم:** ستعد سجل قبول للمصادر ونطاق الملفات والاختبارات والخصوصية والاستخدام.

## أهم النقاط

- **فحص المصدر:** قارن الادعاء الواقعي بسجل موثوق وحديث.
- **فحص النطاق:** افحص الملفات أو الأنظمة التي تغيرت.
- **فحص السلوك:** شغّل الاختبارات والحالات اليدوية ذات الصلة.
- **فحص الخصوصية:** افحص المواد التي وصلت إلى الأداة أو المزوّد.
- **فحص الاستخدام:** سجّل الرموز واستدعاءات الأدوات والسعر المستخدم لحساب التكلفة.

## قبل البدء

**المتطلبات:** مختبر الدورة، و`docs/requirements.md`، ولقطة Git محلية، و[درس MCP](/articles/effective-ai-mcp-server-setup/) أو بديله في المتصفح. خصص 40 دقيقة. مستوى الصعوبة متوسط. استخدم المختبر الذي عدّلته في أول مهمة لوكيل البرمجة. إذا تخطيت التعديل، فاستخدم نسخة استخراج جديدة وسجّل أن فحوص الميزات غير منفذة. لا تزال النسخة الأساسية غير المعدّلة تجتاز اختباريها الأصليين.

## تحقق من ادعاء واقعي

**الادعاء:** «قيم الحالة المعتمدة هي `open` و`pending`». افتح `docs/requirements.md`، المراجعة 1. يذكر الملف `open` و`done`. الادعاء خاطئ. النبرة الواثقة لا تغيّر المتطلب.

**بالنسبة إلى ادعاءات المنتجات،** استخدم الوثائق الرسمية الحالية وسجّل عنوان الصفحة وتاريخ المراجعة. تصبح المعلومات المتعلقة بقائمة أو خطة أو أمر أو حد للسياق قديمة أسرع من مبادئ سير العمل العامة. تعرض [وثائق Codex](https://learn.chatgpt.com/docs/codex/cli) و[وثائق Claude Code](https://code.claude.com/docs/en/overview) و[وثائق OpenCode](https://opencode.ai/docs/) واجهاتها الحالية.

| الادعاء | المصدر | القرار |
|---|---|---|
| **`open` و`pending`** | متطلب المختبر، المراجعة 1 | ارفضه واستبدل `pending` بـ `done` |
| **العدد بلا مرشح هو 4** | البرنامج الأساسي وأربعة سجلات JSON | تحقق بتشغيل البرنامج |
| **حدثت قراءة عبر MCP** | سجل أدوات الجلسة | اقبلها فقط إذا ظهر استدعاء الأداة |

## افحص التغيير

**في مهمة برمجية،** استخدم Git لسرد الملفات المتغيرة وقراءة الفارق الفعلي. يظهر الملف الجديد غير المتعقب في الحالة حتى إن لم يظهر في الفارق المعتاد، لذا افحص الأمرين.

```bash
git status --short
git diff -- task_report.py tests
```

**النطاق المتوقع:** بعد مهمة التصفية، لا يتغير سوى `task_report.py` والاختبارات المحددة. يحتاج أي تغيير في `tasks.json` أو `docs/requirements.md` أو ملف إعداد مخفي إلى تفسير ومراجعة منفصلة. إذا لم تنفذ تعديلًا، فلا تتوقع تغييرات.

## اختبر السلوك

**شغّل فحوص الأساس والميزات نفسها** من مجلد المختبر المستخرج. يجب أن يذكر تقرير إكمال الوكيل النتائج التي لوحظت لهذه الفحوص.

```bash
python3 -m unittest discover -s tests -v
python3 task_report.py tasks.json
python3 task_report.py tasks.json --status open
python3 task_report.py tasks.json --status done
python3 task_report.py tasks.json --status invalid
```

**في النسخة المعدّلة،** تغطي الاختبارات الحالات الجديدة، وتكون الأعداد 4 و2 و2، أما القيمة غير الصالحة فتنتج خطأً واضحًا ورمز خروج غير صفري. في نسخة بدء جديدة، ينجح اختبارا الأساس فقط ويكون الإجمالي 4. سجّل حالة البداية منفصلة.

**شخّص إخفاق اختبار الميزة.** إذا عرض `open` الرقم 4، فتحقق من وصول وسيط التصفية إلى دالة العد ومن مقارنة البرنامج لحقل `status` في المهمة. لا تصف الاختبار الفاشل بأنه ناجح لمجرد أن الوكيل قال إن التنفيذ اكتمل.

## افحص الخصوصية والوصول

**سجّل الملفات التي تلقاها الوكيل.** يحتوي المختبر على بيانات اصطناعية ولا يتضمن أسرارًا. قد يحتوي المشروع الحقيقي على بيانات اعتماد أو سجلات عملاء أو مستندات خاصة. افحص المطالبات والسجلات ولقطات الشاشة والفروق بحثًا عن هذه القيم قبل مشاركة المخرجات.

**يثبت الاختبار المحلي السلوك المحلي فقط.** لا يثبت أذونات حساب سحابي أو نطاق خادم MCP أو سلوك خدمة منشورة. اختبر كل حد في البيئة المعنية.

## سجّل الاستخدام والتكاليف

**تقيس الرموز حجم إدخال النموذج وإخراجه.** تختلف لوحات المنتجات، لذا استخدم أرقام الاستخدام التي يعرضها مزوّدك. سجّل استدعاءات الأدوات ورسوم الصور أو البيئات المستضافة بشكل منفصل عند الحاجة. تحقق من الأسعار الحالية قبل حساب فاتورة فعلية.

**افتح صفحة استخدام الحساب الذي نفّذ المهمة.** سجّل رموز الإدخال والإخراج المعروضة والنموذج وفترة الفوترة وأي فئة للإدخال المخزن مؤقتًا. في اشتراكات ChatGPT أو Claude، لا يعادل حد الاستخدام أو حصته تكلفة API لمهمة واحدة. عند تشغيل OpenCode عبر API أو مزوّد، راجع الاستخدام أو الفوترة لدى ذلك المزوّد وسعره الحالي. إذا لم يعرض المنتج الرموز لكل مهمة، فاكتب «غير متاح» ولا تستنتج الرسوم من طول المحادثة.

**حساب توضيحي وليس سعرًا لمزوّد:** تبلغ تكلفة 30,000 رمز إدخال بسعر دولار واحد لكل مليون 0.03 دولار. وتبلغ تكلفة 5,000 رمز إخراج بسعر 5 دولارات لكل مليون 0.025 دولار. إجمالي تكلفة النموذج في هذا المثال 0.055 دولار قبل رسوم الأدوات أو الاستضافة.

```text
تكلفة الإدخال = رموز الإدخال / 1,000,000 × سعر الإدخال
تكلفة الإخراج = رموز الإخراج / 1,000,000 × سعر الإخراج
الإجمالي = تكلفة الإدخال + تكلفة الإخراج + رسوم الأدوات المنفصلة
```

**تستهلك مهمة العامل رموزًا أيضًا.** ينقل التفويض المخرجات التفصيلية خارج المحادثة الرئيسية، لكنه لا يجعل العمل مجانيًا. قارن التكلفة بقيمة الفحص المستقل.

**افصل فئات الرسوم.** قد تختلف أسعار الإدخال المخزن مؤقتًا والإدخال الجديد والإخراج واستدعاءات الأدوات والتنفيذ المستضاف. يستخدم هذا المثال أسعار الإدخال الجديد والإخراج فقط. ولا يتناول فاتورة الاشتراك أو رسوم الأداة.

## احتفظ بسجل قبول

| الحقل | مثال مكتمل بعد التعديل |
|---|---|
| **المصدر** | تمت قراءة `docs/requirements.md`، المراجعة 1 |
| **الملفات المتغيرة** | `task_report.py` و`tests/test_task_report.py` في `git status --short` |
| **الاختبارات** | نجحت اختبارات الأساس ومرشح الحالة الجديد، سجّل العدد المرصود |
| **المخرجات اليدوية** | لوحظت `Total tasks: 4` و`2` و`2`، ورُفضت القيمة غير الصالحة |
| **حالة الميزة** | نُفّذ `--status open` و`--status done` |
| **الخصوصية** | ملفات اصطناعية فقط |
| **الاستخدام** | سجّل أرقام مزوّدك إن توفرت |
| **القرار** | اقبل فقط بعد اجتياز فحوص المصدر والفارق والاختبارات والخصوصية |

**مخرجك:** انسخ هذا السجل واملأه بعد تشغيلك أنت. لا تستبدل كلمة «لوحظ» إلا بمخرجات شاهدتها. اختر «قبول» عند اجتياز كل الفحوص المطلوبة، و«مراجعة» عندما يكون الإصلاح محدودًا، و«إيقاف» عندما يكون المصدر أو النطاق أو الوصول غير واضح.

## تحقق من فهمك

1. **سؤال:** هل يثبت نجاح خط الأساس في النسخة الأولية وجود الميزة المطلوبة؟ **الإجابة:** لا. اختبر سلوك القبول الجديد بعد التعديل.

2. **سؤال:** ماذا يتضمن سجل القبول؟ **الإجابة:** أدلة المصدر والملفات المتغيرة وفحوص السلوك ونطاق الوصول والاستخدام المرصود.

## استكشاف الأخطاء وإصلاحها

- **لا يوجد مصدر للادعاء:** سجّله على أنه غير متحقق وابحث عن مرجع موثوق.
- **تنجح الاختبارات لكن تختلف المخرجات:** أضف حالة يدوية وافحص البيانات.
- **بيانات الاستخدام غير متاحة:** سجّل «غير متاح» بدل تقدير تكلفة فعلية.
- **يتضمن الفارق بيانات خاصة:** توقف عن مشاركة المخرجات واحذف البيانات من سجل التدريب.
