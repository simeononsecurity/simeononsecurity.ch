[実践的なAIワークフローコースに戻る](/effective-ai-course-start/)

**タスクに適した証拠を確認してから、AIの結果を受け入れます。** 洗練された説明、設定済みのツール、緑色のテスト表示は、それぞれ別の問いに答えます。このレッスンでは、ワークショップのラボ用に1つのレビュー記録を作成します。

**学習目標：**情報源、ファイル範囲、テスト、プライバシー、使用量について受け入れ記録を作成します。

## 要点

- **情報源の確認：**事実に関する主張を、最新の信頼できる記録と比較します。
- **範囲の確認：**変更されたファイルやシステムを調べます。
- **動作の確認：**テストと関連する手動ケースを実行します。
- **プライバシーの確認：**ツールやプロバイダーに渡った内容を調べます。
- **使用量の確認：**トークン、ツール呼び出し、コスト計算に使った料金を記録します。

## 始める前に

**前提条件：**コースのラボ、`docs/requirements.md`、ローカルGitスナップショット、[MCPレッスン](/articles/effective-ai-mcp-server-setup/)またはブラウザーでの代替手順。所要時間は40分です。難易度は中級です。最初のコーディングエージェント課題で編集したラボを使います。編集を省略した場合は、新たに展開したコピーを使い、機能チェックを未実装として記録します。変更前のベースラインは、元の2つのテストに引き続き合格します。

## 事実に関する主張を確認する

**主張：**「承認されたステータス値は `open` と `pending` です。」`docs/requirements.md` のリビジョン1を開きます。そこには `open` と `done` とあります。この主張は誤りです。自信のある口調でも要件は変わりません。

**製品に関する主張では、**最新の公式ドキュメントを使い、ページ名と確認日を記録します。メニュー、プラン、コマンド、コンテキスト上限に関する情報は、一般的なワークフロー原則より早く古くなります。[Codexドキュメント](https://learn.chatgpt.com/docs/codex/cli)、[Claude Codeドキュメント](https://code.claude.com/docs/en/overview)、[OpenCodeドキュメント](https://opencode.ai/docs/)で現在のインターフェースを確認できます。

| 主張 | 情報源 | 判断 |
|---|---|---|
| **状態値 `open` と `pending`** | ラボ要件、リビジョン1 | 却下し、`pending` を `done` に置き換える |
| **フィルターなしの件数は4** | ベースラインプログラムと4つのJSON項目 | プログラムを実行して確認する |
| **MCPの読み取りが行われた** | セッションのツール実行記録 | ツール呼び出しが表示される場合のみ受け入れる |

## 変更を確認する

**コーディングタスクでは、**Gitで変更ファイルを一覧表示し、実際の差分を読みます。新しい未追跡ファイルは通常の差分に表示されなくても、ステータスには表示されます。両方を確認してください。

```bash
git status --short
git diff -- task_report.py tests
```

**想定範囲：**フィルター課題の後に変更されるのは `task_report.py` と対象を絞ったテストだけです。`tasks.json`、`docs/requirements.md`、隠れた設定ファイルの変更には説明と個別レビューが必要です。編集していない場合、変更はないはずです。

## 動作をテストする

**展開したラボのフォルダーで、同じベースライン確認と機能確認を実行します。**エージェントの完了報告には、各確認で観測した結果を記載します。

```bash
python3 -m unittest discover -s tests -v
python3 task_report.py tasks.json
python3 task_report.py tasks.json --status open
python3 task_report.py tasks.json --status done
python3 task_report.py tasks.json --status invalid
```

**編集済みコピーでは、**テストが新しいケースをカバーし、件数は4、2、2となり、無効な値は明確なエラーとゼロ以外の終了コードを返します。新しいスターターコピーでは、2つのベースラインテストだけが合格し、合計は4です。この初期状態は別に記録します。

**機能テストの失敗は原因を調べます。**`open` が4と表示されたら、フィルター引数が集計関数まで届いているか、プログラムがタスクの `status` フィールドを比較しているか確認します。エージェントが実装完了と述べても、失敗したテストを合格扱いにしません。

## プライバシーとアクセスを確認する

**エージェントが受け取ったファイルを記録します。**ラボには合成データのみが含まれ、秘密情報はありません。実際のプロジェクトには認証情報、顧客データ、非公開文書が含まれる場合があります。出力を共有する前に、プロンプト、ログ、スクリーンショット、差分にそうした値がないか調べます。

**ローカルテストで確認できるのはローカルの動作だけです。**クラウドアカウントの権限、MCPサーバーの範囲、デプロイ済みサービスの動作は証明しません。各境界を、関連する環境でテストします。

## 使用量とコストを記録する

**トークンはモデルの入力と出力の量を表します。**製品によってダッシュボードが異なるため、プロバイダーに表示された使用量を使います。必要に応じて、ツール呼び出しや画像、ホスト環境の料金を分けて記録します。実際の請求額を計算する前に、現在の料金を確認します。

**タスクを実行したアカウントの使用量画面を開きます。**表示された入力・出力トークン、モデル、請求期間、キャッシュ入力の区分を記録します。ChatGPTやClaudeのサブスクリプションでは、使用上限や割当量はタスクごとのAPI料金と同じではありません。APIまたはプロバイダー経由でOpenCodeを実行した場合は、そのプロバイダーの使用量または請求画面と現在の料金を確認します。タスクごとのトークンが表示されない場合は「利用不可」と記載し、チャットの長さから料金を推定しません。

**計算例であり、プロバイダーの料金ではありません：**入力100万トークンあたり1ドルの場合、入力30,000トークンは0.03ドルです。出力100万トークンあたり5ドルの場合、出力5,000トークンは0.025ドルです。この例でのモデル料金合計は0.055ドルで、ツールやホスティング料金は含みません。

```text
入力コスト = 入力トークン / 1,000,000 × 入力単価
出力コスト = 出力トークン / 1,000,000 × 出力単価
合計 = 入力コスト + 出力コスト + 別途のツール料金
```

**作業者への委任もトークンを消費します。**委任すると詳細な出力はメインの会話から分離されますが、作業が無料になるわけではありません。コストと独立した確認の価値を比べます。

**料金区分は分けて記録します。**キャッシュ入力、新規入力、出力、ツール呼び出し、ホスト環境の実行では異なる料金が適用される場合があります。この例では新規入力と出力の料金だけを使います。サブスクリプション料金やツール料金については示していません。

## 受け入れ記録を残す

| 項目 | 編集後の記入例 |
|---|---|
| **情報源** | `docs/requirements.md`、リビジョン1、確認済み |
| **変更ファイル** | `git status --short` の `task_report.py` と `tests/test_task_report.py` |
| **テスト** | ベースラインと新しいフィルターテストに合格、観測した件数を記録 |
| **手動出力** | `Total tasks: 4`、`2`、`2` を確認し、無効な値を拒否 |
| **機能の状態** | `--status open` と `--status done` を実装済み |
| **プライバシー** | 合成ファイルのみ |
| **使用量** | 利用できる場合はプロバイダーの値を記録 |
| **判断** | 情報源、差分、テスト、プライバシーの確認後にのみ受け入れる |

**作成物：**この記録をコピーし、自分で実行した後に記入します。「確認済み」は、自分が見た出力に対してだけ使います。必要な確認がすべて合格なら「受け入れ」、修正範囲が限定的なら「修正」、情報源、範囲、アクセスが不明確なら「停止」を選びます。

## 理解度を確認する

1. **質問：**スターターのベースラインが合格したら、要求された機能がある証拠になりますか？**回答：**いいえ。編集後に新しい受け入れ動作をテストします。

2. **質問：**受け入れ記録には何を含めますか？**回答：**情報源の証拠、変更ファイル、動作確認、アクセス範囲、観測した使用量です。

## トラブルシューティング

- **主張の情報源がない：**未検証と記録し、権威ある記録を探します。
- **テストは合格したが出力が異なる：**手動ケースを追加し、データを調べます。
- **使用量が不明：**実費を推定せず、「利用不可」と記録します。
- **差分に非公開データが含まれる：**出力の共有をやめ、練習記録からそのデータを削除します。
