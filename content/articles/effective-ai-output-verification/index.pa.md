[ਵਿਹਾਰਕ AI ਕਾਰਜ-ਪ੍ਰਵਾਹ ਕੋਰਸ ਵੱਲ ਵਾਪਸ ਜਾਓ](/effective-ai-course-start/)

**AI ਨਤੀਜਾ ਤਦ ਹੀ ਮਨਜ਼ੂਰ ਕਰੋ ਜਦੋਂ ਕੰਮ ਲਈ ਢੁੱਕਵੇਂ ਸਬੂਤ ਦੀ ਜਾਂਚ ਕਰ ਲਵੋ।** ਸਾਫ਼-ਸੁਥਰੀ ਵਿਆਖਿਆ, ਸੰਰਚਿਤ ਟੂਲ ਅਤੇ ਹਰਾ ਟੈਸਟ ਸੁਨੇਹਾ ਵੱਖ-ਵੱਖ ਸਵਾਲਾਂ ਦੇ ਜਵਾਬ ਦਿੰਦੇ ਹਨ। ਇਹ ਪਾਠ ਵਰਕਸ਼ਾਪ ਲੈਬ ਲਈ ਇੱਕ ਸਾਂਝਾ ਸਮੀਖਿਆ ਰਿਕਾਰਡ ਬਣਾਉਂਦਾ ਹੈ।

**ਸਿੱਖਣ ਦਾ ਨਤੀਜਾ:** ਤੁਸੀਂ ਸਰੋਤਾਂ, ਫਾਈਲਾਂ ਦੇ ਦਾਇਰੇ, ਟੈਸਟਾਂ, ਨਿੱਜਤਾ ਅਤੇ ਵਰਤੋਂ ਲਈ ਮਨਜ਼ੂਰੀ ਰਿਕਾਰਡ ਬਣਾਓਗੇ।

## ਮੁੱਖ ਗੱਲਾਂ

- **ਸਰੋਤ ਦੀ ਜਾਂਚ:** ਤੱਥੀ ਦਾਅਵੇ ਦੀ ਤੁਲਨਾ ਮੌਜੂਦਾ ਅਤੇ ਭਰੋਸੇਯੋਗ ਰਿਕਾਰਡ ਨਾਲ ਕਰੋ।
- **ਦਾਇਰੇ ਦੀ ਜਾਂਚ:** ਵੇਖੋ ਕਿ ਕਿਹੜੀਆਂ ਫਾਈਲਾਂ ਜਾਂ ਸਿਸਟਮ ਬਦਲੇ ਹਨ।
- **ਵਿਹਾਰ ਦੀ ਜਾਂਚ:** ਟੈਸਟ ਅਤੇ ਸੰਬੰਧਤ ਹੱਥੀਂ ਜਾਂਚਾਂ ਚਲਾਓ।
- **ਨਿੱਜਤਾ ਦੀ ਜਾਂਚ:** ਵੇਖੋ ਕਿ ਟੂਲ ਜਾਂ ਪ੍ਰਦਾਤਾ ਤੱਕ ਕਿਹੜੀ ਸਮੱਗਰੀ ਪਹੁੰਚੀ।
- **ਵਰਤੋਂ ਦੀ ਜਾਂਚ:** ਟੋਕਨ, ਟੂਲ ਕਾਲਾਂ ਅਤੇ ਲਾਗਤ ਲਈ ਵਰਤੀ ਦਰ ਲਿਖੋ।

## ਸ਼ੁਰੂ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ

**ਲੋੜਾਂ:** ਕੋਰਸ ਲੈਬ, `docs/requirements.md`, ਸਥਾਨਕ Git ਸਨੈਪਸ਼ਾਟ ਅਤੇ [MCP ਪਾਠ](/articles/effective-ai-mcp-server-setup/) ਜਾਂ ਬ੍ਰਾਊਜ਼ਰ ਵਾਲਾ ਵਿਕਲਪ। 40 ਮਿੰਟ ਰੱਖੋ। ਔਖਿਆਈ ਦਰਮਿਆਨੀ ਹੈ। ਪਹਿਲੇ ਕੋਡਿੰਗ-ਏਜੰਟ ਕੰਮ ਵਿੱਚ ਸੋਧੀ ਆਪਣੀ ਲੈਬ ਵਰਤੋ। ਜੇ ਸੋਧ ਛੱਡੀ ਸੀ, ਤਾਂ ਨਵਾਂ ਐਕਸਟ੍ਰੈਕਸ਼ਨ ਵਰਤੋ ਅਤੇ ਫੀਚਰ ਜਾਂਚਾਂ ਨੂੰ ਲਾਗੂ ਨਹੀਂ ਹੋਇਆ ਲਿਖੋ। ਬਿਨਾਂ ਸੋਧ ਵਾਲੀ ਬੇਸਲਾਈਨ ਹਾਲੇ ਵੀ ਆਪਣੇ ਦੋ ਮੂਲ ਟੈਸਟ ਪਾਸ ਕਰਦੀ ਹੈ।

## ਤੱਥੀ ਦਾਅਵੇ ਦੀ ਜਾਂਚ

**ਦਾਅਵਾ:** “ਮਨਜ਼ੂਰਸ਼ੁਦਾ ਸਥਿਤੀ ਮੁੱਲ `open` ਅਤੇ `pending` ਹਨ।” `docs/requirements.md`, ਸੋਧ 1 ਖੋਲ੍ਹੋ। ਇਸ ਵਿੱਚ `open` ਅਤੇ `done` ਲਿਖਿਆ ਹੈ। ਦਾਅਵਾ ਗਲਤ ਹੈ। ਭਰੋਸੇ ਵਾਲਾ ਲਹਿਜ਼ਾ ਲੋੜ ਨਹੀਂ ਬਦਲਦਾ।

**ਉਤਪਾਦ ਬਾਰੇ ਦਾਅਵਿਆਂ ਲਈ,** ਮੌਜੂਦਾ ਅਧਿਕਾਰਤ ਦਸਤਾਵੇਜ਼ ਵੇਖੋ ਅਤੇ ਪੰਨੇ ਦਾ ਸਿਰਲੇਖ ਤੇ ਜਾਂਚ ਦੀ ਮਿਤੀ ਲਿਖੋ। ਮੀਨੂ, ਯੋਜਨਾ, ਕਮਾਂਡ ਜਾਂ ਸੰਦਰਭ ਹੱਦ ਬਾਰੇ ਦਾਅਵਾ ਆਮ ਕਾਰਜ-ਪ੍ਰਵਾਹ ਸਿਧਾਂਤ ਨਾਲੋਂ ਜਲਦੀ ਪੁਰਾਣਾ ਹੁੰਦਾ ਹੈ। [Codex ਦਸਤਾਵੇਜ਼](https://learn.chatgpt.com/docs/codex/cli), [Claude Code ਦਸਤਾਵੇਜ਼](https://code.claude.com/docs/en/overview) ਅਤੇ [OpenCode ਦਸਤਾਵੇਜ਼](https://opencode.ai/docs/) ਆਪਣੇ ਮੌਜੂਦਾ ਇੰਟਰਫੇਸ ਦਰਸਾਉਂਦੇ ਹਨ।

| ਦਾਅਵਾ | ਸਰੋਤ | ਫੈਸਲਾ |
|---|---|---|
| **`open` ਅਤੇ `pending`** | ਲੈਬ ਦੀ ਲੋੜ, ਸੋਧ 1 | ਰੱਦ ਕਰੋ, `pending` ਦੀ ਥਾਂ `done` ਲਿਖੋ |
| **ਬਿਨਾਂ ਫਿਲਟਰ ਗਿਣਤੀ 4 ਹੈ** | ਬੇਸਲਾਈਨ ਪ੍ਰੋਗਰਾਮ ਅਤੇ ਚਾਰ JSON ਐਂਟਰੀਆਂ | ਪ੍ਰੋਗਰਾਮ ਚਲਾ ਕੇ ਜਾਂਚੋ |
| **MCP ਰੀਡ ਹੋਇਆ** | ਸੈਸ਼ਨ ਟੂਲ ਟ੍ਰਾਂਸਕ੍ਰਿਪਟ | ਕੇਵਲ ਤਦ ਮਨਜ਼ੂਰ ਕਰੋ ਜਦੋਂ ਟੂਲ ਕਾਲ ਦਿਖੇ |

## ਤਬਦੀਲੀ ਦੀ ਜਾਂਚ ਕਰੋ

**ਕੋਡਿੰਗ ਕੰਮ ਲਈ,** ਬਦਲੀਆਂ ਫਾਈਲਾਂ ਦੀ ਸੂਚੀ ਅਤੇ ਅਸਲ diff ਪੜ੍ਹਨ ਵਾਸਤੇ Git ਵਰਤੋ। ਨਵੀਂ ਅਣ-ਟਰੈਕ ਫਾਈਲ ਆਮ diff ਵਿੱਚ ਨਾ ਹੋਵੇ ਪਰ status ਵਿੱਚ ਦਿਖਦੀ ਹੈ, ਇਸ ਲਈ ਦੋਵੇਂ ਜਾਂਚੋ।

```bash
git status --short
git diff -- task_report.py tests
```

**ਉਮੀਦ ਕੀਤਾ ਦਾਇਰਾ:** ਫਿਲਟਰ ਕੰਮ ਤੋਂ ਬਾਅਦ ਸਿਰਫ਼ `task_report.py` ਅਤੇ ਚੁਣੇ ਟੈਸਟ ਬਦਲਦੇ ਹਨ। `tasks.json`, `docs/requirements.md` ਜਾਂ ਲੁਕੀ ਸੰਰਚਨਾ ਫਾਈਲ ਵਿੱਚ ਤਬਦੀਲੀ ਲਈ ਵਜ੍ਹਾ ਅਤੇ ਵੱਖਰੀ ਸਮੀਖਿਆ ਚਾਹੀਦੀ ਹੈ। ਜੇ ਤੁਸੀਂ ਸੋਧ ਨਹੀਂ ਕੀਤੀ, ਤਾਂ ਬਦਲਾਅ ਨਹੀਂ ਹੋਣੇ ਚਾਹੀਦੇ।

## ਵਿਹਾਰ ਦੀ ਜਾਂਚ ਕਰੋ

**ਐਕਸਟ੍ਰੈਕਟ ਕੀਤੇ ਲੈਬ ਫੋਲਡਰ ਵਿੱਚ ਉਹੀ ਬੇਸਲਾਈਨ ਅਤੇ ਫੀਚਰ ਜਾਂਚਾਂ ਚਲਾਓ।** ਏਜੰਟ ਦੀ ਮੁਕੰਮਲਤਾ ਰਿਪੋਰਟ ਵਿੱਚ ਇਨ੍ਹਾਂ ਦੇ ਵੇਖੇ ਨਤੀਜੇ ਹੋਣੇ ਚਾਹੀਦੇ ਹਨ।

```bash
python3 -m unittest discover -s tests -v
python3 task_report.py tasks.json
python3 task_report.py tasks.json --status open
python3 task_report.py tasks.json --status done
python3 task_report.py tasks.json --status invalid
```

**ਸੋਧੀ ਕਾਪੀ ਵਿੱਚ,** ਟੈਸਟ ਨਵੇਂ ਮਾਮਲਿਆਂ ਨੂੰ ਕਵਰ ਕਰਦੇ ਹਨ, ਗਿਣਤੀਆਂ 4, 2 ਅਤੇ 2 ਹਨ, ਅਤੇ ਗਲਤ ਮੁੱਲ ਸਪਸ਼ਟ ਗਲਤੀ ਤੇ ਗੈਰ-ਜ਼ੀਰੋ ਨਿਕਾਸ ਕੋਡ ਦਿੰਦਾ ਹੈ। ਨਵੀਂ ਸਟਾਰਟਰ ਕਾਪੀ ਵਿੱਚ ਸਿਰਫ਼ ਦੋ ਬੇਸਲਾਈਨ ਟੈਸਟ ਪਾਸ ਹੁੰਦੇ ਹਨ ਅਤੇ ਕੁੱਲ ਗਿਣਤੀ 4 ਹੈ। ਇਸ ਸ਼ੁਰੂਆਤੀ ਹਾਲਤ ਨੂੰ ਵੱਖਰਾ ਲਿਖੋ।

**ਫੀਚਰ ਟੈਸਟ ਫੇਲ੍ਹ ਹੋਵੇ ਤਾਂ ਕਾਰਨ ਲੱਭੋ।** ਜੇ `open` 4 ਦਿਖਾਏ, ਤਾਂ ਜਾਂਚੋ ਕਿ ਫਿਲਟਰ ਦਲੀਲ ਗਿਣਤੀ ਫੰਕਸ਼ਨ ਤੱਕ ਪਹੁੰਚਦੀ ਹੈ ਅਤੇ ਪ੍ਰੋਗਰਾਮ ਕੰਮ ਦਾ `status` ਖੇਤਰ ਮਿਲਾਉਂਦਾ ਹੈ। ਏਜੰਟ ਦੇ ਮੁਕੰਮਲ ਕਰਨ ਦੇ ਦਾਅਵੇ ਕਰਕੇ ਫੇਲ੍ਹ ਟੈਸਟ ਨੂੰ ਪਾਸ ਨਾ ਦੱਸੋ।

## ਨਿੱਜਤਾ ਅਤੇ ਪਹੁੰਚ ਦੀ ਜਾਂਚ

**ਲਿਖੋ ਕਿ ਏਜੰਟ ਨੂੰ ਕਿਹੜੀਆਂ ਫਾਈਲਾਂ ਮਿਲੀਆਂ।** ਲੈਬ ਵਿੱਚ ਕ੍ਰਿਤ੍ਰਿਮ ਡਾਟਾ ਹੈ ਅਤੇ ਕੋਈ ਰਾਜ਼ ਨਹੀਂ। ਅਸਲ ਪ੍ਰੋਜੈਕਟ ਵਿੱਚ ਲਾਗਇਨ ਜਾਣਕਾਰੀ, ਗਾਹਕ ਰਿਕਾਰਡ ਜਾਂ ਨਿੱਜੀ ਦਸਤਾਵੇਜ਼ ਹੋ ਸਕਦੇ ਹਨ। ਨਤੀਜਾ ਸਾਂਝਾ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ prompts, logs, screenshots ਅਤੇ diffs ਵਿੱਚ ਇਹ ਮੁੱਲ ਲੱਭੋ।

**ਸਥਾਨਕ ਟੈਸਟ ਸਿਰਫ਼ ਸਥਾਨਕ ਵਿਹਾਰ ਸਾਬਤ ਕਰਦਾ ਹੈ।** ਇਹ ਕਲਾਉਡ ਖਾਤੇ ਦੇ ਅਧਿਕਾਰ, MCP ਸਰਵਰ ਦੇ ਦਾਇਰੇ ਜਾਂ ਚੱਲਦੀ ਸੇਵਾ ਦੇ ਵਿਹਾਰ ਨੂੰ ਸਾਬਤ ਨਹੀਂ ਕਰਦਾ। ਹਰ ਹੱਦ ਨੂੰ ਸੰਬੰਧਤ ਮਾਹੌਲ ਵਿੱਚ ਜਾਂਚੋ।

## ਵਰਤੋਂ ਅਤੇ ਲਾਗਤ ਲਿਖੋ

**ਟੋਕਨ ਮਾਡਲ ਦੇ ਇਨਪੁੱਟ ਅਤੇ ਆਉਟਪੁੱਟ ਦੀ ਮਾਤਰਾ ਮਾਪਦੇ ਹਨ।** ਉਤਪਾਦਾਂ ਦੇ ਡੈਸ਼ਬੋਰਡ ਵੱਖਰੇ ਹੁੰਦੇ ਹਨ, ਇਸ ਲਈ ਆਪਣੇ ਪ੍ਰਦਾਤਾ ਦੇ ਵਰਤੋਂ ਅੰਕੜੇ ਵਰਤੋ। ਲੋੜ ਹੋਵੇ ਤਾਂ ਟੂਲ ਕਾਲਾਂ ਅਤੇ ਚਿੱਤਰਾਂ ਜਾਂ ਹੋਸਟ ਕੀਤੇ ਮਾਹੌਲ ਦੇ ਖਰਚੇ ਵੱਖਰੇ ਲਿਖੋ। ਅਸਲ ਬਿੱਲ ਕੱਢਣ ਤੋਂ ਪਹਿਲਾਂ ਮੌਜੂਦਾ ਦਰਾਂ ਵੇਖੋ।

**ਕੰਮ ਚਲਾਉਣ ਵਾਲੇ ਖਾਤੇ ਦਾ ਵਰਤੋਂ ਪੰਨਾ ਖੋਲ੍ਹੋ।** ਦਿਖਾਏ ਇਨਪੁੱਟ ਅਤੇ ਆਉਟਪੁੱਟ ਟੋਕਨ, ਮਾਡਲ, ਬਿਲਿੰਗ ਮਿਆਦ ਅਤੇ ਕੈਸ਼ ਇਨਪੁੱਟ ਦੀ ਸ਼੍ਰੇਣੀ ਲਿਖੋ। ChatGPT ਜਾਂ Claude ਮੈਂਬਰਸ਼ਿਪ ਵਿੱਚ ਵਰਤੋਂ ਹੱਦ ਜਾਂ ਭੱਤਾ ਕਿਸੇ ਕੰਮ ਦੀ API ਫੀਸ ਨਹੀਂ ਹੁੰਦਾ। API ਜਾਂ ਪ੍ਰਦਾਤਾ ਰਾਹੀਂ OpenCode ਚਲਾਉਣ ਵੇਲੇ ਉਸ ਪ੍ਰਦਾਤਾ ਦੀ ਵਰਤੋਂ ਜਾਂ ਬਿਲਿੰਗ ਅਤੇ ਮੌਜੂਦਾ ਦਰ ਵੇਖੋ। ਜੇ ਉਤਪਾਦ ਹਰ ਕੰਮ ਦੇ ਟੋਕਨ ਨਹੀਂ ਦਿਖਾਉਂਦਾ, ਤਾਂ “ਉਪਲਬਧ ਨਹੀਂ” ਲਿਖੋ ਅਤੇ ਗੱਲਬਾਤ ਦੀ ਲੰਬਾਈ ਤੋਂ ਫੀਸ ਨਾ ਕੱਢੋ।

**ਸਿਰਫ਼ ਸਮਝਾਉਣ ਵਾਲੀ ਗਣਨਾ, ਪ੍ਰਦਾਤਾ ਦੀ ਦਰ ਨਹੀਂ:** ਦਸ ਲੱਖ ਲਈ $1 ਦੀ ਦਰ ਤੇ 30,000 ਇਨਪੁੱਟ ਟੋਕਨ $0.03 ਹਨ। ਦਸ ਲੱਖ ਲਈ $5 ਦੀ ਦਰ ਤੇ 5,000 ਆਉਟਪੁੱਟ ਟੋਕਨ $0.025 ਹਨ। ਇਸ ਉਦਾਹਰਨ ਵਿੱਚ ਟੂਲ ਜਾਂ ਹੋਸਟਿੰਗ ਤੋਂ ਪਹਿਲਾਂ ਮਾਡਲ ਦੀ ਕੁੱਲ ਫੀਸ $0.055 ਹੈ।

```text
ਇਨਪੁੱਟ ਲਾਗਤ = ਇਨਪੁੱਟ ਟੋਕਨ / 1,000,000 × ਇਨਪੁੱਟ ਦਰ
ਆਉਟਪੁੱਟ ਲਾਗਤ = ਆਉਟਪੁੱਟ ਟੋਕਨ / 1,000,000 × ਆਉਟਪੁੱਟ ਦਰ
ਕੁੱਲ = ਇਨਪੁੱਟ ਲਾਗਤ + ਆਉਟਪੁੱਟ ਲਾਗਤ + ਵੱਖਰੇ ਟੂਲ ਖਰਚੇ
```

**ਕਰਮਚਾਰੀ ਦਾ ਕੰਮ ਵੀ ਟੋਕਨ ਵਰਤਦਾ ਹੈ।** ਕੰਮ ਸੌਂਪਣ ਨਾਲ ਵਿਸਥਾਰ ਵਾਲਾ ਨਤੀਜਾ ਮੁੱਖ ਗੱਲਬਾਤ ਤੋਂ ਬਾਹਰ ਜਾਂਦਾ ਹੈ, ਪਰ ਕੰਮ ਮੁਫ਼ਤ ਨਹੀਂ ਹੁੰਦਾ। ਸੁਤੰਤਰ ਜਾਂਚ ਦੇ ਲਾਭ ਨਾਲ ਲਾਗਤ ਦੀ ਤੁਲਨਾ ਕਰੋ।

**ਖਰਚੇ ਦੀਆਂ ਸ਼੍ਰੇਣੀਆਂ ਵੱਖ ਰੱਖੋ।** ਕੈਸ਼ ਇਨਪੁੱਟ, ਨਵਾਂ ਇਨਪੁੱਟ, ਆਉਟਪੁੱਟ, ਟੂਲ ਕਾਲਾਂ ਅਤੇ ਹੋਸਟ ਕੀਤਾ ਕੰਮ ਵੱਖਰੀਆਂ ਦਰਾਂ ਵਰਤ ਸਕਦੇ ਹਨ। ਇਹ ਉਦਾਹਰਨ ਸਿਰਫ਼ ਨਵੇਂ ਇਨਪੁੱਟ ਅਤੇ ਆਉਟਪੁੱਟ ਦੀਆਂ ਦਰਾਂ ਵਰਤਦੀ ਹੈ। ਇਹ ਮੈਂਬਰਸ਼ਿਪ ਬਿੱਲ ਜਾਂ ਟੂਲ ਫੀਸ ਬਾਰੇ ਨਹੀਂ ਦੱਸਦੀ।

## ਮਨਜ਼ੂਰੀ ਰਿਕਾਰਡ ਰੱਖੋ

| ਖੇਤਰ | ਸੋਧ ਮਗਰੋਂ ਭਰਿਆ ਉਦਾਹਰਨ |
|---|---|
| **ਸਰੋਤ** | `docs/requirements.md`, ਸੋਧ 1, ਪੜ੍ਹਿਆ |
| **ਬਦਲੀਆਂ ਫਾਈਲਾਂ** | `git status --short` ਵਿੱਚ `task_report.py` ਅਤੇ `tests/test_task_report.py` |
| **ਟੈਸਟ** | ਬੇਸਲਾਈਨ ਅਤੇ ਨਵੇਂ ਫਿਲਟਰ ਟੈਸਟ ਪਾਸ, ਵੇਖੀ ਗਿਣਤੀ ਲਿਖੋ |
| **ਹੱਥੀਂ ਨਤੀਜਾ** | `Total tasks: 4`, `2` ਅਤੇ `2` ਵੇਖੇ, ਗਲਤ ਮੁੱਲ ਰੱਦ ਹੋਇਆ |
| **ਫੀਚਰ ਹਾਲਤ** | `--status open` ਅਤੇ `--status done` ਲਾਗੂ |
| **ਨਿੱਜਤਾ** | ਸਿਰਫ਼ ਕ੍ਰਿਤ੍ਰਿਮ ਫਾਈਲਾਂ |
| **ਵਰਤੋਂ** | ਉਪਲਬਧ ਹੋਣ ਤੇ ਪ੍ਰਦਾਤਾ ਦੇ ਅੰਕੜੇ ਲਿਖੋ |
| **ਫੈਸਲਾ** | ਸਰੋਤ, diff, ਟੈਸਟ ਅਤੇ ਨਿੱਜਤਾ ਜਾਂਚ ਪਾਸ ਹੋਣ ਮਗਰੋਂ ਹੀ ਮਨਜ਼ੂਰ ਕਰੋ |

**ਤੁਹਾਡਾ ਨਤੀਜਾ:** ਇਹ ਰਿਕਾਰਡ ਕਾਪੀ ਕਰੋ ਅਤੇ ਆਪਣੀ ਚਲਾਈ ਜਾਂਚ ਮਗਰੋਂ ਭਰੋ। “ਵੇਖਿਆ” ਸਿਰਫ਼ ਉਸ ਨਤੀਜੇ ਲਈ ਲਿਖੋ ਜੋ ਤੁਸੀਂ ਆਪ ਵੇਖਿਆ ਹੋਵੇ। ਸਾਰੀਆਂ ਲੋੜੀਂਦੀਆਂ ਜਾਂਚਾਂ ਪਾਸ ਹੋਣ ਤੇ ਮਨਜ਼ੂਰ ਕਰੋ, ਸੀਮਤ ਸੁਧਾਰ ਲਈ ਸੋਧੋ, ਅਤੇ ਸਰੋਤ, ਦਾਇਰਾ ਜਾਂ ਪਹੁੰਚ ਅਸਪਸ਼ਟ ਹੋਵੇ ਤਾਂ ਰੋਕੋ।

## ਆਪਣੀ ਸਮਝ ਜਾਂਚੋ

1. **ਸਵਾਲ:** ਸਟਾਰਟਰ ਦੀ ਬੇਸਲਾਈਨ ਪਾਸ ਹੋਣਾ ਕੀ ਮੰਗੇ ਗਏ ਫੀਚਰ ਦਾ ਸਬੂਤ ਹੈ? **ਜਵਾਬ:** ਨਹੀਂ। ਸੋਧ ਮਗਰੋਂ ਨਵਾਂ ਮਨਜ਼ੂਰੀ ਵਿਹਾਰ ਜਾਂਚੋ।

2. **ਸਵਾਲ:** ਮਨਜ਼ੂਰੀ ਰਿਕਾਰਡ ਵਿੱਚ ਕੀ ਆਉਣਾ ਚਾਹੀਦਾ ਹੈ? **ਜਵਾਬ:** ਸਰੋਤ ਸਬੂਤ, ਬਦਲੀਆਂ ਫਾਈਲਾਂ, ਵਿਹਾਰ ਜਾਂਚ, ਪਹੁੰਚ ਦਾ ਦਾਇਰਾ ਅਤੇ ਵੇਖੀ ਵਰਤੋਂ।

## ਸਮੱਸਿਆ ਹੱਲ

- **ਦਾਅਵੇ ਦਾ ਸਰੋਤ ਨਹੀਂ:** ਇਸ ਨੂੰ ਗੈਰ-ਪ੍ਰਮਾਣਿਤ ਲਿਖੋ ਅਤੇ ਭਰੋਸੇਯੋਗ ਰਿਕਾਰਡ ਲੱਭੋ।
- **ਟੈਸਟ ਪਾਸ ਪਰ ਨਤੀਜਾ ਵੱਖਰਾ:** ਹੱਥੀਂ ਮਾਮਲਾ ਜੋੜੋ ਅਤੇ ਡਾਟਾ ਜਾਂਚੋ।
- **ਵਰਤੋਂ ਨਹੀਂ ਦਿਖਦੀ:** ਅਸਲ ਲਾਗਤ ਦਾ ਅੰਦਾਜ਼ਾ ਲਗਾਉਣ ਦੀ ਥਾਂ “ਉਪਲਬਧ ਨਹੀਂ” ਲਿਖੋ।
- **Diff ਵਿੱਚ ਨਿੱਜੀ ਡਾਟਾ ਹੈ:** ਨਤੀਜਾ ਸਾਂਝਾ ਕਰਨਾ ਰੋਕੋ ਅਤੇ ਅਭਿਆਸ ਰਿਕਾਰਡ ਤੋਂ ਡਾਟਾ ਹਟਾਓ।
