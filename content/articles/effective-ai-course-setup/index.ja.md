[実践AIワークフローコースに戻る](/effective-ai-course-start/)

**エージェントを使う前に、安全な練習場所を用意してください。** レッスン1と2は、このラボがなくてもブラウザーで受講できます。コース全体に取り組む場合は、レッスン3の前にここへ戻ってください。コーディングの実習では、Git、Python 3.10以降、コーディングエージェント1つを使います。学習ルートでは、利用できないエージェント操作を、明示した手動作業に置き換えます。

**学習目標：**スターターラボを実行し、ローカルの基準状態を保存し、使い捨てコピーをリセットする方法を説明します。

## 要点

- **ブラウザールート：**ChatGPTまたはClaudeで、チャット、計画、情報源の確認、レビューの演習を完了します。
- **ローカルルート：**付属のPythonラボとターミナルを使ってコーディング演習を行います。
- **リセットルート：**演習に失敗した場合は、新しいラボコピーを展開します。
- **安全ルール：**個人ファイル、顧客記録、認証情報をラボに入れないでください。

## ルートを選ぶ

| ルート | 必要なもの | 練習する内容 |
|---|---|---|
| **ブラウザー入門** | 最新のブラウザーとChatGPTまたはClaudeのアカウント | レッスン1と2、およびレッスン1のチャット課題パケット |
| **ローカル実習** | Git、Python 3.10以降、ターミナル、コーディングエージェント1つ | ファイル、差分、テスト、エージェントによる編集 |
| **自習コース** | ブラウザー、ローカルのPython 3.10以降、Git | ラボの全チェック。利用できないエージェントとMCPの手順は未実行と記録 |

**製品ごとにプランと制限が異なります。**機能を前提にする前に、[ChatGPT Projects](https://help.openai.com/en/articles/10169521-projects-in-chatgpt)と[Claude Projects](https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects)を確認してください。自習ルートを完了しても、利用できないコーディングエージェントの実践スキルを証明したことにはなりません。この違いを修了メモに記録してください。

**基本の道筋を1つ選びます。**チャット演習にはブラウザーのChatGPTを使い、その後ローカルラボと利用可能なコーディングエージェントを使います。チャットではClaudeも同等の選択肢です。コーディング段階ではCodex CLI、Claude Code CLI、OpenCodeを選べます。すべてのベンダーのアカウントを作る必要はありません。

**コーディングエージェントを開く前に、5つの事前確認を記録します。**ローカルラボの確認と、アカウントやホストされたワークスペースに関する主張を区別できます。

| 確認項目 | 記録する内容 |
|---|---|
| **ワークスペース** | エージェントが読み取る展開済みラボの正確なフォルダー |
| **実行場所** | ローカルコンピューターまたは選択したリモートワークスペース |
| **プロバイダー** | この作業で使うアカウントまたはモデルプロバイダー |
| **権限** | ファイル書き込みとシェルコマンドが許可済みか、承認が必要か |
| **基準状態** | 編集前に確認した件数と、合格したテスト2件 |

**練習用のルートフォルダーは狭く保ちます。**ホストされたワークスペースには、合成データのラボを別途コピーする必要があります。ローカル実行だけでは、リモートコピーやアカウントに同じファイルと権限があるとは言えません。

## ローカル用語を学ぶ

| 用語 | 簡単な意味 |
|---|---|
| **ターミナル** | コマンドを入力するアプリ |
| **シェル** | コマンドを解釈するソフトウェア |
| **CLI** | プログラムのコマンドラインインターフェース |
| **作業ディレクトリ** | コマンドが既定で使うフォルダー |
| **リポジトリ** | Gitが追跡するプロジェクト |
| **コミット** | 保存されたGitのスナップショット |
| **ブランチ** | 名前付きのGit変更系列 |
| **差分** | 追加または削除された行の表示 |
| **テスト** | 期待する動作を繰り返し確認するもの |
| **終了コード** | コマンドの成功または失敗を示す数値 |

**スターターラボにGitHubは不要です。**Gitは自分のコンピューターで動きます。GitHubは別のホスティングサービスです。ローカルコミットは、ファイルを外部へ送信せずにスナップショットを保存します。

## ラボを準備する

**[コースのスターターラボをダウンロード](/downloads/effective-ai-course-lab.zip)**し、自分で管理できる新しいフォルダーに展開します。そのフォルダーでターミナルを開きます。macOSまたはLinuxではTerminalを開き、`cd`で展開先に移動します。WindowsではPowerShellまたはWindows Terminalを使い、`cd`で移動します。Windowsでは、Pythonコマンドに`python3`ではなく`py -3`を使うことがよくあります。

**必要に応じて[Python 3.10以降](https://www.python.org/downloads/)と[Git](https://git-scm.com/downloads)をインストールします。**ラボを実行する前に、ツールのインストールを確認します。最初の2つのコマンドはバージョンを表示します。`cd`は作業ディレクトリを変更し、`ls`はファイルを一覧表示します。例のパスは、展開したフォルダーの実際のパスに置き換えてください。

```bash
python3 --version
git --version
cd /path/to/effective-ai-course-lab
ls
```

**Windows PowerShellでは、**`py -3 --version`、`git --version`、`cd C:\path\to\effective-ai-course-lab`、`Get-ChildItem`を使います。一覧には`task_report.py`、`tasks.json`、`tests`、`docs`が含まれるはずです。バージョン確認に失敗したら、先にインストールを完了してください。

```bash
pwd
python3 task_report.py tasks.json
python3 -m unittest discover -s tests -v
```

**Windows PowerShellでは、**必要なら`pwd`を`Get-Location`に置き換え、Pythonでランチャーを使う場合は`python3`を`py -3`に置き換えます。最初のコマンドが表示するパスは、展開済みラボフォルダーで終わる必要があります。ファイル名も確認してください。`AGENTS.md.txt`は`AGENTS.md`の代わりになりません。Windowsエクスプローラーでファイル名拡張子を有効にすると、完全な名前を確認できます。

**期待する出力：**レポートに`Total tasks: 4`と表示されます。テストコマンドは2つのテストを示し、`OK`で終わります。成功するとシェルは終了コード0を返します。別の件数やtracebackが表示された場合は、フォルダーとPythonの設定を確認してください。

**コマンドを部分ごとに読みます。**`python3 task_report.py tasks.json`では、`python3`がPythonを起動し、`task_report.py`がプログラムで、`tasks.json`が入力データを指定します。表示された件数は出力であり、次のコマンドではありません。失敗後、macOSとLinuxでは`echo $?`で状態を確認できます。PowerShellでは`$LASTEXITCODE`に直前のネイティブプログラムの状態が入ります。

**Pythonのインストール後、初回実行に約10分を見込みます。**ラボを展開してレポートを実行し、合計を`tasks.json`の4項目と比べます。JSONファイルをテキストエディターで開き、項目を自分で数えます。

## Gitを安全に練習する

**Gitは展開済みのラボフォルダー内でのみ開始します。**以下のコマンドはローカルスナップショットを作成します。`git status`は変更されたファイルを示します。追跡対象のファイルを編集した後、`git diff`は変更行を表示します。

```bash
git init
git add .
git commit -m "コースラボの基準状態"
git status --short
```

**期待する状態：**コミット後にファイル名は表示されません。Gitから名前とメールアドレスを求められたら、このフォルダーでラボ専用の識別情報を設定し、コミットをやり直します。例の値は自分の非公開情報に置き換えてください。識別情報や認証情報の出力を公開チャットに貼り付けないでください。

```bash
git config --local user.name "コース受講者"
git config --local user.email "learner@example.invalid"
git commit -m "コースラボの基準状態"
git status --short
```

**リセットにGitコマンドは不要です。**メモをラボの外に保存し、展開した練習用コピーを削除して、元のZIPをもう一度展開します。レッスンでの編集後にプログラムの状態が分からなくなった場合に使います。

## 練習場所を保護する

**合成データの例を使います。**個人文書をコースプロジェクトにアップロードしないでください。APIキーをプロンプト、ソースファイル、スクリーンショット、コミットに入れないでください。コーディングエージェントがファイルやコマンドにアクセスできる範囲は、権限と開いたフォルダーによって決まります。実行を許可する前に両方を確認します。

**アップロード前に共有範囲を確認します。**プロジェクトメンバーがファイルを利用できる場合があります。実際の業務では組織の方針に従ってください。コースは架空のデータを使うため、ラボ自体に特別な承認は必要ありません。

## 練習して確認する

**成果物：**選んだルート、5つの事前確認項目、レポートの件数、テスト結果、リセット方法を記録します。新しいラボコピーを使い、リセット方法を理解しているか確認します。

**期待する理解：**コマンドがどのフォルダーに作用するか分かり、ローカルGitとホスティングを区別し、エージェントによる編集の前に復元方法を用意できます。

## 理解度を確認する

1. **質問：**ブラウザーだけの入門でローカルラボルートを完了できますか。**回答：**いいえ。完全なルートにはローカルのPythonとGitの基準状態が必要です。

2. **質問：**使い捨てラボを変更する前に何を保存しますか。**回答：**最初のテストに合格した結果と、クリーンなリセット地点です。

## トラブルシューティング

- **Pythonコマンドが見つからない：**公式配布元からPython 3をインストールし、ターミナルを開き直します。
- **ファイルが見つからない：**作業ディレクトリを確認し、展開フォルダーのファイル一覧を表示します。
- **テストが動かない：**展開したラボのREADMEに記載されたコマンドをそのまま使います。
- **Gitがコミット用の識別情報を求める：**Gitをローカル設定し、選んだ値をコースメモに残さないでください。
