**Windows Server ਵਾਤਾਵਰਣ ਦੀ ਸੁਰੱਖਿਆ: ਪ੍ਰਭਾਵਸ਼ਾਲੀ ਹਾਰਡਨਿੰਗ ਦੇ ਵਧੀਆ ਅਮਲ**

Windows Server ਵਾਤਾਵਰਣਾਂ ਦੀ ਸੁਰੱਖਿਆ **ਸੰਸਥਾਵਾਂ ਲਈ ਲਾਜ਼ਮੀ ਹੈ**, ਤਾਂ ਜੋ ਉਹ ਆਪਣਾ ਡਾਟਾ ਬਚਾ ਸਕਣ ਅਤੇ **ਆਈਟੀ ਢਾਂਚੇ ਦੀ ਅਖੰਡਤਾ ਕਾਇਮ ਰੱਖ ਸਕਣ**। ਇਹ ਲੇਖ **Windows Server ਸੁਰੱਖਿਆ ਦੀ ਮਹੱਤਤਾ**, **ਸਰਵਰ ਹਾਰਡਨਿੰਗ ਦੇ ਆਧਾਰ** ਅਤੇ ਇਸ ਨੂੰ ਪ੍ਰਭਾਵਸ਼ਾਲੀ ਢੰਗ ਨਾਲ ਲਾਗੂ ਕਰਨ ਦੇ ਤਰੀਕੇ ਸਮਝਾਉਂਦਾ ਹੈ। ਇਸ ਵਿੱਚ ਸੁਰੱਖਿਆ ਵਧਾਉਣ ਵਾਲੀਆਂ **ਉੱਨਤ ਤਕਨੀਕਾਂ** ਵੀ ਹਨ। ਇਹ ਕਦਮ **ਆਮ ਖਤਰਿਆਂ ਨੂੰ ਘਟਾਉਂਦੇ**, **ਬਿਨਾਂ ਅਧਿਕਾਰ ਪਹੁੰਚ ਨੂੰ ਸੀਮਿਤ ਕਰਦੇ** ਅਤੇ **ਸੰਵੇਦਨਸ਼ੀਲ ਡਾਟੇ ਦੀ ਰੱਖਿਆ ਕਰਦੇ** ਹਨ।

## Windows Server ਸੁਰੱਖਿਆ ਕਿਉਂ ਮਹੱਤਵਪੂਰਨ ਹੈ

ਬਹੁਤੀਆਂ ਸੰਸਥਾਵਾਂ ਦੇ **ਆਈਟੀ ਢਾਂਚੇ ਵਿੱਚ Windows Server ਦੀ ਕੇਂਦਰੀ ਭੂਮਿਕਾ** ਹੁੰਦੀ ਹੈ। ਇਹ ਫ਼ਾਈਲ ਸਾਂਝੀ ਕਰਨ, ਵਰਤੋਂਕਾਰਾਂ ਦੀ ਪਛਾਣ ਜਾਂਚਣ ਅਤੇ ਐਪਲੀਕੇਸ਼ਨਾਂ ਨੂੰ ਹੋਸਟ ਕਰਨ ਵਰਗੀਆਂ ਜ਼ਰੂਰੀ ਸੇਵਾਵਾਂ ਦਿੰਦਾ ਹੈ। ਇਸ ਲਈ ਇਸ ਦੀਆਂ ਕਮਜ਼ੋਰੀਆਂ ਦੇ **ਗੰਭੀਰ ਨਤੀਜੇ** ਹੋ ਸਕਦੇ ਹਨ। **ਅਸੁਰੱਖਿਅਤ ਸਰਵਰ ਸਾਇਬਰ ਅਪਰਾਧੀਆਂ ਲਈ ਦਾਖ਼ਲੇ ਦਾ ਰਾਹ ਬਣ ਸਕਦਾ ਹੈ**, ਜਿਸ ਰਾਹੀਂ ਉਹ ਸੰਵੇਦਨਸ਼ੀਲ ਜਾਣਕਾਰੀ ਤੱਕ ਪਹੁੰਚ ਕੇ ਪੂਰੇ ਨੈੱਟਵਰਕ ਨੂੰ ਖਤਰੇ ਵਿੱਚ ਪਾ ਸਕਦੇ ਹਨ।

### ਆਈਟੀ ਢਾਂਚੇ ਵਿੱਚ Windows Server ਦੀ ਭੂਮਿਕਾ

Windows Server ਅਕਸਰ ਸੰਸਥਾ ਦੇ **ਆਈਟੀ ਢਾਂਚੇ ਦੀ ਰੀੜ੍ਹ ਦੀ ਹੱਡੀ** ਹੁੰਦਾ ਹੈ। ਇਹ ਅਹਿਮ ਐਪਲੀਕੇਸ਼ਨਾਂ ਨੂੰ ਹੋਸਟ ਕਰਦਾ, ਵਰਤੋਂਕਾਰ ਪਹੁੰਚ ਸੰਭਾਲਦਾ ਅਤੇ ਮੁੱਖ ਸੇਵਾਵਾਂ ਦਿੰਦਾ ਹੈ। Active Directory ਵਾਤਾਵਰਣਾਂ ਵਿੱਚ ਇਹ **ਡੋਮੇਨ ਕੰਟਰੋਲਰ** ਵਜੋਂ ਕੰਮ ਕਰ ਸਕਦਾ ਹੈ ਅਤੇ ਵਰਤੋਂਕਾਰ ਪ੍ਰਬੰਧਨ ਨੂੰ ਕੇਂਦਰੀ ਕਰਦਾ ਹੈ, ਤਾਂ ਜੋ ਸਰੋਤਾਂ ਤੱਕ ਸਿਰਫ਼ ਅਧਿਕਾਰਤ ਕਰਮਚਾਰੀ ਪਹੁੰਚਣ।

ਇਹ **ਨੈੱਟਵਰਕ ਸ਼ੇਅਰ** ਬਣਾਉਣ ਅਤੇ ਸੰਭਾਲਣ ਦੀ ਸਹੂਲਤ ਵੀ ਦਿੰਦਾ ਹੈ, ਜਿਸ ਨਾਲ ਟੀਮਾਂ ਦਾ ਸਹਿਯੋਗ ਆਸਾਨ ਹੁੰਦਾ ਹੈ। ਇਹ ਕਾਰੋਬਾਰ ਦੇ ਕੰਮਾਂ ਲਈ ਅਹਿਮ ਐਪਲੀਕੇਸ਼ਨਾਂ ਵੀ ਚਲਾਉਂਦਾ ਹੈ। ਇਸ ਲਈ ਇਨ੍ਹਾਂ ਸਰਵਰਾਂ ਨੂੰ ਸੁਰੱਖਿਆ ਘਟਨਾਵਾਂ ਤੋਂ ਬਚਾਓ।

ਇਸ ਦਾ ਇੱਕ ਫਾਇਦਾ **ਵਧਾਉਣਯੋਗਤਾ** ਹੈ। ਸੰਸਥਾਵਾਂ ਵਧਦੀਆਂ ਲੋੜਾਂ ਮੁਤਾਬਕ ਹੋਰ ਸਰਵਰ ਜੋੜ ਸਕਦੀਆਂ ਹਨ ਅਤੇ ਢਾਂਚੇ ਦੀ ਸੁਰੱਖਿਆ ਕਾਇਮ ਰੱਖ ਸਕਦੀਆਂ ਹਨ।

Windows Server ਵਰਚੁਅਲਾਈਜ਼ੇਸ਼ਨ ਲਈ ਭਰੋਸੇਯੋਗ ਮੰਚ ਵੀ ਦਿੰਦਾ ਹੈ। ਇਸ ਨਾਲ ਸਰਵਰ ਸਰੋਤ ਇਕੱਠੇ ਹੁੰਦੇ ਹਨ, ਹਾਰਡਵੇਅਰ ਖਰਚ ਘਟਦਾ ਹੈ ਅਤੇ ਪ੍ਰਬੰਧਨ ਸੌਖਾ ਹੁੰਦਾ ਹੈ। ਫਿਰ ਵੀ ਵਰਚੁਅਲ ਵਾਤਾਵਰਣ ਨੂੰ **ਬਿਨਾਂ ਅਧਿਕਾਰ ਪਹੁੰਚ ਅਤੇ ਡਾਟਾ ਲੀਕ ਤੋਂ ਬਚਾਉਣ ਲਈ ਸੁਰੱਖਿਅਤ ਕਰੋ**।

### ਆਮ ਖਤਰੇ

Windows Server ਵਾਤਾਵਰਣ ਕਈ **ਸੁਰੱਖਿਆ ਖਤਰਿਆਂ** ਦਾ ਸਾਹਮਣਾ ਕਰਦੇ ਹਨ:

1. **ਮੈਲਵੇਅਰ ਹਮਲੇ**: ਵਾਇਰਸ ਅਤੇ ਰੈਨਸਮਵੇਅਰ ਸਰਵਰ ਨੂੰ ਲਾਗ ਲਾ ਕੇ ਕੰਮ ਰੋਕ ਸਕਦੇ ਹਨ। ਇਸ ਨਾਲ ਡਾਟਾ ਅਤੇ ਪੈਸੇ ਦਾ ਨੁਕਸਾਨ ਅਤੇ ਸਾਖ ਨੂੰ ਧੱਕਾ ਲੱਗ ਸਕਦਾ ਹੈ।
2. **ਬਰੂਟ-ਫੋਰਸ ਹਮਲੇ**: ਹਮਲਾਵਰ ਵਰਤੋਂਕਾਰ ਨਾਂ ਅਤੇ ਪਾਸਵਰਡ ਦੇ ਕਈ ਜੋੜ ਅਜ਼ਮਾਉਂਦੇ ਹਨ। ਮਜ਼ਬੂਤ ਪਾਸਵਰਡ ਨੀਤੀ, ਬਹੁ-ਕਾਰਕ ਪਛਾਣ ਅਤੇ ਖਾਤਾ ਲਾਕ ਕਰਨਾ ਜੋਖਮ ਘਟਾਉਂਦੇ ਹਨ।
3. **ਬਿਨਾਂ ਅਧਿਕਾਰ ਪਹੁੰਚ**: ਹਮਲਾਵਰ ਕਮਜ਼ੋਰੀਆਂ ਦਾ ਫਾਇਦਾ ਲੈ ਕੇ ਸਰਵਰ ਅਤੇ ਸੰਵੇਦਨਸ਼ੀਲ ਡਾਟੇ ਤੱਕ ਪਹੁੰਚਦੇ ਹਨ। ਸੁਰੱਖਿਆ ਪੈਚ ਨਿਯਮਿਤ ਲਗਾਓ ਅਤੇ ਕਮਜ਼ੋਰੀਆਂ ਦੀ ਜਾਂਚ ਕਰੋ।
4. **ਸੇਵਾ ਰੋਕਣ ਵਾਲੇ ਹਮਲੇ (DoS)**: ਹਮਲਾਵਰ ਬੇਹੱਦ ਟ੍ਰੈਫ਼ਿਕ ਨਾਲ ਸਰਵਰ ਨੂੰ ਭਰ ਦਿੰਦੇ ਹਨ, ਜਿਸ ਨਾਲ ਜਾਇਜ਼ ਵਰਤੋਂਕਾਰ ਉਸ ਤੱਕ ਨਹੀਂ ਪਹੁੰਚਦੇ। ਫ਼ਾਇਰਵਾਲ, ਲੋਡ ਬੈਲੈਂਸਰ ਅਤੇ ਟ੍ਰੈਫ਼ਿਕ ਨਿਗਰਾਨੀ ਹਮਲੇ ਪਛਾਣਣ ਅਤੇ ਘਟਾਉਣ ਵਿੱਚ ਮਦਦ ਕਰਦੇ ਹਨ।
5. **ਅੰਦਰੂਨੀ ਖਤਰੇ**: ਬਦਨੀਅਤ ਜਾਂ ਲਾਪਰਵਾਹ ਕਰਮਚਾਰੀ ਜਾਣਬੁੱਝ ਕੇ ਜਾਂ ਗਲਤੀ ਨਾਲ ਸੁਰੱਖਿਆ ਨੂੰ ਨੁਕਸਾਨ ਪਹੁੰਚਾ ਸਕਦੇ ਹਨ। ਪਹੁੰਚ ਨਿਯੰਤਰਣ, ਵਰਤੋਂਕਾਰ ਸਰਗਰਮੀ ਦੀ ਨਿਗਰਾਨੀ ਅਤੇ ਨਿਯਮਿਤ ਸਿਖਲਾਈ ਜੋਖਮ ਘਟਾਉਂਦੇ ਹਨ।

### ਘੱਟ ਸੁਰੱਖਿਆ ਦੇ ਨਤੀਜੇ

ਸਰਵਰ ਦੀ ਘੱਟ ਸੁਰੱਖਿਆ ਦੇ **ਗੰਭੀਰ ਨਤੀਜੇ** ਹੋ ਸਕਦੇ ਹਨ:

- **ਡਾਟਾ ਉਲੰਘਣਾ**: ਸੰਵੇਦਨਸ਼ੀਲ ਡਾਟੇ ਤੱਕ ਬਿਨਾਂ ਅਧਿਕਾਰ ਪਹੁੰਚ ਨਾਲ ਵਿੱਤੀ ਨੁਕਸਾਨ, ਸਾਖ ਨੂੰ ਨੁਕਸਾਨ ਅਤੇ ਕਾਨੂੰਨੀ ਨਤੀਜੇ ਹੋ ਸਕਦੇ ਹਨ। ਮੁਕੱਦਮੇ, ਨਿਯਮਕ ਜੁਰਮਾਨੇ ਅਤੇ ਗਾਹਕਾਂ ਦਾ ਭਰੋਸਾ ਘਟਣਾ ਵੀ ਸੰਭਵ ਹੈ।
- **ਕੰਮਕਾਜ ਵਿੱਚ ਰੁਕਾਵਟ**: ਸੁਰੱਖਿਆ ਘਟਨਾਵਾਂ ਉਤਪਾਦਕਤਾ ਘਟਾਉਂਦੀਆਂ ਅਤੇ ਆਮਦਨ ਘਟਾ ਸਕਦੀਆਂ ਹਨ। ਡਾਊਨਟਾਈਮ ਨਾਲ ਵਪਾਰਕ ਮੌਕੇ ਗੁਆਚਦੇ ਅਤੇ ਗਾਹਕ ਅਸੰਤੁਸ਼ਟ ਹੁੰਦੇ ਹਨ।
- **ਸਾਖ ਨੂੰ ਨੁਕਸਾਨ**: ਉਲੰਘਣਾ ਗਾਹਕਾਂ ਦਾ ਭਰੋਸਾ ਘਟਾਉਂਦੀ ਅਤੇ ਕਾਰੋਬਾਰੀ ਮੌਕੇ ਸੀਮਿਤ ਕਰ ਸਕਦੀ ਹੈ। ਭਰੋਸਾ ਵਾਪਸ ਬਣਾਉਣ ਲਈ ਸਮਾਂ ਅਤੇ ਮਿਹਨਤ ਲੱਗਦੀ ਹੈ।
- **ਨਿਯਮਾਂ ਦੀ ਉਲੰਘਣਾ**: ਉਦਯੋਗੀ ਨਿਯਮ ਨਾ ਮੰਨਣ ਨਾਲ ਜੁਰਮਾਨੇ ਅਤੇ ਕਾਨੂੰਨੀ ਨਤੀਜੇ ਹੋ ਸਕਦੇ ਹਨ। ਸਰਵਰ ਸੁਰੱਖਿਆ ਨੂੰ ਲਾਗੂ ਮਿਆਰਾਂ ਨਾਲ ਮਿਲਾਓ।

## Windows Server ਹਾਰਡਨਿੰਗ ਦੇ ਆਧਾਰ

ਸਰਵਰ ਹਾਰਡਨਿੰਗ ਦਾ ਮਤਲਬ ਕਮਜ਼ੋਰੀਆਂ ਦੂਰ ਕਰਕੇ ਜਾਂ ਘਟਾ ਕੇ Windows Server ਵਾਤਾਵਰਣ ਨੂੰ ਸੁਰੱਖਿਅਤ ਕਰਨਾ ਹੈ। ਇਸ ਵਿੱਚ **ਸੁਰੱਖਿਆ ਨਿਯੰਤਰਣ, ਸੰਰਚਨਾਵਾਂ ਅਤੇ ਵਧੀਆ ਅਮਲ** ਸ਼ਾਮਲ ਹਨ, ਜੋ ਸੁਰੱਖਿਆ ਹਾਲਤ ਸੁਧਾਰ ਕੇ **ਮਜ਼ਬੂਤ ਬੁਨਿਆਦ** ਬਣਾਉਂਦੇ ਹਨ।

### ਸਰਵਰ ਹਾਰਡਨਿੰਗ ਕੀ ਹੈ?

ਹਾਰਡਨਿੰਗ ਵਿੱਚ Windows Server ਨੂੰ ਬਚਾਉਣ ਦੇ ਕਦਮ ਸ਼ਾਮਲ ਹਨ: ਸਰਵਰ ਦੀ ਸੰਰਚਨਾ ਕਰਨਾ, **ਬੇਲੋੜੀਆਂ ਸੇਵਾਵਾਂ ਹਟਾਉਣਾ**, **ਸੁਰੱਖਿਆ ਅੱਪਡੇਟ ਅਤੇ ਪੈਚ ਲਗਾਉਣਾ**, ਅਤੇ **ਪਹੁੰਚ ਨਿਯੰਤਰਣ** ਲਾਗੂ ਕਰਨਾ। ਮਕਸਦ **ਹਮਲੇ ਦੀ ਸਤ੍ਹਾ ਘਟਾਉਣਾ** ਅਤੇ ਕਮਜ਼ੋਰੀਆਂ ਦੇ ਗਲਤ ਇਸਤੇਮਾਲ ਤੋਂ ਸਰਵਰ ਬਚਾਉਣਾ ਹੈ।

### ਮੁੱਖ ਹਿੱਸੇ

ਹਾਰਡਨ ਕੀਤੇ Windows Server ਵਾਤਾਵਰਣ ਦੇ **ਮੁੱਖ ਹਿੱਸੇ** ਇਹ ਹਨ:

1. **ਸੁਰੱਖਿਆ ਸੰਰਚਨਾਵਾਂ**: ਬੇਲੋੜੀਆਂ ਸੇਵਾਵਾਂ ਬੰਦ ਕਰੋ, [**ਮਜ਼ਬੂਤ ਪਾਸਵਰਡ**](https://simeononsecurity.com/articles/how-to-create-strong-passwords/) ਲਾਜ਼ਮੀ ਕਰੋ ਅਤੇ ਪ੍ਰਸ਼ਾਸਕੀ ਅਧਿਕਾਰ ਘਟਾਓ। ਇਸ ਨਾਲ ਕਮਜ਼ੋਰੀਆਂ ਅਤੇ ਅਧਿਕਾਰ ਵਧਾਉਣ ਦਾ ਜੋਖਮ ਘਟਦਾ ਹੈ।
2. **ਪਹੁੰਚ ਨਿਯੰਤਰਣ**: ਸਿਰਫ਼ ਅਧਿਕਾਰਤ ਵਰਤੋਂਕਾਰਾਂ ਨੂੰ ਸਰਵਰ ਤੱਕ ਪਹੁੰਚ ਦਿਓ। ਪਛਾਣ ਜਾਂਚ, **ਭੂਮਿਕਾ-ਅਧਾਰਿਤ ਪਹੁੰਚ ਨਿਯੰਤਰਣ (RBAC)** ਅਤੇ **ਘੱਟੋ-ਘੱਟ ਅਧਿਕਾਰ ਦਾ ਸਿਧਾਂਤ (PoLP)** ਵਰਤੋ।
3. **ਸੁਰੱਖਿਆ ਅੱਪਡੇਟ ਅਤੇ ਪੈਚ**: ਓਪਰੇਟਿੰਗ ਸਿਸਟਮ ਅਤੇ ਸੌਫਟਵੇਅਰ ਦੀਆਂ ਜਾਣੀਆਂ ਕਮਜ਼ੋਰੀਆਂ ਠੀਕ ਕਰਨ ਲਈ ਇਨ੍ਹਾਂ ਨੂੰ ਨਿਯਮਿਤ ਲਗਾਓ।
4. **ਨਿਗਰਾਨੀ ਅਤੇ ਲੌਗਿੰਗ**: ਸਿਸਟਮ ਸਰਗਰਮੀ ਵੇਖੋ ਅਤੇ ਲੌਗਾਂ ਦੀ ਜਾਂਚ ਕਰੋ, ਤਾਂ ਜੋ ਖਤਰੇ ਅਤੇ ਸ਼ੱਕੀ ਵਰਤਾਰਾ ਜਲਦੀ ਲੱਭੇ।
5. **ਬੈਕਅੱਪ ਅਤੇ ਰੀਕਵਰੀ**: ਅਹਿਮ ਡਾਟੇ ਦਾ ਨਿਯਮਿਤ ਬੈਕਅੱਪ ਲਓ ਅਤੇ ਘਟਨਾ ਜਾਂ ਸਿਸਟਮ ਨਾਕਾਮੀ ਤੋਂ ਬਾਅਦ ਡਾਊਨਟਾਈਮ ਘਟਾਉਣ ਲਈ ਰੀਕਵਰੀ ਯੋਜਨਾ ਰੱਖੋ।

### ਹਾਰਡਨਿੰਗ ਦੀ ਪ੍ਰਕਿਰਿਆ

**Windows Server** ਵਾਤਾਵਰਣ ਨੂੰ ਹਾਰਡਨ ਕਰਨ ਲਈ ਇਹ ਕਦਮ ਲਵੋ:

1. **ਕਮਜ਼ੋਰੀਆਂ ਪਛਾਣੋ**: ਮੌਜੂਦਾ ਸੁਰੱਖਿਆ ਹਾਲਤ ਦੀ ਜਾਂਚ ਕਰੋ। ਕਮਜ਼ੋਰੀ ਮੁਲਾਂਕਣ ਅਤੇ ਪੈਨੀਟ੍ਰੇਸ਼ਨ ਟੈਸਟ ਕਮਜ਼ੋਰ ਥਾਵਾਂ ਲੱਭਣ ਵਿੱਚ ਮਦਦ ਕਰਦੇ ਹਨ।
2. **ਯੋਜਨਾ ਬਣਾਓ**: ਉਪਾਅ ਤੈਅ ਕਰੋ, ਗੰਭੀਰ ਕਮਜ਼ੋਰੀਆਂ ਨੂੰ ਪਹਿਲ ਦਿਓ ਅਤੇ ਠੀਕ ਕਰਨ ਦੇ ਕਦਮ ਨਿਰਧਾਰਤ ਕਰੋ।
3. **ਸਰਵਰ ਸੰਰਚਿਤ ਕਰੋ**: ਬੇਲੋੜੀਆਂ ਸੇਵਾਵਾਂ ਬੰਦ ਕਰੋ, ਟ੍ਰੈਫ਼ਿਕ ਨਿਯੰਤਰਣ ਲਈ ਫ਼ਾਇਰਵਾਲ ਲਗਾਓ ਅਤੇ ਸਿਸਟਮ ਘਟਨਾਵਾਂ ਦਰਜ ਕਰਨ ਲਈ ਆਡਿਟ ਨੀਤੀਆਂ ਚਾਲੂ ਕਰੋ।
4. **ਸੁਰੱਖਿਆ ਅੱਪਡੇਟ ਲਗਾਓ**: ਵਿਕਰੇਤਾਵਾਂ ਦੇ ਨਵੀਨਤਮ ਸੁਧਾਰਾਂ ਨਾਲ ਓਪਰੇਟਿੰਗ ਸਿਸਟਮ ਅਤੇ ਸੌਫਟਵੇਅਰ ਅੱਪਡੇਟ ਰੱਖੋ।
5. **ਪਹੁੰਚ ਨਿਯੰਤਰਣ ਲਾਗੂ ਕਰੋ**: ਪਹੁੰਚ ਸਿਰਫ਼ ਅਧਿਕਾਰਤ ਵਰਤੋਂਕਾਰਾਂ ਤੱਕ ਰੱਖੋ। ਪਛਾਣ ਜਾਂਚ, ਘੱਟੋ-ਘੱਟ ਅਧਿਕਾਰ ਅਤੇ ਮਜ਼ਬੂਤ ਪਾਸਵਰਡ ਨੀਤੀਆਂ ਅਪਣਾਓ।
6. **ਸੁਰੱਖਿਆ ਘਟਨਾਵਾਂ ਦੀ ਨਿਗਰਾਨੀ ਅਤੇ ਜਵਾਬ**: ਨਿਗਰਾਨੀ ਸਾਧਨ ਲਗਾਓ, ਸ਼ੱਕੀ ਸਰਗਰਮੀ ਲਈ ਲੌਗ ਵੇਖੋ ਅਤੇ ਘਟਨਾ-ਜਵਾਬ ਯੋਜਨਾ ਤਿਆਰ ਰੱਖੋ।

**ਇਹ ਕਦਮ** Windows Server ਦੀ ਸੁਰੱਖਿਆ ਸੁਧਾਰਦੇ ਅਤੇ ਉਲੰਘਣਾ ਦਾ ਜੋਖਮ ਘਟਾਉਂਦੇ ਹਨ।

## Windows Server ਹਾਰਡਨਿੰਗ ਦੇ ਵਧੀਆ ਅਮਲ

Windows Server ਨੂੰ ਪ੍ਰਭਾਵਸ਼ਾਲੀ ਢੰਗ ਨਾਲ ਸੁਰੱਖਿਅਤ ਕਰਨ ਲਈ ਇਹ **ਵਧੀਆ ਅਮਲ** ਅਪਣਾਓ।

### ਸਰਵਰ ਨਿਯਮਿਤ ਅੱਪਡੇਟ ਕਰੋ

ਜਾਣੀਆਂ ਕਮਜ਼ੋਰੀਆਂ ਠੀਕ ਕਰਨ ਲਈ ਸੁਰੱਖਿਆ ਅੱਪਡੇਟ ਅਤੇ ਪੈਚ ਤੁਰੰਤ ਲਗਾਓ। ਨਿਯਮਿਤ **ਪੈਚ ਪ੍ਰਬੰਧਨ ਪ੍ਰਕਿਰਿਆ** ਅੱਪਡੇਟ ਸਮੇਂ ਸਿਰ ਲਾਗੂ ਕਰਦੀ ਹੈ।

ਅੱਪਡੇਟ **ਕਾਰਗੁਜ਼ਾਰੀ ਅਤੇ ਸਥਿਰਤਾ** ਸੁਧਾਰ ਸਕਦੇ ਹਨ ਅਤੇ ਨਵੇਂ ਖਤਰਿਆਂ ਲਈ ਤਿਆਰੀ ਕਰਦੇ ਹਨ। **ਕਮਜ਼ੋਰੀ ਪ੍ਰਬੰਧਨ ਸਾਧਨ** ਕਮਜ਼ੋਰ ਥਾਵਾਂ ਅਤੇ ਗਲਤ ਸੰਰਚਨਾਵਾਂ ਲੱਭ ਕੇ ਸੁਧਾਰਾਂ ਨੂੰ ਤਰਜੀਹ ਦੇਣ ਵਿੱਚ ਮਦਦ ਕਰਦੇ ਹਨ।

### ਪਹੁੰਚ ਅਧਿਕਾਰ ਸੀਮਿਤ ਕਰੋ

**ਘੱਟੋ-ਘੱਟ ਅਧਿਕਾਰ ਦਾ ਸਿਧਾਂਤ** ਹਰ ਭੂਮਿਕਾ ਨੂੰ ਸਿਰਫ਼ ਲੋੜੀਂਦੇ ਅਧਿਕਾਰ ਦਿੰਦਾ ਹੈ। ਇਸ ਨੂੰ ਮਜ਼ਬੂਤ ਪਛਾਣ ਜਾਂਚ ਅਤੇ ਭੂਮਿਕਾ-ਅਧਾਰਿਤ ਨਿਯੰਤਰਣ ਨਾਲ ਜੋੜੋ। ਅਧਿਕਾਰਾਂ ਦੀ ਨਿਯਮਿਤ ਸਮੀਖਿਆ ਕਰੋ।

ਹਰ ਵਰਤੋਂਕਾਰ ਨੂੰ ਕੰਮ ਲਈ ਸਿਰਫ਼ **ਘੱਟੋ-ਘੱਟ ਲੋੜੀਂਦੇ ਅਧਿਕਾਰ** ਦਿਓ। ਖਾਤਾ ਕਬਜ਼ੇ ਵਿੱਚ ਆਉਣ 'ਤੇ ਸੰਭਾਵੀ ਨੁਕਸਾਨ ਸੀਮਿਤ ਰਹੇਗਾ।

**ਬਹੁ-ਕਾਰਕ ਪਛਾਣ (MFA)** ਵਰਤਣ ਬਾਰੇ ਸੋਚੋ। ਇਹ ਪਾਸਵਰਡ ਦੇ ਨਾਲ ਉਂਗਲ ਛਾਪ ਜਾਂ ਇੱਕ ਵਾਰ ਵਰਤਿਆ ਜਾਣ ਵਾਲਾ ਕੋਡ ਵੀ ਮੰਗਦੀ ਹੈ।

**ਖਾਤਿਆਂ** ਦਾ ਆਡਿਟ ਕਰੋ, ਬੇਲੋੜੇ ਅਧਿਕਾਰ ਹਟਾਓ ਅਤੇ ਸ਼ੱਕੀ ਸਰਗਰਮੀ ਵੇਖੋ।

### ਫ਼ਾਇਰਵਾਲ ਅਤੇ ਘੁਸਪੈਠ ਪਛਾਣ ਪ੍ਰਣਾਲੀਆਂ ਵਰਤੋ

**ਫ਼ਾਇਰਵਾਲ** ਸਰਵਰ ਅਤੇ ਬਾਹਰੀ ਨੈੱਟਵਰਕ ਵਿਚਕਾਰ ਟ੍ਰੈਫ਼ਿਕ ਫਿਲਟਰ ਕਰਦੇ ਹਨ। **ਘੁਸਪੈਠ ਪਛਾਣ ਪ੍ਰਣਾਲੀਆਂ (IDS)** ਨੈੱਟਵਰਕ ਟ੍ਰੈਫ਼ਿਕ ਵੇਖ ਕੇ ਸੰਭਾਵੀ ਘਟਨਾਵਾਂ ਦੀ ਸੂਚਨਾ ਦਿੰਦੀਆਂ ਹਨ। ਦੋਵੇਂ ਮਿਲ ਕੇ ਸੁਰੱਖਿਆ ਮਜ਼ਬੂਤ ਕਰਦੇ ਹਨ।

**ਫ਼ਾਇਰਵਾਲ ਚੁਣੇ** ਹੋਏ ਪੋਰਟ, ਪ੍ਰੋਟੋਕੋਲ ਜਾਂ IP ਪਤੇ ਮਨਜ਼ੂਰ ਜਾਂ ਰੋਕ ਸਕਦਾ ਹੈ। IDS ਸ਼ੱਕੀ ਸਰਗਰਮੀ ਅਤੇ ਜਾਣੇ-ਪਛਾਣੇ ਹਮਲਾ ਪੈਟਰਨ ਲੱਭ ਕੇ ਪ੍ਰਸ਼ਾਸਕਾਂ ਨੂੰ ਚੇਤਾਵਨੀ ਦੇ ਸਕਦਾ ਹੈ।

**ਇਨ੍ਹਾਂ** ਸਾਧਨਾਂ ਨੂੰ ਨਿਯਮਿਤ ਅੱਪਡੇਟ ਅਤੇ ਸੰਰਚਿਤ ਕਰੋ। ਖਤਰੇ ਦੀ ਜਾਣਕਾਰੀ ਤਾਜ਼ਾ ਰੱਖੋ, ਨਿਯਮ ਸੁਧਾਰੋ ਅਤੇ ਪੈਨੀਟ੍ਰੇਸ਼ਨ ਟੈਸਟ ਕਰੋ।

### ਸੰਵੇਦਨਸ਼ੀਲ ਡਾਟਾ ਇਨਕ੍ਰਿਪਟ ਕਰੋ

**ਡਾਟਾ ਇਨਕ੍ਰਿਪਸ਼ਨ** ਬਿਨਾਂ ਅਧਿਕਾਰ ਪਹੁੰਚ ਹੋਣ 'ਤੇ ਵੀ ਸੰਵੇਦਨਸ਼ੀਲ ਜਾਣਕਾਰੀ ਨੂੰ ਨਾ-ਪੜ੍ਹਨਯੋਗ ਰੱਖਦਾ ਹੈ। ਇਹ **ਨਿੱਜੀ ਪਛਾਣ ਜਾਣਕਾਰੀ (PII)**, ਵਿੱਤੀ ਡਾਟੇ ਅਤੇ ਬੌਧਿਕ ਸੰਪਤੀ ਲਈ ਅਹਿਮ ਹੈ। ਸੰਭਾਲੇ ਅਤੇ ਭੇਜੇ ਜਾ ਰਹੇ ਡਾਟੇ ਨੂੰ ਇਨਕ੍ਰਿਪਟ ਕਰੋ।

Windows Server ਡਿਸਕ ਇਨਕ੍ਰਿਪਸ਼ਨ ਲਈ **BitLocker** ਅਤੇ ਫ਼ਾਈਲ ਇਨਕ੍ਰਿਪਸ਼ਨ ਲਈ **Encrypting File System (EFS)** ਦਿੰਦਾ ਹੈ। ਇਨ੍ਹਾਂ ਨੂੰ ਠੀਕ ਸੰਰਚਿਤ ਅਤੇ ਪ੍ਰਬੰਧਿਤ ਕਰੋ, ਕੁੰਜੀਆਂ ਸੁਰੱਖਿਅਤ ਰੱਖੋ ਅਤੇ ਇਨਕ੍ਰਿਪਟ ਕੀਤੇ ਡਾਟੇ ਦਾ ਬੈਕਅੱਪ ਲਵੋ।

**ਡਾਟਾ ਨੁਕਸਾਨ ਰੋਕਥਾਮ (DLP)** ਹੱਲ ਈਮੇਲ, ਸੁਨੇਹਿਆਂ ਅਤੇ ਹੋਰ ਰਸਤਿਆਂ ਰਾਹੀਂ ਸੰਵੇਦਨਸ਼ੀਲ ਜਾਣਕਾਰੀ ਭੇਜਣ ਦੇ ਬਿਨਾਂ ਅਧਿਕਾਰ ਯਤਨਾਂ ਨੂੰ ਲੱਭ ਜਾਂ ਰੋਕ ਸਕਦੇ ਹਨ।

## Windows Server ਸੁਰੱਖਿਆ ਦੀਆਂ ਉੱਨਤ ਤਕਨੀਕਾਂ

ਸੰਗਠਨ Windows Server ਦੀ ਸੁਰੱਖਿਆ ਹੋਰ ਮਜ਼ਬੂਤ ਕਰਨ ਲਈ **ਉੱਨਤ ਤਕਨੀਕਾਂ** ਅਪਣਾ ਸਕਦੇ ਹਨ।

### ਨੈੱਟਵਰਕ ਵੰਡੋ

ਨੈੱਟਵਰਕ ਸੈਗਮੈਂਟੇਸ਼ਨ ਨੈੱਟਵਰਕ ਨੂੰ ਆਪਣੇ ਸੁਰੱਖਿਆ ਨਿਯੰਤਰਣ ਵਾਲੇ ਛੋਟੇ, ਅਲੱਗ ਹਿੱਸਿਆਂ ਵਿੱਚ ਵੰਡਦੀ ਹੈ। ਇਸ ਨਾਲ ਉਲੰਘਣਾ ਦਾ **ਅਸਰ ਸੀਮਿਤ** ਹੁੰਦਾ ਹੈ ਅਤੇ ਬਿਨਾਂ ਅਧਿਕਾਰ ਪਾਸੇ ਵੱਲ ਵਧਣਾ ਰੁਕਦਾ ਹੈ।

### SIEM ਸਾਧਨ ਵਰਤੋ

**ਸੁਰੱਖਿਆ ਜਾਣਕਾਰੀ ਅਤੇ ਘਟਨਾ ਪ੍ਰਬੰਧਨ (SIEM)** ਸਾਧਨ ਕਈ ਸਰੋਤਾਂ ਤੋਂ ਲੌਗ ਇਕੱਠੇ ਅਤੇ ਵਿਸ਼ਲੇਸ਼ਣ ਕਰਕੇ ਤੁਰੰਤ ਦ੍ਰਿਸ਼ਟੀ ਦਿੰਦੇ ਹਨ। ਇਹ ਘਟਨਾਵਾਂ ਲੱਭਣ, ਜਾਂਚ ਕਰਨ ਅਤੇ ਜਲਦੀ ਜਵਾਬ ਦੇਣ ਵਿੱਚ ਮਦਦ ਕਰਦੇ ਹਨ।

### ਖਤਰੇ ਪਛਾਣਨ ਲਈ AI ਵਰਤੋ

**ਕ੍ਰਿਤ੍ਰਿਮ ਬੁੱਧੀ (AI)** ਵੱਡੀ ਮਾਤਰਾ ਵਿੱਚ ਡਾਟਾ ਵੇਖ ਕੇ ਨੁਕਸਾਨਦਾਇਕ ਸਰਗਰਮੀ ਦੇ ਸੰਕੇਤ ਪਛਾਣ ਸਕਦੀ ਹੈ। AI ਹੱਲ ਮਨੁੱਖੀ ਮਿਹਨਤ ਦੀ ਮਦਦ ਕਰਦੇ ਅਤੇ ਸੰਭਾਵੀ ਉਲੰਘਣਾ ਬਾਰੇ ਪਹਿਲਾਂ ਚੇਤਾਵਨੀ ਦੇ ਸਕਦੇ ਹਨ।

## ਸਰਵਰ ਦੀ ਭੂਮਿਕਾ ਮੁਤਾਬਕ ਨਿਯੰਤਰਣ ਦਾ ਕ੍ਰਮ

**ਸਰਵਰ ਹਾਰਡਨਿੰਗ** ਉਸ ਦੀ ਭੂਮਿਕਾ ਅਨੁਸਾਰ ਹੋਣੀ ਚਾਹੀਦੀ ਹੈ। ਡੋਮੇਨ ਕੰਟਰੋਲਰ, ਮੈਂਬਰ ਸਰਵਰ, ਫ਼ਾਈਲ ਸਰਵਰ, ਡਾਟਾਬੇਸ ਹੋਸਟ ਅਤੇ ਵਰਕਗਰੁੱਪ ਸਰਵਰਾਂ ਦੀਆਂ ਨਿਰਭਰਤਾਵਾਂ ਅਤੇ ਖੁੱਲ੍ਹੇਪਣ ਵੱਖਰੇ ਹਨ।

1. ਸਰਵਰ ਦੀ ਭੂਮਿਕਾ, ਸੁਣਨ ਵਾਲੇ ਪੋਰਟ, ਇੰਸਟਾਲ ਭੂਮਿਕਾਵਾਂ, ਤਹਿ ਕੀਤੇ ਕੰਮ, ਸੇਵਾ ਖਾਤੇ, ਦੂਰ-ਪ੍ਰਬੰਧਨ ਰਾਹ ਅਤੇ ਬੈਕਅੱਪ ਟਿਕਾਣੇ ਦਰਜ ਕਰੋ।
2. ਰੱਖ-ਰਖਾਅ ਸਮੇਂ ਅੱਪਡੇਟ ਲਗਾਓ। ਦੂਰ-ਪਹੁੰਚ ਬਦਲਣ ਤੋਂ ਪਹਿਲਾਂ ਕੰਸੋਲ ਜਾਂ ਆਫ਼-ਬੈਂਡ ਪਹੁੰਚ ਪੱਕੀ ਕਰੋ।
3. ਭੂਮਿਕਾ ਮੁਤਾਬਕ Microsoft ਸੁਰੱਖਿਆ ਬੇਸਲਾਈਨ ਵਰਤੋ। [Security Compliance Toolkit](https://learn.microsoft.com/windows/security/operating-system-security/device-management/windows-security-configuration-framework/security-compliance-toolkit-10) Windows Server 2016, 2019, 2022 ਅਤੇ 2025 ਬੇਸਲਾਈਨਾਂ ਦਾ ਸਮਰਥਨ ਕਰਦਾ ਹੈ।
4. ਵੱਖਰੇ ਖਾਤਿਆਂ ਨਾਲ ਪ੍ਰਸ਼ਾਸਕੀ ਪਹੁੰਚ ਬਚਾਓ, ਜਿੱਥੇ ਸਮਰਥਿਤ ਹੋਵੇ MFA ਵਰਤੋ, ਸਥਾਨਕ ਪ੍ਰਸ਼ਾਸਕ ਪਾਸਵਰਡ ਲਈ Windows LAPS ਲਗਾਓ ਅਤੇ ਪ੍ਰਬੰਧਿਤ ਪ੍ਰਸ਼ਾਸਕੀ ਵਰਕਸਟੇਸ਼ਨ ਵਰਤੋ।
5. RDP, WinRM, SMB, LDAP, ਡਾਟਾਬੇਸ ਪੋਰਟ ਅਤੇ ਪ੍ਰਬੰਧਨ ਇੰਟਰਫੇਸ ਮਨਜ਼ੂਰ ਨੈੱਟਵਰਕ ਤੱਕ ਸੀਮਿਤ ਕਰੋ। ਫ਼ਾਈਲ ਸੇਵਾਵਾਂ ਲਈ ਨਵੀਂ SMB ਸੁਰੱਖਿਆ ਲਾਜ਼ਮੀ ਕਰੋ।
6. ਉਤਪਾਦਨ ਟ੍ਰੈਫ਼ਿਕ ਆਉਣ ਤੋਂ ਪਹਿਲਾਂ ਆਡਿਟ ਨੀਤੀ, ਕੇਂਦਰੀ ਲੌਗ ਭੇਜਣਾ, Defender ਸੁਰੱਖਿਆ, ਫ਼ਾਇਰਵਾਲ ਲੌਗ ਅਤੇ ਚੇਤਾਵਨੀਆਂ ਚਾਲੂ ਕਰੋ।
7. ਬੈਕਅੱਪ ਰੀਸਟੋਰ, ਸੇਵਾ ਮੁੜ ਚਾਲੂ ਕਰਨਾ, ਡੋਮੇਨ ਪਛਾਣ, ਐਪਲੀਕੇਸ਼ਨ ਸਿਹਤ ਅਤੇ ਫੇਲਓਵਰ ਦੀ ਜਾਂਚ ਕਰੋ।

**Microsoft ਦੀ** [Windows Server ਸੁਰੱਖਿਆ ਮਾਰਗਦਰਸ਼ਿਕਾ](https://learn.microsoft.com/en-us/windows-server/security/security-and-assurance) ਅੰਦਰੂਨੀ ਸੁਰੱਖਿਆ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ ਬਾਰੇ ਦੱਸਦੀ ਹੈ। Microsoft ਸਿਖਲਾਈ ਵਿੱਚ LAPS, ਵਿਸ਼ੇਸ਼ ਅਧਿਕਾਰ ਪ੍ਰਬੰਧਨ, ਡੋਮੇਨ ਕੰਟਰੋਲਰ ਸੁਰੱਖਿਆ, ਸੁਰੱਖਿਆ ਬੇਸਲਾਈਨ ਅਤੇ SMB 3.1.1 ਸੁਰੱਖਿਆ ਸ਼ਾਮਲ ਹਨ। ਵਿਕਰੇਤਾ ਦੀ ਬੇਸਲਾਈਨ ਨੂੰ ਸ਼ੁਰੂਆਤ ਮੰਨੋ ਅਤੇ ਲਾਗੂ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਸਰਵਰ ਭੂਮਿਕਾ ਨਾਲ ਅਨੁਕੂਲਤਾ ਪਰਖੋ।

## ਡੋਮੇਨ ਕੰਟਰੋਲਰ ਅਤੇ ਮੈਂਬਰ ਸਰਵਰ ਵਿੱਚ ਫ਼ਰਕ

| ਸਰਵਰ ਭੂਮਿਕਾ | ਪਹਿਲ ਦੇ ਨਿਯੰਤਰਣ | ਬਦਲਾਅ ਦਾ ਜੋਖਮ |
|-------------|---------------------|-----------------|
| **ਡੋਮੇਨ ਕੰਟਰੋਲਰ** | AD DS, SYSVOL, DNS, ਪ੍ਰਤੀਕ੍ਰਿਤੀ, ਵਿਸ਼ੇਸ਼ ਅਧਿਕਾਰ ਵਾਲੇ ਸਮੂਹ ਅਤੇ ਭੌਤਿਕ ਜਾਂ ਵਰਚੁਅਲ ਕੰਸੋਲ ਪਹੁੰਚ ਬਚਾਓ | ਗਲਤ ਨੀਤੀ ਜਾਂ ਪਛਾਣ ਬਦਲਾਅ ਡੋਮੇਨ ਨੂੰ ਪ੍ਰਭਾਵਿਤ ਕਰਦਾ ਹੈ |
| **ਮੈਂਬਰ ਸਰਵਰ** | ਸਥਾਨਕ ਪ੍ਰਸ਼ਾਸਨ, ਸੇਵਾ ਖਾਤੇ, SMB, RDP, WinRM ਅਤੇ ਐਪਲੀਕੇਸ਼ਨ ਪੋਰਟ ਸੀਮਿਤ ਕਰੋ | ਐਪਲੀਕੇਸ਼ਨ ਅਤੇ ਡੋਮੇਨ ਨਿਰਭਰਤਾਵਾਂ ਕੰਮ ਮੁਤਾਬਕ ਬਦਲਦੀਆਂ ਹਨ |
| **ਫ਼ਾਈਲ ਸਰਵਰ** | SMB ਦਸਤਖਤ ਜਾਂ ਇਨਕ੍ਰਿਪਸ਼ਨ, ਸਾਂਝੇ ਸਰੋਤ ਅਤੇ NTFS ACL ਦੀ ਸਮੀਖਿਆ, ਰੈਨਸਮਵੇਅਰ ਸੁਰੱਖਿਆ, ਸਨੈਪਸ਼ਾਟ ਅਤੇ ਰੀਸਟੋਰ ਟੈਸਟ | ਸਾਂਝੇ ਸਰੋਤ ਅਤੇ NTFS ਦੇ ਅਧਿਕਾਰ ਇਕੱਠੇ ਲਾਗੂ ਹੁੰਦੇ ਹਨ |
| **ਵਰਕਗਰੁੱਪ ਸਰਵਰ** | ਸਥਾਨਕ ਖਾਤੇ ਵੱਖਰੇ, ਪ੍ਰਸ਼ਾਸਕ ਪਾਸਵਰਡ ਵਿਲੱਖਣ, ਫ਼ਾਇਰਵਾਲ ਮਨਜ਼ੂਰੀ ਸੂਚੀ, ਪੈਚ ਅਤੇ ਕੰਸੋਲ ਰੀਕਵਰੀ | ਡੋਮੇਨ ਨੀਤੀ ਨਾਲ ਕੇਂਦਰੀ ਰੀਕਵਰੀ ਨਹੀਂ ਹੁੰਦੀ |

## ਸੇਵਾ ਬਦਲਾਅ ਵਾਪਸ ਕਰਨ ਦੀ ਯੋਜਨਾ

**ਸੇਵਾ ਬੰਦ** ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਇਸ ਦੀ ਮੌਜੂਦਾ ਸੰਰਚਨਾ, ਨਿਰਭਰਤਾਵਾਂ, ਰੀਕਵਰੀ ਕਦਮ, ਸੇਵਾ ਖਾਤਾ, ਚਲਾਉਣ ਵਾਲੀ ਫ਼ਾਈਲ ਦਾ ਰਾਹ ਅਤੇ ਕੰਮ ਦੇ ਜ਼ਿੰਮੇਵਾਰ ਵਿਅਕਤੀ ਨੂੰ ਦਰਜ ਕਰੋ। ਪਾਇਲਟ ਸਰਵਰ ਜਾਂ ਰੱਖ-ਰਖਾਅ ਸਮੇਂ ਜਾਂਚੋ। ਆਮ debloat ਸੂਚੀ ਦੇ ਆਧਾਰ 'ਤੇ ਡੋਮੇਨ ਕੰਟਰੋਲਰ ਜਾਂ ਉਤਪਾਦਨ ਐਪਲੀਕੇਸ਼ਨ ਹੋਸਟ ਦੀ ਸੇਵਾ ਬੰਦ ਨਾ ਕਰੋ।

```powershell
$name = 'Spooler'
Get-CimInstance Win32_Service -Filter "Name='$name'" |
    Select-Object Name, State, StartMode, StartName, PathName, ExitCode |
    Export-Csv "C:\Temp\$name-before.csv" -NoTypeInformation
Get-Service -Name $name -RequiredServices
Get-Service -Name $name -DependentServices
```

ਪੁਰਾਣਾ ਸਟਾਰਟਅੱਪ ਮੋਡ ਲਿਖੋ। ਜੇ ਸੇਵਾ ਕਦੇ-ਕਦੇ ਚਾਹੀਦੀ ਹੋਵੇ ਤਾਂ **Manual** ਚੁਣੋ। ਬਦਲਾਅ ਤੋਂ ਬਾਅਦ ਪਛਾਣ, ਨਾਂ ਦੀ ਖੋਜ, ਫ਼ਾਈਲ ਸ਼ੇਅਰ, ਤਹਿ ਕੀਤੇ ਕੰਮ, ਨਿਗਰਾਨੀ, ਬੈਕਅੱਪ ਅਤੇ ਐਪਲੀਕੇਸ਼ਨ ਦੀ ਜਾਂਚ ਕਰੋ। `Set-Service` ਨਾਲ ਪੁਰਾਣਾ ਮੋਡ ਵਾਪਸ ਲਿਆਓ, ਸੇਵਾ ਚਾਲੂ ਕਰੋ ਅਤੇ System ਅਤੇ Service Control Manager ਲੌਗ ਵੇਖੋ। Microsoft [`sc.exe config`](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/sc-config) ਵਿੱਚ ਸੇਵਾ ਸੰਰਚਨਾ ਬਾਰੇ ਦੱਸਦਾ ਹੈ।

## Windows Server 2025 ਬੇਸਲਾਈਨ ਵਿਕਲਪ

**Windows Server** 2025 ਡੋਮੇਨ ਕੰਟਰੋਲਰਾਂ, ਮੈਂਬਰ ਸਰਵਰਾਂ ਅਤੇ ਵਰਕਗਰੁੱਪ ਪ੍ਰਣਾਲੀਆਂ ਲਈ ਭੂਮਿਕਾ-ਅਨੁਸਾਰ OSConfig ਸੁਰੱਖਿਆ ਬੇਸਲਾਈਨ ਦਿੰਦਾ ਹੈ। Microsoft ਦੱਸਦਾ ਹੈ ਕਿ OSConfig ਪੁਰਾਣੇ ਸਰਵਰ ਸੰਸਕਰਣਾਂ ਨੂੰ ਸਮਰਥਨ ਨਹੀਂ ਦਿੰਦਾ। ਸਮਰਥਿਤ ਪੁਰਾਣੇ ਸੰਸਕਰਣਾਂ ਲਈ Security Compliance Toolkit ਵਰਤੋ। [Windows Server 2025 ਬੇਸਲਾਈਨ ਮਾਰਗਦਰਸ਼ਿਕਾ](https://learn.microsoft.com/en-us/windows-server/security/osconfig/osconfig-how-to-configure-security-baselines?tabs=configure) ਪੜ੍ਹੋ, ਆਪਣੀ ਭੂਮਿਕਾ ਵਾਲਾ ਦ੍ਰਿਸ਼ ਜਾਂਚੋ ਅਤੇ ਲਾਗੂ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਹਟਾਉਣ ਦੀ ਪ੍ਰਕਿਰਿਆ ਤਿਆਰ ਰੱਖੋ।

## ਸਿੱਟਾ

Windows Server ਨੂੰ ਸੁਰੱਖਿਅਤ ਕਰਨ ਨਾਲ **ਸੰਵੇਦਨਸ਼ੀਲ ਡਾਟਾ ਬਚਦਾ, ਕੰਮਕਾਜ ਦੀ ਨਿਰੰਤਰਤਾ ਕਾਇਮ ਰਹਿੰਦੀ** ਅਤੇ **ਸੰਸਥਾ ਦੀ ਸਾਖ ਦੀ ਰੱਖਿਆ ਹੁੰਦੀ** ਹੈ। ਹਾਰਡਨਿੰਗ ਉਲੰਘਣਾ ਦਾ ਜੋਖਮ ਘਟਾਉਂਦੀ ਹੈ। ਨੈੱਟਵਰਕ ਸੈਗਮੈਂਟੇਸ਼ਨ, SIEM ਅਤੇ AI ਹੱਲ ਬਦਲਦੇ ਖਤਰਿਆਂ ਵਿਰੁੱਧ ਹੋਰ ਬਚਾਅ ਦਿੰਦੇ ਹਨ। ਪਹਿਲਾਂ ਤੋਂ ਸੁਰੱਖਿਆ ਕਦਮ ਚੁੱਕਣ ਨਾਲ ਅਹਿਮ ਪ੍ਰਣਾਲੀਆਂ ਦੀ **ਅਖੰਡਤਾ ਅਤੇ ਗੁਪਤਤਾ** ਬਚਦੀ ਹੈ।
