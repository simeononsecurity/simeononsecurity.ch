**根据任务和所需访问权限选择专用代理。** 检查一个文件的工作代理，与接收消息、保存记忆并执行计划操作的持久系统不同。本选修课以 OpenClaw 和 Hermes Agent 为例，并提供安装前评估工作表。

**学习目标：** 比较代理的访问权限和触发条件，并记录一项范围有限的试点决定。

## 要点

- **限定角色的工作代理：** 负责一个问题或产物的代理。
- **持久代理：** 保留状态或响应后续触发条件的服务或会话。
- **触发条件：** 启动工作的事件、消息或计划。
- **访问清单：** 代理获得的工具、账户、文件和写入权限列表。
- **试点决定：** 拒绝、开展有限测试，或批准明确用途。

## 开始之前

**前置条件：** [委派](/articles/effective-ai-agent-delegation/)、[有界代理循环](/articles/effective-ai-bounded-agent-loops/)和一个虚构用例。预留 35 分钟。难度为中级。本课不要求安装持久代理。

**用例：** 工作坊协调员希望助理读取日程并准备提醒草稿。该请求不授权发送提醒。评估时须保留这条边界。

## 比较角色

| 方式 | 常见任务形式 | 首要问题 |
|---|---|---|
| **单次聊天** | 起草一条提醒 | 是否提供了日程？ |
| **只读代理** | 独立核对日程事实 | 应读取哪个来源？ |
| **编程代理** | 更新本地报告程序 | 哪些文件和测试适用？ |
| **持久平台** | 长期响应消息或日程 | 存在哪些触发条件、工具和已存状态？ |

**OpenClaw** 是一个开源代理平台，包含网关、消息渠道、工具、记忆、MCP 连接和子代理。[概览](https://docs.openclaw.ai/start/why-openclaw)、[MCP 连接指南](https://docs.openclaw.ai/tools/mcp)和[子代理指南](https://docs.openclaw.ai/tools/subagents)介绍了这些组件。试点前，请检查当前启用的渠道、工具和沙箱设置。

**Hermes Agent** 是 Nous Research 的代理应用，与 Hermes 模型系列相互独立。[文档](https://hermes-agent.nousresearch.com/docs/)、[委派指南](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation)和[配置指南](https://hermes-agent.nousresearch.com/docs/user-guide/configuration/)介绍 CLI、消息、工具、记忆和委派任务。[记忆指南](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory/)介绍本地存储和写入审批。文档中 `memory.write_approval` 和 `skills.write_approval` 的默认值为 `false`。若试点要求审查写入，请启用审批或禁用相应存储。依赖任一控制前，都要检查运行中的配置。

| 评估项 | OpenClaw | Hermes Agent |
|---|---|---|
| **入口** | 网关和已连接渠道 | CLI 或已配置的消息界面 |
| **委派工作** | 遵循平台专属会话及工具规则的子代理 | 遵循平台专属工具规则的委派任务 |
| **持久状态** | 检查启用的记忆和会话存储 | 检查记忆、配置档案，以及技能写入设置 |
| **重复工作** | 检查已配置的触发条件和计划 | 检查 [cron 作业](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron/)和网关状态 |
| **首次试点** | 通过选定渠道手动发出一次请求 | 通过 CLI 或消息界面手动发出一次请求 |

此表列出审查点，不代表安全默认值等同。授予真实数据或账户访问权限前，请记录安装版本和当前配置。

**名称不代表共用的权限模型。** 一个产品中的“子代理”获得的文件、工具和历史记录，可能不同于另一个产品中的工作代理。请查看已安装版本的文档和当前设置，不要把一个工具的假设套用到另一个工具。

## 填写访问工作表

**在安装或连接系统前，为每项能力填写一行。** 若产品可用，请使用实际设置。不要猜测，写“未知”。

| 问题 | 工作坊试点的答案 |
|---|---|
| **任务** | 根据合成日程起草提醒 |
| **输入** | 一份已批准的日程文件 |
| **文件** | 读取日程文件，不授予写入权限 |
| **外部工具** | 首次试点不使用 |
| **账户访问** | 不连接邮件或日历账户 |
| **触发条件** | 仅手动请求 |
| **记忆和技能写入** | 记录当前设置，在试点期间禁用存储或要求写入审批 |
| **日志** | 记录存储路径、保留规则、提示词、来源版本和草稿 |
| **审查** | 人工核对日期、时间、地点和收件人名单 |
| **回滚** | 丢弃草稿并禁用试点 |

**数据流也是工作表的一部分。** 记录输入数据何时离开你的电脑、由哪个提供商处理，以及转录或记忆会保存在哪里。若工具连接邮件，请说明它是读取、起草还是发送。这些是不同的权限范围。

## 做出试点决定

**拒绝：** 仅需起草的任务却要求代理拥有邮箱的广泛写入权限，或者触发条件和日志未知。拒绝不合适的方案不需要先安装。

**试点：** 将输入限制为合成日程，使用手动触发，禁用发送，并检查一份草稿。预期结果是时间正确显示为晚上 7 点，且没有消息发出。若运行试点，请记录你自己的观察。

**批准明确用途：** 仅在试点通过检查，且负责人接受确切的访问权限、触发条件、保留期限和审查步骤后批准。批准起草不代表批准发送或后续自动化。

## 诊断故障

**假设提醒草稿写成了下午 6 点。** 检查代理是否读取了当前日程，或过时的时间是否来自存储记忆或旧消息。替换过时输入，手动重跑一次试点，并继续禁用发送。第二份草稿正确，也不能从记录中删掉第一次失败。

**假设设置中显示已连接 MCP，但没有可用工具。** 返回查看 [MCP 连接状态](/articles/effective-ai-mcp-server-setup/)。保存了服务器条目不代表读取成功。

## 练习与检查

**你的产物：** 一份填好的访问工作表和一个决定：拒绝、试点或批准明确用途。写明一个触发条件、一条权限边界、一个数据流问题，以及一种停止代理的方法。

**完成检查：** 另一位读者应能看懂代理会执行什么操作、读取和保存什么、何时运行、由谁检查结果，以及如何禁用。如果任一答案未知，请选择拒绝或范围更小的试点。

## 检查理解情况

1. **问题：** 仅起草提醒的任务需要发送邮件权限吗？**答案：** 不需要。发送不属于试点范围。
2. **问题：** 开展受控写入试点前，应检查 Hermes 的哪些设置？**答案：** 检查记忆和技能的当前写入设置，包括审批控制。
