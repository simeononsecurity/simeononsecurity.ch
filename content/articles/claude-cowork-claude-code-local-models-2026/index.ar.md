**تعمل أدوات Claude الوكيلة الآن مع نماذج على أجهزتك، دون مفتاح API أو اشتراك أو إرسال بياناتك خارج الجهاز.** توفر Ollama واجهة API متوافقة مع Anthropic، ويتصل بها كل من Claude Code وClaude Desktop باستخدام بضعة أوامر.

*تغفل أدلة كثيرة تفصيلاً مهماً. فهي تتحدث عن Claude Cowork ثم تعطي خطوات تضبط أداة سطر الأوامر. هذان تكاملان مختلفان، وواحد فقط منهما يوفر Cowork.*

يشرح هذا الدليل المسارين كلّاً على حدة، ومتغير البيئة الذي تتجاهله الأدلة الشائعة، والنماذج المناسبة لكل مسار في سبتمبر 2026، والميزات التي تبقى حصرية للسحابة مهما كان الإعداد.

**بعد قراءة الدليل:** ستحدد التكامل المطلوب، وتربطه عبر مسار Ollama الموثق، وتتحقق من نقطة الاتصال باختبار واحد لاستدعاء الأدوات. لا تبقي الاستدلال محلياً إلا عند اختيار نموذج محلي وتجنب الميزات المرتبطة بالسحابة.

## الإجابة المختصرة

**يتصل Ollama بـ Claude بطريقتين منفصلتين. واختيار الطريقة الخاطئة هو السبب الأكثر شيوعاً لإنهاء دليل الإعداد بطرفية تعمل من دون Cowork.**

| التكامل | ما يوفره | مسار الإعداد | النظام |
|---|---|---|---|
| **Claude Desktop** | Cowork والوكلاء الفرعيون والبحث على الويب والوضع التلقائي | تطبيق Ollama، ثم **Apps** و**Connect Claude** | **macOS فقط** |
| **Claude Code** | وكيل البرمجة في CLI مع استدعاء الأدوات وتحرير الملفات | `ollama launch claude` أو متغيرات البيئة | macOS وLinux وWindows |

**إذا أردت Cowork، فاستخدم تكامل Claude Desktop.** يُضبط عبر واجهة رسومية في تطبيق Ollama، وهو متاح على macOS فقط. ولا يزال دعم Windows مدرجاً على أنه قادم.

**إذا أردت وكيلاً في الطرفية، فاستخدم Claude Code.** يكفي أمر واحد.

*كلاهما مجاني. التكلفة الوحيدة هي العتاد والكهرباء.*

## تكاملان مختلفان

يبدأ الالتباس من الأسماء. **Claude Cowork ميزة داخل Claude Desktop**، وليس تطبيقاً منفصلاً أو اسماً آخر لـ Claude Code.

تعرض وثائق Ollama التكاملين في صفحتين وعنوانين منفصلين. يظهر Claude Desktop ضمن **Assistants** إلى جانب OpenClaw وHermes. ويظهر Claude Code ضمن **Coding** إلى جانب OpenCode وCline وCodex CLI.

هذا الفرق مهم لأن الإعداد مختلف تماماً:

- تضبط **Claude Desktop** من واجهة تطبيق Ollama. لا تحتاج إلى تعديل ملف إعدادات الصدفة.
- تضبط **Claude Code** عبر متغيرات البيئة أو أمر تشغيل واحد.

الدليل الذي يطلب منك تصدير `ANTHROPIC_BASE_URL` ثم تشغيل `claude` يضبط أداة سطر الأوامر. إذا كنت تتوقع تجربة Cowork على سطح المكتب، **فليس هناك عطل في الإعداد. لقد أعددت منتجاً مختلفاً.**

## إعداد Claude Desktop وCowork

يتم هذا المسار عبر تطبيق Ollama، لا الطرفية.

### المتطلبات

- **تثبيت Ollama** على macOS. دعم Windows مدرج على أنه قادم.
- **تنزيل نموذج مسبقاً** إذا أردت التشغيل محلياً. لاستخدام نموذج سحابي، سجّل الدخول إلى Ollama وفعّل النماذج السحابية. بعض النماذج تحتاج إلى خطة مدفوعة.
- **تثبيت Claude.** إذا لم يكن موجوداً، يعرض Ollama تنزيله أثناء الإعداد.

### الخطوات

1. افتح Ollama واختر **Apps**.
2. اختر **Connect Claude**.
3. اتبع مطالبات الإعداد. ثبّت Claude إذا طُلب منك ذلك، ثم أعد تشغيله عند ظهور الطلب.

هذا هو المسار كاملاً. لتغيير النموذج لاحقاً، افتح **Ollama Settings**، وانتقل إلى **Apps**، واختر النماذج، ثم اضغط **Restart Claude**.

### الميزات المدعومة

تذكر وثائق Ollama أربع ميزات مدعومة عبر هذا التكامل:

- **Cowork** لإتمام المهام الصعبة
- **الوكلاء الفرعيون** لتقسيم المهام الأكبر بين وكلاء
- **Web search** وتوفره Ollama افتراضياً
- **Auto mode**، حيث يقرر الوكيل متى يطلب الإذن قبل إجراء تغييرات

*تظهر Cowork في هذه القائمة، ما يعني أنها متاحة عبر هذا التكامل وليست عبر مسار سطر الأوامر.*

### قطع الاتصال

يعيد قطع الاتصال إعداد Claude السابق، لذا فالتغيير غير إتلافي.

- من الواجهة، افتح **Apps** وافصل Claude، ثم أعد تشغيله عند الطلب.
- من الطرفية، نفّذ `ollama launch claude-desktop --restore`.
- **إغلاق Ollama أثناء اتصال Claude يعيد إعداد Claude المعتاد أيضاً.** اترك Ollama يعمل إذا أردت استمرار الإعداد المحلي.

## إعداد Claude Code من CLI

هذا هو المسار الذي تغطيه معظم الأدلة، وهو المناسب للعمل في الطرفية.

### طريقة الأمر الواحد

```bash
ollama launch claude
```

يضبط الأمر متغيرات البيئة المطلوبة، ويوجه Claude Code إلى نسخة Ollama المحلية، ثم يشغله. اختر نموذجاً من القائمة واضغط Enter. لتحديد النموذج مسبقاً، أضف الخيار:

```bash
ollama launch claude --model qwen3.5
```

*يتولى الغلاف إعداد البيئة. اقرأ القسم التالي أيضاً، فمعرفة القيم التي يضبطها تساعدك على استكشاف المشكلات لاحقاً.*

### ضبط متغيرات البيئة يدوياً

```bash
export ANTHROPIC_AUTH_TOKEN=ollama
export ANTHROPIC_API_KEY=""
export ANTHROPIC_BASE_URL=http://localhost:11434

claude --model qwen3.5
```

**السطر الثاني هو ما تغفله الأدلة الشائعة.** يمنع ضبط `ANTHROPIC_API_KEY` كسلسلة فارغة مفتاحاً حقيقياً موجوداً مسبقاً في البيئة من إرباك الاتصال المحلي. وإذا حذفت الأدلة المنشورة هذا السطر، فقد يواجه من سبق له تصدير مفتاح خطأً محيراً.

لتجنب تغيير إعدادات الصدفة، مرر كل شيء داخل الأمر مباشرةً:

```bash
ANTHROPIC_AUTH_TOKEN=ollama ANTHROPIC_BASE_URL=http://localhost:11434 ANTHROPIC_API_KEY="" claude --model kimi-k2.7-code:cloud
```

معلومتان من الوثائق الرسمية:

- يحمل **`ANTHROPIC_AUTH_TOKEN` مصادقة bearer**، ولهذا يحتوي النص الحرفي `ollama` في الوضع المحلي.
- **تتقدم ملفات إعدادات Claude على متغيرات الصدفة.** إذا تصرف الاتصال بشكل غريب بعد تصدير قيم جديدة، فتحقق من تلك الإعدادات، ثم نفّذ `/status` داخل Claude Code لمعرفة نقطة الاتصال المستخدمة.

### الاتصال مباشرةً بـ Ollama Cloud

لا تحتاج إلى تثبيت Ollama لهذا المسار. عيّن مفتاح API ووجّه Claude Code إلى نقطة الاتصال المستضافة لدى Ollama:

```bash
ANTHROPIC_BASE_URL=https://ollama.com \
ANTHROPIC_AUTH_TOKEN="$OLLAMA_API_KEY" \
ANTHROPIC_API_KEY="" \
claude --model glm-5.3-flash
```

**لهذا المسار قيد واحد.** توضح وثائق Ollama أن البحث المستضاف على الويب والتحكم المتقدم بالأدوات غير مدعومين بالكامل. تعمل المحادثة الأساسية وتحرير الملفات واستدعاء الأدوات مع النماذج المتوافقة.

## اختيار النماذج في سبتمبر 2026

تغيرت مجموعة النماذج كثيراً خلال عام 2026، لذا يجدر إعادة النظر في النصائح المنشورة في الربيع.

| النموذج | النوع | السياق | سبب الاختيار |
|---|---|---|---|
| **Qwen3.8 27B** | محلي، 18 GB | 256K | أفضل نموذج محلي متعدد الاستخدامات حالياً مع الرؤية واستدعاء الأدوات والتحكم في التفكير |
| **Qwen3 Coder Next** | محلي، MoE إجمالي 80B / نشط 3B | 256K | مصمم لوكلاء البرمجة الدائمين، مع وضع سريع بلا تفكير |
| **Qwen3.6 35B A3B** | محلي، MoE 35B / نشط 3B | 262K | ترخيص Apache 2.0 وكفاءة مع ذاكرة متواضعة |
| **kimi-k2.7-code:cloud** | سحابي | كبير | نموذج سحابي للبرمجة لا يحتاج إلى عتاد محلي |
| **glm-5.3-flash** | سحابي | كبير | النموذج الذي تبدأ به وثائق Ollama نفسها |

**ابدأ بـ Qwen3.8 27B إذا كانت لديك ذاكرة كافية.** يعمل محلياً بسياق 256K ورؤية أصلية واستدعاء للأدوات وإمكانية تبديل التفكير لكل طلب. ويقدم أداءً يومياً مريحاً على بطاقة بها 24 GB أو أكثر.

**ابدأ بنموذج سحابي إن لم تتوفر تلك الذاكرة.** لا يكلفك اختبار Claude Code مع نموذج مستضاف شيئاً، ويلغي الحاجة إلى التفكير في العتاد، لكن الشيفرة تغادر جهازك.

### تحذير بشأن النماذج الثلاثية

إذا قرأت **[دليل الذكاء الاصطناعي المحلي](/articles/local-ai-2026-build-your-rig-now/)**، فستعرف أن Bonsai 2 27B الثلاثي يشغل نموذجاً كاملاً بحجم 27B في **5.53 GiB**. قد يبدو خياراً مناسباً هنا أيضاً.

**لن يعمل مع مسار العمل هذا.** توجد النوى الثلاثية في نسخة Prism ML المتفرعة من llama.cpp، ولا يستطيع Ollama القياسي تحميل هذه الملفات. يفشل أمر مثل `ollama launch claude --model Ternary-Bonsai-2-27B` قبل بدء الاستدلال. استخدم حزمة Qwen3.8 27B القياسية مع Claude Code واترك الحزم الثلاثية لبيئة تشغيل متوافقة.

*السهولة وأقصى كفاءة تتطلبان خيارين مختلفين هنا. تتوقع الأدوات المتكاملة ملف GGUF قياسياً.*

## اضبط السياق على 64K قبل لوم النموذج

تقدم وثائق Ollama توجيهاً مباشراً للعمل مع المستودعات: اختر نموذجاً و**اضبط نافذة السياق على 64K أو أكثر**، وارفعها للمستودعات الأكبر.

يضع Claude Code محتوى الملفات والفروق ومخرجات الأوامر في نافذة السياق. إذا كانت القيمة الافتراضية صغيرة، تنفد المساحة في منتصف المهمة. عندها يبدو العطل وكأنه مشكلة استدلال، لكنه ناتج عن الإعداد.

| السياق | الاستخدام |
|---|---|
| أقل من 32K | تعديل ملف واحد والأسئلة السريعة |
| **64K** | العمل على ملفات متعددة في مستودع متوسط |
| 128K | مستودعات أكبر ومخرجات أوامر طويلة |
| 256K | نافذة Qwen3.8 27B الكاملة |

*إذا فقد Claude Code مسار المهمة في منتصفها، فتحقق من إعداد السياق قبل تبديل النموذج.*

## تحقق من استدعاء الأدوات بأمر واحد

استدعاء الأدوات هو ما يفرق بين الوكيل ومولد النصوص. تحقق منه بدلاً من افتراض عمله.

بعد تشغيل Claude Code، اطلب منه:

```text
اقرأ المجلد الحالي واعرض قائمة بكل ملفاته
```

**إذا عرض ملفات فعلية، يعمل استدعاء الأدوات.** إذا أجاب بأنه سيقرأ المجلد ووصف ما يتوقع وجوده فيه، فالميزة غير مفعلة. عندها تتحدث إلى نموذج دردشة أضيف إليه موجه برمجي، لا إلى وكيل. لن يحل المزيد من التوجيهات المشكلة.

تحقق من الأسباب بهذا الترتيب:

1. **بدّل إلى نموذج ثبت دعمه للأدوات.** ليست كل النماذج تدعمها، ولا يكشف عدد المعلمات هذا الفرق.
2. **تحقق من أن البيئة تشير إلى Ollama.** نفّذ `ollama --version` وتأكد من أن `ANTHROPIC_BASE_URL` تشير إلى نقطة الاتصال المحلية.
3. **نفّذ `/status` داخل Claude Code.** تتقدم نقطة الاتصال أو بيانات الاعتماد في إعدادات Claude على متغيرات الصدفة التي صدّرتها للتو.

## الميزات التي تبقى حصرية للسحابة

اعرف حدود الخيارات قبل إعادة بناء سير عمل حول الاستدلال المحلي.

| الميزة | مع النماذج المحلية | السحابة |
|---|---|---|
| المحادثة وتحرير الملفات | نعم | نعم |
| استدعاء الأدوات | بحسب النموذج | نعم |
| الوكلاء الفرعيون | نعم | نعم |
| البحث على الويب | عبر Ollama | نعم |
| **Cowork** | عبر تكامل Claude Desktop | نعم |
| الوضع التلقائي | عبر تكامل Claude Desktop | نعم |
| المطالبات المجدولة | عبر `/loop` في Claude Code | نعم |

ثمة ثلاثة قيود على الجانب المحلي:

- **يتراجع الاستدلال متعدد الملفات قبل السرعة.** يتعامل النموذج المحلي جيداً مع ملف واحد، وبشكل مقبول مع ثلاثة، وضعيفاً مع مستودع كامل. خطط لحجم المهمة وفقاً لذلك.
- **تحتاج بعض النماذج السحابية إلى خطة Ollama مدفوعة.** كما تحتاج إلى تسجيل الدخول وتفعيلها.
- **للاتصال السحابي المباشر حدود في الميزات.** لا يدعم البحث المستضاف على الويب والتحكم المتقدم بالأدوات بالكامل عند تجاوز التثبيت المحلي.

*يناسب الاستدلال المحلي العمل المحدد القابل للتحقق، ويضعف في المهام الواسعة والغامضة. رتّب العمل مع مراعاة هذا الحد.*

## الأتمتة

تتيح ميزتان استخدام النظام بما يتجاوز التفاعل المباشر.

### التشغيل دون واجهة للبرامج النصية وCI

يتجاوز الخيار `--yes` المحددات التفاعلية وينزل النموذج عند الحاجة. وهو يتطلب `--model`، وكل ما يأتي بعد `--` يمر مباشرة إلى Claude Code:

```bash
ollama launch claude --model gemma4:cloud --yes -- -p "how does this repository work?"
```

**انتبه إلى نموذج الأذونات.** يطلب Claude Code التأكيد قبل معظم الإجراءات، لذا يحتاج التشغيل دون واجهة إلى قواعد أذونات مضبوطة أو بيئة معزولة. لا توجه وكيلاً دون إشراف إلى مستودع مهم لك.

### المطالبات المجدولة عبر `/loop`

داخل جلسة Claude Code، ينفذ `/loop` مطالبة أو أمراً مائلاً على فاصل زمني:

```text
/loop 30m تحقّق من طلبات السحب المفتوحة ولخّص حالتها
/loop 1h ابحث عن أحدث أخبار الذكاء الاصطناعي ولخّص أبرز التطورات
/loop 15m تحقّق من مشكلات GitHub الجديدة وصنّفها حسب الأولوية
```

*يعمل الأمر ما دامت الجلسة مفتوحة. إنه ليس خدمة في الخلفية، ويتوقف عند انتهاء الجلسة.*

| **يُستخدم مفتاح API حقيقي بدلاً من نقطة الاتصال المحلية** | ما زال `ANTHROPIC_API_KEY` مصدراً | اضبطه كسلسلة فارغة كما سبق |
| **غياب Cowork بعد الإعداد** | جرى ضبط CLI لـ Claude Code بدلاً من Claude Desktop | استخدم مسار **Apps** في Ollama لتفعيل Cowork |
| **بطء التوليد** | السياق أكبر من اللازم أو اختير نموذج كثيف بينما يكفي نموذج متناثر | قلل السياق ثم جرّب نموذج mixture-of-experts |
| **لا تؤثر المتغيرات المصدرة** | تتقدم إعدادات Claude على متغيرات الصدفة | افحص ملفات الإعداد ثم نفذ `/status` |
| **فشل طلبات الخلفية** | يختار Claude Code نموذجاً صغيراً للمهام الداخلية | وجه إعداد النموذج الصغير إلى النموذج المحلي نفسه |

*يرجع اثنان من هذه المشاكل السبعة إلى السبب نفسه. تنتج معظم مشكلات الإعداد من نقطة اتصال خاطئة أو نموذج لا يدعم استدعاء الأدوات.*

## أهم النقاط

- **Claude Desktop وClaude Code تكاملان منفصلان.** توجد Cowork داخل Claude Desktop، وتُضبط في macOS من لوحة **Apps** في Ollama. لا يوفر مسار CLI ميزة Cowork.
- **يبدأ مسار CLI بأمر واحد:** `ollama launch claude`. يحتاج الإعداد اليدوي إلى ثلاثة متغيرات، و**تغفل أدلة كثيرة `ANTHROPIC_API_KEY=""`**.
- **لا تحتاج إلى تثبيت محلي.** وجه Claude Code إلى `https://ollama.com` باستخدام مفتاح API.
- **اضبط السياق على 64K أو أكثر قبل تقييم النموذج.** قد تبدو النافذة الصغيرة كأنها إخفاق في الاستدلال.
- **تحقق من استدعاء الأدوات بطلب واحد.** إذا وصف النموذج ما كان سيفعله، فأنت تستخدم مولد نصوص لا وكيلاً.
- **لا تعمل حزم Bonsai الثلاثية هنا.** تحتاج إلى نسخة Prism ML المتفرعة من llama.cpp، ولا يستطيع Ollama القياسي تحميلها.
- **قطع الاتصال آمن.** يعيد إنهاء Ollama إعداد Claude السابق، كما يمكنك تنفيذ `ollama launch claude-desktop --restore` من الطرفية.
