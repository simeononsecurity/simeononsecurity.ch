**親指ほどの大きさで、応答しない受動型WiFi脅威センサー**

## 公共WiFiの問題

ホテル、カフェ、空港のWiFiに接続するとき、目の前のアクセスポイントが本物だと信頼します。問題は、ネットワークを通知し、接続を管理し、クライアントを調整する**802.11管理フレーム**が、ほとんどの環境で *認証されていない* ことです。手頃な機材でもSSIDを複製し、クライアントに認証解除フレームを大量送信し、正規のWPA2ネットワークの隣にオープンな偽ネットワークを設置できます。

[**ESP32 WiFi Canary**](https://github.com/simeononsecurity/esp32-wifi-canary)は、この現実に対応する小型の受動型センサーです。角砂糖ほどのM5Stack Atom Liteに収まり、USBポートに接続すると周囲の環境を学習します。無線脅威に一致するパターンを検知するとRGB LEDが点灯します。

ネットワークには接続しません。認証情報を収集しません。フレームを送信しません。周囲を監視してスコアを計算し、色で状態を知らせます。

この記事では、検知内容、信頼度モデル、ビルドと書き込みの方法、実環境での制限を含むプロジェクトの技術情報を説明します。

## ESP32 WiFi Canaryが行うこと、行わないこと

### 常に受動的

WiFi Canaryは、同時には使わない2つの無線モードで動作します。

1. **プロミスキャスモード**: ネットワークに接続せず、認証解除や切断などの802.11管理フレームを受信して調べます。
2. **スキャンモード**: 近くのアクセスポイントをスキャンし、学習済みの基準値と比較します。

デバイスは次の動作をしません。
- ネットワークに関連付けたり接続したりしない
- データフレームや認証情報を収集しない
- 802.11フレームを送信しない
- 永続フラッシュに情報を保存しない
- インターネットと通信しない

**学習した情報はすべてRAMに保持され、再起動すると消去されます。** 意図した設計です。Canaryは**センサー**であり、キャプチャ装置ではありません。

### インターフェースはLED

画面、アプリ、Web UIはありません。デバイスの出力はM5Stack Atom LiteのGPIO 27に接続した**SK6812 RGB NeoPixel**だけです。LEDは4つの状態を示します。

| LEDの状態 | 意味 |
|---|---|
| 🔵 青（ゆっくり点滅） | 起動中、基準を作成 |
| 🟢 緑（点灯） | 正常、高信頼度の問題なし |
| 🟡 黄（点灯） | 注意、疑わしいパターンを検知 |
| 🔴 赤（速い点滅） | 警告、より信頼度の高い脅威を検知 |

起動には約**24秒**かかります（8秒のスキャンを3回）。青から切り替わると基準ができ、監視を開始します。

## ハードウェア

### 主な対象: M5Stack Atom Lite

このプロジェクトは、24 × 24 mmのケースに収まるESP32開発プラットフォーム、M5Stack Atom Lite向けに設計されています。

| 部品 | 詳細 |
|---|---|
| MCU | ESP32-PICO-D4 |
| LED | SK6812 RGB NeoPixel 1個 (GPIO 27) |
| ボタン | GPIO 39、アクティブロー |
| USB | CP2104 UARTブリッジ |
| 電源 | USB-C、スキャン中に約80～120 mA |

**ブレッドボード、外付け部品、はんだ付けは不要です。** USB電源に接続すれば動作します。

### 開発・テスト用の一般的なESP32 DevKit

標準的なESP32開発ボード向けに、PlatformIOの2つ目のビルド環境（`esp32dev`）も用意されています。この構成では:

- NeoPixelの代わりにGPIO 2の内蔵LEDを使用
- シリアルデバッグ出力をすべて有効化
- Atom Lite版と同じ検知ロジックを実行

そのため、5ドルのESP32 DevKitがあれば対象ハードウェアなしでも検知ロジックを試せます。

## 基準値を学習する仕組み

### 基準値が重要な理由

街中のオープンネットワークすべてに反応するCanaryは役に立ちません。ESP32 WiFi Canaryは脅威を採点する前に環境を学習します。最初の段階では、周囲に正規に存在するアクセスポイントの**参照テーブル**を作ります。

### 3回のスキャン、24秒

起動時に、デバイスは間隔を空けてWiFiスキャンを3回連続で実行します。完了すると、SSID、BSSID、暗号化方式、信号強度からなる学習結果を基準値として保存します。

この段階のシリアル出力例:

```
==============================================
 Travel WiFi Canary v1.0
 Passive 2.4 GHz awareness sensor
==============================================
[canary] setup done - starting baseline learning
[canary] baseline scan start (aps=0 score=0)
[canary] scan found 18 APs
[canary] baseline scan 1/3
[canary] baseline scan start (aps=18 score=0)
[canary] scan found 18 APs
[canary] baseline scan 2/3
[canary] baseline scan start (aps=18 score=0)
[canary] scan found 19 APs
[canary] baseline complete: 19 APs learned
  [00] MyHomeWifi                    aa:bb:cc:dd:ee:ff ch06 WPA2     -52 dBm
  [01] XFINITY                       11:22:33:44:55:66 ch01 WPA2     -71 dBm
  ...
[canary] STARTUP → NORMAL  (score=0  "")
```

LEDが青から緑に変わると、デバイスは通常動作に入ります。

## 検知する脅威カテゴリ

WiFi Canaryは6種類の脅威パターンを監視します。それぞれがLED状態を決める**信頼度スコア**に加点されます。*単独の指標を確実な証拠とみなさず、複数の裏付けを集めてから警戒度を上げます。*

### 1. 認証解除・切断フレームの連続送信

**802.11管理フレームのサブタイプ10（切断）と12（認証解除）**はWiFi攻撃でよく使われます。どのデバイスからでも送信でき、受信したクライアントはアクセスポイントから切断されます。

Canaryは**プロミスキャスモード**でフレームを監視し、**5秒間のローリングウィンドウ**内で送信元MACごとに数えます。

| 条件 | 加点 |
|---|---|
| 5秒で1つの送信元から8フレーム以上 | +2 |
| 5秒で1つの送信元から20フレーム以上 | +4 |
| ブロードキャスト認証解除フレーム5個以上 | +1 |

**しきい値が重要な理由**: クライアントがAP間を移動すると、正規の認証解除・切断フレームが少数発生します。*攻撃ツールの出力は質的に異なり*、標的に向けて毎秒数百フレームを継続して送ります。5秒間の窓と8フレームの下限で通常のローミングノイズを除外し、`aireplay-ng`などの継続的なバーストを検知します。

### 2. 既知の暗号化ネットワークのオープンな複製（evil twin）

**最も信頼度の高い検知です。** evil twin攻撃は、次のように行われることがあります。

1. 既知のWPA2 SSIDをパスワードなしで複製する。
2. 実際のAPより信号を強くし、クライアントを自動接続させる。

基準学習後、以前はWPA/WPA2/WPA3のみだったSSIDが、新しいスキャンで**OPEN**として現れた場合:

| 条件 | 加点 |
|---|---|
| 同じSSIDが以前は暗号化済みで、現在はオープン | +3 |
| BSSIDが基準に存在しない | +1 |
| 複製の信号が既知APより10 dB以上強い | +1 |

ホテルのWiFi SSIDをオープンに複製し、実APより10 dB強い信号を出すのは典型的な例です。*この組み合わせは1回のスキャンでスコアを5（注意）まで上げます。*

**シリアル出力例**:

```
[canary] OPEN CLONE: SSID='MyHomeWifi' baseline=WPA2 clone=OPEN bssid=de:ad:be:ef:00:01 rssi=-48/-52
[canary] score +4 → 4  "open clone of encrypted SSID 'MyHomeWifi'"
[canary] NORMAL → CAUTION  (score=4  "open clone of encrypted SSID 'MyHomeWifi'")
```

### 3. 元の暗号化APが消え、オープンな複製が出現

より高度な攻撃では、強い複製にクライアントを誘導し、同時に本物のAPを認証解除で停止させます。

| 条件 | 加点 |
|---|---|
| 基準の暗号化APが消え、対応するオープンネットワークが現れる | +3 |

本物のAPが送信中でも、信号強度の競争に負ける場合や、攻撃によって妨害される場合を対象にします。

### 4. セキュリティのダウングレード

基準と同じSSIDが、記録されたものより弱い暗号化で観測された場合です。

| 条件 | 加点 |
|---|---|
| WPA3 → WPA2 | +1 |
| WPA2 → WPA | +1 |
| 暗号化ランクが2段階以上低下 | +3 |

*オープンへのダウングレードはevil twin検知で扱い、より高いスコアを付けます。* このカテゴリは、オープンか暗号化かだけの比較では見逃し得る部分的な低下を対象にします。

### 5. 予期しないベンダーの重複SSID

基準APとSSIDおよびセキュリティ方式は同じでも、BSSIDの**ベンダーOUI**（MACアドレスの先頭3バイト）が異なる場合です。

| 条件 | 加点 |
|---|---|
| 同一SSIDの基準APとOUIが異なる | +1 |
| 複製の信号も10 dB以上強い | +2 |

*意図的に低いスコアにしています。* 企業ネットワーク、メッシュシステム、ISPのAPは、同一SSIDで異なるベンダーのBSSIDを正当に複数使うことがあります。この信号は単独で反応するのではなく、ほかの証拠と組み合わせます。

### 6. ビーコン・SSIDフラッド

基準にない新しいSSIDが**30秒のローリングウィンドウ**内に現れた数を数えます。

| 条件 | 加点 |
|---|---|
| 30秒で新しいSSIDが15個以上 | +2 |
| 30秒で新しいSSIDが30個以上 | +3 |

**ビーコンフラッド攻撃**では、何千もの偽SSIDを送信してクライアントのスキャン一覧を混乱させたり、正規のビーコンを妨害したりします。多くの環境では30秒に15個の未知SSIDは異常です。

## 信頼度スコアモデル

検知した信号を1つの整数の**脅威スコア**にまとめます。スコアでLED状態を決めます。

| スコア範囲 | LED状態 |
|---|---|
| 0～2 | 正常（緑） |
| 3～5 | 注意（黄） |
| 6以上 | 警告（赤、高速点滅） |

### スコアの減衰

新たなイベントがなければ、スコアは**60秒ごとに1点減ります**。これは実用性に大きく影響する設計判断です。

- 認証解除が1回発生すると注意になりますが、攻撃が止まれば数分で正常に戻ります。
- 攻撃が続いてイベントを発生させる間は警告状態が維持されます。
- 操作や再起動をしなくてもデバイスが回復します。

つまり:
- **短時間の異常**（ローミングや近隣ネットワークの一時変化）は自然に解消します。
- **継続的な攻撃**は警告されたままです。
- 繰り返さない単発イベントによる**警告疲れがありません**。

### ボタンによるリセット

Atom LiteのGPIO 39ボタンを押すと、次の2つが起こります。

1. 現在のAP一覧をすべてシリアル出力します。デバイスが見ている内容を監査できます。
2. 脅威スコアを0に戻します。LEDが直ちに緑に戻り、次のスキャンを新しい状態で観察できます。

## ビルドと書き込み

### 必要なもの

- **PlatformIO**（CLIまたはVS Code拡張機能）
- **M5Stack Atom Lite**（テストにはESP32 DevKitも使用可能）
- USB-Cケーブル

### M5Stack Atom Liteに書き込む

```bash
git clone https://github.com/simeononsecurity/esp32-wifi-canary.git
cd esp32-wifi-canary

# ビルドして書き込む
pio run -e atom-lite --target upload

# 115200 baudでシリアルモニターを開く
pio device monitor -b 115200
```

### 一般的なESP32 DevKitに書き込む

```bash
pio run -e esp32dev --target upload
```

DevKit版はGPIO 2（内蔵LED）を使い、シリアルログ全体を出力します。NeoPixelは駆動しません。検知ロジックはAtom Lite版と同じです。

### プロジェクト構成

```
esp32-wifi-canary/
├── main.cpp              # ファームウェアの全ロジック
├── platformio.ini        # ビルド環境 (atom-lite, esp32dev)
├── partitions_4mb.csv    # 4MBフラッシュのパーティション表
└── README.md
```

ファームウェアは**単一のC++ソースファイル**です。検知ロジックに外部ライブラリはなく、WiFiスキャン、プロミスキャスモードのコールバック、NeoPixel制御にESP32 Arduinoフレームワークを使用します。

### platformio.iniの環境

```ini
[env:atom-lite]
platform = espressif32
board = m5stick-c
framework = arduino

[env:esp32dev]
platform = espressif32
board = esp32dev
framework = arduino
```

`atom-lite`環境は`m5stick-c`ボード定義を使います（同じESP32-PICO-D4シリコンで、GPIO 27のNeoPixelに対応するピン配置です）。

```
[canary] normal scan start (aps=19 score=0)
```

## 検知に関する注意点と実用上の制限

READMEはこのデバイスでできないことも率直に説明しています。ここでは詳しく繰り返します。

### 誤検知の原因

**企業ネットワークとメッシュネットワーク**は、誤検知の主な原因です。大企業、多数のAPがあるホテル、EeroやGoogle WiFiなどのメッシュでは、次の状態が正常に発生します。
- 同一SSIDに異なるベンダーOUIのBSSIDが複数ある（ベンダー検知）
- 帯域ごとにセキュリティ設定が異なる（ダウングレード検知）
- メッシュの調整に伴いAPが出現・消失する

複数帯域に複数のSSIDを使う**AirbnbやSOHOルーター**も、2.4 GHzと5 GHzの無線が異なるMACブロックの連続アドレスを使う場合、OUIの不一致を起こすことがあります。

*近隣ネットワークの一時変化*: 暗号化ネットワークが一時的にスキャンから消え、異なる設定で再出現すると（ファームウェア更新、再起動、再設定など）、一時的に検知されることがあります。

スコアリングと減衰は誤検知を*減らすための設計であり、なくすものではありません*。

### 見逃しの原因

巧妙な**evil twin攻撃**が次の条件を満たすと:
- 正規APと同じBSSIDを偽装してOUIも一致させる
- 正確に同じセキュリティ方式（正しいIE設定のWPA2）を使う
- 信号強度を実APから10 dB以内に保つ

*注意しきい値を超えるスコアが蓄積しないことがあります。* 実APからクライアントを離す認証解除動作は加点しますが、認証解除を最小限にする高度な攻撃者はしきい値を下回る可能性があります。

### 無線モード切り替え中の空白

**ESP32 WiFi無線は、プロミスキャスモードとアクティブAPスキャンを同時に行えません。** ファームウェアはモードを切り替えるため、**約3秒のスキャン中に届いた認証解除フレームは捕捉されません**。*スキャンのタイミングに合わせた攻撃で検知を回避できる可能性があります*が、デバイスのスキャン予定を知る必要があります。

### 2.4 GHzのみ

ESP32の無線は2.4 GHz対応です。**5 GHzと6 GHzのネットワークはスキャンも監視もしません。** *5 GHzのevil twinが攻撃手段になる環境では、このデバイスは検知できません。*

### 受動検知の範囲

認証解除を検知するには、そのフレームが届く範囲にデバイスが必要です。*遠方や指向性の強い攻撃者、またはCanaryから離れたクライアントを狙う攻撃者のフレームは、カウンターを動かすほど強く届かない場合があります。*

## 使用例

### 機密性の高い仕事での旅行

Canaryは主に旅行用です。ノートPCのUSB、ホテルのUSBコンセント、携帯バッテリーにつなぎ、ホテルや会議場の環境を学習させます。その後、ホテルSSIDのオープンな複製という一般的な攻撃が現れると、少なくとも注意状態になります。

### カフェと公共WiFi

オープンWiFi環境はevil twin設置の一般的な攻撃対象です。到着時に正規のカフェAPを基準として学習し、競合するSSIDの出現を監視できます。

### セキュリティ意識と教育

シリアル出力には、検知した内容が読みやすい形で記録されます。研修では認証解除バーストをリアルタイムで見てLEDの色変化を確認すると、スライド説明より効果的です。

### ラボの受動監視

自宅ラボや小規模オフィスでは、Canaryを常時動作する環境センサーとして使えます。LEDで状態をすぐ確認でき、ボタンを押すと現在見えるネットワーク一覧が出ます。

## アーキテクチャに関する説明

### 個別アラートではなく単一スコアを使う理由

信頼度モデルは複数の異なる信号を1つの数値にまとめ、検知カテゴリ別のアラートを出しません。出力が3状態のLEDだけであることを踏まえたUX設計です。カテゴリごとに警告するには画面やアプリが必要です。*ノイズを含み一部相関する信号を、実行に移せる1つの指標に変換します。*

### スコアを減衰させる理由

減衰がなければ、誤検知を消すためにボタンを押す必要があります。60秒ごとの減衰なら、短い異常は数分で自然に解消します。**そのためCanaryをかばん、ホテルの部屋、車内に置いたまま運用できます**。一時的なイベントが終われば基準状態に戻ります。

### 基準スキャンを3回行う理由

1回のスキャンでは、その間に送信していなかったAP（スキャンの合間、または一時的に電源オフなど）を見逃す場合があります。*約24秒で3回スキャンすると監視開始前に安定した環境をより完全に把握できます。*

## 貢献とプロジェクトの状況

プロジェクトは受動利用ライセンスのもと、[github.com/simeononsecurity/esp32-wifi-canary](https://github.com/simeononsecurity/esp32-wifi-canary)で公開されています。コードは単一の`main.cpp`で、読みやすく、監査や拡張も容易です。

PlatformIOとESP32を使う場合、このプロジェクトは変更せずにAtom Liteと標準DevKitの両方でコンパイルできます。

## 他のWiFi監視方式との比較

| 方式 | 受動的? | 認証情報なし | 単一LED出力 | 携帯向け形状 |
|---|---|---|---|---|
| ESP32 WiFi Canary | ✅ | ✅ | ✅ | ✅ |
| Kismet（ノートPC） | ✅ | ✅ | ❌（画面が必要） | ❌（重い） |
| WiFi Pineapple | ❌（能動的） | ❌ | ❌ | 一部対応 |

| 手動スキャン（スマホアプリ） | 一部 | ✅ | ❌ | ✅ |

Canaryは、**操作もネットワーク接続も不要な常時環境監視**という特定の役割を持ち、キーホルダーやPCバッグに入れたままにできる形状です。

## まとめ

ESP32 WiFi Canaryは、2.4 GHz環境を監視し、異常に見えるものを検知すると色を変える、範囲を絞ったツールです。無線侵入検知システム、パケットキャプチャ、フォレンジック解析を目指していません。危険な状況に気づくための受動センサーです。

**信頼度スコアモデル**、**スコアの減衰**、**3段階の基準作成**には、環境センサーで多い誤検知への配慮が表れています。ホテルや会議場で無人運転し、通常のネットワーク変動には反応せず、意味のある異常を知らせます。

携帯用セキュリティ機材を組み立てる人、信頼できないWiFi環境で働く人、実用的なESP32プロジェクトを探す人にとって、WiFi Canaryは15ドルのM5Stack Atom Liteと午後の時間をかける価値があります。
