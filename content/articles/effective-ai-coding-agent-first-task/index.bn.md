[ব্যবহারিক AI কর্মপ্রবাহ কোর্সে ফিরুন](/effective-ai-course-start/)

**কোডিং এজেন্ট একটি কর্মক্ষেত্রে ফাইল পড়ে, সম্পাদনার প্রস্তাব দেয় এবং টুল চালায়।** এই পাঠে আপনি একটি ছোট রিপোজিটরি কাজ করবেন। ChatGPT ডেস্কটপ অ্যাপ বা CLI-এর Codex, Claude Code CLI, অথবা OpenCode TUI বেছে নিন। পরিবর্তন গ্রহণের আগে সেটি পর্যালোচনা করুন।

**শেখার লক্ষ্য:** আপনি একটি সীমিত সম্পাদনা চালাবেন বা হাতে প্রয়োগ করবেন এবং এর ডিফ ও আচরণ যাচাই করবেন।

## মূল বিষয়

- **ChatGPT ডেস্কটপ অ্যাপের Codex** কাজ ও পর্যালোচনার জন্য দৃশ্যমান কর্মক্ষেত্র দেয়।
- **Codex CLI** টার্মিনাল থেকে Codex সেশন চালায়।
- **Claude Code CLI** টার্মিনালে Claude-এর কোডিং কর্মপ্রবাহ চালায়।
- **OpenCode TUI** কনফিগারযোগ্য প্রদানকারী ও অনুমতিসহ টার্মিনাল কর্মপ্রবাহ দেয়।
- **ডিফ এবং পরীক্ষার ফল** সহকারীর কাজ শেষের বার্তার চেয়ে বেশি গুরুত্বপূর্ণ।

## শুরু করার আগে

**পূর্বশর্ত:** [কোর্স সেটআপ](/articles/effective-ai-course-setup/) শেষ করুন, যার মধ্যে প্রাথমিক রান ও স্থানীয় Git স্ন্যাপশট রয়েছে। এই পাঠের আগে [রিপোজিটরি প্রসঙ্গ](/articles/effective-ai-agents-md-context/) এবং [কাজের প্যাকেট](/articles/effective-ai-task-packets/) শেষ করুন। অনুমোদিত একটি কোডিং এজেন্ট ব্যবহার করুন। ৪৫ মিনিট সময় রাখুন। কঠিনতার স্তর প্রাথমিক থেকে মধ্যবর্তী।

**[কোর্সের স্টার্টার ল্যাব](/downloads/effective-ai-course-lab.zip)** একটি অস্থায়ী ফোল্ডারে ব্যবহার করুন। আর্কাইভে ছোট কাজের রিপোর্ট প্রোগ্রাম, নমুনা ডেটা ও পরীক্ষা রয়েছে। প্রথম সম্পাদনায় উৎপাদন রিপোজিটরি ব্যবহার করবেন না। বিদ্যমান মোট সংখ্যা বজায় রেখে `--status` ফিল্টার যোগ করুন।

## কোডিং এজেন্ট ছাড়া অধ্যয়নের পথ

**কোডিং এজেন্ট না থাকলে চ্যাট সহকারীকে একই পরিবর্তনের প্রস্তাব দিতে বলুন।** কৃত্রিম ল্যাব থেকে শুধু `docs/requirements.md`, `task_report.py` এবং নির্দিষ্ট পরীক্ষার ফাইল পেস্ট করুন। ইউনিফায়েড ডিফ ও সংক্ষিপ্ত ব্যাখ্যা চান। ইউনিফায়েড ডিফে পুরোনো লাইন `-` এবং নতুন লাইন `+` দিয়ে চিহ্নিত হয়। বলা ফাইলটি টেক্সট এডিটরে খুলুন, পুরোনো লাইন প্রস্তাবিত পরিবর্তন দিয়ে প্রতিস্থাপন করে সংরক্ষণ করুন। এরপর ফলাফল পর্যালোচনা অংশের সব কমান্ড চালান। `tasks.json` অপরিবর্তিত রাখুন। এজেন্টের ধাপ চালানো হয়নি বলে লিখে রাখুন। চূড়ান্ত প্রকল্পে আলাদা JSON ফাংশন আছে, তাই ফিল্টার সমাধানকে পাঠ ৫-এর চাহিদা ও যাচাইয়ের সঙ্গে তুলনা করুন।

## একটি ইন্টারফেস বেছে নিন

**আগে পর্যালোচনার মাধ্যম বেছে নিন।** ChatGPT ডেস্কটপ অ্যাপের Codex দৃশ্যমান প্রকল্প ও ডিফ পর্যালোচনার জন্য উপযুক্ত। খোলা ল্যাব ফোল্ডারে কাজের জন্য টার্মিনাল ইন্টারফেস উপযুক্ত। টার্মিনাল বিকল্পগুলো তুলনা করুন:

| টার্মিনাল টুল | অ্যাকাউন্ট বা প্রদানকারী যাচাই | শুরু করার কমান্ড |
|---|---|---|
| **Codex CLI** | Codex-এ সাইন-ইন এবং স্থানীয় অনুমতি নিশ্চিত করুন | `codex` |
| **Claude Code CLI** | Claude Code অ্যাক্সেস এবং স্থানীয় অনুমতি নিশ্চিত করুন | `claude` |
| **OpenCode TUI** | সমর্থিত মডেল প্রদানকারী ও অনুমতি কনফিগার করুন | `opencode` |

**নির্বাচিত টুলের বর্তমান সরকারি নির্দেশিকা দেখে ইনস্টল ও সাইন-ইন করুন।** [Codex CLI](https://learn.chatgpt.com/docs/codex/cli), [ChatGPT ডেস্কটপ অ্যাপ](https://learn.chatgpt.com/docs/app), [Claude Code](https://code.claude.com/docs/en/overview), অথবা [OpenCode](https://opencode.ai/docs/) পড়ুন। কমান্ড, সমর্থিত প্ল্যাটফর্ম ও অ্যাকাউন্টের শর্ত বদলায়। এই পাঠে স্থিতিশীল চালু করার নাম এবং সাধারণ পর্যালোচনা পদ্ধতি ব্যবহার করা হয়েছে।

**পণ্য সম্পর্কে আরও জানতে,** সাইটের [CLI কোডিং এজেন্ট তুলনা](/articles/cli-coding-agents-comparison/) বা [গ্রাফিক্যাল ইন্টারফেস কোডিং এজেন্ট তুলনা](/articles/gui-coding-agents-comparison/) পড়ুন। [Codex CLI ও ডেস্কটপ](/articles/codex-cli-vs-desktop/), [Claude Code CLI ও ডেস্কটপ](/articles/claude-code-cli-vs-desktop/) এবং [OpenCode CLI ও ডেস্কটপ](/articles/opencode-cli-vs-desktop/) নির্দেশিকায় প্রতিটি পণ্যের ইন্টারফেস তুলনা করা হয়েছে।

**ল্যাব ফোল্ডার থেকে শুরু করুন।** প্রতিটি ইন্টারফেসে কর্মক্ষেত্র স্পষ্টভাবে বেছে নিতে হয়:

1. **Codex ডেস্কটপ:** ChatGPT ডেস্কটপ অ্যাপ খুলুন, খোলা ল্যাবকে স্থানীয় প্রকল্প হিসেবে বেছে নিন এবং সেখানে স্থানীয় কাজ শুরু করুন। সম্পাদনার আগে ফোল্ডারের পথ ও অনুমোদনের অনুরোধ পরীক্ষা করুন। হোস্ট করা কাজ আলাদা কর্মক্ষেত্রের কপি ব্যবহার করে।
2. **Codex CLI:** `cd /path/to/effective-ai-course-lab` চালিয়ে `codex` চালান। প্রদর্শিত কাজের ফোল্ডার ও অনুমোদন মোড নিশ্চিত করুন।
3. **Claude Code CLI:** একই `cd` কমান্ড চালিয়ে `claude` চালান। প্রকল্প ফোল্ডার ও টুলের অনুমতি নিশ্চিত করুন।
4. **OpenCode TUI:** একই `cd` কমান্ড চালিয়ে `opencode` চালান। বেছে নেওয়া প্রদানকারী, প্রকল্প ও অনুমতি সেটিং নিশ্চিত করুন।

**ChatGPT chat এবং Claude Projects কথোপকথন ও ভাগ করা রেফারেন্স ফাইল সামলায়।** Codex ও Claude Code ফাইল এবং কমান্ডের টুলসহ কোড কর্মক্ষেত্রে চলে। OpenCode-এর ডেস্কটপ ও IDE মাধ্যমও আছে, তবে এই পাঠে টার্মিনাল ব্যবহার করা হয়েছে। প্রদানকারী, অ্যাকাউন্ট এবং স্থানীয় বা হোস্ট করা রান আলাদা। সব সেশনকে একই রান না ধরে বেছে নেওয়া মাধ্যমটি লিখে রাখুন।

**ল্যাব খোলার আগে পাঁচটি বিষয় দেখুন:** সমর্থিত অপারেটিং সিস্টেম, প্রমাণীকরণ, প্রদানকারী বা অ্যাকাউন্টের খরচ, ফাইল ও কমান্ডের অনুমতি, এবং কাজ স্থানীয় নাকি দূরবর্তী হোস্টে চলে। আপনার পছন্দ লিখে রাখুন। ডেস্কটপ অ্যাপ ও টার্মিনাল টুল একই কর্মক্ষেত্র ব্যবহার করে বলে ধরে নেবেন না।

## স্টার্টার পরীক্ষা করুন

**রিপোজিটরি প্রসঙ্গের পাঠ থেকে পরিষ্কার ল্যাব ফোল্ডারটি আবার খুলুন।** এই কপিতে আপনার কমিট করা `AGENTS.md` ও ঐচ্ছিক `CLAUDE.md` নির্দেশনা আছে। এজেন্টকে সম্পাদনা করতে বলার আগে ফাইলগুলো দেখুন। এই ফোল্ডার থেকে প্রাথমিক পরীক্ষা চালান।

```bash
python3 -m unittest discover -s tests -v
python3 task_report.py tasks.json
```

**প্রত্যাশিত প্রাথমিক ফল:** রিপোর্টে `Total tasks: 4` দেখা যায়। পরীক্ষার রান দুটি পরীক্ষার নাম দেখায় এবং `OK` দিয়ে শেষ হয়। কোনোটি ব্যর্থ হলে থামুন এবং খোলা ফাইলগুলো পরীক্ষা করুন। ত্রুটিপূর্ণ প্রারম্ভিক অবস্থার মেরামত এজেন্টের কৃতিত্ব হিসেবে ধরবেন না।

**কোর্স সেটআপ ও রিপোজিটরি প্রসঙ্গ পাঠের স্থানীয় Git স্ন্যাপশট ব্যবহার করুন।** `AGENTS.md` এবং ঐচ্ছিক `CLAUDE.md` আগে থেকেই কমিট করা থাকা উচিত। ফিচার সম্পাদনার আগে `git status --short` চালান এবং কোনো ফাইল না দেখানোর প্রত্যাশা করুন। এজেন্টও কমিট করবে না। আর্কাইভে Git ইতিহাস নেই। এর `.gitignore` ফাইলটি পরীক্ষা চালানোর সময় তৈরি হওয়া Python bytecode বাদ দেয়। নতুন কপি খুললে সেই ফোল্ডারে সেটআপ ও প্রসঙ্গ পাঠ আবার করুন। ফিচার সম্পাদনার আগে নির্দেশনা ফাইলগুলো কমিট করুন। প্রথমে স্টার্টার শুরু ও কমিট করুন:

```bash
git init
git add .
git commit -m "কোর্স ল্যাবের ভিত্তি"
```

**এরপর `AGENTS.md` ও ঐচ্ছিক `CLAUDE.md` যোগ করুন**, যেখানে প্রসঙ্গ পাঠের অনুমোদিত উৎস ও পরীক্ষার কমান্ড থাকবে। ফাইলগুলো কমিট করুন, `git status --short` পরিষ্কার আছে নিশ্চিত করুন, তারপর ফিচার সম্পাদনা শুরু করুন। এই কমান্ডগুলো খোলা অনুশীলন ফোল্ডারে চালান, অন্য রিপোজিটরির মূলে নয়।

## সীমিত অনুরোধ দিন

**নির্বাচিত কোডিং এজেন্টে ল্যাব ফোল্ডার খুলুন।** এই কাজের প্যাকেট পাঠান:

```text
task_report.py-তে ঐচ্ছিক --status আর্গুমেন্ট যোগ করুন।
অনুমোদিত মান: open এবং done।
এটি না থাকলে বর্তমান মোট গণনার আউটপুট অপরিবর্তিত রাখুন।
থাকলে শুধু মিলে যাওয়া কাজ গুনুন এবং Total tasks: N দেখান।
দুটি মান, একটি অবৈধ মান এবং অপরিবর্তিত ডিফল্ট আউটপুটের পরীক্ষা যোগ করুন।
tasks.json বা সম্পর্কহীন ফাইল বদলাবেন না।
পরীক্ষা চালিয়ে সঠিক কমান্ড ও ফল জানান।
কোড ও পরীক্ষা শেষ হলে থামুন। commit বা push করবেন না।
```

**Windows-এ,** সেটআপে যাচাই করা `py -3` দিয়ে `python3` বদলান। সংরক্ষিত রিপোজিটরি নির্দেশনা ও কাজের প্যাকেটেও তাই করুন।

**কোড না চিনলে সম্পাদনার আগে সংক্ষিপ্ত পরিকল্পনা চান।** এজেন্টকে শুধু অস্থায়ী ল্যাব ফোল্ডার সম্পাদনের অনুমতি দিন। টুলভেদে অনুমতি নিয়ন্ত্রণ আলাদা, তাই shell কমান্ড বা ফাইল লেখার অনুমতি দেওয়ার আগে বর্তমান সেটিং পরীক্ষা করুন।

## ফলাফল পর্যালোচনা করুন

**ডিফ পড়ুন।** ফিল্টার ছাড়া আউটপুট অপরিবর্তিত আছে, ফিল্টার কেবল দুটি মান গ্রহণ করে এবং পরীক্ষা ত্রুটি ও অপরিবর্তিত ডিফল্ট আউটপুট যাচাই করে কি না দেখুন। পরীক্ষা তখনই পরিবর্তনের প্রমাণ, যখন সেগুলো চাওয়া আচরণ যাচাই করে।

```bash
git status --short
git diff -- task_report.py tests
python3 -m unittest discover -s tests -v
python3 task_report.py tasks.json
python3 task_report.py tasks.json --status open
python3 task_report.py tasks.json --status done
python3 task_report.py tasks.json --status invalid
```

**প্রত্যাশিত ফল:** প্রথম তিনটি রিপোর্ট কমান্ড 4, 2 ও 2 দেখায়। ভুল মান স্পষ্ট ত্রুটি দেখায় এবং প্রক্রিয়া শূন্য ছাড়া অন্য স্ট্যাটাসে শেষ হয়। নির্দিষ্ট ত্রুটি বার্তা বাস্তবায়নের ওপর নির্ভর করে। macOS বা Linux-এ ভুল কমান্ডের পরপরই `echo $?` চালিয়ে প্রস্থান কোড দেখুন। PowerShell-এ `$LASTEXITCODE` পরীক্ষা করুন।

| প্রমাণ | কী পরীক্ষা করবেন |
|---|---|
| **ফাইলের তালিকা** | কেবল প্রোগ্রাম ও পরীক্ষা বদলেছে |
| **ডিফ** | ফিল্টার লজিক অনুরোধের সঙ্গে মেলে |
| **পরীক্ষার ফল** | নতুন কেস চালানো হয়েছে এবং পাস করেছে |
| **হাতে চালানো** | ডিফল্ট, `open` ও `done` গণনা `tasks.json`-এর সঙ্গে মেলে |

**এজেন্ট পরীক্ষা না চালিয়ে ফল জানালে,** নিজে কমান্ড চালান। পরিবর্তন কাজের প্যাকেট ছাড়িয়ে গেলে সীমিত সংশোধন চান। অবস্থা পরিষ্কার না হলে খোলা অনুশীলন কপি মুছে মূল ZIP আবার খুলুন।

## অধ্যয়ন পথের উত্তর

**হাতে করা প্যাচ ব্যর্থ হলে এই সম্পূর্ণ ফাইলগুলো ব্যবহার করুন।** নতুন করে খোলা ল্যাব দিয়ে শুরু করুন, প্রথম ব্লক `task_report.py` এবং দ্বিতীয়টি `tests/test_task_report.py` নামে সংরক্ষণ করুন, তারপর ফলাফল পর্যালোচনার কমান্ড চালান। `tasks.json` ও `docs/requirements.md` অপরিবর্তিত রাখুন। ফাইল কপি করার আগে প্রথম ব্যর্থতার কথা লিখুন।

`task_report.py`:

```python
"""একটি JSON ফাইল থেকে কাজের সংখ্যা দেখান।"""

import argparse
import json
import sys
from pathlib import Path


def count_tasks(path: Path, status: str | None = None) -> int:
    """সব কাজ অথবা অনুমোদিত অবস্থার কাজ গুনুন।"""
    tasks = json.loads(path.read_text(encoding="utf-8"))
    if not isinstance(tasks, list):
        raise ValueError("task data must be a list")
    if status not in (None, "open", "done"):
        raise ValueError("status must be open or done")
    if status is None:
        return len(tasks)
    return sum(1 for task in tasks if task["status"] == status)


def main() -> int:
    parser = argparse.ArgumentParser(description="কর্মশালার কাজ গুনুন")
    parser.add_argument("path", type=Path, help="JSON কাজের তালিকার পথ")
    parser.add_argument("--status", choices=("open", "done"))
    args = parser.parse_args()
    try:
        total = count_tasks(args.path, args.status)
    except (OSError, ValueError, KeyError) as exc:
        print(f"Error: {exc}", file=sys.stderr)
        return 1
    print(f"Total tasks: {total}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

`tests/test_task_report.py`:

```python
"""কর্মশালার কাজের রিপোর্টের পরীক্ষা।"""

import json
import subprocess
import sys
import tempfile
import unittest
from pathlib import Path
from sys import path as module_path

ROOT = Path(__file__).resolve().parents[1]
module_path.insert(0, str(ROOT))
from task_report import count_tasks  # noqa: E402


class TaskReportTests(unittest.TestCase):
    def test_counts_four_sample_tasks(self):
        self.assertEqual(count_tasks(ROOT / "tasks.json"), 4)

    def test_rejects_non_list_data(self):
        with tempfile.TemporaryDirectory() as directory:
            sample = Path(directory) / "invalid.json"
            sample.write_text(json.dumps({"tasks": []}), encoding="utf-8")
            with self.assertRaises(ValueError):
                count_tasks(sample)

    def test_counts_each_approved_status(self):
        sample = ROOT / "tasks.json"
        self.assertEqual(count_tasks(sample, "open"), 2)
        self.assertEqual(count_tasks(sample, "done"), 2)

    def test_rejects_invalid_status_in_function(self):
        with self.assertRaises(ValueError):
            count_tasks(ROOT / "tasks.json", "pending")

    def test_default_command_stays_unchanged(self):
        result = subprocess.run(
            [sys.executable, str(ROOT / "task_report.py"), str(ROOT / "tasks.json")],
            capture_output=True, text=True, check=False,
        )
        self.assertEqual(result.returncode, 0)
        self.assertEqual(result.stdout.strip(), "Total tasks: 4")

    def test_invalid_command_exits_nonzero(self):
        result = subprocess.run(
            [sys.executable, str(ROOT / "task_report.py"), str(ROOT / "tasks.json"),
             "--status", "invalid"],
            capture_output=True, text=True, check=False,
        )
        self.assertNotEqual(result.returncode, 0)
        self.assertIn("invalid", result.stderr)


if __name__ == "__main__":
    unittest.main()
```

**কনটেক্সট ও ফল যাচাইয়ের পাঠে ফিল্টার পরীক্ষায় উত্তীর্ণ সম্পাদিত কপি রাখুন।** এই উদাহরণ দিয়ে কাজ উদ্ধার করলে পরের পাঠগুলোর জন্য নতুন কপি ও পাস করা পরীক্ষা রাখুন। ডিফ ও পরীক্ষার রেকর্ড ল্যাবের বাইরে রাখুন। প্রতিনিধি-দানের পাঠের আগে স্টার্টার ফিরিয়ে আনুন, অথবা ব্যর্থ চেষ্টা মুছে নতুন করে শুরু করুন।

## অনুশীলন ও যাচাই

**আপনার ফল:** ল্যাবের একটি ডিফ এবং চার সারির পর্যালোচনা রেকর্ড, যেখানে ফাইলের পরিধি, ডিফল্ট আচরণ, ফিল্টার আচরণ ও ভুল ইনপুট থাকবে। সংস্করণ-নির্দিষ্ট সমস্যা পুনরায় দেখার জন্য ব্যক্তিগত নোটে টুলের নাম ও সংস্করণ রাখুন।

**প্রত্যাশিত যুক্তি:** আপনি কাজের ধরন অনুযায়ী ইন্টারফেস বেছেছেন, সীমিত অনুরোধ দিয়েছেন, আসল সম্পাদনা দেখেছেন এবং এজেন্টের রিপোর্ট থেকে স্বাধীন যাচাই চালিয়েছেন।

## বোঝাপড়া যাচাই করুন

1. **প্রশ্ন:** স্ট্যাটাস ফিল্টারের সম্পাদনা কাজ করেছে, তার প্রমাণ কী? **উত্তর:** সীমিত ডিফ, পাস করা পরীক্ষা এবং ডিফল্ট, open, done ও ভুল মানের দেখা ফলাফল।
2. **প্রশ্ন:** এজেন্ট পরীক্ষা চালিয়েছে বললেই কি সেটি আপনার পরীক্ষার ফল? **উত্তর:** না। কমান্ড চালান অথবা পরীক্ষার ফল দেখুন।

## সমস্যা সমাধান

- **কমান্ড নেই:** লিঙ্ক করা বিক্রেতার নির্দেশিকা মেনে ইনস্টলেশন শেষ করুন, তারপর টার্মিনাল আবার খুলুন।
- **ফাইল অ্যাক্সেস নেই:** খোলা ল্যাব ফোল্ডার খুলে কর্মক্ষেত্রের অনুমতি পরীক্ষা করুন।
- **অপ্রত্যাশিত ফাইল বদলেছে:** পরের অনুরোধের আগে থামুন এবং `git status --short` পরীক্ষা করুন।
- **পরীক্ষা পাস, আচরণ ভুল:** হাতে একটি কেস পরীক্ষা করুন বা বাদ পড়া চাহিদার পরীক্ষা যোগ করুন।
