[Вернуться к курсу «Практический рабочий процесс с ИИ»](/effective-ai-course-start/)

**Агент для программирования читает файлы, предлагает изменения и запускает инструменты в рабочей области.** В этом уроке вы выполните небольшую задачу в репозитории. Выберите Codex в настольном приложении ChatGPT или CLI, Claude Code CLI либо OpenCode TUI. Затем проверьте изменение, прежде чем принимать его.

**Цель обучения:** вы выполните или примените вручную одно ограниченное изменение и проверите его diff и поведение.

## Главное

- **Codex в настольном приложении ChatGPT** предоставляет визуальную рабочую область для задач и проверки изменений.
- **Codex CLI** запускает сеанс Codex в терминале.
- **Claude Code CLI** выполняет рабочий процесс программирования Claude из терминала.
- **OpenCode TUI** предлагает работу в терминале с настраиваемыми поставщиками и разрешениями.
- **Diff и результат теста** важнее сообщения ассистента о завершении.

## Перед началом

**Требования:** завершите [настройку курса](/articles/effective-ai-course-setup/), включая исходный запуск и локальный снимок Git. Перед этим уроком пройдите [контекст репозитория](/articles/effective-ai-agents-md-context/) и [пакеты задач](/articles/effective-ai-task-packets/). Используйте агента для программирования, к которому у вас есть разрешенный доступ. Выделите 45 минут. Уровень сложности от начального до среднего.

**Используйте [стартовую лабораторную работу курса](/downloads/effective-ai-course-lab.zip)** в отдельной временной папке. Архив содержит небольшую программу отчета о задачах, примеры данных и тесты. Не используйте рабочий репозиторий для первого изменения. Добавьте фильтр `--status`, сохранив существующий общий счетчик.

## Учебный путь без агента

**Попросите чат-ассистента предложить такое же изменение,** если агент для программирования недоступен. Вставьте только `docs/requirements.md`, `task_report.py` и целевой файл теста из синтетической лабораторной работы. Попросите унифицированный diff и краткое объяснение. В унифицированном diff старые строки помечены знаком `-`, а новые знаком `+`. Откройте указанный файл в текстовом редакторе, замените старые строки предложенными и сохраните файл. Затем выполните все команды из раздела «Проверьте результат». Не меняйте `tasks.json`. Отметьте, что шаг с агентом не выполнялся. Итоговый проект включает отдельную функцию JSON, поэтому сравните решение фильтра с требованием и проверками из урока 5.

## Выберите интерфейс

**Сначала выберите среду проверки.** Codex в настольном приложении ChatGPT подходит для визуального проекта и проверки diff. Для работы в распакованной папке лаборатории подходит терминальный интерфейс. Сравнивайте терминальные варианты между собой:

| Терминальный инструмент | Проверка учетной записи или поставщика | Команда запуска |
|---|---|---|
| **Codex CLI** | Проверьте вход в Codex и локальные разрешения | `codex` |
| **Claude Code CLI** | Проверьте доступ к Claude Code и локальные разрешения | `claude` |
| **OpenCode TUI** | Настройте поддерживаемого поставщика моделей и разрешения | `opencode` |

**Установите выбранный инструмент и войдите в него по актуальному официальному руководству.** Прочитайте документацию [Codex CLI](https://learn.chatgpt.com/docs/codex/cli), [настольного приложения ChatGPT](https://learn.chatgpt.com/docs/app), [Claude Code](https://code.claude.com/docs/en/overview) или [OpenCode](https://opencode.ai/docs/). Команды, поддерживаемые платформы и требования к учетной записи меняются. В уроке используются только стабильные имена команд запуска и общий порядок проверки.

**Чтобы подробнее выбрать продукт,** прочитайте сравнение [агентов для CLI](/articles/cli-coding-agents-comparison/) или [агентов с графическим интерфейсом](/articles/gui-coding-agents-comparison/). Руководства по [Codex CLI и настольной версии](/articles/codex-cli-vs-desktop/), [Claude Code CLI и настольной версии](/articles/claude-code-cli-vs-desktop/) и [OpenCode CLI и настольной версии](/articles/opencode-cli-vs-desktop/) сравнивают интерфейсы каждого продукта.

**Начните с папки лаборатории.** Для каждого интерфейса нужно явно выбрать рабочую область:

1. **Codex для рабочего стола:** откройте настольное приложение ChatGPT, выберите распакованную лабораторию как локальный проект и запустите в нем локальную задачу. До внесения изменений проверьте путь к папке и запросы на подтверждение. Для размещенной задачи используется отдельная копия рабочей области.
2. **Codex CLI:** выполните `cd /path/to/effective-ai-course-lab`, затем `codex`. Проверьте показанную рабочую папку и режим подтверждения.
3. **Claude Code CLI:** выполните ту же команду `cd`, затем `claude`. Проверьте папку проекта и разрешения для инструментов.
4. **OpenCode TUI:** выполните ту же команду `cd`, затем `opencode`. Проверьте выбранного поставщика, проект и разрешения.

**Чат ChatGPT и Claude Projects работают с беседами и общими справочными файлами.** Codex и Claude Code работают в кодовой области с инструментами для файлов и команд. У OpenCode также есть настольный интерфейс и IDE-интерфейсы, но в этом уроке используется терминал. Поставщик, учетная запись и локальное или размещенное исполнение различаются. Запишите выбранную среду, а не считайте все сеансы одинаковым запуском.

**До открытия лаборатории проверьте пять пунктов:** поддерживаемую операционную систему, аутентификацию, стоимость поставщика или учетной записи, разрешения на файлы и команды, а также локальное исполнение или запуск на удаленном узле. Запишите свой выбор. Не предполагайте, что настольное приложение и терминальный инструмент используют одну рабочую область.

## Проверьте стартовый проект

**Снова откройте чистую папку лаборатории** из урока о контексте репозитория. В этой копии уже сохранен ваш `AGENTS.md` и необязательный файл инструкций `CLAUDE.md`. Изучите файлы, прежде чем просить агента их изменить. Запустите исходные тесты из этой папки.

```bash
python3 -m unittest discover -s tests -v
python3 task_report.py tasks.json
```

**Ожидаемый исходный результат:** отчет выводит `Total tasks: 4`. В тестовом запуске указаны два теста, а завершение отмечено `OK`. Если любой тест завершится с ошибкой, остановитесь и проверьте распакованные файлы. Не приписывайте агенту исправление проблемной исходной версии.

**Используйте локальные снимки Git** из настройки курса и урока о контексте репозитория. `AGENTS.md` и необязательный `CLAUDE.md` уже должны быть сохранены в Git. Перед изменением функции выполните `git status --short` и убедитесь, что список пуст. Агент также не должен создавать коммит. Архив не содержит историю Git. Файл `.gitignore` исключает байткод Python, создаваемый при запуске тестов. Если вы распаковали новую копию, повторите в этой папке настройку курса и урок о контексте репозитория. Сначала сохраните файлы инструкций, затем меняйте функцию. Сначала инициализируйте и сохраните стартовый проект:

```bash
git init
git add .
git commit -m "Основа лаборатории курса"
```

**Затем добавьте `AGENTS.md` и необязательный `CLAUDE.md`** с утвержденным источником и командой тестирования из урока о контексте репозитория. Сохраните эти файлы, проверьте, что `git status --short` не показывает изменений, и приступайте к функции. Выполняйте эти команды в распакованной папке для упражнений, а не в корне другого репозитория.

## Отправьте ограниченный запрос

**Откройте папку лаборатории** в выбранном агенте для программирования. Отправьте ему этот пакет задачи:

```text
Добавьте в task_report.py необязательный аргумент --status.
Допустимые значения: open и done.
Если аргумент не указан, оставьте текущий вывод общего числа без изменений.
Если он указан, считайте только подходящие задачи и выведите Total tasks: N.
Добавьте тесты для обоих значений, недопустимого значения и неизмененного вывода по умолчанию.
Не меняйте tasks.json и не связанные с задачей файлы.
Запустите тесты и сообщите точную команду и результат.
Остановитесь после кода и тестов. Не создавайте commit и не выполняйте push.
```

**В Windows** замените `python3` на проверенную при настройке команду `py -3`, в том числе в сохраненных инструкциях репозитория и пакете задачи.

**Перед изменением попросите краткий план,** если код вам незнаком. Разрешите агенту изменять только временную папку лаборатории. Настройки разрешений отличаются в разных инструментах, поэтому проверьте их перед разрешением команд оболочки и записи файлов.

## Проверьте результат

**Прочитайте diff.** Проверьте, что вывод без фильтра не изменился, фильтр принимает только два значения, а тесты охватывают ошибочное значение и прежний вывод по умолчанию. Успешные тесты подтверждают изменение только в том случае, если проверяют требуемое поведение.

```bash
git status --short
git diff -- task_report.py tests
python3 -m unittest discover -s tests -v
python3 task_report.py tasks.json
python3 task_report.py tasks.json --status open
python3 task_report.py tasks.json --status done
python3 task_report.py tasks.json --status invalid
```

**Ожидаемый результат:** первые три команды отчета выводят числа 4, 2 и 2. Для недопустимого значения появляется понятная ошибка, а процесс завершается с кодом, отличным от нуля. Точный текст ошибки зависит от реализации. В macOS или Linux сразу после недопустимой команды выполните `echo $?`, чтобы узнать код завершения. В PowerShell проверьте `$LASTEXITCODE`.

| Свидетельство | Что проверить |
|---|---|
| **Список файлов** | Изменились только программа и тесты |
| **Diff** | Логика фильтра соответствует запросу |
| **Результат тестов** | Новые случаи выполнены и прошли |
| **Ручной запуск** | Обычные результаты и значения для `open` и `done` совпадают с `tasks.json` |

**Если агент сообщает результат, но не запускает тесты,** выполните команду самостоятельно. Если изменения выходят за рамки пакета задачи, попросите внести ограниченную правку. Если состояние непонятно, удалите распакованную учебную копию и снова распакуйте исходный ZIP.

## Ответы для учебного пути

**Используйте эти полные файлы, если ручная правка не сработала.** Начните с новой распакованной лаборатории, сохраните первый блок как `task_report.py`, а второй как `tests/test_task_report.py`, затем выполните команды из раздела «Проверьте результат». Не меняйте `tasks.json` и `docs/requirements.md`. Перед копированием файлов запишите первоначальную ошибку.

`task_report.py`:

```python
"""Выводит число задач из JSON-файла."""

import argparse
import json
import sys
from pathlib import Path


def count_tasks(path: Path, status: str | None = None) -> int:
    """Считает все задачи или задачи с допустимым статусом."""
    tasks = json.loads(path.read_text(encoding="utf-8"))
    if not isinstance(tasks, list):
        raise ValueError("task data must be a list")
    if status not in (None, "open", "done"):
        raise ValueError("status must be open or done")
    if status is None:
        return len(tasks)
    return sum(1 for task in tasks if task["status"] == status)


def main() -> int:
    parser = argparse.ArgumentParser(description="Подсчет задач мастерской")
    parser.add_argument("path", type=Path, help="путь к JSON-списку задач")
    parser.add_argument("--status", choices=("open", "done"))
    args = parser.parse_args()
    try:
        total = count_tasks(args.path, args.status)
    except (OSError, ValueError, KeyError) as exc:
        print(f"Error: {exc}", file=sys.stderr)
        return 1
    print(f"Total tasks: {total}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

`tests/test_task_report.py`:

```python
"""Тесты отчета о задачах мастерской."""

import json
import subprocess
import sys
import tempfile
import unittest
from pathlib import Path
from sys import path as module_path

ROOT = Path(__file__).resolve().parents[1]
module_path.insert(0, str(ROOT))
from task_report import count_tasks  # noqa: E402


class TaskReportTests(unittest.TestCase):
    def test_counts_four_sample_tasks(self):
        self.assertEqual(count_tasks(ROOT / "tasks.json"), 4)

    def test_rejects_non_list_data(self):
        with tempfile.TemporaryDirectory() as directory:
            sample = Path(directory) / "invalid.json"
            sample.write_text(json.dumps({"tasks": []}), encoding="utf-8")
            with self.assertRaises(ValueError):
                count_tasks(sample)

    def test_counts_each_approved_status(self):
        sample = ROOT / "tasks.json"
        self.assertEqual(count_tasks(sample, "open"), 2)
        self.assertEqual(count_tasks(sample, "done"), 2)

    def test_rejects_invalid_status_in_function(self):
        with self.assertRaises(ValueError):
            count_tasks(ROOT / "tasks.json", "pending")

    def test_default_command_stays_unchanged(self):
        result = subprocess.run(
            [sys.executable, str(ROOT / "task_report.py"), str(ROOT / "tasks.json")],
            capture_output=True, text=True, check=False,
        )
        self.assertEqual(result.returncode, 0)
        self.assertEqual(result.stdout.strip(), "Total tasks: 4")

    def test_invalid_command_exits_nonzero(self):
        result = subprocess.run(
            [sys.executable, str(ROOT / "task_report.py"), str(ROOT / "tasks.json"),
             "--status", "invalid"],
            capture_output=True, text=True, check=False,
        )
        self.assertNotEqual(result.returncode, 0)
        self.assertIn("invalid", result.stderr)


if __name__ == "__main__":
    unittest.main()
```

## Практика и проверка

**Ваш результат:** diff лаборатории и четырехстрочная запись проверки: затронутые файлы, поведение по умолчанию, поведение фильтра и недопустимый ввод. Сохраните название и версию инструмента в личных заметках, чтобы воспроизвести проблему конкретной версии.

**Ожидаемое рассуждение:** вы выбрали удобный интерфейс, ограничили задачу, изучили реальное изменение и провели проверку независимо от отчета агента.

## Проверьте понимание

1. **Вопрос:** Что подтверждает работу фильтра статуса? **Ответ:** Ограниченный diff, успешные тесты и проверенные результаты для режима по умолчанию, open, done и ошибочного значения.
2. **Вопрос:** Считается ли сообщение агента о запуске тестов вашим результатом? **Ответ:** Нет. Запустите команду или проверьте вывод тестов.

## Устранение неполадок

- **Команда не найдена:** завершите установку по руководству поставщика, затем снова откройте терминал.
- **Нет доступа к файлам:** откройте распакованную папку лаборатории и проверьте разрешения рабочей области.
- **Изменились неожиданные файлы:** остановитесь и проверьте `git status --short` перед новым запросом.
- **Тесты прошли, но поведение неверно:** добавьте ручной пример или тест для пропущенного требования.
