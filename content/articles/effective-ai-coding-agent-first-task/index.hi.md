**कोडिंग एजेंट कार्यक्षेत्र में फ़ाइलें पढ़ता है, बदलाव सुझाता है और उपकरण चलाता है।** इस पाठ में आप रिपॉज़िटरी का एक छोटा काम करेंगे। ChatGPT डेस्कटॉप ऐप या CLI में Codex, Claude Code CLI अथवा OpenCode TUI चुनें। बदलाव स्वीकार करने से पहले उसकी समीक्षा करें।

**सीखने का लक्ष्य:** आप एक सीमित बदलाव चलाएँगे या स्वयं लागू करेंगे, फिर उसका अंतर और व्यवहार जाँचेंगे।

## मुख्य बातें

- **ChatGPT डेस्कटॉप ऐप में Codex** कार्य और समीक्षा के लिए दृश्य कार्यक्षेत्र देता है।
- **Codex CLI** टर्मिनल से Codex सत्र चलाता है।
- **Claude Code CLI** टर्मिनल से Claude का कोडिंग कार्यप्रवाह चलाता है।
- **OpenCode TUI** कॉन्फ़िगर किए जा सकने वाले प्रदाता और अनुमतियों वाला टर्मिनल कार्यप्रवाह देता है।
- **डिफ़ और परीक्षण का परिणाम** सहायक के पूरा होने वाले संदेश से अधिक मायने रखते हैं।

## शुरू करने से पहले

**ज़रूरी तैयारी:** [पाठ्यक्रम सेटअप](/articles/effective-ai-course-setup/) पूरा करें, जिसमें प्रारंभिक परीक्षण और स्थानीय Git स्नैपशॉट शामिल हैं। इस पाठ से पहले [रिपॉज़िटरी संदर्भ](/articles/effective-ai-agents-md-context/) और [कार्य पैकेट](/articles/effective-ai-task-packets/) पूरे करें। ऐसा कोडिंग एजेंट इस्तेमाल करें जिसे उपयोग करने की आपको अनुमति है। 45 मिनट रखें। कठिनाई शुरुआती से मध्यम है।

**[पाठ्यक्रम की स्टार्टर लैब](/downloads/effective-ai-course-lab.zip)** किसी अस्थायी फ़ोल्डर में इस्तेमाल करें। संग्रह में छोटा कार्य-रिपोर्ट प्रोग्राम, नमूना डेटा और परीक्षण हैं। पहली बार संपादन के लिए उत्पादन रिपॉज़िटरी न लें। मौजूदा कुल संख्या को बनाए रखते हुए `--status` फ़िल्टर जोड़ें।

## कोडिंग एजेंट के बिना अध्ययन मार्ग

**कोडिंग एजेंट उपलब्ध न हो तो चैट सहायक से वही बदलाव सुझाने को कहें।** सिंथेटिक लैब से केवल `docs/requirements.md`, `task_report.py` और लक्षित परीक्षण फ़ाइल दें। यूनिफ़ाइड डिफ़ और छोटा स्पष्टीकरण माँगें। यूनिफ़ाइड डिफ़ में पुरानी पंक्तियों से पहले `-` और नई पंक्तियों से पहले `+` होता है। बताई गई फ़ाइल टेक्स्ट एडिटर में खोलें, पुरानी पंक्तियों को प्रस्तावित बदलाव से बदलें और सहेजें। फिर परिणाम की समीक्षा वाले सभी कमांड चलाएँ। `tasks.json` न बदलें। दर्ज करें कि एजेंट वाला चरण नहीं चला। अंतिम परियोजना में अलग JSON सुविधा है, इसलिए फ़िल्टर समाधान की तुलना पाठ 5 की आवश्यकता और जाँच से करें।

## इंटरफ़ेस चुनें

**पहले समीक्षा का माध्यम चुनें।** ChatGPT डेस्कटॉप ऐप में Codex दृश्य परियोजना और डिफ़ की समीक्षा के लिए उपयुक्त है। निकाली गई लैब निर्देशिका में काम करने के लिए टर्मिनल इंटरफ़ेस उपयुक्त है। टर्मिनल विकल्पों की आपस में तुलना करें:

| टर्मिनल उपकरण | खाता या प्रदाता जाँच | शुरू करने का कमांड |
|---|---|---|
| **Codex CLI** | Codex साइन-इन और स्थानीय अनुमतियाँ जाँचें | `codex` |
| **Claude Code CLI** | Claude Code पहुँच और स्थानीय अनुमतियाँ जाँचें | `claude` |
| **OpenCode TUI** | समर्थित मॉडल प्रदाता और अनुमतियाँ सेट करें | `opencode` |

**चुने हुए उपकरण की मौजूदा आधिकारिक गाइड से इंस्टॉल और साइन इन करें।** [Codex CLI](https://learn.chatgpt.com/docs/codex/cli), [ChatGPT डेस्कटॉप ऐप](https://learn.chatgpt.com/docs/app), [Claude Code](https://code.claude.com/docs/en/overview) या [OpenCode](https://opencode.ai/docs/) पढ़ें। कमांड, समर्थित प्लेटफ़ॉर्म और खाते की शर्तें बदलती रहती हैं। इस पाठ में स्थिर लॉन्च नाम और साझा समीक्षा प्रक्रिया उपयोग होती है।

**उत्पाद को विस्तार से चुनने के लिए,** साइट की [CLI कोडिंग एजेंट तुलना](/articles/cli-coding-agents-comparison/) या [ग्राफ़िकल इंटरफ़ेस कोडिंग एजेंट तुलना](/articles/gui-coding-agents-comparison/) पढ़ें। [Codex CLI और डेस्कटॉप](/articles/codex-cli-vs-desktop/), [Claude Code CLI और डेस्कटॉप](/articles/claude-code-cli-vs-desktop/) और [OpenCode CLI और डेस्कटॉप](/articles/opencode-cli-vs-desktop/) की मार्गदर्शिकाएँ हर उत्पाद के इंटरफ़ेस की तुलना करती हैं।

**लैब फ़ोल्डर से शुरू करें।** हर इंटरफ़ेस में कार्यक्षेत्र स्पष्ट रूप से चुनना होता है:

1. **Codex डेस्कटॉप:** ChatGPT डेस्कटॉप ऐप खोलें, निकाली गई लैब को स्थानीय परियोजना चुनें और उसमें स्थानीय काम शुरू करें। संपादन से पहले फ़ोल्डर पथ और अनुमोदन संकेत जाँचें। होस्ट किया गया काम अलग कार्यक्षेत्र प्रति इस्तेमाल करता है।
2. **Codex CLI:** `cd /path/to/effective-ai-course-lab` चलाएँ, फिर `codex` चलाएँ। दिखाई गई कार्य निर्देशिका और अनुमोदन मोड की पुष्टि करें।
3. **Claude Code CLI:** वही `cd` कमांड चलाएँ, फिर `claude` चलाएँ। परियोजना फ़ोल्डर और उपकरण अनुमतियों की पुष्टि करें।
4. **OpenCode TUI:** वही `cd` कमांड चलाएँ, फिर `opencode` चलाएँ। चुने हुए प्रदाता, परियोजना और अनुमति सेटिंग की पुष्टि करें।

**ChatGPT chat और Claude Projects बातचीत और साझा संदर्भ फ़ाइलें संभालते हैं।** Codex और Claude Code फ़ाइल तथा कमांड उपकरणों वाले कोड कार्यक्षेत्र में चलते हैं। OpenCode में डेस्कटॉप और IDE माध्यम भी हैं, पर यह पाठ टर्मिनल का उपयोग करता है। प्रदाता, खाता और स्थानीय या होस्ट की गई प्रक्रिया अलग होती है। हर सत्र को एक जैसा मानने के बजाय चुना गया माध्यम दर्ज करें।

**लैब खोलने से पहले पाँच बातें जाँचें:** समर्थित ऑपरेटिंग सिस्टम, प्रमाणीकरण, प्रदाता या खाते की लागत, फ़ाइल और कमांड अनुमतियाँ, और प्रक्रिया स्थानीय है या दूरस्थ होस्ट पर। अपना चुनाव दर्ज करें। यह न मानें कि डेस्कटॉप ऐप और टर्मिनल उपकरण एक ही कार्यक्षेत्र इस्तेमाल करते हैं।

## स्टार्टर की जाँच करें

**रिपॉज़िटरी संदर्भ पाठ की साफ़ लैब निर्देशिका फिर खोलें।** इस प्रति में आपका कमिट किया `AGENTS.md` और वैकल्पिक `CLAUDE.md` मार्गदर्शन है। एजेंट से संपादन माँगने से पहले फ़ाइलें देखें। इसी निर्देशिका से आधार परीक्षण चलाएँ।

```bash
python3 -m unittest discover -s tests -v
python3 task_report.py tasks.json
```

**अपेक्षित आधार परिणाम:** रिपोर्ट `Total tasks: 4` दिखाती है। परीक्षण रन दो परीक्षणों के नाम दिखाता है और `OK` पर समाप्त होता है। कोई परीक्षण विफल हो तो रुकें और निकाली गई फ़ाइलों की जाँच करें। खराब शुरुआती स्थिति को ठीक करने का श्रेय एजेंट को न दें।

**पाठ्यक्रम सेटअप और रिपॉज़िटरी संदर्भ पाठ के स्थानीय Git स्नैपशॉट इस्तेमाल करें।** `AGENTS.md` और वैकल्पिक `CLAUDE.md` पहले से कमिट होने चाहिए। सुविधा संपादित करने से पहले `git status --short` चलाएँ और सूची खाली होने की अपेक्षा करें। एजेंट को भी कमिट नहीं करना है। संग्रह में Git इतिहास नहीं है। इसकी `.gitignore` फ़ाइल परीक्षण चलाने से बनने वाले Python bytecode को बाहर रखती है। नई प्रति निकाली हो तो उसी फ़ोल्डर में सेटअप और संदर्भ पाठ दोहराएँ। सुविधा संपादन से पहले निर्देश फ़ाइलों को कमिट करें। पहले स्टार्टर शुरू और कमिट करें:

```bash
git init
git add .
git commit -m "कोर्स लैब आधार"
```

**इसके बाद `AGENTS.md` और वैकल्पिक `CLAUDE.md` जोड़ें**, जिनमें संदर्भ पाठ का स्वीकृत स्रोत और परीक्षण कमांड हों। इन फ़ाइलों को कमिट करें, `git status --short` साफ़ होने की पुष्टि करें, फिर सुविधा संपादित करें। कमांड निकाली हुई अभ्यास निर्देशिका में चलाएँ, किसी अन्य रिपॉज़िटरी के मूल फ़ोल्डर में नहीं।

## सीमित अनुरोध दें

**चुने हुए कोडिंग एजेंट में लैब फ़ोल्डर खोलें।** यह कार्य पैकेट भेजें:

```text
task_report.py में वैकल्पिक --status तर्क जोड़ें।
अनुमत मान: open और done।
इसके बिना कुल संख्या का वर्तमान आउटपुट न बदलें।
इसके साथ केवल मेल खाते कार्य गिनें और Total tasks: N दिखाएँ।
दोनों मानों, एक अमान्य मान और अपरिवर्तित डिफ़ॉल्ट आउटपुट के परीक्षण जोड़ें।
tasks.json या असंबंधित फ़ाइलें न बदलें।
परीक्षण चलाएँ और सटीक कमांड व परिणाम बताएँ।
कोड और परीक्षण के बाद रुकें। कमिट या पुश न करें।
```

**Windows पर,** `python3` को सेटअप में जाँचे `py -3` से बदलें, सहेजे गए रिपॉज़िटरी निर्देशों और कार्य पैकेट में भी।

**कोड की जानकारी न हो तो संपादन से पहले छोटी योजना माँगें।** एजेंट को केवल अस्थायी लैब फ़ोल्डर संपादित करने की अनुमति दें। उपकरणों में अनुमति नियंत्रण अलग होते हैं। शेल कमांड या फ़ाइल लेखन की अनुमति देने से पहले मौजूदा सेटिंग देखें।

## परिणाम की समीक्षा करें

**डिफ़ पढ़ें।** जाँचें कि बिना फ़िल्टर का आउटपुट वैसा ही रहे, फ़िल्टर केवल दो मान स्वीकार करे, और परीक्षण त्रुटि तथा अपरिवर्तित डिफ़ॉल्ट आउटपुट को कवर करें। परीक्षण तभी बदलाव का प्रमाण हैं जब वे माँगा गया व्यवहार जाँचें।

```bash
git status --short
git diff -- task_report.py tests
python3 -m unittest discover -s tests -v
python3 task_report.py tasks.json
python3 task_report.py tasks.json --status open
python3 task_report.py tasks.json --status done
python3 task_report.py tasks.json --status invalid
```

**अपेक्षित परिणाम:** पहली तीन रिपोर्ट कमांड 4, 2 और 2 दिखाती हैं। अमान्य मान स्पष्ट त्रुटि दिखाता है और प्रक्रिया गैर-शून्य स्थिति से समाप्त होती है। सटीक संदेश कार्यान्वयन पर निर्भर है। macOS या Linux पर अमान्य कमांड के तुरंत बाद `echo $?` चलाकर निकास कोड पढ़ें। PowerShell में `$LASTEXITCODE` देखें।

| प्रमाण | क्या देखें |
|---|---|
| **फ़ाइल सूची** | केवल प्रोग्राम और परीक्षण बदले |
| **डिफ़** | फ़िल्टर का तर्क अनुरोध से मेल खाता है |
| **परीक्षण आउटपुट** | नए मामले चले और पास हुए |
| **मैन्युअल रन** | डिफ़ॉल्ट, `open` और `done` की संख्या `tasks.json` से मेल खाती है |

**एजेंट परीक्षण चलाए बिना परिणाम बताए,** तो कमांड स्वयं चलाएँ। बदलाव कार्य पैकेट से बाहर जाए तो सीमित सुधार माँगें। स्थिति स्पष्ट न हो तो निकाली गई अभ्यास प्रति हटाकर मूल ZIP फिर से निकालें।

## अध्ययन मार्ग के उत्तर

**हाथ से लगाया पैच विफल हो तो ये पूरी फ़ाइलें इस्तेमाल करें।** नई निकाली गई लैब से शुरू करें, पहला ब्लॉक `task_report.py` और दूसरा `tests/test_task_report.py` के रूप में सहेजें, फिर परिणाम समीक्षा के कमांड चलाएँ। `tasks.json` और `docs/requirements.md` न बदलें। फ़ाइलें कॉपी करने से पहले पहली विफलता दर्ज करें।

`task_report.py`:

```python
"""JSON फ़ाइल से कार्यों की संख्या दिखाएँ।"""

import argparse
import json
import sys
from pathlib import Path


def count_tasks(path: Path, status: str | None = None) -> int:
    """सभी कार्य या स्वीकृत स्थिति वाले कार्य गिनें।"""
    tasks = json.loads(path.read_text(encoding="utf-8"))
    if not isinstance(tasks, list):
        raise ValueError("task data must be a list")
    if status not in (None, "open", "done"):
        raise ValueError("status must be open or done")
    if status is None:
        return len(tasks)
    return sum(1 for task in tasks if task["status"] == status)


def main() -> int:
    parser = argparse.ArgumentParser(description="कार्यशाला के कार्य गिनें")
    parser.add_argument("path", type=Path, help="JSON कार्य सूची का पथ")
    parser.add_argument("--status", choices=("open", "done"))
    args = parser.parse_args()
    try:
        total = count_tasks(args.path, args.status)
    except (OSError, ValueError, KeyError) as exc:
        print(f"Error: {exc}", file=sys.stderr)
        return 1
    print(f"Total tasks: {total}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

`tests/test_task_report.py`:

```python
"""कार्यशाला कार्य रिपोर्ट के परीक्षण।"""

import json
import subprocess
import sys
import tempfile
import unittest
from pathlib import Path
from sys import path as module_path

ROOT = Path(__file__).resolve().parents[1]
module_path.insert(0, str(ROOT))
from task_report import count_tasks  # noqa: E402


class TaskReportTests(unittest.TestCase):
    def test_counts_four_sample_tasks(self):
        self.assertEqual(count_tasks(ROOT / "tasks.json"), 4)

    def test_rejects_non_list_data(self):
        with tempfile.TemporaryDirectory() as directory:
            sample = Path(directory) / "invalid.json"
            sample.write_text(json.dumps({"tasks": []}), encoding="utf-8")
            with self.assertRaises(ValueError):
                count_tasks(sample)

    def test_counts_each_approved_status(self):
        sample = ROOT / "tasks.json"
        self.assertEqual(count_tasks(sample, "open"), 2)
        self.assertEqual(count_tasks(sample, "done"), 2)

    def test_rejects_invalid_status_in_function(self):
        with self.assertRaises(ValueError):
            count_tasks(ROOT / "tasks.json", "pending")

    def test_default_command_stays_unchanged(self):
        result = subprocess.run(
            [sys.executable, str(ROOT / "task_report.py"), str(ROOT / "tasks.json")],
            capture_output=True, text=True, check=False,
        )
        self.assertEqual(result.returncode, 0)
        self.assertEqual(result.stdout.strip(), "Total tasks: 4")

    def test_invalid_command_exits_nonzero(self):
        result = subprocess.run(
            [sys.executable, str(ROOT / "task_report.py"), str(ROOT / "tasks.json"),
             "--status", "invalid"],
            capture_output=True, text=True, check=False,
        )
        self.assertNotEqual(result.returncode, 0)
        self.assertIn("invalid", result.stderr)


if __name__ == "__main__":
    unittest.main()
```

**संदर्भ और परिणाम-जाँच पाठों के लिए फ़िल्टर परीक्षण पास करने वाली संपादित प्रति रखें।** यदि इस समाधान से काम वापस बनाया, तो आगे के पाठों के लिए नई प्रति और उसके सफल फ़िल्टर परीक्षण रखें। डिफ़ और परीक्षण रिकॉर्ड लैब के बाहर रखें। प्रतिनिधि-कार्य पाठ से पहले स्टार्टर बहाल करें या असफल प्रयास हटाकर साफ़ शुरुआत करें।

## अभ्यास और जाँच

**आपका परिणाम:** लैब का डिफ़ और चार पंक्तियों का समीक्षा रिकॉर्ड, जिसमें फ़ाइल दायरा, डिफ़ॉल्ट व्यवहार, फ़िल्टर व्यवहार और अमान्य इनपुट शामिल हों। संस्करण-विशिष्ट समस्या दोहराने के लिए उपकरण का नाम और संस्करण निजी नोट में रखें।

**अपेक्षित तर्क:** आपने अपने काम के तरीके के अनुसार इंटरफ़ेस चुना, सीमित अनुरोध दिया, वास्तविक संपादन देखा और एजेंट की रिपोर्ट से स्वतंत्र जाँच चलाई।

## अपनी समझ जाँचें

1. **प्रश्न:** स्थिति फ़िल्टर का बदलाव काम करता है, इसका प्रमाण क्या है? **उत्तर:** सीमित डिफ़, पास हुए परीक्षण और डिफ़ॉल्ट, open, done तथा अमान्य मान के देखे गए परिणाम।
2. **प्रश्न:** एजेंट का यह कहना कि उसने परीक्षण चलाए, क्या आपका परीक्षण परिणाम है? **उत्तर:** नहीं। कमांड चलाएँ या परीक्षण आउटपुट देखें।

## समस्या निवारण

- **कमांड नहीं मिला:** लिंक की गई विक्रेता गाइड से इंस्टॉलेशन पूरा करें, फिर टर्मिनल दोबारा खोलें।
- **फ़ाइल पहुँच नहीं:** निकाली गई लैब निर्देशिका खोलें और कार्यक्षेत्र अनुमतियाँ जाँचें।
- **अनपेक्षित फ़ाइलें बदलीं:** अगला अनुरोध देने से पहले रुकें और `git status --short` देखें।
- **परीक्षण पास, व्यवहार गलत:** हाथ से एक मामला जाँचें या छूटी आवश्यकता का परीक्षण जोड़ें।
