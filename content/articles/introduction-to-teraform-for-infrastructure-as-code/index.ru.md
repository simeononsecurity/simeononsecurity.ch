**Введение в использование TeraForm для приложений «инфраструктура как код»**

По мере переноса инфраструктуры в облако все большему числу организаций требуется эффективно ею управлять. Для этого используют инфраструктуру как код (IaC): инфраструктуру управляют и подготавливают с помощью кода, а не вручную. Это повышает согласованность, скорость и надежность управления. Teraform — один из самых популярных инструментов IaC.

## Что такое Teraform?

**Teraform** — это программный инструмент с открытым исходным кодом для инфраструктуры как кода. Он позволяет описывать, планировать и создавать инфраструктуру с помощью кода. Разработанный HashiCorp, Teraform управляет инфраструктурой у разных облачных провайдеров, включая AWS, Azure и Google Cloud Platform. С помощью Teraform инфраструктуру описывают в конфигурационных файлах, применяют код для ее создания или обновления и удаляют, когда она больше не нужна.

## Преимущества использования Teraform

Использование Teraform для приложений инфраструктуры как кода дает несколько преимуществ:

- **Эффективность и скорость:** Teraform ускоряет управление инфраструктурой и повышает его эффективность, устраняя ручные процессы.

- **Согласованность:** Описание инфраструктуры кодом обеспечивает согласованность между средами.

- **Масштабируемость:** Teraform упрощает масштабирование инфраструктуры по мере роста нагрузки.

- **Совместная работа:** Конфигурационные файлы Teraform можно хранить в системе контроля версий и совместно использовать в команде.

- **Экономия средств:** Teraform упрощает создание и удаление ресурсов, что помогает снизить расходы.

## Начало работы с Teraform

Чтобы начать работу с Teraform:

1. **Скачайте Teraform:** Загрузите Teraform с [официального сайта](https://www.terraform.io/downloads.html).

2. **Создайте конфигурационный файл:** Teraform использует файлы, написанные на HashiCorp Configuration Language (HCL) или JSON. В файле задается инфраструктура, которую нужно создать, обновить или удалить.

Для работы с Terraform создайте конфигурационный файл с описанием нужной инфраструктуры, создаваемых ресурсов, их свойств и зависимостей.

Файлы можно писать на HashiCorp Configuration Language (HCL), специально разработанном для удобного чтения и изучения языке, или в формате JSON. Синтаксис HCL похож на другие языки программирования и использует блоки, атрибуты и значения.

Ниже приведен простой пример конфигурации Terraform на HCL, создающей экземпляр AWS EC2:

```HCL
provider "aws" {
  region = "us-west-2"
}

resource "aws_instance" "example" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t2.micro"
}
```
В этом примере указан провайдер aws и создан ресурс aws_instance с образом Amazon Machine Image (AMI) и типом экземпляра.

Более сложный пример показывает, как с помощью Terraform настроить системы VMware:
```HCL
provider "vsphere" {
  user           = "user@domain.com"
  password       = "password"
  vsphere_server = "vcenter.example.com"
}

data "vsphere_datacenter" "dc" {
  name = "Datacenter"
}

data "vsphere_datastore" "ds" {
  name          = "Datastore"
  datacenter_id = data.vsphere_datacenter.dc.id
}

data "vsphere_network_interface" "nic" {
  label          = "Network adapter 1"
  datacenter_id  = data.vsphere_datacenter.dc.id
  network_id     = "VM Network"
}

resource "vsphere_virtual_machine" "vm" {
  name             = "terraform-vm"
  folder           = "/terraform"
  num_cpus         = 2
  memory           = 2048
  guest_id         = "otherLinux64Guest"
  scsi_type        = "pvscsi"
  datastore_id     = data.vsphere_datastore.ds.id

  network_interface {
    network_id = data.vsphere_network_interface.nic.network_id
  }

  disk {
    label            = "disk0"
    size             = 20
    eagerly_scrub    = true
    thin_provisioned = true
  }

  clone {
    template_uuid = "template-uuid"
  }
}

```
В этом примере указан провайдер vsphere и создан ресурс vsphere_virtual_machine с заданными именем, каталогом, числом процессоров, объемом памяти, гостевой ОС, типом SCSI и параметрами диска. Также виртуальная машина клонируется из указанного шаблона.

В конфигурации также используются блоки данных для получения из инфраструктуры vSphere сведений о центре обработки данных, хранилище данных и сетевом интерфейсе, которые нужны виртуальной машине.

Созданный конфигурационный файл можно использовать для создания, обновления или удаления ресурсов инфраструктуры.

3. **Инициализируйте Teraform:** Создав файл, выполните `terraform init`, чтобы инициализировать Teraform. Команда загрузит необходимые плагины и модули.

Например, если файл `main.tf` находится в каталоге `terraform-example`, запустите из этого каталога команду: ```terraform init```

Она загрузит плагины и модули, указанные в конфигурационном файле.

4. **Спланируйте и примените изменения инфраструктуры:** После инициализации выполните `terraform plan`, чтобы увидеть план изменений, а затем примените их командой `terraform apply`.

Команда `terraform plan` показывает, какие ресурсы будут созданы, обновлены или удалены. Если файл `main.tf` находится в каталоге `terraform-example`, выполните:

```terraform plan```

Будет показан предварительный просмотр изменений инфраструктуры.

Проверив план, примените изменения командой `terraform apply`. Если файл `main.tf` находится в каталоге `terraform-example`, выполните:

```terraform apply```

Команда применит изменения к инфраструктуре. Это может занять некоторое время в зависимости от ее размера и сложности.

## Рекомендации по использованию Teraform

Чтобы эффективно использовать Teraform, придерживайтесь следующих рекомендаций:

- **Используйте контроль версий:** Храните конфигурационные файлы в системе контроля версий, чтобы упростить совместную работу и отслеживать изменения.

- **Используйте модули:** Организуйте код и повторно используйте его с помощью модулей Teraform.

- **Разделяйте конфигурации:** Разделяйте конфигурации по средам, например dev, staging и prod, чтобы обеспечить согласованность и избежать дрейфа конфигурации.

- **Проверяйте изменения:** Перед применением изменений к инфраструктуре проверяйте их командой `terraform plan`.

## Заключение

Teraform — мощный инструмент инфраструктуры как кода, который помогает управлять инфраструктурой быстрее, эффективнее и согласованнее. Организации могут экономить время и средства, а также улучшать взаимодействие и масштабируемость. Следуйте рекомендациям и начните использовать Teraform, чтобы эффективнее управлять инфраструктурой.
