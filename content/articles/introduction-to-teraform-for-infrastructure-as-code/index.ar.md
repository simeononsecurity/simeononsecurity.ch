**مقدمة لاستخدام TeraForm في تطبيقات البنية التحتية كرمز**

مع انتقال مزيد من المؤسسات إلى السحابة، تزداد الحاجة إلى إدارة بنيتها التحتية بفعالية. هنا يأتي دور البنية التحتية كرمز (IaC)، وهي إدارة البنية التحتية وتوفيرها باستخدام الشيفرة بدلاً من الإجراءات اليدوية. يحقق ذلك مزيداً من الاتساق والسرعة والموثوقية. ويُعد Teraform من الأدوات الشائعة لهذا الغرض.

## ما هو Teraform؟

**Teraform** أداة مفتوحة المصدر للبنية التحتية كرمز. تتيح للمستخدمين كتابة البنية التحتية والتخطيط لها وإنشائها كشيفرة. طورتها HashiCorp، وتدعم إدارة البنية التحتية لدى موفري سحابة مختلفين، منهم AWS وAzure وGoogle Cloud Platform. باستخدام Teraform، تُعرّف البنية التحتية في ملفات إعدادات، ثم تطبق الشيفرة لإنشائها أو تحديثها، وتحذفها عند انتفاء الحاجة إليها.

## فوائد استخدام Teraform

يوفر استخدام Teraform لتطبيقات البنية التحتية كرمز فوائد متعددة، منها:

- **الكفاءة والسرعة:** يسرّع Teraform إدارة البنية التحتية ويحسن كفاءتها بإلغاء الإجراءات اليدوية.

- **الاتساق:** يضمن تعريف البنية التحتية بالشيفرة اتساق الإعدادات بين البيئات.

- **قابلية التوسع:** يسهّل Teraform توسيع البنية التحتية لتلبية الطلب المتزايد.

- **التعاون:** يمكن حفظ ملفات إعداد Teraform في نظام للتحكم بالإصدارات ومشاركتها مع أعضاء الفريق، ما يسهل التعاون.

- **خفض التكاليف:** يتيح Teraform توفير الموارد وإلغاء توفيرها بسهولة، ما قد يخفض التكاليف.

## البدء باستخدام Teraform

للبدء باستخدام Teraform:

1. **نزّل Teraform:** نزّل Teraform من [الموقع الرسمي](https://www.terraform.io/downloads.html).

2. **أنشئ ملف إعداد:** يستخدم Teraform ملفات إعداد مكتوبة بلغة HashiCorp Configuration Language (HCL) أو بصيغة JSON. يحدد الملف البنية التحتية التي تريد إنشاءها أو تحديثها أو حذفها.

لاستخدام Terraform، أنشئ ملف إعداد يصف البنية التحتية المطلوبة والموارد التي ينبغي إنشاؤها وخصائصها وتبعياتها.

يمكن كتابة ملفات الإعداد بلغة HashiCorp Configuration Language (HCL)، المصممة لتكون مقروءة للبشر وسهلة التعلم، أو بصيغة JSON. وتشبه صياغة HCL لغات البرمجة الأخرى، إذ تستخدم الكتل والسمات والقيم.

فيما يلي مثال أساسي لملف إعداد Terraform بلغة HCL ينشئ مثيل AWS EC2:

```HCL
provider "aws" {
  region = "us-west-2"
}

resource "aws_instance" "example" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t2.micro"
}
```
في هذا المثال، يحدد الملف موفر aws وينشئ مورداً من نوع aws_instance مع صورة جهاز Amazon (AMI) ونوع مثيل.

ولمثال أكثر تقدماً، راجع المثال التالي لاستخدام Terraform في إعداد أنظمة VMware:
```HCL
provider "vsphere" {
  user           = "user@domain.com"
  password       = "password"
  vsphere_server = "vcenter.example.com"
}

data "vsphere_datacenter" "dc" {
  name = "Datacenter"
}

data "vsphere_datastore" "ds" {
  name          = "Datastore"
  datacenter_id = data.vsphere_datacenter.dc.id
}

data "vsphere_network_interface" "nic" {
  label          = "Network adapter 1"
  datacenter_id  = data.vsphere_datacenter.dc.id
  network_id     = "VM Network"
}

resource "vsphere_virtual_machine" "vm" {
  name             = "terraform-vm"
  folder           = "/terraform"
  num_cpus         = 2
  memory           = 2048
  guest_id         = "otherLinux64Guest"
  scsi_type        = "pvscsi"
  datastore_id     = data.vsphere_datastore.ds.id

  network_interface {
    network_id = data.vsphere_network_interface.nic.network_id
  }

  disk {
    label            = "disk0"
    size             = 20
    eagerly_scrub    = true
    thin_provisioned = true
  }

  clone {
    template_uuid = "template-uuid"
  }
}

```
في هذا المثال، يحدد ملف الإعداد موفر vsphere وينشئ مورداً من نوع vsphere_virtual_machine مع اسم ومجلد وعدد وحدات المعالجة والذاكرة ونظام التشغيل الضيف ونوع SCSI وإعدادات القرص. كما يستنسخ الجهاز الافتراضي من قالب محدد.

ويستخدم ملف الإعداد أيضاً كتل البيانات للاستعلام عن معلومات مركز البيانات ومخزن البيانات وواجهة الشبكة التي سيستخدمها مورد الجهاز الافتراضي من بنية vSphere التحتية.

بعد إنشاء ملف الإعداد، يمكنك استخدامه لإنشاء موارد البنية التحتية أو تحديثها أو حذفها.

3. **هيّئ Teraform:** بعد إنشاء ملف الإعداد، شغّل الأمر `terraform init` لتهيئة Teraform. سينزّل الأمر الإضافات والوحدات اللازمة.

على سبيل المثال، إذا كان الملف `main.tf` داخل مجلد `terraform-example`، فنفّذ الأمر التالي من ذلك المجلد: ```terraform init```

سينزّل ذلك الإضافات والوحدات المحددة في ملف الإعداد.

4. **خطط للبنية التحتية وطبّق التغييرات:** بعد التهيئة، شغّل `terraform plan` لمعاينة التغييرات، ثم طبّقها باستخدام `terraform apply`.

يعرض الأمر `terraform plan` الموارد التي ستُنشأ أو تحدّث أو تحذف. مثلاً، إذا كان الملف `main.tf` داخل مجلد `terraform-example`، نفّذ الأمر التالي لمعاينة التغييرات:

```terraform plan```

يعرض الأمر معاينة للتغييرات التي ستطرأ على البنية التحتية.

بعد مراجعة الخطة، استخدم الأمر `terraform apply` لتطبيق التغييرات. إذا كان الملف `main.tf` داخل مجلد `terraform-example`، نفّذ الأمر التالي:

```terraform apply```

سيطبق ذلك التغييرات على البنية التحتية. وقد يستغرق التطبيق بعض الوقت بحسب حجم البنية التحتية وتعقيدها.

## أفضل الممارسات لاستخدام Teraform

للاستفادة من Teraform بفعالية، اتبع أفضل الممارسات التالية:

- **استخدم التحكم بالإصدارات:** خزّن ملفات إعداد Teraform في نظام للتحكم بالإصدارات لدعم التعاون وتتبع التغييرات.

- **استخدم الوحدات:** نظّم الشيفرة وأعد استخدامها عبر وحدات Teraform.

- **افصل الإعدادات:** خصص إعدادات لكل بيئة، مثل dev وstaging وprod، لضمان الاتساق وتجنب انحراف الإعدادات.

- **تحقق من التغييرات:** قبل تطبيق التغييرات على البنية التحتية، تحقق منها باستخدام الأمر `terraform plan`.

## الخلاصة

Teraform أداة قوية للبنية التحتية كرمز، تتيح إدارة أسرع وأكثر كفاءة واتساقاً. باستخدامها، تستطيع المؤسسات توفير الوقت والمال وتحسين التعاون وقابلية التوسع. اتبع أفضل الممارسات وابدأ باستخدام Teraform لإدارة بنيتك التحتية بفعالية أكبر.
