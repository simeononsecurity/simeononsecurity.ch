[العودة إلى الدورة العملية لسير عمل الذكاء الاصطناعي](/effective-ai-course-start/)

**تكرر حلقة الهدف العمل حتى تنجح نتيجة محددة في الفحص أو يُفعّل شرط للتوقف.** تقرأ الحلقة المفيدة الحالة الحالية، وتنفّذ إجراءً محدودًا، وتفحص النتيجة، وتسجل ما حدث. أما التوجيه المفتوح مثل «واصل المحاولة» فلا يحدد قاعدة موثوقة للإنجاز.

**هدف التعلم:** ستنفذ حلقة مختبر محدودة فيها فحص معروف الإخفاق، وستسجل قرار التوقف.

## أهم النقاط

- **الهدف:** نتيجة موصوفة بعبارات قابلة للملاحظة.
- **الحالة:** الملفات والمخرجات والأخطاء ومراجعة المصدر الحالية.
- **الفحص:** اختبار أو مراجعة مرتبطة بالهدف.
- **ميزانية المحاولات:** الحد الأقصى لمحاولات معالجة إخفاق واحد.
- **قاعدة التوقف:** شرط يفرض الإنهاء أو طلب قرار من شخص.

## قبل أن تبدأ

**المتطلبات السابقة:** [حزمة المهمة](/articles/effective-ai-task-packets/) و[سجل التحقق](/articles/effective-ai-output-verification/) و[درس التفويض](/articles/effective-ai-agent-delegation/). خصص 45 دقيقة. مستوى الصعوبة متوسط. استخدم نسخة جديدة من المختبر الاصطناعي حتى يكون معروفًا مسبقًا أن الفحص الأول سيفشل.

## اكتب عقد الحلقة

**لطلب التصفية حسب الحالة،** حدّد العقد قبل أي محاولة جديدة:

```text
الهدف: دعم --status open|done من دون تغيير المخرجات الافتراضية.
المصدر: docs/requirements.md، المراجعة 1.
الملفات المسموح بها: task_report.py والاختبارات المحددة.
الفحوص: اختبارات الوحدة، الأعداد 4/2/2، والقيمة غير الصالحة تنتهي برمز غير صفري.
ميزانية إعادة المحاولات: تعديلان كحد أقصى بعد المحاولة الأولى.
توقف فورًا: تعارض المصدر، أو تغيير غير متوقع في الملفات، أو انكشاف سر،
أو فشل أساسي لا يتعلق بهذا الطلب.
التسليم: أبلغ عن الفرق النهائي والأوامر والمخرجات والمحاولات والمشكلة غير المحسومة.
```

**هذه الميزانية سياسة للمهمة،** وليست قيمة افتراضية للمنتج. تكفي محاولتان إضافيتان لتشخيص مهمة مختبر صغيرة من دون إخفاء الإخفاقات المتكررة. أما مهمة الإنتاج فتحتاج إلى قرار خاص بها بشأن المخاطر والمراجعة.

## استخدم جدولًا للحالة

| الخطوة | الحالة التي ينبغي تسجيلها | القرار |
|---|---|---|
| **اقرأ** | مراجعة المصدر والنتيجة الأساسية | توقف إذا اختلفت الحالة الابتدائية |
| **نفّذ** | الملفات المتغيرة والإجراء المنفذ | ارفض التغييرات خارج النطاق |
| **افحص** | الاختبار المحدد والنتيجة اليدوية | اقبل أو شخّص |
| **أعد المحاولة** | سبب الإخفاق والفرضية الجديدة | تابع ضمن الميزانية فقط |
| **سلّم** | الحالة النهائية والمسؤول التالي | توقف بعد النجاح أو التعذر |

**سجّل المحاولات، لا الرسالة الأخيرة فقط.** لا يوضح اختبار نجح بعد ثلاثة تعديلات مخفية ما الذي تغير. احتفظ بسجل موجز للإخفاق والفرضية المعدلة والأدلة الجديدة.

## راجع إخفاقًا

**مثال للمحاولة الأولى:** يضيف الوكيل التصفية والاختبارات. يعرض `open` الرقم 2، لكن `--status invalid` يعرض 0 وينتهي بنجاح. يتطلب الشرط أن تعيد القيمة غير الصالحة رمز خروج غير صفري. سجّل الفحص بوصفه إخفاقًا.

**التشخيص:** افحص التحقق من الوسائط. تعامل الوكيل مع قيمة غير معروفة كما لو كانت نتيجة فارغة بدلًا من اعتبارها خطأ. اطلب تصحيحًا محدودًا يتحقق من القيم المقبولة قبل العد. أعد الحالة غير الصالحة وجميع الفحوص السابقة.

```text
المحاولة 1: أعادت الحالة غير الصالحة نجاحًا، لذا فشل القبول.
السبب المكتشف: لا يوجد تحقق من القيم المقبولة.
طلب المحاولة 2: ارفض القيم غير المدعومة واحتفظ بالأعداد 4/2/2.
الأدلة المطلوبة: تشغيل الاختبارات كاملة ورمز خروج الأمر غير الصالح.
```

**النتيجة المتوقعة في المحاولة الثانية:** رسالة خطأ واضحة ورمز خروج غير صفري للقيمة `invalid`، مع بقاء الأعداد الصحيحة كما هي. إذا فشلت المحاولة الثانية أيضًا، فاستخدم المحاولة الأخيرة بعد تحديد سبب جديد. تكرار الطلب نفسه ليس تشخيصًا.

## تعامل مع النتائج الملتبسة

**توقف عملية من دون نتيجة لا يعني النجاح.** إذا انتهت مهلة أداة بعد احتمال كتابة ملف، افحص الملفات وحالة Git قبل تشغيلها مرة أخرى. وإذا أبلغت خدمة متصلة عن نتيجة مجهولة، فاقرأ حالتها الحالية قبل تكرار إجراء خارجي. خارج المختبر، تشكل الإرسالات أو المنشورات أو الكتابات المكررة خطرًا حقيقيًا.

**توقف لطلب مراجعة بشرية** إذا تعارض الشرط مع مصدر آخر معتمد، أو منع إذنٌ الإجراء، أو نفدت ميزانية المحاولات، أو تجاوز الإجراء المطلوب حد النشر. يجب أن يذكر التسليم الحالة الدقيقة والقرار الذي لم يُحسم.

## افصل الحلقات عن المراقبات

**حلقة التحرير** تعمل ضمن مهمة محدودة وتفحص النتيجة بعد كل إجراء. أما **المراقب المجدول** فيستيقظ لاحقًا ليتحقق من شرط. يحتاج المراقب إلى وتيرة مستقلة وعتبة للتغيير وقاعدة للإشعار وشرط للتوقف. لا تحوّل حلقة التحرير في المختبر إلى مهمة متكررة. يقيّم الدرس التالي الأنظمة المستمرة قبل تفعيلها.

## نفّذ حلقة مضبوطة

**ابدأ بالمختبر من دون تغيير.** ينجح الاختباران الأساسيان. أنشئ `tests/test_loop_contract.py` في النسخة المستخرجة الجديدة باستخدام الفحص التالي. يحدد هذا الملف وظيفة مطلوبة غير موجودة في نقطة البداية. ولا يدخل ضمن أرشيف ZIP الأساسي الذي تتم صيانته.

```python
"""اختبار واحد مضبوط يفشل في تمرين تصفية الحالة."""

import subprocess
import sys
import unittest
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]


class LoopContractTests(unittest.TestCase):
    def test_open_status_count(self):
        result = subprocess.run(
            [sys.executable, str(ROOT / "task_report.py"),
             str(ROOT / "tasks.json"), "--status", "open"],
            capture_output=True, text=True, check=False,
        )
        self.assertEqual(result.returncode, 0, result.stderr)
        self.assertEqual(result.stdout.strip(), "Total tasks: 2")


if __name__ == "__main__":
    unittest.main()
```

**شغّل `python3 -m unittest discover -s tests -v`.** يفترض أن ينجح الاختباران الأصليان وأن يفشل اختبار العقد الجديد لأن نقطة البداية لا تدعم `--status`. سجّل الإخفاق الفعلي. إذا بدأت مستودع Git كما في الدرس 0، فسجّل أيضًا مخرجات `git status --short`. وإلا فقارن الملفات المتغيرة بنسخة مستخرجة من دون تعديلات. في Windows استخدم `py -3` إذا كان إعدادك يستخدم المشغّل.

**حدد ميزانية من ثلاث محاولات:** التعديل الأول وإصلاحان كحد أقصى. أعطِ وكيلك عقد الحلقة أعلاه واطلب تعديلًا محدودًا واحدًا. بعد كل محاولة، افحص الملفات المتغيرة، وأعد كل الاختبارات، ونفّذ الأوامر الافتراضية و`open` و`done` والقيمة غير الصالحة. سجّل سبب الإخفاق قبل محاولة جديدة. توقف عند النجاح أو عند إخفاق أساسي غير مرتبط بالطلب أو تغيير خارج النطاق أو فشل المحاولة الثالثة.

**مسار الدراسة:** بعد تسجيل الاختبار الأحمر، طبّق [الإجابة الكاملة للدرس 5](/articles/effective-ai-coding-agent-first-task/) في هذه النسخة الجديدة. أعد الفحوص نفسها وسجّل أن تعديل الوكيل لم يُنفذ. احتفظ باختبار العقد المضبوط. لا تضعفه أو تحذفه لجعله ينجح.

| المحاولة | الحالة والملاحظة | القرار |
|---|---|---|
| **قبل التعديل** | ينجح الاختباران الأساسيان، ويفشل فحص `open` الجديد | تابع بتعديل محدود واحد |
| **بعد كل تعديل** | سجّل الاختبارات المحددة والأعداد ورمز الخروج غير الصفري للقيمة غير الصالحة والملفات المتغيرة | اقبل أو شخّص أو توقف |
| **عند نفاد الميزانية** | سجّل الإخفاق المتبقي والفرق الحالي | سلّم المهمة من دون محاولة أخرى |

## تدرّب وتحقق

**المخرج المطلوب:** الاختبار المضبوط الذي يفشل، والمخرجات المرصودة قبله وبعده، وسجل المحاولات، وقرار نهائي بالقبول أو التوقف. إذا نجح التعديل الأول، فسجّل محاولة واحدة. لا تختلق إخفاقًا ثانيًا لملء السجل.

**فحص الإكمال:** يحدد العقد مصدرًا ونطاق الملفات وفحوصًا قابلة للملاحظة وحدًا للمحاولات وشرطًا واحدًا على الأقل للتوقف الفوري وتسليمًا للمهمة. يتضمن السجل الاختبار الأحمر الفعلي ونتائج الفحوص اللاحقة ونجاحًا أو توقفًا بسبب نفاد الميزانية. تحدد المحاولة الثانية سببًا جديدًا وتختلف عن الأولى.

## اختبر فهمك

1. **السؤال:** ماذا يثبت اختبار العقد الأحمر الأول؟ **الإجابة:** أن نقطة البداية تفتقر إلى مرشح الحالة المطلوب، كما يثبت اختبار كُتب قبل التعديل.
2. **السؤال:** متى يجب أن تتوقف الحلقة مع بقاء محاولات؟ **الإجابة:** عند تغيير خارج النطاق أو إذن غير واضح أو شرط متعارض.

## استكشاف الأخطاء وإصلاحها

- **تكرر الحلقة الإخفاق نفسه:** توقف وضع فرضية جديدة للسبب.
- **تضعف الفحوص:** أعد معايير القبول الأصلية.
- **نتيجة خارجية غير مؤكدة:** افحص الحالة الحالية قبل محاولة أخرى.
- **نفدت الميزانية:** سلّم سجل الإخفاق بدل إخفائه.
