**OpenRouter 提供商路由**会影响哪个推理服务处理你的请求。即使两次调用使用相同的模型名称，结果也取决于端点限制、支持的参数、服务软件和路由偏好。回答变短或工具调用失败时，应先检查这些差异，再归因于量化。

## 主要要点

- **精度标签**表示数值格式，不代表准确性评分。
- **端点限制**决定可用上下文、输出长度和功能支持。
- **显式路由**除了提供商偏好，还需要回退策略。
- **Auto Exacto**利用质量信号改善提供商选择，并为不含工具的请求提供可选路由。
- **实际成本**包括输出、缓存行为、重试和成功完成任务的成本。

**准备条件：**了解 JSON 请求，并能访问应用的 OpenRouter 配置。端点检查使用公开 API。发送模型请求需要 API 密钥，也会产生用量费用。重复使用带日期的示例前，请重新检查端点元数据。

**时间和难度：**初步配置检查约需 20 分钟。难度为中级。若要用有代表性的提示比较多个提供商，还需要额外测试。

## 模型名称没有说明什么

**模型标识符**选择请求的模型。提供商运行推理服务，包括模型实现、令牌限制和工具调用解析器。模型级基准测试无法验证每个承载这些权重的服务。

| 端点属性 | 检查内容 |
|---|---|
| **上下文长度** | 为提示、历史记录、工具结果和生成内容预留的空间 |
| **最大完成长度** | 当前任务可用的输出额度 |
| **支持的参数** | 工具使用、结构化输出、采样和推理控制 |
| **量化** | 报告的格式与原始发布格式是否一致 |
| **定价** | 输入、输出、缓存读取及适用的额外费用 |
| **服务行为** | 完成质量、解析错误、延迟和重试 |

**基线路由**会在健康候选项中优先选择价格较低的服务。OpenRouter 文档说明了反平方价格权重：在其简化示例中，价格为 1 美元的候选项获得的选择权重是 3 美元候选项的九倍。这描述的是相对权重，不保证下一次请求一定选择它。显式排序、缓存和质量路由也会影响选择。请参阅[提供商路由文档](https://openrouter.ai/docs/guides/routing/provider-selection)。

**价格权重**无法说明你的工作负载最终会产生最低账单。文档示例没有为价格标量定义通用的输入与输出比例。不要只根据输入价格推断提供商的选择概率。

## 结合上下文理解精度

**量化**使用精度较低的表示形式存储数值。其影响取决于模型、方法和推理实现。低精度值得测试，但仅凭标签不能证明提供商进一步降低了原始权重的精度。

**GPT-OSS 是一个具体示例。**OpenAI 的 [gpt-oss-120b 发布文档](https://huggingface.co/openai/gpt-oss-120b/raw/main/README.md)说明，其混合专家权重使用 MXFP4，评测也采用了相同量化。对这些权重标注四位精度与已发布的信息一致，不能据此证明提供商又降低了一次精度。

**升精度转换**会把已存储的数值转换为更宽的表示形式。把已经量化的检查点转换为 BF16，无法恢复量化时丢失的信息。反过来，把原本精度更高的检查点转为四位格式，则是另一项值得评估的变更。

| 观察结果 | 有依据的结论 |
|---|---|
| **原生 MXFP4 检查点** | 四位专家权重属于该模型发布版本 |
| **BF16 端点标签** | 报告了更宽的格式，但不证明回答更好 |
| **精度未知** | 元数据缺失，不证明存在隐性降级 |
| **精度标签相同** | 不足以证明服务行为等同 |

**标签相同也不能排除量化差异。**标签没有说明哪些张量经过量化、采用了哪些校准选择或执行内核。应测试完整端点，不要把位深当成质量排名。

## 检查令牌预算

```bash
curl --fail --silent --show-error \
  'https://openrouter.ai/api/v1/models/openai/gpt-oss-120b/endpoints' \
  | jq '.data.endpoints[] | {
      name,
      provider_name,
      context_length,
      max_completion_tokens,
      supported_parameters,
      quantization,
      pricing
    }'
```

**端点 API**提供某个模型的提供商级元数据。该命令需要 **`curl`** 和 **`jq`**。选择服务前，请检查[gpt-oss-120b 的实时端点响应](https://openrouter.ai/api/v1/models/openai/gpt-oss-120b/endpoints)。缺失或为 null 的字段应视为未知，而不是无限制。比较结果时，请保存带日期的本地快照。

**2026 年 10 月 5 日的检查**返回了 gpt-oss-120b 以下广告的限制值。这些是元数据，不是实测完成长度，而且提供商可能随时修改。

| 提供商 | 上下文令牌数 | 最大完成令牌数 |
|---|---:|---:|
| **DigitalOcean** | 128,000 | 4,096 |
| **Novita** | 131,072 | 32,768 |
| **Together** | 131,072 | 117,964 |

**上下文长度和输出长度是不同限制。**长上下文模型仍需要为回答留出足够空间。对话历史、系统指令和工具定义也会占用空间。

**推理令牌**也会占用支持推理的模型的生成预算。额度太小可能导致推理不完整、可见输出过少，或在最终回答前结束。应检查用量和结束原因，不要假设每个短回答都源于权重较弱。OpenRouter 在其[推理令牌文档](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)中说明了预算管理。

**显式设置 `max_tokens`**可以让路由器根据请求的输出长度匹配提供商支持情况。应根据实测任务需求和可用上下文选择数值。设得过高会缩小候选范围，也不能保证回答更长或质量更好。

## 要求参数必须受支持

```json
{
  "model": "openai/gpt-oss-120b",
  "messages": [
    {"role": "user", "content": "Explain the failure modes of a retry loop."}
  ],
  "max_tokens": 8192,
  "provider": {
    "require_parameters": true
  }
}
```

**`require_parameters`** 的默认值为 false。在默认路由下，不支持某参数的端点不一定会被排除。OpenRouter 文档说明提供商可能忽略未知参数。将此字段设为 true，会依据已声明的支持情况筛选路由。

**支持元数据不等于行为保证。**端点即使声明支持 seed，也仍需进行可复现性测试。支持工具的端点仍需通过架构验证和应用级测试。此筛选条件会阻止已知不兼容项进入候选范围。

## 有意识地固定提供商

```json
{
  "model": "openai/gpt-oss-120b",
  "messages": [
    {"role": "user", "content": "Summarize the supplied incident report."}
  ],
  "max_tokens": 8192,
  "provider": {
    "order": ["REPLACE_WITH_VERIFIED_PROVIDER_SLUG"],
    "allow_fallbacks": false,
    "require_parameters": true
  }
}
```

**将占位符替换为**从该模型的提供商列表中复制的服务标识。真实请求中还需提供报告。此模板用于审查配置，替换占位符之前不能直接运行。

**`order`**设置优先顺序，但单独使用时仍允许回退到其他提供商。与 **`allow_fallbacks: false`** 配合使用时，路由仅限于所列提供商。如果没有提供商满足请求或仍可用，请求会失败。

**端点变体需要留意。**按照文档中的匹配规则，基础提供商标识可能匹配多个变体。若要测试特定服务配置，请使用具体变体标识。还应检查每个响应所报告的提供商。

**`quantizations`** 是命名格式的允许列表，不是最低数值精度。数组中加入 **`"fp8"`** 会选择匹配的 FP8 端点，不会自动包括 BF16 或所有位数更高的格式。先比较原始检查点，只有在评测支持时才应用此筛选。

## 保持质量路由开启

```json
{
  "model": "openai/gpt-oss-120b:exacto",
  "messages": [
    {"role": "user", "content": "Compare the two supplied incident reports."}
  ],
  "max_tokens": 8192,
  "provider": {
    "require_parameters": true
  }
}
```

**Auto Exacto**利用吞吐量、工具调用遥测和基准测试，降低表现不佳提供商的优先级。OpenRouter 的[2026 年 3 月公告](https://openrouter.ai/blog/announcements/auto-exacto/)报告称，GLM-5 的工具调用错误下降了 88%，错误率从约 8% 降至接近 1%。公告还报告 gpt-oss-120b 的错误率从 5.6% 降至 3.5%。

**这些是供应商报告的推广结果**，不代表你的应用一定能取得同样效果。工具调用有效性衡量 JSON、名称和架构是否有效。语法正确的调用仍需检查参数和操作是否符合任务要求。

**包含工具的请求**在模型有足够提供商覆盖时默认使用 Auto Exacto。其他请求可通过 **`:exacto`** 选择质量路由。因此，当前文档支持将质量路由用于摘要和聊天，不只用于工具调用。

**`sort: "price"`**、**`:floor`** 后缀以及账户级默认价格排序都会退出 Auto Exacto。请同时检查应用设置和账户偏好。将路由控制组合使用前，先查看 [Auto Exacto 文档](https://openrouter.ai/docs/guides/routing/auto-exacto)。

## 计算工作负载成本

**只看输入价格**无法完成比较。以下是用美元表示的示例费率，单位为每百万令牌。它们用于说明计算方法，不是当前提供商报价。

| 示例端点 | 输入价格 | 输出价格 |
|---|---:|---:|
| **A** | $0.03 | $16.00 |
| **B** | $0.42 | $1.32 |

```text
工作负载：600 万输入令牌 + 100 万输出令牌

A = 6 × $0.03 + 1 × $16.00 = $16.18
B = 6 × $0.42 + 1 × $1.32  =  $3.84

每百万个输入与输出合计令牌：
A = $16.18 / 7 = $2.31
B =  $3.84 / 7 = $0.55
```

**在这种输入输出比例下，端点 A 的成本约为端点 B 的 4.2 倍**，尽管 A 的输入价格更低。A 的输出与输入费率之比为 533:1，这是两种费率的比值，不是用户总成本倍数。输入输出比例变化时，比较结果也会变化。

**API 定价单位与比较表不同。**端点 API 按每个令牌给出价格。与上面的费率比较前，应乘以一百万。

**提示缓存**会带来另一个变量。按照提供商的计费规则，缓存读取、缓存写入和未缓存输入需要分别计算。重复文本不保证命中缓存。请依据[提示缓存文档](https://openrouter.ai/docs/guides/best-practices/prompt-caching)检查报告的缓存令牌数和费用。

**路由会影响缓存连续性。**OpenRouter 文档介绍了用于缓存的粘性路由，但手动提供商顺序优先级更高。Auto Exacto 也会重新排列提供商，有时会打断热缓存。更改任一策略前，应将实测缓存节省与质量和重试成本一并比较。

**每个验收结果的成本**是更有用的应用指标：将包括重试和失败尝试在内的总支出，除以满足验收标准的结果数。适用的非令牌费用应单独计入。令牌价格低，无法弥补反复失败的任务。

## 诊断回答不一致

| 症状 | 首要检查项 |
|---|---|
| **回答短或未完成** | 结束原因、输出额度、推理用量 |
| **缺少文档细节** | 提交的内容、端点上下文限制、客户端截断 |
| **工具调用格式错误** | 声明的支持、工具架构、解析行为 |
| **采样行为不同** | 请求的参数和已声明的支持 |
| **费用异常** | 输出量、缓存读取、重试、提供商变更 |
| **没有符合条件的提供商** | 相互冲突的限制、允许列表和回退限制 |

**保存响应返回的生成 ID。**OpenRouter 的[生成元数据 API](https://openrouter.ai/docs/api/api-reference/generations/get-request-&-usage-metadata-for-a-generation)提供提供商身份、用量、成本和结束信息。会话 ID 可关联一组工作，但不能代替单个请求的生成 ID 查询。

**将请求与生成 ID 一起保存。**同时记录模型、提供商偏好、请求参数、时间戳和响应用量。路由、价格或端点元数据改变后，这些信息有助于复现质量或成本比较。

**在相同条件下比较端点。**使用相同提示、工具、推理设置和令牌预算。针对多个有代表性的任务重复测试。应分别统计回答不完整、工具调用无效和回答错误，不要把它们合并成一个无法解释的质量分数。

**基准测试存在不确定性。**Epoch AI 的[基准测试分析](https://epoch.ai/gradient-updates/why-benchmarking-is-hard)介绍了实现、采样和智能体框架带来的变化。一次令人失望的回答不能证明提供商存在持续缺陷，也无法确定原因。

## 下一步

1. **检查一个模型的端点**，记录与你的工作负载相关的限制。
2. **选择路由策略**，明确参数要求和回退行为。
3. **测试有代表性的任务**，比较候选端点和质量路由。
4. **记录验收结果成本**，并同时记录延迟、缓存用量和失败类别。
5. **在模型版本、服务行为或提供商价格变化后重新检查。**
