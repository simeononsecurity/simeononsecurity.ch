**プロジェクト外の最新情報や繰り返し使えるツールが必要なタスクでは、MCPサーバーを使います。** Model Context Protocol（MCP）は、クライアントとサーバーがツール、リソース、プロンプトの情報を交換する方法を定めます。サーバー設定が存在するだけでは、ツールが動く証拠になりません。このレッスンでは読み取り専用のドキュメント接続を検証します。

**学習目標：**設定と実際のMCP読み取りを区別し、安全な削除を記録します。

## 要点

- **MCPホスト：**ユーザー、モデル、権限、クライアントを調整するAIアプリケーション。
- **MCPクライアント：**1つのサーバーと通信するプロトコル要素。
- **MCPサーバー：**ツール、リソース、プロンプトを提供するプログラムまたはリモートサービス。
- **ツール検出：**名前付き機能がクライアントに表示される証拠。
- **ツール実行：**実際の呼び出しと返された内容の証拠。
- **権限範囲：**ホスト、サーバー、アカウント、ユーザーが許可するアクセス。

## 始める前に

**前提条件：**[コンテキストと引き継ぎの練習](/articles/effective-ai-context-window-management/)と、手順例に使う最新のCodex CLI。所要時間は35分、難易度は中級です。他のコーディングエージェントには個別の設定ガイドがあります。[OpenAI Docs MCP公式サーバー](https://learn.chatgpt.com/learn/docs-mcp)は読み取り専用の開発者向けドキュメントを提供し、コースデータのアップロードは不要です。

**コースの合成ラボを使います。**この演習ではカレンダー、メール、本番システムを接続しないでください。接続状態を学ぶには、ドキュメントの読み取りだけで十分です。

## 境界を理解する

| 状態 | 証明すること | 証明しないこと |
|---|---|---|
| **設定済み** | サーバー設定が存在する | 到達可能であること |
| **接続済み** | クライアントがサーバーに到達した | 有用なツールがあること |
| **検出済み** | 名前付きツールが表示される | 呼び出しが成功すること |
| **実行済み** | 呼び出しが内容を返した | 最終タスクが正しいこと |
| **検証済み** | ソースと出力が質問に答える | 今後の呼び出しも常に成功すること |

**MCP自体はアカウント権限を付与しません。**クライアントホスト、サーバー、認証、アカウント範囲、ローカル承認設定も関係します。[MCP仕様](https://modelcontextprotocol.io/specification/2026-07-28)がプロトコルを定め、各製品が操作方法を決めます。

**サーバーの出力は資料として扱います。**取得したページがタスクに優先したり、ファイル書き込みを許可したりすることはありません。各ツール定義はコンテキストも消費するため、この読み取りに必要なサーバーだけ接続し、演習後に削除してください。

## 読み取り専用サーバーを接続する

**Codex CLIで**ターミナルから次のコマンドを実行します。1つ目は公開ドキュメントサーバーを追加し、2つ目は設定済みサーバーを一覧表示します。

```bash
codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp
codex mcp list
```

**期待する設定証拠：**一覧に `openaiDeveloperDocs` が表示されます。これは登録だけを証明します。展開したラボフォルダーでCodexの新しいセッションを開始し、`/mcp` でMCPツールを確認してください。インストール済みバージョンに表示されたツール名を使います。

**実際の読み取りを依頼します：**

```text
OpenAI開発者ドキュメントMCPサーバーで、現在のAGENTS.mdガイダンスを探してください。
ソースページのタイトルとURL、このラボに関係する点を2つ返し、使用したMCPツール名を示してください。
ファイルは編集しないでください。
```
**結果を確認します。**返されたページは `AGENTS.md` をリポジトリのガイダンスとして説明し、正確なソースURLを示す必要があります。引用されたページを自分で開き、内容を確認してください。トランスクリプトにMCP呼び出しがない回答は通常の回答であり、ツール実行の証拠ではありません。

## 1つの障害を診断する

**`codex mcp list` にサーバーが表示されても `/mcp` にツールがない場合、**登録は成功し、検出に失敗しています。セッションを再起動し、`/mcp` で稼働中のサーバーを、`codex mcp get openaiDeveloperDocs` で保存済み設定を確認します。続いてサーバーURLとネットワーク接続を調べます。設定項目だけを根拠にMCP設定の成功を宣言しないでください。

**ツールが表示されても読み取りに失敗する場合、**エラーを記録し、接続を確認してから1回だけ再試行します。同じ呼び出しが失敗したら、引用された公式ページをブラウザーで開いて代替ソースとし、MCP演習は未完了と記録します。ツールの結果を作り上げないでください。

## 接続を削除する

**読み取り後、**Codex CLIから練習用サーバーを削除し、設定項目が消えたことを確認します。

```bash
codex mcp remove openaiDeveloperDocs
codex mcp list
```

**期待する削除証拠：**新しい一覧に `openaiDeveloperDocs` がありません。利用可能なツールが変わったか確認する前に、稼働中のCodexセッションを再起動します。ローカル定義の削除は、別のサービスが使う個別のアカウント認可を取り消しません。

## 別のクライアントを使う

**Claude CodeとOpenCodeもMCPに対応しています。**インストール済みリリースに合う[Claude Code MCPガイド](https://code.claude.com/docs/en/mcp)または[OpenCode MCPガイド](https://opencode.ai/docs/mcp-servers/)に従います。同じ5つの状態、設定済み、接続済み、検出済み、実行済み、検証済みを記録します。OpenCodeの設定スキーマとエージェント権限はバージョンごとに異なるため、対応するガイドの例を使ってください。

**ブラウザーだけを使う場合は、**[公式AGENTS.mdページ](https://learn.chatgpt.com/docs/agent-configuration/agents-md)を読み、同じ検証記録を作成します。ツールの検出と実行は「未実施」とします。この方法はソース確認を学べますが、MCPの動作は証明しません。

## 練習して確認する

**成果物：**サーバー名、ツール名、ソースURL、観察結果、削除証拠を記した5行の接続記録。スクリーンショットやログにトークンやアカウント識別子を含めないでください。

**完了条件：**接続経路は、ツールで実際に読み取り、その後に設定を削除して初めて合格です。代替経路は、MCPを未実施と記録したうえでソース確認を完了すれば合格です。

## 理解度を確認する

1. **質問：**MCPサーバーの保存済み設定は、ツールが動作した証拠ですか。**回答：**いいえ。検出、権限、実際の読み取りを確認してください。
2. **質問：**広範なMCP接続による追加のコンテキストコストは何ですか。**回答：**ツールの説明とスキーマが有効なコンテキストの一部を消費します。

## トラブルシューティング

- **`codex` コマンドが見つからない：**リンク先の公式ガイドからCodex CLIをインストールまたは更新します。
- **サーバーは一覧にあるがツールがない：**セッションの状態とサーバー診断を確認します。
- **ツールが無関係な内容を返した：**クエリを絞り、ソースページを確認します。
- **削除が反映されない：**新しいセッションを開始して、稼働中サーバーの一覧を確認します。
