[व्यावहारिक AI कार्यप्रवाह पाठ्यक्रम पर लौटें](/effective-ai-course-start/)

**जब किसी काम के लिए बार-बार इस्तेमाल होने वाला टूल या परियोजना से बाहर की नई जानकारी चाहिए, तब MCP सर्वर का उपयोग करें।** Model Context Protocol, या MCP, बताता है कि क्लाइंट और सर्वर टूल, संसाधन और प्रॉम्प्ट की जानकारी कैसे साझा करते हैं। सर्वर प्रविष्टि मौजूद होना टूल के काम करने का प्रमाण नहीं है। यह पाठ केवल-पठन दस्तावेज़ कनेक्शन की जाँच करता है।

**सीखने का लक्ष्य:** आप कॉन्फ़िगरेशन और वास्तविक MCP पठन के बीच अंतर करेंगे और सुरक्षित हटाने की प्रक्रिया दर्ज करेंगे।

## मुख्य बातें

- **MCP होस्ट:** AI अनुप्रयोग जो उपयोगकर्ताओं, मॉडल, अनुमतियों और क्लाइंट का समन्वय करता है।
- **MCP क्लाइंट:** प्रोटोकॉल घटक जो एक सर्वर से संचार करता है।
- **MCP सर्वर:** प्रोग्राम या दूरस्थ सेवा जो टूल, संसाधन या प्रॉम्प्ट देती है।
- **टूल खोज:** क्लाइंट में नामित क्षमता दिखने का प्रमाण।
- **टूल निष्पादन:** वास्तविक कॉल और लौटाई गई सामग्री का प्रमाण।
- **अनुमति का दायरा:** होस्ट, सर्वर, खाते और उपयोगकर्ता द्वारा दी गई पहुँच।

## शुरू करने से पहले

**आवश्यकताएँ:** [संदर्भ और कार्य सौंपने का अभ्यास](/articles/effective-ai-context-window-management/) और उदाहरण के लिए Codex CLI का वर्तमान संस्करण। 35 मिनट रखें। कठिनाई मध्यम है। अन्य कोडिंग एजेंटों की अलग सेटअप मार्गदर्शिकाएँ हैं। [आधिकारिक OpenAI Docs MCP सर्वर](https://learn.chatgpt.com/learn/docs-mcp) केवल-पठन डेवलपर दस्तावेज़ देता है और पाठ्यक्रम का डेटा अपलोड नहीं माँगता।

**पाठ्यक्रम की कृत्रिम लैब का उपयोग करें।** इस अभ्यास में कैलेंडर, ईमेल या उत्पादन प्रणाली न जोड़ें। कनेक्शन की अवस्थाएँ सीखने के लिए दस्तावेज़ पढ़ना पर्याप्त है।

## सीमा समझें

| अवस्था | यह क्या सिद्ध करती है | यह क्या सिद्ध नहीं करती |
|---|---|---|
| **कॉन्फ़िगर** | सर्वर प्रविष्टि मौजूद है | सर्वर तक पहुँच |
| **कनेक्ट** | क्लाइंट सर्वर तक पहुँचा | उपयोगी टूल उपलब्ध हैं |
| **खोजा गया** | नामित टूल दिखाई देता है | उसका कॉल सफल होगा |
| **चलाया गया** | कॉल ने सामग्री लौटाई | अंतिम कार्य सही है |
| **सत्यापित** | स्रोत और परिणाम सवाल का उत्तर देते हैं | भविष्य के कॉल हमेशा सफल होंगे |

**MCP अपने आप खाते की अनुमति नहीं देता।** क्लाइंट होस्ट, सर्वर, प्रमाणीकरण, खाता दायरा और स्थानीय स्वीकृति सेटिंग भी मायने रखते हैं। [MCP विनिर्देश](https://modelcontextprotocol.io/specification/2026-07-28) प्रोटोकॉल बताता है, जबकि हर उत्पाद अपना उपयोगकर्ता अनुभव नियंत्रित करता है।

**सर्वर के परिणाम को स्रोत सामग्री मानें।** प्राप्त पृष्ठ आपके काम की जगह नहीं लेता और फ़ाइल लिखने की अनुमति नहीं देता। हर टूल विवरण संदर्भ भी लेता है, इसलिए केवल इस पठन के लिए आवश्यक सर्वर जोड़ें और अभ्यास के बाद हटाएँ।

## केवल-पठन सर्वर जोड़ें

**Codex CLI में,** टर्मिनल पर ये कमांड चलाएँ। पहली सार्वजनिक दस्तावेज़ सेवा जोड़ती है। दूसरी कॉन्फ़िगर सर्वर दिखाती है।

```bash
codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp
codex mcp list
```

**अपेक्षित कॉन्फ़िगरेशन प्रमाण:** सूची में `openaiDeveloperDocs` हो। इससे केवल पंजीकरण सिद्ध होता है। निकाली गई लैब फ़ोल्डर में Codex का नया सत्र शुरू करें और `/mcp` से MCP टूल सूची देखें। स्थापित संस्करण में दिखे टूल नाम ही उपयोग करें।

**एक वास्तविक पठन माँगें:**

```text
OpenAI डेवलपर दस्तावेज़ MCP सर्वर से मौजूदा AGENTS.md मार्गदर्शन खोजें।
स्रोत पृष्ठ का शीर्षक और URL, इस लैब से जुड़े दो बिंदु तथा उपयोग किया गया MCP टूल बताएँ।
फ़ाइलें न बदलें।
```
**परिणाम जाँचें।** लौटे पृष्ठ में `AGENTS.md` को रिपॉज़िटरी मार्गदर्शन के रूप में समझाया जाना चाहिए और सटीक स्रोत URL होना चाहिए। उद्धृत पृष्ठ स्वयं खोलकर विषय की पुष्टि करें। प्रतिलेख में MCP कॉल के बिना उत्तर सामान्य उत्तर है, टूल चलने का प्रमाण नहीं।

## एक विफलता की जाँच करें

**यदि `codex mcp list` सर्वर दिखाए, लेकिन `/mcp` टूल न दिखाए,** तो पंजीकरण सफल और खोज विफल हुई। सत्र फिर शुरू करें, `/mcp` से सक्रिय सर्वर और `codex mcp get openaiDeveloperDocs` से सहेजी गई सेटिंग देखें, फिर सर्वर URL और नेटवर्क पहुँच जाँचें। केवल कॉन्फ़िगरेशन प्रविष्टि को MCP सफल होने का प्रमाण न मानें।

**यदि टूल दिखे, लेकिन पठन विफल हो,** त्रुटि दर्ज करें और कनेक्टिविटी जाँचकर एक बार फिर प्रयास करें। वही कॉल फिर विफल हो तो उद्धृत आधिकारिक पृष्ठ को ब्राउज़र में वैकल्पिक स्रोत के रूप में खोलें और MCP अभ्यास को अधूरा चिह्नित करें। टूल परिणाम न गढ़ें।

## कनेक्शन हटाएँ

**पठन के बाद,** Codex CLI से अभ्यास सर्वर हटाएँ और पुष्टि करें कि प्रविष्टि गायब है।

```bash
codex mcp remove openaiDeveloperDocs
codex mcp list
```

**अपेक्षित हटाने का प्रमाण:** नई सूची में `openaiDeveloperDocs` न हो। सक्रिय Codex सत्र के उपलब्ध टूल बदलने की जाँच से पहले उसे फिर शुरू करें। स्थानीय परिभाषा हटाने से किसी अन्य सेवा की अलग खाता अनुमति रद्द नहीं होती।

## दूसरा क्लाइंट इस्तेमाल करें

**Claude Code और OpenCode भी MCP का समर्थन करते हैं।** स्थापित संस्करण के लिए [Claude Code की MCP मार्गदर्शिका](https://code.claude.com/docs/en/mcp) या [OpenCode की MCP मार्गदर्शिका](https://opencode.ai/docs/mcp-servers/) अपनाएँ। वही पाँच अवस्थाएँ दर्ज करें: कॉन्फ़िगर, कनेक्ट, खोजा गया, चलाया गया और सत्यापित। OpenCode कॉन्फ़िगरेशन स्कीमा और एजेंट अनुमतियाँ संस्करण के अनुसार बदलती हैं, इसलिए अपनी स्थापना वाली मार्गदर्शिका के उदाहरण लें।

**केवल ब्राउज़र वाले विकल्प में,** [आधिकारिक AGENTS.md पृष्ठ](https://learn.chatgpt.com/docs/agent-configuration/agents-md) पढ़ें और वही सत्यापन रिकॉर्ड भरें। टूल खोज और निष्पादन को “नहीं चलाया” चिह्नित करें। यह विकल्प स्रोत जाँच सिखाता है, लेकिन MCP संचालन सिद्ध नहीं करता।

## अभ्यास और जाँच

**आपका परिणाम:** पाँच पंक्तियों का कनेक्शन रिकॉर्ड, जिसमें सर्वर नाम, टूल नाम, स्रोत URL, देखा गया परिणाम और हटाने का प्रमाण हो। स्क्रीनशॉट और लॉग में टोकन या खाता पहचान न रखें।

**पूरा होने की जाँच:** कनेक्टेड मार्ग तभी पास होता है जब वास्तविक टूल पठन और बाद में कॉन्फ़िगरेशन हटाना दोनों हों। वैकल्पिक मार्ग में MCP को नहीं चलाया चिह्नित करके स्रोत जाँच पूरी करें।

## अपनी समझ जाँचें

1. **प्रश्न:** क्या सहेजी गई MCP सर्वर प्रविष्टि सिद्ध करती है कि टूल चला? **उत्तर:** नहीं। खोज, अनुमति और वास्तविक पठन जाँचें।
2. **प्रश्न:** व्यापक MCP कनेक्शन से संदर्भ पर क्या अतिरिक्त लागत आती है? **उत्तर:** टूल विवरण और स्कीमा सक्रिय संदर्भ का कुछ भाग लेते हैं।

## समस्या निवारण

- **`codex` कमांड अज्ञात है:** लिंक की गई आधिकारिक मार्गदर्शिका से Codex CLI स्थापित या अपडेट करें।
- **सर्वर सूची में है, टूल नहीं:** सत्र स्थिति और सर्वर निदान देखें।
- **टूल ने असंबंधित सामग्री लौटाई:** क्वेरी सीमित करें और स्रोत पृष्ठ जाँचें।
- **हटाना असरदार नहीं दिखता:** नया सत्र शुरू करें और सक्रिय सर्वर सूची देखें।
