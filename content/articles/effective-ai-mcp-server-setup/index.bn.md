[ব্যবহারিক AI কর্মপ্রবাহ কোর্সে ফিরুন](/effective-ai-course-start/)

**কোনো কাজে পুনর্ব্যবহারযোগ্য টুল বা প্রকল্পের বাইরের হালনাগাদ তথ্য দরকার হলে MCP সার্ভার ব্যবহার করুন।** Model Context Protocol, বা MCP, ক্লায়েন্ট ও সার্ভারের মধ্যে টুল, রিসোর্স এবং প্রম্পটের তথ্য আদান-প্রদানের নিয়ম নির্ধারণ করে। সার্ভারের একটি কনফিগারেশন থাকলেই টুল কাজ করছে প্রমাণ হয় না। এই পাঠে শুধু-পঠনযোগ্য একটি ডকুমেন্টেশন সংযোগ পরীক্ষা করা হবে।

**শেখার লক্ষ্য:** কনফিগারেশন ও বাস্তব MCP পাঠের পার্থক্য বুঝবেন এবং নিরাপদে সরানোর ধাপ লিখে রাখবেন।

## মূল বিষয়

- **MCP হোস্ট:** AI অ্যাপ্লিকেশন, যা ব্যবহারকারী, মডেল, অনুমতি ও ক্লায়েন্টের সমন্বয় করে।
- **MCP ক্লায়েন্ট:** প্রোটোকলের অংশ, যা একটি সার্ভারের সঙ্গে যোগাযোগ করে।
- **MCP সার্ভার:** প্রোগ্রাম বা দূরবর্তী পরিষেবা, যা টুল, রিসোর্স বা প্রম্পট দেয়।
- **টুল আবিষ্কার:** ক্লায়েন্টে নামসহ কোনো সক্ষমতা দেখা যাওয়ার প্রমাণ।
- **টুল চালানো:** বাস্তব কল এবং ফেরত আসা বিষয়বস্তুর প্রমাণ।
- **অনুমতির পরিসর:** হোস্ট, সার্ভার, অ্যাকাউন্ট ও ব্যবহারকারীর দেওয়া প্রবেশাধিকার।

## শুরু করার আগে

**পূর্বশর্ত:** [প্রসঙ্গ ও কাজ হস্তান্তরের অনুশীলন](/articles/effective-ai-context-window-management/) এবং দেখানো ধাপের জন্য বর্তমান Codex CLI ইনস্টলেশন। ৩৫ মিনিট রাখুন। কঠিনতার মাত্রা মাঝারি। অন্য কোডিং এজেন্টগুলোর জন্য আলাদা সেটআপ নির্দেশিকা আছে। [OpenAI Docs MCP-এর সরকারি সার্ভার](https://learn.chatgpt.com/learn/docs-mcp) শুধু-পঠনযোগ্য ডেভেলপার ডকুমেন্টেশন দেয় এবং কোর্সের তথ্য আপলোড করতে হয় না।

**কোর্সের কৃত্রিম ল্যাব ব্যবহার করুন।** এই অনুশীলনে ক্যালেন্ডার, ইমেইল বা উৎপাদন ব্যবস্থা যুক্ত করবেন না। সংযোগের অবস্থা শেখার জন্য ডকুমেন্টেশন পড়াই যথেষ্ট।

## সীমা বুঝুন

| অবস্থা | কী প্রমাণ করে | কী প্রমাণ করে না |
|---|---|---|
| **কনফিগার করা** | সার্ভারের একটি এন্ট্রি আছে | সার্ভারে পৌঁছানো যায় |
| **সংযুক্ত** | ক্লায়েন্ট সার্ভারে পৌঁছেছে | কাজে লাগার মতো টুল আছে |
| **আবিষ্কৃত** | নামসহ টুল দেখা যায় | টুলের কল সফল হবে |
| **চালানো হয়েছে** | একটি কল বিষয়বস্তু ফিরিয়েছে | চূড়ান্ত কাজটি সঠিক |
| **যাচাই করা** | উৎস ও ফলাফল প্রশ্নের উত্তর দেয় | ভবিষ্যতের কল সব সময় কাজ করবে |

**MCP নিজে অ্যাকাউন্টের অনুমতি দেয় না।** ক্লায়েন্ট হোস্ট, সার্ভার, প্রমাণীকরণ, অ্যাকাউন্টের পরিসর এবং স্থানীয় অনুমোদন সেটিংও গুরুত্বপূর্ণ। [MCP স্পেসিফিকেশন](https://modelcontextprotocol.io/specification/2026-07-28) প্রোটোকল নির্ধারণ করে, আর প্রতিটি পণ্য নিজস্ব ব্যবহারপদ্ধতি নিয়ন্ত্রণ করে।

**সার্ভারের উত্তরকে উৎস উপাদান হিসেবে ধরুন।** উদ্ধার করা পৃষ্ঠা আপনার কাজের নির্দেশ বদলাতে বা ফাইল লেখার অনুমতি দিতে পারে না। প্রতিটি টুলের বিবরণ প্রসঙ্গও ব্যবহার করে, তাই এই পাঠের জন্য দরকারি সার্ভারটিই যুক্ত করুন এবং শেষে সরিয়ে ফেলুন।

## শুধু-পঠনযোগ্য সার্ভার যুক্ত করুন

**Codex CLI-তে** টার্মিনালে এই কমান্ডগুলো চালান। প্রথমটি উন্মুক্ত ডকুমেন্টেশন সার্ভার যোগ করে। দ্বিতীয়টি কনফিগার করা সার্ভার দেখায়।

```bash
codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp
codex mcp list
```

**প্রত্যাশিত কনফিগারেশন প্রমাণ:** তালিকায় `openaiDeveloperDocs` থাকবে। এতে শুধু নিবন্ধন প্রমাণিত হয়। আনজিপ করা ল্যাব ফোল্ডারে Codex-এর নতুন সেশন শুরু করুন এবং `/mcp` দিয়ে MCP টুলের তালিকা দেখুন। ইনস্টল করা সংস্করণে দেখানো নাম ব্যবহার করুন।

**একটি বাস্তব পাঠের অনুরোধ করুন:**

```text
OpenAI ডেভেলপার ডকুমেন্টেশন MCP সার্ভার ব্যবহার করে বর্তমান AGENTS.md নির্দেশনা খুঁজুন।
উৎস পৃষ্ঠার শিরোনাম, URL ও এই ল্যাবের জন্য প্রাসঙ্গিক দুটি বিষয় দিন; ব্যবহৃত MCP টুলের নাম বলুন।
কোনো ফাইল সম্পাদনা করবেন না।
```
**ফলাফল দেখুন।** ফেরত আসা পৃষ্ঠায় `AGENTS.md`-কে রিপোজিটরির নির্দেশনা হিসেবে বর্ণনা করা এবং সঠিক উৎস URL থাকা উচিত। উদ্ধৃত পৃষ্ঠাটি খুলে বিষয় যাচাই করুন। কথোপকথনের নথিতে MCP কল না থাকলে সেটি সাধারণ উত্তর, টুল চালানোর প্রমাণ নয়।

## একটি সমস্যা নির্ণয় করুন

**`codex mcp list` সার্ভার দেখালেও `/mcp` কোনো টুল না দেখালে,** নিবন্ধন সফল হয়েছে, কিন্তু আবিষ্কার ব্যর্থ হয়েছে। সেশন পুনরায় চালু করুন, `/mcp` দিয়ে সক্রিয় সার্ভার এবং `codex mcp get openaiDeveloperDocs` দিয়ে সংরক্ষিত কনফিগারেশন দেখুন। তারপর সার্ভার URL ও নেটওয়ার্ক সংযোগ পরীক্ষা করুন। শুধু কনফিগারেশন এন্ট্রি দেখে MCP সেটআপ সফল বলবেন না।

**টুল দেখা গেলেও পড়া ব্যর্থ হলে,** ত্রুটিটি লিখে রাখুন এবং সংযোগ যাচাই করে একবার আবার চেষ্টা করুন। একই কল আবার ব্যর্থ হলে ব্রাউজারে উদ্ধৃত সরকারি পৃষ্ঠা বিকল্প উৎস হিসেবে ব্যবহার করুন এবং MCP অনুশীলন অসম্পূর্ণ চিহ্নিত করুন। টুলের ফল বানিয়ে লিখবেন না।

## সংযোগ সরান

**পড়ার পরে** Codex CLI থেকে অনুশীলনের সার্ভার সরান এবং এন্ট্রিটি মুছে গেছে কি না নিশ্চিত করুন।

```bash
codex mcp remove openaiDeveloperDocs
codex mcp list
```

**প্রত্যাশিত অপসারণ প্রমাণ:** নতুন তালিকায় `openaiDeveloperDocs` থাকবে না। সক্রিয় Codex সেশনে উপলভ্য টুল বদলেছে কি না দেখার আগে সেশন পুনরায় চালু করুন। স্থানীয় সংজ্ঞা সরালেই অন্য পরিষেবার ব্যবহৃত পৃথক অ্যাকাউন্ট অনুমোদন বাতিল হয় না।

## অন্য ক্লায়েন্ট ব্যবহার করুন

**Claude Code ও OpenCode-ও MCP সমর্থন করে।** ইনস্টল করা সংস্করণের জন্য [Claude Code MCP নির্দেশিকা](https://code.claude.com/docs/en/mcp) অথবা [OpenCode MCP নির্দেশিকা](https://opencode.ai/docs/mcp-servers/) অনুসরণ করুন। একই পাঁচটি অবস্থা লিখুন: কনফিগার করা, সংযুক্ত, আবিষ্কৃত, চালানো এবং যাচাই করা। সংস্করণভেদে OpenCode কনফিগারেশন কাঠামো ও এজেন্টের অনুমতি বদলায়। আপনার ইনস্টলেশনের উপযোগী নির্দেশিকা থেকে উদাহরণ নিন।

**শুধু ব্রাউজার ব্যবহারের পথে,** [সরকারি AGENTS.md পৃষ্ঠা](https://learn.chatgpt.com/docs/agent-configuration/agents-md) পড়ুন এবং একই যাচাই রেকর্ড পূরণ করুন। টুল আবিষ্কার ও চালানোকে “চালানো হয়নি” লিখুন। এই পথ উৎস যাচাই শেখায়, কিন্তু MCP কাজ করছে প্রমাণ করে না।

## অনুশীলন ও যাচাই

**আপনার কাজের নমুনা:** পাঁচ সারির সংযোগ রেকর্ড, যাতে সার্ভারের নাম, টুলের নাম, উৎস URL, দেখা ফল এবং অপসারণের প্রমাণ থাকবে। স্ক্রিনশট বা লগে টোকেন ও অ্যাকাউন্ট পরিচয় রাখবেন না।

**সম্পন্ন করার শর্ত:** সংযুক্ত পথটি তখনই পাস, যখন টুল দিয়ে বাস্তবে পড়া হয়েছে এবং পরে কনফিগারেশন সরানো হয়েছে। বিকল্প পথটি উৎস যাচাই সম্পন্ন করলে পাস, তবে MCP-কে চালানো হয়নি হিসেবে চিহ্নিত করতে হবে।

## আপনার বোঝাপড়া যাচাই

1. **প্রশ্ন:** সংরক্ষিত MCP সার্ভার এন্ট্রি কি প্রমাণ করে যে টুল কাজ করেছে? **উত্তর:** না। আবিষ্কার, অনুমতি ও একটি বাস্তব পাঠ যাচাই করুন।
2. **প্রশ্ন:** বিস্তৃত MCP সংযোগে প্রসঙ্গের অতিরিক্ত খরচ কী? **উত্তর:** টুলের বিবরণ ও কাঠামো সক্রিয় প্রসঙ্গের কিছু অংশ ব্যবহার করে।

## সমস্যা সমাধান

- **`codex` কমান্ড অজানা:** সংযুক্ত সরকারি নির্দেশিকা থেকে Codex CLI ইনস্টল বা হালনাগাদ করুন।
- **সার্ভার তালিকায় আছে, টুল নেই:** সেশনের অবস্থা ও সার্ভার ডায়াগনস্টিক দেখুন।
- **টুল অপ্রাসঙ্গিক বিষয় ফিরিয়েছে:** প্রশ্ন সীমিত করুন এবং উৎস পৃষ্ঠা যাচাই করুন।
- **সরানো কার্যকর মনে হচ্ছে না:** নতুন সেশন শুরু করে সক্রিয় সার্ভারের তালিকা দেখুন।
