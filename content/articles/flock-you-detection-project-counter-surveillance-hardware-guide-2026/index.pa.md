**Flock-You ਖੋਜ ਡਿਵਾਈਸਾਂ ਬਣਾਉਣ ਅਤੇ ਵਰਤਣ ਲਈ ਪੂਰੀ ਤਕਨੀਕੀ ਗਾਈਡ**

## ਜਾਣ-ਪਛਾਣ: ਓਪਨ ਸੋਰਸ ਕਾਊਂਟਰ-ਸਰਵੇਲੈਂਸ

**Flock-You ਪ੍ਰੋਜੈਕਟ** Flock Safety ਦੀ ALPR ਸਰਵੇਲੈਂਸ ਬੁਨਿਆਦੀ ਢਾਂਚੇ ਨੂੰ ਖੋਜਣ ਅਤੇ ਮੈਪ ਕਰਨ ਲਈ ਇੱਕ **ਓਪਨ-ਸੋਰਸ, ਕਮਿਊਨਿਟੀ-ਚਾਲਿਤ ਪਹਿਲਕਦਮੀ** ਹੈ। GitHub 'ਤੇ **colonelpanichacks/flock-you** ਵਜੋਂ ਹੋਸਟ ਕੀਤਾ ਗਿਆ, ਇਹ ਪ੍ਰੋਜੈਕਟ Flock ਕੈਮਰਿਆਂ ਨੂੰ ਉਨ੍ਹਾਂ ਦੇ **WiFi ਨੈੱਟਵਰਕ ਸਿਗਨੇਚਰ** ਰਾਹੀਂ ਪਛਾਣਨ ਲਈ ਸਸਤੀ ESP32-ਆਧਾਰਿਤ ਹਾਰਡਵੇਅਰ ਵਰਤਦਾ ਹੈ।

ਇਹ ਵਿਆਪਕ ਗਾਈਡ Flock ਖੋਜ ਦੀ **ਤਕਨੀਕੀ ਵਿਧੀ** ਤੋਂ ਲੈ ਕੇ ਤਿੰਨ ਹਾਰਡਵੇਅਰ ਪਲੇਟਫਾਰਮਾਂ ਲਈ **ਕਦਮ-ਦਰ-ਕਦਮ ਸੈੱਟਅੱਪ ਨਿਰਦੇਸ਼**, **ਫਰਮਵੇਅਰ ਇੰਸਟਾਲੇਸ਼ਨ** ਅਤੇ **ਅਧਿਕਾਰਤ ਵਿਕ੍ਰੇਤਾਵਾਂ ਤੋਂ ਖਰੀਦ ਜਾਣਕਾਰੀ** ਤੱਕ ਸਭ ਕੁਝ ਕਵਰ ਕਰਦੀ ਹੈ। ਚਾਹੇ ਤੁਸੀਂ ਗੋਪਨੀਯਤਾ ਦੇ ਹਿਮਾਇਤੀ, ਸੁਰੱਖਿਆ ਖੋਜਕਰਤਾ ਜਾਂ ਚਿੰਤਤ ਨਾਗਰਿਕ ਹੋ, ਇਹ ਗਾਈਡ ਤੁਹਾਨੂੰ ਆਪਣੀ ਖੁਦ ਦੀ ਖੋਜ ਡਿਵਾਈਸ ਬਣਾਉਣ ਜਾਂ ਖਰੀਦਣ ਦੇ ਯੋਗ ਬਣਾਵੇਗੀ।

ਇਹ ਤਕਨੀਕ ਕਿਉਂ ਮਹੱਤਵਪੂਰਨ ਹੈ ਅਤੇ ਵਿਆਪਕ ਸਰਵੇਲੈਂਸ ਦ੍ਰਿਸ਼ ਬਾਰੇ ਸੰਦਰਭ ਲਈ, ਸਾਡਾ ਸਾਥੀ ਲੇਖ ਪੜ੍ਹੋ: **[Flock Safety ਕੈਮਰਾ ਸਰਵੇਲੈਂਸ: ਪ੍ਰਸਾਰ, ਗੋਪਨੀਯਤਾ ਚਿੰਤਾਵਾਂ ਅਤੇ ਸੁਰੱਖਿਆ ਰਣਨੀਤੀਆਂ](/articles/flock-safety-camera-surveillance-prevalence-privacy-protection-2026/)**।

ਦੇਖਣਾ ਚਾਹੁੰਦੇ ਹੋ ਕਿ Flock ਕੈਮਰੇ ਪਹਿਲਾਂ ਕਿੱਥੇ ਮੈਪ ਕੀਤੇ ਗਏ ਹਨ? **[Flock Finder](https://simeononsecurity.github.io/flock-finder/)** ਇੱਕ ਓਪਨ-ਸੋਰਸ ਟੂਲ ਹੈ ਜੋ WiGLE WiFi ਡੇਟਾ ਅਤੇ OUI ਫਿੰਗਰਪ੍ਰਿੰਟਿੰਗ ਵਰਤ ਕੇ ਦੁਨੀਆਭਰ ਵਿੱਚ 40,000+ ਸ਼ੱਕੀ Flock Safety ਕੈਮਰੇ ਪਲਾਟ ਕਰਦਾ ਹੈ, ਰੋਜ਼ਾਨਾ ਅੱਪਡੇਟ ਹੁੰਦਾ ਹੈ। ਸੋਰਸ **[GitHub](https://github.com/simeononsecurity/flock-finder)** 'ਤੇ।

## Flock-You ਖੋਜ ਵਿਧੀ ਨੂੰ ਸਮਝਣਾ

### ਤਕਨੀਕੀ ਬੁਨਿਆਦ

Flock Safety ਕੈਮਰਿਆਂ ਵਿੱਚ ਕਨੈਕਟੀਵਿਟੀ ਅਤੇ ਰਿਮੋਟ ਪ੍ਰਬੰਧਨ ਲਈ **ਏਮਬੈਡਡ WiFi ਮੋਡਿਊਲ** ਹੁੰਦੇ ਹਨ। ਇਹ ਮੋਡਿਊਲ ਪਛਾਣਯੋਗ ਨੈੱਟਵਰਕ ਸਿਗਨੇਚਰ ਪ੍ਰਸਾਰਿਤ ਕਰਦੇ ਹਨ ਜੋ **ਪ੍ਰੌਮਿਸਕਿਊਅਸ WiFi ਨਿਗਰਾਨੀ ਮੋਡ** ਵਿੱਚ ਚੱਲਦੀਆਂ ਡਿਵਾਈਸਾਂ ਦੁਆਰਾ ਖੋਜੇ ਜਾ ਸਕਦੇ ਹਨ। Flock-You ਪ੍ਰੋਜੈਕਟ ਇਸ ਵਿਸ਼ੇਸ਼ਤਾ ਦਾ ਹੇਠ ਲਿਖੇ ਤਰੀਕਿਆਂ ਨਾਲ ਫਾਇਦਾ ਉਠਾਉਂਦਾ ਹੈ:

#### 1. WiFi OUI (ਸੰਗਠਨਾਤਮਕ ਰੂਪ ਨਾਲ ਵਿਲੱਖਣ ਪਛਾਣਕਰਤਾ) ਖੋਜ

ਹਰ ਨੈੱਟਵਰਕ ਇੰਟਰਫੇਸ ਵਿੱਚ ਇੱਕ **MAC ਪਤਾ** ਹੁੰਦਾ ਹੈ ਜੋ ਇਹਨਾਂ ਨਾਲ ਬਣਿਆ ਹੁੰਦਾ ਹੈ:
- **ਪਹਿਲੇ 3 ਬਾਈਟ (24 ਬਿੱਟ)**: OUI, ਜੋ ਨਿਰਮਾਤਾ ਦੀ ਪਛਾਣ ਕਰਦਾ ਹੈ
- **ਆਖਰੀ 3 ਬਾਈਟ**: ਡਿਵਾਈਸ-ਵਿਸ਼ੇਸ਼ ਪਛਾਣਕਰਤਾ

ਜਦੋਂ ਕੋਈ ਖੋਜ ਡਿਵਾਈਸ ਪ੍ਰੌਮਿਸਕਿਊਅਸ ਮੋਡ ਵਿੱਚ WiFi ਟ੍ਰੈਫਿਕ ਸਕੈਨ ਕਰਦੀ ਹੈ, **ਇਹ ਇਹਨਾਂ OUIs ਨਾਲ ਫ੍ਰੇਮ ਪ੍ਰਸਾਰਿਤ ਕਰਨ ਵਾਲੀਆਂ ਕਿਸੇ ਵੀ ਡਿਵਾਈਸ ਦੀ ਪਛਾਣ ਕਰਦੀ ਹੈ**।

#### 2. ਵਾਈਲਡਕਾਰਡ ਪ੍ਰੋਬ ਬੇਨਤੀ ਖੋਜ

Flock ਕੈਮਰੇ ਸਮੇਂ-ਸਮੇਂ 'ਤੇ ਉਪਲਬਧ ਨੈੱਟਵਰਕਾਂ ਦੀ ਖੋਜ ਕਰਨ ਲਈ **ਵਾਈਲਡਕਾਰਡ ਪ੍ਰੋਬ ਬੇਨਤੀਆਂ** ਭੇਜਦੇ ਹਨ। ਇਹਨਾਂ ਦੀਆਂ ਵਿਲੱਖਣ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ ਹਨ:

- **802.11 ਪ੍ਰਬੰਧਨ ਫ੍ਰੇਮ**: Type=0, Subtype=4
- **SSID ਜਾਣਕਾਰੀ ਤੱਤ**: Length=0 (ਖਾਲੀ/ਵਾਈਲਡਕਾਰਡ)
- **ਫ੍ਰੇਮ ਬਣਤਰ**: ਪ੍ਰੋਬ ਟਾਈਮਿੰਗ ਵਿੱਚ ਅਨੁਮਾਨਯੋਗ ਪੈਟਰਨ
- **ਵਿਕ੍ਰੇਤਾ-ਵਿਸ਼ੇਸ਼ IEs**: ਫ੍ਰੇਮ ਪੇਲੋਡ ਵਿੱਚ ਵਾਧੂ ਸੂਚਕ

ਖੋਜ ਫਰਮਵੇਅਰ ਸਧਾਰਨ OUI ਮਿਲਾਨ ਤੋਂ ਪਰੇ Flock ਕੈਮਰਾ ਪਛਾਣ ਵਿੱਚ ਵਿਸ਼ਵਾਸ ਵਧਾਉਣ ਲਈ ਇਹਨਾਂ **ਪ੍ਰੋਬ ਬੇਨਤੀ ਪੈਟਰਨਾਂ** ਦਾ ਵਿਸ਼ਲੇਸ਼ਣ ਕਰਦਾ ਹੈ।

#### 3. ਪ੍ਰੌਮਿਸਕਿਊਅਸ ਮੋਡ WiFi ਨਿਗਰਾਨੀ

ਮਿਆਰੀ WiFi ਓਪਰੇਸ਼ਨ ਸਿਰਫ਼ ਤੁਹਾਡੀ ਡਿਵਾਈਸ ਨੂੰ ਸੰਬੋਧਿਤ ਫ੍ਰੇਮ ਪ੍ਰਾਪਤ ਕਰਦਾ ਹੈ। **ਪ੍ਰੌਮਿਸਕਿਊਅਸ ਮੋਡ** ਰੇਂਜ ਵਿੱਚ ਸਾਰੇ WiFi ਫ੍ਰੇਮ ਕੈਪਚਰ ਕਰਦਾ ਹੈ:

- **802.11 ਫ੍ਰੇਮ ਬਣਤਰ**: addr1, addr2, addr3 ਖੇਤਰਾਂ ਦਾ ਵਿਸ਼ਲੇਸ਼ਣ
- **ਪ੍ਰਬੰਧਨ ਫ੍ਰੇਮ**: ਪ੍ਰੋਬ ਬੇਨਤੀਆਂ, ਬੀਕਨ ਫ੍ਰੇਮ, ਐਸੋਸੀਏਸ਼ਨ ਬੇਨਤੀਆਂ
- **ਡੇਟਾ ਫ੍ਰੇਮ**: ਨੈੱਟਵਰਕ ਵਿਵਹਾਰ ਪੈਟਰਨ ਪ੍ਰਗਟ ਕਰਦੇ ਹਨ
- **ਕੰਟਰੋਲ ਫ੍ਰੇਮ**: ACKs, RTSs, CTSs ਟਾਈਮਿੰਗ ਜਾਣਕਾਰੀ ਪ੍ਰਦਾਨ ਕਰਦੇ ਹਨ

ESP32 ਮਾਈਕ੍ਰੋਕੰਟ੍ਰੋਲਰ **esp_wifi API** ਰਾਹੀਂ ਪ੍ਰੌਮਿਸਕਿਊਅਸ ਮੋਡ ਦਾ ਸਮਰਥਨ ਕਰਦੇ ਹਨ, ਘੱਟ-ਲਾਗਤ ਖੋਜ ਹਾਰਡਵੇਅਰ ਨੂੰ ਸਮਰੱਥ ਬਣਾਉਂਦੇ ਹਨ।

#### 4. ਸਿਗਨਲ ਤਾਕਤ ਵਿਸ਼ਲੇਸ਼ਣ

ਖੋਜ ਡਿਵਾਈਸਾਂ **RSSI (ਰਿਸੀਵਡ ਸਿਗਨਲ ਸਟ੍ਰੈਂਥ ਇੰਡੀਕੇਟਰ)** ਮਾਪਦੀਆਂ ਹਨ:
- ਖੋਜੇ ਕੈਮਰਿਆਂ ਤੱਕ **ਦੂਰੀ ਅਨੁਮਾਨ** ਕਰਨ ਲਈ
- ਕਈ ਮਾਪਾਂ ਨਾਲ **ਸਥਾਨ ਤ੍ਰਿਕੋਣਮਿਤੀ** ਕਰਨ ਲਈ
- ਅਨੁਮਾਨਿਤ ਸਿਗਨਲ ਵਿਸ਼ੇਸ਼ਤਾਵਾਂ ਦੇ ਆਧਾਰ 'ਤੇ **ਗਲਤ ਸਕਾਰਾਤਮਕ ਫਿਲਟਰ** ਕਰਨ ਲਈ
- ਕੈਮਰਾ ਘਣਤਾ ਦੇ **ਹੀਟ ਮੈਪ ਬਣਾਉਣ** ਲਈ

### ਖੋਜ ਸ਼ੁੱਧਤਾ ਅਤੇ ਗਲਤ ਸਕਾਰਾਤਮਕ

Flock-You ਵਿਧੀ ਉੱਚ ਸ਼ੁੱਧਤਾ ਪ੍ਰਾਪਤ ਕਰਦੀ ਹੈ:

- **ਸੱਚੀ ਸਕਾਰਾਤਮਕ ਦਰ**: ਰੇਂਜ ਵਿੱਚ ਪੁਸ਼ਟੀ ਕੀਤੇ Flock ਕੈਮਰਿਆਂ ਲਈ ~95%

## ਤਕਨੀਕੀ ਵਿਸਤ੍ਰਿਤ ਵਿਸ਼ਲੇਸ਼ਣ: ਕੋਡ ਸਮਝਣਾ

### ਮੁੱਖ ਖੋਜ ਐਲਗੋਰਿਦਮ (ਸਰਲੀਕ੍ਰਿਤ)

ਤਕਨੀਕੀ ਲਾਗੂਕਰਨ ਵਿੱਚ ਦਿਲਚਸਪੀ ਰੱਖਣ ਵਾਲਿਆਂ ਲਈ, ਇੱਥੇ ਖੋਜ ਤਰਕ ਦਾ ਇੱਕ ਸਰਲੀਕ੍ਰਿਤ ਦ੍ਰਿਸ਼ ਹੈ:

```cpp
// Flock-You Detection Core (Conceptual - not full code)

// OUI Database (31 known Flock-associated OUIs)
const uint8_t FLOCK_OUI_LIST[][3] = {
    {0xD4, 0xAD, 0xFC}, // Espressif ESP32-S3
    {0xAC, 0x67, 0xB2}, // Espressif ESP32-WROOM
    {0x84, 0xF3, 0xEB}, // Espressif ESP32-S3 variant
    // ... 28 more OUIs ...
};

// Promiscuous mode callback
void wifi_sniffer_callback(void* buf, wifi_promiscuous_pkt_type_t type) {
    wifi_promiscuous_pkt_t *pkt = (wifi_promiscuous_pkt_t*)buf;
    
    // Extract MAC address from frame
    uint8_t *mac = pkt->payload + 10; // addr2 field position
    
    // Check against OUI database
    for (int i = 0; i < NUM_OUIS; i++) {
        if (memcmp(mac, FLOCK_OUI_LIST[i], 3) == 0) {
            // OUI match found
            int rssi = pkt->rx_ctrl.rssi;
            
            // Check signal strength threshold
            if (rssi > RSSI_THRESHOLD) {
                // Analyze frame for additional signatures
                if (is_wildcard_probe_request(pkt)) {
                    // High confidence detection
                    trigger_alert(mac, rssi, HIGH_CONFIDENCE);
                } else {
                    // OUI match only
                    trigger_alert(mac, rssi, MEDIUM_CONFIDENCE);
                }
            }
        }
    }
}

// Wildcard probe detection
bool is_wildcard_probe_request(wifi_promiscuous_pkt_t *pkt) {
    // Management frame, subtype probe request
    if ((pkt->payload[0] & 0x0F) != 0x04) return false;
    
    // Check for empty SSID IE (wildcard)
    // Position depends on frame structure
    uint8_t *ie = &pkt->payload[24]; // Start of IEs
    if (ie[0] == 0x00 && ie[1] == 0x00) {
        return true; // Wildcard probe
    }
    return false;
}
```

### ਮੁੱਖ ਤਕਨੀਕੀ ਧਾਰਨਾਵਾਂ ਦੀ ਵਿਆਖਿਆ

**ਪ੍ਰੌਮਿਸਕਿਊਅਸ ਮੋਡ**: ਤੁਹਾਡੀ ਡਿਵਾਈਸ ਨੂੰ ਸੰਬੋਧਿਤ ਫ੍ਰੇਮ ਸਿਰਫ਼ ਪ੍ਰਾਪਤ ਕਰਨ ਦੀ ਬਜਾਏ, ESP32 ਰੇਂਜ ਵਿੱਚ ਸਾਰੇ WiFi ਫ੍ਰੇਮ ਕੈਪਚਰ ਕਰਦਾ ਹੈ। **ਇਹ ਉਹਨਾਂ ਨੇੜਲੀਆਂ ਡਿਵਾਈਸਾਂ ਨੂੰ ਖੋਜਣ ਲਈ ਜ਼ਰੂਰੀ ਹੈ ਜੋ ਤੁਹਾਡੇ ਡਿਟੈਕਟਰ ਨਾਲ ਸੰਚਾਰ ਨਹੀਂ ਕਰ ਰਹੀਆਂ।**

**MAC ਪਤਾ ਬਣਤਰ**: ਹਰ WiFi ਫ੍ਰੇਮ ਵਿੱਚ ਕਈ MAC ਪਤੇ ਹੁੰਦੇ ਹਨ:
- `addr1`: ਪ੍ਰਾਪਤਕਰਤਾ ਪਤਾ
- `addr2`: ਟ੍ਰਾਂਸਮੀਟਰ ਪਤਾ (OUI ਰੱਖਦਾ ਹੈ)
- `addr3`: ਅੰਤਿਮ ਮੰਜ਼ਿਲ/ਸਰੋਤ ਦਾ ਪਤਾ

**RSSI (ਰਿਸੀਵਡ ਸਿਗਨਲ ਸਟ੍ਰੈਂਥ ਇੰਡੀਕੇਟਰ)**: dBm ਵਿੱਚ ਸਿਗਨਲ ਤਾਕਤ (1 ਮਿਲੀਵਾਟ ਦੇ ਸੰਬੰਧ ਵਿੱਚ ਨਕਾਰਾਤਮਕ ਡੈਸੀਬਲ)। ਖਾਸ ਮੁੱਲ:
- -30 dBm: ਬਹੁਤ ਮਜ਼ਬੂਤ (ਬਹੁਤ ਨੇੜੇ)
- -50 dBm: ਮਜ਼ਬੂਤ ਸਿਗਨਲ
- -70 dBm: ਕਮਜ਼ੋਰ ਪਰ ਵਰਤੋਂ ਯੋਗ
- -90 dBm: ਬਹੁਤ ਕਮਜ਼ੋਰ (ਰੇਂਜ ਦਾ ਕਿਨਾਰਾ)

**ਪ੍ਰੋਬ ਬੇਨਤੀਆਂ**: WiFi ਡਿਵਾਈਸਾਂ ਉਪਲਬਧ ਨੈੱਟਵਰਕਾਂ ਨੂੰ ਖੋਜਣ ਲਈ ਪ੍ਰੋਬ ਬੇਨਤੀਆਂ ਭੇਜਦੀਆਂ ਹਨ। *ਵਾਈਲਡਕਾਰਡ ਪ੍ਰੋਬ (ਖਾਲੀ SSID) ਕਿਸੇ ਵੀ ਨੈੱਟਵਰਕ ਦੀ ਖੋਜ ਕਰਦੀਆਂ ਹਨ, ਜੋ Flock ਕੈਮਰਿਆਂ ਵਰਗੀਆਂ IoT ਡਿਵਾਈਸਾਂ ਵਿੱਚ ਆਮ ਹੈ, ਉਹਨਾਂ ਨੂੰ ਭਰੋਸੇਯੋਗ ਤਰੀਕੇ ਨਾਲ ਖੋਜਯੋਗ ਬਣਾਉਂਦੀਆਂ ਹਨ।*

## ਆਮ ਸਮੱਸਿਆਵਾਂ ਦਾ ਨਿਵਾਰਨ

### ਸਮੱਸਿਆ: ਜਾਣੇ ਨੇੜਲੇ ਕੈਮਰੇ ਦੇ ਬਾਵਜੂਦ ਕੋਈ ਖੋਜ ਨਹੀਂ

**ਸੰਭਾਵਿਤ ਕਾਰਨ**:
1. **ਕੈਮਰਾ ਔਫਲਾਈਨ/ਬੰਦ**: Flock ਕੈਮਰੇ ਕਈ ਵਾਰ ਅਸਥਾਈ ਤੌਰ 'ਤੇ ਅਕਿਰਿਆਸ਼ੀਲ ਹੁੰਦੇ ਹਨ
2. **ਸਿਗਨਲ ਬਲੌਕ**: ਇਮਾਰਤ ਸਮੱਗਰੀ WiFi ਸੋਖ ਲੈਂਦੀ ਹੈ (ਧਾਤੂ, ਕੰਕਰੀਟ)
3. **ਰੇਂਜ ਤੋਂ ਬਾਹਰ**: ਰੁਕਾਵਟਾਂ 'ਤੇ ਨਿਰਭਰ ਕਰਕੇ ਪ੍ਰਭਾਵਸ਼ਾਲੀ ਰੇਂਜ ~100-300 ਫੁੱਟ
4. **ਫਰਮਵੇਅਰ ਸਮੱਸਿਆ**: ਪੁਰਾਣਾ ਫਰਮਵੇਅਰ ਨਵੇਂ OUI ਭਿੰਨਤਾਵਾਂ ਖੁੰਝ ਜਾਂਦਾ ਹੈ

**ਹੱਲ**:
- ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਕੈਮਰਾ ਦਿਖਾਈ ਦਿੰਦਾ ਹੈ ਅਤੇ ਕਾਰਜਸ਼ੀਲ ਲੱਗਦਾ ਹੈ (ਸੋਲਰ ਪੈਨਲ, ਲਾਈਟਾਂ)
- ਸ਼ੱਕੀ ਕੈਮਰਾ ਸਥਾਨ ਦੇ ਨੇੜੇ ਜਾਓ
- ਵੱਖ-ਵੱਖ ਐਂਟੀਨਾ ਦਿਸ਼ਾਵਾਂ ਦੀ ਕੋਸ਼ਿਸ਼ ਕਰੋ
- ਨਵੀਨਤਮ Flock-You ਫਰਮਵੇਅਰ ਵਿੱਚ ਅੱਪਡੇਟ ਕਰੋ
- **ਜਾਂਚੋ ਕਿ ਡਿਵਾਈਸ ਸਰਗਰਮੀ ਨਾਲ ਸਕੈਨ ਕਰ ਰਹੀ ਹੈ** (LED/ਡਿਸਪਲੇ ਗਤੀਵਿਧੀ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ)

### ਸਮੱਸਿਆ: ਬਹੁਤ ਜ਼ਿਆਦਾ ਗਲਤ ਸਕਾਰਾਤਮਕ

**ਸੰਭਾਵਿਤ ਕਾਰਨ**:
1. **ESP32 ਡਿਵਾਈਸਾਂ ਦੀ ਉੱਚ ਘਣਤਾ**: ਸਮਾਰਟ ਹੋਮ, IoT ਡਿਵਾਈਸਾਂ ਆਮ ਹਨ
2. **ਸੰਵੇਦਨਸ਼ੀਲਤਾ ਬਹੁਤ ਜ਼ਿਆਦਾ**: ਦੂਰ/ਅਪ੍ਰਸੰਗਿਕ ਡਿਵਾਈਸਾਂ ਖੋਜ ਰਿਹਾ ਹੈ
3. **ਹੋਰ ਸਰਵੇਲੈਂਸ ਕੈਮਰੇ**: ਬਹੁਤ ਸਾਰੇ ESP32 ਮੋਡਿਊਲ ਵਰਤਦੇ ਹਨ

**ਹੱਲ**:
- ਸੰਵੇਦਨਸ਼ੀਲਤਾ ਸੈਟਿੰਗ ਘਟਾਓ
- ਵਾਈਲਡਕਾਰਡ ਪ੍ਰੋਬ ਖੋਜ ਚਾਲੂ ਕਰੋ (ਵੱਧ ਵਿਸ਼ਵਾਸ)
- ਲੌਗ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਖੋਜਾਂ ਦੀ ਭੌਤਿਕ ਪੁਸ਼ਟੀ ਕਰੋ
- ਫਿਲਟਰ ਕਰਨ ਲਈ ਸਿਗਨਲ ਤਾਕਤ ਵਰਤੋ (ਸਿਰਫ਼ ਮਜ਼ਬੂਤ ਸਿਗਨਲਾਂ 'ਤੇ ਅਲਰਟ)
- ਪੁਸ਼ਟੀ ਕੀਤੇ Flock OUIs 'ਤੇ ਧਿਆਨ ਕੇਂਦ੍ਰਿਤ ਕਰਨ ਲਈ OUI ਡੇਟਾਬੇਸ ਅੱਪਡੇਟ ਕਰੋ

### ਸਮੱਸਿਆ: ਬੈਟਰੀ ਤੇਜ਼ੀ ਨਾਲ ਖਤਮ ਹੁੰਦੀ ਹੈ

**ਸੰਭਾਵਿਤ ਕਾਰਨ**:
1. **ਨਿਰੰਤਰ ਸਕੈਨਿੰਗ**: ਕੋਈ ਸੁਸਤ/ਪਾਵਰ ਪ੍ਰਬੰਧਨ ਨਹੀਂ
2. **ਡਿਸਪਲੇ ਹਮੇਸ਼ਾ ਚਾਲੂ**: ਸਕਰੀਨ ਮਹੱਤਵਪੂਰਨ ਪਾਵਰ ਖਪਤ ਕਰਦੀ ਹੈ
3. **GPS ਸਰਗਰਮ**: GPS ਮੋਡਿਊਲ ਪਾਵਰ-ਭੁੱਖੇ ਹੁੰਦੇ ਹਨ
4. **ਪੁਰਾਣੀ ਬੈਟਰੀ**: Li-Po ਬੈਟਰੀਆਂ ਸਮੇਂ ਨਾਲ ਖਰਾਬ ਹੁੰਦੀਆਂ ਹਨ

**ਹੱਲ**:
- ਪੈਸਿਵ ਸਕੈਨ ਮੋਡ ਚਾਲੂ ਕਰੋ (ਰੁਕ-ਰੁਕ ਕੇ ਬਨਾਮ ਨਿਰੰਤਰ)
- ਡਿਸਪਲੇ ਟਾਈਮਆਊਟ ਸੈੱਟ ਕਰੋ
- ਮੈਪਿੰਗ ਦੀ ਲੋੜ ਨਾ ਹੋਣ 'ਤੇ GPS ਅਯੋਗ ਕਰੋ
- ਬੈਟਰੀ ਬਦਲੋ (OUI-SPY/mesh-detect v2 ਵਿੱਚ ਬਦਲੀਯੋਗ ਬੈਟਰੀਆਂ ਹਨ)
- ਲੰਬੇ ਸੈਸ਼ਨਾਂ ਲਈ ਬਾਹਰੀ ਬੈਟਰੀ ਪੈਕ ਵਰਤੋ

### ਸਮੱਸਿਆ: GPS ਲਾਕ ਪ੍ਰਾਪਤ ਨਹੀਂ ਕਰ ਰਿਹਾ

**ਸੰਭਾਵਿਤ ਕਾਰਨ**:
1. **ਅੰਦਰੂਨੀ ਵਰਤੋਂ**: GPS ਨੂੰ ਅਕਾਸ਼ ਦੀ ਦਿੱਖ ਦੀ ਲੋੜ ਹੈ
2. **ਐਂਟੀਨਾ ਜੁੜਿਆ ਨਹੀਂ**: mesh-detect v2 ਨੂੰ ਬਾਹਰੀ ਐਂਟੀਨਾ ਜੁੜਿਆ ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ
3. **ਕੋਲਡ ਸਟਾਰਟ**: ਪਹਿਲੇ GPS ਲਾਕ ਨੂੰ 5-15 ਮਿੰਟ ਲੱਗਦੇ ਹਨ
4. **ਦਖਲਅੰਦਾਜ਼ੀ**: ਨੇੜਲੇ ਇਲੈਕਟ੍ਰੌਨਿਕਸ ਸਿਗਨਲ ਵਿੱਚ ਦਖਲ ਦਿੰਦੇ ਹਨ

**ਹੱਲ**:
- ਸਾਫ਼ ਅਕਾਸ਼ ਦ੍ਰਿਸ਼ਟੀ ਵਾਲੀ ਸਥਿਤੀ 'ਤੇ ਜਾਓ
- ਯਕੀਨੀ ਕਰੋ ਕਿ ਐਂਟੀਨਾ ਸਹੀ ਤਰੀਕੇ ਨਾਲ ਜੁੜਿਆ ਹੈ (SMA ਕਨੈਕਟਰ)
- ਸ਼ੁਰੂਆਤੀ ਲਾਕ ਦੀ ਉਡੀਕ ਕਰੋ (ਬਾਅਦ ਦੇ ਲਾਕ ਤੇਜ਼ੀ ਨਾਲ)
- RF ਦਖਲ ਸਰੋਤਾਂ ਤੋਂ ਦੂਰ ਜਾਓ
- ਜਾਂਚੋ ਕਿ ਸੈਟਿੰਗਾਂ ਵਿੱਚ GPS ਚਾਲੂ ਹੈ

### ਸਮੱਸਿਆ: SD ਕਾਰਡ 'ਤੇ ਡੇਟਾ ਲੌਗ ਨਹੀਂ ਹੋ ਰਿਹਾ

**ਸੰਭਾਵਿਤ ਕਾਰਨ**:
1. **SD ਕਾਰਡ ਫਾਰਮੈਟ ਨਹੀਂ ਕੀਤਾ**: FAT32 ਫਾਰਮੈਟ ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ
2. **SD ਕਾਰਡ ਭਰਿਆ ਹੋਇਆ**: ਕੋਈ ਥਾਂ ਬਾਕੀ ਨਹੀਂ
3. **ਕਾਰਡ ਖੋਜਿਆ ਨਹੀਂ**: ਪੂਰੀ ਤਰ੍ਹਾਂ ਪਾਇਆ ਨਹੀਂ ਗਿਆ
4. **ਫਾਈਲ ਸਿਸਟਮ ਖਰਾਬੀ**: ਕਾਰਡ ਖਰਾਬ ਹੋਇਆ

**ਹੱਲ**:
- **SD ਕਾਰਡ ਨੂੰ FAT32 ਵਜੋਂ ਫਾਰਮੈਟ ਕਰੋ** (ਅਨੁਕੂਲਤਾ ਲਈ ਵੱਧ ਤੋਂ ਵੱਧ 32GB)
- ਪੁਰਾਣੇ ਲੌਗ ਮਿਟਾਓ ਜਾਂ ਵੱਡਾ ਕਾਰਡ ਵਰਤੋ
- ਕਾਰਡ ਪੂਰੀ ਤਰ੍ਹਾਂ ਦੁਬਾਰਾ ਪਾਓ (ਕਲਿੱਕ ਹੋਣਾ ਚਾਹੀਦਾ ਹੈ)
- ਕਾਰਡ ਦੁਬਾਰਾ ਫਾਰਮੈਟ ਕਰੋ ਜਾਂ ਖਰਾਬ ਹੋਣ 'ਤੇ ਬਦਲੋ
- ਜਾਂਚੋ ਕਿ ਡਿਵਾਈਸ ਕਾਰਡ ਪਛਾਣਦੀ ਹੈ (ਮੈਨੂ SD ਸਥਿਤੀ ਦਿਖਾਵੇਗਾ)
