**私たちの Hindsight メモリサービスは、管理下のハードウェアで動作します。** メモリエンジン、データベース、埋め込みモデル、リランカーを 1 つのセルフホスト環境で実行します。Hindsight は生成リクエストをプライベートゲートウェイへ送ります。確認した共有 Qwen バックエンドとテスト済みのページ更新経路は、ホスト型推論の契約を使わず、ローカルモデルサーバーを利用します。

これは稼働中の 1 つの環境についての説明です。**セルフホストはオフラインを意味しません。** VPN は外部の調整サービスを使い、ソフトウェアイメージとモデルウェイトのダウンロードも必要です。ここでの主張はメモリ処理とモデル推論に限られ、端末や他のエージェントツールが行うすべてのネットワーク接続を対象にしません。

## 要点

- **Hindsight がメモリ処理を担います。** Docker コンテナが API、ワーカー、制御プレーンを提供し、永続ボリュームがバンクデータを保存します。
- **小規模な検索モデルはローカルで動きます。** 埋め込みとリランキングは Hindsight プロセス内で CPU 実行します。
- **Qwen がテキストを生成します。** Retain、Reflect、Consolidation は推論を無効にし、出力を制限したプライベート Qwen3.5-4B エイリアスを呼び出します。確認したバックエンドはローカルで提供します。
- **時間のかかるページ更新には GPU を割り当てます。** 別のモデルエイリアスがバックグラウンドリクエストに GPU カードを 1 枚借り、完了後に解放します。
- **ゲートウェイは物理的な配置を隠します。** Hindsight がモデルエイリアスを選び、プライベートルーティングサービスが配信先を選びます。

## モデルを選ぶ前に境界を決める

**Hindsight はメモリエンジンであり、モデルサーバーではありません。** 完全な Docker イメージにはローカルの埋め込みモデルとリランキングモデルが含まれますが、言語生成にはエンドポイントが必要です。[Hindsight のインストールガイド](https://hindsight.vectorize.io/developer/installation)はこの分離を説明し、ホスト型プロバイダーの代替としてローカルの llama.cpp、Ollama、vLLM サーバーを紹介しています。

**メモリ API はプライベートネットワーク内に置きます。** Web 制御プレーンはローカルインターフェースで動作します。永続ボリュームが組み込みデータベースを保持するため、コンテナを再作成してもバンクは消えません。認証が API を保護し、バンクを分けてプロジェクトのコンテキストを整理します。

**生成ゲートウェイは安定したモデル名を提供します。** Hindsight は VPN 経由でプライベートゲートウェイに OpenAI 互換リクエストを送ります。ゲートウェイはローカル配信先へ転送します。確認した Qwen 経路は、ローカル CPU サーバーに割り当てた LiteLLM 環境へ到達します。[LiteLLM ルーターのドキュメント](https://docs.litellm.ai/docs/routing)はこのエイリアス方式を説明しています。別の OpenAI 互換ルーターでも同じ役割を担えます。

**内部 API も存在します。** Hindsight は OpenAI 互換形式でプライベートゲートウェイを呼び出します。確認したモデル経路はローカルで推論します。ゲートウェイのすべてのフォールバック規則を監査したわけではありません。各リクエストがローカル処理される保証として扱う前に、ゲートウェイのポリシーを確認してください。

## メモリ処理ごとに適切なコンピュートを割り当てる

Hindsight の各処理は異なる役割を持ちます。**Retain** は新しい資料から事実を抽出します。**Recall** は関連する記憶を検索します。**Reflect** は検索し、要約した回答を作成します。**Consolidation** は関連する事実をまとめます。**ナレッジページ更新**はバンクから最新の要約を再構築します。

| 処理 | モデルの配置 | 理由 |
| --- | --- | --- |
| **Retain** | プライベートゲートウェイ経由の Qwen3.5-4B | 出力予算を抑えたローカル構造化抽出 |
| **Recall** | CPU 上のローカル埋め込みとリランキング | 検索に生成 API の呼び出しは不要 |
| **Reflect** | プライベートゲートウェイ経由の Qwen3.5-4B | メモリ検索後の回答合成に生成が必要 |
| **Consolidation** | プライベートゲートウェイ経由の Qwen3.5-4B | 小さなバッチで長い構造化出力を抑える |
| **ナレッジページ更新** | 専用のローカル GPU Qwen 経路 | 大規模なバックグラウンド合成が CPU 経路の時間上限を超過 |

*小規模な検索処理は CPU で実行し、計測した長時間処理に GPU 推論を割り当てます。*

Hindsight コンテナは埋め込みに **BAAI/bge-small-en-v1.5**、リランキングに **hindsight-ai/hs-rerank-1** を読み込みます。起動ログから、どちらも CPU 上でローカル実行されることを確認しました。[Hindsight のモデルリファレンス](https://hindsight.vectorize.io/developer/models)はローカルモデルと任意の判断モデル経路を説明しています。

埋め込み空間を変えるには保存済みベクトルを再構築する必要があるため、既存の埋め込みモデルを維持しました。リランカーはすでにローカルです。ホスト型リランキングを追加しても、新たなデータ境界ができるだけで、観測した生成タイムアウトは解決しません。ローカルの **hs-decide-1-flash** 試験では正しい Reflect 回答が 1 件得られましたが、試験の時間上限に近いタイミングで完了しました。合成 Consolidation データでは判断経路を検証していません。そのため、判断モデルは本番ルーティングに含めていません。

## 時間のかかるバックグラウンド処理に GPU を割り当てる

**通常のモデル名と更新用モデル名は異なります。** Retain、Reflect、Consolidation は共有 Qwen エイリアスを使います。バックグラウンドのページ更新はノード専用 GPU エイリアスを使い、同時に実行する言語モデル呼び出しを 1 件に制限します。長時間の保守処理が一度に使う GPU は 1 枚です。

**リクエスト単位の予約で GPU 使用を制限します。** リクエストが来ると GPU プールがモデルワーカーを起動します。コントローラーが GPU を 1 枚予約し、リクエストを処理し、ワーカーを停止して予約を解放します。図には物理ホストの一覧を示していません。

この分離は計測した失敗から生まれました。**CPU を優先したページ更新が 1 時間の上限に達しました。** バックグラウンド更新をローカル GPU プールへルーティングした後、以前失敗した 5 ページが、ある復旧実行で約 2～6 分で完了しました。この数値はそのページと設定についてのものです。一般的な Qwen のスループットベンチマークではありません。

## デフォルト値とタイムアウトを修正する

**以前の Hindsight 出力上限はローカルルーターに合いませんでした。** ルーターは最大 8,192 出力トークンを受け入れ、リクエストに上限がない場合は 256 トークンを適用します。以前の Retain 上限 64,000 トークンでは HTTP 400 が発生しました。8 件の事実を含む Consolidation バッチは出力長で停止し、Reflect にはルーターの 256 トークンへのフォールバックを避ける明示的な上限が必要でした。

**各処理の上限を明示しました。** これらのメモリ処理では Qwen の推論を無効にしています。Hindsight は合計 4 件の LLM 呼び出しを同時に許可し、バックグラウンドページ更新は最大 1 件です。グローバル LLM タイムアウトは 1,800 秒で、モデルの再試行は 1 回です。

| ワークロード | 出力またはバッチ上限 | 呼び出しと処理の上限 |
| --- | --- | --- |
| **Retain** | 8,192 出力トークン | 呼び出し全体のタイムアウト 1,800 秒 |
| **Reflect** | 4,096 出力トークン | 呼び出しごとに 900 秒、処理全体で 3,600 秒 |
| **Consolidation** | 4,096 出力トークン、呼び出しごとに 4 件 | 呼び出しごとに 900 秒、処理全体で 14,400 秒 |
| **ページ更新** | 同時モデル呼び出し 1 件 | 呼び出しごとに 900 秒、専用 GPU 経路 |

*これらの値は 2026 年 11 月時点の環境とローカルルーターを示します。*

**呼び出しタイムアウトと処理全体の上限は異なる段階を制御します。** 有効な Qwen 呼び出しでも、以前の 300 秒の呼び出しタイムアウトを超えることがありました。長い処理上限は複数回の呼び出しを可能にしつつ、各試行は 900 秒で制限します。

復旧実行では、複数の Retain 処理が **1,042～2,076 出力トークン**で完了しました。2 回の Consolidation 実行は **41 件中 41 件**と**30 件中 30 件**を処理しました。その後、ページ更新の時間上限に達したことから、前述の専用 GPU 経路を導入しました。これらの結果は長期的な信頼性を証明するものではありません。

## この設計で引き受けること

**ホスト型モデルの請求がなくても、コストはゼロではありません。** 自前のハードウェア、電力、ストレージ、保守時間、ページ更新中の GPU 時間を使います。配置の選択ごとに、処理能力と遅延または運用の簡便さを交換します。

| 選択 | 利点 | 代償 |
| --- | --- | --- |
| **CPU 優先の生成** | GPU の空きを保つ | テストしたページ更新が 1 時間の上限に到達 |
| **GPU ページ更新** | 1 回の実行で 5 ページが約 2～6 分で完了 | GPU を消費し、専用経路に依存 |
| **組み込みデータベース** | 環境を小さく保つ | 障害範囲が狭まり、バックアップのテストが必要 |

*計測した CPU の遅延が保守時間枠を超えたら、GPU 更新経路を使います。*

大規模な本番環境では PostgreSQL を分離するよう、[Hindsight のインストールガイド](https://hindsight.vectorize.io/developer/installation)が推奨しています。バンクが拡大する前に、**組み込みデータベースのバックアップと復旧経路をテストしてください。**

**プライベート推論は経路全体の特性です。** 使用する Hindsight プロバイダー、ゲートウェイのモデル割り当て、フォールバック規則、ローカルモデルプロセス、ログ保持、外向き通信を確認します。Hindsight のトレース ID はリクエストの照合に役立ち、Docker はコンテナログをローテーションします。どちらも後続のリクエストがローカルに留まった証拠にはなりません。ゲートウェイ監査でエンドツーエンドの証拠を補います。

## 推奨事項

**ローカル検索モデルと明示的な生成上限から始めます。** Hindsight と埋め込み、リランキングモデルを自前のコンピュートに配置します。VPN 経由でプライベートな OpenAI 互換ゲートウェイへ生成リクエストを送ります。CPU または GPU を割り当てる前に各処理を計測し、CPU の遅延が保守時間枠を超えるバックグラウンド処理に GPU 経路を使います。

*環境をプライベートかつ耐障害性があると見なす前に、ゲートウェイの全フォールバックを確認し、バンクの復旧をテストしてください。* [ローカル AI のプライバシー境界ガイド](/articles/local-ai-privacy-boundary/)は初期チェックリストを提供します。

## 結論

**この環境では、Hindsight のメモリと確認済みの推論経路を自前のコンピュートで維持し、ホスト型モデルの契約を使いません。** CPU による検索、上限を設けた Qwen 呼び出し、1 回ずつ処理する GPU 更新経路は、それぞれ異なる負荷を扱います。これらの設定で Retain、Consolidation、ページ更新を完了しました。次の確認事項は、ゲートウェイの全フォールバック監査、バックアップテスト、より長期間の信頼性観測です。
