**Наша служба памяти Hindsight работает на оборудовании под нашим контролем.** Механизм памяти, база данных, модель эмбеддингов и переранжировщик работают в одном развертывании на собственном хостинге. Hindsight отправляет запросы на генерацию через частный шлюз. Проверенный общий бэкенд Qwen и протестированный маршрут обновления страниц используют локальные серверы моделей без подписки на облачный инференс.

Здесь описано одно работающее развертывание. **Самостоятельный хостинг не означает работу без сети.** VPN использует внешнюю службу координации, а образы программ и веса моделей нужно загружать. Это утверждение относится к обработке памяти и инференсу моделей, но не ко всем сетевым подключениям наших устройств или других инструментов агентов.

## Главное

- **Hindsight управляет рабочим процессом памяти.** Контейнер Docker предоставляет API, рабочие процессы и плоскость управления, а данные банков хранятся в постоянном томе.
- **Небольшие модели поиска работают локально.** Эмбеддинги и переранжирование выполняются в процессе Hindsight на CPU.
- **Qwen генерирует текст.** Операции Retain, Reflect и Consolidation обращаются к частному псевдониму Qwen3.5-4B с выключенным рассуждением и ограниченным объемом вывода. Проверенный бэкенд обслуживает запросы локально.
- **Долгие обновления страниц получают GPU.** Отдельный псевдоним модели арендует одну видеокарту для фонового запроса, а затем освобождает ее.
- **Шлюз скрывает физическое размещение.** Hindsight выбирает псевдоним модели. Частные службы маршрутизации выбирают конечную точку обслуживания.

## Определите границы до выбора моделей

**Hindsight — это механизм памяти, а не сервер моделей.** Полный образ Docker содержит локальные модели эмбеддингов и переранжирования, но для генерации языковой моделью нужна конечная точка. [Руководство по установке Hindsight](https://hindsight.vectorize.io/developer/installation) описывает это разделение и приводит локальные серверы llama.cpp, Ollama и vLLM как альтернативы облачным поставщикам.

**API памяти остается в частной сети.** Веб-плоскость управления привязана к локальному интерфейсу. Постоянный том хранит встроенную базу данных, поэтому пересоздание контейнера не удаляет банки. API защищает аутентификация, а отдельные банки разделяют контекст проектов.

**Шлюз генерации предоставляет стабильные имена моделей.** Hindsight отправляет совместимые с OpenAI запросы через частный шлюз по VPN. Шлюз перенаправляет запросы на локальные конечные точки. Проверенный маршрут Qwen ведет к развертыванию LiteLLM, связанному с локальным сервером на CPU. [Документация маршрутизатора LiteLLM](https://docs.litellm.ai/docs/routing) описывает такой шаблон с псевдонимами моделей. Аналогичный совместимый с OpenAI маршрутизатор выполняет ту же роль.

**Внутренний API все же существует.** Hindsight вызывает частный шлюз в формате, совместимом с OpenAI. Проверенные маршруты моделей выполняют инференс локально. Мы не проверяли все правила переключения шлюза, поэтому сначала изучите политику шлюза, а затем считайте локальную обработку гарантией для каждого запроса.

## Назначьте каждой задаче памяти подходящие ресурсы

Операции Hindsight выполняют разные задачи. **Retain** извлекает факты из новых материалов. **Recall** находит подходящие воспоминания. **Reflect** ищет данные и формирует синтезированный ответ. **Consolidation** объединяет связанные факты. Фоновый **knowledge-page refresh** заново создает актуальную сводку банка.

| Операция | Размещение модели | Причина |
| --- | --- | --- |
| **Retain** | Qwen3.5-4B через частный шлюз | Локальное структурированное извлечение с ограниченным бюджетом вывода |
| **Recall** | Локальные эмбеддинги и переранжирование на CPU | Для поиска не нужен вызов API генерации |
| **Reflect** | Qwen3.5-4B через частный шлюз | Для синтеза нужна генерация после поиска воспоминаний |
| **Consolidation** | Qwen3.5-4B через частный шлюз | Небольшие пакеты ограничивают длину структурированных ответов |
| **Knowledge-page refresh** | Отдельный локальный маршрут Qwen на GPU | Большой фоновый синтез превысил лимит времени маршрута CPU |

*Оставляйте небольшие задачи поиска на CPU, а инференс на GPU выделяйте для измеренных долгих задач.*

Контейнер Hindsight загружает **BAAI/bge-small-en-v1.5** для эмбеддингов и **hindsight-ai/hs-rerank-1** для переранжирования. Журналы запуска подтверждают, что обе модели работают локально на CPU. [Справочник моделей Hindsight](https://hindsight.vectorize.io/developer/models) описывает локальные варианты и необязательный маршрут модели принятия решений.

Мы сохранили имеющуюся модель эмбеддингов, так как смена пространства эмбеддингов требует повторного создания сохраненных векторов. Переранжировщик уже работает локально, поэтому облачная служба переранжирования создала бы новую границу обработки данных, не устранив наблюдавшийся тайм-аут генерации. Локальный пилот **hs-decide-1-flash** дал один правильный ответ Reflect, но результат появился почти у предела времени теста. Синтетические данные консолидации не проверяли маршрут принятия решений. Поэтому эта модель не входит в производственную маршрутизацию.

## Выделите GPU для долгих фоновых задач

**Обычное имя модели отличается от имени для обновления страниц.** Retain, Reflect и Consolidation используют общий псевдоним Qwen. Для фонового обновления страниц применяется псевдоним GPU, привязанный к узлу и допускающий один одновременный вызов языковой модели. Так длительная задача обслуживания использует не более одного GPU за раз.

**Резервирование на время запроса ограничивает использование GPU.** Пул GPU запускает рабочий процесс модели после поступления запроса. Контроллер резервирует одну карту, обслуживает запрос, останавливает процесс и снимает резервирование. На схеме не показан перечень физических узлов.

Это разделение появилось после измеренного сбоя. **Одно обновление страницы с приоритетом CPU достигло часового предела.** После перенаправления фоновых обновлений в локальный пул GPU пять ранее неудачных страниц завершились примерно за две-шесть минут в одном цикле восстановления. Эти цифры относятся к тем страницам и настройкам. Это не общий тест пропускной способности Qwen.

## Исправьте значения по умолчанию и тайм-ауты

**Прежние ограничения вывода Hindsight не подходили нашему локальному маршрутизатору.** Маршрутизатор принимает не более 8 192 выходных токенов и ограничивает вывод 256 токенами, если запрос не задает лимит. Прежний лимит Retain в 64 000 токенов вызывал HTTP 400. Пакеты Consolidation по восемь фактов завершались из-за ограничения длины вывода, а для Reflect требовался явный лимит, чтобы избежать подстановки маршрутизатором 256 токенов.

**Мы явно задали лимиты для каждой задачи.** Рассуждение Qwen отключено для этих операций с памятью. Теперь Hindsight разрешает в общей сложности четыре одновременных вызова LLM, включая не более одного фонового вызова обновления страниц. Глобальный тайм-аут LLM составляет 1 800 секунд, предусмотрен один повтор модели.

| Нагрузка | Лимит вывода или пакета | Лимиты вызовов и операций |
| --- | --- | --- |
| **Retain** | 8 192 выходных токена | Глобальный тайм-аут вызова 1 800 секунд |
| **Reflect** | 4 096 выходных токенов | 900 секунд на вызов, 3 600 секунд на операцию |
| **Consolidation** | 4 096 выходных токенов, четыре факта на вызов | 900 секунд на вызов, 14 400 секунд на операцию |
| **Page refresh** | Один одновременный вызов модели | 900 секунд на вызов, отдельный маршрут GPU |

*Эти значения описывают наше развертывание и локальный маршрутизатор в ноябре 2026 года.*

**Тайм-аут отдельного вызова и лимит всей операции ограничивают разные этапы.** Некоторые корректные вызовы Qwen превышали прежний тайм-аут в 300 секунд. Более длительные лимиты операций допускают работу с несколькими вызовами, а ограничение в 900 секунд на вызов по-прежнему ограничивает каждую попытку.

В цикле восстановления несколько задач Retain завершились с **1 042–2 076 выходными токенами**. Два цикла Consolidation завершили **41 из 41** и **30 из 30** элементов. Более позднее превышение времени обновления страницы привело к отдельному маршруту GPU, описанному выше. Эти результаты восстановления не доказывают долгосрочную надежность.

## На какие компромиссы идет эта схема?

**Отсутствие счета за облачные модели не означает нулевых затрат.** Развертывание использует собственное оборудование, электроэнергию, хранилище, время на обслуживание и время GPU при обновлении страниц. Каждый выбор размещения обменивает пропускную способность на задержку или простоту эксплуатации.

| Выбор | Преимущество | Компромисс |
| --- | --- | --- |
| **Генерация с приоритетом CPU** | Сохраняет доступность GPU | Проверенное обновление страницы достигло часового лимита |
| **Обновление страниц на GPU** | Пять страниц завершились примерно за две-шесть минут в одном цикле | Использует ресурсы GPU и зависит от выделенного маршрута |
| **Встроенная база данных** | Делает развертывание компактным | Сужает домен отказа и требует проверки резервного копирования |

*Используйте маршрут обновления на GPU, если измеренная задержка CPU превышает отведенное окно обслуживания.*

[Руководство по установке Hindsight](https://hindsight.vectorize.io/developer/installation) рекомендует отдельный PostgreSQL для крупных производственных развертываний. **Для нашей встроенной базы данных нужна проверенная процедура резервного копирования и восстановления** по мере роста банка.

**Приватный инференс зависит от пути запроса.** Проверьте выбранного поставщика Hindsight, соответствие моделей в шлюзе, правила переключения, локальный процесс модели, срок хранения журналов и исходящий сетевой трафик. Идентификаторы трассировки Hindsight помогают сопоставлять запросы, а Docker ротирует журналы контейнера. Ни то ни другое не доказывает, что последующий запрос оставался локальным. Аудит шлюза дает недостающие сквозные свидетельства.

## Рекомендация

**Начните с локальных моделей поиска и явных лимитов генерации.** Размещайте Hindsight, модели эмбеддингов и переранжирования на собственном оборудовании. Направляйте генерацию через частный шлюз, совместимый с OpenAI, по VPN. Измерьте каждую операцию перед назначением ресурсов CPU или GPU и оставьте маршрут GPU для фоновых задач, задержка которых на CPU превышает ваше окно обслуживания.

*Проверьте каждое правило переключения шлюза и испытайте восстановление банков, прежде чем считать развертывание приватным и отказоустойчивым.* [Руководство по границе приватности локального ИИ](/articles/local-ai-privacy-boundary/) содержит начальный контрольный список.

## Заключение

**В этом развертывании память Hindsight и проверенные пути инференса остаются на собственном оборудовании без подписки на облачный инференс.** Локальный поиск на CPU, ограниченные вызовы Qwen и маршрут обновления страниц на GPU с одним вызовом обслуживают разные нагрузки. В циклах восстановления при этих настройках завершились задачи Retain, Consolidation и обновления страниц. Следующие проверки: полный аудит правил переключения шлюза, тест резервной копии и более длительное наблюдение за надежностью.
