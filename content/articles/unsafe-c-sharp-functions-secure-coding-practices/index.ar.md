## **دوال C# غير الآمنة** **وبدائلها الآمنة**

**C#** لغة برمجة قوية واسعة الاستخدام، وتشتهر بمرونتها ومتانتها. لكن كل لغة برمجة تتضمن دوال قد تسبب ثغرات عند استخدامها دون عناية. نستعرض هنا **دوال C# غير الآمنة** التي قد تعرض التطبيقات للخطر، إلى جانب **بدائلها الآمنة**. يساعد فهم هذه المخاطر وطرق تجنبها المطورين على كتابة شيفرة أكثر أمانًا وموثوقية.

## مقدمة

تُستخدم **C#** لإنشاء أنواع متعددة من البرامج، بدءًا من تطبيقات سطح المكتب ووصولًا إلى حلول الويب. توفر اللغة وظائف وإمكانات عديدة، لكن بعضها قد يؤدي دون قصد إلى ثغرات أمنية. تتناول الأقسام التالية هذه الدوال والمخاطر المرتبطة بها وطرق تجنبها.

### مخاطر دوال C# غير الآمنة

تشكّل بعض دوال C# **مصائد** تتيح للمهاجمين استغلال ثغرات مثل **تجاوز سعة المخزن المؤقت** **وهجمات الحقن** **وتسرب البيانات**. ينبغي للمطورين إدراك هذه المخاطر واختيار بدائل أكثر أمانًا لتفادي الهجمات المحتملة.

## معالجة السلاسل النصية

### **غير آمن: استخدام `string.Format()`**

قد يؤدي استخدام `string.Format()` إلى **ثغرات في تنسيق السلاسل النصية**. ففي ظروف معينة، قد يُدخل المهاجم محددات تنسيق ضارة تؤدي إلى كشف بيانات دون تصريح، وقد تتيح في الحالات الخطيرة تنفيذ التعليمات البرمجية عن بُعد.

```c#
// مثال على استخدام string.Format()
string name = "John";
int age = 30;
string formattedString = string.Format("اسمي {0} وعمري {1} عامًا.", name, age);
Console.WriteLine(formattedString);
```

### **البديل الآمن: استيفاء السلاسل النصية**

يُعد **استيفاء السلاسل النصية** نهجًا أكثر حذرًا للحد من مخاطر التنسيق. فهو يحسن وضوح الشيفرة وينسق النصوص بطريقة مضبوطة، ما يقلل احتمال هذه المشكلات.

```c#
// مثال على استخدام استيفاء السلاسل النصية
string name = "John";
int age = 30;
string interpolatedString = $"اسمي {name} وعمري {age} عامًا.";
Console.WriteLine(interpolatedString);
```

## التحقق من المدخلات

### **غير آمن: التحقق غير الكافي من المدخلات**

يؤدي التقليل من أهمية التحقق الدقيق من مدخلات المستخدم إلى تعريض التطبيقات لثغرات متعددة، منها **حقن SQL** وهجمات **البرمجة النصية عبر المواقع (XSS)** الشائعة.

```c#
string userInput = Request.QueryString["input"];
string sqlQuery = "SELECT * FROM Users WHERE Name='" + userInput + "'";
```

### **البديل الآمن: استخدام استعلامات ذات معاملات**

من الطرق الفعالة للحد من هذه المخاطر استخدام **استعلامات ذات معاملات**. وفي عمليات قواعد البيانات، تمنع هذه التقنية التعامل مع البيانات الضارة على أنها تعليمات قابلة للتنفيذ.

```c#
string userInput = Request.QueryString["input"];
string sqlQuery = "SELECT * FROM Users WHERE Name=@userName";
SqlCommand command = new SqlCommand(sqlQuery, connection);
command.Parameters.AddWithValue("@userName", userInput);
```

## إدارة الذاكرة

### **غير آمن: استخدام `Array.Copy()` دون التحقق من الحدود**

استخدام `Array.Copy()` دون التحقق بعناية من الحدود ينطوي على مخاطر، وقد يؤدي إلى **تجاوز سعة المخزن المؤقت** ومشكلات أخرى في الذاكرة.

```C#
int[] sourceArray = { 1, 2, 3, 4, 5 };
int[] destinationArray = new int[3];
Array.Copy(sourceArray, destinationArray, 5); // احتمال تجاوز سعة المخزن المؤقت
```

### **البديل الآمن: استخدام `Array.CopyTo()`**

يمكن للمطورين استخدام `Array.CopyTo()` لنسخ البيانات بطريقة أكثر ضبطًا. ويساعد هذا الخيار في تقليل خطر تجاوز سعة المخزن المؤقت.

```c#
int[] sourceArray = { 1, 2, 3, 4, 5 };
int[] destinationArray = new int[3];
sourceArray.CopyTo(destinationArray, 0);
```

## معالجة الملفات

### **غير آمن: استخدام `File.Delete()`**

قد تحذف `File.Delete()` الملفات دون ضوابط مناسبة للتحكم في الوصول. وقد يؤدي الاستخدام غير الحذر إلى حذف ملفات مهمة عن طريق الخطأ ومشكلات أمنية أخرى.

```C#
string filePath = "path/to/file.txt";
File.Delete(filePath); // يحذف الملف دون أذونات مناسبة
```

### **البديل الآمن: استخدام **`SecureString`** لمسارات الملفات**

للحد من خطر حذف الملفات دون تصريح، يقترح المثال استخدام **SecureString** لمسارات الملفات مع تطبيق ضوابط مناسبة للتحكم في الوصول. وقد يساعد ذلك التطبيق على إدارة الوصول إلى الملفات بصورة أفضل.

```C#
using System.Security;
// ...
SecureString secureFilePath = new SecureString();
foreach (char c in "path/to/file.txt")
{
    secureFilePath.AppendChar(c);
}
// Implement proper file access control using secureFilePath
```

## **الخلاصة: احمِ الشيفرة لمستقبل أكثر أمانًا**

في تطوير البرمجيات، هناك مبدأ أساسي: **إعطاء الأولوية للأمن**. تعتمد سلامة البرامج على قرارات عديدة، منها تجنب **دوال C# غير الآمنة** واعتماد **بدائلها الآمنة**. ومن خلال معرفة المخاطر وتطبيق التدابير المناسبة، يستطيع المطورون إنشاء برامج أكثر مقاومة للهجمات والحد من الثغرات بفاعلية.

تطوير البرامج الآمنة عملية مستمرة. تابع الممارسات الموصى بها والثغرات المحتملة لاتخاذ قرارات مدروسة. يمنح كل سطر من الشيفرة فرصة لتعزيز متانة البيئة الرقمية.

يتطلب الوصول إلى برامج آمنة انتباهًا مستمرًا. وتظل معرفة الممارسات الجيدة والثغرات المحتملة مهمة للنجاح.
