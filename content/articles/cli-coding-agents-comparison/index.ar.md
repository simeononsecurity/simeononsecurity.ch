تشترك **وكلاء البرمجة الطرفية** في واجهة مألوفة، لكنها تختلف في جمع السياق وتحرير الملفات وطلب الموافقة والاندماج مع النصوص البرمجية. يقارن هذا الدليل Claude Code CLI وCodex CLI وGemini CLI وOpenCode CLI وGitHub Copilot CLI وAider. ويقيّم سير عملها الطرفي بصورة مستقلة عن منتجات سطح المكتب لكل مورد.

**ابدأ بقيودك.** وصول المزود والأتمتة القابلة للتكرار وعادات المراجعة مرشحات أفضل من ترتيب عام. التوصيات التالية أحكام تحريرية تستند إلى وثائق رسمية فُحصت في 10 أكتوبر 2026، وليست تصنيفات أداء مقاسة.

## أهم النتائج

- **Claude Code وCodex وGemini CLI** تستحق التجربة حين تريد سير عمل النماذج الرسمية الخاصة بها.
- **OpenCode وAider** مناسبان للتجارب عبر مزودي النماذج، مع أساليب مختلفة للتفاعل والتحرير.
- **Copilot CLI** يستحق النظر حين يحدد وصول GitHub وسياسة المؤسسة سير عملك مسبقًا.
- **واجهة طرفية لا تعني استدلالًا محليًا** أو اختيارًا غير محدود للنماذج أو تنفيذًا دون إشراف.

**المتطلبات السابقة:** Git، ونسخة عمل يمكن التخلص منها، واختبارات تعمل، وبيانات اعتماد نماذج معتمدة. الصعوبة متوسطة. خصص فترة بعد الظهر لمقارنة أداتين مختارتين عبر ثلاث مهام صغيرة.

## القائمة المختصرة

| أداة طرفية | سبب التقييم | القرار المطلوب |
|---|---|---|
| **Claude Code CLI** | عمل مستودعات يركز على Claude | مسار الحساب وسياسة الأذونات |
| **Codex CLI** | عمل تفاعلي مع تنفيذ نصي | إعدادات sandbox ومعالجة المخرجات |
| **Gemini CLI** | سير عمل Gemini ومخرجات منظمة دون واجهة | المصادقة والحصص وسياسة الأدوات |
| **OpenCode CLI** | اختيار المزود والوكلاء القابلون للتهيئة | توافق النموذج ونقطة النهاية |
| **Copilot CLI** | الوصول إلى Copilot من shell | وصول المؤسسة وموافقة الأدوات |
| **Aider** | برمجة زوجية تركز على Git | اختيار الملفات ونموذج التحرير |

**هذه قائمة مختصرة محددة النطاق.** تقارن ستة سير عمل طرفية راسخة، وليس كل منتج يقدم CLI. تنتمي المحررات والإضافات الرسومية إلى [مقارنة وكلاء البرمجة الرسومية](/articles/gui-coding-agents-comparison/).

## Claude Code وCodex

**Claude Code CLI** يوفر جلسات تفاعلية ومحادثات قابلة للاستئناف وإدخالًا عبر pipe ووضع طباعة للنصوص البرمجية. توثق [مرجعية CLI](https://code.claude.com/docs/en/cli-reference) نقاط الدخول هذه. جرّبه إذا أردت أن يعمل Claude على تغييرات المستودع بينما توجه المهام من shell.

**Codex CLI** يتيح فحص المستودع والتحرير وتنفيذ الأوامر والمراجعة في واجهة طرفية. تصف [وثائق CLI الخاصة بـ OpenAI](https://learn.chatgpt.com/docs/codex/cli) عناصر التحكم التفاعلية. يوفر [الوضع غير التفاعلي](https://learn.chatgpt.com/docs/non-interactive-mode) الأمر `codex exec` للنصوص البرمجية والتكامل المستمر.

**اختر بينهما عبر العمل المكتمل.** امنح كل أداة خطأ غير مألوف واختبارًا موجودًا يفشل. قارن تفسيرها ونطاق التصحيح واختيار الاختبارات والتعافي بعد نهج مرفوض. لا تثبت الرسالة النهائية الواثقة صحة النتيجة.

## Gemini CLI وCopilot

**Gemini CLI** يوثق سياق المشروع والإضافات وتنفيذ الأدوات والأتمتة في [الدليل الرسمي](https://geminicli.com/docs/). يحدد [مرجع headless](https://geminicli.com/docs/cli/headless/) المخرجات المنظمة ورموز الخروج. يجعل هذا معالجة المخرجات جزءًا ملموسًا من التجربة، لا افتراضًا مبنيًا على توفر الطرفية.

**GitHub Copilot CLI** يدعم العمل التفاعلي والمطالبات البرمجية عبر الأمر المستقل الحالي `copilot`. تغطي [وثائق المنتج](https://docs.github.com/en/copilot/concepts/copilot-surfaces/copilot-cli) التخطيط وأذونات الأدوات. قيّمه مقابل الحساب والسياسات التي يستخدمها فريقك، ولا تعتبر علامة GitHub وصولًا تلقائيًا إلى كل مستودع أو خدمة.

| إدخال الأتمتة | عائلة الأوامر الموثقة |
|---|---|
| **Claude Code** | `claude -p` |
| **Codex** | `codex exec` |
| **Gemini CLI** | `gemini -p` |
| **Copilot CLI** | `copilot -p` |

**يحتاج الوضع headless إلى سياسة تنفيذ.** حدد الإجراءات المسموحة والمهلات ومعالجة الأخطاء وجمع المصنوعات قبل وضع الوكيل في pipeline. لا يثبت خروج العملية بنجاح أن الكود الناتج يحقق معايير القبول.

## OpenCode وAider

**OpenCode CLI** يجمع بين واجهة طرفية تفاعلية وعمليات سطر الأوامر. توثق [مرجعية CLI](https://opencode.ai/docs/cli/) الأمر `opencode run`، بينما يصف [دليل المزودين](https://opencode.ai/docs/providers/) اتصالات النماذج. جرّبه عندما تكون مرونة المزود مهمة بما يكفي لتبرير إدارة التوافق وتفاصيل الفوترة.

**Aider** يركز على البرمجة الزوجية في مستودع Git. تغطي [وثائقه](https://aider.chat/docs/) اختيار الملفات وخرائط المستودع واتصالات النماذج وتكامل lint/test. جرّبه عندما تفضل توجيه محادثة تحرير محددة والحفاظ على تغييرات المستودع قريبة من سير عمل Git صريح.

**تستحق أساليب التفاعل المختلفة توقعات مختلفة.** لا يستهلك مساعد تحرير محدود النطاق ووكيل يستكشف مستودعًا كاملًا السياق بالطريقة نفسها. سجل الملفات المقدمة والاستكشاف المسموح والتوجيه البشري المطلوب. لا تمنح أداة فوزًا في الإنتاجية بعد أن تتولى اختيار سياقها بنفسك دون تسجيل ذلك.

## النماذج والوصول والتكلفة

**الوكيل هو البرنامج المحيط بالنموذج.** يبني الطلبات ويتعامل مع نتائج الأدوات ويدير حالة المحادثة ويطبق سياسة التنفيذ. يؤثر النموذج ونقطة التقديم في الاستدلال وموثوقية استدعاء الأدوات والكمون والسياق المتاح.

**مرونة المزود لها تكاليف تشغيلية.** تضيف نقطة نهاية مخصصة قرارات حول معرّفات النماذج وإعدادات السياق والمصادقة ودعم الأدوات. تقلل الخدمة المتكاملة بعض خيارات الإعداد، مع ربط الوصول بحسابها وسياساتها. لا يثبت أي ترتيب جودة عامًا.

| فئة التكلفة | ما يجب تضمينه في التجربة |
|---|---|
| **حصة الحساب** | الوصول المشمول وحدود المعدل وسلوك الاستنفاد |
| **الاستدلال المحسوب** | استخدام prompt والمخرجات وcache وإعادة المحاولة |
| **التقديم المحلي** | العتاد والكهرباء وصيانة runtime |
| **الجهد البشري** | الإعداد والتصحيحات والمراجعة النهائية |
| **العمل الفاشل** | التشغيلات المتروكة والتصحيحات المعادة |

**قارن التكلفة لكل تغيير مقبول.** افصل رسوم الاشتراك عن رسوم API الإضافية ووقت المطور. يختلف عميل مجاني مع استدلال مدفوع عن اشتراك ذي حصة. أعد فحص شروط الحساب الحالية قبل تغيير المزودين.

**ثبّت مدخلات المقارنة.** سجل إصدار كل CLI ومعرّف النموذج والمزود والمراجعة الابتدائية ووضع الأذونات وتهيئة الأدوات. أعد المهمة بعد كل تغيير في أحد هذه العناصر. وإلا فإن النتيجة الأفضل تحدد نظامًا متغيرًا، لا واجهة طرفية أفضل.

## الأذونات وسياق المستودع

**الموافقة والعزل عنصران مختلفان.** يسأل طلب الموافقة هل ينبغي تنفيذ الإجراء. يحد sandbox الموارد المتاحة للإجراء المنفذ. افحص كليهما، بما يشمل وصول الملفات والشبكة والأوامر التي تطلقها الأدوات.

**تفصل وثائق أذونات Codex** صراحة بين قواعد الملفات والشبكة، بما في ذلك شروط فرض قيود الوجهة. استخدم [مرجع الأذونات](https://learn.chatgpt.com/docs/permissions) لفحص الإعداد المثبت. لكل أداة مختارة، اختبر إجراءً مسموحًا غير ضار وإجراءً محظورًا غير ضار قبل الاعتماد على السياسة.

**تحتاج تعليمات المشروع إلى تحقق.** أعط كل أداة أمر البناء نفسه ومعايير القبول والاستثناءات عبر آلية التعليمات المدعومة. اطلب منها تكرار القيود النشطة قبل التحرير. ملف التعليمات المفقود عيب إعداد، وليس معيارًا للنموذج.

```text
Task: Fix the supplied reproduction without changing the public API.
Scope: Preserve unrelated work and avoid new dependencies.
Evidence: Run the existing regression test and relevant neighboring tests.
Report: Explain the cause, changed files, checks, and remaining uncertainty.
```

**هذا الطلب التجريبي محدد عمدًا.** أضف إعادة إنتاج معروفة وفحوصًا مكتوبة باستقلال. استخدم نقطة البدء نفسها في نسخ عمل منفصلة. سجل إصدار الأداة والنموذج والمزود وسياسة الأذونات والوقت المنقضي والتدخلات.

## اختر زوجك الأول

|---|---|
| **سير عمل Claude مقابل OpenAI** | Claude Code CLI وCodex CLI |
| **سير عمل Google مقابل OpenAI** | Gemini CLI وCodex CLI |
| **مرونة المزود** | OpenCode CLI وAider |
| **نشر GitHub موجود** | Copilot CLI وبديل معتمد |

**شغّل ثلاث مهام لكل أداة:** خطأ أعيد إنتاجه وميزة صغيرة باختبارات مستقلة وإعادة هيكلة محددة. احتفظ بالمحاولات الفاشلة. راجع التصحيحات دون النظر إلى الوكيل الذي أنتجها إن أمكن. الفائز هو سير العمل الذي ينتج تغييرات مقبولة بجهد إجمالي أقل في مستودعك.

## استكشاف الأخطاء والخطوات التالية

**تبدأ النتائج غير المتوقعة غالبًا من الإعداد.** الأدوات المفقودة وأدلة العمل الخاطئة وإصدارات النماذج المختلفة والحصص المستنفدة تشوه المقارنات. تحقق منها قبل إعادة كتابة المطالبات مرارًا.
