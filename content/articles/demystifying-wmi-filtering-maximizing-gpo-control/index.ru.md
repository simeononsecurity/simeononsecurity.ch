## Введение

В объектах групповой политики (GPO) [**фильтрация WMI**](https://simeononsecurity.com/github/wmi-filters/) определяет, к каким компьютерам или пользователям применять политики, исходя из результатов запросов WMI (Windows Management Instrumentation). Администраторы могут точнее выбирать цели и применять политики только к нужным системам. В статье рассматриваются фильтрация WMI, её работа с GPO, создание [фильтров WMI](https://simeononsecurity.com/github/wmi-filters/) и практические примеры.

## [Что такое фильтрация WMI?](https://simeononsecurity.com/github/wmi-filters/)

[**Фильтрация WMI**](https://simeononsecurity.com/github/wmi-filters/) применяет фильтры к GPO на основании результатов запросов WMI. WMI встроена в операционные системы Windows и предоставляет инфраструктуру управления. Она позволяет администраторам получать данные для управления и программно взаимодействовать с системными ресурсами. Фильтрация WMI помогает динамически выбирать цели GPO по заданным критериям запросов.

Фильтры WMI пишут на языке запросов WMI (WQL), который является подмножеством SQL (Structured Query Language). Обычно они основаны на свойствах и значениях в пространстве имён WMI. Администраторы могут сочетать условия, логические операторы и пространства имён, создавая запросы для определённых компьютеров или пользователей.

## Как фильтрация WMI работает в GPO?

{{< figure src="wmi-filtering-gpo-evaluation-flow.webp" alt="Блок-схема показывает фильтр WMI, связанный с объектом групповой политики: он оценивает запрос WQL как True или False и решает, применять ли GPO к целевому компьютеру" >}}

В групповой политике **фильтрация WMI** позволяет избирательно применять GPO по результатам оценки **запросов WMI**. Связанный с GPO **фильтр WMI** возвращает **True** или **False**, и от этого зависит применение GPO.

Фильтры используют **язык запросов WMI (WQL)**, подмножество SQL. С его помощью создают сложные запросы по разным **свойствам** и **значениям**, доступным в **пространстве имён WMI**. Так можно выбирать определённые компьютеры или пользователей.

Например, организация хочет применять GPO только к компьютерам под управлением Windows 10. Для этого можно создать фильтр, проверяющий свойство **OperatingSystem** класса **Win32_OperatingSystem**. Запрос WMI может выглядеть так:

```sql
SELECT * FROM Win32_OperatingSystem WHERE Version LIKE "10.%"
```

Запрос проверяет, начинается ли версия операционной системы с «10.», что обозначает Windows 10. Если результат **True**, GPO применяется к целевому компьютеру. В противном случае она не применяется.

Фильтрация WMI также поддерживает условия и логические операторы **AND**, **OR** и **NOT**. Администраторы могут сочетать несколько свойств и значений, точнее управляя применением GPO.

Разные **пространства имён WMI** предоставляют доступ к определённым наборам классов и свойств WMI. Благодаря этому GPO можно выбирать по конфигурации оборудования, установленному ПО, сетевым настройкам и другим критериям.

Дополнительные сведения о создании фильтров и запросов WMI приведены в документации Microsoft о [фильтрации WMI для групповой политики](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/Policy/filtering-the-scope-of-a-gpo).

Фильтрация WMI помогает администраторам применять GPO к компьютерам или пользователям в зависимости от динамических условий и лучше управлять ИТ-средой.

## Создание фильтров WMI для GPO

Чтобы создать фильтр WMI для GPO, выполните следующие действия:

1. Откройте **консоль управления групповой политикой** (GPMC) на компьютере Windows, присоединённом к домену.

2. Разверните домен и перейдите к узлу **WMI Filters**.

3. Щёлкните правой кнопкой мыши **WMI Filters** и выберите **New**.

4. Задайте фильтру понятное имя и введите запрос WMI в поле **Query**, используя синтаксис WQL.

5. Нажмите **OK**, чтобы сохранить фильтр WMI.

Созданный фильтр можно связать с одной или несколькими GPO. Для этого:

1. Щёлкните правой кнопкой мыши нужную GPO и выберите **Properties**.

2. В окне свойств GPO откройте вкладку **WMI Filtering**.

3. Выберите нужный фильтр WMI из списка.

4. Нажмите **OK**, чтобы сохранить изменения.

Связав фильтр WMI с GPO, вы точно определите, где применять политику, исходя из результатов запросов WMI.

## Сколько фильтров WMI можно настроить для одной GPO?

Администраторы могут настроить **несколько фильтров WMI** для одной GPO, чтобы точнее выбирать цели. Конкретного ограничения на число фильтров для одной GPO нет, поэтому можно создавать сложные комбинации.

Однако учитывайте влияние числа фильтров на время обработки GPO. Чем больше фильтров, тем дольше может занимать оценка и применение GPO. Для эффективного применения политик используйте разумное количество фильтров.

Например, организация хочет применять GPO только к компьютерам с Windows 10 и установленной определённой программой. Можно создать два отдельных фильтра: один для **операционной системы**, другой для **установки программного обеспечения**. Их сочетание позволит выбрать нужные компьютеры.

Важно найти баланс между количеством фильтров, необходимым для целевого применения, и временем обработки. Перед выбором оцените сложность среды, число компьютеров или пользователей и возможное влияние на производительность.

Несколько фильтров WMI помогают оптимизировать выбор целей GPO, сохраняя эффективную обработку и управление ИТ-средой.

## Практические примеры фильтрации WMI в GPO

Фильтрация WMI позволяет применять политики к нужным целям. Несколько примеров:

1. **Выбор определённых операционных систем**: чтобы применять GPO только к компьютерам с **Windows 10**, создайте фильтр, проверяющий версию ОС, например `"SELECT * FROM Win32_OperatingSystem WHERE Version LIKE '10.%'"`. Так вы выберете компьютеры с Windows 10.

2. **Разные политики для настольных и портативных компьютеров**: если для этих типов устройств нужны разные политики, используйте два фильтра WMI. Один может распознавать настольные компьютеры по аппаратным атрибутам, например `"SELECT * FROM Win32_ComputerSystem WHERE Desktop = True"`, а второй распознаёт портативные компьютеры. Тогда каждому типу будут назначены подходящие политики.

3. **Выбор политики по свободному месту на диске**: чтобы не применять ресурсоёмкие политики к компьютерам с малым объёмом диска, создайте фильтр, проверяющий свободное место. Например, запрос `"SELECT * FROM Win32_LogicalDisk WHERE FreeSpace > 10737418240"` исключает компьютеры, у которых свободно менее 10 ГБ.

Эти примеры показывают гибкость **фильтрации WMI** в GPO: администраторы выбирают цели применения политик по заданным критериям.

## Заключение

Фильтрация WMI является полезной функцией объектов групповой политики. Она позволяет администраторам избирательно применять политики по результатам запросов WMI. Фильтры помогают точно выбирать компьютеры или пользователей, делая управление политиками эффективнее и контролируемее. В статье рассмотрены понятие фильтрации WMI, её работа в GPO, создание фильтров и практические примеры.

Используя фильтрацию WMI при управлении GPO, вы повышаете точность применения политик и обеспечиваете их применение только к нужным целям.
