**个人安全指南几乎都给你同样的内容：数百条没有优先顺序的建议。**它们把关闭 WebRTC、伪造 canvas 指纹、修改 user-agent，和设置密码管理器、启用自动更新放在同一句话里。

*这些措施的价值并不相同。把它们当成同等重要，会让人先做容易的事，跳过关键事项，风险依旧很高。*

本文保留主题，去掉虚假的等价关系。你会看到同一组建议按投入与风险降低效果排序，也会看到哪些习惯值得放弃。

## 简要回答

| 问题 | 简要回答 |
|---|---|
| **哪些措施最能阻止攻击？** | 密码管理器、抗钓鱼的第二因素，以及及时更新。这些习惯能应对常见的账户入侵途径，但无法覆盖所有威胁。 |
| **今天最值得做的改进是什么？** | **通行密钥或硬件安全密钥。**登录时两者都能抵抗钓鱼，因为凭据不会离开设备。也要保护恢复方式和设备。 |
| **哪些做法被高估？** | 需要记忆的复杂密码、按计划定期改密码，以及大多数浏览器指纹设置。 |
| **哪些做法被低估？** | 备份、账户恢复设置，以及设备的物理安全。 |
| **顺序重要吗？** | 重要，甚至比清单是否完整更重要。**今天完成第1级，比将来某一天做完300项更有用。** |
| **第1级要多久？** | 一次性约两小时。 |

## 为什么顺序比清单完整更重要

完整清单通常会把数百项建议标为**必需**、**可选**或**高级**。标签有助筛选，却不能替代优先级，因为风险降低幅度相差很大的项目仍会被放在同一类别。

**我的观点是：三个级别仍不够精细**，因为“必需”把风险降低效果差异很大的措施放在一起。看看两项被列为必需的做法：

- **启用2FA**可以阻断一整类账户接管攻击。
- **关闭WebRTC**可以阻断本地IP泄露，但这只与少数人有关。

两项都可以出现在完整清单中，但只有一项应该进入你的第一个小时。

**正确的排序原则是按比例衡量。**用所需投入衡量每项措施能消除多少风险，然后从上往下执行：

| 级别 | 目的 | 投入 | 阻止什么 |
|---|---|---|---|
| **1. 阻止攻击** | 关闭攻击者今天常用的途径 | ~2小时 | 凭据盗窃、钓鱼、恶意软件、设备失窃 |
| **2. 控制损失** | 出错时限制影响 | ~1小时 | 单点故障、账户丢失、身份欺诈 |
| **3. 减少暴露** | 缩小个人数据足迹 | 持续进行 | 画像、跟踪、针对性社会工程 |
| **4. 物理与人为安全** | 覆盖软件控制无法触及的层面 | ~30分钟 | 设备被扣押、旁观窥视、语音钓鱼 |

*按顺序向下做。不要因为第3级看起来更有趣就跳过去。*

## 第1级：阻止攻击

五项措施，总计约两小时，用来应对攻击者常用的途径。

### 1. 使用密码管理器，每个网站使用不同密码

**自动化凭据填充是账户接管的主要方式**，因为人们重复使用密码。某个网站发生泄露后，攻击者会自动、大规模地在其他网站尝试这些凭据。

密码管理器从根本上解决问题，让意外重复使用变得困难。它会为每个账户生成不同的高熵密码，并替你填写。

许多建议会漏掉一个关键点：**管理器的主密码现在成了唯一的故障点。**它必须足够长，并且需要记住。这是你唯一不应存放在其他地方的密码。由五到六个随机词组成的短语比短而复杂的字符串更安全，也更容易记忆。

两种架构都合理：

| 方式 | 优点 | 取舍 |
|---|---|---|
| **云端同步**（Bitwarden等） | 方便，可跨设备同步，恢复容易 | 需要信任服务商的加密和可用性 |
| **离线文件**（KeePassXC等） | 完全掌控，不依赖服务商 | 需要自己管理备份和同步 |

*任选一种。使用密码管理器与完全不用之间的差距，远大于这两种架构之间的差距。*

查看完整比较：**[2026年最佳密码管理器：Bitwarden与KeePassXC对比](/articles/bitwarden-and-keepassxc-vs-the-rest/)**，以及指南**[如何在2026年创建强密码](/articles/how-to-create-strong-passwords/)**。

### 2. 使用抗钓鱼的第二因素

第二因素不能互换。它们抵御不同攻击的能力差别很大：

| 方法 | 阻止凭据填充 | 阻止钓鱼 | 阻止会话令牌盗窃 |
|---|---|---|---|
| **短信验证码** | 是 | 部分有效，可防SIM卡交换攻击 | 否 |
| **验证器应用验证码** | 是 | 部分有效，可能遭实时中继攻击 | 否 |
| **推送审批** | 是 | 效果较弱，可能遭提示轰炸 | 否 |
| **通行密钥或硬件密钥** | 是 | **是** | 是 |

**通行密钥和FIDO2硬件密钥是清单中唯一能够抵抗钓鱼的选项。**这是结构上的差别：凭据绑定到来源域名，相似域名得不到可用凭据，受害者也没有验证码可以读给攻击者。

另一个相关威胁也值得说明，因为它能绕过人们以为安全的做法。**信息窃取恶意软件现在会直接收集浏览器Cookie**，攻击者因而可以重用已认证会话，无需密码或第二因素。这正是最后一列重要的原因，也是**第1级第3项不可省略的原因**。

*这项措施的优先顺序：有通行密钥时优先使用，邮箱和金融账户使用硬件密钥，其他情况使用验证器应用，没有更好选择时才用短信。*

{{< figure src="phishing-resistant-second-factor-comparison.webp" alt="比较短信验证码、验证器应用、推送审批和通行密钥对凭据填充、钓鱼及会话令牌盗窃的抵御能力。通行密钥能抵抗三者" >}}

使用我们的**[TOTP和HOTP生成器](/totp-generator/)**在本地生成和验证时效验证码。它读取Base32密钥或`otpauth://` URI，并完全在浏览器中运行。

### 3. 在所有设备上启用自动更新

**大多数成功入侵都利用已有补丁的漏洞。**更新延迟就是攻击者利用的窗口。

实际做法不是提醒自己勤于更新，而是在每一层启用自动更新，彻底去掉这个决定：

- **操作系统**：Windows Update、macOS Software Update，或Linux上的unattended-upgrades
- **浏览器**：保持自动更新开启，提示重启时就重启，因为未重启的浏览器仍缺少补丁
- **手机**：同时启用应用自动更新，不要只更新操作系统
- **路由器**：很多人忘记这一层，但外部网络可以访问它

**等待重启提示的浏览器仍在运行有漏洞的代码。**这一项习惯减少的暴露，超过大多数第3级措施的总和。

*我们的内核逃逸分析**[容器已不再是安全边界](/articles/containers-no-longer-security-boundary-2026/)**展示了发生权限提升时，补丁窗口为何如此重要。*

### 4. 加密设备并设置可靠的锁屏

**全盘加密能把设备失窃从数据泄露变成硬件损失。**没有加密，拿到笔记本或手机的人可以读取其中所有内容，包括密码库和活动会话令牌。

主流平台都提供加密功能，但有些默认没有启用：

| 平台 | 功能 | 检查方法 |
|---|---|---|
| **Windows** | BitLocker或Device Encryption | 设置，然后进入隐私和安全，再看设备加密 |
| **macOS** | FileVault | 系统设置、隐私与安全性、FileVault |
| **Linux** | LUKS | 安装时确认root和home卷已加密 |
| **iOS和Android** | 设置密码后默认启用 | 设置密码并确认加密已开启 |

除了加密，还有两条规则：

- **使用长口令或PIN，不要用四位数字。**邮箱和金融账户值得使用手机上最强的锁屏，因为密码保护着设备上的其他所有内容。
- **如果担心法律或胁迫风险，优先使用PIN而非生物识别。**生物识别方便且不易忘记，但在一些司法辖区，强迫取得的指纹或人脸数据所受的保护，与强迫获取的知识型信息不同。

### 5. 备份，并至少测试恢复一次

**勒索软件和硬件故障的结果相同，备份是唯一能同时应对两者的措施。**这是人们最常跳过、也最常后悔跳过的项目。

标准方案是**3-2-1**：三份副本、两种介质、一份异地保存。个人可以这样做：

- **一份本地副本**，用于快速恢复
- **一份加密的异地副本**，防范勒索软件和火灾
- **一份离线或可写入的副本**，防止勒索软件进入同步存储后破坏备份

*最后一点最重要，也最少人落实。同步存储不是备份，勒索软件和误删操作也会同步。*

**至少测试一次恢复。**从未恢复过的备份只是假设。

## 第2级：控制损失

第1级假设一切正常。第2级假设总有东西会出问题，并限制后果。

### 6. 不要重复使用邮箱地址

**你的邮箱地址是所有泄露数据库之间的关联键。**到处使用同一个地址，一个泄露事件就能与其他事件关联，也为社会工程提供了已验证的起点。

**使用别名能解决两个问题。**为每项服务生成独立地址，让地址本身成为标记：

| 好处 | 为什么重要 |
|---|---|
| **追踪泄露来源** | 某个别名收到垃圾邮件时，你就知道是哪项服务泄露或出售了地址 |
| **立即屏蔽** | 关闭单个别名，不影响真实收件箱 |
| **降低关联性** | 不同地址让攻击者难以把账户合并为同一画像 |
| **发现钓鱼** | 发往已停用别名的邮件显然是欺诈 |

**子地址**（`you+service@example.com`）是较弱的做法。它能帮助确认哪项服务泄露地址，却也暴露真实地址，不能阻止账户关联。

*如果你有自己的域名，catch-all别名可免费提供这种能力。否则，专门的别名服务也能做到。*

### 7. 账户恢复才是真正的攻击面

**攻击者越来越常绕过正门，改为攻击账户恢复流程。**设备丢失后恢复流程必须可用，也不能成为最薄弱的一环。

按以下顺序设置：

- **把备用代码保存在离线位置。**打印出来或存放在加密介质上，并与密码管理器**分开保存**，避免一个被攻破后另一个也暴露。
- **优先使用恢复密钥，而不是安全问题。**母亲婚前姓氏或第一辆车等答案经常能在公开记录中查到。
- **如果网站强制要求回答安全问题，使用虚假答案。**和账户信息一起保存在管理器中。
- **服务允许时注册第二台设备或密钥**，避免一个设备故障就无法登录。
- **删除过期的恢复联系人和电话号码**，因为旧号码可能已属于其他人。

> **警告：没有恢复代码时丢失第二因素，往往意味着永久失去账户；对于保护得当的账户，客服通常不会恢复访问权限。**启用第二因素时，就要同时设置恢复方式。

{{< figure src="three-two-one-backup-strategy-diagram.webp" alt="3-2-1备份模型示意图：两种介质上保存三份数据，其中一份离线副本可防勒索软件和意外删除" >}}

### 8. 监控数据泄露并尽早获知

**数据泄露通知的价值完全取决于时间。**最好在密码仍有可能被用于其他地方时收到通知。

- **Have I Been Pwned**会在你的地址出现在新数据集中时发送提醒。如果你拥有域名并使用别名，也可以设置整个域名的提醒。
- **密码管理器能提供更好的信号**，因为它知道哪些密码库条目对应受影响的服务，并能直接标出。

*有效流程很短：收到提醒，修改受影响账户的密码，并修改所有重复使用旧密码的账户。这就是第1级第1项的收益：密码唯一，就不必做第二步。*

### 9. 在需要之前冻结信用档案

**冻结信用是防范以新账户实施身份欺诈的最强措施**，而且免费。它阻止贷款机构查询你的信用档案，从而阻止别人以你的名义开户。

在美国，你可以在三家主要信用机构分别冻结信用档案。合法申请信贷时可以临时解冻，办完后再冻结：

1. **在三家机构都冻结信用档案**，不要只冻结一家。每家机构保存的档案都不同。
2. **把解冻PIN保存在密码管理器中。**
3. 申请信贷时**临时解冻**，之后再冻结。

*现在就做。在欺诈发生时、还要争议账户时才了解流程，是最糟糕的时机。*

## 第3级：减少暴露

第3级是缩小数据足迹。这很重要，但排在前两级之后，因为它不能阻止账户接管。

### 10. 加固你使用的浏览器

**大部分个人数据暴露发生在浏览器中**，两项改变能解决大部分问题：

- **安装内容拦截器。**广告和跟踪器是网络上的主要信息收集方式。拦截它们既能减少跟踪，也能缩小攻击面。选择一个可靠的拦截器，不要装好几个。
- **只保留实际使用的扩展。****扩展可以读取和修改网页内容**，弃用或恶意扩展可能直接接触你的登录会话。每季度检查一次扩展列表。

*浏览器指纹随机化值得了解，但很少值得优先做。它并非毫无价值，只是相较于第1至第5项收益较低，而且会导致网站出问题。*

完整分析见**[2026年最佳隐私浏览器：LibreWolf、Brave与Tor对比](/articles/best-privacy-browsers-librewolf-brave-firefox-tor/)**。

### 11. 加密DNS

**普通DNS没有加密，可以被观察，因此网络运营商和传输路径上的任何人都能看到你查询的域名。**DNS-over-HTTPS或DNS-over-TLS可以加密查询。

需要诚实看待两点：

- **DoH转移信任，而不是消除信任。**现在是解析器而非ISP看到你的查询。选择有公开隐私政策的解析器才是重点，不能只看协议。
- **DoH会绕过网络级过滤**，包括许多人依赖的家长控制和公司控制。

*除隐私以外，它还有一项实际安全收益：在不可信网络中，加密DNS让DNS欺骗不再是实用的攻击途径。*

### 12. 分享前清除元数据

**照片包含的远不止像素。**大多数手机相机会嵌入EXIF信息，包括GPS坐标、时间戳和设备标识符。

**相比照片，这一点对文档更重要。**分享的PDF或办公文档往往会保留作者姓名、编辑历史和内部文件路径，可能泄露组织信息。

我们的**[EXIF查看器](/exif-viewer/)**会在本地读取图片元数据，让你无需上传就能查看照片暴露了什么。**[URL解析器](/url-parser/)**也能检查链接，在你把地址贴进聊天前显示跟踪参数和authority中的凭据。

## 第4级：物理与人为安全

这一层大约需要三十分钟，用来应对软件控制无法覆盖的风险。

### 13. 控制设备的物理安全

- **锁定所有屏幕**，并设置较短的自动锁定时间。未锁定的笔记本相当于所有账户被攻破。
- **不要把设备留在车内可见处。**这是防盗措施，而设备被盗也意味着数据丢失。
- 在公共场所使用**防窥屏**，避免大多数旁观者窥视。
- **使用公共充电口前先检查。**优先用仅供电的数据线或自己的电源适配器，不要接入陌生USB端口。

### 14. 核实联系人，而不是相信消息

**语音和视频钓鱼已经打破“熟悉的声音就能证明身份”的假设。**利用几秒钟公开音频克隆声音已很常见，来电通常会制造紧迫感，并要求付款或提供凭据。

应通过另一个渠道核实：

1. **挂断，然后拨打你原本就有的号码**，不要拨打来电者提供的号码。
2. **把紧迫感当作警讯，而不是行动理由。**催促立即行动正是攻击手段。
3. 与可能被冒充的家人**约定一个验证短语**。
4. **不要仅凭语音电话或消息转账。**

*这是第4级收益最高的一项，而且不花钱。*

### 15. 文档与销毁

- **碎纸销毁或彻底涂除**包含账户号码、身份号码或医疗信息的文件。
- 针对特定用途分享文档时，**添加水印**并注明收件人和日期。这样不花钱，也便于追踪泄露来源。
- **申请退出个人信息搜索网站**，并做好重复申请的准备，因为列表会重新出现。
- **查看公开记录**，在可能时申请删除。

*我们的**[物理安全清单](/checklists/physical-security-checklist/)**会更深入地介绍这一层。*

## 大多数人做反了什么

以下八种习惯值得放弃。每项都说明了它为何存在，以及替代做法：

| 习惯 | 为什么会存在 | 应该这样做 |
|---|---|---|
| **记住短而复杂的密码** | 多年来一直是常见建议 | 使用管理器，并为密码库设置长口令 |
| **按固定周期更换密码** | 来自旧的合规政策 | 发现泄露或怀疑账户被攻破时再更换，不要按日历更换 |
| **关键账户依赖短信验证** | 服务默认提供短信 | 把邮箱、金融和身份账户改用通行密钥或硬件密钥 |
| **把2FA代码和密码放在同一管理器中** | 这样比较方便 | 分开保存，避免一次入侵泄露两个因素 |
| **把同步云存储当作备份** | 看起来像备份 | 另加一份离线或可写入的副本 |
| **追求完美的浏览器指纹** | 它可以量化，看起来像可执行任务 | 先完成第1至第5项 |
| **如实回答安全问题** | 看起来像必须回答 | 使用虚假答案并保存在管理器中 |
| **认为HTTPS就代表安全** | 锁形图标让人安心 | 检查域名，因为多数钓鱼网站也能取得有效证书 |

这八项有共同模式：**它们都显眼、可衡量，所以容易吸引注意，但都排在更高收益的措施之后。**在设置密码管理器之前先优化指纹熵，就是把顺序弄反了。

> **常见错误：因为密码管理器集中存放秘密，就认为它很危险。**它确实会集中风险，但替代方案是在几十个网站重复使用密码。你能控制的集中存放，胜过你无法控制的分散重复使用。

## 使用工具时不要交出数据

贯穿这一主题的实际问题是：**帮助你保护账户的工具，往往会索取你要保护的同一份秘密。**

把密码发到服务器的强度检查器会制造风险。上传文件的哈希计算器会违背检查目的。查询主机名的证书工具会把你运营哪些网站告诉第三方。

**以下工具都完全在浏览器中运行**，无需上传，也无需账户。这是本站公开说明的政策，例外项目会明确列出。

**你可以自行验证边界：**断开网络，打开工具，在处理测试值时查看浏览器网络面板。本地处理声明描述的是预期设计；你仍应检查浏览器扩展和工具版本。

| 任务 | 工具 | 功能 |
|---|---|---|
| **生成强密码** | **[密码生成器](/password-generator/)** | 使用带拒绝采样的`crypto.getRandomValues`避免取模偏差，并计算所选设置的熵 |
| **检查密码强度** | **[密码强度检查器](/password-checker/)** | 在本地评估候选密码，包括模式和重复使用情况 |
| **设置第二因素** | **[TOTP和HOTP生成器](/totp-generator/)** | 读取Base32密钥或`otpauth://` URI，并在不同时间窗口验证代码 |
| **检查网站证书** | **[SSL证书信息](/ssl-certificate-info/)** | 显示主体、有效期、密钥强度、SAN和弱算法标记 |
| **检查证书链** | **[SSL链测试器](/ssl-chain-tester/)** | 排列证书链并验证每个签名，发现缺失的中间证书 |
| **验证下载或文件** | **[哈希计算器](/hash-calculator/)** | 计算MD5到SHA-512，与公开摘要比对文件完整性 |
| **生成唯一标识符** | **[UUID生成器](/uuid-generator/)** | 生成版本位和变体位正确的Version 4标识符 |
| **检查可疑链接** | **[URL解析器](/url-parser/)** | 解码路径、列出参数，并标出authority中的凭据 |
| **检查照片元数据** | **[EXIF查看器](/exif-viewer/)** | 显示照片包含的GPS、时间戳和设备数据 |
| **测量编码或加密** | **[熵分析器](/entropy-analyzer/)** | 使用香农熵区分重复数据与编码或加密内容 |
| **安全地处理指标** | **[IOC去活与恢复](/ioc-defang-refang/)** | 将URL和地址去活化，便于安全分享 |

*表格背后的原则：如果工具需要秘密，就应在秘密所在的位置运行。查看**[所有工具](/tools/)**了解完整清单，以及少数会发出网络请求的工具及其原因。*

## 威胁模型问题

**合适的清单取决于你要防范谁。**跳过这个问题会让精力花在错误的地方。

| 你的情况 | 现实中的对手 | 重点关注 |
|---|---|---|
| **大多数个人用户** | 机会型犯罪分子、自动化凭据填充、无差别钓鱼 | 第1和第2级，以及随身携带的设备 |
| **公众人物或公开身份** | 定向钓鱼、人肉搜索、账户接管尝试 | 增加隔离管理、别名，并考虑监控社交平台信息 |
| **记者、活动人士或面临法律风险者** | 国家级或资源充足的对手、设备扣押 | 增加Tor、专用设备，以及身份隔离纪律 |
| **小企业主** | 商务邮件入侵、发票欺诈、付款转移 | 每笔转账都通过其他渠道确认 |
| **技术从业者** | 供应链攻击、凭据盗窃、通过依赖项攻击 | 增加硬件密钥、代码签名，并隔离工作和个人身份 |

**表格的真实含义。**对大多数人来说，现实风险主要在第1和第2级。高级措施对真正需要的人非常重要，却也常被不需要的人采用。

*我们的指南**[如何构建自己的个人威胁模型](/articles/how-to-form-your-own-personal-threat-model-safeguard-online-security/)**会带你完成这项评估。*

## 重点总结

- **顺序比完整更重要。**随机完成综合清单的300项，不如先完成第1级五项来得有效。
- **通行密钥和硬件密钥是唯二能抵抗钓鱼的第二因素**，因为凭据绑定来源，绝不会离开设备。
- **信息窃取恶意软件会直接收集会话Cookie**，所以会话令牌盗窃让较弱的第二因素无法独立保护账户。
- **加密能把设备失窃变成硬件损失，而非数据泄露。**确认加密已启用，因为并非所有设备默认开启。
- **同步存储不是备份。**增加一份离线或可写入的副本，并至少测试一次恢复。
- **账户恢复是新的攻击面。**把备用代码离线保存，并与密码管理器分开。
- **别名能打破泄露数据库之间的关联**，避免它们通过你的邮箱地址相连。
- **大多数被反复优化的技巧收益很低。**浏览器指纹调整和user-agent伪装远不如密码管理器和自动更新。
- **正确的清单取决于你的对手。**高级措施对需要的人非常重要，却常被不需要的人采用。
