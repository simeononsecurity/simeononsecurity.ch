**Linux のファイル権限を理解する: ファイルシステムを保護する完全ガイド**

**Linux** は、**ファイル権限**など堅牢なセキュリティ機能を備えた、強力で柔軟なオペレーティングシステムです。権限を理解し、適切に設定することは、**安全なファイルシステム**を維持するために欠かせません。このガイドでは Linux のファイル権限を説明し、システムセキュリティの重要な要素を理解する手助けをします。

## Linux のファイル権限とは

Linux は**マルチユーザー**のオペレーティングシステムで、複数のユーザーが同時にシステムへアクセスできます。ファイル権限はファイルやディレクトリへのアクセスを制御し、許可されたユーザーだけが**読み取り**、**書き込み**、**実行**などの操作を行えるようにします。

Linux の各ファイルとディレクトリには、**ユーザー**、**グループ**、**その他**という3つの権限セットがあります。**ユーザー**の権限はファイルの所有者に適用され、**グループ**の権限はファイルに関連付けられたグループに適用されます。**その他**の権限はそれ以外の全員に適用されます。

### 権限の種類

Linux のファイル権限には、**読み取り**、**書き込み**、**実行**の3種類があります。これらは次の記号で表されます。

- **r**: 読み取り権限があると、ファイルの内容を表示したり、ディレクトリの一覧を表示したりできます。
- **w**: 書き込み権限があると、ファイルの内容を変更したり、ディレクトリ内のファイルを追加、削除、名前変更したりできます。
- **x**: 実行権限があると、ファイルをプログラムとして実行したり、ディレクトリの内容にアクセスしたりできます。

3つの権限セットである**ユーザー**、**グループ**、**その他**のそれぞれに、各権限を付与または拒否できます。

### 権限の数値表現

記号による表記のほか、Linux のファイル権限は数値でも表せます。各権限の値は、**読み取り (4)**、**書き込み (2)**、**実行 (1)**です。値を合計すると、ファイルまたはディレクトリの権限を表す3桁の8進数になります。

たとえば、ユーザーに読み取りと書き込み、グループに読み取りを許可し、その他には何も許可しない場合、数値表現は **640** です。

## ファイル権限の変更

Linux でファイル権限を変更するには、**chmod** コマンドを使います。ユーザー、グループ、その他の権限を個別に変更できます。

### 記号表記で権限を変更する

記号表記では、人が読みやすい記号を使って権限を変更します。基本的な構文は次のとおりです。

```shell
chmod <permissions> <file>
```

<permissions> には、u (ユーザー)、g (グループ)、o (その他)、+ (権限を追加)、- (権限を削除)、= (権限を設定)などの記号を指定できます。

たとえば、ユーザーに読み取りと書き込みを許可するには、次のコマンドを実行します。

```bash
chmod u+rw file.txt
```
### 数値表記で権限を変更する

数値表記では、8進数を使って簡潔に権限を変更できます。前述のとおり、それぞれの権限には数値が割り当てられています。

ユーザーには読み取り、書き込み、実行を許可し、グループには読み取りと実行を許可し、その他には何も許可しない場合、次のコマンドを実行します。

```bash
chmod 750 file.txt
```
## ファイルの所有者とグループ

Linux は権限だけでなく、各ファイルやディレクトリの所有者情報も保持します。所有者情報により、どのユーザーとグループがファイルを管理するかが決まります。

### ユーザーの所有権

ファイルを作成したユーザーがその所有者になります。所有者はファイルを管理し、権限の変更、名前の変更、移動、削除を行えます。`chown` コマンドでファイルまたはディレクトリの所有者を変更できます。

`chown` の基本構文は次のとおりです。

```shell
chown <user> <file>
```

<user> にはユーザー名またはユーザー ID (UID) を指定できます。たとえば、所有者を johndoe に変更するには、次のコマンドを実行します。

```bash
chown johndoe file.txt
```

### グループの所有権
各ファイルとディレクトリはグループにも関連付けられます。既定では、ファイルを作成したユーザーのプライマリグループが割り当てられます。chgrp コマンドを使うと、グループの所有権を変更できます。

chgrp の基本構文は次のとおりです。

```bash
chgrp <group> <file>
```

<group> にはグループ名またはグループ ID (GID) を指定できます。たとえば、ファイルのグループを developers に変更するには、次のコマンドを実行します。

```bash
chgrp developers file.txt
```

## 特殊なファイル権限
標準の読み取り、書き込み、実行権限に加えて、Linux にはセキュリティを高め、追加機能を提供する特殊な権限があります。

### ユーザー識別子の設定 (SUID)
ユーザー識別子の設定 (SUID) 権限を使うと、ユーザー自身ではなくファイル所有者の権限でファイルを実行できます。ユーザーにない高い特権が必要な作業で役立つことがあります。

ファイルに SUID を設定するには、chmod で数値表記を使います。

```bash
chmod 4755 file.txt
```

先頭の数字 4 が、ユーザーに対する SUID 権限を設定します。

### グループ識別子の設定 (SGID)
グループ識別子の設定 (SGID) 権限は SUID と似ていますが、ユーザーではなくグループに適用されます。SGID を設定したファイルは、所有グループの権限で実行されます。

ファイルに SGID を設定するには、chmod で数値表記を使います。

```bash
chmod 2755 file.txt
```
先頭の数字 2 が、グループに対する SGID 権限を設定します。

### スティッキービット
スティッキービットは、ディレクトリ内のファイルが許可なく削除されるのを防ぐセキュリティ機能です。ディレクトリに設定すると、そのディレクトリ内のファイルを削除できるのはファイルの所有者だけです。

ディレクトリにスティッキービットを設定するには、chmod で数値表記を使います。

```bash
chmod 1755 directory/
```

先頭の数字 1 がスティッキービットを設定します。

## ファイル権限のベストプラクティス
Linux で権限を設定するときは、次の方法に従ってファイルシステムを保護してください。

### 最小権限の原則
最小権限の原則では、ユーザーやプロセスにはタスクの実行に必要な最低限のアクセス権だけを付与します。権限を設定するときは、各ユーザーとグループに必要な権限だけを付与してください。

### ファイル権限を定期的に監査する

ファイルシステムの安全を保つには、権限の定期監査が欠かせません。監査によって、不正アクセスや潜在的な脆弱性を特定できます。次の手順で確認します。

1. **重要なファイルとディレクトリを特定する**: 厳しい権限が必要な機密情報や重要なデータを含む場所を確認します。

2. **権限を確認する**: `-l` オプションを付けた `ls` コマンドで、権限を含むファイルとディレクトリの詳細を表示します。セキュリティリスクにつながる、過度に広い権限を探します。

3. **権限を修正する**: 不適切または安全でない権限を見つけたら、`chmod` コマンドで変更します。必要な権限を持つのが許可されたユーザーやグループだけであることを確認します。

4. **定期監査の予定を決める**: 毎週、毎月、または組織のセキュリティポリシーに従って監査を予定します。定期監査はファイルシステムの完全性を守り、権限の問題を速やかに解決するのに役立ちます。

### 規則と規制を文書化する

組織のファイル権限とアクセス制御ポリシーを文書化することが重要です。管理者とユーザーが参照できるよう、次の内容を含めてください。

- ファイル権限の種類と意味の説明。
- ファイル権限の設定と変更方法。
- ユーザーとグループに権限を割り当てる際のベストプラクティス。
- 組織に適用される規制要件や業界標準。たとえば、**一般データ保護規則 (GDPR)** や **医療保険の携行性と責任に関する法律 (HIPAA)** があります。

規則を文書化し、明確な指針を示すことで、組織内の一貫性とセキュリティ意識を高められます。

## まとめ

Linux のファイル権限を理解することは、安全なファイルシステムの維持に不可欠です。権限を理解して正しく変更し、ベストプラクティスに従うことで、Linux システムのセキュリティを高められます。定期的な監査と規則の文書化によってシステムの完全性を保ち、機密データへのアクセスを許可されたユーザーに限定できます。

ファイル権限はシステム全体のセキュリティを構成する要素の1つです。包括的で堅牢なセキュリティ戦略を作るため、暗号化、ユーザー管理、ネットワークセキュリティなどの対策も検討してください。
