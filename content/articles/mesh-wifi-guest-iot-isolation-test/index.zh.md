使用不同的 Wi-Fi 名称，并不能说明哪些设备可以互相通信。Mesh 系统可能把**访客网络**、**IoT 网络**和**无线客户端隔离**视为不同的控制项。本指南帮助你在自己的设备上测试这些路径，不要假设厂商标签就代表实际策略。

<!--more-->

## 要点

- **先确认目标可用：**测试被阻断的路径前，先从主网络访问一个已知服务。
- **逐一测试边界：**访客到主网络、IoT 到主网络、访客之间的访问回答的是不同问题。
- **记录配置：**型号、固件、路由器或接入点模式，以及连接的 Mesh 节点都会影响结果解释。
- **更改后重新测试：**测试结果只适用于已测试的设备、服务、地址族和配置。

## 开始前

预留约 20 分钟。你需要一台能够连接主 Wi-Fi、访客 Wi-Fi 和 IoT Wi-Fi 的笔记本电脑。主网络上还需要一台可信设备，并运行一个**已知开放的 TCP 服务**，例如 NAS 的 Web 界面。TCP 服务会在编号端口上监听，例如 NAS 网页使用的 443 端口。使用你拥有或管理的服务。记下其本地地址和端口，但不要公开。整个测试期间保持该服务运行。

记下 Mesh 型号、固件版本、工作模式，以及访客访问、IoT 访问、共享设备和客户端隔离设置。每次切换 Wi-Fi 后确认笔记本电脑连接的 Wi-Fi 名称。如果你的常规策略允许，可在本地路径测试期间断开 VPN 或代理，测试后再恢复。VPN 会改变被测试的路径。

> **警告：**只测试自己的设备或获准管理的设备。路由器登录页不能替代主网络上的主机，因为网关访问遵循不同规则。

**局域网（LAN）**是你的家庭专用网络。**IoT**（物联网）包括摄像头、扬声器和智能插座等设备。**客户端隔离**会阻止同一 Wi-Fi 网络中设备之间的直接流量。

## 定义边界

更改设置前先确定你想要的结果。互联网访问和本地访问是两个独立结果。

| 路径 | 要回答的问题 | 预期结果示例 |
|---|---|---|
| **访客到主 LAN** | 能否访问电脑或 NAS？ | 阻止，除非你设置了例外 |
| **IoT 到主 LAN** | 能否访问私人设备？ | 取决于产品和策略 |
| **访客之间** | 两个访客设备能否互相访问？ | 取决于客户端隔离设置 |
| **访客到共享设备** | 能否使用共享打印机或显示器？ | 仅在预期情况下允许 |
| **访客到互联网** | 能否访问普通公共网站？ | 访客策略包含互联网时允许 |

这些是不同的测试。TP-Link 的 [Deco 设备隔离指南](https://www.tp-link.com/us/support/faq/3968/)说明，隔离设备仍可访问互联网并与其他隔离设备通信，但无法访问主网络设备。ASUS 的 [AP 隔离指南](https://www.asus.com/us/support/faq/1044821/)介绍了无线对等设备控制，并指出经上游有线路由器的路径不受该控制影响。**一条路径被阻止，并不能证明其他边界也有效。**

## 检查 Mesh 设置

找到控制待测边界的功能。菜单名称和功能是否可用，因型号和固件而异。

| Mesh 设置 | 检查内容 |
|---|---|
| **TP-Link Deco 访客网络** | [路由器模式会将访客网络与主网络隔离](https://www.tp-link.com/us/support/faq/1460/)。接入点模式下检查 **Allow Local Access**。 |
| **ASUS 访客配置文件** | 支持的配置文件使用 [Access Intranet](https://www.asus.com/uk/support/faq/1009857/) 控制主网络访问。 |
| **Google Nest 访客 Wi-Fi** | 在预期隐藏打印机或显示器前，先检查[共享设备](https://support.google.com/googlehome/answer/6327302?hl=en)列表。 |
| **IoT 网络或设备隔离** | 检查产品是否提供单独的隔离控制。仅有 IoT Wi-Fi 名称并不能确定访问规则。 |

Deco 的[设备隔离](https://www.tp-link.com/us/support/faq/3968/)要求主设备和卫星设备都支持。记下哪个节点为测试笔记本提供连接。如果没有该功能，请查看准确型号和固件的文档，不要假设其他用户应用中的页面与你的设置相同。

## 建立正向对照

将 Windows 测试笔记本连接到**主 Wi-Fi**。确认所选服务可从该笔记本访问。如果使用 PowerShell，在提示时输入主网络主机地址和已知开放端口：

```powershell
$targetAddress = Read-Host "Main-network test host address"
$targetPort = [int](Read-Host "Known open TCP port")
Test-NetConnection -ComputerName $targetAddress -Port $targetPort
```

Microsoft 的 [Test-NetConnection 文档](https://learn.microsoft.com/powershell/module/nettcpip/test-netconnection)将 `-ComputerName` 和 `-Port` 定义为针对特定主机和 TCP 服务的测试。记录 `TcpTestSucceeded`。先在此确认 `True`。然后再解释之后出现的 `False`。如果主网络测试失败，问题可能出在服务、地址、主机防火墙或笔记本配置。先修复主网络测试。

如果使用手机或其他操作系统，可在浏览器或应用中打开同一个已知服务。切换 Wi-Fi 时保持服务和目标地址完全相同。设备发现列表只能提供较弱证据，因为发现流量和直接 TCP 访问走不同路径。

## 测试访客和 IoT 访问

将同一台笔记本切换到**访客 Wi-Fi**。确认 Wi-Fi 名称。如果访客策略包含互联网访问，就打开一个公共网站。重新运行同一条 `Test-NetConnection` 命令。不要更改 `$targetAddress` 和 `$targetPort`。记录结果。

切回主网络，确认服务仍返回 `True`。如果此时主网络测试失败，访客测试结果就无法定论。然后，如果系统允许笔记本接入，将其连接到**IoT Wi-Fi**并重复测试。不要假设 IoT 结果与访客结果相同。IoT 到主网络测试成功，表示在当前配置下，所选本地 TCP 服务可从 IoT 网络访问。

如果你希望访客彼此隔离，请在访客网络上使用两台你控制的设备。从一台设备测试另一台设备上的已知服务。将结果与访客到主网络的访问分开记录。如果共享打印机或显示器应当可用，也要测试该例外。通过云端控制智能设备，并不能证明存在直接本地路径。

在每个 Mesh 节点附近重复访客到主网络测试。如果应用显示服务节点，请确认它。**IPv6** 是较新的互联网协议地址族，使用 128 位地址。如果主机支持 IPv6，且主网络正向对照的 IPv6 测试成功，就从访客和 IoT Wi-Fi 使用同一地址族重复测试。仅 IPv4 测试不覆盖 IPv6 路径。

## 解读差异

| 观察结果 | 下一步检查 |
|---|---|
| **主网络和访客网络都失败** | 检查目标服务、地址、端口和主机防火墙。隔离尚未得到证明。 |
| **主网络和访客网络都成功** | 检查访客本地访问、共享设备例外，以及路由器模式与接入点模式。 |
| **主网络成功，访客失败** | 记录该目标和 TCP 路径的证据。测试策略要求的其他路径。 |
| **访客被阻止，IoT 成功** | 检查 IoT 名称是否对应一个没有匹配隔离规则的兼容网络。 |
| **访客到主网络被阻止，访客之间可访问** | 单独检查无线客户端隔离。 |

**ping** 失败无法回答 TCP 问题。主机防火墙可能阻止 ping，但允许所选服务。TCP 测试失败同样有局限：它不能说明其他端口、设备、IPv6 或共享设备例外的情况。出现差异时，应检查已配置规则并重复受控测试。

## 修复并记录结果

每次只更改一个控制项。Deco 处于接入点模式时，检查 **Allow Local Access**。ASUS 访客配置文件中，检查 **Access Intranet**。Google Nest Wifi 中，从 **Shared devices** 移除非预期项目。如果需要本地智能家居控制，在添加例外之前，先确定哪个设备需要访问哪个服务。**VLAN** 是通过共享硬件传输的逻辑网络。若消费级 Mesh 缺少所需访问规则，可参考本站的 [VLAN 分段计划](/articles/homelab-vlan-segmentation-plan/)了解托管网络方案。

记录 Mesh 型号、固件、工作模式、节点、Wi-Fi 名称、源设备、目标服务、地址族、预期结果、实际结果以及唯一一次更改。不要公开私人地址或网络密码。固件更新、节点更换或路由器和接入点模式切换后，重复相同测试。

如果你仍在选择设备，可在[Mesh Wi-Fi 购买指南](/articles/best-wifi-mesh-system-for-consumers/)中比较功能。然后用本流程验证已安装的网络。**标签或应用开关只是一个声明。正向对照和条件相同的复测，才能为你关心的具体路径提供证据。**

## 后续步骤

固件、节点或工作模式发生变化后，重复隔离测试。如果 Mesh 控制无法满足所需边界，请使用 [VLAN 分段计划](/articles/homelab-vlan-segmentation-plan/)。
