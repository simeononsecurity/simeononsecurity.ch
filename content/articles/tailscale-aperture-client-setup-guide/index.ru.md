## Введение

Tailscale Aperture предоставляет ИИ-клиентам единый шлюз в tailnet для инференса моделей и инструментов Model Context Protocol (MCP). Каждый клиент должен использовать маршрут, соответствующий его протоколу API. Инструменты MCP используют отдельную конечную точку, а разрешения Aperture определяют, к каким моделям и коннекторам может обращаться каждая идентичность Tailscale.

В этом руководстве описана настройка Codex, Claude Code, Claude Desktop, OpenCode и Hermes в macOS, Linux и Windows. Здесь разобраны параметры CLI и настольных приложений, показано, как найти доступные вашей идентичности ID моделей, а также приведён обезличенный запрос, который можно использовать при настройке другого устройства или экземпляра Aperture.

**Выбор маршрута:** Пути конечных точек зависят от шлюза и протокола API. Маршрут Responses, например `/codex`, не обслуживает трафик Anthropic Messages или MCP. Проверьте имя узла шлюза и маршрут инференса для каждого клиента. Перед изменением настроек клиента найдите ID моделей через собственный доступ к Aperture.

## Главное

- **Трафику моделей** нужен маршрут API для протокола клиента.
- **Трафик MCP** использует отдельную конечную точку `/v1/mcp`.
- **Разрешения шлюза** должны позволять вашей идентичности Tailscale использовать каждую модель и коннектор.
- **Конфигурация клиента** подтверждает только сохранение настроек. Проверьте реальный запрос и вызов инструмента MCP.

## Как работают маршруты

| Назначение | Запрос клиента | Маршрут Aperture | Что обслуживает маршрут |
|---|---|---|---|
| Codex и модели с поддержкой Responses | API OpenAI Responses | Обычно `/v1`. Пользовательский путь, например `/codex`, зависит от развёртывания. | Инференс моделей |
| Инференс моделей Claude | API Anthropic Messages | Базовый URL шлюза. Aperture обрабатывает `/v1/messages` | Инференс с поддержкой Claude |
| Инструменты MCP | Streamable HTTP MCP | `/v1/mcp` | Инструменты и ресурсы настроенных коннекторов |

**Корневые URL провайдеров:** Aperture добавляет пути клиентских запросов к базовому URL провайдера. Укажите в `baseurl` корневой URL API провайдера. Не добавляйте `/v1` к базовому URL вышестоящего провайдера, если входящий путь уже содержит `/v1`. См. [справочник по настройке Aperture](https://tailscale.com/docs/aperture/configuration), где описаны построение URL, регистрация моделей и разрешения.

## Подготовка шлюза

**До редактирования** запросите у администратора Aperture следующие сведения:

- **Имя узла шлюза:** Для большинства клиентов в tailnet используйте `http://`. Инференсу Claude Desktop нужен `https://` и доверенный сертификат.
- **Маршруты инференса:** OpenAI Responses и Anthropic Messages используют разные форматы запросов.
- **ID моделей:** Найдите модели, доступные вашей идентичности Tailscale, через конечную точку ниже. Используйте точные ID, возвращённые для этой идентичности.
- **Аутентификация:** Проверьте, отправляет ли клиент фиктивный API-ключ или учётные данные пользователя.
- **Конечная точка MCP:** Обычно `http://<APERTURE_HOST>/v1/mcp` для клиентов tailnet. Инференсу Claude Desktop нужен HTTPS с доверенным сертификатом.
- **Разрешения доступа:** Проверьте разрешения на модели и коннекторы для своей идентичности Tailscale.

**Доступ к сети:** Клиентское устройство должно обращаться к шлюзу через tailnet. Одного имени узла недостаточно для доступа к моделям и инструментам. Aperture отклоняет запрос без подходящего разрешения на модель или коннектор.

### Поиск моделей, доступных вашему пользователю

**Запросите список моделей** с устройства, подключённого к той же tailnet. Aperture использует идентичность Tailscale устройства и возвращает модели, разрешённые пользователю. Подробности приведены в [руководстве по разрешениям моделей](https://tailscale.com/docs/aperture/how-to/grant-model-access):

```sh
# macOS или Linux
curl -fsS http://<APERTURE_HOST>/v1/models
```

```powershell
# Windows PowerShell: вызовите curl.exe, чтобы обойти старый псевдоним curl
curl.exe -fsS http://<APERTURE_HOST>/v1/models
```

**Чтение результата:** Используйте каждое возвращённое `id` как ID модели. Проверьте `metadata.provider.id`, чтобы определить провайдера Aperture. Выберите модель, совместимую с форматом API клиента. Например, Claude Desktop требуется модель Anthropic Messages. В [каталоге моделей](https://tailscale.com/docs/aperture/reference/chat) Aperture также перечислены идентификаторы, доступные вошедшему пользователю.

**Модели отсутствуют:** Если ожидаемой модели нет в списке, попросите администратора Aperture проверить конфигурацию провайдера и разрешение на модель. Конечная точка не позволяет пользователям самостоятельно выдавать себе доступ.

**Схема URL:** Tailscale рекомендует `http://` для большинства клиентов в одной tailnet. WireGuard шифрует этот трафик. Claude Desktop требует `https://` и сертификат, которому доверяет операционная система. Используйте схему, указанную ниже для каждого клиента.

### Добавление провайдера инференса

**OpenAI Responses:** Добавьте вышестоящего провайдера в Aperture и включите формат API, используемый клиентом. Для OpenAI добавьте, например, такой фрагмент:

```json
{
  "providers": {
    "openai": {
      "baseurl": "https://api.openai.com",
      "apikey": "<UPSTREAM_PROVIDER_KEY>",
      "models": ["<MODEL_ID>"],
      "compatibility": {
        "openai_chat": true,
        "openai_responses": true
      }
    }
  }
}
```

**Anthropic Messages:** Используйте корневой URL API Anthropic, формат авторизации `x-api-key` и совместимость `anthropic_messages`. ID модели также должен присутствовать в списке `models` провайдера. Добавьте, например, такой фрагмент:

```json
{
  "providers": {
    "anthropic": {
      "baseurl": "https://api.anthropic.com",
      "apikey": "<UPSTREAM_PROVIDER_KEY>",
      "authorization": "x-api-key",
      "models": ["<CLAUDE_MODEL_ID>"],
      "compatibility": {
        "anthropic_messages": true
      }
    }
  }
}
```

**Изменение конфигурации:** Замените каждый заполнитель данными вышестоящего провайдера. Добавьте фрагменты в существующую конфигурацию Aperture. Сохраните остальные настройки файла. Включите флаги совместимости для API, поддерживаемых провайдером.

**Разрешения доступа:** Aperture управляет доступом пользователей к каждой модели и каждому коннектору. Выдавайте пользователям Tailscale только необходимые права. Этот пример разрешает одному пользователю доступ к модели провайдера и коннектору:

```json
{
  "grants": [
    {
      "src": ["<TAILSCALE_USER>"],
      "app": {
        "tailscale.com/cap/aperture": [
          {"role": "user", "models": "openai/<MODEL_ID>"},
          {"connectors": ["teamtools/**"]}
        ]
      }
    }
  ]
}
```

**Разрешение на модель:** Используйте ID провайдера и модели в шаблоне разрешения. В [руководстве по настройке коннекторов](https://tailscale.com/docs/aperture/connectors/get-started) показана текущая конфигурация `connectors.servers`. Прежняя конфигурация верхнего уровня `mcp.servers` устарела.

### Добавление коннектора MCP

**Коннектор MCP:** Aperture подключается к вышестоящим MCP-серверам и предоставляет инструменты через `/v1/mcp`:

```json
{
  "connectors": {
    "servers": {
      "teamtools": {
        "protocol": "mcp",
        "url": "<UPSTREAM_MCP_ENDPOINT>"
      }
    }
  }
}
```

**URL коннектора:** Используйте полный MCP-адрес вышестоящего сервера. Затем предоставьте своей идентичности Tailscale доступ к `teamtools/**` или более узкому шаблону инструментов. В [справочнике прокси MCP](https://tailscale.com/docs/aperture/mcp-server) описаны единая конечная точка клиента и работа коннекторов.

## Codex CLI и настольное приложение

**Общие настройки:** Codex CLI и настольное приложение используют одну конфигурацию. В macOS и Linux отредактируйте `~/.codex/config.toml`. В Windows используйте `%USERPROFILE%\.codex\config.toml` (оболочки, раскрывающие домашний каталог, также понимают `~/.codex/config.toml`). В [обзоре приложения Codex](https://openai.com/index/introducing-the-codex-app/) сказано, что приложение использует настройки Codex CLI. Пользовательская конфигурация Codex хранится в `~/.codex/config.toml`. Документ [основ конфигурации](https://learn.chatgpt.com/docs/config-file/config-basic) описывает пользовательские поля провайдера и MCP. Добавьте провайдера в этот файл, перезапустите приложение и проверьте, что провайдер и модель появились в интерфейсе.

```toml
model = "<MODEL_ID>"
model_provider = "aperture"

[model_providers.aperture]
name = "Aperture Proxy"
base_url = "http://<APERTURE_HOST>/v1"
wire_api = "responses"
requires_openai_auth = true
supports_websockets = false
```

**Необязательные поля:** Эти два значения соответствуют одному варианту провайдера Codex. Оставляйте их, только если этого требуют ваш шлюз и конфигурация Codex. В актуальном [руководстве Tailscale по Codex Aperture](https://tailscale.com/docs/aperture/how-to/use-codex) они отсутствуют, используется `wire_api = "responses"`, и сказано, что Aperture добавляет вышестоящие учётные данные. Используйте точный URL Responses от администратора шлюза. `/codex` зависит от развёртывания. Документированный Tailscale маршрут по умолчанию — `/v1`.

**Настройка MCP:** Добавьте сервер в ту же пользовательскую конфигурацию:

```toml
[mcp_servers.aperture]
url = "http://<APERTURE_HOST>/v1/mcp"
enabled = true
```

**Проверка Codex:** Выполните `codex mcp list`, запустите новый сеанс и откройте `/mcp`. Список серверов подтверждает регистрацию. Наличие инструмента и успешный вызов подтверждают его обнаружение и работу. В [справочнике конфигурации Codex](https://learn.chatgpt.com/docs/config-file/config-reference) описаны пользовательские настройки провайдера и MCP.

## Claude Code CLI

**Протокол:** Claude Code использует Anthropic Messages. Направьте глобальный файл настроек Claude Code на совместимый с Anthropic шлюз Aperture. Используйте `~/.claude/settings.json` в macOS и Linux или `%USERPROFILE%\.claude\settings.json` в Windows. В PowerShell используйте `$HOME\.claude\settings.json`. Маршрут должен обслуживать `/v1/messages`. Codex Responses использует другой протокол и маршрут. Tailscale рекомендует HTTP для Claude Code в tailnet, поскольку WireGuard шифрует соединение.

```json
{
  "apiKeyHelper": "echo '-'",
  "env": {
    "ANTHROPIC_BASE_URL": "http://<APERTURE_HOST>"
  }
}
```

**Аутентификация клиента:** В руководстве Aperture для клиента в `apiKeyHelper` используется заполнитель, поскольку Aperture добавляет вышестоящие учётные данные. Для передачи подписки Claude провайдер Anthropic в Aperture должен передавать учётные данные Claude пользователя. В этом случае оставьте `ANTHROPIC_API_KEY` и `ANTHROPIC_AUTH_TOKEN` незаданными. Эти переменные заменяют данные подписки. Следуйте текущим [инструкциям Claude Code для Aperture](https://tailscale.com/docs/aperture/how-to/use-claude-code) для своей версии и [руководству Anthropic по шлюзам](https://code.claude.com/docs/en/llm-gateway-connect) по вариантам аутентификации.

**MCP через HTTP:** Добавьте конечную точку командами:

```sh
claude mcp add --transport http --scope user aperture http://<APERTURE_HOST>/v1/mcp
claude mcp list
```

**Проверка Claude Code:** Запустите сеанс и выполните `/mcp`. В [документации MCP](https://code.claude.com/docs/en/mcp) Anthropic рекомендует HTTP для удалённых MCP-серверов.

## Графический интерфейс Claude Desktop

**Отдельные настройки:** В Claude Desktop есть экран инференса сторонних служб. Этот параметр направляет запросы моделей Claude Desktop через Aperture. Настройка MCP выполняется отдельно.

1. В Claude Desktop для macOS или Windows выберите **Справка > Устранение неполадок > Включить режим разработчика**. В бета-версии Linux используйте то же меню, если оно доступно. Перезапустите приложение по запросу. Если меню отсутствует, обновите Claude Desktop и проверьте примечания к выпуску для своей платформы.
2. Выберите **Разработчик > Настроить сторонний инференс**.
3. Установите **Тип подключения**: **Шлюз**, а **Тип учётных данных**: **Статический API-ключ**.
4. Введите `https://<APERTURE_HOST>` как **базовый URL шлюза**. Используйте полное имя узла, покрытое доверенным TLS-сертификатом.
5. Введите непустой заполнитель, например `aperture`, в качестве ключа шлюза. Aperture игнорирует его и аутентифицирует подключение через tailnet.
6. Оставьте пользовательские заголовки инференса пустыми.
7. Добавьте включённую модель с точным ID из `GET /v1/models` для вашей идентичности Tailscale. Выберите модель Anthropic Messages. Вручную укажите ID, отображаемое имя и необязательный псевдоним уровня. Claude Desktop не обнаруживает модели на этом экране.
8. Нажмите **Сохранить изменения**, затем **Применить изменения**. Закройте Claude Desktop и запустите снова.

**Проверка протокола:** В [руководстве Aperture для Claude Desktop](https://tailscale.com/docs/aperture/how-to/use-claude-desktop) сказано, что Claude Desktop использует Anthropic Messages по адресу `/v1/messages`. Не указывайте маршрут Codex `/codex` и не выбирайте подключение OpenAI.

### Подключение Claude Desktop к MCP

**Приватный доступ MCP:** Запустите локальный stdio-мост на том же компьютере, где установлен Claude Desktop. Добавьте в локальную конфигурацию MCP:

```json
{
  "mcpServers": {
    "aperture": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://<APERTURE_HOST>/v1/mcp"]
    }
  }
}
```

**Как работает мост:** Локальный процесс подключается к Aperture через Tailscale на компьютере. Используйте путь конфигурации для своей ОС: macOS — `~/Library/Application Support/Claude/claude_desktop_config.json`; Windows — `%APPDATA%\Claude\claude_desktop_config.json`; бета-версия Linux — откройте **Настройки > Разработчик > Изменить конфигурацию** и используйте путь, открытый Claude Desktop. Путь Linux зависит от пакета. Перезапустите Claude Desktop, проверьте список коннекторов и выполните безопасный вызов инструмента. В [проекте `mcp-remote`](https://github.com/punkpeye/mcp-remote) описан локальный мост к удалённому серверу.

**Удалённые коннекторы:** Для раздела Anthropic «Настройки > Коннекторы» нужен удалённый сервер, доступный службе Anthropic. Имя узла только в tailnet закрыто для ваших устройств, поэтому используйте локальный мост. Если вы публикуете MCP-службу, настройте аутентификацию и разрешения до добавления облачного коннектора. См. [руководство Anthropic по удалённым MCP-коннекторам](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

## OpenCode CLI и настольное приложение

**Общие настройки:** OpenCode CLI и настольное приложение читают одну конфигурацию. В текущей документации OpenCode V2 для пользовательских провайдеров используется карта `providers`, а серверы MCP находятся в `mcp.servers`. В примере используется совместимая с OpenAI конечная точка чата `/v1`. Перед использованием проверьте, поддерживает ли провайдер Aperture OpenAI Chat Completions.

**Глобальная конфигурация:** В macOS и Linux отредактируйте `~/.config/opencode/opencode.json`. В Windows используйте `%USERPROFILE%\.config\opencode\opencode.json`. Добавьте совместимого с OpenAI провайдера и замените `<MODEL_ID>` точным ID модели Aperture. OpenCode также принимает `opencode.jsonc` в том же каталоге для комментариев. [Справочник по конфигурации](https://opencode.ai/docs/config/) объясняет приоритет глобальных и проектных настроек.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "model": "aperture/<MODEL_ID>",
  "providers": {
    "aperture": {
      "env": ["APERTURE_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://<APERTURE_HOST>/v1"
      },
      "models": {
        "<MODEL_ID>": { "modelID": "<MODEL_ID>" }
      }
    }
  },
  "mcp": {
    "servers": {
      "aperture": {
        "type": "remote",
        "url": "http://<APERTURE_HOST>/v1/mcp",
        "oauth": false
      }
    }
  }
}
```

**Аутентификация клиента:** `oauth: false` пропускает стандартный вход OpenCode через OAuth. Aperture определяет вызывающего по Tailscale. OpenCode также требует запись аутентификации провайдера, поэтому задайте `APERTURE_API_KEY=-` в локальной среде. Настольное приложение тоже должно получить эту переменную. Если оно не наследует среду оболочки, выполните `/connect` и введите `-` для Aperture. Не храните в этом файле ключ вышестоящего провайдера. В [руководстве OpenCode по провайдерам](https://opencode.ai/docs/providers/) и [руководстве MCP](https://opencode.ai/docs/mcp-servers/) описан актуальный формат. Выполните `opencode mcp list`, затем откройте `/mcps` в приложении, чтобы проверить состояние.

## Hermes CLI и настольное приложение

**Общие настройки:** Hermes Agent хранит именованные провайдеры и серверы MCP в `~/.hermes/config.yaml` в macOS и Linux. В Windows используется `%LOCALAPPDATA%\hermes\config.yaml`. Выполните `hermes config path`, чтобы узнать активный файл. `HERMES_HOME` может изменить расположение по умолчанию. Локальный Hermes Desktop использует тот же каталог Hermes и профиль, что и CLI. Если Desktop подключён к удалённому шлюзу Hermes, настройте Aperture на компьютере с Hermes и проверьте его доступ к tailnet. См. [руководство Hermes Desktop](https://hermes-agent.nousresearch.com/docs/user-guide/desktop).

**Провайдер Responses:** Добавьте именованный провайдер. Значение `api` должно соответствовать конечной точке Responses вашей Aperture:

```yaml
providers:
  aperture:
    api: "http://<APERTURE_HOST>/v1"
    transport: codex_responses
    default_model: "<MODEL_ID>"
    # Добавьте key_env только при необходимости ключа клиента в Aperture.
    # key_env: APERTURE_API_KEY

model:
  provider: "custom:aperture"
  default: "<MODEL_ID>"
```

**Выбор протокола:** Для OpenAI Chat Completions укажите `transport: chat_completions`. Для Anthropic Messages выберите `transport: anthropic_messages` и используйте URL шлюза Anthropic Messages. В актуальном [руководстве по провайдерам](https://hermes-agent.nousresearch.com/docs/integrations/providers) описаны поля `api`, `transport` и `default_model`.

**Настройка MCP:** Добавьте Aperture MCP в тот же YAML-файл:

```yaml
mcp_servers:
  aperture:
    url: "http://<APERTURE_HOST>/v1/mcp"
    enabled: true
```

**Проверка Hermes:** Выполните `hermes mcp` и проверьте каждое подключение в интерактивном списке серверов. Локальный Desktop использует тот же профиль. Hermes описывает [удалённые HTTP-серверы MCP](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp) и [полный справочник конфигурации MCP](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference).

## Проверка обоих маршрутов

**Проведите отдельные проверки** инференса моделей и MCP:

1. Убедитесь, что устройство подключено к Tailscale и достигает шлюза. Для Claude Desktop проверьте, что шлюз предоставляет доверенный TLS-сертификат.
2. Отправьте короткий запрос через каждый настроенный клиент. Убедитесь, что соответствующий запрос появился в списке сеансов Aperture.
3. Проверьте, что выбранный ID модели соответствует модели, разрешённой вашей идентичности Tailscale.
4. Откройте экран состояния MCP клиента или выполните команду списка. Убедитесь, что сервер Aperture подключён и показывает ожидаемые инструменты.
5. Вызовите инструмент только для чтения. Сверьте результат с вышестоящим источником.
6. При сбое запроса модели или инструмента проверьте журналы Aperture. Сохранённая конфигурация не подтверждает успешный запрос.

| Проблема | Проверка |
|---|---|
| Запрос модели возвращает 404 или 405 | Проверьте маршрут и протокол конечной точки клиента. Не используйте `/codex` для Anthropic Messages или MCP. |
| Модель недоступна | Запросите `/v1/models` от имени нужного пользователя Tailscale. Проверьте наличие точного ID и совместимость формата API. Попросите администратора проверить отсутствующие провайдеры или разрешения. |
| Запрос не авторизован | Проверьте, нужны ли клиенту заполнитель, bearer-токен или передача подписки. Не копируйте ключ вышестоящего провайдера в общедоступный файл проекта. |
| Сервер MCP виден, но инструменты отсутствуют | Проверьте `/v1/mcp`, состояние коннектора, его разрешения и сетевой маршрут клиента к Aperture. |
| Claude Desktop не подключается к приватному URL MCP | Запустите локальный мост, например `mcp-remote`, или используйте одобренный публичный коннектор с подходящей аутентификацией. |

## Повторная настройка на другом устройстве

**Новое устройство:** Установите тот же клиент и сначала подключите устройство к tailnet. Запросите `/v1/models` с нового устройства, чтобы увидеть модели, разрешённые его идентичности Tailscale. Скопируйте структуру настроек, но храните учётные данные локально. Замените `<APERTURE_HOST>`, `<MODEL_ID>` и `<UPSTREAM_MCP_ENDPOINT>` значениями целевого экземпляра Aperture. Для каждого протокола API используйте отдельную конечную точку, а для инструментов настройте путь `/v1/mcp`. Затем проверьте запрос модели и вызов инструмента MCP.

**Несколько шлюзов:** Для каждого экземпляра Aperture нужна отдельная конфигурация. Устройство использует Responses для Codex и Hermes, Anthropic Messages для Claude и агрегирующий MCP-адрес для инструментов. Храните ключи API в локальном хранилище секретов клиента или переменной среды. Не копируйте их в общие `config.toml`, `opencode.json`, `config.yaml` или общедоступный репозиторий.

## Повторно используемый запрос для настройки Aperture

**Скопируйте этот обезличенный запрос** в помощник по программированию. Замените заполнители данными шлюза. Перед выбором ID моделей помощник должен обратиться к Aperture от имени вашей идентичности Tailscale.

```text
Настрой существующий шлюз Tailscale Aperture и ИИ-клиенты, установленные на этом устройстве.

Клиенты: Codex CLI и настольное приложение, Claude Code, Claude Desktop, OpenCode CLI и настольное приложение, Hermes CLI и настольное приложение.

Сначала определи, работает ли устройство под macOS, Linux или Windows, найди активную командную оболочку (например, zsh, bash или PowerShell) и используй соответствующие пути и синтаксис команд. Проверь текущий шлюз, подключение Tailscale, версии клиентов и существующие настройки. Прочитай актуальную официальную документацию. Сохрани несвязанные настройки и сделай резервную копию каждого файла перед изменением. Не угадывай имена узлов, ID моделей, маршруты API или учётные данные. Храни ключи вышестоящих провайдеров в Aperture, а не в файлах клиентов или репозитории.

Найди модели, доступные с этого устройства в Tailscale:
1. Запроси `http://<APERTURE_HOST>/v1/models` с идентичностью Tailscale моих клиентов. Если шлюз документирует другой URL списка моделей, используй его.
2. Прочитай `id` и `metadata.provider.id` каждой модели. Список отражает доступ моделей моей идентичности. Не подменяй его списком администратора и не выдумывай ID.
3. Сопоставь API-совместимость модели и клиента. Codex использует OpenAI Responses, Claude — Anthropic Messages. Для OpenCode и Hermes требуются совместимый провайдер и транспорт.
4. По возможности оставь существующую модель по умолчанию. Если клиенту нужна модель по умолчанию, а у меня нет предпочтений, покажи совместимые варианты и попроси выбрать. В Claude Desktop введи точный ID модели вручную.
5. Если нет подходящей модели, проверь провайдера и разрешения только при наличии у меня административного доступа. Иначе укажи, какой доступ к модели должен добавить администратор. Не выдавай доступ самому себе.

Найди развёртывание Aperture и источник его конфигурации. Не предполагай путь к файлу и не заменяй всю конфигурацию. Для OpenAI Responses требуется `openai_responses`; для Anthropic — `anthropic_messages`. Коннекторы MCP находятся в текущей конфигурации `connectors.servers`, клиенты подключаются через `/v1/mcp`.

До изменения общего шлюза подготовь минимальные изменения провайдеров, коннекторов и разрешений. Примени их, только если у меня есть права администратора и запрос разрешает менять шлюз. Иначе сообщи владельцу экземпляра точные предлагаемые изменения. Не создавай и не расширяй разрешения без явного согласия владельца. Сохрани все существующие настройки шлюза.

Настрой каждый установленный клиент в актуальном официальном формате и по пути для его ОС:
- Codex CLI и Desktop используют `~/.codex/config.toml` в macOS/Linux и `%USERPROFILE%\.codex\config.toml` в Windows. Укажи провайдер Aperture, совместимую модель, `wire_api = "responses"` и MCP в `mcp_servers`.
- Claude Code использует `ANTHROPIC_BASE_URL` и удалённый MCP через HTTP. Используй `~/.claude/settings.json` в macOS/Linux и `%USERPROFILE%\.claude\settings.json` в Windows.
- Claude Desktop использует режим разработчика, настройку стороннего инференса, шлюз, статический API-ключ, HTTPS URL с доверенным сертификатом и ID модели, найденный для моего пользователя. Для приватного MCP в tailnet используй локальный мост `mcp-remote`. Найди конфигурацию MCP в Настройки > Разработчик > Изменить конфигурацию или используй документированный путь ОС.
- OpenCode использует схему V2 `providers` и `mcp.servers`. Глобальный файл: `~/.config/opencode/opencode.json` в macOS/Linux или `%USERPROFILE%\.config\opencode\opencode.json` в Windows. Для MCP Aperture задай `oauth: false`. При необходимости используй локальный фиктивный API-ключ.
- Hermes использует именованный провайдер, транспорт для API модели и `mcp_servers`. В macOS/Linux используй `~/.hermes/config.yaml`. В Windows проверь `hermes config path`, обычно `%LOCALAPPDATA%\hermes\config.yaml`. Проверь, использует ли Hermes Desktop локальный профиль Hermes.

Используй HTTP для трафика tailnet, если клиент поддерживает его. Инференсу Claude Desktop нужен HTTPS с доверенным сертификатом. Используй `/v1`, если шлюз не документирует другой маршрут.

Перезапусти клиентов. В Aperture проверь по одному запросу модели от каждого клиента и один безопасный вызов инструмента MCP только для чтения. Укажи найденные для моей идентичности модели, изменённые клиенты и файлы, результаты проверки и оставшиеся действия администратора. Не устанавливай ПО, не открывай шлюз для общего доступа, не создавай коммиты и ничего не публикуй.
```

## Итоги

Для работы Aperture нужны доступный шлюз, маршрут модели для протокола клиента и разрешения на нужные модели и коннекторы MCP. Эти шаблоны подходят для macOS, Linux и Windows, но каждый клиент хранит настройки в своём системном каталоге.

Запрашивайте ID моделей от имени той идентичности Tailscale, которая будет ими пользоваться. Настройте инференс и `/v1/mcp` отдельно, затем проверьте реальный запрос и вызов инструмента только для чтения. При переходе на другое устройство или экземпляр Aperture используйте структуру этого руководства, проверьте маршруты и разрешения нового экземпляра и храните учётные данные локально.
