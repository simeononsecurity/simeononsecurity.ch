**上下文窗口是模型在当前轮次处理的文本和其他材料。**提示词、指令、工具定义、文件摘录、工具输出和对话历史都会占用空间。本课介绍如何让下一项任务保持聚焦，并留下可靠的交接记录。

**学习目标：**编写简洁的交接记录，并在新会话中测试。

## 要点

- **Token（令牌）**是模型处理输入和输出的单位。
- **活动上下文**是当前轮次可用的材料，受产品限制约束。
- **持久来源**是聊天之外的文件或项目记录。
- **压缩**会总结或删减较早的上下文，可能遗漏必要细节。
- **交接记录**会为新会话指明当前来源和已验证的工作。

## 开始之前

**前置条件：**完成[第一个编码代理任务](/articles/effective-ai-coding-agent-first-task/)中的实验，并准备好已批准的需求和[任务包课程](/articles/effective-ai-task-packets/)。如果你走学习路线，请使用手动编辑过的实验。预留 35 分钟。难度为中级。将课程笔记保存在解压后的实验目录之外，让 `git status` 只反映代码更改。

## 按任务选择上下文

**编辑状态筛选器时，**代理需要 `task_report.py`、`docs/requirements.md`、相关测试和一小段 `tasks.json` 示例。旧聊天、整个网站文档和完整 Git 历史都不需要。先查看项目地图，再加载下一步决策所需的最少文件。

| 任务 | 有用的上下文 | 多余的上下文 |
|---|---|---|
| **定义行为** | 已批准的需求和一份数据样例 | 早期探索性对话 |
| **编辑程序** | 程序和针对性测试 | 无关项目目录 |
| **审查结果** | 差异、测试输出、需求 | 完整代理记录 |
| **稍后继续** | 交接记录和来源路径 | 粘贴数小时的完整聊天 |

**这是检索内容的选择，不是隐藏证据的规则。**测试失败时，附上准确的失败输出和相关文件。删除无关日志，保留诊断问题所需的细节。

**添加工作代理之前先计算固定开销。**代理指令和可用工具架构可能在读取任务文件前就占用上下文。第二个工作代理会重复部分开销，并增加一份主代理需要审核的报告。修改两个文件时用一个代理。独立搜索许多来源时，简短的工作报告可能减少主会话的上下文，即使总令牌用量上升。

## 编写简洁的交接记录

**交接记录是留给下一会话的简短记录。**它应区分已完成的工作和计划中的工作。将此示例保存在实验目录之外的 `course-notes/handoff.md`，并用自己的观察结果替换示例内容。

```text
目标：为课程任务报告添加 --status open|done。
来源：docs/requirements.md，修订版 1。
工作区：解压后的 effective-ai-course-lab 文件夹。
当前状态：task_report.py 和测试中已包含状态筛选编辑。
已验证：记录观察到的测试结果，以及手动计数 4、2、2。
决定：tasks.json 未更改。
待办：独立审查差异和来源。
下一项检查：重新运行测试和无效状态案例。
停止条件：需求或基准值与上述记录不符。
```

**此示例不代表你已经完成这些工作。**记录实际观察到的测试结果和已修改文件。如果来源版本发生变化，重新阅读来源后再更新交接记录。

## 测试新会话

**在实验环境中启动新的聊天或编码代理会话。**在聊天中粘贴交接记录和合成实验中的 `AGENTS.md`，并列出要检查的文件。在编码代理中打开实验目录，粘贴交接记录，并允许其读取列出的文件。提出以下问题：

```text
根据这份交接记录和当前仓库文件，列出已批准的状态值、基准计数和下一项检查。不要编辑。
如果交接内容与当前来源冲突，请报告冲突。
```

**预期推理：**新会话会在 `docs/requirements.md` 中找到 `open` 和 `done`，确认基线数量为 4，并指出测试和手动检查。如果它重复了旧值 `pending`，重新阅读需求并修正交接记录。

## 控制协调代理的上下文

**协调代理是负责统筹工作代理的主代理。**给每个工作代理指定一个范围明确的问题和具体输入文件。要求返回简短结果：发现、证据路径、置信度和未解决问题。详细日志放在文件或工作代理自己的会话中。只带回主代理作出下一步决定所需的信息。

**示例：**让一个只读工作代理检查测试，并返回“缺失的用例、文件和行号、建议的检查”。不要让它把所有测试粘贴到主聊天。主代理先在仓库中验证发现，再进行修改。[委派课程](/articles/effective-ai-agent-delegation/)会在任务范围值得投入时增加一项独立的工作代理任务。

**许多产品中的工作会话有自己的上下文，**但上下文继承和隔离方式各不相同。不要假设工作代理能看到与主代理相同的指令、文件或工具，先查看产品当前规则。[Codex 子代理指南](https://learn.chatgpt.com/docs/agent-configuration/subagents)和[Claude Code 子代理指南](https://code.claude.com/docs/en/sub-agents)分别介绍了对应产品的行为。

## 谨慎使用压缩

**压缩会缩短活动历史。**Codex、Claude Code 和 OpenCode 的压缩时机和方式不同。把压缩后的摘要当作继续工作的辅助材料，而不是完整的项目记录。将需求和决定保存到文件，并在压缩后重新核对。查看关于[Codex 最佳实践](https://learn.chatgpt.com/docs/learn/best-practices)、[Claude Code 命令](https://code.claude.com/docs/en/commands)和[OpenCode 2 压缩](https://opencode.ai/v2/docs/compaction)的最新说明。OpenCode 1 与 OpenCode 2 使用不同的压缩架构。复制设置之前先检查 `opencode --version`。

**如果助手忘记了限制条件，**停止编辑，重新打开来源并重述任务包。带有简短且经过验证交接记录的新会话，通常比反复纠正混乱的长对话更省精力。

## 练习与检查

**你的成果：**一份不超过 180 词的交接记录，保存在实验环境之外。将每行标记为来源、观察结果、决定或待办事项。把记录交给新会话，并检查它是否指出两个可接受的状态值和下一项检查。

**完成检查：**新会话无需依赖旧聊天即可说出 `open`、`done`、基线数量 4 和一个测试步骤。补齐缺失内容，然后在另一个新会话中重测。

## 检查理解

1. **问题：**新会话的交接记录应包含什么？**答案：**目标、权威来源、当前状态、已核验结果和下一步行动。

2. **问题：**为什么工作代理报告应简短？**答案：**简洁且带证据的报告能提供协调代理所需的结果，无需重复工作代理的完整记录。

## 故障排查

- **摘要漏掉一项决定：**补充一行简短说明，并注明来源版本。
- **工作代理回复过长：**要求有限范围的证据表和文件引用。
- **交接记录过时：**再次编辑前先重读当前来源文件。
- **上下文仍然紧张：**将任务拆分到多个较小会话，并分别保存成果。
