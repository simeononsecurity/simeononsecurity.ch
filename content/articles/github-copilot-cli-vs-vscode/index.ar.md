**يقدم GitHub Copilot CLI وCopilot في VS Code نقطتي دخول مختلفتين للعمل البرمجي.** يبدأ CLI من الصدفة وموجه المهمة. يجمع VS Code سياق المحرر والاقتراحات والدردشة وسير عمل الوكيل. يجب تقييمهما ضمن سياسة الحساب والمستودع نفسها.

**الاختيار ليس حصريًا.** توثق GitHub اتصال Copilot CLI بـ VS Code. تستفيد المهمة الطرفية من تحديد المحرر والمراجعة المرئية عند وصلهما صراحة.

## أهم الخلاصات

- **استخدم Copilot CLI للمهام الطرفية** والاستدعاء البرمجي المدعوم.
- **استخدم Copilot في VS Code للعمل المتمحور حول المحرر**، بما في ذلك المساعدة المضمنة ووضع Agent.
- **صل CLI بـ VS Code** عند الحاجة إلى موجهات طرفية مع سياق المحرر والفروق.
- **تحقق من إعدادات الحساب والنموذج والسياسة** حتى داخل عائلة منتج واحدة.

**النطاق والتاريخ:** فُحصت الوثائق الرسمية في 10 أكتوبر 2026. تقارن هذه الصفحة CLI المستقل `copilot` مع Copilot في VS Code، ولا تقارن إضافة `gh copilot` القديمة أو وكيلًا سحابيًا أُسندت إليه مشكلة GitHub. المتطلبات مستودع قابل للاختبار ووصول مسموح إلى Copilot. خصص ساعة للتجربة.

## ثلاث طرق للعمل

| سير العمل | التفاعل الرئيسي | مهمة تجربة مناسبة |
|---|---|---|
| **CLI مستقل** | موجه طرفي ومخرجات أوامر | شرح وإصلاح فشل اختبار أعيد إنتاجه |
| **تكامل VS Code** | تحديد المحرر والدردشة والاقتراحات والفروق | تعديل دالة محددة واختباراتها |
| **CLI متصل بـ VS Code** | مهمة طرفية مع سياق المحرر والمراجعة | التحقيق من الصدفة وفحص التصحيح بصريًا |

**يبقى الوضع الهجين جلسة CLI.** تشغيله داخل طرفية مدمجة لا يحوله تلقائيًا إلى محادثة Agent الأصلية في المحرر. تحقق من الجلسة والاتصال النشطين بدل الاعتماد على النافذة التي تعرض الموجه.

## ما يقدمه CLI

```bash
copilot
```

**يبدأ الأمر المستقل الحالي وكيل الطرفية.** يصف [دليل Copilot CLI](https://docs.github.com/en/copilot/concepts/copilot-surfaces/copilot-cli) من GitHub الاستخدام التفاعلي والبرمجي. ويوثق التخطيط وأذونات الأدوات. قيّمه حين تكون مخرجات الطرفية الدليل الرئيسي للمهمة.

**تبدأ المهمة الجيدة بفشل محدد.** قدم الأمر الفاشل والسلوك المتوقع وقيدًا يمنع إعادة الهيكلة غير المرتبطة. اطلب من الوكيل إعادة إنتاج المشكلة قبل تغيير الملفات. راجع مطابقة شرحه النهائي لمخرجات الاختبار المرصودة.

**تحتاج الأتمتة إلى حدود صريحة.** استخدم [أدلة استخدام CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli) الحالية لمعرفة الاستدعاء وخيارات التحكم. حدد الأدوات المسموحة والمهل ومعالجة المخرجات قبل تشغيل الأعمال غير المراقبة. لا تحول سياسة أذونات تفاعلية إلى تفويض شامل لخط أنابيب.

**يغير العزل حدود التجربة.** توثق GitHub العزل المحلي لقيود الملفات والشبكة والنظام، إضافة إلى بيئات سحابية للتنفيذ المعزول. لا يستبدل طلب الدليل الموثوق وعلم الموافقة تلك الحدود. اختبر العزل المقصود والوصول الشبكي ونطاق الكتابة بملف تجريبي غير ضار قبل السماح بتغيير مستودع حقيقي.

## ما يضيفه VS Code

**تضم تجربة Copilot في IDE الاقتراحات والدردشة والمهام الوكيلة.** يفصل [دليل IDE](https://docs.github.com/en/copilot/concepts/copilot-surfaces/copilot-in-ides) هذه الوظائف. تناسب المساعدة المضمنة العمل الذي تبقى فيه المحرر الرئيسي. يناسب وضع Agent نتيجة محددة تتطلب تغييرات عبر ملفات.

**يعدل وضع Agent الأوامر ويشغلها تكراريًا.** يصف [دليل وضع Agent](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/use-copilot-agents/use-agent-mode?tool=vscode) من GitHub اختيار Agent في الدردشة ومراجعة التغييرات وتوسيع الأدوات عبر MCP. يعتمد التوفر وسلوك الموافقة على الأوامر أيضًا على الإعدادات والإدارة.

**قيّم نقل السياق عمدًا.** حدد دالة واطلب شرح معالجة الخطأ فيها. ثم اطلب تغييرًا صغيرًا مع اختبار مستقل. سجل حاجتك إلى تقديم ملفات مجاورة أو تصحيح افتراض الوكيل حول الكود المحدد.

## وصل الواجهتين

```text
/ide
```

**استخدم `/ide` داخل جلسة Copilot CLI تفاعلية** لفحص اتصال VS Code أو تغييره. يوثق [دليل الاتصال](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/connecting-vs-code) مطابقة مساحة موثوقة ومشاركة تحديد المحرر وإظهار تعديلات الملفات المقترحة كفروق.

**يعتمد الاتصال التلقائي على تطابق مساحة العمل.** لا يتصل CLI المحلي بـ Codespace بعيد لمجرد تطابق اسم المستودع. شغل CLI في البيئة المقابلة. يتجاوز تفويض التعديل الواسع أيضًا تدفق الموافقة على الفرق المقترحة. افحص الأذونات إذا اختفت المطالبات المتوقعة.

**تظهر سجلات CLI عبر عرض Sessions في VS Code** مع الاستمرار عبر Resume in Terminal. يحافظ هذا على سير العمل الطرفي. لا تفترض أنه يحول المحادثة إلى جلسة وكيل أصلية قابلة للتبادل داخل المحرر.

| قبل الاتصال | تحقق |
|---|---|
| **مساحة العمل** | المجلد المقصود مفتوح وموثوق |
| **موقع التنفيذ** | يشير CLI وتكامل المحرر إلى البيئة نفسها |
| **التحديد** | يطابق الكود المحدد الطلب الحالي |
| **الأذونات** | تبقى مراجعة التعديل المقترح مفعلة عند الحاجة |
| **الجلسة** | تستمر في المحادثة المقصودة |

## النماذج والفوترة والسياسة

**استخدم النموذج المحدد نفسه لتجربة الواجهتين حين يتوفر.** إذا اختلفت الخيارات، سجل الفرق. يغير النموذج أو اختيار السياق أو مجموعة الأدوات التجربة بما يتجاوز الفرق بين الواجهة الرسومية والطرفية.

**تحقق من احتساب الاستخدام الحالي في حسابك.** تشير وثائق وضع Agent في GitHub إلى AI Credits. لا تطبق تقديرات الطلبات المميزة القديمة على حساب حالي قبل فحص ترتيب الفوترة. لا تعادل مطالبة CLI ومهمة المحرر تلقائيًا وحدة عمل واحدة.

**وصول المؤسسة متطلب سابق.** إذا غابت ميزة، افحص السياسة قبل إعادة تثبيت الإضافة. سجل الأدوات والتكاملات المعتمدة لكل واجهة. لا يمنح تسجيل الدخول إلى مزود صلاحية تعديل كل مستودع أو الاتصال بكل خدمة خارجية.

## نفذ تجربة مزدوجة

**جهز نسختين من المراجعة الابتدائية نفسها.** استخدم التعليمات واختبارات القبول نفسها. نفذ المحاولة الأولى في CLI المستقل والثانية في وضع Agent في VS Code. نفذ محاولة ثالثة باستخدام CLI المتصل فقط إذا ناسبتك المشاركة المختلطة.

| القياس | سبب التسجيل |
|---|---|
| **السياق المقدم** | يكشف جهد الإعداد اليدوي المخفي |
| **الصحة** | يميز الكود المعقول عن الإصلاح المتحقق |
| **خطوات الموافقة** | تظهر عبء الإشراف تحت السياسة نفسها |
| **وقت المراجعة** | يقيس جهد فهم التصحيح الكامل |
| **الإصلاحات اليدوية** | تسجل العمل المتبقي بعد انتهاء الوكيل |
| **الاستخدام** | يربط التكلفة بالنتائج المقبولة |

**أبق الاسترداد داخل الاختبار.** ارفض نهجًا مقترحًا واشرح السبب. راقب حفظ المحاولة التالية للعمل المفيد واحترام التصحيح. يكشف هذا عن سهولة الاستخدام اليومية أكثر من عرض واحد بلا انقطاع.

## استكشاف الأخطاء والخطوات التالية

**إذا اتصل CLI بنافذة المحرر الخطأ**، افحص `/ide` واختر مساحة العمل المقصودة. إذا توقفت الموافقة المرئية، افحص أذونات التعديل الواسعة. إذا غاب وضع Agent، افحص حالة الإضافة وسياسة المؤسسة.

**اختر CLI المستقل** عندما يهيمن سياق الصدفة والاستدعاء القابل للتكرار. **اختر VS Code** عندما يهيمن السياق القائم على التحديد والعمل المضمن والمراجعة الرسومية. **استخدم CLI المتصل** عندما يتكامل إدخال المهمة الطرفية وفحص المحرر جيدًا.
