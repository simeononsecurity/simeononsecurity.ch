## よくある質問

### Rayhunter の使用に有効な SIM カードが必要ですか?

デバイスに SIM カードを挿入する必要がありますが、**Rayhunter** の実行に有効な通信プランは必要ありません。SIM カードは携帯ネットワークへの接続と疑わしい活動の監視に使われます。**Rayhunter** の実行中にデバイスをホットスポットとして使うには、有効なプランが必要です。

### Rayhunter デバイスの動作を確認するには?

**Rayhunter** の設定で Test Heuristic を有効にします。デバイスが携帯基地局を検出するたびに警告が表示されるため、システムの動作を確認できます。このテストモードでは警告が大量に出るので、確認後は無効にしてください。

### ロック済みと SIM フリーのどちらを選ぶべきですか?

**Rayhunter** との互換性を考えると、特に Verizon 以外の SIM カードを使う予定なら、SIM フリーのデバイスが一般に適しています。Verizon ブランドの Orbic デバイスの大半は実際には SIM フリーですが、購入前に互換性を確認してください。STS Collective では、互換性を確認済みの **[Rayhunter 対応機器を購入](https://stscollective.com/collections/rayhunter)** できます。

## インストールガイド

### 最新リリースをインストールする

**Rayhunter** のインストールは macOS と Ubuntu 24.04 でテスト済みです。ビルド済みリリースで問題が起きた場合は、ソースからインストールする必要があります。

#### 前提条件

**Rayhunter** をインストールする前に、対応デバイスを用意してください。TP-Link デバイスでは、録画を保存するために FAT 形式の SD カードを挿入します。

#### ダウンロードとセットアップ

1. **最新リリースをダウンロードする:** 公式リリースページから、使用環境に合った `rayhunter-vX.X.X-PLATFORM.zip` を入手します。
   - Linux x64: `linux-x64`
   - Linux ARM64: `linux-aarch64`
   - Linux ARM v7/v8: `linux-armv7`
   - macOS Intel: `macos-intel`
   - macOS ARM (M1/M2): `macos-arm`
   - Windows: `windows-x86_64`

2. **アーカイブを展開してフォルダーを開く:**
   ```bash
   unzip ~/Downloads/rayhunter-vX.X.X-PLATFORM.zip
   cd ~/Downloads/rayhunter-vX.X.X-PLATFORM
   ```

3. **デバイスに接続する:** デバイスの電源を入れ、WiFi または USB テザリングで接続します。次のアドレスにアクセスできるはずです。
   - Orbic デバイス: `http://192.168.1.1`
   - TP-Link デバイス: `http://192.168.0.1`

#### デバイス別のインストール

**Orbic RC400L デバイスの場合** (**[Rayhunter 対応機器として販売](https://stscollective.com)**):

Orbic RC400L に **Rayhunter** をインストールする方法は 2 つあります。ほとんどの利用者には WiFi 方式を推奨します。USB 方式では追加のデバッグ機能を使えます。

**WiFi インストール方式 (推奨):**
```bash
# macOS の利用者は、最初にこのコマンドを実行します。
xattr -d com.apple.quarantine installer

# Verizon RC400L の場合 (管理者パスワードは WiFi パスワードと同じ):
./installer orbic --admin-password 'YourWiFiPassword'

# Kajeet/Smartspot RC400L の場合:
./installer orbic --admin-password='$m@rt$p0tc0nf!g'

# Moxee デバイスの場合 (パスワード形式: 12$ + WiFi パスワードの末尾 3 桁):
./installer orbic --admin-password='12$XXX'
```

**USB インストール方式 (上級利用者向け):**
USB 方式では高度なデバッグ用に ADB (Android Debug Bridge) を使えますが、通常のインストールには推奨しません。

```bash
# 警告: USB インストーラーはほとんどの用途で推奨しません
./installer orbic-usb
```

この方式はデバイスを強制的にデバッグモードにして ADB を有効にし、rootshell と **Rayhunter** をインストールした後、デバイスを再起動します。他の作業で ADB が必要な場合だけ使用してください。

**TP-Link M7350 デバイスの場合** (**[Rayhunter 対応機器として販売](https://stscollective.com)**):
```bash
./installer tplink
```

インストーラーが **Rayhunter** のフラッシュを完了し、デバイスを再起動します。画面に緑色の線が表示されれば、**Rayhunter** は正常に動作しています。

### ソースからインストールする

ソースから **Rayhunter** をビルドする開発者や利用者向けに、プロジェクトには次のコンポーネントがあります。

- **フロントエンド:** JavaScript の SvelteKit アプリケーション (`./daemon/web/`)
- **サーバー:** Rust バイナリー `rayhunter-daemon` (`./daemon/`)
- **インストーラー:** すべてのコンポーネントをまとめた Rust バイナリー (`./installer`)

#### ビルドの依存関係

次の依存関係をインストールします。
- Rust プログラミング言語
- Node.js/npm
- C ビルドツール (Linux では `build-essential`、macOS では `xcode-select --install`)

#### ビルド手順

```bash
./scripts/build-dev.sh
./scripts/install-dev.sh orbic  # 'orbic' をデバイスの種類に置き換えます
```

自動再読み込みを使ったフロントエンド開発:
```bash
cd daemon/web
npm run dev
# または、独自の接続先を指定します。
API_TARGET=http://192.168.1.1:8080 npm run dev
```

### Rayhunter を更新する

**Rayhunter** の更新手順はインストールと同じです。デバイスを最新の **Rayhunter** に更新するには、最新リリースでインストール手順を繰り返します。

## 設定

デバイスの Web インターフェース、またはデバイス上の `/data/rayhunter/config.toml` を直接編集して **Rayhunter** を設定できます。

### Web インターフェースの設定

**Rayhunter** の Web インターフェースを開くには、デバイスのネットワークに接続して次のアドレスにアクセスします。
- Orbic: `http://192.168.1.1:8080`
- TP-Link: `http://192.168.0.1:8080`

#### 主な設定項目

**デバイス UI レベル:** デバイス画面に表示する **Rayhunter** の内容を制御します。
- **不可視モード:** 画面に何も表示しない
- **控えめモード:** 色付きの線で状態を示す (緑=安全、赤=警告、白=一時停止)
- **デモモード:** シャチのグラフィックと状態表示を出す
- **EFF ロゴ:** 状態表示と EFF ロゴを出す
- **高視認性:** 全画面をカラー表示する

**デバイス入力モード:** 電源ボタンの動作を設定します。
- **ボタン操作を無効化:** **Rayhunter** の電源ボタン操作を無効にする
- **ダブルタップで録画を再開:** 警告をリセットし、監視を再開する

**通知設定:** リモート警告用の ntfy URL を設定し、警告やバッテリー低下の通知を有効または無効にします。

**アナライザーのヒューリスティック:** 環境や脅威モデルに応じて、**Rayhunter** の検出アルゴリズムを有効または無効にします。

## Rayhunter をアンインストールする

### Orbic デバイス

Orbic デバイスから **Rayhunter** を削除するには:

```bash
./installer util orbic-shell --admin-password mypassword
```

デバイスのシェル内で実行します。

> **警告:** 次のコマンドは Rayhunter のファイルと起動スクリプトを完全に削除します。対象のデバイスのシェルであることを確認し、必要な録画や設定をコピーしてください。続行する前にインストーラーと対応ファームウェアも用意します。実行後、ファイルが消え、Rayhunter サービスなしでデバイスが再起動することを確認してください。元に戻すには、公式リポジトリから同じリリースを再インストールします。

```bash
echo 3 > /usrdata/mode.cfg
rm -rf /data/rayhunter /etc/init.d/rayhunter_daemon /bin/rootshell
reboot
```

### TP-Link デバイス

TP-Link デバイスからアンインストールするには:

> **警告:** 次のコマンドは TP-Link デバイスから Rayhunter のファイルと起動スクリプトを削除します。先に録画と設定をエクスポートしてください。デバイスのシェル内でのみ実行し、終了後はパスが消え、デバイスが通常どおり起動することを確認します。元に戻すには、公式リポジトリから同じリリースを再インストールします。

```bash
./installer util tplink-shell
rm /data/rayhunter /etc/init.d/rayhunter_daemon
update-rc.d rayhunter_daemon remove
```

TP-Link 管理画面の Settings > NAT Settings > Port Triggers に残っているポートトリガーも削除します。

## Rayhunter を使う

インストール後、**Rayhunter** は自動的に起動し、疑わしい活動がないか携帯ネットワークを常時監視します。通常動作中は画面に緑色の線が表示されます。IMSI キャッチャーの可能性が検出されると、黄色の点、オレンジ色のダッシュ、または赤い実線に変わります。

### Rayhunter の検出ヒューリスティック

**Rayhunter** は、IMSI キャッチャーの活動の可能性を特定するため、複数の高度な検出アルゴリズムを使用します。

#### IMSI 要求の検出
このヒューリスティックは、携帯基地局が適切な認証手順を踏まずにデバイスの識別情報 (IMSI: International Mobile Subscriber Identity) を要求する疑わしい流れを特定します。**Rayhunter** は要求のタイミングと状況を監視し、監視機器の存在を示す異常なパターンに警告を出します。

正規の携帯ネットワークは、機密性の高い識別子を要求する前に標準化された認証手順を実行します。IMSI キャッチャーはデバイスの識別情報をすばやく収集するためにこの手順を回避し、認証の流れに検出可能な異常を生じさせることがあります。この検出方法は、デバイス情報を集めるだけの基本的な「受動型」IMSI キャッチャーに特に有効です。

#### 接続解除と 2G へのダウングレード検出
**Rayhunter** は、安全な 4G/5G ネットワークからモバイルデバイスを切断し、安全性の低い 2G ネットワークに再接続させようとする疑わしい動きを継続的に監視します。2G は暗号化が弱く傍受しやすいため、IMSI キャッチャーがよく使うダウングレード攻撃です。

システムは接続解除のパターンを分析し、通常のネットワーク最適化ではなく悪意を示す異常な頻度、タイミング、状況を探します。正規のネットワークでもカバレッジや容量の問題でダウングレードを提案する場合がありますが、**Rayhunter** は通常のネットワーク挙動と監視活動の可能性を区別できます。

#### LTE SIB6/7 ダウングレード検出
System Information Block (SIB) は、携帯ネットワークがモバイルデバイスに設定情報を伝えるために送信するメッセージです。**Rayhunter** は、隣接セルや周波数の切り替え情報を含む SIB6 および SIB7 メッセージを特に監視します。

悪意のある攻撃者は偽の SIB6/7 メッセージを送信し、デバイスに安全な 4G 接続を放棄させ、攻撃者が制御する 2G ネットワークへ接続させる場合があります。**Rayhunter** はこれらの送信に不整合や異常なリダイレクトがないか調べ、傍受のために接続をダウングレードしようとする不正基地局の兆候を分析します。

#### 暗号化なしの検出
この重要な検出方法は、携帯ネットワークが通信に暗号化を使わない状態 (null cipher) を提案しているかを特定します。正規の商用携帯ネットワークが暗号化なしの接続を提案することは、セキュリティ基準や規制要件に反するため、あってはなりません。

**Rayhunter** は暗号化なしを提案するネットワークを極めて疑わしいものとして警告します。*正規のネットワークは暗号化なしを提案しません。* これは監視機器が通信を平文で傍受しようとしている明確な兆候です。正規ネットワークを装うよりデータ収集を優先する IMSI キャッチャーに特に有効です。

#### 不完全な SIB の検出
正規の携帯基地局は、ネットワーク設定に必要なデータを含む完全な System Information Block を送信します。**Rayhunter** はシステム情報が不完全または欠落した基地局を監視します。これは急いで設置された監視機器や、不適切な設定を示す場合があります。

IMSI キャッチャーは携帯ネットワークの全機能を実装せず、デバイスの接続とデータ傍受に必要な最低限の機能だけに絞ることがあります。こうした不完全な実装を検出することで、**Rayhunter** は正規の携帯インフラに期待される機能を欠く、悪意のある可能性がある基地局を特定します。

## 5G 時代の Rayhunter の有効性

{{< figure src="rayhunter-5g-downgrade-attack-persistence.webp" alt="5G 対応スマートフォンがダウングレード攻撃で監視対象の 4G または 3G ネットワークに強制接続される図。Rayhunter は 5G 時代にもこの手法を検出する" >}}

携帯ネットワークが 5G に移行するにつれ、2G、3G、4G/LTE の検出には対応していても、5G 固有の監視方法には対応しない **Rayhunter** の有効性が問われています。5G 時代の **Rayhunter** の限界と継続的な有用性を理解することは、長期的な監視検出戦略の計画に欠かせません。

### 5G ネットワークでも Rayhunter が有効な理由

#### ダウングレード攻撃が続いている
デバイスを安全性の低いネットワークに接続させるという、**Rayhunter** が検出する基本的な攻撃経路は、5G の導入後も重要です。**IMSI キャッチャーは 2G と 3G へのダウングレード攻撃を続けています**。その理由は次のとおりです。

- **導入コストが低い:** 旧式プロトコル向けの監視機器は、5G 対応システムの開発より大幅に低コストで作れます
- **幅広いデバイスに対応:** 2G/3G を対象にすれば、5G 非対応の古いデバイスも監視できます
- **攻撃手法が確立されている:** 2G/3G ネットワークの監視手法は十分に文書化され、テストされています
- **規制上の利点:** 高度な 5G 傍受方法より、一部の旧式監視技術に対する法的制限が少ない場合があります

#### ネットワークの後方互換性
5G ネットワークは**4G/LTE との後方互換性**を保っており、大半のモバイルデバイスは複数世代のネットワークに同時対応します。この互換性により、**Rayhunter** が検出を専門とするダウングレード攻撃の機会が続きます。

- **自動的に旧世代へ切り替わる:** 5G のカバレッジが弱いとデバイスは自然に 4G に戻り、監視機器がその切り替えを傍受する機会が生まれます
- **プロトコル交渉の脆弱性:** 世代の異なるネットワーク間のハンドシェイクを、高度な IMSI キャッチャーが操作することがあります
- **カバレッジの隙を利用する:** 5G が十分に届かない地域に配置された監視機器は、デバイスを監視対象の 4G/LTE に強制接続できます

#### 5G 展開は段階的に進む
**5G 全域カバレッジの展開が遅い**ため、**Rayhunter** は今後数年間も有用であり続けます。

- **都市部と地方の格差:** 多くの地域では依然として主に 4G/LTE が使われ、**Rayhunter** の検出機能をそのまま適用できます
- **屋内カバレッジの制約:** 5G 信号は建物内に届きにくく、デバイスは 4G に戻ることがあります。**Rayhunter** はそのネットワークを効果的に監視できます
- **海外旅行時の考慮事項:** 5G の世界的な展開状況は国によって大きく異なるため、旅行中の 4G/LTE 監視は引き続き懸念事項です

#### 脅威アクターの技術導入の遅れ
**監視機器の調達と配備の周期**は、商用ネットワーク技術より遅れることがあります。

- **政府調達の期間:** 5G 展開後も法執行機関や情報機関が既存の 4G 対応監視機器を数年間使い続ける場合があります
- **費用対効果の分析:** 低コストの 4G/LTE 傍受で目的を達成できる監視活動は多く、5G 対応への更新を急ぐ理由が少なくなります
- **訓練と専門知識の要件:** 5G 監視機器の運用には専門知識が必要で、組織内で習得するまでに時間がかかる場合があります

### 実際の 5G 環境における Rayhunter の限界

#### 5G 固有の監視には死角がある
*これが Rayhunter の主な限界です。* **ダウングレード攻撃に頼らない 5G 固有の IMSI キャッチャー活動を Rayhunter は検出できません。**

- **5G スタンドアロン (SA) ネットワーク:** 4G に戻らず純粋な 5G に接続した場合、**Rayhunter** は通信を監視できません
- **高度な 5G 監視機器:** 高度な技術を持つ脅威アクターは、**Rayhunter** の検出ヒューリスティックを作動させずに 5G 通信を傍受する可能性があります
- **ネットワークスライシングの悪用:** 5G のネットワークスライシングを監視に悪用されても、**Rayhunter** では検出できない可能性があります

#### 5G のセキュリティ機能の強化
5G ネットワークには**改善されたセキュリティ対策**が導入され、従来の監視手法の有効性が下がる可能性があります。

- **強固な暗号化プロトコル:** 5G は以前の世代より強固で解読しにくい暗号化標準を実装しています
- **認証手順の強化:** 5G ネットワークの認証改善により IMSI の収集が難しくなる可能性があります
- **ネットワークセキュリティの監視:** 5G インフラには侵入検知機能の改善が含まれ、監視を検出して対抗できる場合があります

#### デバイスの挙動の変化
5G が普及すると、**モバイルデバイスの挙動が変わり**、**Rayhunter** の検出機能に影響する可能性があります。

- **ダウングレードへの抵抗:** 5G カバレッジが改善すれば、今後のデバイスソフトウェアはダウングレード攻撃に強くなる可能性があります
- **5G 接続の優先:** デバイスは 5G をさらに優先し、旧式プロトコルを使う要求を疑うようになる場合があります
- **セキュリティ意識の向上:** モバイル OS に疑わしいネットワーク挙動の検出機能が追加される可能性があります

### Rayhunter の展開に関する戦略的な考慮事項

#### 現在の展開に関する推奨事項
直ちに導入する場合や近い将来の利用において、**Rayhunter** は**幅広い監視検出機能**を提供します。

- **都市部での導入:** 5G カバレッジが広い大都市でも、**Rayhunter** は 4G/LTE を狙う監視を検出します
- **重要なイベントの保護:** デモ、機微な会議、高リスクの活動では、5G の有無にかかわらず **Rayhunter** が重要な検出機能を提供します
- **旅行時の安全:** 国内外の旅行中の監視検出にも **Rayhunter** は引き続き有効です
#### 将来に備える戦略
長期的な監視検出を計画する組織や個人は、次の点を検討してください。

- **複合的な検出方法:** **Rayhunter** を他のセキュリティツールや監視技術と組み合わせ、複数の脅威経路を幅広くカバーします
- **脅威評価を定期的に更新する:** 監視技術の変化を追跡し、**Rayhunter** の機能を補強または置き換える時期を判断します
- **コミュニティの開発を支援する:** **Rayhunter** のオープンソース開発を支援すると、今後のリリースに 5G 検出機能が加わる可能性が高まります

#### 技術の進化を監視する
**Rayhunter** のコミュニティと EFF は、**5G 監視の検出機能**に関する研究を続けています。

- **プロトコル分析の研究:** 5G プロトコルの継続的な研究により、今後の **Rayhunter** に新しい検出方法が見つかる可能性があります
- **ハードウェア互換性の調査:** 現行の **Rayhunter** 対応デバイスを改良し、5G 監視を検出できるか評価します
- **脅威の状況を監視する:** 5G 対応監視機器の開発と配備を追跡し、今後の **Rayhunter** 開発の優先事項を判断します

現在の通信環境において、**Rayhunter** は**監視検出に不可欠なツール**です。5G の展開は段階的に進み、脅威アクターは実績のあるダウングレード攻撃に頼り続けるため、今後数年間も有用であり続けるでしょう。

### 録画を再分析する

**Rayhunter** API は `http://[device-ip]:8080/api/` から利用でき、次のエンドポイントがあります。

- **ネットワーク監視:** 携帯ネットワークのリアルタイムデータにアクセス
- **イベントログ:** 過去の検出イベントや警告を検索

## よくある質問 (FAQ)

### 一般的な質問

#### IMSI キャッチャーとは何ですか? どのように動作しますか?
IMSI キャッチャー (StingRay、携帯基地局シミュレーター、偽基地局とも呼ばれる) は、正規の携帯基地局を装ってモバイルデバイスの通信を傍受する監視機器です。周辺のデバイスを正規の基地局ではなく悪意のある機器に接続させ、運用者がデバイス識別子 (IMSI 番号)、位置情報、通話メタデータを収集したり、通信を傍受したりできるようにします。**Rayhunter** は携帯ネットワーク挙動の異常なパターンを特定して検出します。

#### Rayhunter はあらゆる監視機器を検出できますか?
**Rayhunter** は、2G、3G、4G/LTE ネットワークで動作する IMSI キャッチャーと携帯基地局シミュレーターを特に検出します。WiFi 監視、GPS 追跡機器、物理的監視、ダウングレード攻撃を使わない 5G 固有の監視は検出できません。**Rayhunter** は包括的なプライバシー保護戦略の一部です。

#### Rayhunter の使用は合法ですか?
ほとんどの地域で **Rayhunter** の使用は完全に合法です。携帯ネットワークや他のデバイスに干渉しない受動監視ツールだからです。デバイスが自然に受信する携帯信号だけを分析します。ただし地域の法律は異なるため、使用者は各地域の規制に適合するか確認してください。EFF は正当なプライバシー保護ツールとして **Rayhunter** を開発しました。

### 技術的な質問

#### 有効な通信プランが不要なのに、Rayhunter に SIM カードが必要なのはなぜですか?
SIM カードには International Mobile Subscriber Identity (IMSI) があり、デバイスが携帯ネットワークで認証を受け、**Rayhunter** が監視する携帯プロトコルのやり取りに参加するために必要です。SIM カードがなければデバイスは携帯ネットワークに接続できず、**Rayhunter** が疑わしいパターンを分析するためのネットワーク活動もありません。

#### 通常の動作中に Rayhunter はどのくらいデータを使いますか?
**Rayhunter** は主にインターネット通信ではなく携帯プロトコル情報を分析するため、基本的な監視ではデータ使用量がごくわずかです。ただし、ntfy のリモート通知を有効にした場合や、同時にホットスポットとして使う場合はデータ使用量が増えます。監視自体が使う帯域幅はごく小さいものです。

#### デバイスをモバイルホットスポットとして使いながら Rayhunter を実行できますか?
はい、デバイスをモバイルホットスポットとして使いながら **Rayhunter** を実行できます。アクティブな携帯通信プランが必要です。**Rayhunter** の監視はホットスポット機能とは独立していますが、両方を同時に使うとバッテリーの消費が増えます。

#### WiFi 方式と USB 方式の違いは何ですか?
ほとんどの利用者に推奨する **WiFi 方式**では、デバイスの無線インターフェースから **Rayhunter** をインストールし、標準的な機能を使えます。**USB 方式**はデバッグ機能が必要な上級利用者向けに Android Debug Bridge (ADB) を有効にしますが、手順が複雑で通常のインストールには不要です。

### デバイスと互換性に関する質問

#### Rayhunter が一部のデバイスだけに対応するのはなぜですか?
**Rayhunter** には `/dev/diag` インターフェースを公開する Qualcomm モデムが必要です。このインターフェースから携帯プロトコル情報にアクセスします。セキュリティ上の理由から、一般消費者向けデバイスの多くはこのインターフェースを公開しません。対応デバイスはテストされ、**Rayhunter** の要件を満たすことが確認されています。

#### 一般的なスマートフォンに Rayhunter をインストールできますか?
いいえ、一般的なスマートフォンには **Rayhunter** をインストールできません。診断インターフェースを公開する特定の Qualcomm モデムを搭載した専用モバイルホットスポットが必要です。対応デバイスには Orbic RC400L、TP-Link M7350、その他のモバイルホットスポットモデルがあります。

#### 非対応デバイスに Rayhunter をインストールしようとするとどうなりますか?
**Rayhunter** インストーラーにはデバイス検出機能があり、互換性のないハードウェアには通常インストールを拒否します。非対応デバイスに強制インストールすると、デバイスが損傷したり、動作しなくなったりする可能性があります。インストール前に必ず互換性を確認してください。

#### 地域ごとに異なるデバイスが必要ですか?
はい、携帯の周波数帯は地域によって異なります。Orbic RC400L はアメリカ大陸のネットワークに最適化され、TP-Link M7350 はヨーロッパ、アフリカ、中東でよく動作します。**Rayhunter** の対応情報には、利用地域で最適に動作するよう地域ごとの推奨事項が含まれています。

### 使用方法と設定に関する質問

#### Rayhunter デバイスが正常に動作しているか確認するには?
**Rayhunter** の設定で Test Heuristic を有効にします。デバイスが基地局を検出するたびに警告が出て、システムが動作していることを確認できます。通常の動作中は画面に緑色の線が表示されます。大量の警告が出るため、確認後はテストヒューリスティックを無効にしてください。

#### Rayhunter が警告を出したらどうすればよいですか?
**Rayhunter** が疑わしい活動を検出したら、まず場所と状況を記録します。ネットワーク最適化や機器の問題で誤検知が起きる場合があります。同じ場所や機微な活動中に警告が続く場合は、場所の変更を検討し、Web インターフェースで警告の詳細を見て何が検出されたか確認してください。

#### Rayhunter はどのくらいの頻度で更新すべきですか?
**毎月更新してください。** 新しいヒューリスティックや互換性改善は頻繁に追加されるため、リリースページを確認します。EFF は変化する監視手法に基づき、**Rayhunter** の機能を継続的に改善しています。更新手順は初回インストールと同じです。

#### Rayhunter は複数の人を同時に保護できますか?
**Rayhunter** は周辺の IMSI キャッチャーを検出するため、電波の強さによりますが、通常は数百メートル以内の複数人を保護できる可能性があります。ただし、監視検出を重視する人は、最大限の保護と設定管理のために各自の **Rayhunter** デバイスを持つことを検討してください。

### セキュリティとプライバシーに関する質問

#### Rayhunter を使うと監視の対象として目立ちますか?
**Rayhunter** は受動的に動作し、監視機器に識別される信号を発信しません。ただし、セキュリティツールの使用はプライバシー意識を示します。特にジャーナリストや活動家のような高リスクの人々にとって、検出の利点は通常リスクを上回ります。

#### 監視機器は Rayhunter の使用を検出できますか?
**Rayhunter** は識別信号を送信しない受動監視システムです。携帯プロトコルのレベルで監視運用者が **Rayhunter** の使用を検出することはできません。リモート通知を有効にしていると、デバイスの物理的な観察やネットワーク通信の分析で **Rayhunter** の使用が分かる可能性はあります。

#### Rayhunter はどのような情報を収集しますか?
**Rayhunter** は携帯プロトコル情報を分析し、検出警告をデバイス内に保存します。検出アルゴリズムに必要な範囲を超えて、個人情報、通信内容、位置情報を収集しません。リモート通知を有効にしない限り、すべてのデータはデバイス内に残ります。

### 応用的な質問

#### Rayhunter のデータをコンピューターで分析できますか?
はい、**Rayhunter** には録画済み PCAP と QMDL ファイルをデスクトップで分析する `rayhunter-check` コマンドラインツールがあります。上級利用者はコンピューターの全リソースを使い、検出イベントを詳しく分析したり、疑わしい活動を調査したりできます。

#### 人口密度の高い都市部で Rayhunter はどのように動作しますか?
人口密度の高い都市部では正規の基地局が多く、ネットワーク最適化や基地局の切り替えも頻繁なため、誤検知が増える可能性があります。**Rayhunter** のアルゴリズムは通常のネットワーク挙動と監視活動を区別するよう設計されていますが、密集地域では感度設定の調整が必要な場合があります。

#### 海外旅行中も Rayhunter は動作しますか?
旅行中の **Rayhunter** の有効性は、現地の携帯周波数帯やローミング契約に対するデバイスの互換性に左右されます。検出アルゴリズムは世界中で動作しますが、渡航先で使われる周波数帯にデバイスが対応していることを確認してください。すべての機能を使うには国際ローミングが必要な場合があります。
