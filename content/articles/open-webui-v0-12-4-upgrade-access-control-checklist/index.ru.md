**Open WebUI v0.12.4 содержит исправления безопасности, которые сопровождающие проекта пока не перечислили.** В примечаниях к выпуску рекомендуется своевременно обновлять установки и говорится, что бюллетени появятся после присвоения CVE. Перечисленные ниже изменения совместного доступа к чатам и разрешений видны в примечаниях к выпуску, но не составляют полный список нераскрытых исправлений безопасности. [Примечания к выпуску Open WebUI v0.12.4](https://github.com/open-webui/open-webui/releases/tag/v0.12.4)

<!--more-->

## Краткие выводы

- **Сначала создайте резервную копию.** До изменения приложения сохраните копию тома данных или базы данных и загруженных файлов, которую можно восстановить.
- **Зафиксируйте официальный выпуск.** Для стандартного образа Docker используйте `ghcr.io/open-webui/open-webui:v0.12.4`, а для pip используйте `open-webui==0.12.4`.
- **Проверяйте разрешения с реальными ролями пользователей.** Скрытая кнопка не доказывает, что API проверяет полномочия.
- **Сохраните приватный доступ.** Требуйте аутентификацию приложения и ограничьте сетевой доступ через VPN или аутентифицированный обратный прокси.

## Перед обновлением

**Предварительные условия:** определите текущий способ установки, вариант образа контейнера, расположение постоянных данных, внешнюю базу данных, обратный прокси и поставщика аутентификации. Запланируйте окно простоя и сохраните действующую конфигурацию контейнера или описание службы. Выделите время на проверку восстановления на отдельном экземпляре. Приведенные команды представляют собой документированные поставщиком шаблоны, адаптированные для этой закрепленной версии. Это не результат реального обновления, проведенного для данного руководства. [Обновление Open WebUI](https://docs.openwebui.com/getting-started/updating/)

1. **Проведите инвентаризацию хранилища.** В стандартной конфигурации Docker `open-webui` монтируется в `/app/backend/data`. Запишите bind-монтирования, внешнюю базу данных, объектное хранилище и пользовательские переменные окружения. При использовании pip до изменения среды найдите активный каталог данных приложения и базу данных. Не считайте экспорт чатов полной резервной копией.
2. **Создайте резервную копию при остановленной записи.** Остановите приложение или используйте согласованный снимок базы данных, затем скопируйте том, внешние базы данных и загруженные файлы в отдельное хранилище. Поставщик описывает архивирование тома Docker. Адаптируйте имя тома и путь резервной копии к своей установке. Убедитесь, что архив открывается, и проверьте восстановление на отдельном экземпляре, прежде чем полагаться на него. [Резервное копирование и восстановление](https://docs.openwebui.com/getting-started/updating/#backup--restore)
3. **Прочитайте примечания к выпуску и руководство по миграции.** В примечаниях к v0.12.4 не перечислены ожидающие исправления безопасности и не указан диапазон затронутых версий. Не присваивайте этим исправлениям CVE и не считайте, что каждая версия до v0.12.4 уязвима к одной конкретной проблеме. Руководство по обновлению предупреждает об однонаправленных миграциях базы данных и репликах с разными версиями. Если несколько рабочих процессов или реплик используют общую базу данных, остановите их одновременно и следуйте [процедуре миграции нескольких реплик](https://docs.openwebui.com/troubleshooting/multi-replica/#updates-and-migrations). Для отката может потребоваться резервная копия базы данных, созданная до обновления.

## Обновите установленный пакет

**Docker, процедура поставщика с закрепленным тегом:** после резервного копирования загрузите официальный стандартный образ и пересоздайте контейнер с тем же постоянным томом, конфигурацией и `WEBUI_SECRET_KEY`. В примере предполагаются том с именем по умолчанию и локально привязанный upstream прокси. Не вставляйте настоящий ключ в историю оболочки. Передайте его через существующий защищенный механизм переменных окружения или систему управления секретами. Сохраните параметры GPU, Ollama, пользовательской сети, базы данных и остальные параметры текущей установки. [Обновление Open WebUI](https://docs.openwebui.com/getting-started/updating/) · [Официальные теги образов](https://docs.openwebui.com/getting-started/quick-start/)

```bash
docker pull ghcr.io/open-webui/open-webui:v0.12.4
docker rm -f open-webui
docker run -d --name open-webui --restart always \
  -p 127.0.0.1:3000:8080 \
  -v open-webui:/app/backend/data \
  --env-file ./open-webui.env \
  ghcr.io/open-webui/open-webui:v0.12.4
```

**Перед запуском проверьте `./open-webui.env`:** файл уже должен существовать, иметь ограниченные права доступа и содержать действующий `WEBUI_SECRET_KEY` и необходимые параметры. Привязка к loopback подходит для прокси на том же хосте, но не для прокси на другом компьютере. При использовании Compose замените только образ службы на закрепленный тег, затем выполните `docker compose pull open-webui` и `docker compose up -d open-webui` в существующем проекте. Сохраните тот же том и настройки окружения. Это рекомендуемые команды, а не проверенная миграция вашей установки.

**pip, процедура поставщика для фиксированной версии:** в существующем виртуальном окружении остановите службу, установите точную версию пакета и запустите ее с тем же каталогом данных и окружением. Не создавайте второе окружение Python или новую пустую базу данных. В общей инструкции поставщика используется `pip install -U open-webui`. Ограничение ниже фиксирует эту контрольную проверку на v0.12.4. [Обновление Open WebUI](https://docs.openwebui.com/getting-started/updating/) · [Быстрый запуск](https://docs.openwebui.com/getting-started/quick-start/)

```bash
python -m pip install --upgrade 'open-webui==0.12.4'
python -m pip show open-webui
```

**Проверьте работающую службу, а не только установленный пакет.** Посмотрите версию при запуске в `docker logs open-webui` или журналах службы pip и сравните ее с версией в приложении после входа. Руководство поставщика рекомендует проверить журналы контейнера и открыть страницу входа. Если интерфейс показывает устаревшие ресурсы, принудительно обновите страницу браузера. Если при запуске возникла ошибка миграции, оставьте службу недоступной до выяснения причины. Не устанавливайте старый бинарный файл поверх мигрированной базы данных, не проверив требования к восстановлению. [Проверки после обновления](https://docs.openwebui.com/getting-started/updating/)

## Проверьте доступ после перезапуска

**Поведение, описанное поставщиком:** v0.12.4 скрывает экспорт папок, экспорт архивных чатов и копирование чатов для пользователей без разрешения **Allow Chat Export**. Элементы управления доступом к моделям, промптам, инструментам, знаниям, навыкам, заметкам и папкам также скрываются от пользователей без соответствующего разрешения на совместный доступ. Просматривающие общую папку перестают получать обновления чата в реальном времени после его архивации владельцем. Просматривающие общую ссылку перестают получать такие обновления после того, как владелец отменяет общий доступ ко всем чатам. Скрытые элементы интерфейса относятся к поведению пользовательского интерфейса и не доказывают исправление на сервере неизвестной уязвимости. [Примечания к выпуску](https://github.com/open-webui/open-webui/releases/tag/v0.12.4)

**Рекомендуемая проверка оператором:** с тестовой учетной записью без разрешений на экспорт и общий доступ убедитесь, что перечисленные действия недоступны. Под учетной записью с нужными разрешениями проверьте, что необходимые действия работают. Создайте несекретный тестовый чат в общей папке, откройте его из другой учетной записи, заархивируйте от имени владельца и проверьте, что новые обновления больше не поступают смотрящему. Повторите проверку с общей ссылкой и действием **Unshare All Chats**. Повторно проверьте сохраненные разрешения и старые ссылки. Не считайте архивированный контент или исторические копии удаленными.

| Область проверки | Что проверить |
|---|---|
| **Роли и группы** | Удалите устаревших участников и назначения администраторов. Проверьте действующие права недавно одобренного и ограниченного пользователя. |
| **Модели и инструменты** | Проверьте разрешения для каждой модели, подключенные инструменты, права на создание инструментов и учетные данные поставщиков. Выполните проверку с учетной записью без прав администратора. |
| **Знания и файлы** | Проверьте участников базы знаний, разрешения ресурсов, вложения и параметры совместного доступа. Проверьте учетную запись, у которой отозвали доступ. |
| **Чаты и экспорт** | Проверьте общие папки, ссылки, архивные чаты и назначения Allow Chat Export. Отзовите ненужные ссылки. |

Эти проверки инвентаризации являются **рекомендациями оператору**, а не новыми гарантиями v0.12.4. [Руководство по усилению защиты](https://docs.openwebui.com/getting-started/advanced-topics/hardening/) описывает многоуровневые роли, группы, разрешения для каждого ресурса, права рабочего пространства, ключи API и размещение в сети.

## Устраните пробелы в защите учетных записей и сети

- **Регистрация, настройка поставщика:** отключите открытую регистрацию, если учетные записи создает администратор или поставщик удостоверений. Сверьте `ENABLE_SIGNUP` и сохраненные настройки администратора с [руководством по усилению защиты](https://docs.openwebui.com/getting-started/advanced-topics/hardening/). Ограничьте правила подтверждения новых учетных записей.
- **Ключи API, проверка оператором:** составьте список выданных ключей, удалите неиспользуемые и ограничьте создание ключей и доступ к конечным точкам нужными ролями и маршрутами. Согласно руководству поставщика, ключ действует с разрешениями его создателя. Не включайте ключи в примеры статьи и журналы приложения.
- **Администраторы, проверка оператором:** удалите заброшенные учетные записи администраторов, требуйте надежные проверки входа, проверьте доступность MFA и расследуйте неожиданные изменения учетных записей. Проверьте восстановление учетной записи перед отключением лишнего администратора.
- **Сетевая граница, рекомендации поставщика:** разместите службу за VPN, прокси доступа или обратным прокси с аутентификацией и списком разрешенных IP-адресов. Не открывайте ее в публичной сети без аутентификации. Не устанавливайте `WEBUI_AUTH=False` для доступной службы. Обратный прокси без собственной аутентификации сам по себе не заменяет вход в приложение. [Защита Open WebUI](https://docs.openwebui.com/getting-started/advanced-topics/hardening/)

**Область применения:** этот список относится к официальному выпуску Open WebUI и описанным стандартным вариантам установки. Он не проверяет форки, производные образы и сторонние пакеты. В примечаниях к v0.12.4 не заявлено об активной эксплуатации. Проверяйте [рекомендации по безопасности проекта](https://github.com/open-webui/open-webui/security/advisories), чтобы узнать о последующих раскрытиях и соответствующих затронутых и исправленных версиях. Не приписывайте v0.12.4 исправление из более раннего бюллетеня, не проверив его диапазон версий.
