**Open WebUI v0.12.4 ਵਿੱਚ ਸੁਰੱਖਿਆ ਸੰਬੰਧੀ ਸੁਧਾਰ ਹਨ ਜਿਨ੍ਹਾਂ ਦੀ ਦੇਖਭਾਲ ਕਰਨ ਵਾਲਿਆਂ ਨੇ ਹਾਲੇ ਪੂਰੀ ਸੂਚੀ ਨਹੀਂ ਦਿੱਤੀ।** ਰਿਲੀਜ਼ ਨੋਟ ਤੁਰੰਤ ਅੱਪਡੇਟ ਕਰਨ ਦੀ ਸਲਾਹ ਦਿੰਦੇ ਹਨ ਅਤੇ ਕਹਿੰਦੇ ਹਨ ਕਿ CVE ਮਿਲਣ ਤੋਂ ਬਾਅਦ ਸਲਾਹ ਜਾਰੀ ਹੋਵੇਗੀ। ਹੇਠਾਂ ਦੱਸੇ ਚੈਟ ਸਾਂਝੀਕਰਨ ਅਤੇ ਅਧਿਕਾਰਾਂ ਦੇ ਬਦਲਾਅ ਰਿਲੀਜ਼ ਨੋਟਾਂ ਵਿੱਚ ਦਿਖਦੇ ਬਿੰਦੂ ਹਨ, ਅਣਦੱਸੇ ਸੁਰੱਖਿਆ ਸੁਧਾਰਾਂ ਦੀ ਪੂਰੀ ਸੂਚੀ ਨਹੀਂ। [Open WebUI v0.12.4 ਰਿਲੀਜ਼ ਨੋਟ](https://github.com/open-webui/open-webui/releases/tag/v0.12.4)

<!--more-->

## ਮੁੱਖ ਗੱਲਾਂ

- **ਪਹਿਲਾਂ ਬੈਕਅੱਪ ਲਓ।** ਐਪਲੀਕੇਸ਼ਨ ਬਦਲਣ ਤੋਂ ਪਹਿਲਾਂ ਡਾਟਾ ਵਾਲਿਊਮ ਜਾਂ ਡਾਟਾਬੇਸ ਅਤੇ ਅੱਪਲੋਡਾਂ ਦੀ ਮੁੜ-ਪ੍ਰਾਪਤ ਕੀਤੀ ਜਾ ਸਕਣ ਵਾਲੀ ਨਕਲ ਰੱਖੋ।
- **ਅਧਿਕਾਰਤ ਰਿਲੀਜ਼ ਪਿੰਨ ਕਰੋ।** ਮਿਆਰੀ Docker ਇਮੇਜ ਲਈ `ghcr.io/open-webui/open-webui:v0.12.4` ਜਾਂ pip ਲਈ `open-webui==0.12.4` ਵਰਤੋ।
- **ਅਸਲ ਵਰਤੋਂਕਾਰ ਭੂਮਿਕਾਵਾਂ ਨਾਲ ਅਧਿਕਾਰ ਪਰਖੋ।** ਬਟਨ ਲੁਕਿਆ ਹੋਣਾ API ਵੱਲੋਂ ਅਧਿਕਾਰ ਜਾਂਚ ਦਾ ਸਬੂਤ ਨਹੀਂ।
- **ਪਹੁੰਚ ਨਿੱਜੀ ਰੱਖੋ।** ਐਪਲੀਕੇਸ਼ਨ ਪ੍ਰਮਾਣਿਕਤਾ ਲਾਜ਼ਮੀ ਕਰੋ ਅਤੇ VPN ਜਾਂ ਪ੍ਰਮਾਣਿਤ ਰਿਵਰਸ ਪ੍ਰੌਕਸੀ ਰਾਹੀਂ ਨੈੱਟਵਰਕ ਪਹੁੰਚ ਸੀਮਿਤ ਕਰੋ।

## ਅੱਪਗ੍ਰੇਡ ਤੋਂ ਪਹਿਲਾਂ

**ਲੋੜੀਂਦੀਆਂ ਤਿਆਰੀਆਂ:** ਮੌਜੂਦਾ ਇੰਸਟਾਲ ਤਰੀਕਾ, ਕੰਟੇਨਰ ਇਮੇਜ ਦੀ ਕਿਸਮ, ਸਥਾਈ ਡਾਟੇ ਦੀ ਥਾਂ, ਬਾਹਰੀ ਡਾਟਾਬੇਸ, ਰਿਵਰਸ ਪ੍ਰੌਕਸੀ ਅਤੇ ਪ੍ਰਮਾਣਿਕਤਾ ਪ੍ਰਦਾਤਾ ਦੀ ਪਛਾਣ ਕਰੋ। ਰੁਕਾਵਟ ਦਾ ਸਮਾਂ ਤੈਅ ਕਰੋ ਅਤੇ ਮੌਜੂਦਾ ਕੰਟੇਨਰ ਸੰਰਚਨਾ ਜਾਂ ਸੇਵਾ ਪਰਿਭਾਸ਼ਾ ਸੰਭਾਲੋ। ਵੱਖਰੇ ਇੰਸਟੈਂਸ ਉੱਤੇ ਮੁੜ-ਬਹਾਲੀ ਦੀ ਕਸਰਤ ਲਈ ਸਮਾਂ ਰੱਖੋ। ਹੇਠਾਂ ਦਿੱਤੀਆਂ ਕਮਾਂਡਾਂ ਪ੍ਰਦਾਤਾ ਵੱਲੋਂ ਦਸਤਾਵੇਜ਼ ਕੀਤੇ ਤਰੀਕਿਆਂ ਦੇ ਨਮੂਨੇ ਹਨ, ਜਿਨ੍ਹਾਂ ਨੂੰ ਇਸ ਪਿੰਨ ਕੀਤੇ ਵਰਜਨ ਅਨੁਸਾਰ ਢਾਲਿਆ ਗਿਆ ਹੈ। ਇਹ ਇਸ ਗਾਈਡ ਲਈ ਕੀਤੇ ਅਸਲ ਅੱਪਗ੍ਰੇਡ ਦਾ ਨਤੀਜਾ ਨਹੀਂ ਹਨ। [Open WebUI ਅੱਪਡੇਟ ਕਰੋ](https://docs.openwebui.com/getting-started/updating/)

1. **ਸਟੋਰੇਜ ਦੀ ਸੂਚੀ ਬਣਾਓ।** ਮਿਆਰੀ Docker ਸੈੱਟਅੱਪ ਵਿੱਚ `open-webui`, `/app/backend/data` ਉੱਤੇ ਮਾਊਂਟ ਹੁੰਦਾ ਹੈ। ਬਾਈਂਡ ਮਾਊਂਟ, ਬਾਹਰੀ ਡਾਟਾਬੇਸ, ਆਬਜੈਕਟ ਸਟੋਰੇਜ ਅਤੇ ਕਸਟਮ ਵਾਤਾਵਰਣੀ ਵੇਰੀਏਬਲ ਲਿਖੋ। pip ਲਈ ਵਾਤਾਵਰਣ ਬਦਲਣ ਤੋਂ ਪਹਿਲਾਂ ਸਰਗਰਮ ਐਪ ਡਾਟਾ ਡਾਇਰੈਕਟਰੀ ਅਤੇ ਡਾਟਾਬੇਸ ਲੱਭੋ। ਚੈਟ ਐਕਸਪੋਰਟ ਨੂੰ ਪੂਰਾ ਬੈਕਅੱਪ ਨਾ ਸਮਝੋ।
2. **ਲਿਖਤਾਂ ਰੁਕਣ ਤੋਂ ਬਾਅਦ ਬੈਕਅੱਪ ਲਓ।** ਐਪਲੀਕੇਸ਼ਨ ਰੋਕੋ ਜਾਂ ਡਾਟਾਬੇਸ ਦਾ ਸੰਗਤ ਸਨੈਪਸ਼ਾਟ ਲਓ, ਫਿਰ ਵਾਲਿਊਮ, ਕੋਈ ਵੀ ਬਾਹਰੀ ਡਾਟਾਬੇਸ ਅਤੇ ਅੱਪਲੋਡ ਵੱਖਰੀ ਸਟੋਰੇਜ ਵਿੱਚ ਕਾਪੀ ਕਰੋ। ਪ੍ਰਦਾਤਾ Docker ਵਾਲਿਊਮ ਦਾ ਆਰਕਾਈਵ ਬਣਾਉਣ ਦਾ ਤਰੀਕਾ ਦਿੰਦਾ ਹੈ। ਵਾਲਿਊਮ ਦਾ ਨਾਂ ਅਤੇ ਬੈਕਅੱਪ ਰਸਤਾ ਆਪਣੇ ਡਿਪਲੌਇਮੈਂਟ ਅਨੁਸਾਰ ਬਦਲੋ। ਯਕੀਨੀ ਬਣਾਓ ਕਿ ਆਰਕਾਈਵ ਖੁੱਲ੍ਹਦਾ ਹੈ ਅਤੇ ਭਰੋਸਾ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਵੱਖਰੇ ਇੰਸਟੈਂਸ ਉੱਤੇ ਮੁੜ-ਬਹਾਲੀ ਦੀ ਕਸਰਤ ਕਰੋ। [ਬੈਕਅੱਪ ਅਤੇ ਮੁੜ-ਬਹਾਲੀ](https://docs.openwebui.com/getting-started/updating/#backup--restore)
3. **ਰਿਲੀਜ਼ ਨੋਟ ਅਤੇ ਮਾਈਗ੍ਰੇਸ਼ਨ ਹਦਾਇਤਾਂ ਪੜ੍ਹੋ।** v0.12.4 ਦੇ ਨੋਟ ਉਡੀਕ ਰਹੇ ਸੁਰੱਖਿਆ ਸੁਧਾਰਾਂ ਦੀ ਸੂਚੀ ਜਾਂ ਪ੍ਰਭਾਵਿਤ ਵਰਜਨਾਂ ਦੀ ਹੱਦ ਨਹੀਂ ਦਿੰਦੇ। ਇਨ੍ਹਾਂ ਸੁਧਾਰਾਂ ਨੂੰ CVE ਨਾ ਦਿਓ ਅਤੇ ਨਾ ਮੰਨੋ ਕਿ v0.12.4 ਤੋਂ ਪਹਿਲਾਂ ਦਾ ਹਰ ਵਰਜਨ ਕਿਸੇ ਇੱਕ ਜਾਣੀ ਖਾਮੀ ਨਾਲ ਪ੍ਰਭਾਵਿਤ ਹੈ। ਅੱਪਡੇਟ ਗਾਈਡ ਇਕ-ਦਿਸ਼ੀ ਡਾਟਾਬੇਸ ਮਾਈਗ੍ਰੇਸ਼ਨ ਅਤੇ ਵੱਖਰੇ ਵਰਜਨਾਂ ਵਾਲੀਆਂ ਰੈਪਲਿਕਾਂ ਬਾਰੇ ਚੇਤਾਵਨੀ ਦਿੰਦੀ ਹੈ। ਜੇ ਕਈ ਵਰਕਰ ਜਾਂ ਰੈਪਲਿਕਾਂ ਇੱਕ ਡਾਟਾਬੇਸ ਸਾਂਝਾ ਕਰਦੀਆਂ ਹਨ, ਤਾਂ ਉਨ੍ਹਾਂ ਨੂੰ ਇਕੱਠੇ ਰੋਕੋ ਅਤੇ [ਕਈ ਰੈਪਲਿਕਾਂ ਲਈ ਮਾਈਗ੍ਰੇਸ਼ਨ ਤਰੀਕਾ](https://docs.openwebui.com/troubleshooting/multi-replica/#updates-and-migrations) ਅਪਣਾਓ। ਵਾਪਸੀ ਲਈ ਅੱਪਗ੍ਰੇਡ ਤੋਂ ਪਹਿਲਾਂ ਦਾ ਡਾਟਾਬੇਸ ਬੈਕਅੱਪ ਲੋੜੀਂਦਾ ਹੋ ਸਕਦਾ ਹੈ।

## ਇੰਸਟਾਲ ਕੀਤੇ ਪੈਕੇਜ ਨੂੰ ਅੱਪਡੇਟ ਕਰੋ

**Docker, ਪਿੰਨ ਕੀਤੇ ਟੈਗ ਲਈ ਢਾਲਿਆ ਪ੍ਰਦਾਤਾ ਤਰੀਕਾ:** ਬੈਕਅੱਪ ਤੋਂ ਬਾਅਦ ਅਧਿਕਾਰਤ ਮਿਆਰੀ ਇਮੇਜ ਖਿੱਚੋ ਅਤੇ ਉਸੇ ਸਥਾਈ ਵਾਲਿਊਮ, ਸੰਰਚਨਾ ਅਤੇ `WEBUI_SECRET_KEY` ਨਾਲ ਕੰਟੇਨਰ ਮੁੜ ਬਣਾਓ। ਇਹ ਉਦਾਹਰਨ ਮੂਲ ਨਾਂ ਵਾਲੇ ਵਾਲਿਊਮ ਅਤੇ ਉਸੇ ਮਸ਼ੀਨ ਨਾਲ ਜੁੜੇ ਪ੍ਰੌਕਸੀ ਅੱਪਸਟ੍ਰੀਮ ਨੂੰ ਮੰਨਦੀ ਹੈ। ਅਸਲੀ ਕੁੰਜੀ ਸ਼ੈੱਲ ਇਤਿਹਾਸ ਵਿੱਚ ਨਾ ਪਾਓ। ਇਸਨੂੰ ਮੌਜੂਦਾ ਸੁਰੱਖਿਅਤ ਵਾਤਾਵਰਣ ਜਾਂ ਸੀਕ੍ਰੇਟ ਪ੍ਰਬੰਧਨ ਤਰੀਕੇ ਰਾਹੀਂ ਦਿਓ। ਮੌਜੂਦਾ ਡਿਪਲੌਇਮੈਂਟ ਦੇ GPU, Ollama, ਕਸਟਮ ਨੈੱਟਵਰਕ, ਡਾਟਾਬੇਸ ਅਤੇ ਹੋਰ ਵਿਕਲਪ ਕਾਇਮ ਰੱਖੋ। [Open WebUI ਅੱਪਡੇਟ ਕਰੋ](https://docs.openwebui.com/getting-started/updating/) · [ਅਧਿਕਾਰਤ ਇਮੇਜ ਟੈਗ](https://docs.openwebui.com/getting-started/quick-start/)

```bash
docker pull ghcr.io/open-webui/open-webui:v0.12.4
docker rm -f open-webui
docker run -d --name open-webui --restart always \
  -p 127.0.0.1:3000:8080 \
  -v open-webui:/app/backend/data \
  --env-file ./open-webui.env \
  ghcr.io/open-webui/open-webui:v0.12.4
```

**ਚਲਾਉਣ ਤੋਂ ਪਹਿਲਾਂ `./open-webui.env` ਦੀ ਜਾਂਚ ਕਰੋ:** ਫਾਈਲ ਪਹਿਲਾਂ ਤੋਂ ਹੋਣੀ ਚਾਹੀਦੀ ਹੈ, ਇਸ ਦੀਆਂ ਪਹੁੰਚ-ਇਜਾਜ਼ਤਾਂ ਸੀਮਿਤ ਹੋਣੀਆਂ ਚਾਹੀਦੀਆਂ ਹਨ ਅਤੇ ਇਸ ਵਿੱਚ ਮੌਜੂਦਾ `WEBUI_SECRET_KEY` ਤੇ ਲੋੜੀਂਦੀ ਸੰਰਚਨਾ ਹੋਣੀ ਚਾਹੀਦੀ ਹੈ। ਲੂਪਬੈਕ ਬਾਈਂਡਿੰਗ ਉਸੇ ਹੋਸਟ ਉੱਤੇ ਪ੍ਰੌਕਸੀ ਲਈ ਢੁੱਕਵੀਂ ਹੈ, ਕਿਸੇ ਹੋਰ ਮਸ਼ੀਨ ਉੱਤੇ ਪ੍ਰੌਕਸੀ ਲਈ ਨਹੀਂ। Compose ਵਿੱਚ ਸਿਰਫ਼ ਸੇਵਾ ਇਮੇਜ ਨੂੰ ਪਿੰਨ ਕੀਤੇ ਟੈਗ ਉੱਤੇ ਬਦਲੋ, ਫਿਰ ਮੌਜੂਦਾ ਪ੍ਰੋਜੈਕਟ ਵਿੱਚ `docker compose pull open-webui` ਅਤੇ `docker compose up -d open-webui` ਚਲਾਓ। ਉਹੀ ਵਾਲਿਊਮ ਅਤੇ ਵਾਤਾਵਰਣ ਸੰਰਚਨਾ ਰੱਖੋ। ਇਹ ਸੁਝਾਈਆਂ ਕਮਾਂਡਾਂ ਹਨ, ਤੁਹਾਡੇ ਡਿਪਲੌਇਮੈਂਟ ਦੀ ਪਰਖੀ ਹੋਈ ਮਾਈਗ੍ਰੇਸ਼ਨ ਨਹੀਂ।

**pip, ਨਿਸ਼ਚਿਤ ਵਰਜਨ ਲਈ ਪ੍ਰਦਾਤਾ ਤਰੀਕਾ:** ਮੌਜੂਦਾ ਵਰਚੁਅਲ ਵਾਤਾਵਰਣ ਵਿੱਚ ਸੇਵਾ ਰੋਕੋ, ਪੈਕੇਜ ਦਾ ਠੀਕ ਵਰਜਨ ਇੰਸਟਾਲ ਕਰੋ ਅਤੇ ਉਸੇ ਡਾਟਾ ਡਾਇਰੈਕਟਰੀ ਤੇ ਵਾਤਾਵਰਣ ਨਾਲ ਮੁੜ ਚਾਲੂ ਕਰੋ। ਦੂਜਾ Python ਵਾਤਾਵਰਣ ਜਾਂ ਨਵਾਂ ਖਾਲੀ ਡਾਟਾਬੇਸ ਨਾ ਬਣਾਓ। ਪ੍ਰਦਾਤਾ ਦੀ ਆਮ ਹਦਾਇਤ `pip install -U open-webui` ਵਰਤਦੀ ਹੈ। ਹੇਠਾਂ ਦੀ ਵਰਜਨ ਸੀਮਾ ਇਸ ਜਾਂਚ-ਸੂਚੀ ਨੂੰ v0.12.4 ਉੱਤੇ ਪਿੰਨ ਕਰਦੀ ਹੈ। [Open WebUI ਅੱਪਡੇਟ ਕਰੋ](https://docs.openwebui.com/getting-started/updating/) · [ਤੁਰੰਤ ਸ਼ੁਰੂਆਤ](https://docs.openwebui.com/getting-started/quick-start/)

```bash
python -m pip install --upgrade 'open-webui==0.12.4'
python -m pip show open-webui
```

**ਚੱਲਦੀ ਸੇਵਾ ਦੀ ਜਾਂਚ ਕਰੋ, ਸਿਰਫ਼ ਇੰਸਟਾਲ ਕੀਤੇ ਪੈਕੇਜ ਦੀ ਨਹੀਂ।** `docker logs open-webui` ਜਾਂ pip ਸੇਵਾ ਲੌਗਾਂ ਵਿੱਚ ਸ਼ੁਰੂਆਤੀ ਵਰਜਨ ਵੇਖੋ ਅਤੇ ਸਾਈਨ ਇਨ ਤੋਂ ਬਾਅਦ ਐਪਲੀਕੇਸ਼ਨ ਵਿੱਚ ਦਿਖਦੇ ਵਰਜਨ ਨਾਲ ਤੁਲਨਾ ਕਰੋ। ਪ੍ਰਦਾਤਾ ਦੀ ਅੱਪਡੇਟ ਗਾਈਡ ਕੰਟੇਨਰ ਲੌਗ ਜਾਂਚਣ ਅਤੇ ਲੌਗਇਨ ਪੰਨਾ ਖੋਲ੍ਹਣ ਦੀ ਸਲਾਹ ਦਿੰਦੀ ਹੈ। ਜੇ ਇੰਟਰਫੇਸ ਪੁਰਾਣੇ ਸਰੋਤ ਦਿਖਾਵੇ ਤਾਂ ਬ੍ਰਾਊਜ਼ਰ ਨੂੰ ਜ਼ਬਰਦਸਤੀ ਰੀਫ੍ਰੈਸ਼ ਕਰੋ। ਜੇ ਸ਼ੁਰੂਆਤ ਦੌਰਾਨ ਮਾਈਗ੍ਰੇਸ਼ਨ ਗਲਤੀ ਆਵੇ, ਤਾਂ ਕਾਰਨ ਪਤਾ ਲੱਗਣ ਤੱਕ ਸੇਵਾ ਬੰਦ ਰੱਖੋ। ਮੁੜ-ਬਹਾਲੀ ਦੀਆਂ ਲੋੜਾਂ ਜਾਂਚੇ ਬਿਨਾਂ ਮਾਈਗ੍ਰੇਟ ਕੀਤੇ ਡਾਟਾਬੇਸ ਉੱਤੇ ਪੁਰਾਣਾ ਬਾਈਨਰੀ ਨਾ ਚਲਾਓ। [ਅੱਪਡੇਟ ਤੋਂ ਬਾਅਦ ਦੀਆਂ ਜਾਂਚਾਂ](https://docs.openwebui.com/getting-started/updating/)

## ਮੁੜ ਚਾਲੂ ਹੋਣ ਤੋਂ ਬਾਅਦ ਪਹੁੰਚ ਜਾਂਚੋ

**ਪ੍ਰਦਾਤਾ ਵੱਲੋਂ ਦੱਸਿਆ ਵਿਹਾਰ:** v0.12.4 ਉਹਨਾਂ ਵਰਤੋਂਕਾਰਾਂ ਤੋਂ ਫੋਲਡਰ ਐਕਸਪੋਰਟ, ਪੁਰਾਲੇਖ ਕੀਤੀਆਂ ਚੈਟਾਂ ਦਾ ਐਕਸਪੋਰਟ ਅਤੇ ਚੈਟ ਕਾਪੀ ਲੁਕਾਉਂਦਾ ਹੈ ਜਿਨ੍ਹਾਂ ਕੋਲ **Allow Chat Export** ਨਹੀਂ ਹੈ। ਜਿਨ੍ਹਾਂ ਕੋਲ ਸਬੰਧਤ ਸਾਂਝੀਕਰਨ ਅਧਿਕਾਰ ਨਹੀਂ, ਉਨ੍ਹਾਂ ਤੋਂ ਮਾਡਲ, ਪ੍ਰੌਂਪਟ, ਟੂਲ, ਗਿਆਨ, ਹੁਨਰ, ਨੋਟ ਅਤੇ ਫੋਲਡਰਾਂ ਦੇ ਪਹੁੰਚ-ਨਿਯੰਤਰਣ ਵੀ ਲੁਕਦੇ ਹਨ। ਸਾਂਝੇ ਫੋਲਡਰ ਦੇ ਦਰਸ਼ਕ ਨੂੰ ਮਾਲਕ ਵੱਲੋਂ ਚੈਟ ਪੁਰਾਲੇਖ ਕਰਨ ਤੋਂ ਬਾਅਦ ਲਾਈਵ ਚੈਟ ਅੱਪਡੇਟ ਨਹੀਂ ਮਿਲਦੇ। ਸਾਂਝੇ ਲਿੰਕ ਦੇ ਦਰਸ਼ਕ ਨੂੰ ਮਾਲਕ ਵੱਲੋਂ ਸਾਰੀਆਂ ਚੈਟਾਂ ਦੀ ਸਾਂਝ ਖਤਮ ਕਰਨ ਤੋਂ ਬਾਅਦ ਲਾਈਵ ਅੱਪਡੇਟ ਨਹੀਂ ਮਿਲਦੇ। ਨਿਯੰਤਰਣ ਲੁਕਣਾ ਇੰਟਰਫੇਸ ਦਾ ਵਿਹਾਰ ਹੈ, ਕਿਸੇ ਅਣਦੱਸੀ ਕਮਜ਼ੋਰੀ ਲਈ ਸਰਵਰ ਪਾਸੇ ਦੇ ਸੁਧਾਰ ਦਾ ਸਬੂਤ ਨਹੀਂ। [ਰਿਲੀਜ਼ ਨੋਟ](https://github.com/open-webui/open-webui/releases/tag/v0.12.4)

**ਸਿਫ਼ਾਰਸ਼ੀ ਆਪਰੇਟਰ ਜਾਂਚ:** ਨਿਰਯਾਤ ਅਤੇ ਸਾਂਝੀਕਰਨ ਅਧਿਕਾਰਾਂ ਤੋਂ ਬਿਨਾਂ ਟੈਸਟ ਖਾਤੇ ਨਾਲ ਵੇਖੋ ਕਿ ਦੱਸੀਆਂ ਕਾਰਵਾਈਆਂ ਗਾਇਬ ਹਨ। ਅਧਿਕਾਰ ਵਾਲੇ ਖਾਤੇ ਨਾਲ ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਲੋੜੀਂਦੀਆਂ ਕਾਰਵਾਈਆਂ ਹਾਲੇ ਵੀ ਕੰਮ ਕਰਦੀਆਂ ਹਨ। ਸਾਂਝੇ ਫੋਲਡਰ ਵਿੱਚ ਬਿਨਾਂ ਸੰਵੇਦਨਸ਼ੀਲ ਜਾਣਕਾਰੀ ਵਾਲੀ ਟੈਸਟ ਚੈਟ ਬਣਾਓ, ਦੂਜੇ ਖਾਤੇ ਤੋਂ ਵੇਖੋ, ਮਾਲਕ ਵਜੋਂ ਪੁਰਾਲੇਖ ਕਰੋ ਅਤੇ ਪੁਸ਼ਟੀ ਕਰੋ ਕਿ ਦਰਸ਼ਕ ਨੂੰ ਨਵੇਂ ਅੱਪਡੇਟ ਮਿਲਣੇ ਬੰਦ ਹੋ ਜਾਂਦੇ ਹਨ। ਸਾਂਝੇ ਲਿੰਕ ਅਤੇ **Unshare All Chats** ਨਾਲ ਵੀ ਇਹੀ ਕਰੋ। ਸੁਰੱਖਿਅਤ ਕੀਤੀਆਂ ਇਜਾਜ਼ਤਾਂ ਅਤੇ ਪੁਰਾਣੇ ਲਿੰਕ ਮੁੜ ਜਾਂਚੋ। ਇਹ ਨਾ ਮੰਨੋ ਕਿ ਪੁਰਾਲੇਖ ਕੀਤੀ ਸਮੱਗਰੀ ਜਾਂ ਪੁਰਾਣੀਆਂ ਕਾਪੀਆਂ ਮਿਟ ਗਈਆਂ ਹਨ।

| ਜਾਂਚ ਖੇਤਰ | ਕੀ ਜਾਂਚਣਾ ਹੈ |
|---|---|

| **ਮਾਡਲ ਅਤੇ ਟੂਲ** | ਹਰ ਮਾਡਲ ਦੀ ਪਹੁੰਚ ਮਨਜ਼ੂਰੀ, ਜੁੜੇ ਟੂਲ, ਟੂਲ ਬਣਾਉਣ ਦੇ ਅਧਿਕਾਰ ਅਤੇ ਪ੍ਰਦਾਤਾ ਪ੍ਰਮਾਣ ਪੱਤਰ ਵੇਖੋ। ਗੈਰ-ਪ੍ਰਬੰਧਕ ਖਾਤੇ ਨਾਲ ਟੈਸਟ ਕਰੋ। |

ਇਹ ਵਸਤੂ-ਸੂਚੀ ਜਾਂਚਾਂ **ਆਪਰੇਟਰ ਲਈ ਸਿਫ਼ਾਰਸ਼ਾਂ** ਹਨ, v0.12.4 ਦੀਆਂ ਨਵੀਆਂ ਗਾਰੰਟੀਆਂ ਨਹੀਂ। ਪ੍ਰਦਾਤਾ ਦੀ [ਹਾਰਡਨਿੰਗ ਗਾਈਡ](https://docs.openwebui.com/getting-started/advanced-topics/hardening/) ਪੱਧਰੀ ਭੂਮਿਕਾਵਾਂ, ਸਮੂਹਾਂ, ਹਰ ਸਰੋਤ ਲਈ ਅਧਿਕਾਰ, ਵਰਕਸਪੇਸ ਅਧਿਕਾਰ, API ਕੁੰਜੀਆਂ ਅਤੇ ਨੈੱਟਵਰਕ ਉੱਤੇ ਥਾਂ ਬਾਰੇ ਦੱਸਦੀ ਹੈ।

## ਖਾਤਿਆਂ ਅਤੇ ਨੈੱਟਵਰਕ ਦੀਆਂ ਘਾਟਾਂ ਪੂਰੀਆਂ ਕਰੋ

- **ਸਾਈਨਅੱਪ, ਪ੍ਰਦਾਤਾ ਸੈਟਿੰਗ:** ਜੇ ਪ੍ਰਬੰਧਕ ਜਾਂ ਪਛਾਣ ਪ੍ਰਦਾਤਾ ਖਾਤੇ ਬਣਾਉਂਦਾ ਹੈ, ਤਾਂ ਖੁੱਲ੍ਹਾ ਸਾਈਨਅੱਪ ਬੰਦ ਕਰੋ। [ਹਾਰਡਨਿੰਗ ਗਾਈਡ](https://docs.openwebui.com/getting-started/advanced-topics/hardening/) ਦੇ ਆਧਾਰ ਉੱਤੇ `ENABLE_SIGNUP` ਅਤੇ ਸਥਾਈ ਪ੍ਰਬੰਧਕ ਸੈਟਿੰਗਾਂ ਜਾਂਚੋ। ਨਵੇਂ ਖਾਤਿਆਂ ਲਈ ਮਨਜ਼ੂਰੀ ਦੇ ਨਿਯਮ ਸਖ਼ਤ ਰੱਖੋ।
- **API ਕੁੰਜੀਆਂ, ਆਪਰੇਟਰ ਸਮੀਖਿਆ:** ਜਾਰੀ ਕੀਤੀਆਂ ਕੁੰਜੀਆਂ ਦੀ ਸੂਚੀ ਬਣਾਓ, ਨਾ ਵਰਤੀਆਂ ਕੁੰਜੀਆਂ ਮਿਟਾਓ ਅਤੇ ਕੁੰਜੀ ਬਣਾਉਣ ਤੇ ਐਂਡਪੌਇੰਟ ਪਹੁੰਚ ਨੂੰ ਲੋੜੀਂਦੀਆਂ ਭੂਮਿਕਾਵਾਂ ਅਤੇ ਰਸਤਿਆਂ ਤੱਕ ਸੀਮਿਤ ਕਰੋ। ਪ੍ਰਦਾਤਾ ਦੀ ਗਾਈਡ ਮੁਤਾਬਕ ਕੁੰਜੀ ਆਪਣੇ ਬਣਾਉਣ ਵਾਲੇ ਦੇ ਅਧਿਕਾਰਾਂ ਨਾਲ ਕੰਮ ਕਰਦੀ ਹੈ। ਕੁੰਜੀਆਂ ਨੂੰ ਲੇਖ ਦੇ ਉਦਾਹਰਨਾਂ ਅਤੇ ਐਪਲੀਕੇਸ਼ਨ ਲੌਗਾਂ ਤੋਂ ਬਾਹਰ ਰੱਖੋ।
- **ਪ੍ਰਬੰਧਕ, ਆਪਰੇਟਰ ਸਮੀਖਿਆ:** ਛੱਡੇ ਹੋਏ ਪ੍ਰਬੰਧਕ ਖਾਤੇ ਹਟਾਓ, ਮਜ਼ਬੂਤ ਸਾਈਨ-ਇਨ ਨਿਯੰਤਰਣ ਲਾਗੂ ਕਰੋ, MFA ਦੀ ਉਪਲਬਧਤਾ ਵੇਖੋ ਅਤੇ ਅਚਾਨਕ ਖਾਤਾ ਬਦਲਾਵਾਂ ਦੀ ਜਾਂਚ ਕਰੋ। ਵਾਧੂ ਪ੍ਰਬੰਧਕ ਬੰਦ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਖਾਤਾ ਮੁੜ-ਪ੍ਰਾਪਤੀ ਤਰੀਕਾ ਪਰਖੋ।
- **ਨੈੱਟਵਰਕ ਹੱਦ, ਪ੍ਰਦਾਤਾ ਹਦਾਇਤ:** ਸੇਵਾ ਨੂੰ VPN, ਪਹੁੰਚ ਪ੍ਰੌਕਸੀ ਜਾਂ ਪ੍ਰਮਾਣਿਕਤਾ ਅਤੇ IP ਮਨਜ਼ੂਰ-ਸੂਚੀ ਵਾਲੀ ਰਿਵਰਸ ਪ੍ਰੌਕਸੀ ਦੇ ਪਿੱਛੇ ਰੱਖੋ। ਪ੍ਰਮਾਣਿਕਤਾ ਤੋਂ ਬਿਨਾਂ ਇਸਨੂੰ ਜਨਤਕ ਨਾ ਕਰੋ। ਪਹੁੰਚਯੋਗ ਸੇਵਾ ਉੱਤੇ `WEBUI_AUTH=False` ਤੋਂ ਬਚੋ। ਆਪਣੀ ਪ੍ਰਮਾਣਿਕਤਾ ਤੋਂ ਬਿਨਾਂ ਰਿਵਰਸ ਪ੍ਰੌਕਸੀ ਐਪਲੀਕੇਸ਼ਨ ਸਾਈਨ-ਇਨ ਦੀ ਥਾਂ ਨਹੀਂ ਲੈਂਦੀ। [Open WebUI ਸੁਰੱਖਿਅਤ ਕਰੋ](https://docs.openwebui.com/getting-started/advanced-topics/hardening/)

**ਦਾਇਰਾ:** ਇਹ ਜਾਂਚ-ਸੂਚੀ ਅਧਿਕਾਰਤ Open WebUI ਰਿਲੀਜ਼ ਅਤੇ ਦਸਤਾਵੇਜ਼ੀ ਮਿਆਰੀ ਇੰਸਟਾਲ ਤਰੀਕਿਆਂ ਉੱਤੇ ਲਾਗੂ ਹੁੰਦੀ ਹੈ। ਇਹ ਫੋਰਕ, ਬਦਲੀਆਂ ਇਮੇਜਾਂ ਜਾਂ ਤੀਜੀ ਧਿਰ ਦੇ ਪੈਕੇਜ ਨਹੀਂ ਜਾਂਚਦੀ। v0.12.4 ਦੇ ਨੋਟ ਸਰਗਰਮ ਸ਼ੋਸ਼ਣ ਦਾ ਦਾਅਵਾ ਨਹੀਂ ਕਰਦੇ। ਅਗਲੀਆਂ ਖੁਲਾਸਿਆਂ ਅਤੇ ਉਨ੍ਹਾਂ ਦੇ ਪ੍ਰਭਾਵਿਤ ਤੇ ਠੀਕ ਕੀਤੇ ਵਰਜਨਾਂ ਲਈ [ਪ੍ਰੋਜੈਕਟ ਸੁਰੱਖਿਆ ਸਲਾਹਾਂ](https://github.com/open-webui/open-webui/security/advisories) ਵੇਖੋ। ਪਹਿਲਾਂ ਦੀ ਸਲਾਹ ਦੇ ਸੁਧਾਰ ਨੂੰ v0.12.4 ਨਾਲ ਨਾ ਜੋੜੋ ਜਦ ਤੱਕ ਉਸਦੀ ਵਰਜਨ ਹੱਦ ਨਾ ਪੜ੍ਹ ਲਵੋ।
