## DNS ও রুট DNS যেভাবে কাজ করে

### ভূমিকা

ডোমেইন নেম সিস্টেম (DNS) ইন্টারনেট অবকাঠামোর একটি গুরুত্বপূর্ণ অংশ। এটি IP ঠিকানার বদলে ডোমেইন নাম দিয়ে ওয়েবসাইটে প্রবেশ করতে সাহায্য করে। DNS ফোনবুকের মতো কাজ করে, মানুষের পড়ার উপযোগী ডোমেইন নামকে কম্পিউটারের বোঝার উপযোগী IP ঠিকানায় রূপান্তর করে। DNS-এর কেন্দ্রে আছে রুট DNS, যা নাম সমাধানের জন্য স্তরবিন্যস্ত ও বিতরণকৃত ব্যবস্থা। এই নিবন্ধে DNS, রুট DNS এবং ডোমেইনে থাকা বিভিন্ন রেকর্ডের কাজ ব্যাখ্যা করা হয়েছে।

## ডোমেইন নেম সিস্টেম (DNS)

**ডোমেইন নেম সিস্টেম (DNS)** একটি বিকেন্দ্রীভূত নামকরণ ব্যবস্থা, যা ডোমেইন নামের সঙ্গে IP ঠিকানা যুক্ত করে। ব্রাউজারে ডোমেইন নাম লিখে ওয়েবসাইট ও অন্যান্য ইন্টারনেট রিসোর্সে প্রবেশ করা যায়। DNS জটিল IP ঠিকানা মুখস্থ রাখার প্রয়োজন দূর করে।

### DNS-এর স্তরবিন্যাস

DNS একাধিক স্তরের একটি স্তরবিন্যস্ত কাঠামোয় কাজ করে। সবচেয়ে উপরে থাকে রুট জোন, তারপর টপ-লেভেল ডোমেইন (TLD), দ্বিতীয় স্তরের ডোমেইন এবং সাবডোমেইন। প্রতিটি স্তর সম্পূর্ণ ডোমেইন নামের অংশ। `www.example.com`-এ “www” সাবডোমেইন, “example” দ্বিতীয় স্তরের ডোমেইন এবং “com” হলো TLD।

### DNS নাম সমাধানের প্রক্রিয়া

ব্রাউজারে ডোমেইন নাম লিখলে DNS নাম সমাধান শুরু হয়। ব্রাউজার একটি DNS রিজলভারকে অনুসন্ধান পাঠায়। সাধারণত ইন্টারনেট সেবা প্রদানকারী (ISP) এই রিজলভার দেয়। রিজলভার কয়েকটি ধাপ অনুসরণ করে ডোমেইন নাম সমাধান করে সংশ্লিষ্ট IP ঠিকানা পায়।

1. **স্থানীয় DNS ক্যাশ**: রিজলভার প্রথমে স্থানীয় ক্যাশে অনুরোধ করা ডোমেইন নাম ও IP ঠিকানা খোঁজে। তথ্য পেলে আর অনুসন্ধান না করে ফলাফল ফেরত দেয়।

2. **পুনরাবৃত্ত অনুসন্ধান**: ক্যাশে তথ্য না থাকলে রিজলভার পুনরাবৃত্ত অনুসন্ধান শুরু করে। প্রথমে এটি “.” (ডট) জোনের দায়িত্বে থাকা রুট DNS সার্ভারের সঙ্গে যোগাযোগ করে। রুট সার্ভার অনুরোধ করা ডোমেইনের TLD সার্ভারের IP ঠিকানা জানায়।

3. **TLD অনুসন্ধান**: রিজলভার আগের ধাপে পাওয়া TLD সার্ভারের সঙ্গে যোগাযোগ করে ডোমেইনের কর্তৃত্বপূর্ণ নেম সার্ভারের IP ঠিকানা চায়।

4. **কর্তৃত্বপূর্ণ নেম সার্ভারে অনুসন্ধান**: রিজলভার TLD সার্ভার থেকে পাওয়া কর্তৃত্বপূর্ণ নেম সার্ভারে অনুসন্ধান পাঠায়। এই সার্ভারগুলো ডোমেইনের কর্তৃত্বপূর্ণ রেকর্ড রাখে এবং নামের সঙ্গে যুক্ত IP ঠিকানা ফেরত দেয়।

5. **ক্লায়েন্টকে উত্তর**: রিজলভার কর্তৃত্বপূর্ণ নেম সার্ভার থেকে IP ঠিকানা পেয়ে ব্রাউজারে ফেরত পাঠায়। এরপর ব্রাউজার সেই ঠিকানা ব্যবহার করে ওয়েব সার্ভারের সঙ্গে সংযোগ করে।

### DNS ক্যাশিং

DNS রিজলভার গতি বাড়াতে এবং DNS সার্ভারের চাপ কমাতে উত্তর ক্যাশে রাখে। অনুসন্ধানের উত্তর পাওয়ার পর রিজলভার ডোমেইন নাম ও IP ঠিকানার সম্পর্ক স্থানীয়ভাবে সংরক্ষণ করে। একই নামের পরবর্তী অনুসন্ধানের উত্তর DNS স্তরবিন্যাসে না গিয়েও ক্যাশ থেকে পাওয়া যায়।

স্থানীয় রিজলভার, ISP রিজলভার এবং রাউটার ও অপারেটিং সিস্টেমের মতো যন্ত্রে বিভিন্ন স্তরে ক্যাশিং হয়। DNS উত্তরের Time-to-Live (TTL) মান রেকর্ড কতক্ষণ ক্যাশে থাকবে তা নির্ধারণ করে। TTL শেষ হলে রিজলভার রেকর্ডটি মুছে নতুন অনুসন্ধান করে।

#### স্থানীয় DNS ক্যাশ মুছুন

DNS ক্যাশ মুছলে কিছু DNS সমস্যা সমাধান হয় এবং সিস্টেম নতুন রেকর্ড সংগ্রহ করে। বিভিন্ন অপারেটিং সিস্টেমে এভাবে ক্যাশ মুছুন:

##### Windows

Windows-এ DNS ক্যাশ মুছতে:

1. `Win + R` চাপুন, `cmd` লিখুন এবং Enter চাপুন। এতে কমান্ড প্রম্পট খুলবে।

2. কমান্ড প্রম্পটে নিচের কমান্ড লিখে Enter চাপুন:

```bash
ipconfig /flushdns
```

এই কমান্ড Windows সিস্টেমের DNS রিজলভার ক্যাশ মুছে দেয়।

##### macOS

macOS-এ DNS ক্যাশ মুছতে:

1. Applications > Utilities থেকে টার্মিনাল খুলুন, অথবা Spotlight দিয়ে খুঁজুন।

2. টার্মিনালে নিচের কমান্ড লিখে Enter চাপুন:

```bash
sudo killall -HUP mDNSResponder
```

এই কমান্ড macOS-এ DNS সমাধানের দায়িত্বে থাকা mDNSResponder প্রক্রিয়া পুনরায় চালু করে।

##### Linux

Linux-এ DNS ক্যাশ মুছবার পদ্ধতি ডিস্ট্রিবিউশন ও DNS রিজলভারের ওপর নির্ভর করে। দুটি প্রচলিত পদ্ধতি:

1. **systemd-ভিত্তিক সিস্টেম (যেমন Ubuntu, Fedora)**:

টার্মিনাল খুলে প্রশাসকের অধিকারসহ নিচের কমান্ড চালান:

```bash
sudo systemd-resolve --flush-caches

```

systemd-resolved-কে DNS রিজলভার হিসেবে ব্যবহার করা সিস্টেমে এই কমান্ড ক্যাশ মুছে দেয়।

2. **systemd-বিহীন সিস্টেম**:

টার্মিনাল খুলে প্রশাসকের অধিকারসহ নিচের কমান্ড চালান:

```bash
sudo /etc/init.d/nscd restart

```

এই কমান্ড Name Service Cache Daemon (nscd) পুনরায় চালু করে। systemd-বিহীন Linux ডিস্ট্রিবিউশনে এটি DNS ক্যাশের দায়িত্বে থাকে।

এই ধাপগুলো সাধারণ নির্দেশনা। অপারেটিং সিস্টেমের সংস্করণ অনুযায়ী কমান্ড বা পদ্ধতি কিছুটা বদলাতে পারে। DNS ক্যাশ মুছলে কিছু সমস্যা সমাধান হয়, তবে নেটওয়ার্ক সংযোগের সব সমস্যা সমাধান হয় না।

## রুট DNS সিস্টেম যেভাবে কাজ করে

রুট DNS সিস্টেম DNS অবকাঠামোর একটি মৌলিক অংশ। এর কাজের ধাপগুলো দেখুন:

### 1. রুট জোন ও রুট সার্ভার

রুট DNS সিস্টেম শুরু হয় **রুট জোন** থেকে, যা DNS স্তরবিন্যাসের সর্বোচ্চ স্তর। এতে .com, .org, .net-এর মতো সব টপ-লেভেল ডোমেইন (TLD) এবং .us, .uk-এর মতো দেশের কোড TLD-এর কর্তৃত্বপূর্ণ নেম সার্ভারের তথ্য থাকে।

রুট DNS সিস্টেমে A থেকে M অক্ষরে চিহ্নিত 13টি রুট সার্ভার রয়েছে। নির্ভরযোগ্যতা ও অতিরিক্ত সক্ষমতার জন্য সেগুলো পৃথিবীর বিভিন্ন স্থানে ছড়িয়ে আছে।

### 2. Anycast রাউটিং

বিপুল DNS ট্রাফিক সামলাতে রুট সার্ভার **anycast রাউটিং** ব্যবহার করে। একাধিক সার্ভার একই IP ঠিকানা ব্যবহার করলেও ভৌগোলিকভাবে আলাদা থাকে। নেটওয়ার্কের অবস্থা অনুযায়ী অনুসন্ধান উপযুক্ত সার্ভারে পাঠানো হয়, ফলে চাপ দক্ষভাবে ভাগ হয়।

ব্যবহারকারী DNS অনুসন্ধান শুরু করলে anycast অনুরোধটি কাছের উপলভ্য রুট সার্ভারে পাঠায়। নেটওয়ার্ক অবস্থা দেখে অবকাঠামো সবচেয়ে ছোট পথের সার্ভার বেছে নেয়। Anycast চাপ ভাগ করে এবং জট তৈরি হওয়া কমায়।

### 3. পুনরাবৃত্ত DNS রিজলভার

DNS রিজলভার কোনো ডোমেইন নামের অনুসন্ধান পেলে পুনরাবৃত্ত নাম সমাধান শুরু করে এবং একটি রুট সার্ভারে যোগাযোগ করে।

রুট সার্ভার অনুরোধ করা TLD-এর দায়িত্বে থাকা TLD নেম সার্ভারের IP ঠিকানা জানিয়ে রেফারেল দেয়। এই TLD সার্ভারগুলো TLD-এর অধীন নির্দিষ্ট ডোমেইনের কর্তৃত্বপূর্ণ নেম সার্ভারের তথ্য রাখে।

### 4. রেফারেল ও কর্তৃত্বপূর্ণ নেম সার্ভার

রুট সার্ভারের রেফারেল পাওয়ার পর রিজলভার উপযুক্ত TLD নেম সার্ভারের সঙ্গে যোগাযোগ করে।

TLD নেম সার্ভার আরেকটি রেফারেল দেয়, যেখানে অনুরোধ করা ডোমেইনের কর্তৃত্বপূর্ণ নেম সার্ভারের IP ঠিকানা থাকে।

এরপর রিজলভার কর্তৃত্বপূর্ণ নেম সার্ভারের কাছে ডোমেইন নামের IP ঠিকানা চায়।

### 5. ক্যাশিং ও TTL

DNS নাম সমাধানের সময় ক্যাশিং কর্মক্ষমতা বাড়ায় এবং DNS সার্ভারের চাপ কমায়। রিজলভার ডোমেইন নাম ও IP ঠিকানার সম্পর্ক সংরক্ষণ করে।

Time-to-Live (TTL) মান যতক্ষণ নির্ধারণ করে, DNS রেকর্ড ততক্ষণ ক্যাশে থাকে। TTL রেকর্ডের বৈধতার সময় জানায়। সময় শেষ হলে রিজলভার রেকর্ড মুছে হালনাগাদ IP ঠিকানার জন্য নতুন অনুসন্ধান করে।

### 6. সহযোগিতা ও ব্যবস্থাপনা

Internet Corporation for Assigned Names and Numbers (ICANN) এবং রুট সার্ভার পরিচালকেরা যৌথভাবে রুট DNS সিস্টেম পরিচালনা করে।

ICANN DNS-এর সামগ্রিক ব্যবস্থাপনা ও সমন্বয় তদারক করে এবং রুট সার্ভার অপারেটরদের সঙ্গে কাজ করে। তারা মিলে রুট জোন ফাইল বজায় রাখে, যেখানে 13টি রুট DNS সার্ভার ও তাদের IP ঠিকানার তথ্য থাকে।

রুট সার্ভার পরিচালকেরা রুট DNS সার্ভারের কার্যক্রম ও প্রাপ্যতা নিশ্চিত করে। এতে DNS অবকাঠামোর স্থিতিশীলতা ও সহনশীলতা বজায় থাকে।

রুট DNS সিস্টেম DNS নাম সমাধানের শুরু। এটি ডোমেইন নামকে IP ঠিকানার সঙ্গে মেলায়, ফলে ব্যবহারকারী দক্ষভাবে ওয়েবসাইট ও অন্যান্য ইন্টারনেট রিসোর্সে প্রবেশ করতে পারে।

#### 13টি রুট DNS সার্ভার

13টি রুট DNS সার্ভার A থেকে M অক্ষরে চিহ্নিত। অতিরিক্ত সক্ষমতা ও ত্রুটি সহনশীলতার জন্য প্রতিটি সার্ভার বিভিন্ন ভৌত স্থানে পরিচালিত হয়। এগুলো রুট জোনের অনুসন্ধান সামলায়, যার মধ্যে .com, .org, .net-এর মতো TLD এবং .us, .uk-এর মতো দেশের কোড TLD রয়েছে।

#### ICANN ও রুট DNS ব্যবস্থাপনা

Internet Corporation for Assigned Names and Numbers (**ICANN**) DNS ব্যবস্থাপনা ও সমন্বয় এবং IP ঠিকানা বরাদ্দের দায়িত্বে থাকে। রুট DNS-এর স্থিতিশীলতা ও নিরাপত্তা নিশ্চিত করতে ICANN রুট সার্ভার পরিচালকেরা-এর সঙ্গে কাজ করে। তারা মিলে 13টি রুট সার্ভার ও তাদের IP ঠিকানার তথ্যসহ রুট জোন ফাইল বজায় রাখে।

## DNS রেকর্ডের ধরন ও কাজ

{{< youtube id="HnUDtycXSNE" >}}

DNS রেকর্ড ডোমেইন নেম সিস্টেমের গুরুত্বপূর্ণ অংশ এবং ডোমেইন নামের সঙ্গে সম্পর্কিত বিভিন্ন তথ্য দেয়। প্রচলিত কয়েকটি ধরন ও তাদের কাজ নিচে দেওয়া হলো:

| রেকর্ডের ধরন | বিবরণ | উদাহরণ |
|-------------|-----------------------------------------------------------------------------|-------------------------------------------|
| A | ডোমেইন নামকে IPv4 ঠিকানার সঙ্গে যুক্ত করে। | `example.com     IN A 192.0.2.1` |
| AAAA | ডোমেইন নামকে IPv6 ঠিকানার সঙ্গে যুক্ত করে। | `example.com     IN AAAA 2001:db8::1` |
| CNAME | একটি alias (প্রামাণ্য নাম) প্রকৃত ডোমেইন নামের সঙ্গে যুক্ত করে। | `www.example.com IN CNAME example.com` |
| MX | ডোমেইনের আগত ইমেল গ্রহণকারী মেইল সার্ভার নির্দেশ করে। | `example.com     IN MX 10 mail.example.com` |
| TXT | যেকোনো টেক্সট রাখে, সাধারণত SPF, DKIM বা ডোমেইন যাচাইয়ের জন্য। | `example.com     IN TXT "v=spf1 a mx -all"`|
| NS | ডোমেইনের কর্তৃত্বপূর্ণ নেম সার্ভার নির্দেশ করে। | `example.com     IN NS ns1.example.com` |
| SOA | জোনের সাধারণ বৈশিষ্ট্য নির্ধারণ করে (start of authority রেকর্ড)। | `example.com     IN SOA ns1.example.com` |
| SRV | ডোমেইনের নির্দিষ্ট পরিষেবার অবস্থান নির্ধারণ করে। | `_service._proto.example.com IN SRV 10 20 5060 target.example.com` |
| PTR | IP ঠিকানাকে ডোমেইন নামের সঙ্গে যুক্ত করে (বিপরীত DNS অনুসন্ধান)। | `1.2.0.192.in-addr.arpa IN PTR example.com` |

### 1. A রেকর্ড (ঠিকানা রেকর্ড)

**A রেকর্ড** একটি ডোমেইন নামকে IPv4 ঠিকানার সঙ্গে যুক্ত করে। এটি সবচেয়ে মৌলিক ও বহুল ব্যবহৃত DNS রেকর্ড। ব্রাউজারে ডোমেইন নাম লিখলে ওয়েবসাইটের সার্ভারের IP ঠিকানা খুঁজতে A রেকর্ড সাহায্য করে।

### 2. AAAA রেকর্ড (IPv6 ঠিকানা রেকর্ড)

**AAAA রেকর্ড** A রেকর্ডের মতোই কাজ করে, তবে ডোমেইন নামকে IPv6 ঠিকানার সঙ্গে যুক্ত করে। IPv6-এ রূপান্তরের সঙ্গে IPv6 নেটওয়ার্কে সংযোগের জন্য এর গুরুত্ব বাড়ছে।

### 3. CNAME রেকর্ড (প্রামাণ্য নাম রেকর্ড)

**CNAME রেকর্ড** ডোমেইনের জন্য alias বা প্রামাণ্য নাম তৈরি করে। কোনো ডোমেইন বা সাবডোমেইনকে অন্য ডোমেইনের দিকে নির্দেশ করতে এটি ব্যবহার হয়। উদাহরণস্বরূপ, "www"-কে "mywebsite.com"-এ নির্দেশ করতে CNAME তৈরি করা যায়।

### 4. MX রেকর্ড (মেইল আদান-প্রদান রেকর্ড)

**MX রেকর্ড** ডোমেইনের আগত ইমেল গ্রহণকারী মেইল সার্ভার নির্ধারণ করে। একাধিক MX রেকর্ডে অগ্রাধিকার দেওয়া যায়, যাতে প্রধান সার্ভার অনুপলভ্য হলে চেষ্টা করার ক্রম ঠিক হয়।

### 5. TXT রেকর্ড (টেক্সট রেকর্ড)

**TXT রেকর্ড** ডোমেইনের সঙ্গে যুক্ত টেক্সট তথ্য রাখে। ডোমেইন যাচাই, ইমেল প্রমাণীকরণের জন্য SPF (Sender Policy Framework) রেকর্ড এবং সাধারণ তথ্য বা নোটে এটি প্রায়ই ব্যবহৃত হয়।

### 6. SRV রেকর্ড (সেবা রেকর্ড)

**SRV রেকর্ড** ডোমেইনের নির্দিষ্ট সেবা বা রিসোর্সের অবস্থান নির্ধারণ করে। VoIP, তাৎক্ষণিক বার্তা এবং নির্দিষ্ট সার্ভার বা সেবা খোঁজা দরকার এমন অ্যাপে এটি ব্যবহৃত হয়।

### 7. NS রেকর্ড (নেম সার্ভার রেকর্ড)

**NS রেকর্ড** ডোমেইনের কর্তৃত্বপূর্ণ নেম সার্ভার নির্দেশ করে। এই সার্ভারগুলো ডোমেইনের DNS রেকর্ড রাখে। রিজলভার NS রেকর্ড ব্যবহার করে কর্তৃত্বপূর্ণ নেম সার্ভার খুঁজে পায়।

### 8. PTR রেকর্ড (নির্দেশক রেকর্ড)

**PTR রেকর্ড** বিপরীত DNS অনুসন্ধানে IP ঠিকানাকে ডোমেইন নামের সঙ্গে যুক্ত করে। মেইল সার্ভারের পরিচয় যাচাই এবং স্প্যাম প্রতিরোধে এটি প্রায়ই ব্যবহৃত হয়। বিপরীত অনুসন্ধান ইমেল সার্ভারের সত্যতা যাচাইয়ে সাহায্য করে।

### 9. SOA রেকর্ড (কর্তৃত্ব শুরুর রেকর্ড)

**SOA রেকর্ড** ডোমেইনের প্রশাসনিক তথ্য ধারণ করে। এতে প্রাথমিক কর্তৃত্বপূর্ণ নেম সার্ভার, ডোমেইন প্রশাসকের ইমেল ঠিকানা এবং DNS রেকর্ডের বিভিন্ন সময়সীমা থাকে।

এগুলো অনেক DNS রেকর্ডের কয়েকটি উদাহরণ। প্রতিটি রেকর্ডের নির্দিষ্ট কাজ রয়েছে, যা ডোমেইন নামকে সংশ্লিষ্ট রিসোর্সে নির্ভুলভাবে সমাধান করতে সাহায্য করে।

## বিভিন্ন অপারেটিং সিস্টেমে DNS সমস্যা নির্ণয়ের কমান্ড

DNS সমস্যা হলে নির্ণয়ের কমান্ড কারণ খুঁজতে সাহায্য করে। বিভিন্ন অপারেটিং সিস্টেমে ব্যবহৃত কিছু প্রচলিত কমান্ড:

### Windows

#### 1. `ipconfig /flushdns`

এই কমান্ড Windows-এর DNS ক্যাশ মুছে দেয় এবং পুরোনো বা ভুল রেকর্ডের সমস্যা সমাধানে সাহায্য করে। কমান্ড প্রম্পট খুলে কমান্ডটি চালান।

#### 2. `ipconfig /all`

`ipconfig /all` Windows নেটওয়ার্ক ইন্টারফেসের বিস্তারিত তথ্য দেখায়, যার মধ্যে কনফিগার করা DNS সার্ভারও আছে। সঠিক সার্ভার ব্যবহৃত হচ্ছে কি না তা যাচাই করতে এটি সাহায্য করে।

### macOS

#### 1. `sudo killall -HUP mDNSResponder`

এই কমান্ড macOS-এর DNS সমাধানের দায়িত্বে থাকা mDNSResponder প্রক্রিয়া পুনরায় চালু করে। এতে DNS সেটিংস রিফ্রেশ হতে এবং কিছু সমস্যা সমাধান হতে পারে। টার্মিনাল খুলে প্রশাসকের অধিকারসহ চালান।

#### 2. `nslookup`

`nslookup` দিয়ে DNS রেকর্ড অনুসন্ধান, নাম সমাধান পরীক্ষা এবং DNS সার্ভারের সঙ্গে সংযোগ যাচাই করা যায়। টার্মিনালে `nslookup`-এর পরে অনুসন্ধান করতে চাওয়া ডোমেইন নাম বা IP ঠিকানা লিখুন।

### Linux

#### 1. `systemd-resolve --flush-caches`

DNS রিজলভার হিসেবে systemd ব্যবহার করা Linux সিস্টেমে `systemd-resolve --flush-caches` DNS ক্যাশ মুছে দেয়। পুরোনো ক্যাশ এন্ট্রির সমস্যা এতে সমাধান হতে পারে। টার্মিনালে প্রশাসকের অধিকারসহ কমান্ডটি চালান।

#### 2. `dig`

`dig` Linux-এর একটি বহুমুখী DNS নির্ণয় সরঞ্জাম। এটি DNS অনুসন্ধান, উত্তর ও সার্ভার কনফিগারেশনের বিস্তারিত দেখায়। নির্দিষ্ট DNS রেকর্ড জানতে, নাম সমাধান পরীক্ষা করতে এবং সমস্যা নির্ণয়ে `dig` ব্যবহার করুন। টার্মিনালে `dig`-এর পরে ডোমেইন নাম বা IP ঠিকানা লিখুন।

এই কমান্ডগুলো বিভিন্ন অপারেটিং সিস্টেমে DNS সমস্যা নির্ণয় ও সমাধানে সাহায্য করে। এগুলো দিয়ে DNS কনফিগারেশন, সার্ভার সেটিং এবং সংযোগের সমস্যা পরীক্ষা করা যায়।

অপারেটিং সিস্টেমের সংস্করণ ও ডিস্ট্রিবিউশন অনুযায়ী কমান্ড এবং বিকল্প বদলাতে পারে। বিস্তারিত ব্যবহার জানতে আপনার সিস্টেমের সংস্করণের নথি দেখুন।

## উপসংহার

ডোমেইন নেম সিস্টেম (DNS) ও রুট DNS ইন্টারনেটের কাজে গুরুত্বপূর্ণ ভূমিকা রাখে। DNS সহজে পড়া যায় এমন ডোমেইন নাম দিয়ে ওয়েবসাইটে প্রবেশ করায়, আর রুট DNS পুরো DNS স্তরবিন্যাসের ভিত্তি। এদের কাজ বুঝলে ওয়েব ব্যবহার এবং অনলাইন পরিষেবার অবকাঠামো বোঝা সহজ হয়।
