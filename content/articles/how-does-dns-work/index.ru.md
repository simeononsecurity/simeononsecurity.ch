## Как работают DNS и корневая зона DNS

### Введение

Система доменных имен (DNS) является важной частью интернет-инфраструктуры. Она позволяет открывать сайты по доменным именам вместо IP-адресов. DNS работает как телефонная книга: преобразует понятные людям имена в IP-адреса, которые понимают компьютеры. В основе DNS находится корневая зона, иерархическая распределенная система, участвующая в разрешении доменных имен. В этой статье объясняется работа DNS, корневой зоны и записей, которые могут быть у домена.

## Система доменных имен (DNS)

**Система доменных имен (DNS)** представляет собой децентрализованную систему именования, которая связывает доменные имена с IP-адресами. Она позволяет открывать сайты и другие интернет-ресурсы, вводя доменное имя в браузере. Благодаря DNS не нужно запоминать сложные IP-адреса.

### Иерархия DNS

DNS устроена иерархически и состоит из нескольких уровней. Наверху находится корневая зона, за ней следуют домены верхнего уровня (TLD), домены второго уровня и поддомены. Каждый уровень входит в полное доменное имя. В `www.example.com` имя «www» является поддоменом, «example» является доменом второго уровня, а «com» относится к TLD.

### Процесс разрешения DNS

Когда пользователь вводит доменное имя в браузере, начинается разрешение DNS. Браузер отправляет запрос DNS-резолверу, который обычно предоставляет интернет-провайдер (ISP). Резолвер выполняет несколько шагов, чтобы разрешить имя и получить соответствующий IP-адрес.

1. **Локальный кеш DNS**: сначала резолвер проверяет локальный кеш на наличие запрошенного доменного имени и IP-адреса. Если данные найдены, он сразу возвращает результат.

2. **Рекурсивный запрос**: если данных в кеше нет, резолвер запускает рекурсивный запрос. Сначала он обращается к корневым DNS-серверам, отвечающим за зону «.» (точку). Корневые серверы возвращают IP-адреса серверов TLD для запрошенного домена.

3. **Запрос к TLD**: резолвер связывается с серверами TLD, найденными на предыдущем шаге, и запрашивает IP-адреса авторитетных серверов имен для домена.

4. **Запрос к авторитетному серверу имен**: резолвер отправляет запрос авторитетным серверам имен, полученным от серверов TLD. Эти серверы хранят авторитетные записи домена и отвечают IP-адресом, связанным с именем.

5. **Ответ клиенту**: резолвер получает IP-адрес от авторитетных серверов имен и передает его браузеру. После этого браузер устанавливает соединение с веб-сервером по полученному адресу.

### Кеширование DNS

DNS-резолверы используют кеширование, чтобы ускорить работу и снизить нагрузку на DNS-серверы. Получив ответ, резолвер сохраняет в локальном кеше связь доменного имени с IP-адресом. Повторный запрос того же имени можно обслужить из кеша без обращения к иерархии DNS.

Кеширование выполняется на нескольких уровнях: в локальном резолвере, у провайдера и на устройствах, например маршрутизаторах и операционных системах. Значение Time-to-Live (TTL) в DNS-ответе определяет срок хранения записи в кеше. По истечении TTL резолвер удаляет запись и выполняет новый запрос.

#### Очистка локального кеша DNS

Очистка кеша DNS помогает устранить некоторые проблемы и заставить систему получить актуальные записи. Ниже описаны способы для разных операционных систем.

##### Windows

Чтобы очистить кеш DNS в Windows:

1. Нажмите `Win + R`, введите `cmd` и нажмите Enter, чтобы открыть Командную строку.

2. Введите команду и нажмите Enter:

```bash
ipconfig /flushdns
```

Команда очищает кеш DNS-резолвера в Windows.

##### macOS

Чтобы очистить кеш DNS в macOS:

1. Откройте приложение «Терминал» в папке «Программы» > «Утилиты» или найдите его через Spotlight.

2. Введите команду и нажмите Enter:

```bash
sudo killall -HUP mDNSResponder
```

Команда перезапускает процесс mDNSResponder, который отвечает за разрешение DNS в macOS.

##### Linux

Способ очистки кеша DNS в Linux зависит от дистрибутива и используемого резолвера. Вот два распространенных метода:

1. **Системы на основе systemd (например, Ubuntu и Fedora)**:

Откройте Терминал и выполните команду с правами администратора:

```bash
sudo systemd-resolve --flush-caches

```

Команда очищает кеш DNS на системах, где резолвером служит systemd-resolved.

2. **Системы без systemd**:

Откройте Терминал и выполните команду с правами администратора:

```bash
sudo /etc/init.d/nscd restart

```

Команда перезапускает Name Service Cache Daemon (nscd), отвечающий за кеширование DNS в дистрибутивах Linux без systemd.

Это общие рекомендации. Команды и методы могут немного отличаться в разных версиях ОС. Очистка кеша DNS помогает устранить некоторые проблемы, но не решает все проблемы с сетевым подключением.

## Как работает корневая система DNS

Корневая система DNS является основополагающей частью инфраструктуры DNS. Рассмотрим ее работу.

### 1. Корневая зона и корневые серверы

Корневая система DNS начинается с **корневой зоны**, верхнего уровня иерархии DNS. Она содержит сведения об авторитетных серверах имен всех доменов верхнего уровня (TLD), например .com, .org, .net, а также национальных доменов, таких как .us и .uk.

Корневая система DNS состоит из 13 корневых серверов с обозначениями от A до M. Они географически распределены по всему миру для обеспечения резервирования и надежности.

### 2. Маршрутизация anycast

Для обработки большого объема DNS-трафика корневые серверы используют **маршрутизацию anycast**. Несколько серверов используют один IP-адрес, находясь в разных местах. В зависимости от состояния сети запрос направляется к подходящему серверу, что помогает эффективно распределить нагрузку.

Когда пользователь отправляет запрос DNS, anycast направляет его к ближайшему доступному корневому серверу. Сетевая инфраструктура выбирает сервер с кратчайшим путем с учетом условий сети. Anycast распределяет нагрузку и помогает избежать узких мест.

### 3. Рекурсивные DNS-резолверы

Получив запрос для доменного имени, DNS-резолвер начинает рекурсивное разрешение и обращается к одному из корневых серверов.

Корневой сервер отвечает перенаправлением к IP-адресам серверов имен TLD, отвечающих за запрошенный TLD. Эти серверы содержат сведения об авторитетных серверах имен доменов внутри TLD.

### 4. Перенаправления и авторитетные серверы имен

Получив перенаправление от корневого сервера, резолвер обращается к соответствующему серверу имен TLD.

Сервер TLD возвращает еще одно перенаправление с IP-адресами авторитетных серверов имен запрошенного домена.

Затем резолвер запрашивает у авторитетных серверов IP-адрес, связанный с доменным именем.

### 5. Кеширование и TTL

Во время разрешения DNS кеширование ускоряет работу и снижает нагрузку на серверы. Резолверы сохраняют соответствия между доменными именами и IP-адресами.

Записи DNS кешируются на срок, заданный значением Time-to-Live (TTL). TTL показывает, как долго запись остается действительной. После его истечения резолвер удаляет запись и запрашивает актуальный IP-адрес.

### 6. Сотрудничество и управление

Корневой системой DNS совместно управляют Internet Corporation for Assigned Names and Numbers (ICANN) и операторы корневых серверов.

ICANN контролирует общее управление и координацию DNS и тесно сотрудничает с операторами корневых серверов. Они совместно поддерживают файл корневой зоны, содержащий информацию о 13 корневых DNS-серверах и соответствующих IP-адресах.

операторы корневых серверов обеспечивают работу и доступность корневых серверов, поддерживая стабильность и устойчивость всей инфраструктуры DNS.

Корневая система DNS служит отправной точкой разрешения имен. Она помогает сопоставлять доменные имена с IP-адресами, чтобы пользователи могли эффективно открывать сайты и другие интернет-ресурсы.

#### 13 корневых DNS-серверов

13 корневых DNS-серверов обозначены буквами от A до M. Каждый сервер размещен в разных физических точках, что обеспечивает резервирование и отказоустойчивость. Они обрабатывают запросы для корневой зоны, включая TLD .com, .org, .net и национальные домены .us и .uk.

#### ICANN и управление корневой зоной DNS

Internet Corporation for Assigned Names and Numbers (**ICANN**) отвечает за управление и координацию DNS, а также распределение IP-адресов. ICANN сотрудничает с операторы корневых серверов для обеспечения стабильности и безопасности корневой зоны DNS. Вместе они поддерживают файл корневой зоны со сведениями о 13 корневых серверах и их IP-адресах.

## Типы записей DNS и их назначение

{{< youtube id="HnUDtycXSNE" >}}

Записи DNS являются важными элементами системы доменных имен. Они предоставляют разные сведения, связанные с доменом. Ниже приведены распространенные типы записей и их назначение.

| Тип записи | Описание | Пример |
|-------------|-----------------------------------------------------------------------------|-------------------------------------------|
| A | Сопоставляет доменное имя с IPv4-адресом. | `example.com     IN A 192.0.2.1` |
| AAAA | Сопоставляет доменное имя с IPv6-адресом. | `example.com     IN AAAA 2001:db8::1` |
| CNAME | Сопоставляет псевдоним (каноническое имя) с настоящим доменным именем. | `www.example.com IN CNAME example.com` |
| MX | Указывает почтовые серверы, принимающие входящую почту домена. | `example.com     IN MX 10 mail.example.com` |
| TXT | Хранит произвольный текст, часто для SPF, DKIM или проверки домена. | `example.com     IN TXT "v=spf1 a mx -all"`|
| NS | Указывает авторитетные серверы имен домена. | `example.com     IN NS ns1.example.com` |
| SOA | Задает общие свойства зоны (запись start of authority). | `example.com     IN SOA ns1.example.com` |
| SRV | Определяет расположение конкретной службы домена. | `_service._proto.example.com IN SRV 10 20 5060 target.example.com` |
| PTR | Сопоставляет IP-адрес с доменным именем (обратный поиск DNS). | `1.2.0.192.in-addr.arpa IN PTR example.com` |

### 1. Запись A (запись адреса)

**Запись A** сопоставляет доменное имя с IPv4-адресом. Это самый простой и распространенный тип записи DNS. Когда пользователь вводит домен в браузере, запись A позволяет найти IP-адрес веб-сервера, на котором размещен сайт.

### 2. Запись AAAA (запись адреса IPv6)

**Запись AAAA** выполняет ту же задачу, что и запись A, но связывает доменное имя с IPv6-адресом. По мере перехода на IPv6 записи AAAA становятся все важнее для связи через сети IPv6.

### 3. Запись CNAME (запись канонического имени)

**Запись CNAME** создает псевдоним или каноническое имя для домена. Она используется, когда нужно направить домен или поддомен на другой домен или поддомен. Например, можно создать CNAME, который направит "www" на "mywebsite.com".

### 4. Запись MX (запись почтового обмена)

**Запись MX** указывает почтовый сервер, принимающий входящие сообщения для домена. Она определяет, куда доставлять почту. Можно задать несколько записей MX с приоритетами, определяющими порядок обращения к серверам, если основной недоступен.

### 5. Запись TXT (текстовая запись)

**Запись TXT** хранит текстовую информацию о домене. Ее часто используют для проверки домена, публикации SPF (Sender Policy Framework) для аутентификации почты и хранения общих сведений или заметок.

### 6. Запись SRV (запись службы)

**Запись SRV** определяет расположение конкретной службы или ресурса в домене. Она используется для VoIP, мгновенных сообщений и других приложений, которым нужно находить определенные серверы или службы.

### 7. Запись NS (запись сервера имен)

**Запись NS** указывает авторитетные серверы имен домена. Эти серверы хранят записи DNS домена. Резолвер использует NS, чтобы найти авторитетные серверы имен.

### 8. Запись PTR (указательная запись)

**Запись PTR** сопоставляет IP-адрес с доменным именем при обратном поиске DNS. Ее часто используют для проверки почтового сервера и борьбы со спамом. Обратный поиск DNS помогает подтвердить подлинность почтового сервера.

### 9. Запись SOA (запись начала зоны)

**Запись SOA** содержит административные сведения о домене, например имя основного авторитетного сервера, адрес электронной почты администратора и временные параметры записей DNS.

Это лишь несколько из множества типов записей DNS. Каждая запись выполняет определенную задачу и помогает точно и эффективно разрешать доменные имена в связанные с ними ресурсы.

## Команды диагностики DNS для разных операционных систем

При проблемах DNS диагностические команды помогают найти причину. Вот часто используемые команды для разных операционных систем:

### Windows

#### 1. `ipconfig /flushdns`

Команда очищает кеш DNS в Windows и может помочь при устаревших или неверных записях. Откройте Командную строку и выполните ее.

#### 2. `ipconfig /all`

Команда `ipconfig /all` показывает подробные сведения о сетевых интерфейсах Windows, включая настроенные DNS-серверы. Так можно проверить, используются ли правильные серверы.

### macOS

#### 1. `sudo killall -HUP mDNSResponder`

Команда перезапускает процесс mDNSResponder в macOS, отвечающий за разрешение DNS. Это может обновить настройки DNS и устранить проблемы. Откройте Терминал и выполните команду с правами администратора.

#### 2. `nslookup`

Команда `nslookup` позволяет запрашивать записи DNS, проверять разрешение имен и связь с DNS-серверами. Откройте Терминал и выполните `nslookup`, указав доменное имя или IP-адрес для проверки.

### Linux

#### 1. `systemd-resolve --flush-caches`

В системах Linux, использующих systemd как DNS-резолвер, команда `systemd-resolve --flush-caches` очищает кеш DNS. Она может устранить проблемы, вызванные устаревшими данными. Откройте Терминал и выполните команду с правами администратора.

#### 2. `dig`

Команда `dig` является универсальным инструментом диагностики DNS в Linux. Она показывает подробную информацию о запросах, ответах и настройках DNS-серверов. Используйте `dig` для запроса записей, проверки разрешения имен и диагностики проблем. Откройте Терминал и выполните `dig`, указав домен или IP-адрес.

Эти команды помогают диагностировать и устранять проблемы DNS в разных операционных системах. Они дают сведения о конфигурации DNS, настройках серверов и сетевом подключении.

Команды и их параметры могут различаться в зависимости от версии ОС и дистрибутива. Подробные сведения об использовании см. в документации для вашей версии.
