## DNSとルートDNSの仕組み

### はじめに

Domain Name System（DNS）はインターネットインフラの重要な要素です。IPアドレスの代わりにドメイン名を使ってWebサイトへアクセスできます。DNSは電話帳のように、人が読めるドメイン名をコンピューターが理解するIPアドレスに変換します。その中核にあるルートDNSは、ドメイン名の解決を支える階層型の分散システムです。この記事では、DNSとルートDNSの仕組み、ドメインで使われるレコードを説明します。

## Domain Name System（DNS）

**Domain Name System（DNS）** は、ドメイン名とIPアドレスを対応付ける分散型の名前解決システムです。ブラウザーにドメイン名を入力するだけで、Webサイトやその他のインターネットリソースへアクセスできます。DNSにより、複雑なIPアドレスを覚える必要がありません。

### DNSの階層

DNSは複数のレベルから成る階層構造で動作します。最上位はルートゾーンで、その下にトップレベルドメイン（TLD）、第2レベルドメイン、サブドメインがあります。各レベルが完全なドメイン名を構成します。`www.example.com`では、「www」がサブドメイン、「example」が第2レベルドメイン、「com」がTLDです。

### DNS名前解決の流れ

ブラウザーにドメイン名を入力すると、DNS名前解決が始まります。ブラウザーはDNSリゾルバーへクエリを送信します。通常、リゾルバーはインターネットサービスプロバイダー（ISP）が提供します。リゾルバーは複数の手順を経てドメイン名を解決し、対応するIPアドレスを取得します。

1. **ローカルDNSキャッシュ**: リゾルバーはまず、要求されたドメイン名とIPアドレスがローカルキャッシュにあるか確認します。情報があれば、追加の問い合わせをせず結果を返します。

2. **再帰クエリ**: キャッシュに情報がない場合、リゾルバーは再帰クエリを開始します。最初に「.」（ドット）ゾーンを担当するルートDNSサーバーへ問い合わせます。ルートサーバーは、要求されたドメインのTLDサーバーのIPアドレスを返します。

3. **TLDへの問い合わせ**: リゾルバーは前の手順で特定したTLDサーバーに接続し、そのドメインを担当する権威ネームサーバーのIPアドレスを要求します。

4. **権威ネームサーバーへの問い合わせ**: リゾルバーはTLDサーバーから得た権威ネームサーバーにクエリを送信します。権威ネームサーバーはドメインの正式なレコードを保持し、対応するIPアドレスを返します。

5. **クライアントへの応答**: リゾルバーは権威ネームサーバーからIPアドレスを受け取り、ブラウザーへ返します。ブラウザーは取得したIPアドレスを使ってWebサーバーに接続します。

### DNSキャッシュ

DNSリゾルバーはパフォーマンスを高め、DNSサーバーの負荷を軽減するために応答をキャッシュします。DNSクエリへの応答を受け取ると、ドメイン名とIPアドレスの対応をローカルに保存します。同じドメイン名への次の問い合わせは、DNS階層をたどらずキャッシュから解決できます。

キャッシュは、ローカルリゾルバー、ISPのリゾルバー、ルーターやOSなど複数の場所で使われます。DNS応答のTime-to-Live（TTL）が、レコードをキャッシュする期間を決めます。TTLが切れると、リゾルバーは保存したレコードを破棄し、新しい問い合わせを行います。

#### ローカルDNSキャッシュを消去する

DNSキャッシュを消去すると、一部のDNS関連の問題が解決し、システムが最新のレコードを取得できます。OSごとの手順を紹介します。

##### Windows

WindowsでDNSキャッシュを消去する手順:

1. `Win + R`を押して`cmd`と入力し、Enterキーを押してコマンドプロンプトを開きます。

2. コマンドプロンプトで次のコマンドを入力し、Enterキーを押します。

```bash
ipconfig /flushdns
```

このコマンドはWindowsのDNSリゾルバーキャッシュを消去します。

##### macOS

macOSでDNSキャッシュを消去する手順:

1. 「アプリケーション」>「ユーティリティ」からターミナルを開くか、Spotlightで検索します。

2. ターミナルで次のコマンドを入力し、Enterキーを押します。

```bash
sudo killall -HUP mDNSResponder
```

このコマンドはmacOSでDNS名前解決を担当するmDNSResponderプロセスを再起動します。

##### Linux

LinuxでDNSキャッシュを消去する方法は、ディストリビューションとDNSリゾルバーによって異なります。一般的な方法を2つ紹介します。

1. **systemdを使うシステム（UbuntuやFedoraなど）**:

ターミナルを開き、管理者権限で次のコマンドを実行します。

```bash
sudo systemd-resolve --flush-caches

```

systemd-resolvedをリゾルバーとして使うシステムでDNSキャッシュを消去します。

2. **systemdを使わないシステム**:

ターミナルを開き、管理者権限で次のコマンドを実行します。

```bash
sudo /etc/init.d/nscd restart

```

このコマンドはsystemdを使わないLinuxディストリビューションでDNSをキャッシュするName Service Cache Daemon（nscd）を再起動します。

これらは一般的な手順です。OSのバージョンによってコマンドや方法が少し異なる場合があります。DNSキャッシュの消去で一部の問題は解決できますが、ネットワーク接続の問題すべてが解決するわけではありません。

## ルートDNSシステムの仕組み

ルートDNSシステムはDNSインフラの基盤です。動作の流れを見ていきます。

### 1. ルートゾーンとルートサーバー

ルートDNSシステムは、DNS階層の最上位にある**ルートゾーン**から始まります。ルートゾーンには、.com、.org、.netなどのTLDや、.us、.ukなどの国別コードTLDを担当する権威ネームサーバーの情報があります。

ルートDNSシステムには、AからMの文字で識別される13のルートDNSサーバーがあります。冗長性と信頼性を確保するため、世界中に分散しています。

### 2. エニーキャストルーティング

膨大なDNSトラフィックを処理するため、ルートDNSサーバーは**エニーキャストルーティング**を使います。複数のサーバーが同じIPアドレスを共有し、地理的に分散して配置されます。ネットワークの状態に応じてクエリを適切なサーバーへ送り、負荷を効率よく分散します。

ユーザーがDNSクエリを開始すると、エニーキャストによって近くの利用可能なルートサーバーに要求が届きます。ネットワークは状況に基づいて最短経路のサーバーへルーティングします。エニーキャストは負荷分散を助け、ボトルネックを防ぎます。

### 3. 再帰DNSリゾルバー

DNSリゾルバーがドメイン名のクエリを受け取ると、再帰的な名前解決を開始し、ルートDNSサーバーの1つに問い合わせます。

ルートサーバーは、要求されたTLDを担当するTLDネームサーバーのIPアドレスを紹介します。TLDネームサーバーは、そのTLD内のドメインを担当する権威ネームサーバーの情報を保持しています。

### 4. 紹介応答と権威ネームサーバー

ルートサーバーから紹介を受けると、リゾルバーは該当するTLDネームサーバーへ問い合わせます。

TLDネームサーバーは次の紹介を返し、要求されたドメインの権威ネームサーバーのIPアドレスを示します。

その後、リゾルバーは権威ネームサーバーにドメイン名に対応するIPアドレスを要求します。

### 5. キャッシュとTTL

DNS名前解決では、キャッシュがパフォーマンスを高め、DNSサーバーの負荷を軽減します。DNSリゾルバーはドメイン名とIPアドレスの対応を保存します。

DNSレコードはTime-to-Live（TTL）で指定された期間キャッシュされます。TTLはレコードが有効な期間を示します。期限が切れると、リゾルバーはキャッシュを破棄し、最新のIPアドレスを取得するため新たに問い合わせます。

### 6. 連携と管理

ルートDNSシステムは、Internet Corporation for Assigned Names and Numbers（ICANN）とルートサーバー運用者の連携で管理されます。

ICANNはDNS全体の管理と調整を監督し、ルートサーバー運用者と協力します。両者は13のルートDNSサーバーとそのIPアドレスの情報を含むルートゾーンファイルを維持します。

ルートサーバー運用者はルートDNSサーバーの運用と可用性を確保し、DNSインフラ全体の安定性と回復力を支えます。

ルートDNSシステムはDNS名前解決の出発点です。ドメイン名とIPアドレスの対応を可能にし、Webサイトやその他のインターネットリソースへの効率的なアクセスを支えます。

#### 13のルートDNSサーバー

13のルートDNSサーバーはAからMの文字で識別されます。冗長性と耐障害性のため、それぞれのサーバーは複数の物理拠点で運用されます。.com、.org、.netなどのTLDや、.us、.ukなどの国別コードTLDを含むルートゾーンのクエリを処理します。

#### ICANNとルートDNSの管理

Internet Corporation for Assigned Names and Numbers（**ICANN**）は、DNSの管理と調整、IPアドレスの割り当てを担当します。ICANNはルートサーバー運用者と協力してルートDNSの安定性とセキュリティを保ちます。両者は13のルートサーバーとIPアドレスの情報を含むルートゾーンファイルを維持します。

## DNSレコードの種類と用途

{{< youtube id="HnUDtycXSNE" >}}

DNSレコードはDomain Name System（DNS）の重要な要素で、ドメイン名に関する情報を提供します。代表的なレコードの種類と用途を紹介します。

| レコードの種類 | 説明 | 例 |
|-------------|-----------------------------------------------------------------------------|-------------------------------------------|
| A | ドメイン名をIPv4アドレスに対応付けます。 | `example.com     IN A 192.0.2.1` |
| AAAA | ドメイン名をIPv6アドレスに対応付けます。 | `example.com     IN AAAA 2001:db8::1` |
| CNAME | エイリアス（正規名）を実際のドメイン名に対応付けます。 | `www.example.com IN CNAME example.com` |
| MX | ドメイン宛てのメールを受信するメールサーバーを示します。 | `example.com     IN MX 10 mail.example.com` |
| TXT | 任意のテキストを保存します。SPF、DKIM、ドメイン検証などでよく使います。 | `example.com     IN TXT "v=spf1 a mx -all"`|
| NS | ドメインの権威ネームサーバーを示します。 | `example.com     IN NS ns1.example.com` |
| SOA | ゾーンの全般的な情報を示します（start of authorityレコード）。 | `example.com     IN SOA ns1.example.com` |
| SRV | ドメインが提供する特定サービスの場所を示します。 | `_service._proto.example.com IN SRV 10 20 5060 target.example.com` |
| PTR | IPアドレスをドメイン名に対応付けます（逆引きDNS）。 | `1.2.0.192.in-addr.arpa IN PTR example.com` |

### 1. Aレコード（アドレスレコード）

**Aレコード**はドメイン名をIPv4アドレスに対応付けます。最も基本的で一般的なDNSレコードです。ブラウザーにドメイン名を入力すると、サイトをホストするWebサーバーのIPアドレスを見つけるために使われます。

### 2. AAAAレコード（IPv6アドレスレコード）

**AAAAレコード**はAレコードと同じ目的で使われますが、ドメイン名をIPv6アドレスに対応付けます。IPv6への移行に伴い、IPv6ネットワークでの接続に重要性が高まっています。

### 3. CNAMEレコード（正規名レコード）

**CNAMEレコード**はドメインのエイリアスまたは正規名を作成します。あるドメインやサブドメインを別のドメインやサブドメインへ向ける場合に使います。たとえば"www"を"mywebsite.com"へ向けるCNAMEを設定できます。

### 4. MXレコード（メール交換レコード）

**MXレコード**はドメイン宛てのメールを受け取るメールサーバーを指定します。複数のMXレコードに優先度を設定すると、プライマリサーバーが利用できない場合に試す順番を決められます。

### 5. TXTレコード（テキストレコード）

**TXTレコード**はドメインに関連付けられたテキスト情報を保存します。ドメイン検証、メール認証用のSender Policy Framework（SPF）レコード、一般的な情報やメモなどに使われます。

### 6. SRVレコード（サービスレコード）

**SRVレコード**はドメイン内の特定サービスやリソースの場所を定義します。VoIP、インスタントメッセージ、特定のサーバーやサービスを探す必要があるアプリケーションで使われます。

### 7. NSレコード（ネームサーバーレコード）

**NSレコード**はドメインの権威ネームサーバーを指定します。DNSリゾルバーはNSレコードを使い、ドメインのDNSレコードを保持するサーバーを特定します。

### 8. PTRレコード（ポインターレコード）

**PTRレコード**は逆引きDNSでIPアドレスをドメイン名に対応付けます。メールサーバーの身元確認やスパム対策に使われます。逆引きDNSはメールサーバーの正当性を検証する際にも使われます。

### 9. SOAレコード（権威開始レコード）

**SOAレコード**はドメインの管理情報を含みます。プライマリ権威ネームサーバー、ドメイン管理者の連絡先メールアドレス、DNSレコードの各種時間パラメーターなどを指定します。

ここで紹介したのは、数多くあるDNSレコードの一部です。各レコードが固有の役割を担い、ドメイン名を関連するリソースへ効率よく正確に解決します。

## OS別のDNSトラブルシューティングコマンド

DNSの問題が起きたとき、診断コマンドで原因を特定できます。OSごとによく使うコマンドを紹介します。

### Windows

#### 1. `ipconfig /flushdns`

このコマンドはWindowsのDNSキャッシュを消去します。古いDNSレコードや誤ったレコードが原因の問題に役立ちます。コマンドプロンプトを開いて実行します。

#### 2. `ipconfig /all`

`ipconfig /all`はWindowsのネットワークインターフェース情報を表示し、設定済みのDNSサーバーも確認できます。正しいDNSサーバーを使用しているか確認する際に役立ちます。

### macOS

#### 1. `sudo killall -HUP mDNSResponder`

このコマンドはmacOSでDNS名前解決を担当するmDNSResponderプロセスを再起動します。DNS設定を更新し、関連する問題を解消する場合があります。ターミナルを開き、管理者権限で実行します。

#### 2. `nslookup`

`nslookup`はDNSレコードの照会、名前解決のテスト、DNSサーバーへの接続確認に使えます。ターミナルで`nslookup`に続けて、調査するドメイン名またはIPアドレスを指定します。

### Linux

#### 1. `systemd-resolve --flush-caches`

DNSリゾルバーにsystemdを使うLinuxでは、`systemd-resolve --flush-caches`でDNSキャッシュを消去できます。古いキャッシュエントリーによる問題に役立ちます。ターミナルで管理者権限を使って実行します。

#### 2. `dig`

`dig`はLinuxで使える多機能なDNS診断ツールです。DNSクエリ、応答、DNSサーバー設定に関する詳しい情報を表示します。`dig`を使って、特定レコードの照会、名前解決のテスト、DNS問題の調査ができます。ターミナルで`dig`に続けて、調べるドメイン名またはIPアドレスを指定します。

これらのコマンドは、各OSでDNSの問題を診断し、解決するために役立ちます。DNS設定、DNSサーバー、接続の問題を調べられます。

コマンドやオプションはOSのバージョンやディストリビューションによって異なる場合があります。詳しい使い方は、使用しているOSのドキュメントを確認してください。

## まとめ

Domain Name System（DNS）とルートDNSはインターネットの動作を支えます。DNSにより、ユーザーは分かりやすいドメイン名でWebサイトへアクセスできます。ルートDNSはDNS階層全体の基盤です。DNSとルートDNSの仕組みを理解すると、Webを使ううえで役立ち、オンラインサービスを支えるインフラも把握できます。
