## DNS ਅਤੇ ਰੂਟ DNS ਕਿਵੇਂ ਕੰਮ ਕਰਦੇ ਹਨ

### ਜਾਣ-ਪਛਾਣ

ਡੋਮੇਨ ਨੇਮ ਸਿਸਟਮ (DNS) ਇੰਟਰਨੈੱਟ ਦੇ ਬੁਨਿਆਦੀ ਢਾਂਚੇ ਦਾ ਅਹਿਮ ਹਿੱਸਾ ਹੈ। ਇਹ IP ਪਤਿਆਂ ਦੀ ਥਾਂ ਡੋਮੇਨ ਨਾਵਾਂ ਨਾਲ ਵੈੱਬਸਾਈਟਾਂ ਖੋਲ੍ਹਣ ਦਿੰਦਾ ਹੈ। DNS ਫ਼ੋਨਬੁੱਕ ਵਾਂਗ ਕੰਮ ਕਰਦਾ ਹੈ ਅਤੇ ਲੋਕਾਂ ਲਈ ਪੜ੍ਹਨਯੋਗ ਡੋਮੇਨ ਨਾਵਾਂ ਨੂੰ ਕੰਪਿਊਟਰਾਂ ਵੱਲੋਂ ਸਮਝੇ ਜਾਂਦੇ IP ਪਤਿਆਂ ਵਿੱਚ ਬਦਲਦਾ ਹੈ। ਰੂਟ DNS ਇਸ ਲੜੀਵਾਰ ਅਤੇ ਵੰਡੇ ਹੋਏ ਸਿਸਟਮ ਦਾ ਕੇਂਦਰ ਹੈ, ਜੋ ਡੋਮੇਨ ਨਾਵਾਂ ਨੂੰ ਹੱਲ ਕਰਦਾ ਹੈ। ਇਹ ਲੇਖ DNS, ਰੂਟ DNS ਅਤੇ ਡੋਮੇਨ ਦੇ ਰਿਕਾਰਡਾਂ ਦਾ ਕੰਮ ਸਮਝਾਉਂਦਾ ਹੈ।

## ਡੋਮੇਨ ਨੇਮ ਸਿਸਟਮ (DNS)

**ਡੋਮੇਨ ਨੇਮ ਸਿਸਟਮ (DNS)** ਇੱਕ ਵਿਕੇਂਦਰੀਕ੍ਰਿਤ ਨਾਮਕਰਨ ਸਿਸਟਮ ਹੈ, ਜੋ ਡੋਮੇਨ ਨਾਵਾਂ ਨੂੰ IP ਪਤਿਆਂ ਨਾਲ ਜੋੜਦਾ ਹੈ। ਬ੍ਰਾਊਜ਼ਰ ਵਿੱਚ ਡੋਮੇਨ ਨਾਮ ਲਿਖ ਕੇ ਵੈੱਬਸਾਈਟਾਂ ਅਤੇ ਹੋਰ ਇੰਟਰਨੈੱਟ ਸਰੋਤ ਖੋਲ੍ਹੇ ਜਾ ਸਕਦੇ ਹਨ। ਇਸ ਨਾਲ ਗੁੰਝਲਦਾਰ IP ਪਤੇ ਯਾਦ ਰੱਖਣ ਦੀ ਲੋੜ ਨਹੀਂ ਰਹਿੰਦੀ।

### DNS ਦੀ ਲੜੀਵਾਰ ਬਣਤਰ

DNS ਕਈ ਪੱਧਰਾਂ ਵਾਲੀ ਲੜੀਵਾਰ ਬਣਤਰ ਵਿੱਚ ਚੱਲਦਾ ਹੈ। ਸਭ ਤੋਂ ਉੱਪਰ ਰੂਟ ਜ਼ੋਨ ਹੁੰਦਾ ਹੈ, ਫਿਰ ਟੌਪ-ਲੈਵਲ ਡੋਮੇਨ (TLD), ਦੂਜੇ ਪੱਧਰ ਦੇ ਡੋਮੇਨ ਅਤੇ ਸਬਡੋਮੇਨ ਆਉਂਦੇ ਹਨ। ਹਰ ਪੱਧਰ ਪੂਰੇ ਡੋਮੇਨ ਨਾਮ ਦਾ ਹਿੱਸਾ ਹੁੰਦਾ ਹੈ। `www.example.com` ਵਿੱਚ "www" ਸਬਡੋਮੇਨ, "example" ਦੂਜੇ ਪੱਧਰ ਦਾ ਡੋਮੇਨ ਅਤੇ "com" TLD ਹੈ।

### DNS ਨਾਮ ਹੱਲ ਕਰਨ ਦੀ ਪ੍ਰਕਿਰਿਆ

ਜਦੋਂ ਤੁਸੀਂ ਬ੍ਰਾਊਜ਼ਰ ਵਿੱਚ ਡੋਮੇਨ ਨਾਮ ਲਿਖਦੇ ਹੋ, DNS ਨਾਮ ਹੱਲ ਕਰਨ ਦੀ ਪ੍ਰਕਿਰਿਆ ਸ਼ੁਰੂ ਹੁੰਦੀ ਹੈ। ਬ੍ਰਾਊਜ਼ਰ DNS ਰਿਜ਼ੋਲਵਰ ਨੂੰ ਪੁੱਛਗਿੱਛ ਭੇਜਦਾ ਹੈ, ਜੋ ਆਮ ਤੌਰ 'ਤੇ ਇੰਟਰਨੈੱਟ ਸੇਵਾ ਪ੍ਰਦਾਤਾ (ISP) ਦਿੰਦਾ ਹੈ। ਰਿਜ਼ੋਲਵਰ ਡੋਮੇਨ ਨਾਮ ਹੱਲ ਕਰਕੇ ਸੰਬੰਧਿਤ IP ਪਤਾ ਲੱਭਣ ਲਈ ਕਈ ਕਦਮ ਚੁੱਕਦਾ ਹੈ।

1. **ਸਥਾਨਕ DNS ਕੈਸ਼**: ਰਿਜ਼ੋਲਵਰ ਪਹਿਲਾਂ ਆਪਣੇ ਸਥਾਨਕ ਕੈਸ਼ ਵਿੱਚ ਮੰਗਿਆ ਡੋਮੇਨ ਨਾਮ ਅਤੇ IP ਪਤਾ ਲੱਭਦਾ ਹੈ। ਜਾਣਕਾਰੀ ਮਿਲੇ ਤਾਂ ਉਹ ਸਿੱਧਾ ਨਤੀਜਾ ਵਾਪਸ ਕਰਦਾ ਹੈ।

2. **ਆਵਰਤੀ ਪੁੱਛਗਿੱਛ**: ਕੈਸ਼ ਵਿੱਚ ਜਾਣਕਾਰੀ ਨਾ ਹੋਵੇ ਤਾਂ ਰਿਜ਼ੋਲਵਰ ਆਵਰਤੀ ਪੁੱਛਗਿੱਛ ਸ਼ੁਰੂ ਕਰਦਾ ਹੈ। ਪਹਿਲਾਂ ਉਹ "." (ਬਿੰਦੀ) ਜ਼ੋਨ ਲਈ ਜ਼ਿੰਮੇਵਾਰ ਰੂਟ DNS ਸਰਵਰਾਂ ਨਾਲ ਸੰਪਰਕ ਕਰਦਾ ਹੈ। ਰੂਟ ਸਰਵਰ ਮੰਗੇ ਡੋਮੇਨ ਦੇ TLD ਸਰਵਰਾਂ ਦੇ IP ਪਤੇ ਦਿੰਦੇ ਹਨ।

3. **TLD ਪੁੱਛਗਿੱਛ**: ਰਿਜ਼ੋਲਵਰ ਪਿਛਲੇ ਕਦਮ ਵਿੱਚ ਮਿਲੇ TLD ਸਰਵਰਾਂ ਨਾਲ ਸੰਪਰਕ ਕਰਕੇ ਡੋਮੇਨ ਦੇ ਅਧਿਕਾਰਤ ਨੇਮ ਸਰਵਰਾਂ ਦੇ IP ਪਤੇ ਮੰਗਦਾ ਹੈ।

4. **ਅਧਿਕਾਰਤ ਨੇਮ ਸਰਵਰ ਨੂੰ ਪੁੱਛਗਿੱਛ**: ਰਿਜ਼ੋਲਵਰ TLD ਸਰਵਰਾਂ ਤੋਂ ਮਿਲੇ ਅਧਿਕਾਰਤ ਨੇਮ ਸਰਵਰਾਂ ਨੂੰ ਪੁੱਛਗਿੱਛ ਭੇਜਦਾ ਹੈ। ਇਹ ਸਰਵਰ ਡੋਮੇਨ ਦੇ ਅਧਿਕਾਰਤ ਰਿਕਾਰਡ ਰੱਖਦੇ ਹਨ ਅਤੇ ਨਾਮ ਨਾਲ ਜੁੜਿਆ IP ਪਤਾ ਵਾਪਸ ਕਰਦੇ ਹਨ।

5. **ਕਲਾਇੰਟ ਨੂੰ ਜਵਾਬ**: ਰਿਜ਼ੋਲਵਰ ਅਧਿਕਾਰਤ ਨੇਮ ਸਰਵਰਾਂ ਤੋਂ IP ਪਤਾ ਲੈ ਕੇ ਬ੍ਰਾਊਜ਼ਰ ਨੂੰ ਦਿੰਦਾ ਹੈ। ਫਿਰ ਬ੍ਰਾਊਜ਼ਰ ਉਸ ਪਤੇ ਨਾਲ ਵੈੱਬ ਸਰਵਰ ਨਾਲ ਜੁੜਦਾ ਹੈ।

### DNS ਕੈਸ਼ਿੰਗ

DNS ਰਿਜ਼ੋਲਵਰ ਕਾਰਗੁਜ਼ਾਰੀ ਸੁਧਾਰਨ ਅਤੇ DNS ਸਰਵਰਾਂ ਦਾ ਭਾਰ ਘਟਾਉਣ ਲਈ ਕੈਸ਼ਿੰਗ ਵਰਤਦੇ ਹਨ। ਜਵਾਬ ਮਿਲਣ ਤੋਂ ਬਾਅਦ ਰਿਜ਼ੋਲਵਰ ਡੋਮੇਨ ਨਾਮ ਅਤੇ IP ਪਤੇ ਦਾ ਜੋੜ ਸਥਾਨਕ ਤੌਰ 'ਤੇ ਸੰਭਾਲ ਲੈਂਦਾ ਹੈ। ਉਸੇ ਨਾਮ ਦੀ ਅਗਲੀ ਪੁੱਛਗਿੱਛ ਦਾ ਜਵਾਬ DNS ਲੜੀ ਨੂੰ ਮੁੜ ਚੈੱਕ ਕੀਤੇ ਬਿਨਾਂ ਕੈਸ਼ ਤੋਂ ਮਿਲ ਸਕਦਾ ਹੈ।

ਕੈਸ਼ਿੰਗ ਕਈ ਪੱਧਰਾਂ 'ਤੇ ਹੁੰਦੀ ਹੈ, ਜਿਵੇਂ ਸਥਾਨਕ ਰਿਜ਼ੋਲਵਰ, ISP ਦਾ ਰਿਜ਼ੋਲਵਰ ਅਤੇ ਰਾਊਟਰਾਂ ਜਾਂ ਓਪਰੇਟਿੰਗ ਸਿਸਟਮਾਂ ਵਰਗੇ ਯੰਤਰ। DNS ਜਵਾਬ ਵਿੱਚ Time-to-Live (TTL) ਮੁੱਲ ਦੱਸਦਾ ਹੈ ਕਿ ਰਿਕਾਰਡ ਕਿੰਨਾ ਸਮਾਂ ਕੈਸ਼ ਵਿੱਚ ਰਹੇਗਾ। TTL ਮੁੱਕਣ 'ਤੇ ਰਿਜ਼ੋਲਵਰ ਰਿਕਾਰਡ ਮਿਟਾ ਕੇ ਨਵੀਂ ਪੁੱਛਗਿੱਛ ਕਰਦਾ ਹੈ।

#### ਆਪਣਾ ਸਥਾਨਕ DNS ਕੈਸ਼ ਸਾਫ਼ ਕਰੋ

DNS ਕੈਸ਼ ਸਾਫ਼ ਕਰਨ ਨਾਲ ਕੁਝ DNS ਸਮੱਸਿਆਵਾਂ ਹੱਲ ਹੋ ਸਕਦੀਆਂ ਹਨ ਅਤੇ ਸਿਸਟਮ ਨਵੇਂ ਰਿਕਾਰਡ ਲੈਂਦਾ ਹੈ। ਵੱਖ-ਵੱਖ ਓਪਰੇਟਿੰਗ ਸਿਸਟਮਾਂ ਲਈ ਤਰੀਕੇ ਇਹ ਹਨ:

##### Windows

Windows ਵਿੱਚ DNS ਕੈਸ਼ ਸਾਫ਼ ਕਰਨ ਲਈ:

1. `Win + R` ਦਬਾਓ, `cmd` ਲਿਖੋ ਅਤੇ Enter ਦਬਾ ਕੇ ਕਮਾਂਡ ਪ੍ਰੌਂਪਟ ਖੋਲ੍ਹੋ।

2. ਕਮਾਂਡ ਪ੍ਰੌਂਪਟ ਵਿੱਚ ਹੇਠਾਂ ਦਿੱਤੀ ਕਮਾਂਡ ਲਿਖੋ ਅਤੇ Enter ਦਬਾਓ:

```bash
ipconfig /flushdns
```

ਇਹ ਕਮਾਂਡ Windows ਸਿਸਟਮ ਵਿੱਚ DNS ਰਿਜ਼ੋਲਵਰ ਦਾ ਕੈਸ਼ ਸਾਫ਼ ਕਰਦੀ ਹੈ।

##### macOS

macOS ਵਿੱਚ DNS ਕੈਸ਼ ਸਾਫ਼ ਕਰਨ ਲਈ:

1. Applications > Utilities ਤੋਂ ਟਰਮੀਨਲ ਖੋਲ੍ਹੋ ਜਾਂ Spotlight ਵਿੱਚ ਲੱਭੋ।

2. ਟਰਮੀਨਲ ਵਿੱਚ ਹੇਠਾਂ ਦਿੱਤੀ ਕਮਾਂਡ ਲਿਖੋ ਅਤੇ Enter ਦਬਾਓ:

```bash
sudo killall -HUP mDNSResponder
```

ਇਹ ਕਮਾਂਡ macOS ਵਿੱਚ DNS ਹੱਲ ਕਰਨ ਵਾਲੀ mDNSResponder ਪ੍ਰਕਿਰਿਆ ਮੁੜ ਸ਼ੁਰੂ ਕਰਦੀ ਹੈ।

##### Linux

Linux ਵਿੱਚ DNS ਕੈਸ਼ ਸਾਫ਼ ਕਰਨ ਦਾ ਤਰੀਕਾ ਡਿਸਟ੍ਰਿਬਿਊਸ਼ਨ ਅਤੇ DNS ਰਿਜ਼ੋਲਵਰ 'ਤੇ ਨਿਰਭਰ ਕਰਦਾ ਹੈ। ਦੋ ਆਮ ਤਰੀਕੇ:

1. **systemd-ਆਧਾਰਿਤ ਸਿਸਟਮ (ਜਿਵੇਂ Ubuntu, Fedora)**:

ਟਰਮੀਨਲ ਖੋਲ੍ਹੋ ਅਤੇ ਪ੍ਰਸ਼ਾਸਕ ਅਧਿਕਾਰਾਂ ਨਾਲ ਇਹ ਕਮਾਂਡ ਚਲਾਓ:

```bash
sudo systemd-resolve --flush-caches

```

ਇਹ ਕਮਾਂਡ ਉਹਨਾਂ ਸਿਸਟਮਾਂ ਵਿੱਚ DNS ਕੈਸ਼ ਸਾਫ਼ ਕਰਦੀ ਹੈ ਜੋ systemd-resolved ਨੂੰ ਰਿਜ਼ੋਲਵਰ ਵਜੋਂ ਵਰਤਦੇ ਹਨ।

2. **systemd ਤੋਂ ਬਿਨਾਂ ਸਿਸਟਮ**:

ਟਰਮੀਨਲ ਖੋਲ੍ਹੋ ਅਤੇ ਪ੍ਰਸ਼ਾਸਕ ਅਧਿਕਾਰਾਂ ਨਾਲ ਇਹ ਕਮਾਂਡ ਚਲਾਓ:

```bash
sudo /etc/init.d/nscd restart

```

ਇਹ ਕਮਾਂਡ Name Service Cache Daemon (nscd) ਮੁੜ ਸ਼ੁਰੂ ਕਰਦੀ ਹੈ, ਜੋ systemd ਤੋਂ ਬਿਨਾਂ Linux ਡਿਸਟ੍ਰਿਬਿਊਸ਼ਨਾਂ ਵਿੱਚ DNS ਕੈਸ਼ ਸੰਭਾਲਦਾ ਹੈ।

ਇਹ ਆਮ ਹਦਾਇਤਾਂ ਹਨ। ਓਪਰੇਟਿੰਗ ਸਿਸਟਮ ਦੇ ਸੰਸਕਰਣ ਮੁਤਾਬਕ ਕਮਾਂਡਾਂ ਅਤੇ ਤਰੀਕੇ ਥੋੜ੍ਹੇ ਵੱਖਰੇ ਹੋ ਸਕਦੇ ਹਨ। DNS ਕੈਸ਼ ਸਾਫ਼ ਕਰਨ ਨਾਲ ਕੁਝ ਸਮੱਸਿਆਵਾਂ ਹੱਲ ਹੁੰਦੀਆਂ ਹਨ, ਪਰ ਹਰ ਨੈੱਟਵਰਕ ਕਨੈਕਸ਼ਨ ਦੀ ਸਮੱਸਿਆ ਨਹੀਂ।

## ਰੂਟ DNS ਸਿਸਟਮ ਕਿਵੇਂ ਕੰਮ ਕਰਦਾ ਹੈ

ਰੂਟ DNS ਸਿਸਟਮ DNS ਬੁਨਿਆਦੀ ਢਾਂਚੇ ਦਾ ਅਹਿਮ ਹਿੱਸਾ ਹੈ। ਇਸਦਾ ਕੰਮ ਕਰਨ ਦਾ ਢੰਗ ਵੇਖੋ:

### 1. ਰੂਟ ਜ਼ੋਨ ਅਤੇ ਰੂਟ ਸਰਵਰ

ਰੂਟ DNS ਸਿਸਟਮ **ਰੂਟ ਜ਼ੋਨ** ਤੋਂ ਸ਼ੁਰੂ ਹੁੰਦਾ ਹੈ, ਜੋ DNS ਲੜੀ ਦਾ ਸਭ ਤੋਂ ਉੱਚਾ ਪੱਧਰ ਹੈ। ਇਸ ਵਿੱਚ ਸਾਰੇ ਟੌਪ-ਲੈਵਲ ਡੋਮੇਨਾਂ (TLD) ਜਿਵੇਂ .com, .org, .net ਅਤੇ ਦੇਸ਼-ਕੋਡ TLD ਜਿਵੇਂ .us, .uk ਦੇ ਅਧਿਕਾਰਤ ਨੇਮ ਸਰਵਰਾਂ ਦੀ ਜਾਣਕਾਰੀ ਹੁੰਦੀ ਹੈ।

ਰੂਟ DNS ਸਿਸਟਮ ਵਿੱਚ A ਤੋਂ M ਤੱਕ ਅੱਖਰਾਂ ਨਾਲ ਪਛਾਣੇ ਜਾਂਦੇ 13 ਰੂਟ ਸਰਵਰ ਹਨ। ਭਰੋਸੇਯੋਗਤਾ ਅਤੇ ਵਾਧੂ ਸਮਰੱਥਾ ਲਈ ਇਹ ਦੁਨੀਆ ਭਰ ਵਿੱਚ ਵੱਖ-ਵੱਖ ਥਾਵਾਂ 'ਤੇ ਵੰਡੇ ਹੋਏ ਹਨ।

### 2. Anycast ਰਾਊਟਿੰਗ

ਵੱਡੀ ਮਾਤਰਾ ਵਿੱਚ DNS ਟ੍ਰੈਫ਼ਿਕ ਸੰਭਾਲਣ ਲਈ ਰੂਟ ਸਰਵਰ **anycast ਰਾਊਟਿੰਗ** ਵਰਤਦੇ ਹਨ। ਕਈ ਸਰਵਰ ਇੱਕੋ IP ਪਤਾ ਸਾਂਝਾ ਕਰਦੇ ਹਨ, ਪਰ ਵੱਖ-ਵੱਖ ਭੂਗੋਲਿਕ ਥਾਵਾਂ 'ਤੇ ਹੁੰਦੇ ਹਨ। ਨੈੱਟਵਰਕ ਦੀ ਹਾਲਤ ਮੁਤਾਬਕ ਪੁੱਛਗਿੱਛ ਢੁੱਕਵੇਂ ਸਰਵਰ ਵੱਲ ਭੇਜੀ ਜਾਂਦੀ ਹੈ, ਜਿਸ ਨਾਲ ਭਾਰ ਵੰਡਿਆ ਜਾਂਦਾ ਹੈ।

ਜਦੋਂ ਵਰਤੋਂਕਾਰ DNS ਪੁੱਛਗਿੱਛ ਸ਼ੁਰੂ ਕਰਦਾ ਹੈ, anycast ਉਸਨੂੰ ਨੇੜਲੇ ਉਪਲਬਧ ਰੂਟ ਸਰਵਰ ਵੱਲ ਭੇਜਦਾ ਹੈ। ਨੈੱਟਵਰਕ ਹਾਲਤ ਦੇ ਆਧਾਰ 'ਤੇ ਬੁਨਿਆਦੀ ਢਾਂਚਾ ਛੋਟਾ ਰਸਤਾ ਚੁਣਦਾ ਹੈ। Anycast ਭਾਰ ਵੰਡਦਾ ਅਤੇ ਰੁਕਾਵਟਾਂ ਘਟਾਉਣ ਵਿੱਚ ਮਦਦ ਕਰਦਾ ਹੈ।

### 3. ਆਵਰਤੀ DNS ਰਿਜ਼ੋਲਵਰ

DNS ਰਿਜ਼ੋਲਵਰ ਨੂੰ ਡੋਮੇਨ ਨਾਮ ਦੀ ਪੁੱਛਗਿੱਛ ਮਿਲਣ 'ਤੇ ਉਹ ਆਵਰਤੀ ਹੱਲ ਸ਼ੁਰੂ ਕਰਦਾ ਹੈ ਅਤੇ ਕਿਸੇ ਰੂਟ ਸਰਵਰ ਨਾਲ ਸੰਪਰਕ ਕਰਦਾ ਹੈ।

ਰੂਟ ਸਰਵਰ ਮੰਗੇ TLD ਲਈ ਜ਼ਿੰਮੇਵਾਰ TLD ਨੇਮ ਸਰਵਰਾਂ ਦੇ IP ਪਤਿਆਂ ਵੱਲ ਹਵਾਲਾ ਦਿੰਦਾ ਹੈ। ਇਹ TLD ਸਰਵਰ ਆਪਣੇ TLD ਅਧੀਨ ਡੋਮੇਨਾਂ ਦੇ ਅਧਿਕਾਰਤ ਨੇਮ ਸਰਵਰਾਂ ਦੀ ਜਾਣਕਾਰੀ ਰੱਖਦੇ ਹਨ।

### 4. ਹਵਾਲੇ ਅਤੇ ਅਧਿਕਾਰਤ ਨੇਮ ਸਰਵਰ

ਰੂਟ ਸਰਵਰ ਤੋਂ ਹਵਾਲਾ ਮਿਲਣ ਤੋਂ ਬਾਅਦ ਰਿਜ਼ੋਲਵਰ ਢੁੱਕਵੇਂ TLD ਨੇਮ ਸਰਵਰ ਨਾਲ ਸੰਪਰਕ ਕਰਦਾ ਹੈ।

TLD ਨੇਮ ਸਰਵਰ ਇੱਕ ਹੋਰ ਹਵਾਲਾ ਦਿੰਦਾ ਹੈ, ਜਿਸ ਵਿੱਚ ਮੰਗੇ ਡੋਮੇਨ ਦੇ ਅਧਿਕਾਰਤ ਨੇਮ ਸਰਵਰਾਂ ਦੇ IP ਪਤੇ ਹੁੰਦੇ ਹਨ।

ਫਿਰ ਰਿਜ਼ੋਲਵਰ ਅਧਿਕਾਰਤ ਨੇਮ ਸਰਵਰਾਂ ਤੋਂ ਡੋਮੇਨ ਨਾਮ ਨਾਲ ਜੁੜਿਆ IP ਪਤਾ ਮੰਗਦਾ ਹੈ।

### 5. ਕੈਸ਼ਿੰਗ ਅਤੇ TTL

DNS ਨਾਮ ਹੱਲ ਕਰਨ ਦੌਰਾਨ ਕੈਸ਼ਿੰਗ ਕਾਰਗੁਜ਼ਾਰੀ ਸੁਧਾਰਦੀ ਅਤੇ DNS ਸਰਵਰਾਂ ਦਾ ਭਾਰ ਘਟਾਉਂਦੀ ਹੈ। DNS ਰਿਜ਼ੋਲਵਰ ਡੋਮੇਨ ਨਾਵਾਂ ਅਤੇ IP ਪਤਿਆਂ ਦੇ ਜੋੜ ਸੰਭਾਲਦੇ ਹਨ।

DNS ਰਿਕਾਰਡ Time-to-Live (TTL) ਮੁੱਲ ਵੱਲੋਂ ਨਿਰਧਾਰਤ ਸਮੇਂ ਤੱਕ ਕੈਸ਼ ਵਿੱਚ ਰਹਿੰਦੇ ਹਨ। TTL ਦੱਸਦਾ ਹੈ ਕਿ ਰਿਕਾਰਡ ਕਿੰਨਾ ਸਮਾਂ ਵੈਧ ਹੈ। ਸਮਾਂ ਮੁੱਕਣ 'ਤੇ ਰਿਜ਼ੋਲਵਰ ਕੈਸ਼ ਤੋਂ ਰਿਕਾਰਡ ਮਿਟਾ ਕੇ ਮੌਜੂਦਾ IP ਪਤੇ ਲਈ ਨਵੀਂ ਪੁੱਛਗਿੱਛ ਕਰਦਾ ਹੈ।

### 6. ਸਹਿਯੋਗ ਅਤੇ ਪ੍ਰਬੰਧਨ

Internet Corporation for Assigned Names and Numbers (ICANN) ਅਤੇ ਰੂਟ ਸਰਵਰ ਸੰਚਾਲਕ ਦੇ ਸਹਿਯੋਗ ਨਾਲ ਰੂਟ DNS ਸਿਸਟਮ ਦਾ ਪ੍ਰਬੰਧ ਹੁੰਦਾ ਹੈ।

ICANN DNS ਦੇ ਸਮੁੱਚੇ ਪ੍ਰਬੰਧ ਅਤੇ ਤਾਲਮੇਲ ਦੀ ਦੇਖ-ਰੇਖ ਕਰਦਾ ਹੈ ਅਤੇ ਰੂਟ ਸਰਵਰ ਆਪਰੇਟਰਾਂ ਨਾਲ ਕੰਮ ਕਰਦਾ ਹੈ। ਉਹ ਮਿਲ ਕੇ ਰੂਟ ਜ਼ੋਨ ਫ਼ਾਈਲ ਸੰਭਾਲਦੇ ਹਨ, ਜਿਸ ਵਿੱਚ 13 ਰੂਟ DNS ਸਰਵਰਾਂ ਅਤੇ ਉਹਨਾਂ ਦੇ IP ਪਤਿਆਂ ਦੀ ਜਾਣਕਾਰੀ ਹੁੰਦੀ ਹੈ।

ਰੂਟ ਸਰਵਰ ਸੰਚਾਲਕ ਰੂਟ DNS ਸਰਵਰਾਂ ਦੇ ਚੱਲਣ ਅਤੇ ਉਪਲਬਧਤਾ ਨੂੰ ਯਕੀਨੀ ਬਣਾਉਂਦੇ ਹਨ। ਇਸ ਨਾਲ DNS ਬੁਨਿਆਦੀ ਢਾਂਚੇ ਦੀ ਸਥਿਰਤਾ ਅਤੇ ਲਚਕ ਬਣੀ ਰਹਿੰਦੀ ਹੈ।

ਰੂਟ DNS ਸਿਸਟਮ DNS ਹੱਲ ਦਾ ਸ਼ੁਰੂਆਤੀ ਬਿੰਦੂ ਹੈ। ਇਹ ਡੋਮੇਨ ਨਾਵਾਂ ਨੂੰ IP ਪਤਿਆਂ ਨਾਲ ਜੋੜਦਾ ਹੈ ਅਤੇ ਵੈੱਬਸਾਈਟਾਂ ਤੇ ਹੋਰ ਇੰਟਰਨੈੱਟ ਸਰੋਤਾਂ ਤੱਕ ਪ੍ਰਭਾਵਸ਼ਾਲੀ ਪਹੁੰਚ ਦਿੰਦਾ ਹੈ।

#### 13 ਰੂਟ DNS ਸਰਵਰ

13 ਰੂਟ DNS ਸਰਵਰ A ਤੋਂ M ਅੱਖਰਾਂ ਨਾਲ ਪਛਾਣੇ ਜਾਂਦੇ ਹਨ। ਵਾਧੂ ਸਮਰੱਥਾ ਅਤੇ ਖ਼ਰਾਬੀ ਸਹਿਣਸ਼ੀਲਤਾ ਲਈ ਹਰ ਸਰਵਰ ਵੱਖ-ਵੱਖ ਭੌਤਿਕ ਥਾਵਾਂ 'ਤੇ ਚਲਾਇਆ ਜਾਂਦਾ ਹੈ। ਇਹ ਰੂਟ ਜ਼ੋਨ ਲਈ ਪੁੱਛਗਿੱਛਾਂ ਸੰਭਾਲਦੇ ਹਨ, ਜਿਸ ਵਿੱਚ .com, .org, .net ਅਤੇ .us, .uk ਵਰਗੇ ਦੇਸ਼-ਕੋਡ TLD ਸ਼ਾਮਲ ਹਨ।

#### ICANN ਅਤੇ ਰੂਟ DNS ਪ੍ਰਬੰਧਨ

Internet Corporation for Assigned Names and Numbers (**ICANN**) DNS ਪ੍ਰਬੰਧਨ ਅਤੇ ਤਾਲਮੇਲ ਅਤੇ IP ਪਤਿਆਂ ਦੀ ਵੰਡ ਲਈ ਜ਼ਿੰਮੇਵਾਰ ਹੈ। ਰੂਟ DNS ਦੀ ਸਥਿਰਤਾ ਅਤੇ ਸੁਰੱਖਿਆ ਲਈ ICANN ਰੂਟ ਸਰਵਰ ਸੰਚਾਲਕ ਨਾਲ ਕੰਮ ਕਰਦਾ ਹੈ। ਉਹ ਮਿਲ ਕੇ 13 ਰੂਟ ਸਰਵਰਾਂ ਅਤੇ ਉਨ੍ਹਾਂ ਦੇ IP ਪਤਿਆਂ ਦੀ ਜਾਣਕਾਰੀ ਵਾਲੀ ਰੂਟ ਜ਼ੋਨ ਫ਼ਾਈਲ ਸੰਭਾਲਦੇ ਹਨ।

## DNS ਰਿਕਾਰਡਾਂ ਦੀਆਂ ਕਿਸਮਾਂ ਅਤੇ ਉਨ੍ਹਾਂ ਦੇ ਕੰਮ

{{< youtube id="HnUDtycXSNE" >}}

DNS ਰਿਕਾਰਡ ਡੋਮੇਨ ਨੇਮ ਸਿਸਟਮ ਦੇ ਅਹਿਮ ਹਿੱਸੇ ਹਨ। ਇਹ ਡੋਮੇਨ ਨਾਮ ਨਾਲ ਜੁੜੀ ਵੱਖ-ਵੱਖ ਜਾਣਕਾਰੀ ਦਿੰਦੇ ਹਨ। ਕੁਝ ਆਮ ਕਿਸਮਾਂ ਅਤੇ ਉਨ੍ਹਾਂ ਦੇ ਕੰਮ ਇਹ ਹਨ:

| ਰਿਕਾਰਡ ਦੀ ਕਿਸਮ | ਵੇਰਵਾ | ਉਦਾਹਰਨ |
|-------------|-----------------------------------------------------------------------------|-------------------------------------------|
| A | ਡੋਮੇਨ ਨਾਮ ਨੂੰ IPv4 ਪਤੇ ਨਾਲ ਜੋੜਦਾ ਹੈ। | `example.com     IN A 192.0.2.1` |
| AAAA | ਡੋਮੇਨ ਨਾਮ ਨੂੰ IPv6 ਪਤੇ ਨਾਲ ਜੋੜਦਾ ਹੈ। | `example.com     IN AAAA 2001:db8::1` |
| CNAME | ਉਪਨਾਮ (ਮਿਆਰੀ ਨਾਮ) ਨੂੰ ਅਸਲ ਡੋਮੇਨ ਨਾਮ ਨਾਲ ਜੋੜਦਾ ਹੈ। | `www.example.com IN CNAME example.com` |
| MX | ਡੋਮੇਨ ਲਈ ਆਉਣ ਵਾਲੀ ਈਮੇਲ ਲੈਣ ਵਾਲੇ ਮੇਲ ਸਰਵਰ ਦੱਸਦਾ ਹੈ। | `example.com     IN MX 10 mail.example.com` |
| TXT | ਮਨਮਾਨਾ ਲਿਖਤ ਸੰਭਾਲਦਾ ਹੈ, ਅਕਸਰ SPF, DKIM ਜਾਂ ਡੋਮੇਨ ਜਾਂਚ ਲਈ। | `example.com     IN TXT "v=spf1 a mx -all"`|
| NS | ਡੋਮੇਨ ਦੇ ਅਧਿਕਾਰਤ ਨੇਮ ਸਰਵਰ ਦੱਸਦਾ ਹੈ। | `example.com     IN NS ns1.example.com` |
| SOA | ਜ਼ੋਨ ਦੇ ਆਮ ਗੁਣ ਦੱਸਦਾ ਹੈ (start of authority ਰਿਕਾਰਡ)। | `example.com     IN SOA ns1.example.com` |
| SRV | ਡੋਮੇਨ ਵੱਲੋਂ ਦਿੱਤੀ ਜਾਂਦੀ ਖ਼ਾਸ ਸੇਵਾ ਦੀ ਥਾਂ ਦੱਸਦਾ ਹੈ। | `_service._proto.example.com IN SRV 10 20 5060 target.example.com` |
| PTR | IP ਪਤੇ ਨੂੰ ਡੋਮੇਨ ਨਾਮ ਨਾਲ ਜੋੜਦਾ ਹੈ (ਉਲਟੀ DNS ਖੋਜ)। | `1.2.0.192.in-addr.arpa IN PTR example.com` |

### 1. A ਰਿਕਾਰਡ (ਪਤਾ ਰਿਕਾਰਡ)

**A ਰਿਕਾਰਡ** ਡੋਮੇਨ ਨਾਮ ਨੂੰ IPv4 ਪਤੇ ਨਾਲ ਜੋੜਦਾ ਹੈ। ਇਹ ਸਭ ਤੋਂ ਸਰਲ ਅਤੇ ਆਮ DNS ਰਿਕਾਰਡ ਹੈ। ਬ੍ਰਾਊਜ਼ਰ ਵਿੱਚ ਡੋਮੇਨ ਨਾਮ ਲਿਖਣ 'ਤੇ ਇਹ ਵੈੱਬਸਾਈਟ ਹੋਸਟ ਕਰਨ ਵਾਲੇ ਵੈੱਬ ਸਰਵਰ ਦਾ IP ਪਤਾ ਲੱਭਣ ਵਿੱਚ ਮਦਦ ਕਰਦਾ ਹੈ।

### 2. AAAA ਰਿਕਾਰਡ (IPv6 ਪਤਾ ਰਿਕਾਰਡ)

**AAAA ਰਿਕਾਰਡ** A ਰਿਕਾਰਡ ਵਾਂਗ ਕੰਮ ਕਰਦਾ ਹੈ, ਪਰ ਡੋਮੇਨ ਨਾਮ ਨੂੰ IPv6 ਪਤੇ ਨਾਲ ਜੋੜਦਾ ਹੈ। IPv6 ਵੱਲ ਬਦਲਾਅ ਨਾਲ IPv6 ਨੈੱਟਵਰਕਾਂ 'ਤੇ ਸੰਪਰਕ ਲਈ ਇਸਦੀ ਅਹਿਮੀਅਤ ਵਧ ਰਹੀ ਹੈ।

### 3. CNAME ਰਿਕਾਰਡ (ਮਿਆਰੀ ਨਾਮ ਰਿਕਾਰਡ)

**CNAME ਰਿਕਾਰਡ** ਡੋਮੇਨ ਲਈ ਉਪਨਾਮ ਜਾਂ ਮਿਆਰੀ ਨਾਮ ਬਣਾਉਂਦਾ ਹੈ। ਜਦੋਂ ਕਿਸੇ ਡੋਮੇਨ ਜਾਂ ਸਬਡੋਮੇਨ ਨੂੰ ਹੋਰ ਡੋਮੇਨ ਵੱਲ ਭੇਜਣਾ ਹੋਵੇ ਤਾਂ ਇਸਦੀ ਵਰਤੋਂ ਕਰੋ। ਉਦਾਹਰਨ ਵਜੋਂ, CNAME "www" ਨੂੰ "mywebsite.com" ਵੱਲ ਭੇਜ ਸਕਦਾ ਹੈ।

### 4. MX ਰਿਕਾਰਡ (ਮੇਲ ਅਦਲਾ-ਬਦਲੀ ਰਿਕਾਰਡ)

**MX ਰਿਕਾਰਡ** ਡੋਮੇਨ ਦੀ ਆਉਣ ਵਾਲੀ ਈਮੇਲ ਪ੍ਰਾਪਤ ਕਰਨ ਵਾਲੇ ਮੇਲ ਸਰਵਰ ਦੀ ਪਛਾਣ ਕਰਦਾ ਹੈ। ਕਈ MX ਰਿਕਾਰਡਾਂ ਦੀ ਤਰਜੀਹ ਨਿਰਧਾਰਤ ਕਰਦੀ ਹੈ ਕਿ ਮੁੱਖ ਸਰਵਰ ਉਪਲਬਧ ਨਾ ਹੋਵੇ ਤਾਂ ਕਿਹੜਾ ਸਰਵਰ ਪਹਿਲਾਂ ਅਜ਼ਮਾਇਆ ਜਾਵੇ।

### 5. TXT ਰਿਕਾਰਡ (ਲਿਖਤ ਰਿਕਾਰਡ)

**TXT ਰਿਕਾਰਡ** ਡੋਮੇਨ ਨਾਲ ਜੁੜੀ ਲਿਖਤੀ ਜਾਣਕਾਰੀ ਰੱਖਦਾ ਹੈ। ਇਸਦੀ ਵਰਤੋਂ ਡੋਮੇਨ ਦੀ ਜਾਂਚ, ਈਮੇਲ ਪ੍ਰਮਾਣਿਕਤਾ ਲਈ Sender Policy Framework (SPF) ਰਿਕਾਰਡ ਅਤੇ ਆਮ ਜਾਣਕਾਰੀ ਜਾਂ ਨੋਟ ਲਈ ਹੁੰਦੀ ਹੈ।

### 6. SRV ਰਿਕਾਰਡ (ਸੇਵਾ ਰਿਕਾਰਡ)

**SRV ਰਿਕਾਰਡ** ਡੋਮੇਨ ਵਿੱਚ ਕਿਸੇ ਖ਼ਾਸ ਸੇਵਾ ਜਾਂ ਸਰੋਤ ਦੀ ਥਾਂ ਦੱਸਦਾ ਹੈ। ਇਹ VoIP, ਤੁਰੰਤ ਸੁਨੇਹਿਆਂ ਅਤੇ ਉਹਨਾਂ ਐਪਲੀਕੇਸ਼ਨਾਂ ਵਿੱਚ ਵਰਤਿਆ ਜਾਂਦਾ ਹੈ ਜਿਨ੍ਹਾਂ ਨੂੰ ਖ਼ਾਸ ਸਰਵਰ ਜਾਂ ਸੇਵਾਵਾਂ ਲੱਭਣੀਆਂ ਹੁੰਦੀਆਂ ਹਨ।

### 7. NS ਰਿਕਾਰਡ (ਨੇਮ ਸਰਵਰ ਰਿਕਾਰਡ)

**NS ਰਿਕਾਰਡ** ਡੋਮੇਨ ਦੇ ਅਧਿਕਾਰਤ ਨੇਮ ਸਰਵਰ ਦੱਸਦਾ ਹੈ। ਇਹ ਸਰਵਰ ਡੋਮੇਨ ਦੇ DNS ਰਿਕਾਰਡ ਰੱਖਦੇ ਹਨ। ਰਿਜ਼ੋਲਵਰ NS ਰਿਕਾਰਡਾਂ ਰਾਹੀਂ ਅਧਿਕਾਰਤ ਨੇਮ ਸਰਵਰ ਲੱਭਦਾ ਹੈ।

### 8. PTR ਰਿਕਾਰਡ (ਸੂਚਕ ਰਿਕਾਰਡ)

**PTR ਰਿਕਾਰਡ** ਉਲਟੀ DNS ਖੋਜ ਵਿੱਚ IP ਪਤੇ ਨੂੰ ਡੋਮੇਨ ਨਾਮ ਨਾਲ ਜੋੜਦਾ ਹੈ। ਇਸਦੀ ਵਰਤੋਂ ਮੇਲ ਸਰਵਰ ਦੀ ਪਛਾਣ ਜਾਂਚਣ ਅਤੇ ਸਪੈਮ ਘਟਾਉਣ ਲਈ ਹੁੰਦੀ ਹੈ। ਉਲਟੀ DNS ਖੋਜ ਈਮੇਲ ਸਰਵਰ ਦੀ ਪ੍ਰਮਾਣਿਕਤਾ ਜਾਂਚਣ ਵਿੱਚ ਮਦਦ ਕਰਦੀ ਹੈ।

### 9. SOA ਰਿਕਾਰਡ (ਅਧਿਕਾਰ ਸ਼ੁਰੂ ਰਿਕਾਰਡ)

**SOA ਰਿਕਾਰਡ** ਡੋਮੇਨ ਦੀ ਪ੍ਰਬੰਧਕੀ ਜਾਣਕਾਰੀ ਰੱਖਦਾ ਹੈ, ਜਿਵੇਂ ਮੁੱਖ ਅਧਿਕਾਰਤ ਨੇਮ ਸਰਵਰ, ਡੋਮੇਨ ਪ੍ਰਸ਼ਾਸਕ ਦਾ ਈਮੇਲ ਪਤਾ ਅਤੇ DNS ਰਿਕਾਰਡਾਂ ਦੇ ਸਮੇਂ-ਸਬੰਧੀ ਪੈਰਾਮੀਟਰ।

ਇਹ ਉਪਲਬਧ ਕਈ DNS ਰਿਕਾਰਡਾਂ ਵਿੱਚੋਂ ਕੁਝ ਉਦਾਹਰਨ ਹਨ। ਹਰ ਰਿਕਾਰਡ ਦਾ ਆਪਣਾ ਕੰਮ ਹੈ ਅਤੇ ਇਹ ਡੋਮੇਨ ਨਾਵਾਂ ਨੂੰ ਸਬੰਧਤ ਸਰੋਤਾਂ ਤੱਕ ਸਹੀ ਅਤੇ ਪ੍ਰਭਾਵਸ਼ਾਲੀ ਢੰਗ ਨਾਲ ਹੱਲ ਕਰਨ ਵਿੱਚ ਮਦਦ ਕਰਦਾ ਹੈ।

## ਵੱਖ-ਵੱਖ ਓਪਰੇਟਿੰਗ ਸਿਸਟਮਾਂ ਲਈ DNS ਜਾਂਚ ਕਮਾਂਡਾਂ

DNS ਸਮੱਸਿਆ ਆਉਣ 'ਤੇ ਜਾਂਚ ਕਮਾਂਡਾਂ ਕਾਰਨ ਲੱਭਣ ਵਿੱਚ ਮਦਦ ਕਰਦੀਆਂ ਹਨ। ਵੱਖ-ਵੱਖ ਓਪਰੇਟਿੰਗ ਸਿਸਟਮਾਂ ਲਈ ਕੁਝ ਆਮ ਕਮਾਂਡਾਂ:

### Windows

#### 1. `ipconfig /flushdns`

ਇਹ ਕਮਾਂਡ Windows ਵਿੱਚ DNS ਕੈਸ਼ ਸਾਫ਼ ਕਰਦੀ ਹੈ ਅਤੇ ਪੁਰਾਣੇ ਜਾਂ ਗਲਤ ਰਿਕਾਰਡਾਂ ਨਾਲ ਜੁੜੀਆਂ ਸਮੱਸਿਆਵਾਂ ਹੱਲ ਕਰਨ ਵਿੱਚ ਮਦਦ ਕਰ ਸਕਦੀ ਹੈ। ਕਮਾਂਡ ਪ੍ਰੌਂਪਟ ਖੋਲ੍ਹ ਕੇ ਇਹ ਕਮਾਂਡ ਚਲਾਓ।

#### 2. `ipconfig /all`

`ipconfig /all` Windows ਨੈੱਟਵਰਕ ਇੰਟਰਫੇਸਾਂ ਦੀ ਵਿਸਥਾਰਪੂਰਵਕ ਜਾਣਕਾਰੀ ਦਿਖਾਉਂਦਾ ਹੈ, ਜਿਸ ਵਿੱਚ ਸੰਰਚਿਤ DNS ਸਰਵਰ ਵੀ ਸ਼ਾਮਲ ਹਨ। ਇਸ ਨਾਲ ਪਤਾ ਲੱਗਦਾ ਹੈ ਕਿ ਸਹੀ DNS ਸਰਵਰ ਵਰਤੇ ਜਾ ਰਹੇ ਹਨ ਜਾਂ ਨਹੀਂ।

### macOS

#### 1. `sudo killall -HUP mDNSResponder`

ਇਹ ਕਮਾਂਡ macOS ਵਿੱਚ DNS ਹੱਲ ਕਰਨ ਵਾਲੀ mDNSResponder ਪ੍ਰਕਿਰਿਆ ਮੁੜ ਚਾਲੂ ਕਰਦੀ ਹੈ। ਇਸ ਨਾਲ DNS ਸੈਟਿੰਗਾਂ ਤਾਜ਼ਾ ਹੋ ਸਕਦੀਆਂ ਹਨ ਅਤੇ ਕੁਝ ਸਮੱਸਿਆਵਾਂ ਹੱਲ ਹੋ ਸਕਦੀਆਂ ਹਨ। ਟਰਮੀਨਲ ਖੋਲ੍ਹ ਕੇ ਪ੍ਰਸ਼ਾਸਕ ਅਧਿਕਾਰਾਂ ਨਾਲ ਚਲਾਓ।

#### 2. `nslookup`

`nslookup` ਨਾਲ DNS ਰਿਕਾਰਡ ਪੁੱਛੇ ਜਾ ਸਕਦੇ ਹਨ, ਨਾਮ ਹੱਲ ਦੀ ਜਾਂਚ ਕੀਤੀ ਜਾ ਸਕਦੀ ਹੈ ਅਤੇ DNS ਸਰਵਰਾਂ ਨਾਲ ਸੰਪਰਕ ਪਰਖਿਆ ਜਾ ਸਕਦਾ ਹੈ। ਟਰਮੀਨਲ ਵਿੱਚ `nslookup` ਤੋਂ ਬਾਅਦ ਜਾਂਚਣ ਵਾਲਾ ਡੋਮੇਨ ਨਾਮ ਜਾਂ IP ਪਤਾ ਦਿਓ।

### Linux

#### 1. `systemd-resolve --flush-caches`

DNS ਰਿਜ਼ੋਲਵਰ ਵਜੋਂ systemd ਵਰਤਣ ਵਾਲੇ Linux ਸਿਸਟਮਾਂ ਵਿੱਚ `systemd-resolve --flush-caches` DNS ਕੈਸ਼ ਸਾਫ਼ ਕਰਦਾ ਹੈ। ਇਹ ਪੁਰਾਣੀਆਂ ਕੈਸ਼ ਐਂਟਰੀਆਂ ਕਾਰਨ ਆਈਆਂ ਸਮੱਸਿਆਵਾਂ ਹੱਲ ਕਰ ਸਕਦਾ ਹੈ। ਟਰਮੀਨਲ ਵਿੱਚ ਪ੍ਰਸ਼ਾਸਕ ਅਧਿਕਾਰਾਂ ਨਾਲ ਚਲਾਓ।

#### 2. `dig`

`dig` Linux ਵਿੱਚ ਉਪਲਬਧ ਬਹੁਪੱਖੀ DNS ਜਾਂਚ ਸੰਦ ਹੈ। ਇਹ DNS ਪੁੱਛਗਿੱਛਾਂ, ਜਵਾਬਾਂ ਅਤੇ ਸਰਵਰ ਸੰਰਚਨਾ ਬਾਰੇ ਵਿਸਥਾਰ ਦਿੰਦਾ ਹੈ। ਖ਼ਾਸ ਰਿਕਾਰਡ ਪੁੱਛਣ, ਨਾਮ ਹੱਲ ਦੀ ਜਾਂਚ ਅਤੇ ਸਮੱਸਿਆਵਾਂ ਲੱਭਣ ਲਈ `dig` ਵਰਤੋ। ਟਰਮੀਨਲ ਵਿੱਚ `dig` ਤੋਂ ਬਾਅਦ ਡੋਮੇਨ ਨਾਮ ਜਾਂ IP ਪਤਾ ਦਿਓ।

ਇਹ ਕਮਾਂਡਾਂ ਵੱਖ-ਵੱਖ ਓਪਰੇਟਿੰਗ ਸਿਸਟਮਾਂ ਵਿੱਚ DNS ਸਮੱਸਿਆਵਾਂ ਦੀ ਜਾਂਚ ਅਤੇ ਹੱਲ ਵਿੱਚ ਮਦਦ ਕਰਦੀਆਂ ਹਨ। ਇਨ੍ਹਾਂ ਨਾਲ DNS ਸੰਰਚਨਾ, ਸਰਵਰ ਸੈਟਿੰਗਾਂ ਅਤੇ ਸੰਪਰਕ ਸਮੱਸਿਆਵਾਂ ਵੇਖੀਆਂ ਜਾ ਸਕਦੀਆਂ ਹਨ।

ਕਮਾਂਡਾਂ ਅਤੇ ਉਨ੍ਹਾਂ ਦੇ ਵਿਕਲਪ ਓਪਰੇਟਿੰਗ ਸਿਸਟਮ ਦੇ ਸੰਸਕਰਣ ਅਤੇ ਡਿਸਟ੍ਰਿਬਿਊਸ਼ਨ ਅਨੁਸਾਰ ਵੱਖਰੇ ਹੋ ਸਕਦੇ ਹਨ। ਵਰਤੋਂ ਦੇ ਵੇਰਵਿਆਂ ਲਈ ਆਪਣੇ ਸੰਸਕਰਣ ਦੇ ਦਸਤਾਵੇਜ਼ ਵੇਖੋ।
______


## ਸਿੱਟਾ

ਡੋਮੇਨ ਨੇਮ ਸਿਸਟਮ (DNS) ਅਤੇ ਰੂਟ DNS ਇੰਟਰਨੈੱਟ ਦੇ ਕੰਮ ਵਿੱਚ ਅਹਿਮ ਭੂਮਿਕਾ ਨਿਭਾਉਂਦੇ ਹਨ। DNS ਪੜ੍ਹਨਯੋਗ ਡੋਮੇਨ ਨਾਵਾਂ ਨਾਲ ਵੈੱਬਸਾਈਟਾਂ ਤੱਕ ਪਹੁੰਚ ਦਿੰਦਾ ਹੈ, ਜਦਕਿ ਰੂਟ DNS ਪੂਰੀ DNS ਲੜੀ ਦਾ ਆਧਾਰ ਹੈ। ਇਹ ਕਿਵੇਂ ਕੰਮ ਕਰਦੇ ਹਨ, ਇਹ ਸਮਝਣ ਨਾਲ ਵੈੱਬ ਵਰਤਣਾ ਅਤੇ ਆਨਲਾਈਨ ਸੇਵਾਵਾਂ ਦੇ ਪਿੱਛੇ ਦਾ ਬੁਨਿਆਦੀ ਢਾਂਚਾ ਸਮਝਣਾ ਆਸਾਨ ਹੁੰਦਾ ਹੈ।
