## DNS और रूट DNS कैसे काम करते हैं

### परिचय

डोमेन नेम सिस्टम (DNS) इंटरनेट अवसंरचना का एक महत्वपूर्ण हिस्सा है। यह उपयोगकर्ताओं को IP पतों के बजाय डोमेन नाम से वेबसाइट खोलने देता है। DNS फोनबुक की तरह काम करता है और इंसानों के लिए पढ़ने योग्य डोमेन नाम को कंप्यूटर के लिए समझने योग्य IP पतों में बदलता है। रूट DNS इस पदानुक्रमित और वितरित प्रणाली का आधार है, जो डोमेन नामों का समाधान करती है। इस लेख में DNS, रूट DNS और डोमेन से जुड़े रिकॉर्ड की जानकारी दी गई है।

## डोमेन नेम सिस्टम (DNS)

**डोमेन नेम सिस्टम (DNS)** एक विकेंद्रीकृत नामकरण प्रणाली है, जो डोमेन नामों को IP पतों से जोड़ती है। ब्राउज़र में डोमेन नाम लिखकर वेबसाइट और अन्य इंटरनेट संसाधन खोले जा सकते हैं। DNS से जटिल IP पते याद रखने की जरूरत नहीं रहती।

### DNS पदानुक्रम

DNS कई स्तरों वाली पदानुक्रमित संरचना में काम करता है। सबसे ऊपर रूट ज़ोन होता है, उसके बाद टॉप-लेवल डोमेन (TLD), दूसरे स्तर के डोमेन और सबडोमेन आते हैं। हर स्तर पूरे डोमेन नाम का हिस्सा होता है। `www.example.com` में "www" सबडोमेन, "example" दूसरे स्तर का डोमेन और "com" TLD है।

### DNS नाम समाधान प्रक्रिया

ब्राउज़र में डोमेन नाम डालते ही DNS नाम समाधान शुरू होता है। ब्राउज़र DNS रिज़ॉल्वर को क्वेरी भेजता है। यह रिज़ॉल्वर सामान्यतः इंटरनेट सेवा प्रदाता (ISP) देता है। रिज़ॉल्वर डोमेन नाम का समाधान करके संबंधित IP पता पाने के लिए कई चरणों से गुजरता है।

1. **स्थानीय DNS कैश**: रिज़ॉल्वर पहले स्थानीय कैश में अनुरोधित डोमेन नाम और IP पता खोजता है। जानकारी मिलने पर वह आगे क्वेरी किए बिना परिणाम लौटाता है।

2. **पुनरावर्ती क्वेरी**: कैश में जानकारी नहीं मिलने पर रिज़ॉल्वर पुनरावर्ती क्वेरी शुरू करता है। पहले वह "." (डॉट) ज़ोन के लिए जिम्मेदार रूट DNS सर्वर से संपर्क करता है। रूट सर्वर अनुरोधित डोमेन के TLD सर्वर के IP पते लौटाते हैं।

3. **TLD क्वेरी**: रिज़ॉल्वर पिछले चरण में मिले TLD सर्वर से संपर्क करके डोमेन के प्रामाणिक नाम सर्वर के IP पते माँगता है।

4. **प्रामाणिक नाम सर्वर क्वेरी**: रिज़ॉल्वर TLD सर्वर से मिले प्रामाणिक नाम सर्वर को क्वेरी भेजता है। इन सर्वरों में डोमेन के प्रामाणिक रिकॉर्ड होते हैं और वे नाम से जुड़ा IP पता लौटाते हैं।

5. **क्लाइंट को उत्तर**: रिज़ॉल्वर प्रामाणिक नाम सर्वर से IP पता लेकर ब्राउज़र को लौटाता है। फिर ब्राउज़र उस पते से वेब सर्वर से जुड़ सकता है।

### DNS कैशिंग

DNS रिज़ॉल्वर प्रदर्शन बेहतर करने और DNS सर्वर पर भार घटाने के लिए कैशिंग का उपयोग करते हैं। उत्तर मिलने पर रिज़ॉल्वर डोमेन नाम और IP पते का संबंध स्थानीय कैश में रखता है। उसी नाम की अगली क्वेरी कैश से हल हो सकती है, जिससे DNS पदानुक्रम से दोबारा पूछने की जरूरत नहीं पड़ती।

कैशिंग कई स्तरों पर होती है, जैसे स्थानीय रिज़ॉल्वर, ISP रिज़ॉल्वर और राउटर या ऑपरेटिंग सिस्टम जैसे उपकरण। DNS उत्तर में Time-to-Live (TTL) मान बताता है कि रिकॉर्ड कितनी देर कैश में रहेगा। TTL समाप्त होने पर रिज़ॉल्वर रिकॉर्ड हटाकर नया अनुरोध करता है।

#### स्थानीय DNS कैश साफ़ करें

DNS कैश साफ़ करने से कुछ DNS समस्याएँ हल हो सकती हैं और सिस्टम नए रिकॉर्ड प्राप्त करता है। अलग-अलग ऑपरेटिंग सिस्टम के चरण:

##### Windows

Windows में DNS कैश साफ़ करने के लिए:

1. `Win + R` दबाएँ, `cmd` लिखें और Enter दबाकर कमांड प्रॉम्प्ट खोलें।

2. कमांड प्रॉम्प्ट में नीचे दिया कमांड लिखें और Enter दबाएँ:

```bash
ipconfig /flushdns
```

यह कमांड Windows सिस्टम में DNS रिज़ॉल्वर कैश साफ़ करता है।

##### macOS

macOS में DNS कैश साफ़ करने के लिए:

1. Applications > Utilities से टर्मिनल खोलें या Spotlight से खोजें।

2. टर्मिनल में नीचे दिया कमांड लिखें और Enter दबाएँ:

```bash
sudo killall -HUP mDNSResponder
```

यह कमांड macOS में DNS समाधान के लिए जिम्मेदार mDNSResponder प्रक्रिया को पुनः शुरू करता है।

##### Linux

Linux में DNS कैश साफ़ करने की विधि वितरण और DNS रिज़ॉल्वर के अनुसार बदलती है। दो सामान्य तरीके:

1. **systemd-आधारित सिस्टम (जैसे Ubuntu, Fedora)**:

टर्मिनल खोलें और व्यवस्थापक अधिकारों के साथ यह कमांड चलाएँ:

```bash
sudo systemd-resolve --flush-caches

```

यह कमांड उन सिस्टम में DNS कैश साफ़ करता है जहाँ systemd-resolved DNS रिज़ॉल्वर है।

2. **systemd के बिना सिस्टम**:

टर्मिनल खोलें और व्यवस्थापक अधिकारों के साथ यह कमांड चलाएँ:

```bash
sudo /etc/init.d/nscd restart

```

यह कमांड Name Service Cache Daemon (nscd) को पुनः शुरू करता है, जो systemd के बिना Linux वितरणों में DNS कैश संभालता है।

ये सामान्य दिशा-निर्देश हैं। ऑपरेटिंग सिस्टम के संस्करण के अनुसार कमांड और विधि थोड़ी अलग हो सकती है। DNS कैश साफ़ करने से कुछ समस्याएँ ठीक होती हैं, पर नेटवर्क कनेक्टिविटी की हर समस्या नहीं।

## रूट DNS सिस्टम कैसे काम करता है

रूट DNS सिस्टम DNS अवसंरचना का मूल हिस्सा है। इसके काम करने का तरीका:

### 1. रूट ज़ोन और रूट सर्वर

रूट DNS सिस्टम **रूट ज़ोन** से शुरू होता है, जो DNS पदानुक्रम का सबसे ऊपरी स्तर है। इसमें सभी टॉप-लेवल डोमेन (TLD), जैसे .com, .org, .net और देश कोड TLD, जैसे .us और .uk, के प्रामाणिक नाम सर्वर की जानकारी होती है।

रूट DNS सिस्टम में A से M तक अक्षरों से पहचाने जाने वाले 13 रूट DNS सर्वर होते हैं। अतिरिक्त क्षमता और विश्वसनीयता के लिए वे दुनिया भर में अलग-अलग स्थानों पर वितरित हैं।

### 2. Anycast रूटिंग

DNS ट्रैफ़िक की बड़ी मात्रा संभालने के लिए रूट सर्वर **anycast रूटिंग** अपनाते हैं। कई सर्वर एक ही IP पता साझा करते हैं, लेकिन भौगोलिक रूप से अलग होते हैं। नेटवर्क की स्थिति के आधार पर क्वेरी उपयुक्त सर्वर तक पहुँचती है और भार कुशलता से बँटता है।

उपयोगकर्ता DNS क्वेरी शुरू करता है तो anycast अनुरोध को पास के उपलब्ध रूट सर्वर तक भेजता है। नेटवर्क अवसंरचना स्थितियों के अनुसार सबसे छोटा रास्ता चुनती है। Anycast भार वितरण और अवरोध कम करने में मदद करता है।

### 3. पुनरावर्ती DNS रिज़ॉल्वर

DNS रिज़ॉल्वर को डोमेन नाम की क्वेरी मिलने पर वह पुनरावर्ती समाधान शुरू करके किसी रूट सर्वर से संपर्क करता है।

रूट सर्वर अनुरोधित TLD के लिए जिम्मेदार TLD नाम सर्वर के IP पते का संदर्भ देता है। ये TLD सर्वर अपने TLD के अंतर्गत डोमेन के प्रामाणिक नाम सर्वर की जानकारी रखते हैं।

### 4. संदर्भ और प्रामाणिक नाम सर्वर

रूट सर्वर से संदर्भ मिलने के बाद रिज़ॉल्वर संबंधित TLD नाम सर्वर से संपर्क करता है।

TLD नाम सर्वर दूसरा संदर्भ देता है, जिसमें अनुरोधित डोमेन के प्रामाणिक नाम सर्वर के IP पते होते हैं।

इसके बाद रिज़ॉल्वर प्रामाणिक नाम सर्वर से डोमेन नाम का IP पता माँगता है।

### 5. कैशिंग और TTL

DNS समाधान के दौरान कैशिंग प्रदर्शन बढ़ाती है और DNS सर्वर का भार कम करती है। DNS रिज़ॉल्वर डोमेन नामों और IP पतों के संबंध सहेजते हैं।

DNS रिकॉर्ड Time-to-Live (TTL) मान में तय अवधि तक कैश में रहते हैं। TTL बताता है कि रिकॉर्ड कितनी देर तक मान्य रहेगा। समय पूरा होने पर रिज़ॉल्वर रिकॉर्ड हटाकर नया IP पता पाने के लिए फिर से पूछता है।

### 6. सहयोग और प्रबंधन

रूट DNS सिस्टम का प्रबंधन Internet Corporation for Assigned Names and Numbers (ICANN) और रूट सर्वर संचालक के सहयोग से होता है।

ICANN DNS के सामान्य प्रबंधन और समन्वय की देखरेख करता है तथा रूट सर्वर ऑपरेटरों के साथ काम करता है। वे मिलकर रूट ज़ोन फ़ाइल बनाए रखते हैं, जिसमें 13 रूट DNS सर्वर और उनके IP पतों की जानकारी होती है।

रूट सर्वर संचालक रूट DNS सर्वर का संचालन और उपलब्धता सुनिश्चित करते हैं। इससे पूरी DNS अवसंरचना की स्थिरता और मजबूती बनी रहती है।

रूट DNS सिस्टम DNS समाधान का शुरुआती बिंदु है। यह डोमेन नामों को IP पतों से जोड़ता है और वेबसाइट तथा अन्य इंटरनेट संसाधनों तक प्रभावी पहुँच देता है।

#### 13 रूट DNS सर्वर

13 रूट DNS सर्वर A से M तक अक्षरों से पहचाने जाते हैं। अतिरिक्त क्षमता और विफलता सहनशीलता के लिए हर सर्वर कई भौतिक स्थानों पर होस्ट किया जाता है। वे रूट ज़ोन की क्वेरी संभालते हैं, जिसमें .com, .org, .net और .us, .uk जैसे देश कोड TLD शामिल हैं।

#### ICANN और रूट DNS प्रबंधन

Internet Corporation for Assigned Names and Numbers (**ICANN**) DNS प्रबंधन और समन्वय तथा IP पतों के आवंटन के लिए जिम्मेदार है। रूट DNS की स्थिरता और सुरक्षा के लिए ICANN, रूट सर्वर संचालक के साथ काम करता है। वे 13 रूट सर्वर और उनके IP पतों की जानकारी वाली रूट ज़ोन फ़ाइल बनाए रखते हैं।

## DNS रिकॉर्ड के प्रकार और उनके काम

{{< youtube id="HnUDtycXSNE" >}}

DNS रिकॉर्ड Domain Name System (DNS) के जरूरी घटक हैं। वे डोमेन नाम से जुड़ी कई तरह की जानकारी देते हैं। कुछ आम रिकॉर्ड और उनके काम:

| रिकॉर्ड प्रकार | विवरण | उदाहरण |
|-------------|-----------------------------------------------------------------------------|-------------------------------------------|
| A | डोमेन नाम को IPv4 पते से जोड़ता है। | `example.com     IN A 192.0.2.1` |
| AAAA | डोमेन नाम को IPv6 पते से जोड़ता है। | `example.com     IN AAAA 2001:db8::1` |
| CNAME | उपनाम (canonical name) को वास्तविक डोमेन नाम से जोड़ता है। | `www.example.com IN CNAME example.com` |
| MX | डोमेन के आने वाले ईमेल लेने वाले मेल सर्वर बताता है। | `example.com     IN MX 10 mail.example.com` |
| TXT | मनमाना पाठ रखता है, अक्सर SPF, DKIM या डोमेन सत्यापन के लिए। | `example.com     IN TXT "v=spf1 a mx -all"`|
| NS | डोमेन के प्रामाणिक नाम सर्वर बताता है। | `example.com     IN NS ns1.example.com` |
| SOA | ज़ोन के सामान्य गुण बताता है (start of authority रिकॉर्ड)। | `example.com     IN SOA ns1.example.com` |
| SRV | डोमेन द्वारा दी जाने वाली खास सेवा का स्थान बताता है। | `_service._proto.example.com IN SRV 10 20 5060 target.example.com` |
| PTR | IP पते को डोमेन नाम से जोड़ता है (रिवर्स DNS लुकअप)। | `1.2.0.192.in-addr.arpa IN PTR example.com` |

### 1. A रिकॉर्ड (पता रिकॉर्ड)

**A रिकॉर्ड** डोमेन नाम को IPv4 पते से जोड़ता है। यह सबसे सरल और आम DNS रिकॉर्ड है। ब्राउज़र में डोमेन नाम डालने पर यह वेबसाइट होस्ट करने वाले वेब सर्वर का IP पता ढूँढने में मदद करता है।

### 2. AAAA रिकॉर्ड (IPv6 पता रिकॉर्ड)

**AAAA रिकॉर्ड** A रिकॉर्ड जैसा काम करता है, लेकिन डोमेन को IPv6 पते से जोड़ता है। IPv6 की ओर बदलाव के साथ IPv6 नेटवर्क पर संपर्क के लिए इसकी अहमियत बढ़ रही है।

### 3. CNAME रिकॉर्ड (मानक नाम रिकॉर्ड)

**CNAME रिकॉर्ड** डोमेन के लिए उपनाम या canonical name बनाता है। जब किसी डोमेन या सबडोमेन को दूसरे डोमेन या सबडोमेन की ओर भेजना हो तो इसका उपयोग करें। उदाहरण के लिए, CNAME "www" को "mywebsite.com" की ओर भेज सकता है।

### 4. MX रिकॉर्ड (मेल विनिमय रिकॉर्ड)

**MX रिकॉर्ड** डोमेन के आने वाले ईमेल स्वीकार करने वाले मेल सर्वर को निर्दिष्ट करता है। कई MX रिकॉर्ड की प्राथमिकता तय कर सकती है कि मुख्य सर्वर उपलब्ध न होने पर किस क्रम में सर्वर आजमाए जाएँ।

### 5. TXT रिकॉर्ड (पाठ रिकॉर्ड)

**TXT रिकॉर्ड** डोमेन से जुड़ी पाठ जानकारी रखता है। इसका उपयोग डोमेन सत्यापन, ईमेल प्रमाणीकरण के लिए SPF (Sender Policy Framework) रिकॉर्ड और सामान्य जानकारी या नोट रखने में होता है।

### 6. SRV रिकॉर्ड (सेवा रिकॉर्ड)

**SRV रिकॉर्ड** डोमेन के भीतर किसी खास सेवा या संसाधन का स्थान बताता है। VoIP, त्वरित संदेश और ऐसी अन्य ऐप में इसका उपयोग होता है जिन्हें खास सर्वर या सेवा ढूँढनी होती है।

### 7. NS रिकॉर्ड (नाम सर्वर रिकॉर्ड)

**NS रिकॉर्ड** डोमेन के प्रामाणिक नाम सर्वर बताता है। ये सर्वर डोमेन के DNS रिकॉर्ड रखते हैं। DNS रिज़ॉल्वर NS रिकॉर्ड से प्रामाणिक नाम सर्वर ढूँढता है।

### 8. PTR रिकॉर्ड (सूचक रिकॉर्ड)

**PTR रिकॉर्ड** रिवर्स DNS लुकअप में IP पते को डोमेन नाम से जोड़ता है। इसका उपयोग मेल सर्वर की पहचान जाँचने और स्पैम रोकने में होता है। रिवर्स DNS लुकअप ईमेल सर्वर की प्रामाणिकता जाँचने में मदद करता है।

### 9. SOA रिकॉर्ड (प्राधिकार आरंभ रिकॉर्ड)

**SOA रिकॉर्ड** डोमेन की प्रशासनिक जानकारी रखता है। इसमें प्राथमिक प्रामाणिक नाम सर्वर, डोमेन व्यवस्थापक का ईमेल और DNS रिकॉर्ड के समय संबंधी कई पैरामीटर शामिल होते हैं।

ये कई उपलब्ध DNS रिकॉर्ड में से कुछ उदाहरण हैं। हर रिकॉर्ड का विशिष्ट काम है और यह डोमेन नामों को उनके संसाधनों तक सही ढंग से पहुँचाने में मदद करता है।

## अलग-अलग ऑपरेटिंग सिस्टम के लिए DNS निदान कमांड

DNS समस्या आने पर निदान कमांड कारण पता लगाने में मदद करते हैं। अलग-अलग सिस्टम के लिए आम कमांड:

### Windows

#### 1. `ipconfig /flushdns`

यह कमांड Windows में DNS कैश साफ़ करता है और पुराने या गलत DNS रिकॉर्ड से जुड़ी समस्याएँ हल कर सकता है। कमांड प्रॉम्प्ट खोलकर इसे चलाएँ।

#### 2. `ipconfig /all`

`ipconfig /all` Windows नेटवर्क इंटरफेस की विस्तृत जानकारी दिखाता है, जिसमें कॉन्फ़िगर किए DNS सर्वर भी शामिल हैं। इससे पुष्टि करें कि सही DNS सर्वर उपयोग हो रहे हैं।

### macOS

#### 1. `sudo killall -HUP mDNSResponder`

यह कमांड macOS में DNS समाधान के लिए जिम्मेदार mDNSResponder प्रक्रिया को पुनः शुरू करता है। इससे DNS सेटिंग अपडेट हो सकती हैं और कुछ समस्याएँ हल हो सकती हैं। टर्मिनल खोलें और व्यवस्थापक अधिकार के साथ चलाएँ।

#### 2. `nslookup`

`nslookup` से DNS रिकॉर्ड पूछे जा सकते हैं, नाम समाधान जाँचा जा सकता है और DNS सर्वर से कनेक्टिविटी जाँची जा सकती है। टर्मिनल में `nslookup` के बाद जाँचने वाला डोमेन नाम या IP पता दें।

### Linux

#### 1. `systemd-resolve --flush-caches`

systemd को DNS रिज़ॉल्वर के रूप में उपयोग करने वाले Linux सिस्टम में `systemd-resolve --flush-caches` DNS कैश साफ़ करता है। पुराने कैश की वजह से आई समस्या इससे हल हो सकती है। टर्मिनल में व्यवस्थापक अधिकार के साथ कमांड चलाएँ।

#### 2. `dig`

`dig` Linux का बहुउपयोगी DNS निदान उपकरण है। यह DNS क्वेरी, उत्तर और DNS सर्वर कॉन्फ़िगरेशन की विस्तृत जानकारी देता है। रिकॉर्ड पूछने, नाम समाधान जाँचने और DNS समस्या खोजने के लिए `dig` उपयोग करें। टर्मिनल में `dig` के बाद डोमेन नाम या IP पता दें।

ये कमांड अलग-अलग ऑपरेटिंग सिस्टम में DNS समस्याओं का निदान और समाधान करने में मदद करते हैं। इनसे DNS कॉन्फ़िगरेशन, सर्वर सेटिंग और कनेक्टिविटी की जाँच होती है।

ऑपरेटिंग सिस्टम के संस्करण और वितरण के अनुसार कमांड और विकल्प बदल सकते हैं। उपयोग की जानकारी के लिए अपने संस्करण का दस्तावेज़ देखें।

## निष्कर्ष

Domain Name System (DNS) और रूट DNS इंटरनेट के काम में अहम भूमिका निभाते हैं। DNS उपयोगकर्ताओं को पढ़ने योग्य डोमेन नाम से वेबसाइट खोलने देता है, जबकि रूट DNS पूरी DNS पदानुक्रम की नींव है। इनके काम को समझने से वेब चलाना और ऑनलाइन सेवाओं के पीछे की अवसंरचना समझना आसान होता है।
