**اختر امتداد Claude Code حول مشكلة محددة في سير عملك.** تحتاج المتطلبات غير الواضحة إلى محادثة تخطيط. تحتاج العيوب التي لم تُكتشف إلى مراجعة واختبارات. تحتاج الأبحاث المتكررة إلى مصادر قابلة للتتبع. لا تفيدك كثرة الأدوات إلا عندما تكون مسؤولياتها واضحة.

يقارن هذا الدليل بين **عشرة مشاريع** لهذه المهام، مع أمثلة إعداد وتمرين تقييم عملي. يستند التحليل إلى وثائق المشاريع الحالية وفيديو Chase AI المقدم. التوصيات أحكام تحريرية، وليست قياسات أداء عملية أو دليلاً على زيادة إنتاجية بمقدار عشرة أضعاف.

## أهم النقاط

- **اختر حسب الناتج:** تحتاج الخطة التي تمت مراجعتها وخريطة الكود والصورة المولدة إلى أدوات مختلفة.
- **افصل طبقات التثبيت:** تختلف تبعيات التعليمات والبرامج القابلة للتنفيذ والإضافات واتصالات الخدمات.
- **تحقق من الأسماء الحالية:** توجد Graphify وgrill-me-codex الآن في موقعي مستودعات أساسيين مختلفين.
- **تحقق بأكثر من الاتفاق:** لا يثبت قبول نموذجين لخطة أن التنفيذ صحيح.
- **قس العمل المقبول:** سجّل الإعداد واستخدام الخدمة والمحاولات الفاشلة وتصحيحات الإنسان.

## قبل أن تبدأ

**المتطلبات المسبقة:** تثبيت Claude Code يعمل، ومشروع أو فرع قابل للتخلص منه، وإذن لاستخدام الخدمات الخارجية المحددة. تفترض أمثلة CLI وجود طرفية ومدير الحزم المذكور. تحتاج عمليات التكامل السحابية إلى حساباتها ومصادقتها الخاصة.

**الوقت المقدر:** 15 دقيقة للقراءة، ثم خصص من 30 إلى 60 دقيقة لتجربة واحدة محددة. **الصعوبة:** متوسطة لإعداد CLI وتكامل الخدمات. تحتاج قراءة مهارات التعليمات إلى إعداد أقل.

**الوثائق التي فُحصت في 10 أكتوبر 2026.** تعكس الأوامر وقواعد الوصول المصادر المرتبطة. أعد فحص الإصدار المثبت قبل اتباع درس قديم. يركز هذا المقال على الامتدادات المستخدمة من Claude Code، مع توضيح اختلافات المضيف عند الحاجة.

**تحقق على طبقات بعد التثبيت.** افحص الملفات واكتشاف المضيف والتبعيات القابلة للتنفيذ وبيانات الاعتماد ومهمة ممثلة واحدة كلًّا على حدة. لا يثبت نجاح المثبت عمل المتصفح أو خادم MCP أو أداة الوسائط أو الحساب الخارجي. اجعل الاختبار الأول على بيانات اصطناعية وسجّل إصدار المصدر.

## وضّح العمل

### grill-me وgrill-with-docs

**تساعد مهارات Matt Pocock** على تحويل الفكرة غير المحددة إلى قرارات. تستدعي [نقطة دخول grill-me الحالية](https://github.com/mattpocock/skills/blob/main/skills/productivity/grill-me/SKILL.md) مهارة الاستجواب المشتركة. وتستدعي [grill-with-docs](https://github.com/mattpocock/skills/blob/main/skills/engineering/grill-with-docs/SKILL.md) الاستجواب ونمذجة المجال. تصف [وثائق المجموعة](https://github.com/mattpocock/skills) المصطلحات المشتركة وسجلات قرارات المعمارية إلى جانب المقابلة.

**استخدم نسخة الوثائق** عندما تؤثر مصطلحات العمل في التنفيذ. في مستورد CSV توضيحي، احسم هل يعني العميل الموجود البريد نفسه أو المعرّف الخارجي نفسه أو كليهما. سجّل التعريف المختار قبل كتابة كشف التكرار.

**اجعل المقابلة متناسبة.** تحل الجلسة المفيدة عدم اليقين المؤثر. لا تطلب منك المقابلة إعادة إجابات موجودة في المستودع. اختم بخطة وأسئلة غير محسومة وفحوص إكمال قابلة للملاحظة.

### CLAUDE.md مستوحى من Karpathy

**تحول إرشادات Multica** ملاحظات Karpathy إلى أربعة محاور: افتراضات صريحة وحلول بسيطة وتغييرات مركزة وأهداف قابلة للتحقق. [المستودع](https://github.com/multica-ai/andrej-karpathy-skills) تطبيق مجتمعي مستوحى من ملاحظاته. وصف المشروع بأنه إضافة يديرها Karpathy شخصيًا يخطئ في مصدره.

**ادمج الإرشادات المفيدة في سياسة المشروع الحالية.** حافظ على أوامر البناء واتفاقيات المحتوى وقيود النشر. إنشاء ملف تعليمات بديل يحذف هذه التفاصيل يضيف مصادر جديدة للأخطاء.

**مثال على قاعدة مشروع:** اطلب من تغيير المستورد الحفاظ على معالجة التكرار الحالية وشرح أي تغيير مقصود باستخدام fixture. تحول هذه القاعدة تفضيل الحذر العام إلى فحص يفهمه المراجع. تعبر التعليمات عن التوقعات. تنشئ الاختبارات وضوابط التشغيل دليلًا منفصلًا.

| أثر التخطيط | الغرض |
|---|---|
| **متطلب** | يسمي الناتج المرئي للمستخدم |
| **مدخل معجم** | يعطي المصطلح متعدد المعاني معنى واحدًا |
| **سجل قرار** | يحفظ سبب الاختيار المؤثر |
| **فحص قبول** | يحدد طريقة تقييم الإكمال |

## راجع الخطط والكود

### grill-me-codex، الآن Claudex Loop

**Claudex Loop** هو الوجهة الحالية لمستودع grill-me-codex الأصلي. تصف [وثائقه](https://github.com/chaseai-yt/claudex-loop) استكشاف المستودع والمتطلبات والمراجعة من الموفر الآخر والتنفيذ والفحص المستقل. تحتاج الحلقة الكاملة إلى CLI لكلا الطرفين وPython 3.10 أو أحدث.

**استخدم Claudex Loop للخطط المؤثرة** التي تستحق تحدي افتراضاتها قبل التنفيذ. يدعم سير العمل الحالي البدء من Claude Code أو Codex. يسجل سير العمل النتائج والتصرفات ويميز إذن المراجعة من إذن البناء. لا تستبدل ميزانية الجولات الحالية لسير العمل المثبت بالوصف الأقدم ذي الجولات الخمس في الفيديو.

**اطلب دليلًا مع كل اعتراض.** يجب أن تحدد مراجعة مستورد CSV تكرارًا ملموسًا أو حالة إعادة محاولة وسلوكها المتوقع. اتفاق النماذج نتيجة مراجعة وليس دليلًا. احتفظ بالنتائج غير المحسومة عند انتهاء ميزانية المراجعة.

### إضافة OpenAI Codex

```text
/plugin marketplace add openai/codex-plugin-cc
/plugin install codex@openai-codex
/reload-plugins
/codex:setup
```

**تضيف إضافة Codex من OpenAI لـ Claude Code** مراجعة الكود وتفويض المهام داخل Claude Code. هذه أوامر Claude Code وليست أوامر shell. يوثق [المستودع الرسمي](https://github.com/openai/codex-plugin-cc) Node.js 18.18 أو أحدث ووصول Codex موثقًا عبر ChatGPT أو مفتاح OpenAI API.

```text
/codex:review --background
/codex:status
/codex:result
```

**استخدم المراجعة العادية** للتغييرات الحالية أو مقارنة فرع. استخدم **`/codex:adversarial-review`** لتحدٍّ مركز. تنفذ أوامر التفويض مثل **`/codex:rescue`** مهمة مختلفة عن المراجعة للقراءة فقط، لذا حدد الصلاحية المقصودة.

**ضع ميزانية لاستخدام Codex منفصلة.** يدرج المشروع ChatGPT Free ضمن الحسابات المدعومة، لكن حدود الاستخدام تظل قائمة. لا تنشئ إضافة التثبيت وصولًا غير محدود.

**قاعدة الاختيار:** استخدم مراجعة إضافة محددة لتصحيح قائم. اختر الحلقة الأكبر عندما تحتاج المتطلبات ومراجعة الخطة إلى عملية مسجلة خاصة بها.

## حافظ على السياق المفيد

### Graphify

```bash
uv tool install graphifyy
graphify install --project
graphify extract . --code-only
graphify query "show the authentication flow"
```

**ترسم Graphify** علاقات المستودع في رسم معرفة قابل للاستعلام. يوجد [المستودع الأساسي](https://github.com/Graphify-Labs/graphify) الآن تحت Graphify-Labs. اسم الحزمة هو **`graphifyy`** بحرفي y في النهاية. تظل الأداة التنفيذية **`graphify`**.

**يستخدم الاستخراج المقتصر على الكود** تحليل شجرة بناء الجملة المحلي، ويقرأ بنية الكود. ويستخدم تفسير الوثائق والوسائط مسارًا آخر مدعومًا بالنموذج. لا تمدد ادعاء الخصوصية أو التكلفة المحلية إلى كل وضع.

**الخطافات الاختيارية** تعيد بناء رسم الكود بعد عمليات الالتزام وتبديل الفروع. بعد السحب أو الدمج، يدعو سير العمل الموثق إلى **`graphify update .`**. تحتاج تغييرات الوثائق إلى تحديث خاص. يوفر تصدير Obsidian عرضًا آخر للرسم.

**استخدم Graphify لأسئلة العلاقات**، ثم افحص المصدر المرتبط. يساعد الرسم في اختيار الملفات. لا يثبت هيكل الرسم سلوك التشغيل ولا يستبدل الاختبارات. قس أي توفير في الرموز مقابل أسئلتك الخاصة، مع احتساب بناء الرسم وصيانته.

### claude-obsidian

**ينظم claude-obsidian** مواد المصدر في صفحات Obsidian مترابطة ومستشهدة بالمصدر. يصف [المستودع](https://github.com/AgriciDaniel/claude-obsidian) الاستيعاب والاسترجاع وصيانة المعرفة والاحتفاظ بالمصدر وسجلات الدعم أو التعارض. تظل الخزنة ملفات محلية عادية.

**استخدم claude-obsidian لمعرفة المشروع الدائمة:** قرارات التصميم ووثائق المصدر وملاحظات البحث التي تحتاج إلى البقاء بعد المحادثات الفردية. الناتج المفيد سجل قابل للصيانة مع مصدر، أي أصل قابل للتتبع لكل ادعاء مهم.

**راجع الخزنة بعد الاستيعاب.** اختر بعض الادعاءات واتبع استشهاداتها إلى المادة الأصلية. احتفظ بالدليل المتعارض بدل دمج الخلاف في ملخص واثق. لا يثبت التخزين المحلي وحده الاستدلال المحلي. افحص إعداد المضيف والنموذج قبل تقديم وثائق حساسة.

| نظام السياق | السؤال الأول الأفضل |
|---|---|
| **Graphify** | ما مكونات المصدر المتصلة؟ |
| **claude-obsidian** | ما الدليل المحتفظ به الذي يدعم هذا القرار؟ |
| **notebooklm-py** | ماذا تقول مصادر البحث المحددة؟ |

### notebooklm-py

```bash
uv tool install "notebooklm-py[browser]"
notebooklm login
notebooklm auth check --test --json
notebooklm skill install
```

**توفر notebooklm-py** مكتبة Python وCLI ومهارة وكيل لخدمة بحث Google. يوثق [المشروع](https://github.com/teng-lin/notebooklm-py) استيراد المصادر والأسئلة المرتكزة على المصادر والمنتجات المولدة والتنزيلات الدفعية. يدعم ملحق browser تدفق تسجيل الدخول التفاعلي.

**هذا تكامل غير رسمي.** تعتمد المكتبة على واجهات Google غير الموثقة وتظل معرضة للكسر وحدود المعدل. لا تقدم المكتبة على أنها API عامة مدعومة من Google.

**استخدم notebooklm-py لمجموعة بحث محددة،** مثل ملاحظات الإصدار وأدلة الترحيل لتبعية واحدة. افحص الاستشهادات مقابل نص المصدر قبل إدخال النتائج في خطة. احمِ حالة المصادقة المخزنة باعتبارها مادة وصول للحساب.

يغير **تفويض البحث مكان تنفيذ العمل.** لا يلغي التفويض رموز التنسيق أو حصص الخدمة أو جهد المراجعة أو التزامات التعامل مع البيانات. تعامل مع توفير الرموز كقياس تجمعه، لا كخاصية تلقائية للتثبيت.

## صمّم الأصول وأنشئها

### Impeccable

```text
/impeccable critique settings
/impeccable audit settings
/impeccable polish settings
```

**توفر Impeccable** مفردات تصميم للعمل المركز على الواجهات. تغطي [وثائقها](https://github.com/pbakaus/impeccable) النقد والتخطيط والطباعة وفحوص الوصول والحركة والتكرار المرئي في المتصفح. تفترض الأمثلة مهارة مثبتة ومشروعًا يضم واجهة إعدادات.

**ابدأ بمشكلة تفاعل.** بالنسبة للمستورد، اسأل لماذا يفوت المستخدمون أخطاء التحقق أو يسيئون فهم اختيار معالجة التكرار. راجع التغييرات المقترحة قبل تطبيق تنقيح مرئي. لا يصلح التباعد الجذاب وحده إجراءً غامضًا.

**تساعد التكرارات المباشرة** على مقارنة البدائل في المتصفح. تحقق من التنقل بلوحة المفاتيح وتخطيط الهاتف ورسائل الخطأ والتباين الناتج. تتغير أعداد الأوامر بين الإصدارات، لذا استخدم قائمة الأوامر المشحونة مع إصدارك بدل حفظ عدد الفيديو.

### Higgsfield

**يربط تكامل Higgsfield عبر MCP** الوكلاء بخدمة توليد الصور والفيديو. تسرد [صفحة التكامل الرسمية](https://higgsfield.ai/mcp) خيارات اتصال Claude Code وCLI إلى جانب سير العمل الإبداعي. استخدم مسار الإعداد الحالي لحسابك وواجهتك المختارة.

**اختر Higgsfield عندما تكون الوسائط هي التسليم المفقود.** بالنسبة لصفحة منتج توضيحية، حدد نسبة الأصل وتكوينه وقيود العلامة وموضعه قبل إنشاء النسخ. افصل الموجز المرئي عن مهمة تنفيذ الصفحة.

**تحقق من الوصول إلى الخدمة والاستهلاك أولًا.** لا يثبت إدراج التكامل الوصول إلى كل نموذج أو إنشاء غير محدود أو حقًا تجاريًا محددًا. افحص شروط الحساب المعنية والنموذج المختار قبل اعتماد سير عمل إنتاجي.

**راجع الملف النهائي** في حجم عرضه المقصود. افحص النص المرئي والرموز غير المقصودة والقص والتوافق مع المنتج. لا تخدم شاشات الطرفية والمخططات المولدة دليلًا على اختبار ناجح.

| تسليم التصميم | دليل الإكمال |
|---|---|
| **مراجعة الواجهة** | تعمل الإجراءات المطلوبة عبر إطارات العرض المستهدفة |
| **أصل صورة** | تطابق الأبعاد والقص والمحتوى الموجز |
| **أصل فيديو** | يطابق التوقيت والحركة والتصدير النهائي الموجز |

## اربط سير العمل المتكرر

### n8n MCP

**يعرض خادم MCP المدمج في n8n** عمليات سير العمل للعملاء المتصلين. تغطي [وثائق الاتصال الحالية](https://docs.n8n.io/connect/connect-to-n8n-mcp-server) المثيلات السحابية والمستضافة ذاتيًا. يوثق بناء سير العمل وتعديله من n8n 2.13.0. يشير هذا المقال إلى خادم n8n الخاص، لا إلى حزمة مجتمعية غير مرتبطة تحمل اسمًا مشابهًا.

**استخدم وصول مستوى المثيل** للتكامل الموصوف هنا. تملك عقدة MCP Server Trigger نطاقًا مختلفًا، فهي تعرض أدوات من سير عمل واحد. افحص [مرجع الأدوات](https://docs.n8n.io/connect/connect-to-n8n-mcp-server/mcp-server-tools-reference) مقابل الإصدار المنشور لديك.

**فعّل الوصول بقصد.** تحتاج سير العمل الموجودة إلى تعريض MCP للوصول الكامل. تملك معاينات البحث رؤية أوسع ضمن صلاحيات المستخدم الموجودة. تعريض سير العمل ليس قائمة سماح منفصلة لكل عميل، مع أن صلاحيات العميل الممنوحة تحكم العمليات أيضًا.

**افحص وضع التنفيذ.** يشغل **`execute_workflow`** المنشور الإنتاجي افتراضيًا وفق الوثائق. يشغل الوضع اليدوي النسخة الحالية غير المنشورة. تحقق من المدخلات والإجراءات اللاحقة قبل التنفيذ.

**تجربة أولى مفيدة:** صنّف طلبات دعم اصطناعية واكتب النتائج إلى وجهة اختبار. تأكد من معالجة سير العمل للحقول الناقصة وإعادات المحاولة. تظل الاستضافة الذاتية بحاجة إلى حوسبة وصيانة وأي خدمات لاحقة مدفوعة.

## نفّذ تجربة مضبوطة

**تمرين توضيحي:** أضف مستورد CSV إلى تطبيق صغير. يعاين المستورد الصفوف ويبلغ عن حقول البريد غير الصالحة ويمنع إنشاء التكرارات. لا تحتاج التمرين إلى سجلات عملاء أو وجهات خارجية حية.

```yaml
# ورقة تقييم، وليست ملف إعداد أداة
task: "add CSV import preview"
inputs:
  - "valid rows"
  - "invalid email field"
  - "repeated customer identifier"
  - "same import submitted twice"
acceptance:
  - "preview creates no records"
  - "invalid rows receive useful messages"
  - "duplicate policy matches the written requirement"
  - "repeat submission creates no extra records"
record:
  - "source revision and selected skill version"
  - "model and service configuration"
  - "elapsed time and billed usage"
  - "failed checks and human corrections"
```

**أنشئ خط الأساس أولًا.** احفظ الإصدار الابتدائي واطلب من الوكيل إكمال المهمة بسير عملك الحالي. نفّذ فحوص قبول مستقلة واحتفظ بالنتيجة. كرر من الإصدار الابتدائي نفسه مع امتداد واحد والمتطلبات نفسها.

**طابق التجربة مع المشكلة المفترضة.** إذا أسيء فهم معالجة التكرار مرارًا، فجرّب مهارة متطلبات. إذا أغفل الوكيل مدققًا موجودًا، فجرّب رسم المستودع. إذا فاتت الأخطاء المستخدمين، فجرّب نقد الواجهة. يمنع تحميل الأدوات العشر معًا عزو أي تحسن.

**التفكير المتوقع:** المحاولة الثانية الناجحة دليل مفيد، لكن تشغيلًا واحدًا لا يثبت مضاعف إنتاجية عام. تساعد التشغيلات المتكررة على فصل قيمة الأداة عن تغير النموذج. قارن النتائج المقبولة، بما فيها جهد المراجعة والمحاولات الفاشلة.

| الملاحظة | التفسير |
|---|---|
| **إجابة أسرع، اختبارات فاشلة** | زمن استجابة أقل دون إكمال المهمة |
| **تشغيل أطول، تصحيحات أقل** | فائدة محتملة في جهد التسليم الكلي |
| **مراجعان متفقان** | اتفاق يحتاج إلى تحقق مستقل |
| **استخدام وكيل أقل، رسوم خدمة جديدة** | انتقلت التكلفة بين الموفرين |

**أنشئ سجل قرار محتفظًا به.** سمِّ المشكلة والأداة المختارة والفائدة الملحوظة والمشكلة غير المحسومة وشروط التجربة الأخرى. احتفظ بالأداة عندما تصمد مساهمتها أمام هذا الفحص. لا تفرض مجموعة مثبتة كبيرة سير عمل نشطًا كبيرًا.
